# Ledger 导入知识——投资节（投资交易 / 基金申赎 / 基金转换 / 份额调整 / 现金分红）

> 分域知识节，经 `GET /api/v1/import/knowledge/investment` 按需获取；基础约定（每行拆解、商户、幂等去重、对账与纠错）见 `GET /api/v1/import/knowledge`。

## 投资交易（buy / sell）

- 标的解析三步法（带代码标的的权威路径，与「基金申赎」节对称，不依赖本地标的字典）：① **先按代码查询** `GET /api/v1/stocks/{code}` 确认识别（`market` 可省）；② **再以真实代码创建** `POST /api/v1/instruments`（`symbol`/`type`/`market` 按查询结果填）；③ 用返回的标的 `id` 填 `instrument_id` 写 buy/sell。查无此码（400 中文报错）请核对代码或跳过该行；东财临时不可达时创建仍成功（降级建行、市场保留），无需重试、不阻塞导入。同码异类型（如基金 000001 与股票 000001）经查询端点天然分流。
- 源数据确无代码时才以名称充代码兜底建行（`symbol` = 名称，该行不触发东财校验、不进行情通道）；`GET /api/v1/instruments` 搜索仅作名称消歧的辅助（参数语义见契约；命中语义为契约缺口缓存：`query` 按空白切词、词条间 AND，对「代码 · 名称」判定原文连续子串或拼音首字母串，如 `gzmt` 命中 600519 贵州茅台），带代码行的解析走三步法。
- `account_id` 必须是投资账户（`GET /api/v1/accounts` 的 `type` 可辨）；`quantity` / `price_cents` / `fee_cents` 的单位与约束见契约字段说明。`buy` / `sell` 不带商户。
- 直扣/直付场景可带可选 `funding_account_id`（出资账户）：结算现金实际流出（买入）/流入（卖出）的账户，如银行卡直扣买基金——现金类账户（cash/bank/credit/ewallet/other）、币种与交易一致、不得是投资账户；缺省即投资账户自身结算。确认单直接从银行卡扣款/到账时携带，场内余额买卖不携带。
- 行金额照契约 `fee_cents` 字段说明的重算公式预填即可（服务端按固定公式重算覆盖）；场外基金例外见「基金申赎」节。
- 纠错：错误行按 400 中文报错自纠——`instrument_id` 不存在时重走三步法拿正确 id 再提交；`sell` 数量不得超过当前持仓；已有部分卖出的买入禁改（改持仓历史会破坏已实现盈亏）但**可删**：删除买入会级联软删其在用卖出并回补持仓（卖出随买入一并消失，204 无被删列表）；删除卖出则回补其持仓扣减并清空卖出匹配。
- 对账：读回行金额按契约公式核对；余额核对含结算账户现金流——`buy` 减现金、`sell` 增现金，带 `funding_account_id` 时现金腿记出资账户、投资账户现金腿为 0（`GET /api/v1/accounts/balances`）；创建标的回填的权威名称可与账单名称不同，以读回的标的名称为准。

## 基金申赎（buy / sell，场外基金）

- 行拆解：申购 → `buy`、赎回 → `sell`，行字段同「投资交易」节；`quantity` = 确认份额（份）、`amount_cents` = 确认单整分金额（**权威事实**，原样提交：申购为含费扣款额、赎回为减费到账额）、`fee_cents` = 申购/赎回费（分，归属费用字段）。**不传 `price_cents`**（成交净值由服务端按金额反算，口径与「投资交易」节的重算公式相反）：行金额恒等于确认单金额、不被净值舍入污染。
- 标的解析差异（三步法见「投资交易」节，此处只教差异）：基金账单必带 6 位代码——先 `GET /api/v1/funds/{code}` 确认识别（优先于通用搜索），再以**真实 6 位代码**作 `symbol`、`type: "fund"` 创建。fund 标的经查询通道创建后 `market` 恒 unknown、币种恒人民币（显式传参不生效）；基金**不走「查无此码 → 名称充代码」**：查无此码请核对代码或跳过该行，仅源数据确无代码时才兜底建行（该行无真实代码、不进净值通道）。
- 对账：行金额与确认单金额逐行核对（本节金额权威，见上行拆解）；直扣/直付行带 `funding_account_id`（同「投资交易」节）；其余同「投资交易」节对账条——余额核对含结算账户现金流（含出资账户）、标的名称以读回为准。

## 基金转换（convert，场外基金）

- 形态：一笔转换 = **一条** `convert` 记录、两腿同记录（转出标的 → 转入标的）、**无现金腿**——钱不进银行卡、也不进投资账户现金池。**禁止**落成「卖出 + 买入（黑洞出资）」两条借位记录：那会凭空产生已实现盈亏、把转入成本按转入日市值重置、并污染黑洞账户余额。
- 快照字段位置（且慢 API 快照 A36/A363 单，单腿一条记录）：转出端 = 顶层 `product`（代码/名称）+ `share` / `successShare`（转出份额）+ `convertAmount`（转出金额，元）；转入端 = `tradingTarget.product`（代码/名称）+ `tradingTarget.successShare`（转入份额）+ `tradingTarget.successAmount`（转入金额，元）；手续费 = `confirmInfoList` 中 `key=fee` 的 `valueText`（形如 `0.14元`，剥「元」得元值、×100 取整为分）——手续费在转入端扣份额，故 `tradingTarget.successShare` 已是**扣费后净份额**，直接作 `to_quantity`。
- 提交（`POST /api/v1/transactions/batch`，`kind: "convert"`）：`account_id` = 投资账户；`instrument_id` / `quantity` / `out_amount_cents` = 转出标的 / 转出份额 / 转出金额（分）；`to_instrument_id` / `to_quantity` / `in_amount_cents` = 转入标的 / 转入份额 / 转入金额（分）；`fee_cents` = 手续费（分）。标的解析同「基金申赎」节（先按 6 位代码查询、再以真实代码建标的）；**不传 `price_cents`**（两侧单价由金额 ÷ 份额反算）；`amount_cents` 占位 0（服务端按 FIFO 消耗算出**结转成本**写行金额锚点）；不带 `to_account_id`（不跨账户）、不带 `funding_account_id`（无现金腿）。
- 多腿拆单：一笔源转换拆多腿时，按**单腿一条记录**拆成多条 `convert`，各腿带自己的转出份额与转出金额。各腿转出份额有**逐腿直读** / **金额占比拆分**两写，按快照实际形态择一（这是快照口径假设，迁移侧须在真实数据上核对后固定其一，勿在同批混用）：① **逐腿直读**——每腿快照记录自带转出份额（`share` / `successShare`，如一笔转出 006793 拆两腿读得 684.76 / 2791.12 份），直接填 `quantity`；② **金额占比拆分**——快照只给转出总份额时，按各腿转出金额占比拆分总份额、**尾差末腿**。同一转出标的的金额与份额成比例，两写结果应一致。
- 成本结转与分摊：转入批次成本 = 被消耗转出批次原始成本（服务端 FIFO 逐批次取用、耗尽闭合精确到分），**不按转入日市值重置**；多腿分摊口径 = 按各腿转出金额占比、尾差末腿；转换本身对已实现盈亏贡献恒为 0；手续费如实记录在转换记录上、不进支出报表、不摊入持仓成本。
- 幂等键：多腿即全节「一行拆多笔」，以腿序作序号派生 `{源文件名}:{行号}:{腿序}`（如 `:1` / `:2`）——腿序是身份的一部分，勿复用同键。
- 纠错：**修改接口不允许把 kind 改成 / 改出 `convert`**（码化中文错误）——存量「假卖出 + 假买入」按「软删假买 / 假卖（删买级联软删其在用卖出）→ 重建 `convert` → 按快照重导被级联的后续卖出」纠错，「不删后重导」纪律不变；转换转出份额不得超当前持仓；误录的转换软删即整笔回退（级联软删其在用后续卖出并精确回补持仓与批次）；但转入批次已被后续在用转换消耗时删除被守卫拒绝（否则会抹掉下游转换的转出消耗记录），须从最后一腿往前处理。
- 对账：余额核对——`GET /api/v1/accounts/balances`（**含黑洞账户**）在转换落账前后应**完全不变**（无现金腿）；份额换手——转出标的持仓减 `quantity`、转入标的持仓增 `to_quantity`；盈亏——转换不贡献已实现盈亏；全平仓后 Σ 已实现盈亏 = Σ 卖出金额 − Σ 买入金额 − Σ 转换结转成本（无转换批次时退化为「Σ 已实现盈亏 = Σ 卖出金额 − Σ 买入金额」）。

## 份额调整（split，场外基金与股票同构）

- 形态：一笔份额调整 = **一条** `split` 记录，表达**同一投资账户内、单标的**的非现金份额变动（折算 / 结转 / 送股 / 缩股）；**无现金腿**——钱不进银行卡、也不进投资账户现金池。**禁止**落成 `buy` / `sell` 借位：那会虚增买入成本、扭曲已实现盈亏，并继续污染黑洞账户。
- 字段位置：`account_id` = 投资账户；`instrument_id` = 被调整的标的（类型不限，基金 / 股票同构）；`quantity` = **带符号份额增量** Δ——`+` 折算 / 结转 / 送股、`−` 缩股，Δ 不能为 0；`amount_cents` 必填、恒填 0；**不传** `price_cents`（提供即 400）；`fee_cents` 只能为 0（非 0 拒绝）；**不传** `to_instrument_id` / `to_account_id` / `funding_account_id` / 商户 / 分类 / 保单（携带即 400 码化中文报错，字段级约束见契约说明）。
- 守卫：`+Δ` 同样要求该标的在该账户**有在用持仓**——价值已含在原批次，零持仓无从重述批次成本；`−Δ` 要求缩股幅度**严格小于**当前持仓（等号会让每份成本凭空消失，被拒绝）；账户必须是投资账户。
- 成本与盈亏：按比例重述在用批次成本（每份成本稀释 / 浓缩，批次总成本不变）；`split` 本身对已实现盈亏贡献恒为 0，全平仓恒等式「Σ 已实现盈亏 = Σ 卖出金额 − Σ 买入金额 − Σ 转换结转成本」**不引入新项**。
- 对账：`GET /api/v1/accounts/balances`（**含黑洞账户**）在调整前后**完全不变**（这是无现金腿的弱表述）；份额换手——该标的持仓数量增减 Δ；**持仓市值、未实现盈亏与净资产随份额变化**（钱没动不等于资产口径没动），按调整前后两组数字分别核对；读回 `GET /api/v1/transactions?kinds=split` 可见落账行（行金额恒 0）。
- 纠错：**修改接口不允许把 kind 改成 / 改出 `split`**（码化中文错误）——改出 / 改入只能「软删 + 重建」；`split` 行本身可全字段替换修改、可软删，但本行重述过的批次若已被**在用**后续交易（卖出 / 转换 / 后一次 `split`）消耗，改 / 删会被码化守卫拒绝（精确回补会篡改下游账面），须从最后一笔往前处理；发现误录时不要用买 / 卖借位掩盖、也不要手工改持仓。

## 现金分红（dividend，股息 / 基金分红 / 投顾组合分红同构）

- 形态：一笔现金分红 = **一条** `dividend` 记录，表达**归属于某标的**的现金收入。**禁止**落成普通 `income`（投资域不可见、累计收益漏算分红）、也不得落成 `sell`（那会虚增卖出与已实现盈亏）。
- 字段位置：`account_id` = **到账账户**（任意在用账户——银行卡 / 现金 / 投资账户皆可，不要求投资账户、也不要求当前有持仓：除息 / 到账错位合法）；`currency_code` 须与该账户币种一致；`instrument_id` = 分红归属标的（标的解析见「基金申赎」节：带代码先按代码查询再以真实代码建标的）；`amount_cents` = 分红金额（分，必须 > 0）；`date` = 到账日。**不传** `quantity` / `price_cents` / `fee_cents`（只能省或填 0）/ `to_instrument_id` / `to_account_id` / `funding_account_id` / 商户 / 分类 / 保单（携带即 400 码化中文报错，字段级约束见契约说明）。
- 成本与盈亏：分红**不摊薄持仓成本**、不触碰 FIFO 批次、不产生已实现盈亏；它计入「累计收益」的**第三腿**——累计收益 = 未实现盈亏 + 已实现盈亏 + 累计分红（按币种分组，不跨币种折算）。
- 对账：到账账户余额按 `amount_cents` 增加（计入收入口径、不进支出报表）；读回 `GET /api/v1/transactions?kinds=dividend` 可见落账行（行金额 = 分红金额），来源列显示归属标的；持仓份额与持仓成本不变。
- 纠错：**修改接口不允许把 kind 改成 / 改出 `dividend`**（码化中文错误）；`dividend` 行可就地修改（`PUT` 全字段替换，扩展行重建）；误录的分红行软删即整笔回退（余额与累计收益实时重聚，无物化状态）。
- 红利再投（DRIP）不在本口径：再投份额按 **0 手续费 `buy`** 模拟，不落 `dividend`（不产生现金腿、不计入累计收益的分红腿）。
