# Verification Ladder

按改动类型选验证档位的纪律——什么改动跑哪一档检查与测试，中间轮次跑什么、交付前跑什么。触发条件见 `AGENTS.md` 的「开始前：按触发条件读文档」。

先例与动机（#863）：一次会话为「确认修复没引入新问题」跑了 6 轮全量（每轮约 6 分钟），其中中间几轮只需最小档；同期发现的 6 个缺陷中 3 个靠核查调用点与写复现测试，不是靠跑测试。过度验证的代价是真实的：它挤占本该用于核查的时间。本页目标：**全量验证一轮 ≪ 修复处数**。

## 验证工具与量级

| 命令 | 覆盖面 | 量级 |
|---|---|---|
| `cargo test --lib <过滤>` | 域单测（决策钉住层）；过滤为测试名子串，含模块路径（如 `<域>::`） | 秒级 |
| `cargo test --test e2e -- --name "<场景子串>"` | BDD 场景子集 | 秒级 |
| `pnpm exec vitest run <文件路径子串>` | 前端测试子集 | 秒级 |
| `bun scripts/check-<x>.ts` | 单项守门（结构 / 命令 / i18n / 测试桩 / 测试支持 / 后台服务 / 样式块 / 弹窗表单） | 秒级 |
| `./scripts/check.sh` | 静态检查（vue-tsc / oxlint / clippy / fmt / 文档一致性）+ 全部守门脚本；**不跑任何测试** | ~1 分钟 |
| `cargo test --all-targets`（src-tauri 下） | Rust 全部测试目标（lib / 集成 / bin 一并编译并运行） | ~1 分钟 |
| `pnpm exec vitest run` | 前端测试全量 | ~1 分钟 |

量级是数量级参考，不是 SLA；冷编译（新 worktree 首跑）另计。

## 选档判据：什么会红？

选档不靠估改动「大小」，靠回答一个问题：**这个改动如果写错了，哪个检测器会红？**

- 域规则错（折算、写入编排、余额规则、查询语义）→ 域单测红。
- 接线 / 分层 / 漏门错（壳层调用、命令注册、白名单、守门对象）→ **任何断言都不会红**，只有守门脚本红。#863 实证：两个漏门与一个分层违规由守门脚本与人工核查发现，测试全程绿。
- 用户可见行为错（旅程、交互、文案）→ e2e 或前端测试红。

判断不了就往高档走。即使误判，交付前的全量一轮会兜底（见下），误判代价有界——这是阶梯安全性的结构依据，不依赖「中间轮次全量没发现过问题」这类经验归纳。

## 阶梯：按改动类型

| 改动类型 | 中间轮次最小档 |
|---|---|
| 域内单点逻辑（域目录内的规则 / 折算 / 编排） | `cargo test --lib <域>::`；前端逻辑则 `vitest run <文件>` |
| 跨切面接缝 / 分层 / 接线 / 入口（壳层、命令注册、白名单、守门脚本自身） | `./scripts/check.sh`——守门脚本才是这类改动的真检测器——外加被触碰域的单测 |
| 用户可见行为 / 端到端旅程 | `cargo test --test e2e -- --name "<场景子串>"` + `pnpm exec vitest run <文件>` |
| 仅文档 / 仅文案 | `./scripts/check-docs.sh`；涉及文案加 `bun scripts/check-i18n-keys.ts` |

一次改动可命中多行：取并集，都用过滤形态，保持中间轮次秒级。

## 多轮修复的节奏与硬门

- **中间轮次**：每处修复后只跑该改动类型对应的最小档，修到最小档绿为止。不要用跑全量「求安心」——那是在挤占核查调用点、写复现测试的时间；#863 的中间几轮全量从未发现额外问题，有信息量的是 `check.sh` 与人工核查。
- **最小档红了不升档**：修到最小档绿。连续多轮同档位红，说明对改动面的判断错了——回到「识别受影响域」重看，而不是改跑全量。
- **硬门（不可省略）**：建 PR 前在分支 tip 跑**一轮**全量：`./scripts/check.sh` + `cargo test --all-targets`（src-tauri 下）+ `pnpm exec vitest run`。分支中间 commit 不要求各自全量。
- 中间轮次的最小档**不是**提交门槛，交付前全量一轮**才是**。阶梯防的是「每修一处跑一遍全量」，不是「跑全量」本身。

## 例外：全量提前

依赖升级（`docs/agents/dependency-upgrades.md`）要求升级前先跑基线、升级后对比，天然是全量两轮，不属于本阶梯的「中间轮次」，按该专项文档执行。
