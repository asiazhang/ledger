# ADR-0044: 失效信号发射收单点——「写命令发哪个信号」由映射单点承载

- 状态：已接受
- 日期：2026-08-31
- 作者：Ledger 项目
- 关联：spec #311；ADR-0012（参考失效信号）、ADR-0031（价格失效信号）、ADR-0033（行为层编排入口）

## 背景

「写命令成功后要发哪个失效信号」这条规则，此前靠散落样板执行——IPC 命令壳尾部手写
`emit_reference_changed(app, "命令名")`，HTTP 端点壳尾部手写 `emit_ledger_changed_if_present`，
物品域走第三条路（`*_internal` 收 `notify` 回调注入），价格域走第四条路（sync / 按代码即拉 /
手动报价四个各自独立的 `should_emit_prices_changed` 判定）。信号知识藏在调用方而非一处，
漏发、错发（决定 reference store 四表新鲜度与价格失效，ADR-0012/0031 消费侧的命脉）在
测试里不可见——集成测试传 `app: None` 跳过发射分支，BDD 仅物品域有注入点计数。

本决策确定「写操作 → 失效信号」的单点形态，把两个适配器壳（IPC 壳与 HTTP 壳）退化为纯转发通道。

## 决策

1. **单点 = 一个纯函数 `signals_for(写操作, 结果证据) -> 信号集`**。形态为**静态映射 + 结果证据
   混合**：命令身份是静态的一半，`结果证据`（小型 typed enum，如 `PriceWritten(bool)` /
   `BlackHoleCreated(bool)` / `MerchantCreated(bool)` / `Noop`）承载条件的一半。两个壳只做
   「调纯函数 → 遍历信号集 → 发射」，不再各自持有判定知识。纯函数可直接断言、不依赖 Tauri 运行时。
   **修订（spec #523，ADR-0073）**：「调纯函数 → 遍历信号集 → 发射」进一步内化进统一写入口
   `write_entry`，壳层连这一步也收敛为一行调用；映射单点与穷尽裁决地位不变。
2. **键是跨两壳共享的强类型「写操作身份」enum**，不沿用 `REFERENCE_WRITE_COMMANDS` 的命令名字符串。
   字符串会漂移；HTTP handler 无命令名（axum）、且两壳命令面不对称，强类型键是「两壳不各自漂移」的正解。
3. **映射闭集穷举**：所有写命令都登记（含零信号与交易/预算/定时/settings 域），「漏登记」由
   穷尽 match（编译期）+ 交叉核对测试（命令→WriteOp 声明表 × 映射表）两道兜底，「零信号」是显式行而非缺行。
   **修订（spec #523，ADR-0073）**：手写声明表（IPC 158 行 / HTTP 32 行）消亡为源码扫描
   派生物，交叉核对测试改形为「扫描 `write_entry` 调用点提取派生表 + 反向守门（`db::write`/
   发射调用必经入口）+ 例外白名单」，「漏声明即红」的守门价值不降级；穷尽 match 与零信号
   显式行不变。
4. **条件信号三类归一化**：
   - 价格写入（`written > 0` / `price_written`）：各写操作把结果归一化到证据 enum，
     映射表只保留一份 `written > 0` 判定，消除「第四处判定与第一处口径漂移」的风险；
   - 余额调整按需建黑洞账户（`adjust_account_balance` → 仅 `BlackHoleCreated(true)` 发 `ledger:changed`）；
   - **交易写「即建商户」**：行为层 `plan` 在入参带 `merchant_name` 且未命中时即建商户
     （写 `merchants` 表，第四张参考表），证据经行为层 `create`/`update` 返回的
     `WriteEvidence { merchant_created: bool }` 外传，batch 聚合「本批是否任一即建」；
     壳层据此发 `ledger:changed`——这是此前静默漏发的真实缺陷（HTTP 导入路径商户字典陈旧）。
5. **三个 `ledger:*` 信号全收编**：`ledger:changed` / `ledger:prices-changed` /
   `ledger:backups-changed` 都进映射；自动备份深路径（无命令身份、经 `EVENT_APP` 镜像句柄）登记为
   映射表的一个特例条目，不做命令键。
6. **`create_market_price` 登记为刻意零信号**：它写 `market_prices` 现价缓存、被价格失效信号定义
   覆盖，但属「issue #291 前」的半成品通道、前端零调用点，补广播只会制造「发了但没人听」的假一致性。
   登记为零信号并附动机注释 + TODO 指向 #291 的淘汰/合并路径（`record_manual_price` 已承载该信号）。
7. **落点 = 独立映射模块**（`signals.rs`），`events.rs` 退化为纯发射器（事件名常量 + `emit_*` 入口 +
   `EVENT_APP` 镜像），把 `REFERENCE_WRITE_COMMANDS` / `is_reference_write` / `emit_reference_changed`
   这堆「判定知识」迁进映射模块——`events.rs` 现有的职责已混了「知识（谁发什么）」与「机制（怎么发）」，
   正是本决策要拆的两半。
8. **物品的 `notify` seam 保留**：`*_internal` 的 `notify: &mut dyn FnMut()` 是 BDD 计数注入点，
   信号决策在壳层走 `signals_for`，内部函数签名与 BDD 注入点零改动——notify 只是发射钩子，不再是决策点。

## 理由

1. **映射是知识、发射是机制，知识必须单点**。散在四处的发射样板正是「bug 藏在调用方式里」的形状；
   纯 `a`（静态映射表）表达不了条件信号（价格/黑洞/商户三类都取决于本次写的结果），纯 `b`（运行时返回）
   要把返回形状塞进所有 `*_internal` 与 HTTP handler——混合形态让知识可直测、机制可复用。
2. **条件证据是写操作的自然返回值**，不是可变状态。交易入口证据外传被锁死在三个交易入口
   （其余命令的壳层早已持有证据），比可变容器显式、可直测、不穿透 `db.write` 闭包。
3. **穷举闭集才能把「不发」变成决策而非遗漏**。开集映射下「忘了登记」依旧静默；强类型 enum +
   穷尽 match + 交叉核对测试，是「映射可查、漏配可测」的完整闭环。
4. **不改任何信号语义与触发条件**。本决策只收编发射位置与证据外传；`ledger:changed` 语义锚定
   「参考数据变更」（ADR-0012）不动，物品复用同名事件（ADR-0014 独立域订阅者）与
   `create_market_price` 刻意零信号都只做显式登记，不翻既有语义基线。

## 代价

1. **交易入口返回形状扩张**：`create`/`update` 从 `Result<String>` 扩为携带 `WriteEvidence`，
   改动面 = 交易行为层两入口 + batch/IPC/HTTP 三处调用点——范围锁死、无二义。
2. **穷举映射是持续维护负担**：新增写命令须声明 WriteOp + 进映射表 + 过交叉核对测试；
   漏接线在测试期即红，这是「漏发不可见」缺陷的交换价。
3. **`create_market_price` 刻意零信号保留了一个已知陈旧点**：该通道无消费方、待 #291 淘汰，
   登记为决策而非修复——语义基线与既有信号消费方不变。

## 替代方案

- **纯静态映射表（spec 选项 a）**：表达不了三类条件信号，会把「发不发」逼回调用方分支，否决。
- **纯运行时返回待发信号清单（spec 选项 b）**：准确性随调用路径，但返回形状扩张覆盖所有命令与
  HTTP handler，且知识仍沉在调用方，否决。
- **即建商户的瞬间在行为层直接发信号**：行为层拿不到 AppHandle，且把决策点又拆回行为层，违背本决策初衷，否决。
- **`create_market_price` 按定义补齐价格信号**：语义一致但给无人订阅的半成品通道发广播，
  制造「发了但没人听」的假一致性，否决——登记为零信号。

## 后果

1. IPC 壳与 HTTP 壳只剩转发职责，两壳不可能再各自漂移出不同发射行为。
2. 「哪个命令发哪个信号」回归测试可见：直打 `signals_for`，每个写操作一条断言（含零信号显式断言），
   不 mount、不起 Tauri。
3. 既有 BDD 信号计数注入点（物品 `notify` seam）保持兼容，场景零改动。
4. 词汇表同步：参考数据域修正「交易类写入不触发（不改参考表）」的断言（商户即建例外），
   物品域明确「复用 `ledger:changed` 的独立域订阅者」措辞。
