# ADR 0051: 保单（保险域）MVP 决策——建档 / 缴费复用订阅 / 流水直挂 / 现金流入口径 / 生命周期 / 侧栏分组与键位上限

- 状态：已接受
- 日期：2026-09-01
- 作者：Ledger 项目

## 背景

Ledger 此前没有保险概念：保费只能作为普通支出挂「金融保险」分类记一笔，无法回答「我有哪几张保单、每张何时扣款、交了几年、赔了多少」。经设计评审确定保单域 MVP 范围与一批跨域决策，本文记录决策与取舍。业务语义见保险分域词汇表 `docs/contexts/CONTEXT-insurance.md`，界面语义（侧栏分组 / 键位上限）见界面状态与交互域词汇表 `docs/contexts/CONTEXT-ui-interaction.md`。

## 决策

### 1. 保单建档：消费型静态合同档案，单列小域

- 新增保单实体（Policy），仅覆盖**消费型**语义（保障型费用支出 + 收入侧资金流）；储蓄/返还型保单的现金价值资产化（进净资产）明确**缓行**——涉及现金价值估值口径（数字谁提供、按什么频率），复杂度是另一个量级，无消费方不建。
- 保单是静态合同档案，与物品域 Item 同为独立领域概念：不是字典行、不是流水、不是生成流水的协议。单列小域先例：物品（ADR-0014）、预算（ADR-0029）。
- **备选与否决**：纯流水记录（保司/单号写备注）——多保单管理问题（列表、扣款日、累计统计）无解；储蓄型资产化进 MVP——估值口径未定，缓行留独立票。

### 2. 缴费复用订阅形态，不另造引擎

- 保费扣缴协议 = 定时计划域订阅形态（Subscription），周期规则含按年（保费年缴场景已覆盖）；价格变更 = 取消旧计划 + 按新金额重建、暂停/取消等语义全部继承（ADR-0023 决策三 / ADR-0024），不另造缴费引擎——生成流水只有定时计划一条路是既有域边界。
- 协议持保单引用（方向：协议 → 保单），1 张保单可对应历史多段协议（费率变更重建的历史多段性）。
- **建档不强制缴费协议**：趸交/缴清保单纯档案存在，保费手动补记后经保单引用归属。与物品域「无交易不可录入」（ADR-0025）不冲突——物品的成本语义完全来自关联交易，保单的静态要素不依赖任何流水。
- **备选与否决**：保单域自带缴费引擎——重复建设且撕裂生成路径；强制绑定协议——把趸交/缴清保单挡在门外。

### 3. 流水直挂保单（归属不经推导链）

- 保费（`expense`）与保单现金流入（`income`）流水携带**可选**保单引用；不挂保单的流水行为与现状完全一致。
- 归属的唯一事实是流水直挂：「缴费协议 → 期次 → 流水」推导链在手动补记场景断裂，不作归属依据——否则保单统计必然漏掉手动补记的保费。
- schema 尚未发布（发布约定：未发布期 schema/API 可自由修改），加列与加表均合规。
- **备选与否决**：仅经计划推导、transactions 不动——手动补记无法归属，保单视角统计漏数，而「单的视角」正是本域核心价值。

### 4. 保单现金流入记 income，非 refund

- 理赔款、退保款、满期返还统一记 `income` + 挂保单；三者记账语义无差别，不为场景造专名（统称保单现金流入）。
- 口径动机：`refund` 在支出净额度量中是冲减项（expense_net = 毛支出 − 退款），理赔若记退款，「保费支出」统计被冲小、口径失真；且理赔与原保费不是同一笔经济往来，refund 的「原交易部分退回」语义不符。
- **备选与否决**：记 `refund`——仅当用户想要「医疗实际负担 = 保费 + 医疗费 − 报销」这类冲抵报表时有理，但扭曲保费口径的代价更大；需要冲抵视图将来可用报表层口径另解，不动记账语义。

### 5. 生命周期与删除

- **到期判定**：由保障期间推导（止日期非空且早于今天 → 已到期），无手动状态字段——可推导的状态不持久化（先例：预算永久滚动，ADR-0029）。
- **删除**：软删除；已删保单不进列表，但其上历史流水引用**保留不置空**——保单是档案非字典，置空会毁掉已缴/已赔历史（与商户字典行硬删置空的先例刻意不同：字典行无历史语义，档案有）。

### 6. 保单视角统计：实时推导不落库，不做全局口径

- 单张保单统计（累计已缴、累计现金流入、下期扣款日）按流水忠实统计、不摊销、不落库（与 SubscriptionSpend 实际花费口径同纪律）；下期扣款日来自其缴费协议的期次。
- 年度保费总额等全局口径**不做**：无下游消费方的派生聚合不建（对照 AnnualBudgetTotal——它有财务自由度作消费方，ADR-0048）。

### 7. 保司复用商户字典；AI 导入不识别保单

- 保险公司字段引用商户（Merchant）字典——保险公司即保费流水的付款对象（商户 =「花给谁」），复用精确匹配/软删/改名语义，不建第二份保司字典。
- **演进（ADR-0082）**：保司复用商户字典被推翻——保险公司升格为保险域自有独立字典（Insurer），保费流水不再挂商户（付款对象语义由保单保司承担），并预置常用国内保司种子；本条作废，以 ADR-0082 为准，历史照录不删。AI 导入不识别保单的边界不变（保司字典同在 AI 契约之外）。
- AI 导入（AI API）不识别、不建档保单：建档不涉及账户余额变动，在 AI 读回验证契约（按 InvolvingAccount 余额口径对账）之外；待真实「保单文档导入」需求出现再扩端点。

### 8. 界面：独立视图进侧栏「资产」组；数字键上限诚实化

- 保单为**独立视图**（先例：预算/物品各有视图），不挂靠其他视图作页签；新建/编辑为弹窗，缴费协议区可折叠可选（对应决策 2 的建档不强制协议）。
- 侧栏改为**分组**形态（记账 / 资产 / 洞察三组 + 固定项），组固定、组内右键排序；保单入「资产」组（投资 = 金融资产、物品 = 实物资产、保单 = 合同权益）。
- ViewShortcut 修订：数字键位覆盖**前 10 个视图**（物理上限 ⌘1–⌘0，AI 固定 ⌘0、设置固定 ⌘,）；可排区扩为九项后**末位无键位**（默认序即保单），右键重排即换谁无键位——「位置即键位」哲学的诚实延伸。
- **落地校正（issue #360）**：保单按域职责归入「资产」组内末位（全局可排区第 7 位、键位 ⌘8），默认序下无键位的是可排区第 9 位（洞察组末位视图，出厂序为搜索）——正文「默认序即保单」为设计期措辞，以本注记与代码为准。
- **演进（issue #371/#372，ADR-0055）**：低频的保单其后迁入侧栏「更多」聚合视图——本节「保单入资产组」的放置决策按收纳策略演进（域归位原则对高频新视图依然成立），「资产」组二项化、可排区九→八，键位带 2–9 十键十视图全占——上文「末位无键位」的 wart 与本节键位表述随之作废，以 ADR-0055 为准。
- **术语澄清（ADR-0064）**：本节「物品 = 实物资产」是解释资产组构成的设计期措辞；「实物资产（PhysicalAsset）」自此为实物资产域的正式术语（要跟踪估值并计入净资产的大件实物，如房产、车辆），物品域不使用「资产」自称（见物品域词汇表别名边界）——资产组构成的表述以 ADR-0064 为准。
- **备选与否决**：平铺 12 项——超认知舒适区，分组迟早要做；扩键位池（⌘⇧数字 / ⌘字母）——与系统快捷键冲突面大，记一笔快捷键决策已否决过组合键双轨；搜索降级腾位——独立界面重构，不归保单域 MVP，可另票。

## 后果

- schema：新增保单表、流水可选保单引用、订阅计划扩展表保单引用（未发布期，就地实施）。
- 词汇表：新增保险分域；界面域新增「侧栏分组」、修订 ViewShortcut / ViewState。
- 缓行清单（留独立票）：储蓄型现金价值资产化、⌘K 命令面板（视图快捷键兜底）、搜索降级、AI 识别保单。
