# ADR 0067: 余额与净资产持久化缓存——写路径整体重算 / 五出口切缓存 / 读探针指纹自愈

- 状态：已接受
- 日期：2026-09-04
- 作者：Ledger 项目
- 关联：issue #491（父 #489 B2）；前置 #490（结构索引，V016）；性能基准 ADR-0062（ledger-perf）；口径真源 ADR-0011（kind→度量矩阵）；净资产口径 ADR-0020；余额调整 ADR-0026；行为层编排 ADR-0033（定时引擎例外接缝）；置脏收口 ADR-0032；性能基准数据集 ADR-0062

## 背景

ledger-perf 基准（ADR-0062，50 万笔库）实测两项读路径 p95 ~88s：全账户实时余额与首页净资产总览。两者每次读取都对 `transactions` 全量实时聚合（`account_flow` 口径），个人账本规模下读放大随流水线性增长，已到不可用程度。

ADR-0019 曾裁定「个人规模下持久化余额收益趋零」——该前提在 50 万笔实测下不成立，本决策将其推翻：引入**持久化缓存**消灭读路径全量聚合，同时以「写路径同事务整体重算 + 读探针指纹自愈 + 手动审计兜底」保证任何写入序列下缓存与实时计算完全一致（B2 验收：p95 ≤ 200ms）。

## 决策

### 1. 两张派生缓存表（V017），单一事实来源不变

- `account_balance_cache(account_id PK, balance_cents, updated_at)`：每账户一行；`net_worth_cache(id=1 单例, fingerprint, native_currency, net_worth_cents, 三腿分项, updated_at)`。
- 两表均为**派生缓存**：单一事实来源恒为 `accounts` / `transactions` 及各净资产贡献表；缓存污染/缺失不承载独立业务语义，经手动审计修复。不参与同步、不参与备份语义（恢复路径替换库文件后重跑迁移，V017 回填天然覆盖旧库）。
- 迁移内以与 Rust `account_flow_expr` 同一 kind→符号矩阵的唯一表达式回填全账户余额；一致性不靠人工比对，由迁移回填测试（回填值 == 实时重算）锁定。净资产缓存不回填——首读由读探针自愈。

### 2. 写路径：同事务整体重算（禁止增量加减）

- 新接缝 `refresh_account_balances`（指定账户）与 `refresh_all_account_balances`（全量，审计修复专用）：单条 `INSERT … SELECT … ON CONFLICT DO UPDATE` 按口径表达式整体重算，表达式由 `account_flow_expr` 生成（与实时计算同一真源）。
- 挂钩点全部在既有事务内：Writer 接缝 `insert_row`（创建单一收口，覆盖手动/批量/余额调整/buy/sell/定时引擎例外）刷新 `account_id ∪ to_account_id`；`update_row` 刷新旧∪新引用并集；行为层删除入口刷新原引用；账户创建（含黑洞即建）建缓存行，删除/修改随写刷新。
- `updated_at` 毫秒精度且每次无条件刷新（即使余额值未变）——这是净资产指纹判定「源已变更」的依据；秒级源表时间戳的既有冻结约定不在此改动。
- 禁止增量加减：任何「+Δ/−Δ」式维护都会在回滚、重放、审计修复路径上漂移，整体重算让正确性与口径单一真源结构性绑定。

### 3. 读路径：五出口切缓存，缺失即码化错误

- `list_account_balances_with_visibility`（账户列表/余额页、dashboard 余额腿、财务自由度、余额调整取数、HTTP/AI 清单五个出口的同一入口）改读缓存；实时计算函数（`compute_balance` 等）保留为**实时权威**，供测试与审计比对。
- 缓存行缺失视为不变量破坏：报码化错误（`balance.cache-row-missing`）引导审计修复，**不静默回退实时计算**——静默回退会把缓存退化重新变成读路径常态，性能目标失效且漂移不可见。

### 4. 净资产读探针指纹自愈（无定时任务、无写挂钩）

- 指纹 = 各贡献表（accounts / transactions / security_lots / market_prices / exchange_rates / physical_assets / physical_asset_valuations[created_at] / account_balance_cache）`MAX(updated_at)` 的命名拼接；`account_balance_cache` 的毫秒时间戳为秒级源表补上同秒区分度。
- 首页净资产总览改读探针：指纹命中且基准币种一致 → 直接返回缓存终值；失配或无缓存行 → 既有实时聚合重算并回填。源表写入天然推进 `MAX(updated_at)`，无需任何写路径挂钩或定时任务。

### 5. 手动审计兜底（唯一新增接缝）

- IPC `audit_balance_cache`：全账户实时重算 vs 缓存逐户比对 → 修复（整体重算回写）→ 返回差异报告（含缓存缺失记 None 的行）。
- 修复属派生数据自愈：不经 `db.write` 置脏包装、不发失效信号（与设置/恢复同列豁免形态，ADR-0032）。

## 备选与否决

- **读路径静默回退实时计算**：漂移不可见、性能目标随回退失效；否决。
- **写路径增量加减维护缓存**：回滚/重放/修复路径必然漂移，且每条写路径都要懂全部 kind 符号——与口径单一真源冲突；否决。
- **净资产也挂写路径刷新**：贡献表多（行情、汇率、实物资产）且更新频率高，挂钩面大收益低；读探针指纹已足够自愈；否决。
- **后台定时任务对账**：引入调度基础设施，个人单机场景过重；手动审计（用户可从设置触发）+ 读探针自愈已覆盖；否决。

## 影响

- 50 万笔库两项读基准 p95 从 ~88s 降至 ≤200ms（读路径 O(账户数) 行读而非全量聚合）。
- 写路径每笔交易多一次对受影响账户的聚合重算（索引覆盖下 O(该账户流水)），写入延迟增量可忽略；强一致性由同事务重算保证。
- `check.sh` 全量测试与 ledger-perf 基准纳入验收；迁移回填测试锁定 SQL 表达式与 Rust 矩阵不漂移。
