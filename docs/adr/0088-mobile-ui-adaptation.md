# ADR-0088: 移动端 UI 适配——两轴模型、840dp 单断点、导航抽屉与触控交互替换

- 状态：已接受（已落地；随移动端在 Unreleased 交付，grilling 定稿）
- 日期：2026-09-08
- 作者：Ledger 项目
- 关联：ADR-0074（Android 发布基建，其实施落地是本 ADR 分期收尾真机冒烟的前置；其决策 5「UI 移动端适配另立任务」由本 ADR 承接）；ADR-0079（对话框排版，本 ADR 决策 8 补移动档条款）；ADR-0035（弹层注册表，系统返回语义复用其开/关判定）；ADR-0063 / ADR-0065（侧栏分组与键位带——移动档不渲染键位带，信息架构与存储零改动）；ADR-0061（会话内保留，移动档不改变保留粒度）

## 背景

ADR-0074 决策 5 把 UI 移动端适配留作另立任务，本 ADR 即该任务的设计定稿。现状事实（2026-09-08 探查）：全前端仅 1 处媒体查询且为 `prefers-reduced-motion`；App 壳为侧栏 + 内容区硬布局，窗口最小宽 900；交易表固定列总宽 965px 靠横向滚动兜底；行操作主入口右键、多处信息收进悬停 tooltip（分类构成占比、金额省略全文、来源列类型全称）、两套快捷键（⌘1–9 视图键位带 + 记一笔裸键）、遮罩点击不关 + ESC 关弹层——全部建立在「鼠标 + 键盘 + 宽窗口」三假设上，触屏无一有替代路径。

目标设备：6.5–6.9 寸 Android 手机（竖屏约 360–412dp）与 Android 平板（主横屏，宽度与桌面窗口重叠）。完成度标准：作者真机日常顺手，不为外部用户加码（无障碍、商店合规等留待有外部用户时另议）。

## 决策

### 1. 两轴模型：宽度定布局、输入方式定交互

把「移动端体验差」拆成两个正交维度：**宽度轴**（窗口分级）决定信息架构与展示密度；**输入轴**（触控 / 指针键盘）决定交互组件形态。平板横屏 = 桌面布局 + 触控交互——「平板直接用桌面 UI」只解决了宽度轴，右键 / hover / 快捷键问题一个都没解决，这是本模型立项的动机，也是后续所有决策的分类基础。

- **备选与否决**：单一「移动 / 桌面」二元开关——把平板误伤为任一极，无法表达「宽屏 + 触控」组合。

### 2. 窗口分级：840dp 单断点，minWidth 降为 360 随壳票落地

单一断点 **840dp**：≥840 为桌面档（既有布局），<840 为移动档。断点常量唯一收口（窗口分级 composable 供 JS 条件渲染，CSS 媒体查询消费同值）。

- 桌面窗口最小宽（现 900）恒大于断点，桌面端永远不会落入移动档——断点实际只服务 Android 屏幕。
- **minWidth 900 → 360 随移动导航壳票落地**：此前保持 900，避免出现「能缩进但布局不支持」的中间态发布；此后 <840 成为受支持形态，桌面用户缩窗进移动档是附带能力，开发期全程桌面缩窗验证、不依赖 Android 基建。
- **备选与否决**：Material 3 三档（600/840 双断点，为平板竖屏单独立 medium 档）——平板竖屏是次要姿态，先复用移动档，真机用出不适再拆第二断点（YAGNI）。

### 3. 平板横屏：桌面布局原样 + 触控轴替换，不做双栏增强

≥840 的触屏设备直接用桌面布局（960–1280dp 下侧栏 160–200px + 内容区已宽松），只做输入轴替换（决策 6、7）。master-detail 双栏等「利用宽度」的增强不进本轮，真机用出痛点再议。

### 4. 移动导航：顶栏 + 导航抽屉，信息架构零改动

<840 时侧栏替换为顶部应用栏（当前视图名 + 汉堡按钮）+ 导航抽屉，完整映射既有「侧栏分组 + 组内收纳 + 固定项」层级；ViewState（上次视图、组内顺序、收纳清单）语义与存储零改动，抽屉只是侧栏的另一壳层渲染。

- **备选与否决**：底部标签栏——5 槽装不下 15+ 视图，且与用户自定义收纳冲突；底部栏 + 抽屉混合——两套导航心智。

### 5. 记一笔悬浮按钮

移动档交易页右下 FAB：点开五枚大号类型选择（支出/收入/转账/买入/卖出），经弹窗意图编排的记一笔意图（携带类型）进入对应表单。二击进表单、零表单内部改造；类型选择是独立轻弹层，入弹层注册表。

- **备选与否决**：FAB 直开支出表单（省一击，但要动表单内部类型切换）；长按 / 速拨（可发现性差）。

### 6. 触控轴替换：行菜单第二入口常显、快捷键退役渲染、hover 一击可达

- **交易行「⋯」按钮常显**（桌面也显示，对齐账户行既有先例），与右键共用 RowContextMenu 同一 open 入口、全平台一致、零输入轴依赖。**长按否决**（与滚动冲突、可发现性差）。备选「仅触控轴显示」否决：省桌面一列按钮，但与账户行现状不一致、多一特例。
- **触控轴下快捷键退役渲染**：ViewShortcut 不渲染 ⌘ 提示、CreateShortcut 不绑裸键监听；指针轴行为不变。
- **hover 原则**：悬停才可见的信息，触控档必须一击可达——空间够则常驻，不够则点按显示。金额省略全文、分类构成占比、来源列类型全称三项逐项落实施票，ADR 只立原则。
- 输入轴信号：hover / pointer 媒体查询收口同一 composable，与窗口分级并列为两根轴的唯一事实源。

### 7. 弹层关闭语义：遮罩不关不动，系统返回键作第四显式通道

- **点遮罩不关原则不动**（issue #249 误触零代价；触屏误触率更高，动机更强）。
- **Android 返回键桥接**：有弹层时返回 = 关最上层弹层（经弹层注册表判定，ESC 的移动等价物）；无弹层时 = 路由回退；路由栈底交还系统。弹层显式关闭闭集从「提交 / ✕ / ESC」扩为四通道，桌面档无此通道、两档语义互不渗透。

### 8. 弹窗移动档：AppModal 全屏化，不引入 bottom sheet

<840 时统一弹窗薄封装走**全屏化分支**：近全屏卡片、标签上置（居左在窄屏挤压输入宽度）、按钮行底部固定；对话框排版（ADR-0079）词汇表补移动档条款，分档宽度（sm/md/lg）是桌面档口径。

- **备选与否决**：bottom sheet——新弹层形态 = 注册表接线 + 关闭语义 + 动画三件套成本，收益只在拇指热区；留作真机痛点后候选。lg 档（表格详情类）全屏化后内部表格可读性归对应页面实施票。

### 9. 交易列表：断点双渲染

<840 渲染新建的移动卡片列表组件，桌面表格一字不动（回归红线）；搜索结果同构复用；**分页语义不变**（20/页，不做无限滚动）；卡片字段取舍与来源列呈现归实施票；金额隐私模式兼容是验收硬条件。

### 10. 范围裁剪：桌面专属管理动作清单

移动档明确不提供、桌面完成：分类树拖拽排序、侧栏组内排序与组内收纳管理、实施票盘点出的同类低频批量管理。裁剪原则：**移动档覆盖「浏览 + 记账主流程 + 生命周期操作」**。闭集单点记录于本 ADR，新增裁剪项改本 ADR，不在实施票临时扩。

### 11. 实施分期：10 票，每票独立可合并、桌面回归安全

| # | 票 | 要点 |
|---|----|----|
| 1 | 断点与输入轴基建 | 窗口分级 + 输入轴两个 composable、常量收口、jsdom matchMedia 测试基建；零视觉变化 |
| 2 | 移动导航壳 | 抽屉 + 顶栏 + minWidth→360 + 忙碌条 / 安全区适配 |
| 3 | 触控交互轴 | 「⋯」常显、触控档快捷键提示 / 监听关闭、hover 一击可达替代 |
| 4 | 弹窗移动档 | AppModal 全屏化分支（纯前端，桌面零影响） |
| 5 | 系统返回桥接 | Android 返回键语义接线（可能含 Rust 侧，真机才能全验） |
| 6 | 交易页移动档 | 卡片列表 + 记一笔悬浮按钮 + 分页语义保持；搜索结果复用 |
| 7 | 概览与账户移动档 | |
| 8 | 预算与定时移动档 | |
| 9 | 报表与投资移动档 | 含各「更多」收纳页与设置；体量大按页再拆票 |

每票验收基线：桌面 Vitest 全绿 + 桌面缩窗手动核对（≥840 零变化）+ 票内功能点；**触控目标 ≥48px**（Material 触控下限，grilling 中曾拟 44px，定稿改随 Android 惯例）为各票抽查项。实施按票开 GitHub issue，走认领 + worktree + PR 既有流程。

## 后果

- 词汇表：界面状态与交互分域新立 6 条（窗口分级、输入轴、导航抽屉、记一笔悬浮按钮、系统返回语义、桌面专属管理动作），扩充 3 条（RowContextMenu 第二入口消费面扩至交易行、弹层关闭语义补第四通道指针、对话框排版补移动档条款）。
- 桌面侧可见变化仅两处且都已裁决：交易表新增常显「⋯」列（决策 6）、minWidth 降为 360（决策 2，随票 2）。
- 回归验证面：前端无浏览器级 e2e，移动布局回归靠组件测试（票 1 建 matchMedia 基建）+ 每票缩窗手动 + 收尾真机冒烟。
- ADR-0074 与本 ADR 解耦推进：票 1–9 不依赖 Android 基建（桌面缩窗验证），仅票 10 依赖。
