# ADR-0075: SQLite 加密模式——SQLCipher 文件级加密、主口令派生密钥、加密状态随文件走

- 状态：已接受（已落地，随 0.6.0 发布；grilling 定稿。三条修订已并入正文，沿革见演进脉络）
- 日期：2026-09-05（现行态收束：2026-11-20）
- 作者：Ledger 项目
- 关联：ADR-0007（文件级备份恢复，产物随加密模式自然变密文）、ADR-0016（自动备份调度，零改动继承）、ADR-0017/0018（AppSettings 与 DataLocation 库外引导——本决策**不**新增第二个引导状态）、ADR-0032（置脏连接层，加密转换属显式设置操作语义）、ADR-0074（Android 发布——解锁屏为前端页面天然可用）、ADR-0080（原位重引导——转换/恢复完成后自动重启的时机承接）、ADR-0127（明文库形态不变式与 ATTACH 显式 KEY——转换链的后续收口）

## 背景

账本含敏感财务数据，当前 `ledger.db` 及其全部备份在磁盘上明文存放。经 grilling 定稿的威胁模型是**静态数据保护**：防设备丢失、被他人物理接触、库文件或备份被拷走后的直接阅读；不防运行期访问（解锁后密钥必然在进程内存，静态保护是唯一诚实承诺的边界）。工程现状：rusqlite `bundled` 单连接架构，连接创建单点可插 `PRAGMA key` 接缝；备份/恢复/搬迁三条路径均走 `VACUUM INTO` 文件级快照——这一事实是本 ADR 多个决策的决定性输入。

## 决策（现行）

1. **引擎与依赖：SQLCipher，经 rusqlite `bundled-sqlcipher-vendored-openssl`**：与现有 `bundled` 同构，三平台产物自包含、可复现；加密参数用 SQLCipher 4 默认值，MVP 不调参。备选与否决：SEE（商业授权）；应用层逐字段加密（覆盖全部查询路径、索引与模糊搜索失效）；链接系统 sqlcipher（分发要用户装依赖）；sqleet 等纯 Rust codec（不成熟无维护）。**易混点澄清（记录在案）**：OpenSSL 在此仅作 SQLCipher 的本地加密原语提供方，与网络栈 rustls 无关——reqwest+rustls 的行情同步通道一行不动。
2. **威胁模型与开启方向：静态数据保护，用户显式开启（opt-in）**：存量明文库不受影响，新装库默认明文；**新装默认开启**与**存量自动转换**均否决——加密引入「密钥丢失＝数据不可读」这一新故障类别，不替用户做此决定。**无后门**：主口令丢失（且无钥匙串缓存）即数据永久不可读，不提供密钥导出/恢复文件；唯一逃生门是重置新建空库（旧库改名保留副本——密文副本不裸奔）。
3. **密钥体系：主口令派生密钥；钥匙串只缓存口令，不持派生密钥**：密钥 = KDF(主口令)，口令本身不落盘。可选「本机记住」：把**主口令本身**缓存于系统钥匙串（macOS 首发支持）；发布构建的读取前**生物门 = LocalAuthentication 应用层门**——钥匙串条目普通写入（无 ACL），读取前经 `LAContext.evaluatePolicy` 弹 Touch ID，验证通过才读（ACL 生物门对 Developer ID 分发不可用，证据矩阵实证：不挂 entitlements 报 `errSecMissingEntitlement`、挂 restricted entitlement 被 AMFI SIGKILL）；已知行为差异：生物特征重录**不再使缓存失效**（门在读取时评估当前特征，不与条目绑定）；取消/不可用回退手输不变。Windows Hello 视后续调研另接；Linux 及不支持平台回退每次手输。**否决（决定性理由）**：钥匙串存随机密钥——备份是 `VACUUM INTO` 文件级快照，密文随密钥走，换机后旧备份沦为读不开的密文，击穿备份可移植性核心安全网；缓存口令方案下密钥永远由口令派生，备份天然跨设备可恢复。
4. **加密状态感知：探测文件头，文件即真相**：明文库有固定文件头（`SQLite format 3\0`），SQLCipher 密文库头部为随机盐，读前 16 字节即可靠判定；0 字节文件视为明文新装。**不**在 `data_location.json` 增加加密标志（标志与文件状态会失同步，且扩大库外引导配置例外面积）。推论：加密模式是**库文件的属性**，随备份/恢复/复制自然流动。
5. **启动与解锁：加密模式必经前端解锁屏，数据库打开推迟到解锁后**：统一路径不做双模式启动。**自动解锁的触达点在解锁屏**：前端启动探测确认锁定相位后调用后端命令，钥匙串读取/生物认证在解锁屏加载态内进行，等待**有界**（超时回退手输并提示、加载态不再遮蔽手输与逃生门双入口；后端调用不取消，迟到成功照常进入）；无缓存时人工输入；解锁成功才打开数据库、加载主界面（明文模式启动流程零改动）。解锁先于一切业务读写：自动备份调度与 AI 导入 HTTP 面在解锁前不可用（后者沿用既有码化错误语义）。**口令错误与文件损坏运行期不可靠区分**（SQLCipher 下两者同为 NOTADB）：解锁失败提示采用合并口径；解锁失败**无限重试**——本地威胁模型下锁定只防自己；解锁屏常驻「忘记口令」入口做后果说明并可达重置，且常驻「从备份文件恢复」入口；**启动期库打不开（含明文库损坏）由前端失败恢复承担**——密文库进解锁屏恢复入口、明文库损坏进启动失败恢复屏，应用不退出，恢复走既有 Restore 全语义（跨模式警告、安全备份、恢复后自动重启均不变）。
6. **转换：一套机制覆盖开启加密、关闭加密、修改主口令**：整库文件级转换（ATTACH 空钥匙新库 + SQLCipher 标准导出，见 ADR-0127 的显式 KEY 收口）→ 新库用新口令试开验证 → 原子替换，旧文件按现有重置命名语义保留副本 → 完成即自动重启（ADR-0080 承接时机）。中途失败原库原样保留，不存在半加密状态；三形态同机制、测试面复用。**否决**：`PRAGMA rekey` 原地改钥（机制双轨）；逐表逐行应用层改写。
7. **备份与恢复：模式随文件走，跨模式恢复允许并警告**：加密库的备份产物**天然是密文**（`VACUUM INTO` 继承源库加密与密钥），自动备份、恢复安全备份、搬迁三条路径零改动；备份列表展示增锁形标记（backup.json 可选 `encrypted` 标记，备份时探测写入；旧备份缺标记视为明文——zip 纯增量向后兼容）。跨模式恢复**允许**：确认弹窗在模式不一致时显著警告；恢复后自动重启，由启动探测（决策 4）接管实际模式。**否决**：禁止跨模式恢复（多一道人为门槛且文件即真相时无必要）；恢复后静默自动重新加密（应用状态与备份内容出现用户无法预期的分叉）。
8. **发布边界**：schema/migration 零改动；AI API 契约不变（无新端点，解锁前返回既有码化错误）；备份 zip 仅增可选元数据字段，向后兼容。

## 否决方案汇总（防重提）

SEE（商业授权）、应用层逐字段加密（索引与模糊搜索失效）、系统 sqlcipher 依赖、纯 Rust codec、钥匙串存随机密钥（击穿备份可移植性）、原生密码输入窗（无 i18n/样式复用）、强制钥匙串缓存永不手输（恢复通道断裂）、引导文件加加密标志（失同步）、`PRAGMA rekey`（双轨）、禁止跨模式恢复、恢复后静默重加密。

## 代价与边界

密钥丢失即数据不可读（重置是唯一逃生门）；首次构建时长增加（缓存后不重复）；生物特征重录不失效缓存（应用层门形态的已知差异）；自动解锁依赖钥匙串可用性与系统弹窗及时返回（有界等待兜底）；范围外（v1 不做）：密钥导出/恢复文件、Windows Hello、逐字段加密、云同步场景加密、多套密钥/多账本、移动端生物认证。
