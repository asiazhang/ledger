# ADR-0075: SQLite 加密模式——SQLCipher 文件级加密、主口令派生密钥、加密状态随文件走

- 状态：已接受（实施待启动，grilling 定稿）
- 日期：2026-09-05
- 作者：Ledger 项目
- 关联：ADR-0007（文件级备份恢复，产物随加密模式自然变密文）；ADR-0016（自动备份调度，零改动继承）；ADR-0017/0018（AppSettings 与 DataLocation 库外引导——本决策**不**新增第二个引导状态）；ADR-0032（置脏连接层，加密转换属显式设置操作语义）；ADR-0074（Android 发布——解锁屏为前端页面天然可用，移动端 api_server 不启动无暴露面）

## 背景

账本含敏感财务数据，当前 `ledger.db` 及其全部备份在磁盘上明文存放。经 grilling 定稿的威胁模型是
**静态数据保护**：防设备丢失、被他人物理接触、库文件或备份被拷走后的直接阅读；不防运行期访问
（解锁后密钥必然在进程内存，静态保护是唯一诚实承诺的边界）。工程现状：rusqlite `bundled`
单连接架构，连接创建单点可插 `PRAGMA key` 接缝；备份/恢复/搬迁三条路径均走 `VACUUM INTO`
文件级快照——这一事实是本 ADR 多个决策的决定性输入。

## 决策

### 1. 引擎与依赖：SQLCipher，经 rusqlite `bundled-sqlcipher-vendored-openssl`

- 与现有 `bundled` 同构：SQLCipher 4.x 与 OpenSSL 一并静态编译进二进制，三平台产物自包含、
  可复现，代价仅首次构建时长（cargo 缓存后不重复）。加密参数用 SQLCipher 4 默认值（KDF、
  页密钥、HMAC），MVP 不调参。
- **备选与否决**：SEE（商业授权）；应用层逐字段加密（改动面覆盖全部查询路径，范围失控，索引与
  模糊搜索失效）；链接系统 sqlcipher（分发要求用户装依赖）；sqleet 等纯 Rust codec（不成熟、
  无维护）。
- **易混点澄清（记录在案）**：OpenSSL 在此仅作 SQLCipher 的本地加密原语提供方（AES/PBKDF2/
  HMAC/随机盐），与网络栈 rustls 无关——reqwest+rustls 的行情同步通道一行不动；SQLCipher
  上游 provider 仅 OpenSSL/CommonCrypto，不存在也不需要 rustls 类后端。

### 2. 威胁模型与开启方向：静态数据保护，用户显式开启（opt-in）

- 存量明文库不受影响，新装库默认明文，开启走设置页显式操作。加密引入「密钥丢失＝数据不可读」
  这一新故障类别，不替用户做此决定；**新装默认开启**与**存量自动转换**均否决。
- **无后门**：主口令丢失（且无钥匙串缓存）即数据永久不可读，不提供密钥导出/恢复文件（MVP 否决：
  扩大密钥暴露面）；唯一逃生门是重置新建空库，沿用现有重置语义（旧库改名保留副本——密文副本
  不裸奔）。

### 3. 密钥体系：主口令派生密钥；钥匙串只缓存口令，不持派生密钥

- 密钥 = KDF(主口令)，口令本身不落盘。可选「本机记住」：把**主口令本身**缓存于系统钥匙串
  （macOS 首发支持，可挂生物认证门——生物认证是取回缓存口令的关卡，不是密码学原语）；不缓存
  派生密钥。Windows Hello 视后续调研另接；Linux 及不支持平台回退每次手输。
- **备选与否决（决定性理由）**：钥匙串存随机密钥——备份是 `VACUUM INTO` 文件级快照，密文随
  密钥走；换机后新机器钥匙串里是另一把钥匙，旧备份沦为读不开的密文，击穿备份可移植性这一核心
  安全网（自动备份/恢复安全备份/跨机恢复，ADR-0007/0016）。缓存口令方案下密钥永远由口令派生，
  备份天然跨设备可恢复（恢复时输口令即验证），生物识别挂掉只损失便利。

### 4. 加密状态感知：探测文件头，文件即真相

- 明文库有固定文件头（`SQLite format 3\0`），SQLCipher 密文库头部为随机盐：读前 16 字节即可
  可靠判定；0 字节文件视为明文新装。**不**在 `data_location.json` 增加加密标志。
- **备选与否决**：引导文件加标志——标志与文件状态可能失同步（恢复、换文件、搬迁后），且扩大
  ADR-0017/0018 「库外引导配置唯一例外」的面积。
- 推论：加密模式是**库文件的属性**，随备份/恢复/复制自然流动；这也是决策 7 的口径基础。

### 5. 启动与解锁：加密模式必经前端解锁屏，数据库打开推迟到解锁后

- 统一路径，不做双模式启动：加密模式下启动必经解锁屏——有钥匙串缓存时静默或经生物认证自动通过
  （后端触发，阻塞发生在 setup 期，与现有原生对话框等价），无缓存时人工输入；解锁成功才打开
  数据库、加载主界面。明文模式启动流程零改动。
- 解锁先于一切业务读写：自动备份调度与 AI 导入 HTTP 面在解锁前不可用（后者沿用既有码化错误
  语义，不新增契约端点）。
- 口令错误 ≠ 库损坏（SQLCipher 对错误密钥报「not a database」）：由文件头探测区分「加密库等
  待口令」与「库损坏」；解锁失败**无限重试**——本地威胁模型下锁定只防自己；解锁屏常驻「忘记
  口令」入口做后果说明并可达重置。
- **备选与否决**：原生密码输入窗（现有阻塞对话框插件无文本输入能力，自建原生窗口无 i18n/样式
  复用）；强制钥匙串缓存、永不手输——钥匙串被清时口令无处可输，恢复通道断裂，与决策 2 冲突。

> 注（2026-09-05 修订，见「修订记录」）：文件头探测承担的是「明文/密文」判别——SQLCipher 对
> 错误口令与文件损坏报同一错误，运行期不可可靠区分，解锁失败提示采用「口令错误或文件损坏」
> 合并口径。启动期库打不开（含明文库损坏）不再走原生「重置/退出」对话框，改由前端失败恢复
> 承担：密文库在解锁屏常驻「从备份文件恢复」入口，明文库损坏进启动失败恢复屏，应用不退出，
> 恢复走既有 Restore 全语义。

### 6. 转换：一套机制覆盖开启加密、关闭加密、修改主口令

- 整库文件级转换（ATTACH 空钥匙新库 + SQLCipher 标准导出）→ 新库用新口令试开验证 → 原子替换，
  旧文件按现有重置命名语义保留副本 → 完成即自动重启（与 Restore「恢复成功后自动重启」语义同型）。
  中途失败原库原样保留，不存在半加密状态。改口令＝转入新口令的新库，三形态同机制、测试面复用。
- **备选与否决**：`PRAGMA rekey` 原地改钥——改口令另走一条代码路径，机制双轨；逐表逐行应用层
  改写（见决策 1 否决理由）。

### 7. 备份与恢复：模式随文件走，跨模式恢复允许并警告

- 加密库的备份产物**天然是密文**（`VACUUM INTO` 继承源库加密与密钥）：自动备份、恢复安全备份、
  DataLocation 搬迁三条路径零改动，ADR-0007/0016 语义不变；备份列表展示增锁形标记（依据
  backup.json 新增的可选 `encrypted` 标记，备份时探测写入；旧备份缺标记视为明文——zip 格式
  纯增量，向后兼容）。
- 跨模式恢复**允许**：恢复确认弹窗在当前模式与备份模式不一致时显著警告（如「恢复后此库将变为
  未加密」）；恢复后应用自动重启，由启动探测（决策 4）接管实际模式。
- **备选与否决**：禁止跨模式恢复（多一道人为门槛，且文件即真相时无必要）；恢复后静默自动重新
  加密——应用状态与备份内容出现用户无法预期的分叉，违背「文件即真相」。

### 8. 发布边界

- schema/migration 零改动（`user_version` 不动），无已发布迁移修改；AI API 契约不变（无新端点，
  解锁前返回既有码化错误）；备份 zip 仅增可选元数据字段，向后兼容。属用户可见功能，随实施在
  CHANGELOG `Unreleased` 记录。

## 后果

- 实施面（均走既有接缝）：新 IPC 命令（解锁/开启加密/关闭加密/修改主口令）入既有命令模块并过
  一致性检查，前端 API/类型同步；前端解锁屏（加密模式启动首屏）与设置页加密卡片、全部用户可见
  文案经 i18n；实现时审计日志与 trace 输出不落主口令与明文数据（含现有 perf trace 面）。
- 范围外（v1 明确不做）：密钥导出/恢复文件、Windows Hello、逐字段加密、云同步场景加密、多套
  密钥/多账本。
- Android（ADR-0074）：解锁屏为前端页面天然可用；移动端 api_server 不启动，无解锁前 HTTP 暴露面；
  移动端生物认证不在 v1 范围。
