# ADR 0146: 启动账本目录解析链与首启引导——解除 #2015 立桩收窄、book-missing 显式出口

- 状态：已接受（决策入档；实现随实现票落地；修订：决策 3④ 与决策 4 的密文分支随 #2088 反转为登记+打开，见文末修订注记）
- 日期：2026-11-10
- 作者：Ledger 项目
- 关联：ADR-0018（数据位置——损坏回退默认目录与搬迁「意图下次启动生效」的对照基准）、ADR-0089（多账本注册表——解析链的消费对象与持久化归口）、ADR-0145（原生壳——本决策的壳域载体与发布形态前提）、ADR-0078（危险确认分级——新建确认对话的分级基准）、#2015（立桩收窄原文——本决策显式解除其 argv-only 与缺库 fail loud）、#2088（加密面——密文库解锁另票）、#2038（文件对话框壳内先例）；词汇表：参考数据与设置域「账本（Book）」「默认数据目录」、应用壳域「首启引导」（随本 ADR 入档）
- 来源：grill-with-docs 裁决（2026-11-10，三轮）

## 背景

切轨后产品形态 = release 二进制 + `.desktop` 直跑（`Exec` 无参数，ADR-0145 决策 7 修订），而现行壳沿 #2015 立桩收窄只认 argv 显式账本目录：缺参即死路窗口（「用法：nsh-app <账本目录>」）——点图标启动的每个新用户必经。同时词汇表早已定义解析语义（账本注册表活动指针掌管「哪本是活动本」、默认数据目录是「未配置或回退时的默认库目录」），壳内悬空未接线；老壳（已退役）的对应语义是首次运行静默在默认目录新建、缺库建连即建库、注册表损坏回退默认目录带回退原因。基础设施侧 `plan_boot` 既有接缝（解析注册表活动本 + 库文件处置探测）已在新壳引导路径半接线，缺库防线只在壳层（`boot_ledger` 的 `book-missing` 检查；infra `open_db_in` 自带建库与迁移）。

## 决策

### 1. 启动账本目录解析链

argv 显式账本目录（开发/测试面，优先级最高）→ 账本注册表活动指针（产品主路径，经既有 `plan_boot` 接缝解析）→ 默认数据目录（注册表未配置或损坏回退，in-memory `single_default` 语义）。此链是词汇表既有语义的壳内接线，不立新语义。

### 2. 首启引导

注册表未配置且解析落点无库（含注册表损坏回退后无库）时，启动竖井缺参态改造为**首启引导**：双动作——「新建账本」（落默认数据目录，确认对话明示完整路径后建库并登记为「默认账本」条目）与「打开已有账本」（目录选择器）。选定即本次启动打开，登记与活动指针**即时落盘**——与搬迁「意图下次启动生效」（ADR-0018）的区分依据：启动期无在开库，不存在切换风险；注册表损坏回退时界面带损坏告示。

### 3. 选择器现场语义闭集

「打开已有账本」选中目录按现场分流：①注册表在册的其他本 → 切活动指针打开；②有库未登记 → 登记新条目 + 切活动指针，打开；③无库 → 视为新建意图，走决策 2 的确认后新建并登记；④密文库 → 既有码化错误 `nsh-shell.encrypted-unsupported` 呈现（解锁向导归 #2088）；⑤损坏残留 → 既有损坏码呈现，不自动换目录重试。

### 4. book-missing 显式出口

注册表已解析出活动本但库文件缺失（含 argv 打错路径）时，维持 fail loud 错误态（#2015 防假空态的内核不变），错误态增挂「选择账本库目录…」按钮（复用目录选择对话框壳内先例）；取消留原态可再触发；平台能力缺失沿既有 `nsh-shell.file-dialog-failed` 码化呈现。密文库与损坏残留失败态不挂选择器（缺的是解锁与诊断，不是目录）。

### 5. 新建落点与持久化归口

首启新建首本直落默认数据目录（`ledger.db` 在默认目录内，登记为「默认账本」）——与 infra `single_default` 语义、词汇表「存量目录折叠为唯一默认账本」升级路径一致；「新建账本子目录」的多本管理另票。选中/新建结果的持久化归口账本注册表（登记 + 活动指针），不立 NSH Storage 键（避免第二份账本身份口径）。

### 6. 范围收窄

不动「数据存储位置」设置卡的搬迁 / 恢复默认语义（本决策只消费注册表，不改写其搬迁写面）、不动跨账本汇总、不做解锁向导（#2088）。

## 理由

- 缺参死路是发布形态的必经缺口，且词汇表解析语义早已定案，壳内接线成本低。
- 首启引导是对老壳「静默新建」的**有意偏离**：库落点与「这是一本新账」的事实应让用户知情（知情权优先于零摩擦）；而「未配置但默认目录已有库」的升级现场不经引导直接打开，回归词汇表回退语义。
- fail loud 的不对称有原则：argv 路径存在「打错」风险（#2015 防的假空态），注册表解析链不存在该问题——故 argv 缺库保持错误态 + 显式出口，注册表解析缺库不静默新建而是引导。

## 代价

- 首装用户从「零点击进空账本」变为「引导页 + 一次新建确认」：多一步交互换取知情。
- 启动竖井缺参态改造面：死路窗口与 `book-missing` 文案（「立桩期请传入已有账本的目录，不新建账本」）需随立桩语义解除重写。
- 选择器现场闭集五种分流全部落壳层编排，headless 组件测试面扩大。

## 替代方案

- **完全沿老壳静默新建**：零摩擦但库落点与新建事实无知情，与「引导更友好」的裁决相反，否决。
- **缺参直接弹目录选择器**（不设引导页）：少了「新建」主动作，首装用户被迫先理解「目录 / 库」概念，否决。
- **选择结果立 NSH Storage 键**：第二份账本身份口径，违反归口纪律（注册表掌管「有哪些本、哪本是活动本」），否决。
- **登记意图下次启动生效**（对齐搬迁语义）：启动期无在开库，延迟生效只会造成「选了却没发生」，否决。

## 影响

- 词汇表：应用壳域新增「首启引导」词条；CONTEXT-MAP 分域一览第 16 行主题列同步。
- 实现票：解析链接线（`plan_boot` 缺参消费）、首启引导界面、选择器现场闭集、`book-missing` 失败态按钮与文案重写，另立 GitHub issue 挂本 ADR。
- 发布边界：纯壳层编排与呈现改动，无 schema / API 契约变更。
- #2015 立桩收窄（argv-only、缺库 fail loud、无引导）由本决策显式解除，其假空态防线在决策 4 保留。

## 修订注记（#2088 加密面落地，2026-11-11）：决策 3④ 反转为登记+打开、决策 4 的密文出口退役

密文库解锁路径落地（锁定视图 + 解锁面板 + 忘口令重置，issue #2088）后，本决策两处随语义反转：

- **决策 3④**（选中目录为密文库 → 码化错误 `nsh-shell.encrypted-unsupported`、注册表零写入）反转为**同 ②③ 登记 + 置活动指针 + 判开**——打开后引导落锁定视图（`StartupView::Locked`）解锁。反转依据：决策 3④ 零写入口径的论证前提是「该失败态无选择器出口、指针已移走后应用内不可恢复」，锁定视图成为一等启动态后前提失效；沿用⑤损坏残留的零写入（损坏残留仍无解锁路径，前提继续成立）。
- **决策 4** 的「密文库与损坏残留失败态不挂选择器」中，密文库半边随④反转退役（密文库不再进失败态，锁定期结构性无业务面、无选择器出口的不变量不变）；损坏残留半边保留。`nsh-shell.encrypted-unsupported` 码退役，引导层产出 `nsh-shell.awaiting-unlock` 码化信号供纯函数面断言与呈现面映射。
- 实现面：`boot::resolve_picked_book_dir` 分类门只拦 Unreadable；`boot_ledger_by_plan` AwaitUnlock 臂产出等待解锁信号 + 引导记录落槽 + 锁定门置锁；lib/headless 断言同步翻转。
