# 模糊搜索术语表

## Unified Fuzzy Search Semantics（统一模糊搜索语义）

全局搜索与拼音可搜下拉共同遵守的匹配规格（ADR-0027，规格文本以 issue #195 为唯一真源）：

> 输入按空白切词，词条之间 AND；每个词条对每个字段判定——
> **命中 = 原文连续子串（大小写不敏感）∨ 词条是该字段拼音首字母串的子序列（大小写不敏感）**

混合输入（如「招zsyh」）无需特判：含汉字的词条对纯 ASCII 首字母串的子序列匹配必然失败，自然落到原文子串路径。

## Subsequence Match（子序列匹配）

词条的每个字符按原顺序出现在目标串中（允许跳字、间隔不限）的判定，如 `wy` 命中首字母串 `wkwy`（万科物业）、`zsyh` 命中 `zsyh`（招商银行）。大小写不敏感；空词条恒命中。与倒排索引根本不兼容（命中键集合不可枚举），是全局搜索采用 Rust 全量扫描的直接原因。

## Pinyin Initial（拼音首字母）

中文文本每个字的拼音首字母串，统一小写。生成规则：中文字取拼音首字母、ASCII 字母/数字小写原样保留、标点与空格跳过；多音字按前字规则修正（「银行」→ `yh`）。后端 `pinyin` crate（`commands::search::text` 纯函数）、前端 pinyin-pro 各自实现同一规则，接受生僻多音字的字库级分歧。

## Searchable Field（可搜索字段）

全局搜索的匹配字段：交易备注 + 转出账户名（V005 收窄语义保持不变）；分类名、转入账户名不在范围。下拉搜索的字段为选项 label（issue #197–#200）。

## Full Scan（全量扫描）

全局搜索实现（ADR-0027）：SQL 取候选（软删除口径 + 金额/日期过滤仍走 SQL 索引）→ Rust 内存中按统一语义逐条过滤 → 交易日期降序排序后分页。个人账本量级（10 万条约 90ms/次）实测无感；无任何索引与一致性机制，**写入立即可搜**。

## Soft-Delete Filter（软删除过滤）

所有搜索结果必须排除 `is_deleted = 1` 的记录：SQL 层 JOIN `accounts`/`categories` 并限定 `is_deleted = 0`（与交易列表口径一致）。全量扫描实现下软删除即刻生效，无索引滞后窗口。
