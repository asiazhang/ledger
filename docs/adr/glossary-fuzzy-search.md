# 模糊搜索术语表

## Search Document（搜索文档）

一笔交易在搜索索引中的可搜索表示。它把交易本身的备注、转出账户名以及它们的中文拼音首字母拼接成一段文本，供 FTS5 全文索引使用。

## Searchable Content（可搜索内容）

搜索文档中实际被 FTS5 索引的文本。生成规则：

```
note + 转出账户名 + 备注拼音首字母 + 账户名拼音首字母
```

例如一笔「吃饭」交易，关联账户「招商银行」：

```
"吃饭 招商银行 cf zsyh"
```

> 分类名、转入账户名不在可搜索内容中（V005 收窄后的搜索范围）。

## Pinyin Initial（拼音首字母）

中文文本每个字的拼音首字母串。用于支持用户输入拼音首字母匹配中文内容，如 `cf` 匹配「吃饭」。由 Rust 层在写入索引时生成并统一转小写。

## FTS5 Virtual Table（FTS5 虚拟表）

SQLite 提供的全文搜索虚拟表。本设计使用 `search_transactions` 作为 contentful 虚拟表（存储可搜索文本副本以便维护与 rank 排序），另存交易 ID 元数据用于回查主表。

## Reindex（重建索引）

当交易或账户名发生变化时，重新生成对应交易的搜索文档并写入/更新 FTS5 索引的过程。SQLite 触发器负责把受影响交易入队 `search_reindex_queue`，后台定时刷新（默认 60 秒周期）消费队列批量重建；批量导入完成后立即消费一次；启动时按文档数对账，不一致则全量重建（ADR-0004 决策 #14）。分类名不在索引中，改名不触发重建。

## 后台定时刷新（Background Refresh）

搜索索引的一致性维护策略（ADR-0004 决策 #14）：交易写入路径不做任何同步索引工作，由后台线程固定周期消费重建队列。写入后到下次刷新前，新建交易不可搜、软删除交易仍可搜（时效性要求低，可接受）；搜索结果附 `stale` 标志提示索引可能滞后。

## Soft-Delete Filter（软删除过滤）

所有搜索结果必须排除 `is_deleted = 1` 的记录。FTS5 索引本身不感知软删除状态，查询时通过 JOIN 主表并加 `is_deleted = 0` 条件实现。

## Rank（相关性得分）

FTS5 根据词频、字段权重等计算出的匹配得分。搜索结果默认按 `rank` 降序，再按交易日期降序。

## Match Query（匹配查询）

用户输入经过分词/预处理后传给 FTS5 `MATCH` 子句的表达式。例如用户输入 `cf 吃饭` 会被转换为 `cf OR 吃饭`，以便同时命中拼音首字母和原始中文。
