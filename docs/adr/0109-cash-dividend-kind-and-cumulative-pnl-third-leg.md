# ADR-0109: 现金分红（dividend）：激活已声明 kind、累计收益三腿、现金腿 kind 只读呈现

- 状态：已接受（grilling 定稿，2026-09-11）
- 日期：2026-09-11
- 作者：Ledger 项目
- 关联：#1078（本票）；ADR-0011（kind→度量矩阵——`dividend` 行既有，本次不改）；ADR-0013 / ADR-0036 决策 6 / ADR-0099（`dividend` 当时维持显式拒绝与「另行议题」的预留开口）；ADR-0106（split 激活先例与界面只读化）；ADR-0107（累计收益按币种分组口径）；ADR-0091 / ADR-0101 / ADR-0105（同步重放与写入协议）；issue #1077（累计收益两腿口径的落地）

## 背景

现金分红（股息、基金分红、投顾组合分红）此前只有两条路：以核心交易域普通 `income` 流水手工承载，或经交易接口被显式拒绝——`dividend` kind 虽在闭集与金额度量矩阵（account_flow + / income_net +）与 `security_transactions.action` 检查约束中早已声明，但写入层维持「暂不支持」（ADR-0013 决策 4；ADR-0036 决策 6；ADR-0099 决策 1 明示的预留开口）。

后果是一处已知偏差：投资域看不见分红，累计收益（ADR-0107 / issue #1077 落地的「未实现盈亏 + 已实现盈亏」两腿口径）不含分红，与且慢等第三方平台的同名口径存在差额。虚拟股分红以普通 `income` 入现金账户，同样不进投资视角。

## 决策

1. **激活 `dividend` 的写入路径**，而不是给既有 `income` 加投资指针。交易行落 `kind=dividend`（现金腿记 `amount_cents`，度量符号沿用 ADR-0011 矩阵既有行：account_flow +、income_net +）+ `security_transactions` 扩展行（`action='dividend'`、`instrument_id` 归属标的、`quantity` / `price_cents` 留 NULL）。**schema 零改动**——两侧 CHECK 早已含 `dividend`。收入流水的「同 schema、不同语义」（一条 `income` 到底是不是投资分红）不可检测，投资分红因而必须是自己的 kind。
2. **分红计入累计收益的第三腿，不摊薄持仓成本**：累计收益 = 未实现盈亏 + 已实现盈亏 + 累计分红。FIFO 批次成本是已实现盈亏、基金转换结转成本与份额调整重述共同的审计锚点，分红若摊薄成本会同时改写「持仓收益」、污染这三条既有链路；分红只按其自身现金流量入第三腿，与「当前市值 + 累计卖出净收入 − 累计买入总支出 + 累计分红」的现金流口径一致。
3. **有现金腿的 kind 同样界面只读**（沿用 ADR-0106 决策 10 的形态）：无创建 / 编辑 / 软删操作入口，只保留列表 / 筛选 / 只读详情与 kind 标签「分红」；写入与纠错走 HTTP 契约（AI 导入 / 迁移侧）。
4. **形态与守卫**：标的必填且存在；**不要求当前有持仓**（除息 / 到账时间错位合法）；金额 > 0；到账账户为**任意在用账户**（不限于投资账户——分红可直达银行卡），币种须与账户币种一致；不接受份额 / 单价 / 手续费 / 转入标的 / 转入账户 / 出资账户 / 商户 / 分类 / 保单（全部码化中文错误）。进 / 出 `dividend` 的 kind 变更一律拒绝（纠错只有「软删 + 重建」一条路），但 dividend 行本身可就地修改（全字段替换）。
5. **多端同步完整重放**：分红作为语义命令重放，复用交易命令既有投资字段成员（只携标的 id，现金腿随归一化行），create / update / delete 三 op 均可重放且幂等；扩展行自包含、无 FIFO 重建；标的不在时以既有码挂起（ParkedOp），依赖补齐后重投递自然重试。
6. **AI 导入契约教学节是一等交付物**：导入知识新增现金分红教学节（字段位置、到账账户与币种、禁止落 `income`、累计收益对账、纠错边界、红利再投口径），能力文案锁由「`dividend` 仍不受支持」翻绿。

## 理由

- **预留开口已经存在，激活比新造第二套语义便宜**：`dividend` 在 kind 闭集、度量矩阵与扩展表约束中都已就位，激活只需行为层与投资域补写入路径；给 `income` 加可选投资指针则要在核心交易行新增指针列、在行为层加一套「同 kind 两种语义」的准入，并且永远无法从数据上区分普通收入与投资分红。
- **第三腿保证既有口径不动**：issue 的验收判据要求「无分红持仓的行为与现状逐位一致」，第三腿是唯一能同时满足「累计收益含分红」与「两腿口径逐位不变」的形态。
- **到账账户放开到任意在用账户**：分红到账的常见落点是银行卡而非投资账户；限定投资账户会逼用户先记一笔转账，凭空制造资金流。
- **不要求有持仓**：除息日与到账日错位、以及清仓后的尾款分红都是合法现实，要求持仓会把正确记账挡在门外。
- **只读呈现**：手工录入的分红缺少标的解析与到账账户校验的界面接缝，而 AI 导入 / 迁移是分红的主要来源；先只读、后续按需再开录入入口，与 convert / split 的既有节奏一致。

## 替代方案（防重提）

- **以分类 / 商户 / 关联指针标记既有 `income` 流水**（PolicyReference 式可选直挂）：核心交易行需新增可选投资指针列，且「普通收入」与「投资分红」在数据上不可区分——用户把一条普通收入改挂标的即可凭空造出分红腿，第三腿的审计意义消失。否决。
- **分红摊薄持仓成本**（部分平台口径）：会同时改写「持仓收益」（未实现盈亏），并让 FIFO 批次成本不再忠实于实际成交——已实现盈亏、转换结转成本、份额调整重述三条链路的审计锚点全部漂移。ADR-0107 已裁决不采用摊薄成本法，本票不重开。否决。
- **维持 `income` 承载、只在展示层按商户 / 分类拼一个分红腿**：口径靠约定而非数据，AI 与用户任何一侧漂移都静默失真。否决。
- **顺便把红利再投（DRIP）也纳入本 kind**：DRIP 是「现金分红 + 再买入」两步的合成动作，落成一条 `dividend` 会缺一腿份额、落成两条又要求本票定义配对语义；维持 0 手续费 `buy` 模拟。否决（另行议题）。
- **顺带放开界面手工录入**：需要新增标的解析选择器与到账账户口径的前端接缝，收益远小于成本，且与 convert / split 的只读先例不一致。否决。
- **本次一并处理送股 / 转增**：改变份额的公司行为属份额调整（Split，ADR-0106）的语义，与现金分红互补但不重合，合并只扩大一次改动面。否决。

## 代价

1. 分红是**唯一有现金腿且界面只读**的 kind——「只读 kind = 无现金腿」的直觉被打破，术语与注释需显式说明（本票已在词汇表与前端行激活注释留痕）。
2. 到账账户币种一致性是新守卫：跨币种到账（如美元分红入人民币账户）须用户自行换汇或选对账户，后端不折算。
3. 分红不摊薄成本意味着「持仓收益」与「累计收益」的差额里永远含分红——这正是 ADR-0107 裁决的可解释差额，不是缺陷。
4. AI 导入多一节教学与一条能力文案，契约体积与知识体量小幅增长（体积护栏无需提高）。

## 后果

- `TransactionKind` 九种 kind 全部落地，不再有「暂不支持」的声明壳；`transaction.kind-unsupported` 这一条码不再由交易写入路径产生。
- 新增公开错误码：`trade.dividend-kind-change-forbidden` 与分红形态守卫码（见错误码模板）；中英文模板同步。
- 累计收益的展示口径扩为三腿；无分红账本的读数与现状逐位一致（第三腿为空贡献）。
- 相关词汇表条目：核心交易域 Transaction（kind）/ Transaction Kind Mapping / 写入协议；投资域现金分红（Dividend）/ 累计收益（CumulativePnl）/ Investment / 自建标的；AI 导入域投资迁移链路。
