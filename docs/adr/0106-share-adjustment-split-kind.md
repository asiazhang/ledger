# ADR-0106: 份额调整（split）——激活已声明 kind、单标的非现金份额变动与批次成本按比例重述

- 状态：已接受（grilling 定稿 2026-09-11；行为层与前端随 #1045 落地，代码排在 #1005 之后）
- 日期：2026-09-11
- 作者：Ledger 项目
- 关联：ADR-0011（kind→度量矩阵与 raw/native 金额分离——split 行早已在矩阵内、六系数全 0）、ADR-0013 / 0033（行为层单点穷尽分派与编排入口、事务所有权）、ADR-0067（余额与净资产持久化缓存：写路径整体重算）、ADR-0091（同步 op 语义、载荷只增与挂起队列）、ADR-0096（出资账户准入闭集）、ADR-0097（删除语义修订：revert 与级联先例）、ADR-0099（基金转换 convert——同一「无现金腿」家族的承载模板，本决策的兄弟）、ADR-0050（码化错误）、ADR-0087（断言强度与三层测试权威层）、ADR-0090（AI 契约双投影与体积护栏）、ADR-0105（写入协议单正文：kind 守卫单点）、#1005（investment lots / unwind 深模块，先行票）、#1048（撤下 convert 手工入口，姊妹票）、spec #1045

## 背景

数据迁移侧（`ledger-migrate`）迁移且慢 API 快照时遇到**非现金份额调整**类记录，现行契约无法表达：

- 且慢快照 `typeCode=144`（长赢年度份额结转）6 笔，标的均为 502010 易方达中证全指证券公司指数(LOF)A，合计 **+339.76 份**——快照中无金额、无净值、无现金腿。
- moomoo 侧同形态的「送股」另有 5 笔（2022-05~2025-07，无金额），迁移设计同为 skip。

迁移侧原决策是 skip「待 buy/sell 升级时对账」，2026-06 触发：一笔真实卖出 502010 5,820.53 份被可卖出数量守卫拒绝（当前持有 5,480.77），差额恰为 339.76 份；`qieman-2026-06` 因此卡在重迁中间态。

借位方案的排除理由：0 元 `buy` 会被金额权威校验拒绝、且界面显示「买入」；按当期净值伪造金额会虚增买入成本、扭曲已实现盈亏并继续污染黑洞账户语义；把卖出数量砍到 5,480.77 则是篡改确认单权威事实。

关键事实：`split` **早已在闭集里**——kind 枚举、`transactions.kind` CHECK、`security_transactions.action` CHECK、kind→度量矩阵的 split 行（六系数全 0）与 AI 契约闭集均已声明，只有写入层以「暂不支持」显式拒绝（ADR-0099 决策 1 明示维持该拒绝）。建表注释也已写下预期口径：拆股/送股等公司行为需要应用层调整所有相关 lot 的 `quantity` 与 `cost_per_unit_cents`。

所以这是一次**激活已声明 kind**，不是第 10 种 kind；schema 无需扩容任何 CHECK。真正的争议集中在**成本口径**与**回退依据**——这是本 ADR 的立据。

**为什么是 ADR 级**：kind 是编译期闭集，`kind→度量矩阵`是全库金额口径的唯一真源（ADR-0011）；成本重述会牵动 FIFO 闭合机制（批次每份成本不再能用当前值回算历史消耗）、余额/净资产缓存对拍、已实现盈亏闭合不变式、多端同步确定性与 AI 契约教学面。而「按比例重述在用批次」是货真价实的取舍（0 成本新批次是可行的省事解），且批次重述不可逆——这决定了必须新增一张审计表。改主意的代价大，事后不看记录无法理解为什么多一张表、为什么历史消耗要改读落库成本，故立 ADR。

## 决策

### 1. 语义：单标的、非现金、带符号的份额变动

`split` = **同一投资账户内、单标的的非现金份额变动**：份额折算 / 结转 / 送股为 `+`，缩股为 `−`。一笔 = 一条 `transactions` 记录，表达标的、**带符号的份额变动量 Δ** 与调整日；**无现金腿**——`amount_cents` / `amount_native_cents` 恒为 0，六度量系数沿用矩阵既有全 0 行，落账前后全部账户余额（含黑洞账户）完全不变。

与 `convert` 的分界：convert 是**两标的互换**（A→B，两腿同记录），split 是**单标的份额变多/变少**。

输入语义为**绝对增量 Δ**（不是换算比例 f），按落账时的在用持仓锚定：`f = (当前持仓 + Δ) / 当前持仓`。`Δ > 0` 时要求该标的在该账户**有在用持仓**（价值已含在原批次中，零持仓无从重述）；`Δ < 0` 时要求 `|Δ| < 当前持仓`（等号会让 f = 0、成本凭空消失，与「恒不产生已实现盈亏」冲突）。标的类型不限（基金/股票同构），账户必须是投资账户。

### 2. 成本口径：按比例重述在用批次（否决 0 成本新批次）

`f = (当前持仓 + Δ) / 当前持仓`，对受影响批次逐批 `remaining_quantity × f`、`initial_quantity × f`、`cost_per_unit_cents ÷ f`，**批次总成本精确不变**，舍入尾差归末批次闭合（沿用 convert 的「尾差末腿」纪律）。

- **选它的理由**：「已实现盈亏最小意外」——每份成本随份额同比例稀释，部分卖出如实按新每份成本结算，与净值折算 / 送股的经济实质一致；正负两向共用同一公式；且这正是建表注释已声明的预期口径。
- **否决 0 成本新批次**：FIFO 按插入序消耗，0 成本批次被卖出的时点由插入顺序决定——买 100 份 @10 元、送 10 份、卖 55 份，比例重述得已实现 50 元，0 成本批次排首位得 100 元、排末位得 0 元，同一笔真实交易三个答案。且负份额批次在「剩余数量 > 0」的持仓谓词下不可表达，缩股只能改成 FIFO 吃掉批次，会生成假匹配、伪造已实现盈亏。
- **验收数据判不了这个决策**（502010 那笔是全清仓，两案等价）——必须为部分卖出单写一条测试钉住口径。

### 3. 存储与审计：零 CHECK 改动 + 新增批次重述审计表

split 行复用 `security_transactions` 既有列（`instrument_id`、`quantity` = Δ、`price_cents` 留 NULL），**不新增列、不动任何 CHECK**（`split` 本就在两侧 CHECK 内）。新增 `security_lot_adjustments` 承载逐批次 before/after 重述，角色对齐 `security_lot_conversions`：重述不可逆（含舍入），它是 `revert` 精确回补与审计的**唯一依据**。

因为不需要就地改已发布迁移，本票走 **additive 迁移（当前最高 V023 → V024）**，**不发 BREAKING、存量库免重建**——与 ADR-0099 决策 9 那次被 SQLite 重建表逼出来的就地修改不是一回事。

### 4. 校准既有闭合机制：历史消耗改读落库成本

现有历史消耗回算用**当前**每份成本，配合「耗尽批次 = 买入锚点金额 − 历史消耗」闭合。批次每份成本被重述后该口径失效（100 份 @1.00 卖出 40 后 +100%，清仓闭合会给出 80 而非 60）。改为读 `security_lot_sales` / `security_lot_conversions` 行里**记录时**的消耗成本：**无 split 行时与今天恒等**，属行为保持型改动，单独一条绑定测试钉住。

### 5. 守卫（行为层收口，全部码化中文错误）

零持仓提交拒绝、缩股不等式取严、不接受手续费（非 0 拒绝）/ 出资账户 / 商户 / 分类 / 保单、账户须为投资账户。进/出 `split` 的 kind 变更一律拒绝（沿用 convert 的 kind 变更禁止先例），纠错只有「软删 + 重建」一条窄路。**被下游在用消耗过的批次**（后续 sell / convert / 后一次 split 已消耗）挂守卫：该 split 不可改、不可删——判据沿用 ADR-0097 / 0099 的「在用占用」谓词（归因到未软删下游行）。

### 6. 日期语义：写入序作用于当时的在用批次

split 的效果作用于**落账那一刻**的在用批次（与 buy/sell 一致：FIFO 排序键是插入序）；`date` 只承担展示与时点持仓（AsOfHolding）前缀求和。理由：FIFO 状态在后续交易发生后不可重建（ADR-0099 决策 2 的同一论证）；按交易日重算是另一个数量级的工程。代价显式接受：回填旧日 split 在批次侧重述的是落账时在场的批次，而 as-of 推算按日期把它计入历史前缀——两者在「今天」的聚合值一致，历史区间的批次构成是既定近似，写进词汇表而不假装精确。

### 7. 零盈亏与不变式

split 本身对已实现盈亏贡献**恒为 0**；全平仓恒等式 `Σ已实现 = Σ卖出 − Σ买入 − Σ转换结转成本` **不引入新项**（成本只是在同一标的的批次间重新分摊）。余额与净资产缓存（ADR-0067）由写路径同事务整体重算自动覆盖（六系数 0，缓存值不变），「回填 == 实时」对拍自动生效。

持仓市值、未实现盈亏与净资产**会随份额变化**——这是补上此前少算的份额，不是口径漂移；`accounts/balances` 不变只是「无现金腿」的弱表述，验收必须显式钉住两组数字。

### 8. 推算与视图

时点持仓推算模块纳入 split 腿（`+Δ`）；组合走势、净资产、可投资资产、持仓标的谓词随之自动跟随，兑现既有注释「未来公司行为落地时只改本模块内部」的承诺。持仓视图冻结不动，批次驱动自动跟随。

### 9. 同步：载荷只增、本地重建、不一致挂起

同步命令载荷只增（ADR-0091）；**不携带重述结果**，只携带 Δ（复用 `quantity`）。理由：重述是 `(当前批次快照, Δ)` 的纯函数，而重放端按 op 序重建的批次快照与源端一致——与 convert「转出时的 FIFO 状态在后续交易发生后不可重建、故必须携带结转成本」的前提不同。重放端本地重建重述并比对最终持仓与总成本，不一致即显式挂起（ParkedOp），不静默错账。确定性由尾差规则（归末批次）与批次序保证，**由一条确定性重放测试钉住，不靠纪律**。

### 10. 界面：无操作按钮，只读呈现（AI / 契约是唯一写入面）

产品定位以 AI 记账为主：这两类「无现金腿」记录对用户概念成本高——一笔记录静默改变持仓，且删一行会按 ADR-0097 级联软删下游真实卖出。故 convert 与 split 在 UI 上**不体现任何操作按钮**：无创建入口、无编辑、无软删；只保留列表、筛选与**只读详情**（需求「详情可辨识」无法用列表行替代）。筛选闭集保留这两个 kind——否则 AI 落进来的记录不可见、不可筛，那才是真的丢信息。写入与纠错仍走 HTTP 契约（AI / 迁移侧）。

本决策**反转 ADR-0099 决策 8** 交付的 convert 前端形态，改动另立票 #1048；本 ADR 只记录裁决本身。

### 11. 契约与导入知识

既然 AI / 契约是唯一写入面，`/api/v1/import/knowledge` 的份额调整教学节是**一等交付物**而非脚注：字段位置、方向符号、无现金腿、余额不变但持仓市值随份额变化、纠错步骤。契约方言优先零新增字段，`quantity` 的描述改动控制在现有余量内；越线才按 ADR-0090 的显式流程提预算并留痕。能力文案锁（「`dividend` / `split` 仍不受支持」）随实现改红 → 改绿。

### 12. 验收（迁移侧真实数据实写）

落上述 6 笔结转 + 1 笔被阻塞卖出（2026-06-26，5,820.53 份 / 7,730.25 元）：落账后 502010 持仓 `5,480.77 + 339.76 = 5,820.53`，卖出成功；split 前后 `GET /api/v1/accounts/balances` **完全不变**；份额换手与持仓视图前后差一致；净资产与未实现盈亏按决策 7 的增量断言；已实现盈亏不变。moomoo 5 笔送股**不纳入本票验收**（数据源待重新导出），但语义与测试必须覆盖股票标的。

## 备选与否决

- **0 成本新批次**：见决策 2——部分卖出的已实现盈亏由 FIFO 插入顺序决定，且负方向不可表达。
- **按交易日重算历史批次状态**：FIFO 状态后续不可重建，工程量量级不同，且与全库既有约定冲突（决策 6）。
- **顺带放开 `dividend`**：现金分红是现金腿 + 收入口径（已由 `income` 表达），与份额变动的领域语义无关，合并只扩大一次改动面；`dividend` 维持显式拒绝。
- **顺带就地重构两处 CHECK / 迁就迁移形态**：split 不需要动 CHECK，就地改已发布迁移只会白白引入 BREAKING 与存量库重建代价（决策 3）。
- **为 split 建专用扩展表或专用列**：单标的、单方向，既有「标的 + 带符号数量」已完整表达，新增表只增加一套读投影与契约面。
- **UI 保留编辑 / 删除入口**：与产品定位（AI 记账为主）及这两个 kind 的用户概念成本冲突（决策 10）。
- **同步重放携带重述结果**：其前提（FIFO 状态不可重建）在 split 不成立，白白放大载荷与两端比对面（决策 9）。

## 影响

- **行为层**：kind 守卫与分派（`dividend` 维持拒绝、`split` 转实现）、五处穷尽 match（prepare / apply / revert / release_for_delete / replay_plan）接入、kind 变更守卫；kind 守卫落点在 ADR-0105 的写入协议单正文。
- **投资域**：比例重述、批次重述审计表与精确回补、在用占用守卫、历史消耗回算改口径、时点持仓推算纳入 split 腿。
- **schema**：additive 迁移 V024 建 `security_lot_adjustments`；**零 CHECK 改动、零 BREAKING、存量库免重建**。
- **契约与前端**：AI 契约字段描述与导入知识教学节；前端只读详情形态（与 #1048 共用同一形态）。
- **词汇表同步（随行为层票落地，本 ADR 不抢先）**：核心交易域 `split` 词条由「拆股/送股」改写为「份额调整」并去掉「未实现」表述；投资域新增「份额调整（Split）」词条，并改掉「时点持仓」「PortfolioValueTrend」「Holding」「已实现盈亏」四处「split 被写入层拒绝故无影响」的现注；AI 导入域能力清单同步。**术语定义随行为可用而生效，避免文档领先于代码**——沿用 ADR-0099 的同一纪律。
- **前置**：代码排在 #1005（lots / unwind 深模块）之后，避免在投资域新增第五份 FIFO 取批 / 守卫 / 回退拷贝、再被该票碾一遍。
- **遗留假设（迁移侧环境就绪时验证）**：缩股方向的真实数据形态；moomoo 送股的份额精度与日期口径。

## 勘误注记（2026-09-11 实施 · #1053）

> **勘误 1（决策 9 落实口径：比对锚点随载荷携带，逐批次重述仍本端重建）**：决策 9 同时要求「不携带重述结果、只携带 Δ」与「重放端本地重建重述并比对最终持仓与总成本，不一致即显式挂起」——两者并置时后者缺参照物：仅携 Δ 时「比对」只剩自洽校验，前序 op 未达导致的部分快照发散无从可辨，与本决策「不静默错账」的验收判据冲突。实施裁决：比对锚点**必须**随载荷携带，取源端重述后的**总持仓与批次总成本**两个整数/标量（逐批次 before / after 快照仍不携带、仍由重放端本地重建）——这与各端「已发布契约只增不改」纪律相容，也与姊妹票 convert 携带 `carried_cost_cents` 作权威比对基准的先例同构（ADR-0099 决策 6）。落点：命令载荷新增可选成员 `SplitCommandFields { instrument_id, delta_quantity, final_quantity, total_cost_cents }`（`#[serde(default)]`），split 的 `investment` 成员随之恒为 None（与 convert 同形）；旧版本设备产出的 split op 缺该成员，经 kind 防御臂码化挂起（`transaction.split-fields-missing`），不静默落出未经校验的重述。`final_quantity` = Σ `remaining_after`、`total_cost_cents` = 权威闭合目标 Σ（锚点 − 既往记录消耗，重述精确不变），二者在源端与重放端由同一函数算出；不一致即 `transaction.split-restatement-mismatch` 挂起。决策 9 的其余部分（更新序、本地重建、不携逐批次重述）不变。

> **勘误 2（决策 5 落点：更新/删除已随 #1051 收编）**：本 ADR 决策 5 记「被下游在用消耗过的批次挂守卫」时，改 / 删 split 行的就地实现归 #1051（全字段替换 + 按重述审计逐批次精确回补），非「软删 + 重建」唯一窄路——后者只适用于**进 / 出 split 的 kind 变更**。
