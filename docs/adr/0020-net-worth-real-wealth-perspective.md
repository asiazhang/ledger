# ADR 0020: 首页净资产采用真实财富视角——非投资账户余额 + 持仓市值

- 状态：已接受
- 日期：2026-08-27
- 作者：Ledger 项目

## 背景

首页财务全貌仪表盘（spec #140）需要回答用户打开应用的第一问：「我现在总共有多少钱」。这要求把两类性质不同的资产合成一个本位币数字：普通账户里的现金（含存款、信用卡、负债等 8 类账户的 `account_flow` 余额），以及投资账户里当前持有的证券市值（含浮盈）。难点不在实现而在**口径**：投资账户余额与持仓市值是同一笔钱的两种表达，合错了就会重复计算；缺汇率的币种合错了就会给出看似正确实则残缺的数字。

## 决策

**采纳 B 方案（真实财富视角）**：净资产 = Σ 非投资账户折本位币余额 + Σ 折本位币持仓市值。

三个候选方案对比：

| 方案 | 口径 | 结论 |
| --- | --- | --- |
| A. 现金流视角 | 仅 Σ 非投资账户余额 | 否——抛掉持仓浮盈，回答不了「我总共有多少钱」；持有股票的用户净资产被系统性低估 |
| **B. 真实财富视角（采纳）** | Σ 非投资账户余额 + Σ 持仓市值 | 见下 |
| C. 全账户口径 | Σ 全部账户余额 + Σ 持仓市值 | 否——买入后现金扣减、持仓入账，同一笔钱被计两次，净资产凭空膨胀 |

配套细则：

1. **投资账户余额不计入**（B 方案成立的关键）：买入后现金已转化为持仓，账户侧剔除 `type='investment'` 后，「卖出得到的现金在普通账户余额里、持仓市值只计 `remaining_quantity` 对应部分」两个事实天然互斥，不重复计算。
2. **折算单一入口**：币种折算一律复用 Amount 接缝的 `convert_to_native`（基准为全局默认币种）；账户余额沿用 `list_account_balances_with_visibility` 的 `account_flow` 口径。不在命令里另写第二份口径表达式。
3. **缺汇率上抛**：任一参与合计的币种缺正反向汇率时，命令整体报错（中文错误信息），不静默返回残缺合计——错误的数字比没有数字更有害。
4. **未录价按空值语义**：`v_holdings.market_value_cents` 为 NULL（从未录价或缺折算汇率）的持仓跳过，不以零计入——零会把「未知」伪装成「已知为零」。
5. **负债账户维持现状**：按 `account_flow` 现行符号忠实求和，不在净资产层强制取负（口径修正是独立议题，见 spec #140 Out of Scope）。
6. **只读边界**：`dashboard_overview` 为纯新增只读命令，投资域不为其暴露任何新写函数（遵守 ADR-0013）；零 schema 迁移，不触碰发布冻结约束。

## 理由

- **B 是唯一同时满足用户故事 1（一眼看到总共有多少钱）与 2（含浮盈反映真实财富）的方案**：用户持仓的价值确实属于他，抛掉它是 A 的缺陷；重复计它是 C 的缺陷。
- **术语上明确避开「总资产」**：投资域词汇表（CONTEXT-investment.md）在 PortfolioValueTrend 词条已为「总资产走势」（含现金的历史时间序列）留位；净资产（当前时刻的静态合计）与总资产走势（时间序列）是两个概念，同页面混用同义词会造成口径混淆。
- **错误上抛优于残缺合计**：多币种用户缺一条汇率时，返回「少了某币种的合计」会被当作真实数字消费掉；报错并提示补汇率是对用户故事 5（看到清晰提示而非错误合计）的直接兑现。

## 代价

- 净资产依赖最新行情：`market_prices` 长期未同步时，净资产含过期市值。接受——市值口径本就是「最新已知价 × 当前持仓」，价格时效性由行情同步职责承担（ADR-0015），不在净资产层重复处理。
- 缺汇率时首页净资产卡整体不可用（而非降级显示部分合计）。接受——由前端捕获错误展示提示文案引导补汇率。
- 持仓按行折算到本位币存在逐行四舍五入误差（每持仓行 ROUND 到分）。接受——与交易行 `amount_native_cents` 的既有折算粒度一致。

## 替代方案

- A 方案（仅现金）：实现最简，可作为「现金流视图」在将来以独立指标补充，不与净资产互斥。
- C 方案（全账户 + 市值）：除非将来引入「投资账户内部现金」的独立表达，否则无正确形态。
- 前端拼装合计：被否决——跨币种口径若散落前端，与 `amount_native_cents`、报表等既有后端口径必然漂移（spec #140 用户故事 17 明确要求后端单一入口）。
