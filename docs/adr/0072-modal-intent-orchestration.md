# ADR-0072: 弹窗开启编排通用化——ModalIntent 工厂收编手搓弹窗三件套

- 状态：已接受
- 日期：2026-09-04
- 作者：Ledger 项目
- 关联：issue #521（spec，经 grilling 两轮收敛定型）；先例 ADR-0045（TransactionModalState，工厂语义蓝本与本决策的首个适配器）、ADR-0030 / ADR-0041（房式：工厂形态、纪律门槛与测试策略转移）、ADR-0035（弹层纯度边界）

## 背景

交易弹窗族的开启编排已由 TransactionModalState 证明（ADR-0045）：意图闭集进、显示开关由意图非空派生、目标行随递增序号内化、关闭清回空终态。但它只服务交易页——仓库其余弹窗各手搓一份「show + target + seq」三件套。#521 grilling 期盘点定稿：手搓三件套实存 13 处——目标行类十处（账户编辑、账户调整两处带序号守卫；物品编辑、实物资产表单〔新建/编辑双模式〕、实物资产估值、实物资产处置、预算编辑、计划编辑〔订阅页签〕、保单表单〔新建/编辑双模式〕、商户编辑八处无守卫）加纯新建布尔三处（订阅/分期/转账三页签的计划新建）；另有计划详情弹窗为 ref-expose 自含形态、账户新建为页面内联表单（两者不在收编范围）。手搓方言的代价已经现形：无守卫处「弹窗开着时目标行被替换」会回填指向旧行，不报错、只在特定时序下污染用户正在编辑的表单；关闭散落多处（提交成功处与模板取消各一份），无「清回空终态」的接口保证。spec 原稿的「七处」清单与实际不符——账户新建非弹窗、物品（Item）与实物资产（PhysicalAsset）两域混称、计划新建实为三页签三处。

## 决策

1. **新增通用工厂 `useModalIntent<TIntent>`（工厂形态 composable，弹窗意图编排）**：调用方声明意图闭集（判别联合，可携带目标载荷），工厂不持任何业务语义。接口四面：`intent`（`TIntent | null`，唯一事实源，显示由非空派生，无独立布尔）、`seq`（只读，随每次意图落位递增、关闭不重置）、`open(intent)`（纯同步：设意图 + 递增序号；每次开启产出全新意图对象，同一目标重开亦重触发消费方响应）、`close()`（清回 null 终态）。无「目标非空但已关闭」的中间态、无异步语义、不接弹层注册表（弹层纯度）。
2. **异步时序守卫留适配器层，不上浮**：TransactionModalState 迁为工厂之上首个适配器，对外接口与行为不变（意图闭集四、open 异步签名、异步守卫），既有模块测试零断言变化全绿为等价证据。其「编辑先取买卖明细再开窗、失败不开窗、最后一次开启胜出」守卫留在适配器——适配器代数计数器与工厂序号是**两个计数器**：代数随每次开启尝试递增（含取数失败），序号只在意图真正落位递增，语义不同、不合并。
3. **消费清单定稿（13 处，盘点取代「实施票发现」）**：目标行类十处——账户编辑、账户调整、物品编辑（ItemsView）、实物资产表单（新建/编辑双模式）、实物资产估值、实物资产处置（PhysicalAssetsView 三处）、预算编辑、计划编辑（订阅页签）、保单表单（新建/编辑双模式）、商户编辑；纯新建布尔三处——订阅/分期/转账三页签的计划新建（意图为单成员闭集）。**不在清单**：账户新建（页面内联表单，无开启编排可收）；计划详情弹窗（ref-expose 自含形态，无三件套样板，ADR-0041 决策 10「计划详情弹窗不动」边界不变）。物品与实物资产是两个域，清单与后续词汇按各自域术语书写。
4. **父层编排统一为硬边界**：意图状态只由弹窗所属父层经工厂持有；弹窗组件内部的表单回填机制（props 直灌或 watch 回填）不属本编排，各消费票裁量，不作为验收条件。
5. **等价边界与唯一一类显式行为变化**：迁移 = 等价重构 + 序号守卫从无到有一类显式声明的缺陷修复——「弹窗开着时目标行被替换回填旧行」缺陷类自此消亡，同目标重开重回填等边缘语义细化同归此类；每个迁移提交声明该处三件套现状（有无守卫）与迁移后等价或缺陷修复，杜绝悄悄改行为。
6. **迁移步骤**：工厂与 TransactionModalState 适配器化先行（用最复杂消费者立即检验抽象）；13 处消费各自独立提交、逐个可停，次序票内裁量。
7. **测试策略转移（ADR-0030 决策 7 同款）**：工厂零外部依赖（无 store、无 api、无组件），模块测试直接实例化直打接口——意图（开/重开/关/带载荷开）→ 意图终态与序号递增，不断言内部实现拓扑；各消费迁移以「既有视图测试零断言变化全绿」为等价证据，不可迁移用例删除时记录用例名与理由（ADR-0041 决策 10 同款）。

## 理由

- **为什么现在泛型化**：ADR-0045 理由段「target 锁 Transaction 不做泛型，等真正第二个消费者出现再参数化」的条件已触发——盘点确认 13 处消费者在望；继续手搓等于放任「回填旧行」缺陷类存续，新弹窗也仍会抄方言。
- **为什么判别联合而非 type + payload 二元组**：闭集由消费方类型声明，「意图非空即显示」的单一事实源性质靠判别联合的类型系统保证；开放字符串把闭集打散，回退到手搓时代的非法中间态。
- **为什么 open 纯同步**：异步取数是交易弹窗族特有形态（其余十二处开启即开），上浮通用工厂让全部简单消费者陪绑复杂度；守卫留适配层已被 ADR-0045 验证可测。
- **为什么序号公开为可观察终态**：它是表单重建与迟到回调过期判定两类消费的唯一凭据，也是本决策的测试断言对象（序号递增）；每次开启产出全新意图对象与之并存，watch 消费开箱即用，两机制不冲突。
- **为什么纯新建布尔也收编**：迁移成本一行；收益是消灭最后一种「布尔弹窗」方言——全仓只一种形态可模仿（新弹窗接入从「抄三件套并祈祷抄全」降为「声明意图」）；新建弹窗日后挂预填载荷时，单成员闭集天然扩得动。
- **为什么序号守卫从无到有按缺陷修复显式声明**：它是全决策唯一的用户可见行为变化；显式声明既锁死等价重构的验收边界，也防止实施时顺手多改。
- **为什么账户新建与计划详情弹窗不收**：前者是页面内联表单，无「开启/关闭编排」对象；后者无三件套样板且 ADR-0041 已判不动——收编无对象即形而上学，扩大范围违等价重构边界。

## 代价与边界

1. 迁移期手搓方言与工厂并存（至多 13 个独立提交的窗口），短期混存。
2. 序号守卫引入的语义细化（同目标重开重回填）是行为变化，按缺陷修复显式声明；既有依赖「重开不重回填」的用例（若有）属不可迁移用例，须记录用例名与理由。
3. 本决策只定接缝与纪律：不定各弹窗组件内部回填机制的取舍（票内裁量），也不定消费切换次序（票内裁量）。
4. 工厂接口面刻意最小（intent / seq / open / close 四面）；未来若出现多弹窗互斥、开启队列等需求，扩展接口而非复用现语义。
