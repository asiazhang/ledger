# ADR 0016: 自动定时备份（AutoBackup）

- 状态：已接受
- 日期：2026-08-27
- 作者：Ledger 项目

## 背景

备份功能目前只支持**手动触发**：用户需到设置页点"一键备份"或"另存为"。实践中用户长期忘记手动备份是常态，一旦数据丢失（磁盘故障、误操作、设备更换）往往追悔莫及。目标：让备份成为"有数据变化时自动发生"的保护网，用户无需记得。

但"自动定时备份"在桌面应用里有一层硬约束：**备份只能发生在应用运行且系统醒着时**——系统休眠期间进程挂起，任何定时器都不生效；应用退出后更是完全没有机会。因此设计必须回答三件事：① 什么算"数据有变化"；② 醒来后多久补上；③ 状态存哪里（避免跨会话丢失）。

## 决策

1. **触发模型：周期轮询 + 写时顺带检查，间隔固定 24 小时**。
   - 后台线程每 **30 分钟**醒来检查一次"距上次备份 ≥24h 且脏"→ 备份。系统休眠唤醒后最多 30 分钟内补上。
   - 每次业务写库成功后顺带检查是否已到期，到期立即备份——把备份提前到用户活跃时刻，缩小"该备份但马上要退出"的窗口。
   - 锚点是"距上次备份"而非固定时刻；备份频率上限是每天一次，不做小时级/自定义间隔。
   - 应用退出前若脏则兜底备份一次（不受每日约束）。
   > 注（2026-09-01 修订，见「修订记录」）：到期锚点已由「滚动 24 小时」修订为「本地自然日每天最多一次」，退出兜底「不受每日约束」的豁免同步取消——三个触发入口统一受同一道日界门约束，当天已有自动备份即静默跳过。本条按修订前原文保留。
2. **"数据有变化" = 任何业务写库成功**。置脏挂钩点：交易写入（经 Writer 接缝：增删改、批量导入、定时交易执行、buy/sell 交易行）、参考数据 CRUD（账号/分类，IPC + HTTP 端点）、市场数据写入（`create_exchange_rate` / `create_market_price` / `create_instrument`）。恢复操作不置脏；调度器自身状态写入不置脏（避免自触发）。
   > 注（ADR-0032）：挂钩点逐点手动调用的触发协议已修订为连接层统一写入口默认置脏 + 集中豁免（`app_settings` 全表 + 恢复路径）；本条的排除项与语义由 ADR-0032 承接，触发模型本身不变。
3. **开关与调度状态存 `ledger.db`（后端权威），`backupDir`/`backupMaxCount` 保持前端 localStorage**。原因：调度器跑在后端 Rust，消费的开关必须后端可见；前端 localStorage 后端读不到，双存储会产生同步不一致。`backupDir`/`backupMaxCount` 只在备份/清理时经 IPC 参数传入，无此问题，维持现状（设备本地偏好语义）。
4. **产物复用现有手动备份机制**（VACUUM INTO 快照 + zip 打包，ADR-0007），仅命名与元数据区分来源：`ledger-auto-YYYYMMDD-HHMMSS.db.zip` 前缀 + zip 内 `backup.json` 加 `kind: "auto"|"manual"` 字段。
   > 注（2026-09-01 修订，见「修订记录」）：自动备份命名的时间戳由 UTC 修订为本地时间，与手动备份命名拉齐；存量 UTC 命名产物不迁移，随滚动清理自然淘汰。
5. **清理语义：自动与手动受管备份同等对待**。共享 `backupMaxCount` 上限，最旧淘汰，不区分来源（沿用现有 `pruneToLimit` 逻辑，仅受管前缀集合扩展为 `ledger-backup-` + `ledger-auto-`）。手动"另存为"到备份目录外的文件仍不受约束。
6. **默认开启 + 首次兜底 + 目录未配置静默**。默认开启（间隔固定每天）；首次启动若备份列表为空（不分手动/自动）立即备份一次；`backupDir` 为空时自动备份静默不执行，设置页提示引导。
7. **失败处理**：失败弹 toast 通知 + 保留脏标记（下周期重试），不升级为持久警告；成功不通知。备份执行拿锁超时（5s）跳过本轮，保留脏标记。
8. **前端感知**：新增无 payload 事件 `ledger:backups-changed`，自动备份完成/清理后 emit；设置页打开时监听并刷新列表。

## 理由

1. **轮询 + 写时检查组合，是因为单靠任何一个都不够**。纯轮询的检查间隔受"备份频率"（24h）锚点限制，休眠 3 天醒来要等下一个锚点，可能又睡过去；纯写时检查在"用户连续几天只读不改"时永远不触发。30 分钟轮询兜底 + 写时提前触发，二者互补，且都不改变备份频率上限（每天一次）。
2. **状态存库是唯一自洽选项**。调度器在后端消费开关/到期时间；存前端 localStorage 后端读不到。存 `ledger.db` 顺带获得跨会话持久与随备份/恢复迁移的一致性——恢复后调度状态与数据同源，不会出现"恢复旧数据但调度状态是新会话的"错位。
3. **自动/手动同等对待，是因为"受管备份"的语义就是"系统替你管理数量"**。手动快照是用户主动动作，自动快照是保护网，二者都受同一上限约束、最旧淘汰，心智模型最简单。分桶配额（自动独立上限）会让手动备份挤掉自动保护网或反之，徒增理解成本。
4. **目录未配置时静默，与手动备份心智一致**（手动备份也是选目录才生效）；默认目录兜底会把备份写到用户找不到的地方，反而更危险。
5. **失败不重试，因为保留脏标记就是重试机制**——下个周期自然再试，无需额外的失败队列/退避逻辑。

## 代价

1. **休眠期间的变更在唤醒后才备份**：最长窗口 = 24h 间隔 + 30 分钟检查周期（+ 唤醒后补上；修订注记：检查周期已收紧为 10 分钟，见「修订记录」；2026-09-01 再修订：改为自然日语义后，当天已备份的后续改动最坏要到次日第一个触发点才受保护，见「修订记录」）。对记账场景可接受，但需在文档/UI 里明确"备份是尽力而为，不是实时"。
2. **自动备份的产物与手动混在同一目录**：靠命名前缀与元数据 kind 区分；`isManagedBackupPath` 等按前缀判定的逻辑需扩展为前缀集合，涉及前端常量与后端清理逻辑两处。
3. **调度状态存 `ledger.db` 引入一个新表**（或复用 meta 区）：迁移 V008；恢复旧版本备份时该表缺失，需容忍缺失（视为未配置/未开启）。
4. **写时顺带检查给写路径增加一次状态读取**：每次写库后读一次到期时间（毫秒级，可忽略），但需确保不引入额外锁竞争（读与写都走现有串行连接）。

## 替代方案

- **纯固定时刻触发（每天 0 点）**：休眠/关闭错过就跳一天，锚点混乱；与用户活跃时刻脱节，否决。
- **纯写时触发（写即备份）**：高频写入会频繁备份（即使有 24h 间隔限制，写时检查仍是轮询的补充而非替代——纯写时在只读期永不触发），否决。
- **开关/状态存前端 localStorage + IPC 同步**：双存储、同步逻辑、重启后以后端为准，不一致风险高，否决。
- **自动备份独立数量上限（分桶）**：与"受管备份共享配额、最旧淘汰"相比，分桶语义复杂且手动/自动互相挤占生存空间，否决。
- **默认关闭 + 用户显式开启**：违背"避免用户忘了"的初衷——默认开启 + 首次兜底才是保护网，否决。
- **失败升级为持久警告**：UI 复杂度高，收益低（脏标记保留已保证下周期重试），否决。

## 修订记录

- **2026-09-01：触发语义修订——「滚动 24 小时」改「本地自然日每天最多一次」，取消退出兜底的每日豁免，自动备份命名改本地时间。** 「备份频率上限是每天一次」的声明与退出兜底「不受每日约束」的豁免自相矛盾，且同日多次退出应用（迁移期反复重启）实际产生多份产物。修订内容：
  - 到期判定由「距上次备份 ≥24h 且脏」改为「今天（本地自然日）尚未自动备份过且脏」；调度状态沿用「上次自动备份时刻」单一锚点，判定时换算本地日期比较，不新增设置键、不迁移数据。「今天」取本地时区，与定时追补、订阅花费总览同口径（跨时区随之漂移）。
  - 三个触发入口（到期轮询 + 写时顺带检查 / 退出兜底 / 首次兜底）统一受同一道日界门：当天已有自动备份即静默跳过；当天尚未备份时各入口仍按原语义触发。当天已备份后的后续改动当天不再备份（跳过而非覆盖当天文件），次日第一个触发点补上；手动备份不计入「今天已备份」。
  - 自动备份产物命名的时间戳由 UTC 改为本地时间，与手动备份命名拉齐；列表展示取文件名时间戳原样呈现，改名后界面自然显示本地时间。存量 UTC 命名产物不迁移，随滚动清理自然淘汰。
- **2026-08-31（issue #306）：轮询检查周期 30 分钟 → 10 分钟。** 触发模型（周期轮询 + 写时顺带检查 + 退出兜底）、备份频率锚点（距上次成功备份 ≥24h 且脏）与「尽力而为、非实时」定位均不变，收紧的只是检查间隔——它只影响「到期后多久被发现」：睡眠唤醒后最多 10 分钟内补上备份（原最多 30 分钟）。代价可控：未到期的每轮开销仅为拿锁 + 读几行设置 + 一次日期比较（毫秒级），备份频率上限（每天一次）不变。
