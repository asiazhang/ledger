# ADR 0016: 自动定时备份（AutoBackup）

- 状态：已接受（触发语义与失败呈现均已修订，正文收束为现行态，沿革见演进脉络）
- 日期：2026-08-27（现行态收束：2026-11-20）
- 作者：Ledger 项目
- 关联：ADR-0007（文件级快照备份机制）、ADR-0032（置脏触发收口统一写入口）；词汇表：备份与数据文件域 AutoBackup / DirtyMarker / BackupRetentionLimit

## 背景

备份功能原本只支持手动触发，用户长期忘记手动备份是常态，一旦数据丢失往往追悔莫及。目标：让备份成为"有数据变化时自动发生"的保护网，用户无需记得。

但"自动定时备份"在桌面应用里有一层硬约束：**备份只能发生在应用运行且系统醒着时**——系统休眠期间进程挂起，任何定时器都不生效；应用退出后更是完全没有机会。因此设计必须回答三件事：① 什么算"数据有变化"；② 醒来后多久补上；③ 状态存哪里（避免跨会话丢失）。

## 决策（现行）

1. **触发模型：周期轮询 + 写时顺带检查 + 退出兜底，频率锚点 = 本地自然日每天最多一次**。
   - 后台轮询每 **10 分钟**醒来检查一次「今天（本地自然日）尚未自动备份过且脏」→ 备份；系统休眠唤醒后最多 10 分钟内补上。
   - 每次业务写库成功后顺带检查是否当天已到期，到期立即备份——把备份提前到用户活跃时刻，缩小「该备份但马上要退出」的窗口。
   - 三个触发入口（到期轮询 / 写时顺带检查 / 退出兜底 / 首次兜底）统一受同一道**日界门**：当天已有自动备份即静默跳过，次日第一个触发点补上；当天已备份后的后续改动当天不再备份。手动备份不计入「今天已备份」。锚点是本地自然日而非滚动 24 小时（跨时区随之漂移，与定时追补、订阅花费总览同口径）；不做小时级/自定义间隔。
2. **"数据有变化" = 任何业务写库成功**。置脏经 ADR-0032 的连接层统一写入口默认置脏 + 集中豁免（`app_settings` 全表 + 恢复路径 + 调度器自身状态写入）承接——恢复操作不置脏，避免自触发。
3. **开关与调度状态存 `ledger.db`（后端权威），`backupDir`/`backupMaxCount` 保持前端 localStorage**。调度器跑在后端 Rust，消费的开关必须后端可见；双存储会产生同步不一致。`backupDir`/`backupMaxCount` 只在备份/清理时经 IPC 参数传入，维持设备本地偏好语义。
4. **产物复用手动备份机制**（VACUUM INTO 快照 + zip 打包，ADR-0007），命名前缀与 zip 内元数据 kind 字段区分来源，时间戳取**本地时间**（与手动备份命名拉齐；存量 UTC 命名产物随滚动清理自然淘汰）。
5. **清理语义：自动与手动受管备份同等对待**。共享 `backupMaxCount` 上限，最旧淘汰，不区分来源；手动「另存为」到备份目录外的文件不受约束。
6. **默认开启 + 首次兜底 + 目录未配置静默**。默认开启；首次启动若备份列表为空（不分手动/自动）立即备份一次；`backupDir` 为空时自动备份静默不执行，设置页提示引导。
7. **失败处理：保留脏标记下周期重试 + 连续失败达阈值后设置页状态提示**。调度状态新增连续失败计数（执行失败累加且饱和、一次成功清零，计数写入沿 ADR-0032 置脏豁免不自激）；达阈值（3 次）后设置页自动备份卡片呈现用户可见提示（失败次数 + 排查指引）并经 `ledger:backups-changed` 通知刷新，提示持续到成功清零后撤下。单次失败不上浮界面；不升级为持久警告或阻塞弹窗（保留脏标记即重试机制，无需失败队列/退避）。备份执行拿锁超时跳过本轮、保留脏标记。
8. **前端感知**：无 payload 信号 `ledger:backups-changed`，自动备份完成/清理后 emit；设置页打开时监听并刷新列表。

## 理由

1. **轮询 + 写时检查组合，因为单靠任何一个都不够**：纯轮询的检查间隔受频率锚点限制，休眠 3 天醒来要等下一个锚点；纯写时检查在「连续几天只读不改」时永不触发。10 分钟轮询兜底 + 写时提前触发互补，且都不改变频率上限（每天一次）。
2. **状态存库是唯一自洽选项**：调度器在后端消费开关/到期时间；存 `ledger.db` 顺带获得跨会话持久与随备份/恢复迁移的一致性——恢复后调度状态与数据同源。
3. **自动/手动同等对待**：「受管备份」的语义就是「系统替你管理数量」；分桶配额会互相挤占生存空间，徒增理解成本。
4. **目录未配置时静默，与手动备份心智一致**；默认目录兜底会把备份写到用户找不到的地方，反而更危险。
5. **连续失败计数是「静默失败」教训的收口**：保留脏标记的重试在现场结构性不可能成功时（备份目录永久失效）退化为无限静默失败（#1452 事故中安全网停摆 4 天只能从日志发现）——达阈值的状态提示补上用户可见性，不引入阻塞弹窗。

## 否决方案与代价

**否决方案（防重提）**：纯固定时刻触发（每天 0 点，休眠/关闭错过跳一天）；纯写时触发（只读期永不触发）；开关/状态存前端 localStorage + IPC 同步（双存储不一致风险）；自动备份独立上限分桶（语义复杂互相挤占）；默认关闭 + 显式开启（违背保护网初衷）；失败升级为持久警告/阻塞弹窗（脏标记已保证重试，复杂度不值）。

**代价与已知边界**：休眠期间的变更在唤醒后才备份（当天已备份后的改动最坏到次日第一个触发点才受保护）——「尽力而为、非实时」定位须在文档/UI 明确；自动产物与手动混在同一目录（靠命名前缀与 kind 区分）；调度状态存 `ledger.db` 恢复旧版本备份时需容忍表缺失（视为未配置）；写时顺带检查给写路径增加一次毫秒级状态读取。
