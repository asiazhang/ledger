# ADR-0095: 标的信息同步确定进度——事件驱动、有通道分母、不做取消

- 状态：已接受
- 日期：2026-09-09
- 作者：Ledger 项目
- 关联：ADR-0081 决策 3（旧全量同步进度/取消事件整体退役，本 ADR 在现役增量同步上重建）；ADR-0031 / ADR-0044（价格失效信号边界：进度事件不是失效信号）；ADR-0054（主线程非阻塞投递，进度事件共用该机制）；词汇表：投资域「InstrumentInfoSync」「价格失效信号」、界面状态与交互域「GlobalBusyBar」

## 背景

「同步标的信息」（InstrumentInfoSync）触发后，界面上只有同步按钮转圈与顶部无确定进度的全局忙碌条（GlobalBusyBar）。同步覆盖库内全部标的：行情分区逐标的报价 + 日 K 回填、基金逐只拉净值 + 逐只拉名称，在约百只标的的用户库上是分钟级长任务——用户无法得知同步进行到哪、还剩多少、什么时候完成。

旧「标的全量同步」曾有进度/取消事件，已随 ADR-0081 决策 3 整体退役；本 ADR 是在现役增量同步上重建进度可见性，不是恢复旧全量同步。

## 决策

### 1. 确定进度、事件驱动（而非不确定指示）

同步进度由后端在编排过程中发出的**带 payload 确定进度事件**驱动：`ledger:instrument-sync-progress`，payload 为 `{ done, total }`，经既有主线程非阻塞投递机制（ADR-0054）发出。前端不做任何估算或假装进度。

- 进度事件**不是**失效信号：带 payload、高频逐标的推进，与无 payload、粗粒度、只锚「数据变了」的 `ledger:prices-changed` 语义不同；发射不经 signals 映射单点（ADR-0044 只裁决失效信号）。价格失效信号的发射条件（实际写入才广播）不变。
- 事件名常量与发射入口归 sync 域收口（不经失效信号映射的带 payload 事件只共用投递机制，先例见 events 模块分工）；编排核心不碰事件系统——同步编排核心函数在既有五个抓取闭包之外追加一个进度回调闭包，生产入口（命令壳）把回调接到事件发射，测试注入 mock。
- **确定百分比的全局进度仍然不做**：GlobalBusyBar「无确定进度」的既有划界不变。本条是同步场景专属的局内确定进度；GlobalBusyBar 词条中原本指向「行情同步进度条」的划界改指向本进度条。

### 2. 分母口径 = 有通道标的数，跳过行不计

- 分母 `total` 为**有通道标的数**：行情分区（股票/场内 ETF，可构造 secid 查询）逐标的计 1（报价 + 日 K 合并为该标的完成）；场外基金逐只计 1（净值水位增量 + 名称查询合并为一步完成）。名称充代码的基金行（无真实代码）、市场未知与无行情类型（债券/其他）行无通道，不计入分母——它们本就计入「跳过 M 只」统计。
- `total` 时点：标的收集与通道分区完成后立即发 `{ done: 0, total }`；之后每完成一个有通道标的推进一格。停牌/查询无果/基金「已是最新（无新净值）」照常推进——推进速度对齐真实处理量，而非成功量。
- 分母为 0（空库或全部无通道）不发任何进度事件：空转不伪装成推进，既有「暂无标的可同步」与跳过统计提示照旧。
- 不显示阶段（无「正在同步基金净值…」之类的阶段披露）；不按请求数计更细粒度。
  > **修订（issue #1061）**：首刷/深回填的场外基金在**页级**追加一个可选明细字段 `fund`，仅暴露「回填的基金代码 + 已完成页 / 总页数」，不引入阶段标签、不按请求数重算百分比——分母口径与进度条宽度仍全是标的级 `done`/`total`。见文末修订记录。

### 3. 不做取消

同步幂等、失败可重跑，本期不引入中断/取消机制；前端接缝不造「取消」态的既有口径不变。进行中重复触发走既有在途短路复用，进度条展示的是唯一那次在途同步。

## 前端形态与状态归属（随决策 1 落地）

- 进度条形态与 GlobalBusyBar 同款细条、蓝色区分，条旁一行计数文案「同步标的信息 37/100」，经 i18n 随界面语言；基金深回填期间（issue #1061，见修订记录）计数文案之下再一行页级明细「回填 110022：第 3/25 页」。
- 位置两处：盈亏页「当前持仓」卡顶部、标的页标的列表顶部；进度状态收口在既有 `useInstrumentInfoSync` 接缝——订阅进度事件、产出可观察进度、终态（成功/失败）收起清空。接缝承诺从「同步完成即通知失效」扩展为「同步全程可见、完成即通知失效」；两入口渲染同一份展示组件，行为零分叉。
- 同步完成后进度条收起，现有「已同步 N 只，跳过 M 只」结果消息照旧；失败时进度条收起、走既有错误通道。同步期间界面照常可用（无模态、快捷键不被抑制），价格与名称写入后的列表刷新仍由价格失效信号驱动。

## 备选否决

- **前端假装进度（估算 + 动画）**：分钟级任务的假进度必然长期卡在 90%，比没有进度更糟；确定进度必须来自真实编排事件。
- **按请求数计进度**：每标的请求数不等（基金首刷多页、股票固定两请求），按请求计会让百分比与「处理了多少只」脱节；按标的计格与「还剩多少只」的用户心智一致。
- **把进度做成失效信号**：失效信号无 payload、粗粒度，塞进 `{done,total}` 会破坏其「数据变了」语义锚（ADR-0031），各消费方被迫过滤不相关载荷。
- **复用旧全量同步的进度事件名**：旧事件随 ADR-0081 决策 3 退役且不在 `ledger:*` 命名空间；新事件归位命名空间、由现役域收口。

## 后果

- **词汇表修订**：投资域「InstrumentInfoSync」词条补进度承诺（事件、分母、终态收起）；界面状态与交互域「GlobalBusyBar」词条的「与同步进度条划界」改指向本进度条（原「行情同步进度条」已悬空）。
- 前端 `useInstrumentInfoSync` 接缝扩展（订阅进度事件、共享进度状态、在途短路跨入口唯一），调用方接线不变。
- 取消/中断留待后续；若未来引入，须新 ADR 推翻决策 3。

## 修订记录

- 2026-09-11 深回填页级可见（issue #1061）：决策 2 的「不显示阶段 / 不按请求数计更细粒度」按**页级明细**修订——首刷回填一只场外基金要翻约 25 页（服务端 20 条/页硬上限，ADR-0038 决策 6）、按全局限速接近一分钟，期间标的级进度完全静止、看起来像卡死。现于进度事件追加**可选** `fund` 字段（`{ code, page, pages }`），每页**抓取返回之后**推进一次：抓取内部的退避/重试等待不产生推进（等待不伪装成推进）；被拦截的空响应页（报文 `Data` 缺省/非对象）不算「已回填的一页」、不推进页码，与 #1059「空响应不是成功」同源；基金完成后的标的级推进（无 `fund`）清掉明细。分母口径与进度条宽度仍全是标的级 `done`/`total`（跳过行不进分母的不变量不变），单页的增量常态不产生该字段。前端 `useInstrumentInfoSync` 接缝透传明细、进度条以次行文案展示（ADR-0049 i18n）。仍不做全局确定百分比、不做取消。
- 2026-09-12 grilling 复核（模型审查）：①「既有五个抓取闭包之外追加一个进度回调闭包」中的抓取闭包现为**六个**（函数签名与注入同样式），计数以代码为准；②前端形态节的进度条位置自「盈亏页『当前持仓』卡顶部」迁至**投资页持仓页签**（#902 起概览卡随盈亏页改造迁入持仓页签；与标的页顶部仍为两入口共用同一接缝）。
