# ADR-0068: 性能阈值与门禁——perf-bench 全部基准 p95 ≤ 200ms 判定

- 状态：已接受（分项例外机制保留、清单为空；正文收束为现行态，沿革见演进脉络）
- 日期：2026-09-04（现行态收束：2026-11-20）
- 作者：Ledger 项目
- 关联：ADR-0062（本 ADR 兑现其「观察期后另立决策」承诺）、ADR-0009（100ms 慢查询告警线保留不动）、ADR-0008（列表分页契约不动）、ADR-0027（搜索实现形态——B1–B3 修复与基准项出入集的关联决策）、ADR-0067（余额/净资产缓存，消灭两个 88s 项）、ADR-0114（跨账本投资汇总基准项的被测路径）；#489（性能达标 spec）、#490–#493（B1–B3 修复与本 ADR 落地票）、#514/#516（分项例外立撤）、#1627–#1630（基准集扩围四票）、#1640（CI 首跑分布复核与三项超标处置）、#1654/#1655（超标项优化票）、#1885（商品名搜索入集）、#1915（基准语料失真修正）；词汇表无新增词条（开发侧基础设施与 CI 行为，不产生领域术语）

## 背景

ADR-0062 落地确定性基准数据集与 bench 工具（50 万笔 seed 42 库）时明确 CI「只记录不判定」：尚无达标基线，阈值无从谈起。彼时 perf-bench #1 基线显示：10 项基准 9 项超 100ms 慢查询告警线，全账户实时余额与净资产总览各约 88 秒、备注搜索 2.9 秒。#489 据此拆出 B1–B3 三层修复（V016 结构索引、V017 余额缓存〔ADR-0067〕、V018 搜索两段式〔ADR-0027〕），合入后全部基准项回落到 200ms 线以内且分布稳定——观察期结束，若继续「只记录」，B1–B3 的成果随时会被无声侵蚀，兑现承诺的条件成熟。

## 决策（现行）

1. **阈值判据：全部基准 p95 ≤ 200ms，分项例外机制保留、清单为空**。perf-bench CI（ubuntu-latest runner，现场生成 50 万笔 seed 42 确定性库）对全部基准项（当前 16 项）逐项判定 p95 ≤ 默认线，任何一项超标 job 失败。默认线 200ms 取交互可感阈值的工程上限，与 ADR-0009 的 100ms 观测线保持 2× 关系，覆盖索引加速型基准的 CI 实测分布（余量约 1.4×）；**新增基准即自动纳入门禁，无需登记**。个别基准确需不同阈值时，例外清单钉在 bench 工具内（`PER_BENCH_MAX_P95_MS`）并由测试钉住，增删例外须同步修订本 ADR——清单当前为空，历史两轮立撤见演进脉络。
2. **统计口径：预热 3 次 + 计时 20 次，p95 最近秩法**。预热只热 SQLite 页缓存；n=10 时 p95 恒等于 max、无分位数分辨力，迭代 10 → 20（rank=19）是判据成立的前提。判据一律以 CI 运行为准，本地 NVMe 计时与 CI 盘差异可达数倍，只作开发参考。
3. **判定下沉工具内，workflow 只传参**：`ledger-perf bench --max-p95-ms 200` 对全部基准项逐项判定，超标即打印清单（随 tee 进 Job Summary）并以非零退出码失败——本地与 CI 跑同一条命令，门禁行为可精确复现，不存在第二事实来源。执行面为每日 cron + 手动 dispatch，**不进 PR 流水线**（release 冷编译 + 生成 + 四段基准约 35 分钟/次，逐 PR 成本不可接受）；「无变动即跳过」门闸兜底：调度触发时比对本次提交与最近一次成功运行的 head_sha，相同即整体跳过，上次失败则差异成立次日自动重试。拦截路径＝性能相关批次合入后手动触发留基线 + 每日 cron 常规运行。
4. **豁免原则：基准集内读/写形态全覆盖，外部网络往返不进判据**。读基准项逐项判定；写基准（bench-import 批量导入、bench-sync 同步重放、bench-market 行情批量 upsert）走权威写入口、随每日 cron 固定参数观测并记录进 Summary——但**写基准阈值未立，现行只观测不判定**，立阈值须修订本 ADR 另立判据，不悄悄纳入门禁。启动迁移、备份/恢复等合法慢路径不在基准集内。**网络边界豁免**：S3 通道传输、行情源抓取、AI 请求等外部往返不进判据——往返延迟由外部服务决定，不反映本地路径回归；基准剥离网络、只量本地部分（bench-sync 只量 apply_ops/ingest_ops 本地合并写库，bench-market 只量价格写入单点本地落库）。
5. **ADR-0009 的 100ms 单条 SQL 慢查询告警线保留不动**，两层互不替代：观测线回答「哪条 SQL 慢」（语句级、warn、含启动迁移等全部上下文），门禁线回答「这批用户可感查询是否达标」（基准项级、p95、仅 CI 判定）。每项基准的 ▲ 报告标记仍按观测线点亮，与门禁行并存各表其义：▲ 超观测线不等于门禁失败。

## 否决方案

- **阈值定 100ms（与告警线一致）**：CI 盘慢、runner 抖动大，必然假红；且 100ms 是语句级观测线，与基准项级阈值不是一个口径，否决。
- **p50/avg 判据**：均值对尾延迟不敏感，而用户感知的正是「最慢的那一次」，p95 才与体感对齐，否决。
- **PR 触发 perf-bench（逐 PR 拦截）**：单次数十分钟乘以 PR 频率成本不可接受；拦截由「性能批合入后手动触发 + 每日 cron（无变动即跳过）」承担，否决。
- **workflow 侧脚本解析报告做判定**：判定逻辑与数据源分离后本地无法复现门禁，CI 与本地必然漂移；判定下沉工具内则天然同源，否决。
- **进程内候选缓存消除搜索慢（ADR-0027 预留手段）**：以数十 MB 常驻堆为代价，而真实用户设备本就达标、超标仅是 CI 验收环境画像，不成比例，否决；手段保留预留，未来低端设备实测超标再评估（届时亦可考虑本地文件 + mmap）。

## 后果与处置纪律

- 性能回归在 perf-bench 运行时被拦截：job 红、Summary 列出超标项名字与实测值及各自阈值。门禁首跑即兑现价值（拦截搜索项本地/CI 口径差异），历史超标处置均按下列纪律走，见演进脉络。
- CI runner 抖动可能造成间歇假红：默认线余量最小的项约 2.0×。处置纪律：复核单次运行的完整分布（报告含 min/avg/p95 全列）；持续贴线或常态超标则修订本 ADR 显式调整阈值——不悄悄改参数重跑，不以单次绿掩持续红；测量对象失真（语料/计划翻转类）修正测量对象而非放宽判据。
- 迭代 10→20 使计时阶段约翻倍，相对单次全程（约 35 分钟）可忽略；bench 缺省仍不判定（`--max-p95-ms` 缺省 None），门禁是 CI 调用参数不是工具缺省行为。
