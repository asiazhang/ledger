# ADR-0068: 性能阈值与门禁——perf-bench 全部读基准 p95 ≤ 200ms 判定

- 状态：已接受（兑现 ADR-0062 观察期承诺；正文已按 #514–#516、#1627–#1630、#1640、#1727/#1735、#1885/#1915 现行态收敛）
- 日期：2026-09-04（现行态收敛：2026-10-09）
- 作者：Ledger 项目
- 关联：ADR-0062（确定性基准数据集与工具）；ADR-0009（100ms 单条 SQL 慢查询告警线）；ADR-0008（服务端分页）；ADR-0027（交易搜索 SQL 下推，撤销原 400ms 分项例外的前提）；ADR-0067（余额/净资产缓存）；ADR-0114（跨账本投资汇总基准）；ADR-0138（购买项名称搜索基准）；#489（性能达标 spec）、#493（门禁落地）、#1627–#1630 / #1640 / #1727 / #1735 / #1885 / #1915

## 背景

ADR-0062 落地 50 万笔 seed 42 确定性基准库与 `ledger-perf` 工具时先实行「CI 只记录不判定」（首跑 10 项基准 9 项超 100ms，余额/净资产 ~88s、备注搜索 2.9s）。经 #489 三层修复（V016 覆盖索引、V017 余额/净资产缓存 ADR-0067、V018/SQL 下推搜索优化 ADR-0027）后，全部读基准回落至 200ms 线内，观察期结束，性能门禁正式立规以防后续改动无声侵蚀。

## 决策

### 1. 阈值判据：全部读基准默认 p95 ≤ 200ms，保留分项例外机制（当前为空）

- **默认线 200ms**：perf-bench CI（ubuntu-latest、现场生成 50 万笔 seed 42 确定性主库 + 2 本 2,000 笔附属账本）上，全部读基准项（当前 16 项，覆盖列表、余额/净资产、报表三件套、备注与商品名搜索、持仓/走势/XIRR/财务自由度、跨账本投资汇总）逐项判定 `p95 ≤ 200ms`，任一项超标即 job 失败。新增读基准自动适用默认线，无需额外登记。
- **分项例外机制保留，清单当前为空**：`PER_BENCH_MAX_P95_MS` 钉在 bench 工具内并由测试锁定，增删例外必须同步修订本 ADR。原交易搜索 400ms 分项例外已随 SQL 下推（#515/#516）撤销。
- 默认线 200ms 取交互可感上限，与 ADR-0009 的 100ms 语句级告警线保持 2× 关系。

### 2. 统计口径：预热 3 次 + 计时 20 次，最近秩法 p95，以 CI 为准

- 预热 3 次不计入统计（仅热 SQLite 页缓存；#1735 纠正：全仓未接入语句缓存 `prepare_cached`）。
- 计时迭代 20 次，p95 取升序样本第 ⌈0.95·n⌉ = 19 位（n=10 时 p95 恒等于 max，无分位数分辨力）。
- 判据一律以 CI runner 口径为准，本地开发机计时仅作参考（同库扫描型项 CI 约为本地 1.8–2.1×）。

### 3. 判定下沉工具内；每日 cron + 无变动跳过门闸，不进 PR 流水线

- 门禁判定在 `ledger-perf bench --max-p95-ms 200` 内实现（缺省不判定，不影响本地调试），超标输出清单并以非零退出码失败；`.github/workflows/perf-bench.yml` 只传参调用，消除本地与 CI 第二判定源。
- 执行面为**每日 cron + 手动 dispatch**，不进 PR 流水线：单次全程含 release 编译 + 生成 + 四段基准（1 读门禁 + 3 写观测），命中 rust-cache 后约 35 分钟，逐 PR 跑成本不可接受。
- 每日 cron 由 gate job 比对本次 `head_sha` 与本 workflow 最近一次成功运行的 `head_sha`，无新提交即整体跳过；上次失败则差异仍成立、次日自动重试。

### 4. 覆盖边界：写基准只观测不判定，网络往返与合法慢路径豁免

- **写基准形态（观测面）**：`bench-import`（批量导入）、`bench-sync`（同步重放）与 `bench-market`（行情/价格历史批量 upsert）同属基准集，走权威写入口随每日 cron 记录进 Summary，因写单元成本高且缺少交互阈值依据，**现行只观测不判定**；未来立阈须修订本 ADR。
- **网络边界豁免（#1628）**：S3 同步传输、行情源抓取、AI 请求等外部网络往返不进判据；基准剥离网络，只量测本地合并与写库。
- **合法慢路径不入集**：启动迁移、备份/恢复等不进基准集；ADR-0009 的 100ms 单条 SQL 慢查询告警线保留并行（语句级观测 vs 基准项级门禁，报告中 `▲` 超告警线不等于门禁失败）。

### 5. 超标处置纪律

持续贴线或超标时，须先复核单次运行完整分布（min/avg/p95）并区分三类根因，不悄悄改参数掩盖：
1. **查询计划翻转 / 实现缺陷**：随票钉定索引或单独立优化票修复，**不立分项例外**（先例：#1640 分类占比因 V029 加列致 SQLite 3.51 计划翻转，用 `INDEXED BY` 钉回；商户占比 #1655 与组合趋势 #1654 单独立优化票）。
2. **基准语料失真**：修正生成语料逼近真实分布而非放宽判据（先例：#1915 商品名搜索 16 词小池致单字命中 39% 订单，扩至 400 词 SKU 级名称池后回落默认线，ADR-0062）。
3. **计算模型确与默认线异类**：经实测分布论证后修订本 ADR 登记分项例外。

## 备选与否决

- **阈值定 100ms**：与 SQL 语句级告警线混淆，在 CI runner 抖动下对扫描型项必然假红，否决。
- **p50 / avg 判据**：掩盖尾延迟，与用户体感脱节，否决。
- **进 PR 流水线**：单次 ~35 分钟，PR 频率下成本不可接受，否决。
- **workflow 内用 awk/脚本解析报告判定**：本地无法同命令复现，易漂移，否决。
- **用进程内候选缓存消除搜索慢（#493 否决）**：几十 MB 常驻堆内存换 CI 验收余量不成比例；SQL 下推（#515）落地后搜索 CI p95 降至 ~70–82ms，已无引入必要。

## 演进摘要（关键节点证据）

- **400ms 搜索分项例外的设立与撤销（#493 → #514 → #516）**：门禁首跑（run 33867886806）拦截了备注搜索本地 154ms vs CI 313ms 的口径差异，初设 400ms 分项线（后随 #514 扩至两项）；#515 搜索 SQL 下推落地后实测 CI p95 降至 69.5ms / 82.2ms，#516 正式撤销全部搜索例外，默认线 200ms 收回全局生效。
- **基准集演进**：初版 10 项 → 增拼音子序列（#514，后随 #1727 交易搜索退回原文而出集）→ 增商户占比/组合走势/XIRR/财务自由度（#1627）→ 增跨账本投资汇总及多账本夹具（#1630）→ 增商品名搜索（#1885，#1915 修正语料），现役 16 项读基准 + 3 项写观测基准。
- **触发频率（2026-09-04）**：由每周 cron 改为每日 cron + 无变动跳过门闸，压缩回归发现窗口同时避免无提交空转。

## 后果

- 性能回归在每日 perf-bench 中以显式失败和超标清单暴露，不再靠人工翻日志。
- 基准集增删、例外变更与写基准立阈均受本 ADR 与名单钉住测试双重约束。
