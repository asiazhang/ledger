# ADR-0068: 性能阈值与门禁——perf-bench 全部基准 p95 ≤ 200ms 判定

- 状态：已接受
- 日期：2026-09-04
- 作者：Ledger 项目
- 关联：ADR-0062（本 ADR 兑现其「观察期后另立决策」承诺）、ADR-0009（100ms 慢查询告警线保留不动）、ADR-0008（列表分页契约不动）、ADR-0027（搜索全量扫描语义与实现形态，分项例外的对象）、ADR-0067（余额/净资产缓存，消灭两个 88s 项）；#489（性能达标 spec）、#490/#491/#492（B1–B3 三层修复）、#493（本 ADR 与门禁落地票）；词汇表无新增词条（开发侧基础设施与 CI 行为，不产生领域术语）

## 背景

ADR-0062 落地确定性基准数据集与 bench 工具（50 万笔 seed 42 库、10 项查询基准）时，明确 CI「只记录不判定」：当时尚无一份达标基线，阈值从何谈起没有依据，故承诺「阈值机制等基线分布稳定后另立决策」。彼时的 perf-bench #1 基线（run 33826098405）显示：10 项基准 9 项超过 100ms 慢查询告警线，全账户实时余额与净资产总览各约 88 秒，备注搜索 2.9 秒——先修复、后立阈值的顺序是唯一可行的。

#489 据此拆出 B1–B3 三层修复：V016 结构索引与统计（消灭 6 项慢查询）、V017 余额与净资产持久化缓存（消灭两个 88s 项，ADR-0067）、V018 搜索取行两段式（2932ms → 约 155ms @ CI）。三层已全部合入 main，全部基准项回落到 200ms 判据线以内且分布稳定——观察期结束，兑现承诺的条件成熟。若继续「只记录」，性能回归将在合入后无人拦截，B1–B3 的成果随时可能被无声侵蚀。

## 决策

### 1. 阈值判据：默认判据全部基准 p95 ≤ 200ms，全量扫描型基准分项例外

perf-bench CI（ubuntu-latest runner，现场生成 50 万笔 seed 42 确定性库）上，bench 报告的全部基准项（当前 10 项）逐项判定 p95 ≤ 各自阈值；任何一项超标，perf-bench job 失败。阈值分两层：

- **默认线 200ms**：对全部基准项生效，未列入分项例外者一律适用——新增基准即自动纳入门禁，无需登记；
- **分项例外**：全量扫描型基准（子序列语义无法索引加速，纯 CPU 密集、耗时线性于交易数，ADR-0027）不能与索引加速型基准共用一条线。当前唯一例外：**备注搜索拼音过滤 400ms**。例外清单钉在 bench 工具内（`PER_BENCH_MAX_P95_MS`）并由测试钉住，增删例外须同步修订本 ADR。

### 2. 统计口径：预热 3 次 + 计时 20 次，p95 最近秩法

- 预热 3 次不计入统计（热 SQLite 页缓存与语句缓存）；
- 计时迭代 20 次，p95 取升序样本第 ⌈0.95·n⌉ 位（最近秩法）。n=10 时 rank=⌈9.5⌉=10，p95 恒等于 max、无任何分位数分辨力——迭代数由 10 提到 20（rank=19，第 19 位样本）是判据成立的前提，不是可选项；
- 判据一律以 CI 运行为准；本地 NVMe 计时与 CI 盘差异可达数倍，只作开发参考（#489 实测决策原文照录）。

### 3. 判定下沉工具内，workflow 只传参

门禁判定实现在 `ledger-perf bench --max-p95-ms 200`：工具对全部基准项逐项判定，超标即打印超标清单（报告尾部，随 tee 进 Job Summary）并以非零退出码失败。workflow（`.github/workflows/perf-bench.yml`）只负责以固定参数调用——本地与 CI 跑同一条命令，门禁行为可精确复现，不存在「CI 里另一套 awk 判定」的第二事实来源。

执行面为每日 cron + 手动 dispatch（2026-09-04 修订，原为每周 cron，见修订记录），**不进 PR 流水线**：一次 perf-bench 含 release 冷编译 + 现场生成 + 基准，rust-cache 命中后约 6 分钟/次，逐 PR 跑成本不可接受。每日 cron 由「无变动即跳过」门闸兜底：workflow 内 gate job 在调度触发时比对本次提交与本 workflow 最近一次成功运行的 head_sha，相同（自上次成功以来无新代码）即整体跳过；上次失败则最近成功停在更早提交、差异成立自动重试。性能回归的拦截路径是：性能相关批次合入后手动触发 perf-bench 留基线（#489 验收流程），加上每日 cron 常规运行（无新提交不空转）——超标即红，超标清单直接给出回归项名字。

### 4. 豁免原则：判据只覆盖基准集内的读查询

判据只覆盖 bench 的 10 项读查询（用户高频读路径的性能形似画像）。启动迁移、备份/恢复、搜索拼音列惰性回填等合法慢路径**不在判据内**——它们本来就不在基准集里；未来若考虑入集，须先修订本 ADR 论证「合法慢」与「性能回归」在该项上如何区分。

ADR-0009 的 100ms 单条 SQL 慢查询告警线（连接级 trace_v2 观测机制）**保留不动**。两层互不替代：观测线回答「哪条 SQL 慢」（语句级、warn、含启动迁移等全部执行上下文），门禁线回答「这批用户可感查询是否达标」（基准项级、p95、仅 CI 判定）。门禁生效后启动/回填仍可能成群出现 100ms warn，按 ADR-0009 原样解读，不是门禁问题。

### 5. 阈值出处：交互可感的工程上限 + 分项余量对齐

默认线 200ms 取交互可感阈值的工程上限，与 ADR-0009 的 100ms 观测线保持 2× 关系，覆盖 B1–B3 后索引加速型基准的 CI 实测分布（最慢 140ms，余量约 1.4×）。

分项线 400ms 的出处：门禁首跑（run 33867886806）实测备注搜索 CI p95 = 313ms，超 200ms 线即红——此前 ADR-0027 修订记录中的「实测裁决 154ms 达标」系本地 release 口径，CI 单核性能约为其一半，门禁首跑拦截的正是这一口径差异。400ms = CI 实测 313ms × 约 1.28，与其它项对默认线的余量（1.4×）同量级：既留出 runner 抖动空间，又不至形同虚设。该项的本质是 CPU 密集全量扫描（拼音子序列语义与一切索引不兼容，ADR-0027），耗时线性于交易数，与「索引加速后毫秒级」的其余各项不属同一计算模型，分线判定是判据设计本身的修正，不是放水。分项阈值生效后的首次运行（run 33872176341）：10/10 项达标，备注搜索 p95 = 271ms（run 间抖动 ±13%，余量 1.3–1.5×），其余各项均在 200ms 线内。

## 备选否决

- **阈值定 100ms（与告警线一致）**：否决。CI 盘慢、runner 抖动大，对搜索项必然假红；且 100ms 是 SQL 语句级观测线，与用户可感的基准项级阈值不是一个口径。
- **p50/avg 判据**：否决。均值对尾延迟不敏感，而用户感知的正是「最慢的那一次」；p95（20 次迭代）才是与体感对齐的口径。
- **PR 触发 perf-bench（逐 PR 拦截）**：否决。冷编译 + 生成 + 基准单次数十分钟，乘以 PR 频率成本不可接受；拦截由「性能批合入后手动触发 + 每日 cron（无变动即跳过）」承担（rust-cache 命中后单次约 6 分钟）。
- **workflow 侧脚本解析报告做判定**（awk 阈值比较 bench-report.txt）：否决。判定逻辑与数据源分离后，本地无法用同一条命令复现门禁，CI 与本地行为必然漂移；判定下沉工具内则天然同源。
- **进程内候选缓存消除搜索慢（ADR-0027 修订记录预留手段）**：否决（本次）。第一段候选集物化为进程内数组可降至 ~百毫秒内，但以数十 MB 常驻堆内存为代价；而真实用户设备（本地 release 实测 154ms）本就达标，超标仅是 CI 验收环境的性能画像，为验收环境支付常驻内存代价不成比例。该手段仍保留预留，若未来低端设备实测超分项线再评估（届时亦可考虑本地文件 + mmap 形态，页缓存可回收）。

## 后果

- 性能回归在 perf-bench 运行时被拦截：job 红、Summary 列出超标项名字与实测值及各自阈值，不再「只记录」。门禁首跑即兑现价值：拦截了备注搜索项的本地/CI 口径差异（本地 154ms、CI 313ms），处置为分项判据（ADR-0027 修订记录同步），未启用内存代价较高的候选缓存手段。
- CI runner 抖动可能造成间歇假红：默认线余量最小的报表项约 1.4×、分项线约 1.28×。处置纪律：复核单次运行的完整数据（报告含 min/avg/p95 全列），持续贴线或常态超标则修订本 ADR 显式调整阈值——不悄悄改参数重跑，不以单次绿掩持续红。
- 迭代 10→20 使 bench 计时阶段时长约翻倍（10 项 × 20 次 + 预热，秒级到分钟级），相对 release 冷编译（rust-cache 命中后单次全程约 6 分钟）可忽略。
- bench 缺省仍不判定（`--max-p95-ms` 缺省 None）：本地观察、开发调试不受门禁影响；门禁是 CI 调用参数，不是工具缺省行为。
- 每项基准的 ▲ 报告标记仍按 ADR-0009 的 100ms 阈值点亮（观测视角），与门禁行（默认线 + 分项例外）并存于报告，各表其义：▲ 超观测线不等于门禁失败（如月度汇总、分类占比、搜索项常态带 ▲ 而达标）。

## 修订记录

- **2026-09-04：执行面由每周 cron 提升为每日 cron，新增「无变动即跳过」门闸。** 每周一次使回归发现窗口最长滞后 7 天，门禁红到人工介入的间隔过长；提升为每日后，调度触发时由 gate job 比对本次提交与最近一次成功运行的 head_sha，无新提交即跳过——「每日」只提高回归发现的及时性，不增加无变动时的空转成本（gate 本身秒级）。上次运行失败时最近成功停在更早提交、差异成立，次日自动重试，天然覆盖偶发 runner 抖动的假红复跑。手动 dispatch 语义不变（无条件放行）；阈值判据、统计口径、判定下沉与豁免原则均不受本修订影响。
