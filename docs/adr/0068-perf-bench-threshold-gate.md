# ADR-0068: 性能阈值与门禁——perf-bench 全部基准 p95 ≤ 200ms 判定

- 状态：已接受
- 日期：2026-09-04
- 作者：Ledger 项目
- 关联：ADR-0062（本 ADR 兑现其「观察期后另立决策」承诺）、ADR-0009（100ms 慢查询告警线保留不动）、ADR-0008（列表分页契约不动）、ADR-0027（搜索统一模糊搜索语义与实现形态，分项例外的对象；其 SQL 下推修订是例外的撤销前提）、ADR-0067（余额/净资产缓存，消灭两个 88s 项）、ADR-0114（跨账本投资汇总，#1630 基准项的被测路径）；#489（性能达标 spec）、#490/#491/#492（B1–B3 三层修复）、#493（本 ADR 与门禁落地票）、#514（拼音子序列基准项与例外扩充）、#515/#516（搜索 SQL 下推与随后的例外撤销收口）、#1627（商户占比与投资三项读基准入集）、#1628（同步重放写基准与网络边界豁免成文）、#1630（跨账本投资汇总基准项与多账本夹具入集）、#1629（行情/价格历史批量 upsert 写基准，计数同步）、#1640（CI 首跑分布复核与三项超标处置）、#1654（投资组合趋势取数路径优化票）、#1655（商户占比覆盖索引优化票）；词汇表无新增词条（开发侧基础设施与 CI 行为，不产生领域术语）

## 背景

ADR-0062 落地确定性基准数据集与 bench 工具（50 万笔 seed 42 库、10 项查询基准）时，明确 CI「只记录不判定」：当时尚无一份达标基线，阈值从何谈起没有依据，故承诺「阈值机制等基线分布稳定后另立决策」。彼时的 perf-bench #1 基线（run 33826098405）显示：10 项基准 9 项超过 100ms 慢查询告警线，全账户实时余额与净资产总览各约 88 秒，备注搜索 2.9 秒——先修复、后立阈值的顺序是唯一可行的。

#489 据此拆出 B1–B3 三层修复：V016 结构索引与统计（消灭 6 项慢查询）、V017 余额与净资产持久化缓存（消灭两个 88s 项，ADR-0067）、V018 搜索取行两段式（2932ms → 约 155ms @ CI）。三层已全部合入 main，全部基准项回落到 200ms 判据线以内且分布稳定——观察期结束，兑现承诺的条件成熟。若继续「只记录」，性能回归将在合入后无人拦截，B1–B3 的成果随时可能被无声侵蚀。

## 决策

### 1. 阈值判据：默认判据全部基准 p95 ≤ 200ms，个别基准分项例外（当前为空）

perf-bench CI（ubuntu-latest runner，现场生成 50 万笔 seed 42 确定性库）上，bench 报告的全部基准项（当前 16 项）逐项判定 p95 ≤ 各自阈值；任何一项超标，perf-bench job 失败。阈值分两层：

- **默认线 200ms**：对全部基准项生效，未列入分项例外者一律适用——新增基准即自动纳入门禁，无需登记；
- **分项例外**：机制保留、清单当前为空（2026-09-04 修订，原两项搜索 400ms 例外随 SQL 下推落地撤销，见修订记录）——个别基准确需不同阈值时在此登记项名与阈值，例外清单钉在 bench 工具内（`PER_BENCH_MAX_P95_MS`）并由测试钉住，增删例外须同步修订本 ADR。

### 2. 统计口径：预热 3 次 + 计时 20 次，p95 最近秩法

- 预热 3 次不计入统计（热 SQLite 页缓存与语句缓存）；
- 计时迭代 20 次，p95 取升序样本第 ⌈0.95·n⌉ 位（最近秩法）。n=10 时 rank=⌈9.5⌉=10，p95 恒等于 max、无任何分位数分辨力——迭代数由 10 提到 20（rank=19，第 19 位样本）是判据成立的前提，不是可选项；
- 判据一律以 CI 运行为准；本地 NVMe 计时与 CI 盘差异可达数倍，只作开发参考（#489 实测决策原文照录）。

### 3. 判定下沉工具内，workflow 只传参

门禁判定实现在 `ledger-perf bench --max-p95-ms 200`：工具对全部基准项逐项判定，超标即打印超标清单（报告尾部，随 tee 进 Job Summary）并以非零退出码失败。workflow（`.github/workflows/perf-bench.yml`）只负责以固定参数调用——本地与 CI 跑同一条命令，门禁行为可精确复现，不存在「CI 里另一套 awk 判定」的第二事实来源。

执行面为每日 cron + 手动 dispatch（2026-09-04 修订，原为每周 cron，见修订记录），**不进 PR 流水线**：一次 perf-bench 含 release 冷编译 + 现场生成 + 四段基准（读门禁 + 三写观测），rust-cache 命中后约 35 分钟/次（2026-09-21 bench-sync + bench-market 接入后的量级，此前单段基准约 6 分钟；写基准观测段约占 30 分钟，bench-sync 逐条事务形态约占 20 分钟、bench-market 批量 upsert 形态约占数分钟），逐 PR 跑成本不可接受。每日 cron 由「无变动即跳过」门闸兜底：workflow 内 gate job 在调度触发时比对本次提交与本 workflow 最近一次成功运行的 head_sha，相同（自上次成功以来无新代码）即整体跳过；上次失败则最近成功停在更早提交、差异成立自动重试。性能回归的拦截路径是：性能相关批次合入后手动触发 perf-bench 留基线（#489 验收流程），加上每日 cron 常规运行（无新提交不空转）——超标即红，超标清单直接给出回归项名字。

### 4. 豁免原则：判据覆盖基准集内的读查询与写基准形态；外部网络往返不进判据

判据覆盖 perf-bench 的读基准项（bench 全部基准项，16 项，用户高频读路径的性能形似画像）：默认线逐项判定。写基准形态同属基准集（2026-09-21 修订扩围，见修订记录）：bench-import（批量导入）、bench-sync（同步重放）与 bench-market（行情/价格历史批量 upsert，issue #1629 接入）走权威写入口、随每日 cron 以固定参数观测并记录进 Summary——但写基准的阈值判定未立（写单元成本高、本地/CI 磁盘与 runner 口径差异未测），现行只观测不判定，立阈值时须修订本 ADR 另立判据，不悄悄纳入门禁。启动迁移、备份/恢复、搜索拼音列惰性回填等合法慢路径**不在判据内**——它们本来就不在基准集里；未来若考虑入集，须先修订本 ADR 论证「合法慢」与「性能回归」在该项上如何区分。

**网络边界豁免**（2026-09-21 修订成文）：外部服务往返——S3 通道传输、行情源抓取、AI 请求——不进判据。往返延迟由外部服务与网络状况决定，不反映本地账本路径的回归；基准涉及外部服务时剥离网络、只量测本地部分（bench-sync 同步重放基准即按此裁决剥离 S3 传输，op 流确定性生成、只量 apply_ops/ingest_ops 的本地合并与写库；bench-market 行情批量 upsert 基准同理剥离腾讯/新浪等行情源抓取，点流确定性生成、只量价格写入单点的本地批量落库）。

ADR-0009 的 100ms 单条 SQL 慢查询告警线（连接级 trace_v2 观测机制）**保留不动**。两层互不替代：观测线回答「哪条 SQL 慢」（语句级、warn、含启动迁移等全部执行上下文），门禁线回答「这批用户可感查询是否达标」（基准项级、p95、仅 CI 判定）。门禁生效后启动/回填仍可能成群出现 100ms warn，按 ADR-0009 原样解读，不是门禁问题。

### 5. 阈值出处：交互可感的工程上限 + 分项余量对齐

默认线 200ms 取交互可感阈值的工程上限，与 ADR-0009 的 100ms 观测线保持 2× 关系，覆盖 B1–B3 后索引加速型基准的 CI 实测分布（最慢 140ms，余量约 1.4×）。

分项线 400ms 的出处：门禁首跑（run 33867886806）实测备注搜索 CI p95 = 313ms，超 200ms 线即红——此前 ADR-0027 修订记录中的「实测裁决 154ms 达标」系本地 release 口径，CI 单核性能约为其一半，门禁首跑拦截的正是这一口径差异。400ms = CI 实测 313ms × 约 1.28，与其它项对默认线的余量（1.4×）同量级：既留出 runner 抖动空间，又不至形同虚设。该项的本质是 CPU 密集全量扫描（拼音子序列语义与一切索引不兼容，ADR-0027），耗时线性于交易数，与「索引加速后毫秒级」的其余各项不属同一计算模型，分线判定是判据设计本身的修正，不是放水。分项阈值生效后的首次运行（run 33872176341）：10/10 项达标，备注搜索 p95 = 271ms（run 间抖动 ±13%，余量 1.3–1.5×），其余各项均在 200ms 线内。

## 备选否决

- **阈值定 100ms（与告警线一致）**：否决。CI 盘慢、runner 抖动大，对搜索项必然假红；且 100ms 是 SQL 语句级观测线，与用户可感的基准项级阈值不是一个口径。
- **p50/avg 判据**：否决。均值对尾延迟不敏感，而用户感知的正是「最慢的那一次」；p95（20 次迭代）才是与体感对齐的口径。
- **PR 触发 perf-bench（逐 PR 拦截）**：否决。冷编译 + 生成 + 基准单次数十分钟，乘以 PR 频率成本不可接受；拦截由「性能批合入后手动触发 + 每日 cron（无变动即跳过）」承担（单次时长见决策 3：现约 35 分钟/次）。
- **workflow 侧脚本解析报告做判定**（awk 阈值比较 bench-report.txt）：否决。判定逻辑与数据源分离后，本地无法用同一条命令复现门禁，CI 与本地行为必然漂移；判定下沉工具内则天然同源。
- **进程内候选缓存消除搜索慢（ADR-0027 修订记录预留手段）**：否决（本次）。第一段候选集物化为进程内数组可降至 ~百毫秒内，但以数十 MB 常驻堆内存为代价；而真实用户设备（本地 release 实测 154ms）本就达标，超标仅是 CI 验收环境的性能画像，为验收环境支付常驻内存代价不成比例。该手段仍保留预留，若未来低端设备实测超分项线再评估（届时亦可考虑本地文件 + mmap 形态，页缓存可回收）。

## 后果

- 性能回归在 perf-bench 运行时被拦截：job 红、Summary 列出超标项名字与实测值及各自阈值，不再「只记录」。门禁首跑即兑现价值：拦截了备注搜索项的本地/CI 口径差异（本地 154ms、CI 313ms），处置为分项判据（ADR-0027 修订记录同步），未启用内存代价较高的候选缓存手段。
- CI runner 抖动可能造成间歇假红：默认线余量最小的项约 2.0×（分类占比，2026-09-04 例外撤销后的分布；撤销前为报表项约 1.4×、分项线约 1.28×）。处置纪律：复核单次运行的完整数据（报告含 min/avg/p95 全列），持续贴线或常态超标则修订本 ADR 显式调整阈值——不悄悄改参数重跑，不以单次绿掩持续红。
- 迭代 10→20 使 bench 计时阶段时长约翻倍（10 项 × 20 次 + 预热，秒级到分钟级），相对单次全程（现约 35 分钟，见决策 3）可忽略。
- bench 缺省仍不判定（`--max-p95-ms` 缺省 None）：本地观察、开发调试不受门禁影响；门禁是 CI 调用参数，不是工具缺省行为。
- 每项基准的 ▲ 报告标记仍按 ADR-0009 的 100ms 阈值点亮（观测视角），与门禁行（默认线，分项例外如有则注明）并存于报告，各表其义：▲ 超观测线不等于门禁失败（如月度汇总、分类占比、搜索项常态带 ▲ 而达标）。

## 修订记录

- **2026-09-21（issue #1640）：CI 首跑三项超标处置——分类占比 V029 计划翻转随票钉定修复，商户占比与投资组合趋势另立优化票、不登记分项例外。** #1627 合入后首次每日 cron（run 35568004083，main @ 624154bb，50 万笔 seed 42，预热 3 × 迭代 20）完整分布：15 项中 12 项达标，三项超标——分类占比 p95 1421.71ms、商户占比 p95 777.28ms、投资组合趋势 p95 8850.12ms。逐项处置：

  - **分类占比（1421.71ms）：计划翻转缺陷，非计算模型异类，随票修复不立例外。** 前一日 run 35493762162（V029 合入前）同项 p95 128.45ms、其余 12 项两次 run 全部持平——根因锁定为 V029（#1623）给 transactions 加两列（未被该查询引用）令应用内嵌 SQLite 3.51.3 计划器把分类聚合从 V016 分类覆盖索引（分组序自带、无临时 B-tree）翻转退回表达式索引 ANY 扫 + GROUP BY 临时 B-tree；本地同库对照（数据逐位一致仅差两列）复现 159ms → 1400ms，系统 SQLite 3.42 两库同计划同耗时，证实系 3.51.3 计划器成本模型对表列数敏感。修复为 `category_shares_rows` INDEXED BY 钉定分类覆盖索引（月度汇总 issue #490 同款先例），本地复测 1400ms → 174ms；同款计划翻转风险扫查：月度汇总/搜索/商户筛选列表/日期极值/分类下钻均已钉定，其余基准项两次 run 持平。V029 幸未发布（v0.7.0 不含），发布前已钉死。
  - **商户占比（777.28ms）：常态超标且近期有优化计划 → 另立 #1655，不登记例外。** 根因：所需列组合（merchant_id/kind/date/amount_native_cents）无单一覆盖索引，两种可达计划（merchant 索引 SCAN / date 范围扫 + GROUP BY B-tree）本地均在 800–1420ms 量级，钉定既有索引无效；方向为 V030 商户维度覆盖索引（分类覆盖索引镜像）+ INDEXED BY 钉定，落地后回落默认线。
  - **投资组合趋势（8850.12ms，超默认线约 44 倍）：应修的用户可感慢路径 → 另立 #1654，不登记例外。** 与 #1627 本地参考观测（p95 ≈ 10.6s）同量级，确证常态超标而非 runner 口径假红；前端「全部」预设即全窗口形态，10 秒级等待不可接受。根因是周采样价格线 × 逐行委托时点持仓接缝的结构性嵌套循环，方向为数量推算按标的分组增量推进、消除逐价格行全量重算，优化落地后该项自然回落默认线。

  `PER_BENCH_MAX_P95_MS` 清单保持为空；三项超标期间每日 cron 将持续红，以报告尾部门禁行给出的项名为准，两票落地后自然转绿。

- **2026-09-21（issue #1629）：写基准形态计数同步——两处 → 三处（接入 bench-market 行情/价格历史批量 upsert 写基准）。** 行情换源大批复接线（#1542–#1568）与价格历史后台补全（#1375）引入大体量本地批量 upsert，此前无基准守护；新增 ledger-perf 子命令 bench-market（照 bench-import / bench-sync 先例：快照恢复隔离写副作用、确定性点流、价格写入单点计时，事务边界照生产形态「一只标的一个事务」），复用 #1628 网络边界豁免成文（行情源抓取不属回归面，剥离后只量本地落库）。政策无变更：判据范围、统计口径、豁免原则均沿用现行文字，本条仅同步决策 3（三段 → 四段基准）与决策 4（写基准形态列举）中的计数；写基准阈值仍未立，CI 以最大档 5200 点 × 两分布观测、只记录不判定。

- **2026-09-21（issue #1630）：基准集增补跨账本投资汇总基准项，15 → 16 项。** 跨账本投资汇总（ADR-0114，issue #1196）是多库只读聚合，此前无基准守护且数据集形状缺口——generate 只产单库。按 grilling Q8 裁决，夹具与消费它的基准同票落地：generate 扩「1 主库 + 2 附属账本」生成（附属账本固定 2,000 笔/本小规模、经同一生成路径产出含标的交易与批次持仓的全套画像，种子派生确定性不变——每本由基础种子派生自己的种子，主库确定性不受影响；目录形态与 ADR-0089「一库 = 一本账」一致，主库文件同级 `ledger-perf-books/book-NN/`，每次生成先清后建）；bench 增「跨账本投资汇总」读基准项，经壳层编排既有 pub 函数（`collect_other_books` / `read_book_investment` / `merge_readings`）调用——与 IPC 命令同一编排与 SQL 路径，附属账本逐本只读建连（生产形态：每次汇总重建非活动本连接），前置探测保证夹具齐备且 schema 与主库一致（删除生成侧 → 基准运行红）。按「新增基准即自动纳入门禁」默认线 200ms 直接生效，无分项例外登记；`PER_BENCH_MAX_P95_MS` 清单不变（仍为空）。名单钉住断言同步（15 → 16 项，跨账本项接在财务自由度后）。

- **2026-09-21（issue #1628）：判据范围扩围到写基准形态（成文收编 bench-import 先例）+ 网络边界豁免成文。** 多端同步是主航线，`apply_ops` 循环逐条合并外来 op 流在 50 万笔库上的写放大此前无基准守护；新增 bench-sync 同步重放写基准（ledger-perf 子命令，照 bench-import 先例：快照恢复隔离写副作用、确定性 op 流、权威入口计时），并把豁免原则从「判据只覆盖基准集内的读查询」扩围到写基准形态——bench-import 批量导入写基准（issue #532）彼时已在 perf-bench 每日观测但在判据文字之外，本次成文收编：写基准属基准集组成部分，现行只观测不判定（阈值未立，立阈值须再修订本 ADR）。同时把网络边界豁免成文（2026-09 grilling 会话 Q5 决策）：S3 通道传输、行情源抓取、AI 请求等外部服务往返不进判据，基准剥离网络、只量本地合并/写库部分——bench-sync 据此不把 S3 传输计入计时窗口。`CONTEXT-testing.md`「性能基准」词条的「随票登记」注记同步收编；决策 3/后果/否决项中的单次时长数字同步为三段基准后的量级（约 6 分钟 → 约 35 分钟）。

- **2026-09-21（issue #1627）：基准集增补四项读基准——商户占比、投资组合趋势、资金加权收益率、财务自由度，11 → 15 项。** 基准缺口调研（grilling 会话）发现近三个月新增的耗时读路径未入集：报表三件套独缺商户占比（月度汇总、分类占比已有基准项），投资侧组合市值走势（周采样 × 时点持仓嵌套循环）、资金加权收益率（每对 200 次迭代 XIRR 数值解）、财务自由度（多次持仓全量求和）三条读路径无基准。数据集不扩展（generate 已产出标的交易、instruments、价格线与汇率历史）；四项均经既有 pub 查询函数调用（唯一接缝不变），前置参数照惯例预热外一次性定型（商户占比全窗口期间口径 top_n 全量、走势全窗口周线、收益率区间不设界即 IPC 缺省形态、财务自由无参）。按「新增基准即自动纳入门禁」默认线 200ms 直接生效，无分项例外登记；`PER_BENCH_MAX_P95_MS` 清单不变（仍为空）。名单钉住断言同步（11 → 15 项，顺序稳定：商户占比接在分类占比后、投资三项接在时点持仓后）。本地参考观测（issue #1627 实施时，共享负载开发机、非判据口径）：投资组合趋势全窗口形态 p95 ≈ 10.6s——5240 条价格线 × 逐行时点持仓接缝的结构性嵌套循环（逐行调用 ≈ 2ms），预计常态超标默认线；按本 ADR 处置纪律，待 perf-bench CI 首跑定完整分布（min/avg/p95）后再行分项例外修订或另行立项优化取数路径，不在本地参考值上预设阈值。

- **2026-09-04（issue #516 / 父 #512）：搜索分项例外撤销，默认线 200ms 收回对全部基准生效。** 交易搜索 SQL 下推落地（ADR-0027 修订，issue #515 / PR #548）后手动触发 perf-bench 实测（run 33890569837，main @ d62db0b、ubuntu-latest、50 万笔 seed 42、预热 3 + 迭代 20）：11/11 项全部达标，**备注搜索拼音过滤 p95 = 69.52ms**（中文子串「咖啡」，命中 18568 条）、**备注搜索拼音子序列 p95 = 82.21ms**（拼音子序列「kf」，命中 18571 条），对默认线余量 2.9×/2.4×，且优于当时最慢默认线项分类占比（p95 99.12ms，余量 2.0×）——分项线的前提（子序列语义只能 Rust 逐行全扫、计算模型异于索引加速项，ADR-0027）已随下推消失，400ms 线对实测余量 5.8×/4.9×形同虚设。处置：撤销两项分项例外，`PER_BENCH_MAX_P95_MS` 清空（机制保留、钉住断言同步为空表），默认线 200ms 对全部基准生效；bench 门禁行、workflow 注释与 step 名、main.rs 帮助文本同步。若未来搜索回归贴线或超标，按本 ADR 处置纪律复核完整数据后修订本 ADR 再行调整，不悄悄改参数。

- **2026-09-04（issue #514 / 父 #512）：例外清单扩充至两项——新增拼音子序列基准「备注搜索拼音子序列」（默认关键字 kf），与中文子串基准「备注搜索拼音过滤」（默认关键字 咖啡）并列。** 原基准项虽名带「拼音」，关键字「咖啡」实际只走原文连续子串匹配，统一模糊搜索语义的拼音首字母子序列路径（kf 命中「买咖啡」mkf 等、不构成原文子串）此前无基准覆盖。新基准项与原项同属全量扫描型（子序列语义无法索引加速、耗时线性于交易数，ADR-0027），同一计算模型故沿用同一分项线 400ms；门禁逐项判定自然覆盖两条路径，无需其它判据变更。配套地，generate 补填 note_pinyin 派生列（此前裸 INSERT 未填、靠 bench 预热时搜索入口惰性回填才与真实库对齐），基准库与真实库搜索路径画像一致——判定口径不受本次扩充影响，基准数字口径更干净（见 ADR-0062 修订记录）。
- **2026-09-04：执行面由每周 cron 提升为每日 cron，新增「无变动即跳过」门闸。** 每周一次使回归发现窗口最长滞后 7 天，门禁红到人工介入的间隔过长；提升为每日后，调度触发时由 gate job 比对本次提交与最近一次成功运行的 head_sha，无新提交即跳过——「每日」只提高回归发现的及时性，不增加无变动时的空转成本（gate 本身秒级）。上次运行失败时最近成功停在更早提交、差异成立，次日自动重试，天然覆盖偶发 runner 抖动的假红复跑。手动 dispatch 语义不变（无条件放行）；阈值判据、统计口径、判定下沉与豁免原则均不受本修订影响。
