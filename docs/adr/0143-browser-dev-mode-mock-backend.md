# ADR 0143: 浏览器开发模式——替身后端内存读写闭环，渐进补齐、不追行为等价

- 状态：已接受（决策入档；实现随实施票落地）
- 日期：2026-10-21
- 作者：Ledger 项目
- 关联：ADR-0085（前端 invoke 测试接缝唯一化——「未命中报错」同语义的测试侧先例，本决策不迁移其消费面）、ADR-0012（`ledger:changed` 失效信号——替身写路径必发的契约）、ADR-0044（失效信号发射收单点）、ADR-0118（前端 pnpm workspace 拆包——按消费面成包）、ADR-0046（pnpm 严格隔离）；词汇表：测试基础设施域「替身后端」「浏览器开发模式」（随本 ADR 入档）
- 来源：grill-with-docs 三轮裁决（2026-10-21）

## 背景

前端 UI 开发迭代的回路目前必须过完整 Tauri 壳：起 Rust 后端、等编译、开应用窗口。`pnpm dev` 起的 vite dev server 虽然独立可跑，但在普通浏览器里打开即瘫——IPC 的 invoke 收口在 `@ledger/api`（全仓唯一 import tauri core 的生产代码），应用启动即调 `getBootStatus`，浏览器下不可达，落 bootFailed 受控失败页；另有 12 个生产文件直用 tauri 事件/插件 API（事件 listen、plugin-dialog、plugin-opener、系统返回的窗口句柄），其中系统返回 composable 是模块级依赖，浏览器下加载即抛错。

自动化测试侧已有完整替身基建（invoke 测试接缝，ADR-0085），但它是 vitest 运行时内的 `vi.mock` 机制，只服务测试进程，不构成「应用能跑起来」的开发模式。仓库里没有任何浏览器 mock 分支、代理配置或相关 ADR。

诉求：前端 UI 迭代不依赖 Rust 侧——起 dev server 就能在浏览器里浏览、操作、写入。

## 决策

### 1. 定位：开发模式，不追行为等价，测试三层不动

浏览器开发模式服务前端 UI 开发迭代的「操作→界面反馈」闭环；替身后端刻意**不追求与 Rust 后端行为等价**——金额折算细节、余额缓存维护、复杂读口径都不模拟。自动化测试不迁来此模式：测试仍走 vitest + invoke 测试接缝，测试三层权威（ADR-0087）不变。两者是同族不同消费面的替身：接缝服务 vitest 进程，替身后端服务 vite 应用构建。

### 2. 形态：内存状态替身 + 渐进补齐

替身后端落新包 `packages/mock-backend`（与 `@ledger/test-support` 分家：后者绑定 vitest，消费面是测试运行时；本包消费面是 vite 应用构建，按消费面成包，ADR-0118 取向）。夹具作种子，主路径读写闭环——写入真的改内存、读真的投影内存，「记一笔账→列表出现」成立。未实现替身的命令运行时报错（含命令名，与接缝「未命中报错」同语义；console + toast 双出口），开发中用到哪个补哪个；**不做类型层全覆盖强制**——全覆盖要求一次实现全部命令面或维护豁免清单，把渐进补齐变成先付全款。

### 3. 失效信号必发：写路径统一发 `ledger:changed`

事件驱动失效是参考数据等 store 的唯一重拉触发源（无 pull 侧兜底），替身写路径完成后必须统一发射 `ledger:changed`（无 payload），否则写后刷新即断——这是产品契约的组成部分，不是可选保真度。`ledger:prices-changed` / `ledger:backups-changed` 与各进度事件不模拟：对应域的写入在替身里未实现，未命中报错兜住缺口。

### 4. 挂载：vite mode 构建期隔离，替身不进生产包

新增 `pnpm dev:mock`（vite `--mode mock`）作为唯一入口；`main.ts` 按 mode 静态分支安装替身后端。生产构建走静态消除，替身代码进不了 release 包——隔离由编译器保证，不靠纪律。否决运行时开关（替身进生产包、开关面暴露给用户）与独立 HTML 入口（双份启动装配要长期同步）。

### 5. 生产代码零改动：tauri API 面整体模块替身

mock mode 下把 tauri API 面（core / event / window / app / plugin-dialog / plugin-opener）以构建期模块替身整体替换，全部散用直连点（事件 listen、文件对话框、外链打开、系统返回）一字不动。这些直连点是既有结构现状：收口与否属独立重构议题，单独立 issue 记录，不搭车本特性。对话框替身返回假路径，外链打开替身空操作。

### 6. 夹具与状态：确定性小夹具，刷新即重置

手写确定性小夹具（参考数据五字典 + 覆盖主要 kind 形态的少量交易）提交进仓库、随代码维护；替身状态不持久，刷新即重置回种子——开发迭代要的是可复现起点，不是拟真；要看更多数据就在夹具加行。启动门由替身答「已解锁」直接进主界面。

## 理由

- **内存状态替身是 UI 迭代的最低可用形态**：纯静态替身让所有写操作「成功但无反馈」，主流程（表单提交→列表变化）验证不了，模式即失去存在理由；而行为等价是无底洞，明确不追才能把实现成本钉在「用到哪个补哪个」。
- **失效信号必发是事实约束推出来的**：push-first 生命周期（ADR-0012、ADR-0123）把重拉触发收口在事件上，替身不发信号，写入闭环在界面上就不成立。
- **构建期隔离是零成本的安全边界**：vite mode 分支被静态消除，不需要任何「发布前检查替身没带进去」的流程。
- **不搭车收口**：模块替身与直连点收口正交；收口是健康的方向但要动 12 个生产文件并各配测试，绑进本特性会把一个小开发模式变成一次横切重构。

## 代价

- 替身后端是第二套命令实现，必然与 Rust 侧漂移：缺口靠未命中报错暴露（当场补），语义漂移（替身答的对不上真后端）无自动防护，靠「本模式不承载契约验证」的定位兜底——发现替身误导 UI 开发时，以真后端行为为准修替身。
- 夹具与真实数据形态可能漂移：命令契约演化后夹具字段过时，由消费该命令时的报错/类型错暴露。
- tauri API 面升级（新增插件、改事件签名）时模块替身要跟着补面。
- 复杂口径页面（折算、余额缓存自愈等）在替身下的数字与真后端不一致，是接受的差异，不作排错依据。

## 替代方案

- **纯静态替身**（答固定夹具、写不落状态）：主流程验证不了，否决。
- **类型层全覆盖 handler 表**：漂移在编译期暴露但要求先付全款，与渐进补齐冲突，否决。
- **运行时开关进同一构建**：替身代码进生产包、开关面暴露给用户，否决。
- **顺势收口直连点**：搭车横切重构，范围失控，否决（收口评估另立 issue）。
- **前端对接非 Tauri 真后端**（域层 HTTP 化）：范围大一个量级且改变部署形态，非本诉求，否决。
- **扩展 `@ledger/test-support`**：把 vitest 依赖拖进应用构建图，违背按消费面成包，否决。
- **替身状态 localStorage 持久**：引入脏状态排错负担与一套序列化维护，否决。

## 影响

- 新包 `packages/mock-backend`；`package.json` 新增 `dev:mock` 脚本；vite 配置增加 mock mode 的模块替身分支。生产代码、IPC/HTTP 契约、schema 零改动。
- 词汇表同步：测试基础设施域新增「替身后端」「浏览器开发模式」词条；地图条目主题追加。
- 实施拆票建议：单票可落——包骨架 + `dev:mock` + 模块替身 + 夹具 + 启动门替身 + 首批主路径命令（启动/参考数据/交易读写闭环）；此后补命令随开发即时进行，不立票。
- 范围外记录：12 个生产文件的 tauri API 直连点收口评估，另立技术债 issue。
