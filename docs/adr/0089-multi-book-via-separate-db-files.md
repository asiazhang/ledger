# ADR 0089: 多账本立项——多库文件经引导层实现，schema 永不加账本维度

- 状态：已接受
- 日期：2026-09-08（同日修订：由「不立项、只立立场」改为立项实现）
- 作者：Ledger 项目

## 背景

「要不要支持多账本」最初按「不立项、只立立场」收场：当时驱动是推测性的（维护者本人无多账本需求，外部用户需求未经验证），故只钉了「一库 = 一本账、若立项经多库文件」的架构立场。同日维护者改判：直接立项实现。本 ADR 随之修订——原「当前不建功能」决策作废；多文件载体的论证、schema 禁令、术语预留全部延续并升格为实现决策。修订本身符合本 ADR 原定的触发路径（立项前先修订本 ADR）。

代码事实盘点（决定实现载体怎么选）：

| 事实 | 含义 |
|---|---|
| schema（V001–V019）无任何账本维度，一库隐含即一本账 | 多文件路线对 schema 与域引擎零改动 |
| 设备偏好（外观/界面语言/隐私模式/备份目录/自动解锁开关）在 localStorage，不随库走 | 多本之间设备偏好不碎片化 |
| 加密随文件走（文件头即真相），主口令/解锁是每文件语义 | 每本可独立加密，机制天然成立 |
| Backup/Restore 是文件级整库快照；同步字段（device_id/LWW）以库为单元 | 备份与同步天然按本隔离 |
| 已有原位重引导（数据位置解析 → 库文件处置 → 换连）原语，且进程启动与重引导共用同一段引导序列 | 切换账本 = 换活动账本 + 重跑既有引导序列，引导内核零分叉 |

结论：多账本最便宜的实现路径是**多个 SQLite 文件**——每本是完整独立的数据宇宙，成本集中在引导配置（引导指针文件泛化为账本注册表）与外壳 UX，schema 与域层零感知。

## 决策

### 1. 实现载体：多库文件，一库 = 一本账

schema 永不引入 book / book_id、不建账本表；域引擎、域单测与既有写入接缝对「当前是哪本」零感知。净资产、预算、财务自由度等全局口径都是「当前账本」口径。本约束面向未来所有 migration 与域演进。

### 2. 账本注册表在引导层（显式修订 ADR-0018 后果条款）

账本登记（有哪些本、哪本是活动本）是「打开库之前必须可读」的引导配置，落点就是库外引导指针文件：原单字段指针（仅记库目录）泛化为**账本注册表**（账本清单 + 活动指针 + 各本目录与展示名）。这是对 ADR-0018「除 data_dir 外不得再向指针文件添加任何内容」后果条款的显式修订——账本注册表论证通过：它不是「也想放在建连前读」的新诱惑，而是引导层本体的自然泛化。

- **账本 = 一个库目录**（内含固定名 `ledger.db`，文件名仍不可配置），身份即目录；注册表另存展示名，同一目录不得登记为两个账本。
- 存量单字段指针**确定性升级**为单账本注册表（现有目录即唯一账本兼活动账本），无数据移动、无感迁移。
- 指针/注册表损坏或条目不可用 → 按既有回退原则回退默认账本并显著提示；绝不删除或修改任何既有文件。从注册表移除账本只摘登记、不删文件（与回退原则同源）。

### 3. 切换 = 改活动指针 + 原位重引导

切换账本复用 ADR-0080 原位重引导：写入活动账本意图 → 重跑唯一引导序列 → 前端重载 WebView 落主界面/解锁屏/失败恢复屏。引导序列本体零分叉。切到密文库走既有解锁屏；自动解锁缓存按账本区分（钥匙串条目携带账本标识）。

### 4. 不跨本聚合

每本互不可见；净资产、预算、财务自由度、报表只有「本内」口径，不做「全部账本合计」视图——聚合是此功能复杂度的最大来源，且个人场景下「合计」等于把账记回一个本里。

### 5. 外壳适配按文件语义自然延伸

- 加密：随文件走，机制零改动；每本独立口令。
- 备份：产物命名携带账本标识；受管备份在共享 BackupDirectory 内按账本分别滚动清理（BackupRetentionLimit 仍为设备本地偏好）；自动备份/脏标记本就按当前连接运转，零改动。
- 搬迁（Relocation）语义收窄为「当前活动账本搬目录」，校验复用既有三步校验。
- 失败恢复、启动失败门、AI 导入 HTTP 面、定时计划调度：全部只作用于当前活动账本，语义零改动。

### 6. 术语

领域术语定为**账本（Book）**，英文禁用 Ledger（与产品名冲突，ADR-0076）；不使用「工作区/空间」。DataLocation 词汇表词条随实现改写：「单一活动路径」边界由账本注册表接管，DataLocation 本身收窄为「默认数据目录与引导文件所在处」。

### 备选与否决

- **逐表 book_id 列（库内多本）**：侵入 schema 与全部写入接缝，LWW 同步、加密、备份、余额缓存（V017）都要感知「本」维度，跨本聚合口径还要重设计——为唯一一个零改动方案可覆盖的需求付出最大成本，否决。
- **交易分组标签冒充账本**：与侧栏分组、交易筛选职责重复；「分组可筛」不等于「独立宇宙」，用前者回应后者的需求是伪方案，否决。
- **多库同目录异名文件**：打破「目录 + 固定文件名」的既有事实（搬迁、备份、加密探测都建立在它上面），为省一层目录付出的兼容成本不成比例，否决。

## 后果

- 新增一个 IPC 命令面：账本注册表管理（列出/新建/切换/改名/移除），归 API 集成测试守门；域命令面零新增，不新增 HTTP-only 端点。
- ADR-0018 后果条款由本 ADR 显式修订（指针文件 → 账本注册表）；DataLocation 词汇表词条随实现同步改写。
- 存量升级无感：旧单字段指针确定性迁移为单账本注册表。
- 备份命名、自动解锁缓存、搬迁三处加「账本」维度；其余既有文件级机制全部按「当前活动账本」运转，机制零改动。
- 前端新增账本管理/切换入口与切换确认弹窗（ADR-0078 分级）；文案经 i18n。入口落**侧栏左下角常驻按钮**（当前账本名，折叠态保留图标形态）。

> **2026-09-08 修订（issue #837 文档收口）**：上列末条入口落点原写「设置页『数据』Tab，数据文件管理域内」，与 spec #831 定稿及实现（issue #834）不符，显式修正为侧栏左下角常驻入口。
