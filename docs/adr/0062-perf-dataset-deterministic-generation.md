# ADR-0062: 性能基准数据集——确定性生成而非入库

- 状态：已接受（观察期已结束，CI 门禁判据由 ADR-0068 另立；正文已按 #532 / #1628–#1630 / #1885 / #1915 现行态收敛）
- 日期：2026-09-03（现行态收敛：2026-10-09）
- 作者：Ledger 项目
- 关联：spec #458（`ledger-perf` 工具）；ADR-0056（bin 属包内自动发现目标）；ADR-0068（性能阈值与门禁——兑现本 ADR 观察期承诺）；ADR-0089 / ADR-0114（多账本夹具）；ADR-0138（购买项语料）；#459–#462 / #532 / #1628–#1630 / #1885 / #1915

## 背景

常规测试运行在内存小库上，无法回答数十万笔真实账本下的查询与写入性能问题。若将 50 万笔大库提交进仓库，会导致仓库永久膨胀（百 MB 级）、二进制 diff 不可审查且随 schema 演进静默漂移；git-lfs 同样无法解决漂移与审查问题；另写带 DDL 拷贝的脚本则会制造第二份 schema 事实源。

## 决策

### 1. 数据集现场确定性生成，永不入库

- 由 `ledger-perf generate` 按需现场生成：默认 500,000 笔（`--transactions`）、默认种子 42（`--seed`）、锚定结束日期 `2025-12-31`（不锚定「今天」，避免随墙钟漂移）。
- 手写可种子化 PRNG 与参数解析，**零新增依赖**；同参数必产出全表有序摘要一致的确定性数据集，新增表必须登记进确定性摘要清单（#1915 补齐 `transaction_purchases`）。
- 扩展夹具采用**独立派生种子流**，确保追加新表或附属账本不扰动主库既有随机流与历史基准基线：
  - **多账本夹具（#1630）**：在主库同级 `ledger-perf-books/` 下派生生成 2 本附属账本（2,000 笔/本），支撑跨账本投资汇总基准；
  - **购买项名称池（#1915）**：采用 400 个 SKU 级名称（品牌 × 品类 × 规格 + 复购块，且与备注素材池关键词不交），避免小词池（初版 16 词致默认词命中 39% 订单）制造失真长尾，使单字命中贴近真实账本的数百单量级。

### 2. 经应用自身迁移入口建库，不复制 DDL

生成器打开文件库后直接调用产品启动相同的迁移路径，保证 schema 与 `user_version` 永远与产品同源；数据画像追求性能形似（核心交易、长尾商户、多币种汇率、投资持仓、定时计划与购买项），不追求业务语义全完备。

### 3. 物理隔离与包内 bin 形态

- 默认输出至 `src-tauri/target/ledger-perf/`（被 git 忽略、与真实用户库物理隔离，重建前先删旧库保幂等）。
- `ledger-perf` 作为后端根包自动发现 bin（`src/bin/`），携带正确性单测（画像行数、外键、确定性摘要）——schema 演进破坏生成器时在常规测试中第一时间暴露，同时产品 lib 不因工具扩散接缝。
- 基准消费入口复用既有 `pub` 查询/写入口，不重写业务 SQL：除读基准 `bench`（阈值门禁归 ADR-0068）外，同 bin 承载三个写基准观测子命令——`bench-import`（#532，批量导入 50/100/200 行 × 集中/均匀分布，快照恢复隔离副作用并断言余额缓存一致）、`bench-sync`（#1628，同步重放）与 `bench-market`（#1629，行情/价格历史批量 upsert），写基准当前只观测不设门禁。

## 备选与否决

- **大库文件提交进仓库 / git-lfs**：仓库膨胀、diff 不可审查且与迁移漂移，否决。
- **外部 JS/Python 脚本加 DDL 拷贝**：引入第二套 schema 事实源与第二技术栈，迁移演进后静默失真，否决。

## 后果

- 仓库零膨胀，任何人可在同参数下精确复现 50 万笔性能问题与优化前后对照。
- 读基准阈值门禁与 CI 调度规则由 ADR-0068 承载（原「CI 观察不判定」观察期已结束；原 V018 `note_pinyin` 补填随 V031 退役清除）。
