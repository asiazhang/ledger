# ADR 0107: 盈亏页退役逐匹配卖出明细——汇总三视图兜底，交易页新增标的下钻维度

- 状态：已接受（决策入档；实现随实施票落地）
- 日期：2026-09-11
- 作者：Ledger 项目
- 关联：ADR-0030（TransactionFilter 深模块与 URL 下钻参数表）；ADR-0094（会话内保留、URL 永远赢）；ADR-0038/ADR-0099（convert 两腿同记录）；词汇表：投资域「已实现盈亏（RealizedPnl）」、界面状态与交互域「TransactionFilter」「分类下钻」「商户排行下钻」「持仓下钻」（新）；来源：grill-with-docs 产品裁决（2026-09-11）

## 背景

盈亏页（已实现盈亏概览）当前五块：账户/标的筛选、总盈亏卡、按年/按账户/按标的三张汇总表、「卖出明细」卡。明细卡的数据本体是卖出匹配记录（security_lot_sales）的逐匹配行（卖出所得 − FIFO 对应批次成本），与交易页的 sell 流水行高度同构（日期/账户/标的/数量逐行都有），但数字语义是盈亏口径（成本单价、逐匹配盈亏）而非交易口径（成交单价、卖出所得）。产品评审中「卖出明细」卡两次被误读为交易流水冗余——卡名与内容物错位本身即是问题证据。

交易列表过滤维度（TransactionFilter）没有标的维度：`TransactionListFilter` 与 URL 下钻参数表（account / merchant / category / kinds / dateFrom / dateTo）均不持 instrument，从持仓页签跳到交易页按标的看流水目前不可达。持仓页签又只显示在持标的（v_holdings 有行），已清仓标的的卖出流水没有任何入口。

## 决策

1. **退役盈亏页「卖出明细」卡**（逐匹配明细视图）：盈亏页收敛为筛选 + 总盈亏卡 + 按年/按账户/按标的三张汇总视图，同源同过滤口径不变。后端 `realized_pnl_summary` 的 details 查询与投影随之删除，前端 `PnlDetail` 类型与明细表清理。
2. **逐匹配盈亏接受降级**：交易页 sell 行不补「已实现盈亏」列；逐匹配的成本批次与盈亏不再有逐笔可见处，由三张汇总视图兜底。将来真需要再立票翻案。
3. **交易页新增「标的」过滤维度**：`TransactionListFilter` 增 `instrument_id`——命中该标的的**全部证券流水**：buy/sell 行、convert 行**任一腿命中即算**（与时点持仓推算认 convert 两腿的既有口径对齐）、份额调整与现金分红行同样命中（实现不过滤 kind；2026-09-12 grilling 复核就地改正，原文只写前三种）；URL 参数表增一条 `?instrument=`，URL-only 下钻、无手动控件（与分类维度同规）；标的不在参考数据字典，按 id 形状校验、未命中视为参数不在场。
4. **持仓下钻**：持仓页签行的标的/代码列变可点击 → 交易页 `?account=&instrument=`（不带 kinds——「该标的的交易历史」语义完整，sell 筛选交易页一键可得）。
5. **清仓标的入口**：盈亏页「按标的汇总」行的代码列加同款跳转（只带 instrument、不带账户）——该表包含已清仓标的，是清仓标的卖出流水的唯一入口；标的字典无软删（被流水引用的标的不可删），跳转恒可达、不提供落空的跳转。
6. **汇总按币种分组**：总数与三张汇总表按匹配行币种分组展示（与持仓页签市值/未实现盈亏的按币种分组同款口径，issue #902 形态先例），不做跨币种折算——原「各币种裸数字直接 SUM」的混算口径废止（多币种账户下合计是错的）。盈亏的本位币折算需交易时点汇率，与 FxRateHistory 既有边界纠缠，MVP 不做。
7. **布局顺手收敛**：总盈亏卡 `cols="1 s:2 m:4"` 网格只放一个统计的冗余布局随本次一并清理。

## 理由

- 明细卡与交易页的信息重叠是产品事实（评审中两轮被误读为交易流水）；不可替代的只有逐匹配成本/盈亏，产品裁决该粒度不需要——页面简化收益大于逐笔粒度损失。
- 标的维度走 URL-only 与分类维度同规：列表页过滤控件面保持简洁，无第二个消费方前不给手动控件；URL 永远赢、会话内保留、复位守卫由参数表同规则继承，零新增语义。
- 汇总按币种分组是真实缺陷的顺手修复，且有持仓页签现成先例；单币种用户显示无变化。
- 多入口共享同一下钻机制（同一 URL 参数、同一落点），边际成本极低；清仓标的的可达性与来源列「不提供落空的跳转」原则一致。

## 代价

- 逐匹配明细（成本批次粒度）永久失去 UI 可见处，恢复须翻案本 ADR。
- 交易页 URL 参数面 +1；后端列表查询多一个可选 JOIN，convert 命中判定需扩到两腿字段。
- 汇总展示从单一数字变按币种分组（多币种用户显示多组数字）。

## 替代方案

- **交易页 sell 行补「已实现盈亏」聚合列**：保住逐笔盈亏，但动核心读路径（list_transactions 逐页 JOIN 聚合），且产品已裁决逐笔粒度不需要——否决。
- **保留明细卡与持仓跳转并存**：冗余不消除，否决。
- **标的维度给手动下拉控件**：列表过滤面膨胀，消费方仅两个跳转入口，与分类维度「仅 URL 下钻」先例不符——否决。
- **汇总按本位币折算（历史汇率）**：需交易时点汇率折算，复杂度高且引入第二套折算口径——MVP 否决，留后续迭代议题。

## 影响

- 词汇表：投资域 RealizedPnl 词条（四视图改三视图、明细退役注记、汇总按币种分组口径）；界面状态与交互域 TransactionFilter 词条（标的维度）、新增「持仓下钻」词条；CONTEXT-MAP.md 分域一览同步。
- 契约：`TransactionListFilter` 新增可选字段（只增不改，无 BREAKING）；`realized_pnl_summary` 返回形状删除 details 并将汇总改为按币种分组（IPC 读命令，前后端同仓同发布，类型与测试同步改）。
- 实现：拆实施票交付——后端标的过滤维度、前端持仓下钻与盈亏页收敛、汇总按币种分组、死代码清理；验收判据见 issue 正文。
