# ADR 0081: 投资标的按代码查询为主干道——股票按代码查询端点、美股市场扩展、全量同步退役、AI 导入脱钩标的字典

- 状态：已接受（决策入档；实现随后续议题落地，schema 前置随本议题先行落地）
- 日期：2026-09-06
- 作者：Ledger 项目
- 关联：spec #690；延伸 ADR-0037（标的搜索与幂等创建形状）、ADR-0039（基金查询端点与创建增强先例，股票侧对称为同一模式）；退役 ADR-0015 职责切分中的全量修字典一翼、修订 ADR-0036「股票类字典的修正归标的全量同步」口径；消费 ADR-0038（场外基金一等标的、按代码即拉）；词汇表：投资域 Instrument / InstrumentSync / HoldingPriceSync，AI 导入域 AI API

## 背景

投资类数据迁移（spec #690）暴露出一条失衡的链路：股票导入依赖一个 AI 既不知道也触发不了的前置——标的搜索只搜本地标的字典，而股票字典靠用户手动「全量同步」填充（仅 IPC 命令、无 HTTP 端点，入口提示词与导入知识零处提及）；字典为空时既定出路「名称充代码」建行无行情通道，AI 也缺省 market 导致 unknown 行同样永无行情。基金侧已有「按 6 位代码实时查询」端点与东财创建增强（ADR-0039），股票没有对等能力。同时全量同步（数百次 API 请求）只为录三五只标的，性价比极低；场内 ETF 不在全量同步板块范围、又被增量同步的类型分区跳过，持仓无价无市值；美股不支持，而数据源（东方财富）的既有接口族实测原生支持（2026-09 实测）。

经 spec #690 设计定案：把「按代码查询」确立为投资标的解析的主干道（基金先例推广到全类型），全量同步退役。本 ADR 记录四项架构决策与市场闭集扩展的 schema 前置。

## 决策

1. **股票按代码实时查询端点**：语义对齐基金查询端点（ADR-0039 决策 2），`GET /api/v1/stocks/{code}`，market 为可选 query 参数；缺省按代码形态单点推断（6 位 6 开头→沪、6 位 0/3 开头→深、5 位数字→港股左补零、纯字母→美股三市场候选遍历），推断失败或显式 market 与代码形态矛盾返回 400。响应对齐基金查询投影：代码、东财权威名称、精确市场、币种、最新价（价格刻度口径）、价格日期；查无此码 400、网络故障 500。**「按代码实时查询优先」自此是投资标的解析的主干道**：基金（ADR-0038/0039）与股票是同一模式的两翼，本地字典搜索（ADR-0037）降为辅助。
2. **美股市场扩展（nasdaq/nyse/amex）**：标的 market 闭集从 sh/sz/hk/unknown 扩至含美股三市场，创建落精确交易所归属、报价币种 USD（缺省推导表扩展）、行情 secid 前缀 105/106/107；UI 只显「美股」。北交所暂不纳入（另行议题）。schema 前置见决策 5。
3. **全量同步退役**：ADR-0015 职责切分「全量修字典 / 增量刷价格」中，全量修字典一翼失去存在理由——全量同步入口、命令、进度/取消事件与前端组装整体退役；持仓价格增量同步（HoldingPriceSync）保留。**股票字典修正职责改由「按代码查询/创建带回权威名称」承担**——ADR-0036「股票类字典的修正归标的全量同步」的口径自此读作「归按代码查询」，随用随修。
4. **AI 导入不再依赖标的字典**：标的解析对「本地字典已被全量同步填充」的隐含假设解除——字典为空时 buy/sell 迁移照常经「按代码查询 → 创建 → 写入」三步完成（ADR-0039 决策 4 基金三步流推广到全类型）；「名称充代码」降为源数据确无代码时的兜底路径，不再是有代码行的既定出路。
5. **schema 前置（市场闭集扩展，就地 BREAKING）**：`instruments.market` 检查约束在 V002 就地扩展（sh/sz/hk/unknown → 增 nasdaq/nyse/amex）。SQLite 检查约束不可 ALTER，就地修改只影响全新安装；**存量库不重跑迁移、保持旧闭集，其上创建美股市场标的将被 CHECK 拒绝，不提供自动修复**——发布边界判定：最新 tag v0.5.0 之后的提交均未发布，本修改随下一版本发布（2026-09-06 裁定：1.0 前就地修改历史迁移可接受 BREAKING，不做兼容，与 ADR-0038 决策 5 先例同口径）。两级 BREAKING 标记随本议题落地：V002 头部就地修改注记 + CHANGELOG「Unreleased」BREAKING 条目。报价币种推导表扩展（三美股市场→USD）与行情 secid 前缀映射（105/106/107）随本议题先行落地；`v_holdings` 视图不引用 `instruments` 表，无视图依赖处理；美股行情通道（增量同步类型分区扩展、f2 换算）、查询端点、创建增强与 UI 随后续议题落地。

## 理由

1. **按代码查询优于本地字典搜索**：基金先例（ADR-0039）已验证「查询命中→真实代码创建→回填权威名称」的链路质量——账单里的代码是权威事实，东财可达时字典质量由后端保证；本地字典搜索的覆盖面取决于一个用户永远不会主动触发的重前置，主干道放错位置。
2. **美股精确落库而非合并单市场**：三市场精确归属让行情查询零候选开销（secid 一次命中），也保留未来按交易所细分的空间；UI 层折叠为「美股」是展示语义，不进存储闭集。
3. **全量同步退役是职责切分的自然收束**：ADR-0015 拆分的动机（高频轻操作不该绑在低频重操作上）在按代码查询落地后走得更远——字典修补频率从「低频重操作」降到「随用随修的个位数请求」，全量链路（数百次请求、进度/取消事件、二次确认）整体失去用户。
4. **闭集扩展走就地修改而非重建收敛迁移**：市场 CHECK 只放宽不改紧，存量行全部合法；代价收敛在「存量库上美股功能不可用」，1.0 前不构成兼容义务（裁定见决策 5）。表重建迁移（含视图依赖处理）的机制面在收益不成立阶段不引入；若 1.0 发布边界需要，可再补收敛迁移。

## 代价

1. 存量库（≤ 当前发布版）升级后无法创建美股市场标的，且无自动修复——处置与否由维护者自行权衡（重建账本或人工迁移）。
2. 代码形态推断（market 缺省时）对歧义代码依赖显式 market 参数消歧；推断失败的报错路径成为查询端点的常态分支。
3. 美股行情通道落地前，本议题扩展的 secid 前缀映射暂无调用方（增量同步类型分区仍只走 stock 既有范围）——映射先行是为后续议题消除 schema 阻塞。
4. 「按代码查询带回权威名称」承担字典修正后，未查询过的既有错误行不会被自动修正（无全量兜底）；错行走自建标的删除通道。

## 替代方案

- **新增表重建迁移兼容存量库**（instruments 重建 + 外键关闭 + 视图重建）：机制面大且收益在「1.0 前不兼容」裁定下不成立，否决；1.0 边界需要时再议。
- **全量同步保留与按代码查询并存**：字典修正双路径、用户心智两套，且数百次请求的重链路无使用场景，否决。
- **美股合并为单一 market 值（如 'us'）**：丢精确交易所归属，行情查询退化为候选遍历或另立映射表，否决。
- **北交所随本批纳入**：代码形态与沪深重叠加深推断歧义，数据源支持未实测，否决（另行议题）。
- **市场闭集不加 CHECK、由写入通道收口**（source 列先例）：market 是行情路由的硬键，库层闭集能在同步/AI/手动三通道之外拦住脏值，与 source 的「纯标记」语义不同，否决。

## 影响

- 词汇表：投资域 Instrument 词条市场闭集边界随本议题更新；InstrumentSync（退役）、HoldingPriceSync（分区扩展）、AI 导入域 AI API（端点清单）词条随对应实现议题改写。
- 前端：`MarketType` / `MARKET_TYPES` 闭集镜像与市场显示标签（含「美股」折叠）随 UI 议题落地；在镜像扩宽前，标的页对闭集外 market 值回退显示裸值（既有回退语义），不提前暴露三交易所选项。
- Schema：V002 就地 BREAKING（两级标记已落地）；不新增迁移。
- AI 契约：market 枚举值放宽属「只增不改」合规面；新查询端点与创建增强随后续议题落地，届时契约自描述同步覆盖。
