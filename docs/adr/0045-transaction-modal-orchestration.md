# ADR-0045: 交易行操作弹窗编排收进 TransactionModalState 深模块 + 页码回退入口

- 状态：已接受
- 日期：2026-08-30
- 作者：Ledger 项目
- 关联：issue #313（spec，经 grilling 两轮收敛定型）；先例 ADR-0030（TransactionFilter 深模块，接口纪律与测试策略沿其房式）、ADR-0041（ScheduledPlanList 深模块，弹层纯度与 direct-import 依赖惯例）；ADR-0035（弹层注册表，本决策的弹层纯度边界）

## 背景

交易列表视图里四个行操作弹窗（记一笔、退款、编辑、加入物品）各持一套「显示开关 / 目标行 / 回调序号 + 开启回调 + 关闭处理」样板，定时页签还有两套同款——同一编排知识复制六处。接口泄漏也已现网发生：删除当前页最后一条后，视图直接改写页码以回退（`if (data.length === 1 && page > 1) page -= 1` 后自行 `load()`），绕开了 ADR-0030 决策 6「翻页归零只走模块出口」的接口保证，靠注释维持而非接口维持。issue #313 决定抽一个行操作弹窗状态模块统一编排，并给 TransactionFilter 增补显式页码回退入口，本 ADR 沉淀 grilling 确认的接缝与规则。

## 决策

1. **新增前端 composable `TransactionModalState`（工厂形态，交易弹窗编排）**：意图闭集四——`create`（携带 `CreateTransactionKind` 子类型，无目标行）、`refund` / `edit` / `add-item`（携带目标 `Transaction` 行，`edit` 另携带取到的 `TransactionTrade`）。`show = 意图非空` 由单一判别联合派生（无独立 show 布尔），`close()` 清回 null 终态，回调序号随 `open` 递增内化——「开启 / 目标 / 关闭编排」全仓仅此一处，视图不再持有任何 `showXxx / xxxSource / xxxSeq` 三件套。
   > 注（2026-09-04 修订，issue #521）：本决策「等真正第二个消费者出现再参数化」的条件已触发——grilling 期盘点确认其余弹窗手搓「show + target + seq」三件套共 13 处。弹窗开启编排泛型化为通用工厂 ModalIntent（弹窗意图编排，ADR-0072），本模块迁为其上首个适配器，对外接口与行为不变；异步时序守卫（决策 2）仍留在本模块适配器层，不上浮通用工厂语义。
2. **open 统一异步签名 + 编辑取数竞态守卫**：`open` 统一返回 `Promise<void>`（仅 `edit` 真正 await）。编辑的「先取买卖明细再开窗」时序内化：取到再开窗，失败走错误提示不开窗；并加代数守卫（last-open-wins）——每次 open 递增一代，await 返回后代数已过期则丢弃（不设意图、不 bump 序号、不开窗），消灭「慢 A 覆盖快 B」竞态。慢取/失败行为一处定义（user story 4）。
3. **依赖 direct-import，不做注入**：模块直接 `import api` 与 `useMessage`，沿用 `useScheduledPlanList` 惯例；测试在 `vi.mock('naive-ui')`（捕获提示）+ `vi.mocked(invoke)`（捕获命令）两层 mock，不新增注入面。`getTransactionTrade` 只有一个实现，注入是 YAGNI。
4. **关闭后副作用留视图**：模块只内化「关闭」（意图 → null 终态），refresh / load 仍归视图——视图成功 handler 收缩为 `close(); refresh()` / `close(); load()`。弹窗编排与 TransactionFilter 两个深模块保持正交，不建立「弹窗模块 → 过滤模块」依赖（ADR-0041 弹层纯度方向的延续）。
5. **TransactionFilter 增补页码回退入口（接口增补而非新模块）**：语义 = 声明「删除当前页一行后本页剩 N 条」——`N === 0 && page > 1` 时减一页（回退），然后一律版本 bump（不走「翻回第一页」的既有 `refresh` 语义：不回退时保持当前页）。视图 `remove()` 变为「删除成功 → 回退入口（剩 N 条）」，不再直写页码、不再自行 `load()`。这是 ADR-0030 代价 3 预留的「不翻页的静默重拉」接口扩展，而非复用现语义。
   - 判定用「删前本页仅 1 条」而非「重拉后 total 超页」：在 offset 分页每次删一条、无并发新增的前提下两者严格等价（本页 1 条 ⇔ 当前页是末页且删后超页），免去回退前的第二次请求；并发新增导致的漂移沿用 ADR-0008 已知边界。
6. **定时页签两套弹窗样板不进本票**：其行操作已由 ScheduledPlanList 的 `rowActions` 描述符体系接管，且「编辑订阅」是表单接缝变体而非「目标行 + Modal」编排，形态不同；顺带消费降级为后续票（不强制）。
7. **测试策略转移（ADR-0030 决策 7 / ADR-0041 决策 10 同款）**：模块测试直打接口——`open` 意图 → 意图终态（type / payload / trade / 序号）与代数守卫竞态（慢 A + 快 B → 终态 B，A 丢弃）；回退入口 → page 终态与请求参数（剩 0 条且非第一页 → page-1 + 一次重拉；剩 ≥1 条 → 只重拉不翻页）。组件测试收缩为渲染与交互冒烟，可迁移的时序用例迁到模块测试。

## 理由

- **为什么 target 锁 `Transaction` 不做泛型**：定时页签行操作已由 `rowActions` 描述符接管、形态不同，首版把 target 泛型化是 YAGNI 且违 ADR-0041「防上帝模块」教训；等真正第二个消费者出现再参数化（同 ADR-0030「工厂形态等第二个消费者」的既有取舍）。
- **为什么 show 由意图派生而非独立布尔**：消灭「source 非空但 show=false」的非法中间态，意图即唯一事实源，终态由判别联合的类型系统保证而非运行时约定。
- **为什么代数守卫**：慢取竞态散在视图里无人定义，收进模块正是「慢取行为一处定义」的落点，且可测（终态断言）。
- **为什么不注入 fetcher**：`getTransactionTrade` 唯一实现，`useScheduledPlanList` 已走通 direct-import + 两层 mock 的组件外测试路径，注入的解耦收益不抵接口膨胀代价。
- **为什么副作用留视图**：内化会造「弹窗模块 → 过滤模块」单向依赖，恰是 ADR-0041 弹层纯度要避免的方向；两个深模块正交、由视图接线。
- **为什么回退入口用「减页不归零」**：与既有 `refresh()`「翻回第一页」语义不同，复用现语义会错误改写页码；ADR-0030 代价 3 已预留「扩展接口而非复用」。
- **为什么删前 1 条判定**：精确判定「超页」需重拉拿 `total`（多一次请求），而 offset 分页下两者等价；省下的请求换来接口语义的简洁。

## 代价与边界

1. 编辑 open 变异步，调用处需 await（视图侧微小代价）。
2. 模块测试需 mock invoke + naive-ui 两层（既有技法，非新发明）。
3. 回退入口语义固定为「删后本页空才减页」；未来若出现「一次删多条后精确判定超页」需求，需重拉拿 `total`，应扩展接口而非复用现语义。
4. 本决策只定接缝与纪律，不定实现文件名与目录——实施票在仓库既有命名约定内自行落位（同 ADR-0041 决策 4）。
5. 视图 `remove()` 的成功提示仍留视图（回退入口只负责页码与版本信号，不吞 toast）。
