# ADR-0096: buy/sell 增设出资账户——直扣买卖的资金流归因

- 状态：已接受
- 日期：2026-09-10
- 作者：Ledger 项目
- 关联：ADR-0038（场外基金申赎同构复用 buy/sell）、ADR-0011（金额模型与度量矩阵）、ADR-0067（余额与净资产缓存）、ADR-0091（多端同步语义命令）、ADR-0053（借贷复用转账，「资金账户」一词的既有占用）

## 背景

场外基金申赎等直扣场景里，钱从银行卡直接变成份额，不经投资账户现金停留（ADR-0038 只定义了份额侧：申购=buy、赎回=sell）。现行 buy/sell 行只有 `account_id` 一端，kind 矩阵把现金腿恒记在投资账户上（buy −/sell +），于是直扣一笔申购：资金实际流出方（银行卡）无任何流水、余额虚高；投资账户余额被扣成负数；净资产（非投资账户余额 + 持仓市值）每笔虚高。用户只能在备注手填资金来源，机器不可读，资金流动在账本里断链。

「资金账户」一词已被借贷域用作账户侧别（receivable/debt 之外的一切账户），本决策另起名「出资账户」。

## 决策

1. **buy/sell 增设可选出资账户**：`transactions` 新增可空列（已发布 schema 只增；删除语义比照 `account_id` 硬删受限，命名随迁移落地）。填写出资账户 = 结算现金从该账户流出（buy）/流入（sell）；不填 = 维持现状。
2. **归因规则单条**：结算账户 = 出资账户 ?? 投资账户（`account_id`）；buy 对结算账户记 −、sell 记 +，kind 矩阵符号不变、归因端点可变。出资账户命中时投资账户现金腿为 0——钱不经手；未填时现金腿记投资账户自己，保住场内「充值（transfer）→ 余额买入」两步流，该路径今天即正确。
3. **投资账户余额 = 子弹**：已充值未投入的现金；充值/提现经既有 transfer 承载，出资账户命中的买卖不动子弹。可投资资产的「子弹」腿与净资产的守恒随归因规则自然成立，不再依赖用户自觉成对记账。
4. **出资账户准入闭集**：现金类账户（cash/bank/credit/ewallet/other）；排除投资账户（跨投资账户走 transfer，保住子弹语义单一）与 receivable/debt（借贷账户不承载投资结算）；币种必须与交易币种一致，跨币种出资 MVP 不做。
5. **InvolvingAccount 扩为三端**（转出 ∪ 转入 ∪ 出资）：账户过滤、余额重算的受影响账户、AI 读回对账共用同一口径自动覆盖；修改路径全字段替换，受影响账户取旧行 ∪ 新行的三端并集。
6. **列表展示**：出资账户命中的 buy/sell 行账户列按「资金流出方在前」展示——buy 展示「出资账户 → 投资账户」、sell 展示「投资账户 → 出资账户」（与决策 1 的流出（买入）/流入（卖出）语义一致，转账同款两端风格；sell 方向修正 issue #1030，原文误写为 buy/sell 统一「出资账户 → 投资账户」）；备注回归自由文本。
7. **无负余额守卫**：余额买入可买穿，与支出可透支账户一致——余额是口径不是信贷控制。
8. **契约面全部只增**：HTTP 交易创建/修改加可选字段；同步 DomainCommand 载荷追加可选成员（旧日志可在新 schema 重放）；AI 契约经运行时自描述自动带出。旧设备重放新 op 时未知字段被忽略、按旧规则把现金腿记在投资账户上，余额错至全部设备升级——已接受代价。导入去重哈希纳入出资账户（应用层行为、无唯一索引，历史行不受影响）。
9. **存量不设产品迁移工具**：既有直扣买入由用户经 AI API 逐行修改补录出资账户（修改 = 全字段替换）；「不删后重导」纪律不变，已有部分卖出的买入行禁改的残差由用户自行处置（余额调整可兜底）。

## 理由

- **为什么单笔挂第二账户，而不是「转账 + 买入」两笔**：真实资金流是「银行卡 −、份额 +」，两笔隐含钱在投资账户现金停一站（先 + 再 −），与场外申赎现实不符；且成对语义（同事务写两行、成对编辑/删除/回退、AI 与同步成对产出）会渗透全部写入入口，列表也翻倍——恰是用户明确拒绝的查看体验。
- **为什么不是仅改展示**：余额口径错误是真金白银的（净资产每笔虚高），展示层救不了余额，备注文本也进不了任何口径。
- **为什么归因规则不写进 kind 矩阵**：矩阵回答「某 kind 对度量的符号」，本决策改变的只是行级归因端点；单条归因规则让 Writer、余额重算、读回对账共用同一口径，不给闭集矩阵开账户类型条件分支。

## 代价

1. 同一 buy/sell 行涉及两端账户，修改的受影响账户并集扩至三端（旧出资 ∪ 新出资 ∪ 投资账户），写入路径成本略增。
2. 多端场景旧设备余额偏差窗口（决策 8），至全部设备升级消失。
3. 存量行补录前按新语义读作「从余额购买」，投资账户余额呈现透支形态——由用户自行补录消除，产品不设迁移机制（决策 9）。
4. 出资账户命中的 sell 在确认日记收款 +，到卡存在在途时差——记账以确认单日期为准的既有口径不变，接受。
