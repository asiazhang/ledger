# ADR-0112: 后端 workspace crate 拆分——按域拆箱、无环单向正交与门禁保底

- 状态：已接受（spec #1086 grilling 定稿；P0–P1 已落地——workspace 骨架与门禁继承 #1087、基础设施 crate 全量归位 #1088、协议 crate 破环 #1089；写路径副作用接缝反转余量由 #1090 承接；P2 核心交易域已落地 #1092；业务域逐域 crate 化与壳层收敛按 #1091、#1093–#1108 逐票交付，落地状态见各票而非本文；修订：决策 1「不做域内模块重排」被 ADR-0113 限缩为拆 crate 阶段纪律——拆出后的域内重排归该 ADR 管辖，见文末修订注记）
- 日期：2026-09-13
- 作者：Ledger 项目
- 关联：spec #1086（顶层 spec）；本文档票 #1111；实施序 #1087 → #1088 → #1089 → #1090 → #1091–#1108，CI 侧 #1109/#1110/#1112；修订对象 ADR-0056（分层载体从目录升级为 crate）、ADR-0071（认许边在 crate 边界下的新形态）、ADR-0084（测试工厂前提）；分工相邻 ADR-0111（crate 内部组织，与本文「拆分轴 vs 内部形状」分家，决策 7 交叉引用）；引用 ADR-0060（panic 门禁）、ADR-0083（守门 Bun 运行时）、ADR-0032（置脏单点）、ADR-0067（余额缓存写路径整体重算）、ADR-0091（同步写后触发）、ADR-0101（重放注册表）

## 背景

后端约 302 个文件、83,756 行实现集中在单一 crate（tauri 应用包），两个代价显性化：

- **固定编译成本**：PR 端到端时长由后端测试 job 单独决定（典型 285–370s、最差 440s），其中依赖 100% 命中缓存后，本仓单 crate 自己的编译仍占 113s——成本不随改动规模变化，而随单体体积变化。缓存体积 2009MB、解包 40–60s，apt 安装随 runner 波动 20–98s（CI 侧治理独立成票 #1109/#1110，与本 ADR 的结构改动互不依赖）。
- **边界无编译期信号**：域边界只由文本守门脚本约束（域目录白名单 + 认许边，ADR-0056/0071），任何跨域引用只要白名单放行即可编译；「域不依赖壳」「基础设施不依赖域」靠评审纪律维持。正交分解是文档承诺而不是编译器可验证的事实，域无法独立编译、独立演进。

spec #1086 同时定下价值判据：**拆 crate 的价值不以编译时间是否显著下降为条件**——即使编译只降 10s 也保留，按域分箱本身就是更好的架构组织方式。

## 决策

### 1. 拆分轴：按域拆，crate 清单封闭

按业务域拆箱：**协议 crate**（`ledger-sync-protocol`：设备标识、领域命令契约、op 本地记录与读取、流位点）；**基础设施 crate**（`ledger-infra`：数据库、错误、设置、文件工具、日志、事件、信号、闭集、壳层统一读写入口）；**核心交易 crate**（最底层域，任何业务域可依赖）；**业务域 crate ×15**（账户、分类、币种、商户、投资、定时计划、物品、保单、预算、实物资产、报表、仪表盘、备份、行情同步、多端同步）；**测试支持 crate**（统一测试数据库工厂与共享断言，随首个域 crate 的 dev-dependency 需求落地）；**根包**仍是 tauri 应用包，持有壳层（`commands/` + `api_server/`）、命令注册扫描、菜单与集成测试入口——工具链与打包流程零变化。

参考数据三域（分类、币种、商户）保持各自独立 crate、不合并；不做域内模块重排。

### 2. 正交判据：无环且方向单一

「正交」的判据是**无环且方向单一**：允许上层域依赖下层域（分层优先级 壳 → 域 → 基础设施 → 协议，数值大者可依赖数值小者），被禁止的是任何环与「域/基础设施依赖壳」方向。域间横向依赖允许但必须显式——跨 crate 引用天然显式（`Cargo.toml` 一行即依赖声明）；同 crate 内的横向边延续 ADR-0071 决策 5 的逐条留痕口径。正交性由 cargo 依赖图编译期验证：成环即编译失败，「正交分解」从文档承诺变为编译器事实。

### 3. 布局与迁移纪律

- workspace 根 = Rust 根 `src-tauri/`，`[workspace] members = ["crates/*"]` glob 纳入——新 crate 落入约定成员目录即自动成为成员，不依赖手工清单。
- 迁移顺序：P0 门禁前置 → P1 基础设施 + 协议（破环）→ P2 核心交易 → P3 叶子域逐域 → P4 行情同步与多端同步 → P5 壳层收敛；每域一次独立交付（一域一票一 PR，可回退、可审查），大体量搬迁前设检查点复盘。
- 调用点零改动：域 crate 化后原引用路径以再导出形态保持可用（#1088 先例：根包 `pub use ledger_infra::…`，域与壳层既有调用点零改动）。
- 行为等价证据 = 既有三层测试原样跑绿；迁移过程只许改引用形态（包名/路径），断言与场景文本不改——出现断言修改即视为行为被意外改变，停下报告。

### 4. 门禁保底：三层，缺一即红

crate 拆分的边界约束若只靠自觉，会以「静默漏检」方式失效，故门禁先于拆分（P0 硬前置）：

- **编译期**：cargo 依赖图本身——未声明依赖的越界引用编译失败，是最强的门禁；声明的依赖方向越界（如域 crate 依赖壳）则由结构守门的 CRATES 依赖方向核对拦住。机器面先例：协议 crate 根文档 compile_fail 负向用例（反向引用 `tauri_app_lib` 编译必红）。
- **门禁接线**：lint 表不跨 package 自动继承，clippy 六件套（ADR-0060）的唯一声明处在 workspace 级 `[workspace.lints.clippy]`，成员必须显式 `[lints] workspace = true`——漏写时 clippy 对该成员照常全绿（独立 scratch workspace 实测），故由结构守门负向核对：删任一成员的继承行即红。非虚拟 workspace 下 cargo 默认只作用根包：静态检查与测试命令显式 `--workspace`/词尾 `--all`，缺范围参数即红（`--all-targets` 这类 `--all*` 旗标不算范围声明，假绿形态有夹具锁死）。
- **结构守门升级**：`check-structure.ts` 从模块路径白名单升级为 crate 边界核对——`CRATES` 清单是 workspace 成员、分层与允许依赖方向的唯一事实源，成员目录与清单双向全等（新 crate 未登记即红）；模块级白名单、认许边与账本数据表 DML 禁令（ADR-0111）继续辖编译器看不见的规则。边界知识的唯一来源仍只有一份。

以上负向用例断言对准「检查失败」这一可观察结果（退出码与输出），不对准实现形状（#1087 交付，夹具见 `src/__tests__/check-structure.test.ts`；接线/时机类条目的「删除即变红」纪律见 ADR-0087）。

### 5. 破环方式：不是一次协议抽离，而是一类写路径副作用接缝反转

破环的完整答案由两部分组成，结论的主体是第二部分：

- **共享契约下沉（协议抽离）**：多端同步的 op 记录让业务域在写路径引用同步域，同步域又要把命令重放回业务域。抽协议 crate 作最底层共享底座（业务域/同步域 → 协议 → 基础设施），打断三条生产环：核心交易域 ↔ 多端同步域、账户域 ↔ 多端同步域、投资域 ↔ 多端同步域（根因都是写路径记录 op；#1089）。
- **写路径副作用接缝反转（一类挂载点，不是单次动作）**：其余环全是同一根因的实例——下层在写/读路径内直调上层的副作用（置脏、重算、来源解析）。这类环按同一形态逐挂载点反转：**下层定义注册点、上层注册实现、壳层启动时接线**；未注册时行为显式（失败可见或明确降级），不静默丢副作用。覆盖的挂载点清单：

  | # | 挂载点 | 原边（下层 → 上层） | 反转形态 | 状态 |
  | --- | --- | --- | --- | --- |
  | ① | 连接层提交点的置脏触发 | `db::after_commit` → `backup::{mark_dirty, …}`（ADR-0032 置脏单点） | 基础设施只留 `db::AfterCommitHook` 注册点与调用时机，备份域 `install_after_commit_hook` 提供实现；壳层启动、测试工厂、BDD world、基础设施单测四类入口各自接线一次，「删除启动接线即红」由源码扫描守门兜底（`check-background-services.ts::BOOT_WIRING`） | 已落地（#1088） |
  | ② | 交易写入的受影响账户余额重算 | transaction writer/behavior → `accounts::balance`（ADR-0071 决策 5 回边，ADR-0067 同事务整体重算约束不变） | 交易域定义注册点，账户域注册实现，壳层启动接线 | #1090 |
  | ③ | 交易读取的计划来源解析 | transaction read → `scheduled_transactions`（来源列「计划反查」批量填充） | 同上 | #1090 |
  | ④ | 备份调度线程的追补触发 | `backup::auto` 调度线程单一 tick → `scheduled_transactions::run_catch_up`（ADR-0042，#1091 起调度宿住 ledger-backup crate） | 备份域只留 `register_catch_up_hook` 注册点，定时计划域 `auto_run::catch_up_hook` 提供实现（开关镜像与本地「今天」在实现内注入），壳层启动接线；「删除启动接线即红」由源码扫描守门兜底（`check-background-services.ts::BOOT_WIRING`） | 已落地（#1091） |
  | ⑤ | 核心交易域对六个域的写/读路径残留边（#1092 crate 化前置）：投资 kind 装配（Local/Replay）/副作用应用/修改回退/删除释放、商户名先查/即建、本位币基准读取、出资账户视图（含原 AccountType 类型只读认许边的消亡）、来源列①保单/③物品/④标的反查与转换两腿扩展 | transaction → `investment` / `merchants` / `currencies` / `item` / `policy` / `accounts` | 交易域定义注册点（`investment_seam` / `merchant_seam` / `base_currency_seam` / `read` / `funding`），各提供域 `install_*_hook(s)` 提供实现，壳层启动/测试工厂/BDD world/ledger-perf/产品建缝测试点五类入口接线；未注册即码化错误（失败可见，不静默），无需 BOOT_WIRING 扫描兜底 | 已落地（#1092） |

  同类先例：协议 crate 的同步写后触发（ADR-0091 决策 9 的信号点随迁协议 crate 成钩子槽，同步调度 `install_after_write_hook()` 在壳层/测试工厂/BDD world 启动时装入响应闭包，#1089）——与挂载点①同构，证明该形态在协议抽离过程中同样适用。#1091 交付后（①②③ #1090、④ #1091）数据库↔备份域、核心交易域↔账户域、核心交易域↔定时计划域、备份域↔定时计划域四对互引全部消除；#1092 交付后（⑤）核心交易域对投资/商户/币种/物品/保单/账户六向的残留边亦按同一形态反转，全部域间依赖成为无环单向图。

- **测试专用边（dev-dependency 环）**：数据库 ↔ 核心交易域的双向引用只存在于测试侧（基础设施 crate 单测经根包测试工厂建库），用 dev-dependency 环解决——Cargo 允许，测试目标与生产依赖图分离，不构成生产环；结构守门的依赖方向核对只辖生产依赖。

### 6. 测试工厂落点：独立测试支持 crate + dev-dependency

测试工厂以**独立测试支持 crate** 形态由各域 crate 以 dev-dependency 引用，测试设施不在各域复制、也不制造生产依赖环；「跟随基础设施 crate + feature 暴露」方案作废——它让基础设施反向依赖域，等于重建刚拆掉的环。当前过渡形态：工厂仍住根包 `test_support/`（域目录尚在根包，环无必要），基础设施 crate 经 dev-dependency 环消费（#1088 实证环可解）。ADR-0084 决策 2 的否决前提（「单 crate 无 workspace，自依赖循环不可解」）随之修订，见该 ADR 修订注记。

### 7. 文档分工与同步

拆分轴、正交判据、破环方式与门禁保底归本文；crate 内部组织（定位口径、四区、共享接缝、文件粒度）归 ADR-0111，两者交叉引用、不互相复述。随本文生效的修订：ADR-0056 分层载体从目录升级为 crate（见其修订注记）；ADR-0071 认许边记录 crate 边界下的新形态（生产边改注册点形态、清单辖测试专用边）；ADR-0084 测试工厂前提修订为「workspace 下 dev-dependency 环可解」；AGENTS.md 后端分层指导同步。**领域词汇表地图不动**：crate 边界是代码结构，不是领域术语。

## 备选与否决

- **维持单 crate + 文本守门**：固定编译成本不降、反向依赖无编译期信号，已被判定失效；CI 侧治理（#1109/#1110）只压固定开销、给不出边界信号，两者不可互替。
- **合并大 crate**（业务域并入少数大 crate，如参考数据三域合一或全部业务域一个 crate）：P0–P1 的门禁与工具改造照付，域边界却仍不在编译器视野内（crate 内退回文本守门），失去逐域独立编译、独立演进、越界即编译失败的核心收益；「每域一 crate」与参考数据三域不合并是 spec 明文裁决。
- **端口/事件反转**（用 trait 端口或事件总线消解一切跨域引用）：否决——把合法的、方向单一的依赖也改成间接层，真实依赖方向被运行时接线掩盖，导航与编译期可读性双输。反转只用于决策 5 的「下层直调上层的路径内副作用」这一类挂载点，不作为通用架构风格；合法依赖（上层 → 下层）保持直呼。
- **测试工厂跟随基础设施 + feature 暴露**：见决策 6，重建刚拆掉的环，作废。

## 后果

- 域边界由 cargo 依赖图强制，跨层越界引用编译失败；同级域可并行编译；每域独立演进、独立被引用。
- 根包保持 tauri 应用包身份：桌面三平台与 Android 打包、命令注册扫描、集成测试入口零变化；前端 job 不受影响。
- 编译时间只作观测记录（#1087 起每票记录 CI 编译阶段耗时与缓存体积，基线见 `docs/verification/1087-workspace-gate-baseline.md`），不构成保留或回退的理由。
- 门禁接线由删除即变红的负向用例锁死：成员漏继承、新成员漏登记、命令漏 `--workspace`，任一发生即红。
- 零用户可见行为变化：schema、迁移、IPC/HTTP 契约不变；行为等价由三层测试原样跑绿证明。
- 文档同步面已按决策 7 落盘（ADR-0056/0071/0084 修订 + AGENTS.md 同步 + 本 ADR）。

## 修订注记（ADR-0113，2026-09-12）：决策 1「不做域内模块重排」限缩为拆 crate 阶段纪律

决策 1 末句「不做域内模块重排」的适用域限缩：该纪律与决策 3 的迁移纪律同源，只约束「拆出时的布局」——拆出即冻结原域内布局、不做顺手重排，为的是让迁移可机械核对、行为等价可证明。拆出后的域内重排由 ADR-0113 管辖（业务域 crate 四区、写路径 / 跨域接缝 / 共享语义的单向层序、模块清单双向全等守门），首个对象是 `ledger-transaction`。本文的拆分轴（决策 1 前半句）、正交判据（决策 2）、迁移纪律（决策 3）、门禁保底（决策 4）、破环方式（决策 5）、测试工厂落点（决策 6）与文档分工（决策 7）均不变。
