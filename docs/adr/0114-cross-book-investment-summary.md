# ADR-0114: 跨账本投资汇总：多库只读聚合、只覆盖投资域、按主账本位币折算

- 状态：已接受（grilling 定稿，2026-09-12）
- 日期：2026-09-12
- 作者：Ledger 项目
- 关联：ADR-0089（多账本立项：一库 = 一本账、schema 永不加账本维度、「不跨本汇总」口径）；ADR-0067（余额与净资产读探针）；ADR-0075（SQLite 加密模式）；ADR-0107（盈亏按币种分组）；词汇表：投资域跨账本投资汇总（CrossBookInvestmentSummary）、参考数据与设置域账本（Book）

## 背景

ADR-0089 确立「一库 = 一本账」并明确「不跨本汇总」——净资产、预算、财务自由度与报表只有本内口径。实际使用中用户按人分本（如本人与配偶各一本），希望在不选择任何账本时看到投资合起来有多少；「分账本」与「合起来看」并存是真实需求，与 ADR-0089 的「不跨本汇总」形成需要显式裁决的张力。

## 决策

1. **汇总只覆盖投资域口径**：持仓市值、持仓收益（未实现盈亏）、累计收益、可投资资产。收支、预算、净资产、财务自由度维持本内口径不变——它们跨本相加的语义未经裁决（两个人各记各的账，合并月度开销的价值存疑），且需要跨域口径一并裁决。
2. **读路径聚合，不落汇总状态、不改 schema**：汇总时同时打开各本账本的库（各自只读连接），逐本取投资口径后在内存合并。ADR-0089 的「一库 = 一本账」「schema 永不加账本维度」不动；不建预聚合副本（双写即双份真相，任一本写入失败即静默失真）。
3. **币种口径**：各账本位币一致时直接相加；不一致时按查看时**当期汇率**折算到主账本本位币，并在界面标注折算口径。**主账本＝当前活动账本**（2026-09-14 补定义，见修订记录）：折算目标取活动账本的本位币，当期汇率同源取活动账本的当期汇率表（`exchange_rates`），与活动账本一切既有本内折算同一口径，不另立「主账本」登记概念。历史汇率只属投资域明细（走势曲线 PortfolioValueTrend），不进汇总数字。
4. **汇总视图只读**：不提供任何编辑入口，一切写入回到单账本语境；下钻到单账本的方式（是否合并为「切换活动账本 + 定位」）留后续议题。
5. **加密账本计入以进程内已解锁为界（2026-09-14 修订，原文存照见修订记录）**：汇总语境下「已解锁」＝当前活动账本——活动加密本已随解锁进进程，正常计入；**非活动加密本恒不计入**（进程内没有逐本解锁能力，且读连接的口令协议禁止在解锁窗外读钥匙串，ADR-0117 决策 2），在汇总中显式标注「未解锁、未计入」，不静默少算、不阻塞其他账本出数。同族边界一并显式：只登记未建库的本标注「尚未初始化」、schema 版本与活动本不一致的本标注「版本不一致」、只读打开失败的本标注「读取失败」——四类排除全部逐本可见，「不计入」与「算不出」的原因不混装。
6. **入口＝独立汇总路由 + 账本切换弹层置顶入口项（2026-09-14 补充，见修订记录）**：汇总是独立只读路由，本内页面与口径零改动；入口为账本切换弹层顶部的「全部账本（投资汇总）」项——不动活动指针、不触发原位重引导，语境切换发生在「选哪本」的既有心智处；注册表损坏回退（清单不可信）时入口不可用。

## 理由

- 用户诉求是「两个人的投资合起来多少」，投资是唯一明确要跨本比的口径；先窄后宽的收益比一次性做全域汇总大得多，也避免把一个展示需求升级成全域架构改造。
- 读路径聚合零新增持久状态——与 ADR-0067 的读探针同款口味：能实时聚合就不落库，不引入第二份真相。
- 折算取当期汇率：汇总回答「现在总共多少」，当期汇率是对的；历史汇率是时间序列语义，属于走势曲线。

## 替代方案（防重提）

- **合并为单一账本**：推翻 ADR-0089 的分本动机（独立数据宇宙、各自加密口令），并让「两个人的账互不可见」这一既有能力消失。否决。
- **建跨本预聚合副本（定时或写时维护）**：引入第二份真相，任一本写入失败即静默失真，加密本的副本还需再解决密钥问题。否决。
- **连收支与净资产一起汇总**：跨域口径（预算、净资产三腿、账户可见性、财务自由度分母）都要一并裁决，收益远大于成本且与用户诉求不符。否决（留后续议题）。
- **汇总页另立一套「汇总本位币」设置**：多一个跨本共享设置与一条折算规则，却不回答任何新问题。否决（取主账本本位币）。

## 代价

1. 汇总成本随账本数线性增长（每本一个连接、一次投资口径查询）；账本数量在本产品场景下有限，可接受。
2. 密文库必须逐本解锁才计入——汇总页在未解锁时给出的是**部分合计**，界面「未计入」标注因此是硬要求，不能只靠数字表达。
3. 汇总数与单本数之间存在「当期汇率折算」这一层：跨币种账本下两者不满足简单相加，文档与文案必须显式说明，否则会被当成计算错误。

## 后果

- 新增跨本读路径与汇总投影；账本注册表（引导层）成为汇总的账本清单来源。
- 界面新增跨账本汇总语境（独立只读路由，经账本切换弹层入口项进入，决策 6）；所有既有本内入口与行为不变。
- 相关词汇表条目：投资域跨账本投资汇总（CrossBookInvestmentSummary）；参考数据与设置域账本（Book）的「不跨本汇总」边界需显式指向本 ADR 的例外范围。

## 修订记录

- 2026-09-14 实施前裁决落档（issue #1196 实施票；三处裁决由实施前核查提出、owner 定案「按推荐」）：①**主账本＝当前活动账本**（决策 3 就地补定义）——活动账本的本位币是用户此刻全应用各本内视图的折算基准，汇总数字与既有视图同口径；「登记序首本」是历史产物归属的兼容概念（ADR-0089），对用户不可见，不作折算目标。②**决策 5 改写**（原文存照：「加密账本必须已解锁才计入：未解锁的账本在汇总中显式标注『未解锁、未计入』，不静默少算、不阻塞其他账本出数」）——实施前核查证实注册表恒有活动指针、「未选择任何账本」的进程态不存在，且进程内没有逐本解锁能力；ADR-0117（读路径独立只读连接）落地后「未解锁＝无口令可用＝不建真实读连接」成为机制事实，非活动加密本恒不计入是该事实的诚实表述而非暂态缺位；逐本解锁流程属新增能力，如要做另票裁决。③**入口形态**（新增决策 6）——候选含切换弹层加项、投资页范围选择器、独立路由三案，定案为独立汇总路由 + 切换弹层置顶入口项的组合：独立路由保本内口径零改动，入口项落在「选哪本」的既有心智处且不占侧栏导航位。④**逐本状态显式标注**（决策 5 同段）——未初始化 / 版本不一致 / 读取失败三类排除与「未解锁」同款逐本可见；版本判据＝非活动本 `user_version` 与活动本比对（活动本建连必经迁移，其版本即当前应用 schema 版本），不一致即排除，不读旧库猜查询。
