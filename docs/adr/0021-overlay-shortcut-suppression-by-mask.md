# ADR 0021: 快捷键弹层抑制嗅探「仅打开时存在」的遮罩，而非弹层容器存在性

- 状态：已接受
- 日期：2026-08-27
- 作者：Ledger 项目

## 背景

视图快捷键（Cmd/Ctrl+1..9，见 ViewShortcut）与记一笔快捷键（裸键 a/z/i/b/s，见 CreateShortcut）共用同一个弹层抑制判定 `hasOpenOverlay()`：命中快捷键后先探测弹层是否打开，打开则不触发。原实现以 DOM 存在性嗅探 `.n-modal-container`、`.n-dialog` 等容器类名为信号。

上线路后出现「只要关闭过一次弹窗，Cmd+1..9 与裸键快捷键就永久失效」的 bug。根因在 Naive UI 的实现方式：NModal 经 `VLazyTeleport` 挂载，其内部用 `useFalseUntilTruthy(show)` —— **容器首次显示后就永久留在 DOM**，关闭后只剩隐藏空壳（`display-directive="if"` 也一样，`if` 只控制内容卸载，容器本体不卸载）；useDialog 确认框复用同一结构。于是「容器存在」≠「弹层打开」，存在性嗅探在第一次关闭后就永远返回 true。

## 决策

**模态类弹层（弹窗 / useDialog 确认框）改嗅探 `.n-modal-mask` 遮罩**：遮罩随 `show` 真实挂载/卸载（v-if），「遮罩存在 ⟺ 弹层打开」严格成立；气泡确认、下拉菜单、筛选下拉维持不变（它们基于 Follower + v-if，关闭即卸载，存在性本就可靠）；日历面板 `.n-date-panel` 系无遮罩弹层，且面板内按钮聚焦时不在可编辑目标，一并纳入信号集。同时把 `.n-modal-container`、`.n-dialog` 从信号集中剔除，并在代码注释与 CONTEXT.md（Overlay Suppression 词条）中写明不可用的原因。

候选方案对比：

| 方案 | 结论 |
| --- | --- |
| A. 容器存在性 + 可见性检查（display:none / getClientRects） | 否——Naive UI 关闭后残留的 body-wrapper 空壳在 `display-directive="if"` 下自身可见（仅内容隐藏），可见性启发式对容器信号无效，且 jsdom 不可测 |
| **B. 嗅探仅打开时存在的遮罩（采纳）** | 见下 |
| C. 反应式弹层注册表（全局计数，各弹层开关时注册/注销） | 否——语义最正但需改动全部弹层/下拉/选择使用点，成本高且新弹层容易漏注册 |

## 理由

- **信号与语义严格对齐**：遮罩就是「模态打开」的视觉本体，存在性即状态，不依赖任何启发式；而容器存在性在 Naive UI 的懒传送门语义下天然不可靠。
- **单点修复、零使用点改动**：两个快捷键消费同一个 `hasOpenOverlay()`，改一处即全部恢复；未来新增快捷键只要继续走这一判定就天然免疫。
- **jsdom 可测**：回归测试直接模拟「残留空壳 + 隐藏内容」的 DOM 形态断言不再抑制，无需等待过渡动画。
- **代价可接受**：`show-mask=false` 的模态（本应用不存在，也约定不用）会脱离抑制；弹层关闭淡出动画期间（约 150ms）仍视为打开，属预期行为而非缺陷。

## 代价与边界

- 依赖 Naive UI 的遮罩类名（`.n-modal-mask`）：升级若改类名，抑制会静默失效（快捷键在弹层打开时也能触发）。接受——这比反向失效（永久禁用）温和得多，且类名是 Naive UI 稳定的公开 DOM 契约。
- 抽屉（NDrawer）如未来引入，需自行加入信号集（抽屉容器同样是懒传送门残留结构，不能直接用容器存在性）。
