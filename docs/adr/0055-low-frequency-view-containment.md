# ADR-0055: 低频视图收纳策略——侧栏「更多」固定项 + 开发者清单 + 页签聚合

- 状态：已接受
- 日期：2026-09-01
- 作者：Ledger 项目
- 关联：spec #370 / issue #373（本文档票）；实现 issue #371（「更多」聚合页与保单路由迁移）/ #372（侧栏重组与键位收紧）；演进 ADR-0051 决策 8（保单放置与键位上限诚实化）；迁移先例 issue #202（旧订阅路由重定向）；弹层抑制 ADR-0035；词汇表：界面状态与交互域「侧栏分组」「ViewShortcut」「ViewState」

## 背景

侧边栏是应用内导航的唯一一级入口，此前没有「低频功能往哪放」的常设机制——每个新功能默认挤占一个顶级侧栏位，导航条目随功能线性增长，稀释高频项的位置记忆。保单视图（ADR-0051）是第一个真实案例：使用频率低（不在日常记账动线上），却占据一个顶级侧栏位与一个数字键位（⌘8）。

键位侧同时暴露既有 wart：数字键物理上限 0–9，可排区（组内可排序视图，见「侧栏分组」）九项 > 键位带 2–9 八格，洞察组末位视图（出厂序为搜索）永远无键位——「有视图无键位」的死角与「位置即键位」的哲学相悖。

更根本的问题是：没有裁决机制，未来每个低频功能都会重演一遍「占一个侧栏位还是另想办法」的临时裁量。本文立常设机制，保单为首个被收纳视图；词汇表三词条修订（「侧栏分组」「ViewShortcut」「ViewState」）随本文同票落地。

## 决策

### 1. 全局单一收容器：侧栏「更多」固定项 + 页签聚合页

- 侧栏新增固定项「更多」（en-US "More"），为**第四个固定项**（与概览/AI/设置同类）：位置在「洞察」组之后、AI 之前；不参与组内右键排序、不占数字键位、不出键位提示。侧栏共 12 项：可排区八项分记账/资产/洞察三组，外加概览、更多、AI、设置四个固定项——自此**结构封闭**：未来低频功能一律成为「更多」的新页签，侧栏条目数不再随功能增长。
- 点进「更多」是**页签式聚合页**（容器形态先例：定时页三页签），低频视图组件整体作为页签装载，容器零业务逻辑——被收纳视图功能零损失（保单的列表、建档、软删、保单视角统计原样保留）。

### 2. 判定机制 = 开发者清单（显式、可查、不配置、不统计）

- 「什么算低频、什么进更多」由**开发者清单**显式判定，随决策记录于本 ADR（追加成员 = 修订本文），不做用户配置、不做使用频率统计（本地单机无遥测）。
- 判定参考（语义标准，非量化门槛）：不在日常记账动线上、使用频率显著低于记账主循环、移出侧栏后仍应两步内可达。
- **清单成员：保单**（首个，随本决策迁入）、**商户**（issue #444 迁入：商户管理高频自动增长但属低频维护动作，原为设置页 Tab，迁入后设置页移除该 Tab、管理入口全应用唯一）。物品、预算留原位——收纳机制留待第二次真实使用验证，不为迁移而迁移。

### 3. 键位收紧：十键十视图全占

- 保单迁出后可排区九→八（交易…报表），线性键位推导规则不变：概览 ⌘1、可排区八项按组内序 ⌘2–⌘9、AI ⌘0、设置 ⌘,。组内排序机制照旧，键位与提示随组内序实时同步。
- 「可排区末位无键位」的 wart 随之消除：0–9 十键对十个有键视图**恰好全占**，无死角、无空转位（搜索获 ⌘9）。
- 「更多」不占也不耗任何数字键位——固定项无键位语义与概览/AI/设置一致，十键十视图的键位心智不被杂项破坏。

### 4. 存量无感迁移与页签路由态

- 旧保单路由**保留 name + 重定向**到「更多」页并携带页签参数（迁移先例：issue #202 旧订阅路由并入定时页）——「上次视图停在保单」的升级用户经既有启动恢复逻辑自动落到「更多·保单」，所有恢复路径不产生未知视图。
- 页签状态收敛在路由单字段上：页内切换即更新地址（可深链、刷新不丢，切页签 replace 写回——定时页既有约定），无/非法页签参数回退默认页签。
- **页签不跨启动持久化**：路由监听持久化的视图名恒为「更多」，重启回到「更多」页默认页签——属 ViewState「不做过度记忆」既有边界的自然延伸，收纳零新增持久化。

### 5. 反域命名：收纳器不承诺域归属

- 收容器命名「更多」，刻意**不用域名**（如「保险」）：收纳器成员跨域变动（今天收保单、明天可能是任何域的低频视图），域名会随第一个异域成员入场即刻失义；「低频」则是机制描述而非用户语言。
- 代价是查找语义间接：用户找保单需知其在「更多」内。缓解：保单是当前唯一页签（两步内必达）；「更多」作为杂项聚合入口在桌面软件惯例中已被广泛训练。

## 备选方案与否决理由

- **挂投资页页签**：保单不是投资持仓——保单是合同档案，与投资域的持仓/盈亏口径无涉（ADR-0051 决策 8 已明确「独立视图、不挂靠其他视图作页签」）；且把低频入口绑死在一个具体高频视图上，第二个低频视图仍无去处，机制问题没解决只是挪位。
- **每组各配收容器**（每组一个「更多」）：机制碎片化——用户要记住多个杂项入口的位置，侧栏总条目数仍随组内增长，封闭性是假的；单一收容点的全部价值就在「只记一个位置」。
- **侧栏子菜单**（组内悬浮二级菜单）：仍是每视图一个侧栏位，侧栏照样被撑开；交互上加深悬停/展开层级与误触成本，折叠态需引入特例，子菜单项的键位无从安放——封闭性、键位、折叠一致三个问题一个都没答。
- **扩键位池 / 命令面板兜底**（⌘⇧数字、⌘K）：只治键位不治侧栏增长，组合键与系统快捷键冲突面大（记一笔快捷键先例已否决组合键双轨）；命令面板留 ADR-0051 缓行清单不动。
- **数据驱动 / 用户配置收纳**：本地单机无遥测，使用频率无从统计；配置面是把机制成本转嫁给每个用户——默认结构应当即最优，个性化已由组内排序承载。

## 后果

- **直达性换简洁**：被收纳视图从一步变两步（点「更多」→ 选页签）、失去独立键位。对低频视图是划算的交易：高频项位置记忆不再被稀释，低频不等于不可达。
- **反域命名的取舍**：收纳器语义稳定（成员跨域变动不更名），代价是查找语义间接（见决策 5）。
- **对 ADR-0051 决策 8 的演进关系（演进而非否定）**：彼时解决「新视图按域归位」——保单按域职责入「资产」组（投资 = 金融资产、物品 = 实物资产、保单 = 合同权益），并键位诚实化预留「末位无键位」；本轮解决「低频视图的去处」——收纳优先于域相邻，保单迁出、资产组保留高频部分（投资/物品）、键位 wart 顺势消除。域归位原则对高频新视图依然成立；词汇表历史注记保留不删、标注演进。
- **未来低频视图的默认落点 = 「更多」新页签**：开发者引入低频功能时不再做「占侧栏位」的临时裁量，按决策 2 清单机制修订本 ADR 即完成裁决。
- 词汇表修订随本决策落地（界面状态与交互域）：「侧栏分组」（资产组二项化 + 第四固定项 + 演进注记）、「ViewShortcut」（十键十视图全占，「可排区末位无键位」表述作废）、「ViewState」（页签不跨启动持久化的表述复核，无新增持久化）。
- 弹层抑制零新机制：「更多」页内弹层继续经既有弹层封装与注册表驱动抑制（ADR-0035），页签切换不触碰抑制语义。
- 无后端改动：纯前端导航与信息架构，schema / API / 命令 / 数据模型零变化，不触及发布约定。
