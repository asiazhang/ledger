# ADR 0147: 原生壳视觉系统——主题令牌主权、视觉唯一真源与壳内 ui 层双轨

- 状态：已接受（决策入档；实现随落地票系列）
- 日期：2026-11-11
- 作者：Ledger 项目
- 关联：ADR-0145（原生壳——本决策的承载体）、ADR-0118（ui-kit `App*` 封装族——封装纪律在原生壳延续，壳内 ui 层的雏形）、ADR-0093（样式方案与 Design Tokens——Web 参照前端语境，不推翻其参照形态存续）、#2053（外观设置——设备级亮暗开关，与出厂主题基线分层）；词汇表：应用壳域「主题令牌」「视觉规约」「壳内 ui 层」（随本 ADR 入档）
- 来源：grill-with-docs 会话裁决（2026-11-11，四病灶全认）；对照研究 `docs/research/spotish-ui-design-study.md`（对照物 huacnlee/spotish @ a7a4253 ＋ NSH 官方设计指南）

## 背景

原生壳切轨后（ADR-0145），壳内视觉常量处于无单一来源状态，四个用户体感病灶经会话逐项确认（量化证据见对照研究 §1）：

1. **字号无层级**：壳根包 `text_size(px(…))` 裸调 643 处、13 种取值并存（12px×288、13px×236、11px×67 承担 92% 正文），散布全部 68 个顶层模块，无字阶。
2. **颜色无主权**：壳内无 `nsh.json`，主题整体落在 NSH 出厂默认 shadcn `neutral`（黑白灰 + 10pt 圆角）；431 处 `app_class` 令牌类全部指向出厂 palette；业务/UI 语义色（走势主色、警告色等）以常量散落模块内。
3. **控件尺寸不齐**：按钮/输入框/菜单内边距与高度各视图直写，无控件规格。
4. **间距/圆角随意**：无间距尺度与圆角阶，无同心约束。

NSH 官方设计指南本身强制同一纪律：app 自有 ui 层、视图禁裸样式、禁裸 hex 与 palette 类、规范数值体系（字阶 ≈12/14/16/18/20、间距 2/4/8/12/16/24/32、桌面控件高 24–32pt、同心圆角「内 ≈ max(0, 外 − 缝)」）。spotish 以「主题令牌表 + 视觉规约文档 + 组件封装单点」三件套在真实应用落地该纪律，且三件全部模式无关。

## 决策

### 1. 主题主权：引入 nsh.json + 主题令牌表

壳内引入 `nsh.json`，其 `"theme"` 指向主题令牌表（NSH 主题文件，shadcn `cssVars` 格式，亮暗双态齐全，覆盖式只写差异）。令牌闭集 = shadcn 标准 UI 语义名（background/primary/muted/destructive 等）+ 本仓自有令牌——散落模块的 UI/业务语义色（走势主色、危险/警告、盈亏涨跌、图表系列色）收编进表，Rust 侧 `theme().color(…)`、类侧 `bg-…` 消费。分层：主题令牌表答「出厂观感是什么」，参考设置域外观设置（#2053）答「这台设备用亮还是暗」——出厂基线与设备级开关正交，两层互不取代。

### 2. 视觉唯一真源：docs/DESIGN.md

建立 `docs/DESIGN.md` 作本仓视觉唯一真源，叠于 NSH 官方设计指南之上（指南管「无论长什么样必须为真的事」，本规约管「本仓长什么样」，相左时本规约赢）。骨架：原则 → 色彩 → 字阶 → 形状与间距 → 表面与层级 → 组件规格。纪律：视图零裸值——颜色走令牌、字号走字阶、圆角间距走尺度；例外（图表数据色、密集表格行高等）必须在规约中挂账。

### 3. 尺寸单一来源双轨

蓝图按官方正典：壳内 ui 层——一文件一件、variant + size 有限 API、样式内聚件内，视图只组合封装件与设计常量、不裸写视觉值。落地分两步：先立设计常量模块（字阶/间距/圆角唯一来源）止血存量散写；既有选择类封装族（ADR-0118 的 NSH 后继）即本层雏形，视图随触碰渐进收口，不一次性重排全部视图模块。

### 4. 数值标定采用官方规范值

字阶 ≈12/14/16/18/20pt、间距 2/4/8/12/16/24/32pt、圆角阶 8/12/16 + inset（同心规则「内 ≈ max(0, 外 − 缝)」）、桌面控件高 24–32pt（默认 32）、行 28–36pt。不发明第二套数；表格行高等密集数据例外落地时按密度微调并在规约挂账。

### 5. Omarchy 系统主题派生跟随：否决

spotish 的系统主题派生跟随（信 4 个系统色 + 对比度校验派生全表）列为可选后续另票，本决策不采纳：主题主权先行，派生算法与对比度校验工程量成套。

## 理由

- 四病灶是同一结构性根因（视觉常量无单一来源）的四个切面；逐处手改无法收敛，必须先立来源再改值。
- 出厂默认 neutral 是「未选择」而非「选择了朴素」；主题文件机制原生支持亮暗双态、自定义令牌与构建期校验，拿回主权零框架阻力。
- 双轨的理由：壳视图已平铺成型（切轨重写刚完成），一次性建全 ui 层等于第二场重写；官方指南对既有应用的原话即「先检查并扩展既有地基」。
- 数值照抄官方规范的理由：账本正是指南定义的 information work 密集应用，该数值体系为其而调；自创数值需重验对比度与层级论据，无收益。

## 否决方案

- **保持 neutral 默认 + 仅立用法规约**：不解决颜色无主权，规约无值可循。
- **一次性建全 ui 层再动视图**：第二场重写、冻结功能迭代，与决策 3 互斥。
- **Omarchy 派生跟随（本次内做）**：见决策 5。
