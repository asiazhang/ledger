# ADR 0039: AI 基金导入——fund-lookup 只读端点与创建端点基金增强

- 状态：已接受
- 日期：2026-08-30
- 作者：Ledger 项目
- 关联：顺应 ADR-0037（标的搜索与幂等创建的形状，不做内联即建）；消费 ADR-0038（场外基金一等标的）；词汇表：AI 导入域 AI API / 投资域 Instrument

## 背景

场外基金一等标的（ADR-0038）落地后，AI 迁移基金申赎账单的标的引用有了新解法空间：基金账单必带 6 位代码，且后端具备按代码查询东方财富的能力。本轮设计曾提议商户式内联即建（batch 输入带代码+类型、后端命中复用/未命中即建），但与 ADR-0037 同日定稿的形状直接冲突——该决策已明确否决内联（标的维度多于商户名、TransactionInput 引用互斥与行为层编排机制面大、孤儿行残留）。经再裁决：顺应 ADR-0037，以内联否决为前提做基金增量。

## 决策

1. **batch 输入保持只收 `instrument_id`，不加自然键**——ADR-0037 的独立端点形状对基金同样成立，不出现第二种标的引用形状。
2. **新增只读基金查询端点（按 6 位代码查询）**：从东方财富（FundSearchAPI / lsjz）返回名称、基金类型、最新单位净值与净值日期；供 AI 主动校验「代码 → 名称」映射与查净值。代码无效返回中文错误，AI 可提示用户或跳过该行。
3. **创建端点对 type=fund 增强**：提交真实 6 位代码时后端尽力经东方财富校验并回填权威名称与最新净值（落现价缓存，按价格失效信号语义广播）；东财确认查无此码则创建失败、显式报错；东财网络不可达时降级用 AI 提供的名称 + 真实代码建行（不阻塞导入；名称误差留待人工编辑，净值通道按代码照常服务）。
4. **AI 基金导入流程三步**：按代码查询（校验/查净值）→ 创建标的（真实代码，东财增强）→ batch 提交 buy/sell（instrument_id）；每步都是既有形状的小增量。名称充代码约定仅适用于无代码来源；名称充代码的基金行无真实代码、不进净值通道。
5. **导入知识补基金申赎节**：基金账单行拆解（申购→buy、赎回→sell、申赎费→费用字段、6 位代码→标的解析三步），与商户约定并列表述。

## 理由

- 尊重同日两轮 grilling 刚定稿的 ADR-0037：推翻已有决策的举证责任在后续方，而三步流只多一次本机 HTTP 往返，AI 编排对此不敏感；查询端点本身独立有价值（校验映射、查净值日期）。
- 创建增强保证字典质量：东财可达时名称以后端取得的为准，防 AI 抄错名；「查无此码即拒绝」与「网络不可达降级建行」分开处置——查得到却不查等于自弃质量，查不到而硬拒则把临时故障放大成导入阻塞。
- 基金代码是账单必带的权威事实，真实代码建行让标的天然进入净值通道（ADR-0038），优于名称充代码的语义糊化。

## 代价

- 基金导入三步而非一步（相比内联方案）：AI 编排略长，换取全应用统一的标的引用形状。
- 创建路径引入外部 HTTP 依赖：东财不可达时基金标的名称质量降级（可用性优先）；股票类创建不受影响（无增强、不发外部请求）。
- 查询端点与标的端点并存，AI 需要教学指引区分（导入知识承担）。

## 替代方案

- 商户式内联（batch 带代码+类型、后端即建）：一步到位但推翻 ADR-0037、引入双轨引用形状，否决。
- 无创建增强（AI 报什么名称存什么）：AI 抄错名直接污染字典且基金无自动修名通道，否决。
- 东财失败一律拒绝（含网络故障）：把临时故障放大成整批导入阻塞，否决。
