# ADR-0097: 投资交易删除语义修订——sell 删除回补、buy 删除级联软删在用 sell

- 状态：已接受
- 日期：2026-09-10
- 作者：Ledger 项目
- 关系：部分修订 ADR-0013 决策 #1 的删除条（「删除路径仅 buy 走 revert，sell 删除不清理持仓关联」）与 ADR-0033 决策 #4 的删除入口守卫（「已有部分卖出的买入禁删」）；修改路径守卫与 ADR-0033 其余决策不变

## 背景

ADR-0013 锁定的删除语义是「删除只软删交易行：buy 清理持仓批次与买入明细，sell 不清理持仓关联（历史匹配与持仓扣减原样保留）」。该不对称在「部分卖出后删 sell」场景把买入永久锁死（issue #940）：

- sell 软删后其 `security_lot_sales` 匹配与持仓扣减仍在，买入批次看起来「已有部分卖出」；
- 删除守卫（按批次剩余数量判定）与修改守卫因此拒绝——但 sell 已删、无法经正常途径撤销占用，存量库中 53 笔买入陷入「既删不掉、也改不动」的死锁。

守卫谓词按「批次剩余数量」归因是把幽灵占用当真占用的根源：已删 sell 的历史匹配不该再算「在用卖出」。

## 决策

1. **删除即撤销持仓影响（删除路径与修改路径同语义）**：
   - **sell 删除回补**：删除 sell 先回补其扣减的持仓（`security_lot_sales` 逐笔数量加回批次），再清空其卖出匹配与卖出明细，最后软删交易行——不再遗留「幽灵占用」；
   - **buy 删除级联**：删除 buy 先级联回退其持仓批次的**在用** sell（逐笔回补），被级联的 sell 随之软删（各自余额刷新与 delete op），再整批清理批次与匹配；投资域返回被级联 sell id 列表，供行为层编排逐笔软删。
2. **「在用卖出占用」归因谓词**：守卫与级联对象均按 `security_lot_sales` 归因到 sell 交易行、只计未软删者（JOIN `transactions.is_deleted=0`）。修改路径的「已有部分卖出禁改」守卫沿用同一谓词——已删 sell 的历史匹配不再误伤修改；删除路径不经守卫（在用 sell 已被级联消化），「已有部分卖出的买入禁删」退场，`trade.partially-sold-delete` 错误码退役。
3. **批次清理单点火化幽灵匹配**：批次清理按 `lot_id` 归批删除全部 `security_lot_sales`——旧版本遗留的幽灵匹配（指向已软删 sell）随批次一并消失，无需数据迁移；存量死锁在用户下次正常删除/修改该买入时自愈。不做审计/修复命令（与 ADR-0033 定时引擎存量残留同款裁决：存量残留不救援，个案手动）。
4. **级联软删逐笔留痕**：被级联的 sell 各自产出 delete op（先于主行落日志），同步重放按 op 序先删 sell 再删 buy，级联与显式 op 不打架；重放端复用同一删除编排协议（`delete` 入口），无需感知级联语义。

## 理由

1. **删除的语义是「撤销这笔交易的全部影响」**。sell 的持仓影响（扣减 + 匹配）不随删除撤销，派生状态就与交易现状脱节——幽灵占用既让守卫误判（死锁根源），也让已实现盈亏读口径背上「排除已删 sell 匹配」的永久特例。删除即回补让交易行（软删）与持仓派生状态恢复一致，读口径特例收敛为仅覆盖存量幽灵行。
2. **级联优于拒绝**。拒绝删除（旧行为）把一致性责任推给用户——必须先处理卖不掉的 sell 才能删 buy，而 sell 已删时无路可走（issue #940 的死锁形状）；级联让「删买入 = 连同其卖出历史一起撤销」符合删除直觉，且同一事务内整体回滚保证不出现半套级联。
3. **在用归因消除幽灵误伤**。归因谓词从「批次剩余数量」（物证推定）改为「在用 sell 的匹配记录」（逐笔归因），已删 sell 的历史匹配不再算占用——修改守卫不再被幽灵扣减永久锁死。
4. **守卫退役是 breaking change**：依赖 `trade.partially-sold-delete` 400 语义的外部脚本需跟随更新（删除部分卖出的买入从 400 变为 204 + 级联软删）。

## 代价

1. 删除 sell 不再是纯标记：回补与清匹配使删除变为重操作——但与软删 UPDATE 同处一个事务（ADR-0033 嵌套感知），失败整体回滚，一致性由构造保证。
2. 级联是隐式行为：删除一笔 buy 可能软删多笔 sell，API 204 不返回被删列表；契约描述与变更日志已注明。
3. 存量幽灵态不做迁移救援：死锁买入在用户删除/修改该买入时自愈，从不触及则维持原状。

## 替代方案

- **sell 删除维持不回补，仅把守卫谓词改为在用归因**：删除与修改路径的守卫死锁解开（不再被幽灵误伤），但幽灵扣减永久留在持仓里——「删除后持仓凭空变少」且读口径特例永不退休。放弃。
- **删除 buy 时仅解除匹配、不级联软删 sell**：sell 变成无匹配的孤儿行（交易行在、持仓影响无），比级联更费解。放弃。
- **提供审计/修复命令清理存量幽灵态**：存量 53 笔死锁可一次性救援，但命令面只为一次性迁移存在；级联 + 在用归因已让存量态在正常使用中自愈。放弃（个案手动改库）。

## 后果

- **词汇表修订**：核心交易域「买入守卫文案按入口内化」条目改写（删除入口无守卫）；投资域 Investment 词条出口面改写（三件套 + 删除路径 `release_for_delete`）、已实现盈亏词条「sell 删除不清理匹配行」口径废止（删除即回补 + 清匹配）。
- **契约**：HTTP `DELETE /api/v1/transactions/{id}` 描述更新（级联语义，400 响应退场）；导入知识纠错条同步。
- **测试**：删除级联 / 回补 / 跨批次涟漪 / 幽灵火化 / update 守卫在用归因由域单测与 BDD 钉住。
