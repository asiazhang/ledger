# ADR-0063: 组内收纳——每组「更多」与用户移入移出

- 状态：已接受
- 日期：2026-09-03
- 作者：Ledger 项目
- 关联：取代 ADR-0055 决策 1（全局单一收容器）、决策 2 后半（不做用户配置）、决策 5（反域命名的单点依据）；继承其决策 2 前半（开发者清单，转任出厂默认判定）与决策 4（存量路由重定向先例）；其决策 3 的键位推导规则保留、「十键十视图全占」表述废止；词汇表：界面状态与交互域「组内收纳」「侧栏分组」「ViewShortcut」「ViewState」；弹层抑制 ADR-0035；容器先例 ADR-0055（页签聚合页）

## 背景

ADR-0055 以全局单一「更多」收容器解决低频视图的去处，并显式否决「每组各配收容器」，否决理由是每组条目无上限时封闭性是假的。该否决前提已被打破：本决策同时立下**每组主项至多 3 项的运行时硬上限**，每组结构恒为「至多 3 主项 + 1 个更多链接」，侧栏总条目数有界——单一收容器「只记一个位置」的核心理由不复存在。

其次，「更多」成员天然分属不同域（保单之于资产、商户之于记账），全局收容器的反域命名让查找语义只能靠软件惯例训练（ADR-0055 决策 5 自认的代价）；收纳单位回到分组后，域归位原则重新接管收纳成员的分组归属。

第三，ADR-0055 决策 2 否决用户配置收纳，理由是「默认结构应当即最优、配置面是把机制成本转嫁给用户」。本决策保留这一内核——开发者清单继续裁定**出厂默认**——在其上增设用户个性化层（右键移入/移出），默认最优与个性调整不再互斥（先例：组内排序之于默认序）。

## 决策

### 1. 收纳单位 = 侧栏分组：每组一个「更多」链接 + 组内聚合页

- 侧栏三个分组（记账/资产/洞察）各拥有一个「更多」入口，渲染在**组标题行右侧**（菜单组件的分组标题天然不可交互，链接是自定义渲染的新界面元素）；点击进入该组的页签式聚合页（容器形态沿用 ADR-0055 页签容器：被收视图整体装载、容器零业务逻辑、功能零损失）。
- 链接**仅当组内存在收纳成员时渲染**：洞察组出厂无收纳成员故无链接；其路由预建，用户把首个视图移入后链接即现、路由即用。
- 全局「更多」固定项移除。侧栏结构 = 概览 + 三组（各自主项 + 按需「更多」链接）+ AI + 设置。

### 2. ≤3 是硬上限，且上限就是键位带的封闭性

- 每组主项至多 3 项，是**运行时不变量**而非出厂布局建议：组满 3 项时「移回侧栏」被阻止（菜单项置灰 + 提示），不提供自动换出、不弹窗强制腾位。
- 上限的体系意义：3 组 × 3 主项 = 9 = ⌘2–⌘9 恰好铺满——**键位带永不溢出由上限保证**。上限不是任意的体验裁剪，是键位封闭性本体；这也是对「每组收容器」被否决理由的正面回答。
- 键位保持线性推导（位置即键位，规则不变）：主项按组序与组内序连续取 ⌘2 起；收纳成员与「更多」链接无键位。**代价如实记录**：出厂态主项 7 项，⌘2–⌘8 占用、⌘9 空置——ADR-0055「十键十视图全占、无空转位」的表述自此不再恒真；用户把三组填满后 ⌘9 自然回填。移入/移出使主项集变化时，其后主项键位重编号。

### 3. 出厂默认 = 开发者清单（ADR-0055 决策 2 机制转任）

- 开发者清单继续显式判定收纳成员（追加成员 = 修订本 ADR），裁定对象从「全局更多成员」变为**各组出厂收纳状态**：
  - **记账**：主项 = 交易、账户、预算；收纳 = 定时、商户（满员）。
  - **资产**：主项 = 投资、物品；收纳 = 保单。
  - **洞察**：主项 = 报表、搜索；收纳 = 无。
- 由此产生**移回不对称**的直接后果：记账组出厂满员，定时与商户在不动现有主项的前提下无法移回——想移回须先右键移出一个主项腾位。这是上限规则的诚实代价，不做特例豁免。

### 4. 用户移入移出：右键菜单，移入自由、移回受限

- **移入**：任一主项右键 → 「移入更多」，追加到本组收纳清单尾。规则无例外清单（交易亦可移入；误移有「两步内可达」兜底且可自行移回）；固定项（概览/AI/设置）与「更多」链接本身不可收纳。
- **移回**：组「更多」页内右键页签 → 「移回侧栏」，落本组主项**末位**（可再右键排序微调）；组满时菜单项**置灰 + 提示**（上限可见、可学习），不隐藏菜单项。
- **不跨组**：收纳只在组内进行，词汇表分域的归位原则（保单→资产、商户→记账）不因用户配置而打破。
- **恢复默认排序**扩展为同时复位组内序与收纳清单——一键回到出厂布局的唯一通道。

### 5. 持久化与路由

- 每组一个**有序收纳清单**，入 ViewState 跨启动持久化（与组内序存储同族同机制，界面状态不进 SQLite）：页签序 = 清单序，移入追加、移回删除——单一清单同时承载成员资格与顺序，不另设布尔标志。
- 路由镜像侧栏层级：`/bookkeeping/more`、`/assets/more`、`/insights/more`（预建）；页签参数走 query（切页签 replace 写回，定时页既有约定）；页签不跨启动持久化（ViewState「上次视图只存视图名」粒度不变，重启回该组默认页签）。
- 存量迁移链：`/more` → 记账·更多；`/more?tab=merchants` → 记账·更多商户页签；`/more?tab=policies` 与更早的 `/policies` → 资产·更多保单页签；老用户 ViewState 持久化的 `'more'` 视图名在启动恢复时映射到记账·更多（不回退概览）。

### 6. 折叠态不渲染

侧栏折叠态不显示「更多」链接（折叠态本就不渲染组标题）。收纳视图低频，展开即达；不为折叠态引入图标特例。

## 备选方案与否决理由

- **维持全局单一「更多」**（ADR-0055 现状）：单点记忆价值真实，但成员跨域混装的查找代价随成员增长放大；≤3 上限落地后其封闭性论据不复存在。
- **键位跟随视图**（移入更多不丢键位）：肌肉记忆零成本，但「位置即键位」破例、键位提示跳号、移回时的键位归属规则复杂化——弃。
- **组满自动换出 / 禁止移出特定主项**：前者把裁决推给弹窗交互，后者需要人为的「高频清单」例外面；置灰 + 提示、让用户自己换位最简单——弃。
- **空组常驻「更多」链接**：死链接，且与「有成员才渲染」的机制不一致——弃。
- **≤3 仅为出厂建议、运行时放开**：第 4 主项无键可用（或挤占 ⌘0），键位带失守，「每组收容器」封闭性存疑的老问题原样回归——弃。

## 后果

- **对 ADR-0055 是演进而非否定**：决策 1（单一收容器）、决策 2 后半（不配置）、决策 5（反域命名）被本决策取代；决策 2 前半（开发者清单）转任出厂默认判定；决策 3 键位线性推导规则保留、「十键全占」表述废止（出厂 ⌘9 空置）；决策 4 迁移先例延伸为迁移链。「更多」名称保留——组标题提供域语境，反域命名的单点理由消失。
- **分四票落地（#472–#475），中间态以票为准**：本决策记录终态——#472 落数据基座与资产组（全局「更多」暂留、仅剩商户页签，记账组仍四主项）；#473 记账/洞察接入并退役全局「更多」、键位改只扫主项；#474 右键移入；#475 右键移回与组满置灰。中间态代码与终态决策的差异（如过渡期可排区八项、⌘2–⌘9 全占）是分期实施的既定事实，不构成决策冲突。实物资产（#466，ADR-0064）诞生于全局收容器尚存的中间态，入口随域归位资产组「更多」，与保单同为出厂清单成员。
- **移入自由、移回受限的不对称**是上限规则的内洽结果，非疏漏；出厂满员的记账组存在「须先腾位」的移回门槛。
- **键位重编号**：每次移入/移出改变主项集，其后主项键位随线性规则重排；⌘9 在出厂态空置。
- **弹层抑制零新机制**：移入/移出右键菜单沿用既有菜单封装与注册表上报（ADR-0035）；页签切换不触碰抑制语义。
- **纯前端导航与信息架构**：schema / API / 命令 / 数据模型零变化，不触及发布约定；后端零改动。
- **词汇表修订随本决策落地**（界面状态与交互域）：新增「组内收纳」，改写「侧栏分组」「ViewShortcut」「ViewState」。
