# ADR 0022: 设置页 Tab 按领域分域收敛（6 → 4）

- 状态：已接受
- 日期：2026-08-28
- 作者：Ledger 项目

## 背景

设置页曾按功能陆续追加为 6 个 Tab：分类、币种、备份与恢复、外观、关于、存储位置。随功能增长暴露出三个问题：

1. **同域能力被拆散**：备份与存储位置都是"数据文件管理"，却分居两处；危险操作的确认语义（接管确认、回退告警、"下次启动生效"）散落在不同 Tab，用户难以建立"动数据来这一个地方"的心智。
2. **设备偏好与参考数据混装**：「币种」Tab 同时承载默认币种下拉（前端独享的设备偏好，localStorage）与支持币种表格（后端参考数据的只读展示），两类东西的变更来源、失效机制（`ledger:changed` vs 本地即时生效）完全不同。
3. **顺序无惯例**：「关于」被夹在外观与存储位置之间，新 Tab 无既定插入位置。

## 决策

**Tab 按领域归属收敛为 4 个，最终格局固定为：通用 → 分类与币种 → 数据 → 关于。**

| Tab | 领域 | 承载内容 |
| --- | --- | --- |
| 通用 | 轻量设备偏好 | 深色模式开关、默认币种下拉 |
| 分类与币种 | 参考数据维护 | 分类管理器、支持币种表格 |
| 数据 | 数据文件管理（危险操作集中） | 备份与恢复、数据存储位置 |
| 关于 | 元信息 | 版本、日志入口等（恒在末位） |

分域细则（与参考数据与设置域词汇表 CONTEXT-reference-settings.md「轻量设置项」条目互为表里）：

- **轻量只决定可否合并，归属领域决定合到哪**：一个设置项若是轻量设备偏好（仅前端消费、localStorage 持久化、无后端命令参与，判定标准见参考数据与设置域词汇表 CONTEXT-reference-settings.md），才有资格进「通用」；它最终放哪由其领域归属决定——默认币种是设备偏好进「通用」，备份目录同样是设备偏好却归属数据文件管理，留在「数据」Tab 的备份卡片内。
- **币种 Tab 一拆为二**：默认币种（设备偏好）迁入「通用」，支持币种表格（参考数据）迁入「分类与币种」；两者行为不变，仅归属变化。
- **危险操作集中且语义不变**：「数据」Tab 同时承载备份与存储位置，接管确认、回退告警、待重启提示等异常态交互一律原样保留，不得因合并而弱化。
- **缓存语义不回退**：原备份 pane 的 `display-directive="show"`（内容保持挂载、备份列表在 Tab 切换间不重拉）由「数据」pane 以 `display-directive="show:lazy"` 继承——首次激活挂载、此后常驻，缓存语义等价且避免设置页一挂载就触发全部数据加载。
- **「关于」末位惯例**：「关于」恒在末位；未来新增设置 Tab 一律插在「关于」之前，先按上述规则判断领域归属——能并入既有 Tab 的不新开 Tab。

## 理由

- **按"变更来源与消费方"分域**，而非按控件类型：通用 Tab 内全部是即时生效的本地偏好；分类与币种是走 `ledger:changed` 失效机制的参考数据；数据 Tab 的每个操作都触碰文件系统。用户与开发者都能从 Tab 名直接推断操作的后果等级。
- **危险操作集中**降低误触面，也便于未来统一加二次确认等防护。
- **`show:lazy` 而非 `show`**：原 `show` 让设置页挂载即渲染全部 pane（含存储位置探测、备份列表 IO）；`show:lazy` 首次进入才挂载，切换后常驻，缓存不回退的同时首屏更轻。

## 代价与边界

- 新增设置项时必须先做"轻量判定 + 领域归属"两问，不能随手开新 Tab；判据在参考数据与设置域词汇表（CONTEXT-reference-settings.md）「轻量设置项」条目，违反时以本 ADR 为准回绝。
- 「分类与币种」内 CategoryManager 与币种表格纵向并列，参考数据量增大后如需再分层（折叠/子页）属后续演进，不在本决策内。
