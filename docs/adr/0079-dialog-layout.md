# ADR-0079: 对话框排版规范——卡片外观统一收口 AppModal

- 状态：已接受（已随 spec #630 实施票 #631–#640 全量落地）
- 日期：2026-09-06
- 作者：Ledger 项目
- 关联：spec #630（父 spec，grilling 定稿）、实施票 #631–#640；ADR-0035（弹层注册表，正交）、ADR-0072（ModalIntent 开合编排，正交）、ADR-0058（字段错误态，错误红同域）
- 编号注：issue #641 立项时本决策按当时的下一空闲号写作「ADR-0078」；立项后 0078（危险操作确认应用内分级）先行落地占用，按编号唯一顺延为 0079，内容与语义不变

## 背景

全仓对话框已由统一弹窗薄封装 AppModal 收口「弹层之外」的行为——遮罩不关、✕/ESC 关（弹层关闭语义）与快捷键抑制（Overlay Suppression，ADR-0035）。但卡片内部的排版长年各自为政，用户在不同功能的弹窗间切换时风格拼凑（spec #630 盘点定稿）：

- **卡片边框**：多数卡片弹窗显式声明无边框，但仍有约七处未声明，渲染出组件库默认边框（物品编辑/处置/详情、实物资产建档/估值/处置、保单表单）。
- **宽度**：从 380 到 560 共七档 magic number（380/400/420/440/460/480/560）散落在各调用点的 style 里，同一功能家族内部也不同（实物资产 460/420/420、物品 440/400/480），无匹配规则。
- **按钮行**：三种编排并存——「表单内右对齐 取消+主操作」（主流）、`#footer` 插槽（预算编辑）、单颗全宽 block 主键无取消（商户/分类编辑）。
- **辅助说明文案**：三种呈现——段落式弱化文本 + 错误行（投资/恢复弹窗）、空标签的畸形表单项行（实物资产处置）、内联透明度小字挤在表单项旁（实物资产估值、保单）。

排版不一致的根源是「视觉规范没有归宿」：宽度、边框与按钮编排逐调用点各自声明，规范只能靠模仿维持，新弹窗每开一个都要重新考古「别家怎么写」。经 grilling 定稿：把排版规范收口进 AppModal 深模块，各调用点收敛为单一声明。

## 决策

1. **视觉规范收口位置 = AppModal（深模块），主题层不动**：主题覆盖层不新增弹窗默认样式，规范收在组件层，与既有「薄封装 + 深模块」取向一致（AppSelect / AppDropdown / AppModal 同型）。卡片弹窗默认无边框（`bordered` 默认 `false`），把卡片外观默认值钉在封装层而非依赖组件库上游默认；调用点仍可显式覆盖（逃逸门语义，与 `maskClosable` 的覆盖语义同型）。
2. **AppModal 新增 `cardSize` 分档（`'sm' | 'md' | 'lg'`）**：内部映射宽度 sm=420 / md=480 / lg=560（分档像素的唯一事实源是封装层常量），以卡片 style 宽度应用；`cardSize` 未声明时不获宽度（沿用调用方自身声明），存量调用点渐进收口。行为性 attrs（title / preset / display-directive / update:show）透传不变。
3. **宽度档位按内容密度归属，同族收齐到同一档**：sm=420 编辑类轻弹窗（账户编辑/调余额、预算编辑、分类编辑、商户编辑、实物资产估值/处置、物品编辑/处置、交易「加入物品」确认）；md=480 表单类（交易记账/退款/编辑、物品详情、实物资产建档、保单表单、投资弹窗族、定时计划新建+编辑、恢复确认）；lg=560 详情类（计划详情——期次表格显然需要更宽）。家族内分散归位：实物资产 460/420/420、物品 440/400/480 等收齐到单一声明。
4. **表单约定统一小尺寸 + 标签居左**：弹窗内表单统一 `size="small"` 与 `label-placement="left"`，控件密度与标签朝向跨弹窗一致；这是弹窗观感继宽度、边框之后的第三根支柱，随本规范同批统一，不留调用点自选。行距同属表单约定（issue #699 修订补入）：统一由表单项外层的 `<NSpace vertical :size="12">` 提供，按钮行同包其内共享同一节奏——`NFormItem` 默认零行距，漏包即行贴死（保单表单等四处漏网先例），调用点不得依赖默认零行距裸排表单项。
5. **按钮行统一表单内右对齐**：统一为表单内「取消 + 主操作」右对齐编排（`NSpace justify="end"`）；轻量单字段编辑（商户/分类）保留单主键、去除全宽 `block`、改右对齐；预算编辑从 `#footer` 插槽移回表单内；按钮统一默认尺寸（去除个别 `size="small"`）。
6. **辅助文案段落式**：引言/说明统一段落式弱化文本（`NText depth="3"`），错误行统一语义红（`NText type="error"`，既有先例）；废除空标签表单项行与内联透明度/边距挤占表单的排版特技。
7. **行为不变项（明确不动）**：弹层关闭语义、Overlay Suppression（ADR-0035）、`display-directive`、ModalIntent 开合编排（ADR-0072）、业务逻辑、i18n 键、数据流全部不动——本规范只管卡片内视觉排版，不涉业务与契约，回归面可控。
8. **测试以 AppModal 为主接缝 + 既有套件为回归护栏**：扩展既有 AppModal 测试覆盖 `cardSize` → 宽度三档映射与未显式传 `bordered` 时的默认无边框（只测外部可观察行为，不深究组件库内部实现）；不新增 BDD / HTTP API 集成测试（无业务语义、无契约变化，宽度/边框等视觉值不宜断言到后端 BDD）；全部既有前端套件与 vue-tsc 原样通过即等价性护栏。

## 理由

- **为什么收口进组件层而不是主题层**：宽度与边框是「每个弹窗的声明」，主题层管不了逐调用点差异；收在 AppModal 后，新弹窗一个 `cardSize` 声明即长对，规范有唯一归宿，不再靠模仿维持。
- **为什么分档而不是自由宽度**：380–560 七档没有一档有独立的存在理由，是逐弹窗试出来的偶然值；三档按内容密度（编辑轻表单 / 多字段表单 / 表格详情）覆盖全部在场弹窗，档位归属可讨论、可复用，家族内部不再漂移。
- **为什么默认无边框**：多数卡片弹窗已经显式声明无边框——事实标准先行，规范只是把「每次都要记得传」改为「默认对、可逃逸」，消除七处漏传。
- **为什么表单、按钮行与辅助文案也入规范**：宽度统一只是节奏一致，表单控件尺寸与标签朝向、按钮编排与提示形态不一致同样让弹窗显得拼凑；四者同批收口，一次把「卡片内长什么样」定完整。
- **为什么不新增 BDD**：纯视觉排版、无业务语义与契约变化；把宽度/边框断言写进后端 BDD 是把视觉值放错层。组件层可观察行为（映射、默认值）+ 既有套件原样通过已是充分护栏。

## 代价与边界

1. 分档像素（420/480/560）是决策定稿值：调整档位须回本 ADR 修订，不在调用点零散改。
2. `cardSize` 未声明的调用点不获宽度——规范对存量渐进收口、非强制迁移；新弹窗一律声明 `cardSize`。
3. 逃逸门保留：仍可显式传 style 宽度与 `bordered` 覆盖（style 冲突时调用方显式值胜出）；逃逸是显式例外，不是规范第二款。
4. 抽屉 / 自定义弹层形态不在本规范范围（词汇表既定其关闭语义另行考虑；排版是否同批纳入，留待彼时裁决）；移动端 / 跨平台视觉细节同不在范围。
