# ADR-0065: 固定键位带——概览迁 ⌘`、每组固定三键

- 状态：已接受
- 日期：2026-09-04
- 作者：Ledger 项目
- 关联：取代 ADR-0063 决策 2 的键位推导规则（主项按组序与组内序连续取 ⌘2 起、主项集变化时其后主项键位全局重编号）；其 ≤3 硬上限、组满置灰与收纳机制全部保留；ADR-0051 / #359 确立的「位置即键位」线性推导先例自此收窄为组内带内；词汇表：界面状态与交互域「ViewShortcut」「侧栏分组」

## 背景

键位现状（ADR-0063 决策 2）：概览恒 ⌘1，三组主项按组序与组内序连续取 ⌘2 起，AI 恒 ⌘0、设置恒 ⌘,。线性推导下键位是全局连续编号：任一组移入/移出收纳使主项集变化时，其后所有组的主项键位整体重编号；数字键带与侧栏分组结构不同构，用户无法从键位读出「视图属于哪个组」。

其次，线性带的封闭性论证存在算术缺口：⌘2–⌘9 只有八键，而主项理论上限为 3 组 × 3 主项 = 9 项，第 9 项无键可用（代码以 null 兜底）；实际可达峰值 8 项（洞察组出厂无收纳种子、无可移回成员，主项恒 ≤2）恰好掩盖了这一缺口。

## 决策

### 1. 概览迁 ⌘`，数字键 1–9 全数让给主项键位带

概览键位从恒 ⌘1 改为恒 ⌘`（主修饰键 + 反引号，数字带上方、Esc 下方的定位键）；AI 恒 ⌘0、设置恒 ⌘, 不变。⌘1 释放后 1–9 九键恰好等于主项理论上限 3×3，键位封闭性首次严格成立。

⌘` 的运行时验证前提：macOS 系统级 Cmd+` 惯例为「同应用切换窗口」，Tauri 默认原生菜单可能先于 WebView 截获该键，反引号在部分键盘布局是死键。实现后在打包应用实测通过才算落地；若被原生层吞键，概览回退 ⌘1 再议——固定键位带改造（决策 2/3）不依赖 ⌘`，独立成立。

### 2. 固定键位带：每组三键、带序随组序

三组按固定组序各占连续三键的固定带：记账 = ⌘1/2/3、资产 = ⌘4/5/6、洞察 = ⌘7/8/9。组内键位按组内线性序从带首排起——组内右键重排仍键随位置（「位置即键位」收窄为带内），但重排与收纳变动的键位波及面收窄到本组带内，不再跨组重编号。键位带与侧栏分组同构：从键位即可读出视图所属组（1–3 记账、4–6 资产、7–9 洞察）。

### 3. 空键带内保留，不跨组压缩

组主项不足 3 时，带内空键保留待命：出厂态资产 2 项占 ⌘4/⌘5、洞察 2 项占 ⌘7/⌘8，⌘6 与 ⌘9 空置。移回主项落本组带内空位（如保单移回侧栏拿 ⌘6），不抢占他组键位、不全局压缩——空键换稳定性，这是固定带方案的诚实代价。

## 备选方案与否决理由

- **维持线性连续取键**（ADR-0063 现状）：键位紧凑（出厂仅 ⌘9 一个空键），但跨组键位牵连重排、键位与分组结构不同构，且 9 主项理论上限对 8 键的算术缺口始终存在——弃。
- **概览保持 ⌘1、键带延展**：⌘0 是 AI 的固定惯例键位，让出即破坏「固定项键位恒定」；满编仍差一键——弃。
- **空键全局压缩（带间让渡）**：空键被后组借用则固定带名存实亡，键位稳定性收益归零——弃。

## 后果

- **对 ADR-0063 是演进而非否定**：决策 2 的 ≤3 硬上限、组满置灰与收纳机制全部保留，被取代的只是键位推导规则（线性连续取键 → 固定键位带）与键位波及面（全局重编号 → 组内带内）；「3 组 × 3 主项 = 键位带」的封闭性论述在 ⌘1–⌘9 九键下首次严格成立。
- **键位稳定性提升的代价是出厂双空键**：⌘6、⌘9 空置（线性方案仅 ⌘9 一个空键）；组内补足主项后自然回填，空键不影响任何交互（无提示、不命中）。
- **纯前端导航改动**：schema / API / 命令 / 数据模型零变化；键位不持久化（每次由组内序按固定带推导），无存量数据迁移。
- **⌘` 附验证条件**：见决策 1——打包实测通过前，该决策视为未落地。
- **词汇表修订随本决策落地**（界面状态与交互域）：改写「ViewShortcut」「侧栏分组」。
