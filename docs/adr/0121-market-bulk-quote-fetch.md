# ADR-0121: 行情日常刷新改走批量取数面——接受页面级批量接口、逐标的通道保留为降级、不换源

- 状态：已接受（grilling 定稿，2026-09-15；实现随实施票落地）
- 日期：2026-09-15
- 作者：Ledger 项目
- 关联：ADR-0015 / ADR-0019（同步职责切分与价格历史化）；ADR-0038 决策 6（首刷单请求通道失败 fail-closed 回退分页——本裁决的降级先例）；ADR-0081（按代码查询主干道与通道分区）；ADR-0095（同步进度——本裁决不改其分母口径）；ADR-0103（行情接入接缝——本取数面与手动报价、标的信息同步同款留在接缝外）；ADR-0069 决策 4 / ADR-0120（网络等待不进连接锁）；ADR-0122（现价与历史解耦）；词汇表：投资域「行情批量取数」「InstrumentInfoSync」「价格通道」

## 背景

「同步标的信息」的请求量随标的数线性增长：每只行情标的各一次日线请求、每只有码基金各一次净值请求加一次名称请求。在一个 233 只标的（其中 232 只为场外基金）的真实账本上实测：每次同步约 2 × 228 ≈ 456 次请求；全局限速写死每请求 2 秒（30 次/分钟），一次同步约 15 分钟。

而数据源的可承受量级约为 60 次/分钟——限速只用了额度的一半，另一半浪费在「每只标的一次请求」这个结构上。数据源自身提供了批量取数面：基金名称有全量字典（一次请求覆盖全市场基金代码与权威名称），场外基金净值有排行批量面（一次分页请求覆盖上万只基金并携带单位净值与净值日期），两者实测均可用、单次响应在秒级。场内行情通道的报价本就是批量面（一批 50 个 secid），它的逐标的请求集中在日线——那是因为现价与历史共用一次请求（ADR-0019），历史解耦后该理由随之消失（ADR-0122）。

## 决策

### 1. 日常现价刷新改走批量取数面

标的现价刷新（含名称随行刷新）以批量取数面为主：名称走全量字典，场外基金净值走排行批量面；场内行情通道的批量报价不变。取数面从「每标的一次请求」改为「每批一次请求」，请求量从随标的数线性增长降为常数级。

### 2. 批量取数面不是价格来源

价格来源仍由价格通道的四值闭集判定，本裁决不改其成员与判定单点；批量取数面只回答「这次刷新用几次请求」。价格与名称的写入仍记东方财富为来源，标的列表的「价格来源」列不因取数方式而变。

### 3. 降级契约：fail-closed 回退 + 同步内熔断 + 跨同步记忆 + 按条缺口不熔断

- **fail-closed 回退**：批量取数失败一律回退逐标的通道（与 ADR-0038 决策 6 的首刷单请求通道失败回退分页同款），不静默丢数据。
- **同步内熔断**：批量取数面一次失败即本次同步后续全部走逐标的通道——否则每只标的都先试一次批量再回退，请求量比改造前更多。
- **跨同步轻微记忆**：连续失败达阈值后停用批量取数面一个期限，到期先半开试一次，避免在风控期内每轮都撞一次。
- **按条缺口不触发熔断**：批量面不承诺覆盖全部基金（新成立、已终止、清盘、部分货币基金不在排行列表中），缺失的标的后退到逐标的通道逐条补齐——这是缺口，不是失败，两者的日志与统计须分得开。

### 4. 降级可见

本次同步回退到逐标的通道时，界面明示「已降级、本次较慢」。理由：这是公开发布的应用，别人的网络环境会撞上不同的风控结果；静默降级会变成无法解释的「有时要等十几分钟」的缺陷报告，而这类报告的成本高于一行提示。

### 5. 全局限速自适应

全局限速不再写死每请求 2 秒：正常状态贴近数据源可承受量级，遇限流响应或疑似风控页时自动降速并复用既有冷却，恢复后逐步提速回升。理由：这个数字的权威来源是对方服务器能承受多少，写死任一个值都会在某个环境里错——保守值浪费额度，激进值撞风控。

### 6. 不做多源

维持东方财富为唯一行情数据源：不引入第二个报价源分流，也不引入可插拔的数据源抽象（见否决段）。

## 否决

- **引入第二数据源分流（新浪 / 腾讯 / Tushare / 付费源等）**：批量取数面已把日常请求量压到常数级，单源额度不再构成日常瓶颈。第二源的增量收益是「单源封禁时的可用性保险」与「额度相加」，代价是两套解析、两套口径（不同源的净值与报价口径差异要逐个裁决）以及为公开发布引入的授权面。等单源封禁成为真实故障再立项，不在没有故障时先付维护税。
- **靠并发提速**：单源额度是天花板，并发只是把排队变成被拒；现有实现串行 + 全局限速正是为规避风控而设。天花板不变的前提下提高并发度只会提高被封概率。
- **用批量取数面完全取代逐标的通道**：批量面有覆盖缺口，且单一取数面失效即全库无价；逐标的通道是降级兜底，必须留。
- **维持写死的 2 秒节流**：只用了一半额度，且真值随网络环境与对方风控变化。
- **把取数面做成 trait / 注册表机制**：与 ADR-0103 同款——没有「遍历一组取数面统一处理」的多态消费点，trait 是纯机制税；取数面由统一形状与命名承载。
- **降级不告知用户**：把不可解释的慢留给用户，见决策 4。

## 后果

- 日常刷新的请求量从随标的数线性增长降为常数级；用户感知从分钟级等待变为秒级完成，「快」不再由本地优化决定，也不承诺任何具体耗时。
- 词汇表：投资域新增「行情批量取数」词条；「InstrumentInfoSync」的行情访问量与名称刷新边界随之改写（历史一翼由 ADR-0122 分走）。
- 新增两条守门判据：①降级路径必须存在且被接线——删除批量取数接线后逐标的路径仍可用但降级标注与熔断逻辑无用武之地，接线型断言须红；②降级对用户可见——删除降级标注则界面测试红。
- 批量面覆盖缺口成为常态认知：日志与跳过统计须能区分「批量面没覆盖」与「标的确实无数据」。
