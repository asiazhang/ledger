# ADR-0077: 行右键菜单编排工厂化——RowContextMenu 收编手搓定位四件套

- 状态：已接受
- 日期：2026-09-05
- 作者：Ledger 项目
- 关联：issue #522（spec，经 grilling 一轮收敛定型）、issue #550（实施首票：工厂落地 + 交易列表接入）；先例 ADR-0030 / ADR-0041 / ADR-0045（房式：工厂形态、弹层纯度、回调注入与测试策略转移）、ADR-0072（ModalIntent，单判别状态「非空即显示」的同款形态）、ADR-0035（弹层注册表，弹层纯度边界）

## 背景

行菜单的定位状态机——菜单开关、坐标、目标行四个状态字段，外加一段非显然的「先收起菜单再下一帧重开以刷新位置」时序——长在各视图文件里逐行重复。grilling 期事实盘点定稿：全仓实存**四份**同构拷贝——交易行（TransactionsView）、账户行（AccountsView，含「⋯」按钮第二入口）、侧栏排序菜单（App.vue）、组内收纳页签菜单（GroupMoreView，盘点中新发现）；「先捕获目标行、再收起菜单」的收尾时序同样逐份重复，读错顺序就读到空行。想测它只能挂载整个视图组件间接覆盖，而账户视图的菜单行为（含「⋯」第二入口）零测试覆盖；第五个消费者出现时只能再抄第五份方言。

## 决策

1. **新增通用工厂 `useRowContextMenu<TRow>(onSelect)`（工厂形态 composable，行右键菜单编排）**：泛型目标行、每次调用独立实例；工厂永不读行内容、只存储回传（纪律门槛）。接口四面：`state`（单判别状态 `{ x, y, row } | null`，只读——可见性由非空派生、无独立开关布尔，close 清回全空终态、无滞留行，「行非空但菜单已关」的非法中间态由形态消灭）；`open(event, row)`（幂等升级：未开即开、已开即重定位）；`close()`；`select(key)`。
2. **open 统一「收起 → 下一帧重开」舞步单路径**：已开重定位与关闭态打开同一路径，从关闭态打开同样延迟一帧——与既有行为严格等价，不做快路径优化；同一同步批次内连续 open，最后一次开启胜出。视图右键另一行时无脑调 open，永不知道菜单当前开不开。
3. **select 收尾时序内化**：`select(key)` = 收起菜单 + 以**收起瞬间**的状态把 `(key, row)` 交给工厂入参回调 `onSelect(key, row)`；回调体 100% 是视图业务代码，工厂不认识任何 key；菜单未开时无可交付、回调不触发。「捕获目标行要在收起前」的时序收进工厂一处（回调注入先例：ADR-0041）。
4. **事件纪律**：工厂不调 preventDefault、只读事件坐标；原生菜单拦截单点归窗口行为守卫（issue #154，document 捕获阶段、可编辑元素放行），行视图迁移时删除各自的冗余双保险调用——守卫先行拦截，行为严格等价。
5. **弹层纯度**：工厂不接弹层注册表（ADR-0035）；开/关上报由既有薄封装 AppDropdown 的 attrs watch 承担，视图以 `:show` 绑定即自动生效，注册表接线零改动。
6. **职责边界**：菜单选项构建（transaction-row-menu 等纯函数）、菜单项结构、组件 props（placement / min-width 等）与业务动作分派（编辑、退款、加入物品、余额调整、删除等）全留各视图——工厂只管「菜单怎么出现」，不管「菜单里有什么」。
7. **收编清单与排除裁决**：四份同构拷贝中，**行拷贝**（交易行、账户行）收编进工厂、逐个切换、各自独立提交、中途可停；**两份非行拷贝排除**——侧栏排序菜单与组内收纳页签菜单的目标语义是视图名（字符串）而非行对象，接线形态亦不同（菜单节点 props、无 preventDefault），作为已知候选消费方记录在案，工厂验证后另票快追，本决策不收。
8. **测试策略转移（ADR-0030 决策 7 / ADR-0041 决策 10 同款）**：工厂零外部依赖（无 store、无 api、无组件，只等下一帧），模块测试**裸调直测**——open/close/select 的状态终态与重定位舞步（已开时 open → 状态过 null 一跳 → 下一帧新坐标新行重开）、select 收尾回调收到的 `(key, row)`、close 清回全空、独立实例互不串扰，不断言内部 nextTick 接线细节；行视图既有测试 = 等价性护栏，切换后零断言变化全绿；账户视图现状零菜单覆盖，其切换提交须先补 2–3 条最小冒烟（右键弹菜单、「⋯」按钮弹菜单、select 分派到业务动作）再切换。

## 理由

- **为什么现在抽工厂**：四份拷贝意味着定位缺陷（如高分屏坐标偏移）要修四处；「收起重开」时序没有名字与接口，只能靠注释维持；账户视图第二入口零覆盖，切换无护栏可依——先立工厂与护栏，迁移才有等价性证据。
- **为什么单判别状态而非 show + x/y + row 四状态**：四状态方言存在「行非空但菜单已关」的非法中间态（select 后 show=false 而 row 滞留），是「菜单已关还读到旧行」隐患的根源；非空即显示的派生让非法中间态在形态上不可表达（ADR-0072「意图非空即显示」同款）。
- **为什么 open 不做快路径**：从关闭态打开也延迟一帧是既有行为；统一单路径让「打开」只有一个可观察时序可断言、可模仿，快路径优化没有在场的性能需求，属 YAGNI。
- **为什么 select 以回调交付而非视图事后读状态**：收起后状态清空是工厂的接口保证；视图若事后读行，要么读到 null、要么诱使工厂滞留行——「收起瞬间捕获」内化后，收尾纪律只有一种且天然正确。
- **为什么工厂不 preventDefault**：窗口行为守卫已在捕获阶段无条件拦截（可编辑元素放行），视图级调用是双保险冗余；双保险的坏处是拦截语义两处声明，改一处漏一处。
- **为什么非行拷贝排除**：目标语义（视图名 vs 行对象）与接线形态（菜单节点 props、无 preventDefault）均不同，强行收编要么泛型到失去「行」语义、要么为两处改接线引入本票等价边界外的变化；记录在案另票快追即可，无需重新考古。

## 代价与边界

1. 迁移期手搓方言与工厂并存（行拷贝各自独立提交的窗口），短期混存。
2. 「重定位状态过 null 一跳」是既有「收起重开」行为的如实转写：菜单在两帧间瞬断一次，`:show` 的观察者（含弹层注册表上报）在该帧收到关再开——与现状逐位一致，非新增行为。
3. 本决策只定接缝与纪律：不定实现文件名与目录（在仓库既有 composable 命名惯例内落位，ADR-0045 代价 4 同款）、不定消费切换次序（票内裁量）。
4. 工厂接口面刻意最小（state / open / close / select 四面）；未来若出现多菜单互斥、键盘导航等需求，扩展接口而非复用现语义。
5. 非行拷贝（侧栏排序、页签菜单）暂继续手搓同款舞步；其收敛须先裁决「视图名目标是否泛型进本工厂或另立形态」，本决策不预设。
