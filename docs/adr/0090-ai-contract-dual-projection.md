# ADR-0090: AI 契约双投影——标准 OpenAPI 与紧凑方言同源分流

- 状态：已接受
- 日期：2026-09-08
- 作者：Ledger 项目
- 关联：spec #839（本文档票）；前置 ADR-0044（信号映射，「端点集真源 = 契约装配」先例）；ADR-0038（价格刻度，方言字段描述原文承载其口径）；#304 / #693（契约体积预算护栏传统）；#286（提示词/知识分界，本 ADR 延续其「两处重复即口径分叉」红线）

## 背景

AI 编程助手使用本机 HTTP API 前必须拉取契约。实测 `openapi.json` 45.9KB ≈ 13–15K tokens，其中约 54% 是中文教学描述，其余大部分是零语义的 OpenAPI 结构样板（`content` / `application/json` / `schema` / `$ref` 仪式）。单次迁移会话的静态阅读（契约 + 导入知识 + 入口提示词）≈ 17–19K tokens，挤占真正用于账本数据行的上下文。同时契约端点级描述与导入知识存在教学复述（基金/股票三步法等），触碰 #286 已声明的红线：两处重复即口径分叉的温床。

## 决策

### 1. 双投影同源：一个 ApiDoc，两个端点

契约唯一源仍是壳层 [`ApiDoc`]（utoipa 装配，生成机制零修改）：

- `GET /api/v1/openapi.json` —— 标准投影，端点/字段/状态码结构原样保留（Swagger 类标准工具链持续可用，依赖升级与 rustdoc 流程保持标准）；端点级描述按决策 3 收敛为「一句话 + 指针」，出处引用照常保留；
- `GET /api/v1/contract` —— 新增紧凑方言投影，返回为 AI 设计的 `ledger-contract-1` JSON 方言。

两投影都是 `ApiDoc` 的机械产物（壳层纯函数：输入 utoipa OpenApi 模型、输出方言 JSON 值，进程内 `OnceLock` 一次性懒构建），**不存在任何手写契约第二文本**。端点纯增量发布，`openapi.json` 契约面零变化，无 BREAKING。

- **备选与否决**：手写紧凑契约文本——即写即漂移，违背「手写零复述」红线；改造 utoipa 生成机制——把依赖升级与标准工具链兼容性押上，收益不成比例。

### 2. 方言形状（`ledger-contract-1`）

```
{ "v": "ledger-contract-1", "base": "http://127.0.0.1:9527/api/v1",
  "legend": "类型: str/i64/f64/bool/obj; T[] 数组; 后缀? 可选; 字段值[类型,说明]",
  "endpoints": [ { "m", "p", "s", "d", "body", "res": { "200": "T", "400": "ErrorResponse" } } ],
  "schemas": { "枚举闭集": "a|b|c", "对象": { "字段?": "类型" | ["类型", "描述"] } } }
```

类型表达式规则：`$ref`→schema 名、数组→`T[]`、可空/可选→`?` 后缀（可选与可空共用一个 `?`，不叠加）、枚举→`a|b|c` 闭集、integer/number→`i64`/`f64`、string/boolean/object→`str`/`bool`/`obj`。端点路径省略 `/api/v1` 前缀（base 单列，连接信息自足）。`res` 映射全部状态码；无 JSON 响应体的状态码（204、text/plain 端点）以 `"-"` 占位——状态码本身保留，是读回自纠的依据（ErrorResponse 的 `code` + 中文 `message` 承载错误语义）。

- **备选与否决**：保留 OpenAPI 全形状只压描述——样板 token 仍占大头；MCP 等新传输载体——HTTP + 自描述是本域立身之本，另行议题。

### 3. 描述政策：字段级原文保留，端点级一句话 + 指针

- **字段级描述原文保留**（仅剥出处引用，见决策 4）：契约仍是字段语义的唯一权威；投资四字段（`instrument_id`/`quantity`/`price_cents`/`fee_cents`）描述锁的语义不动（#298）。
- **端点级 7 条长教学描述**（POST /instruments、GET /instruments、GET /stocks/{code}、GET /funds/{code}、POST /transactions/batch、GET /transactions、PUT /transactions/{id}）**迁入导入知识对应节**，契约留一句话语义 + 「见导入知识」指针——教学单一权威归导入知识，消除两处复述。
- **schema 级（组件级）描述不入方言**：其信息由字段级描述与既有知识承载（如「幂等键不可编辑」由 `UpdateTransactionInput` 无 `idempotency_key` 字段的表达 + 知识文本共同锁定）。
- info 级描述不入方言：base 在方言头单列。「退役」的范围是方言侧——`openapi.json` 的 info 块照常保留，否则违背决策 1 的结构原样保留与纯增量发布；其教学性内容（价格刻度、基金申赎、三步法摘要）的单一权威同样归导入知识。

### 4. 出处剥离：投影期机械剥离，源注解保留

投影期正则剥离 `issue #N` / `spec #N` / `ADR-N`（含紧随的「二期」「决策 N」限定语与紧邻分隔符，并以裸 `#N` 兜底——已核对契约文本中裸 `#N` 仅以「issue #693/#696」同源串联形态出现；残留空括号/悬挂标点一并清理）；出处保留在源注解（utoipa 属性串）里给开发者，`openapi.json` 标准投影同样保留。可追溯性资产与 AI 信噪比各自最优。

### 5. 接线：提示词与知识换指向

- 入口提示词第一步 `GET /api/v1/openapi.json` → `GET /api/v1/contract`（三步骨架、「不删后重导」纪律、禁词清单不变）；
- 导入知识内嵌的契约地址同步换轨；迁入的 7 段教学在知识关键词锁清单追加锚词（静默复用、上限 100、不影响其余行、稳定排序、逗号分隔、落最新价现价、市场保留），防教学迁移静默丢失。

### 6. 体积护栏：≤20KB + token 换算口径注释

方言产物 ≤20KB（实测 ~17.1KB）。换算口径 ASCII ≈ 1 token / 3.6 字符、中文 ≈ 0.95 token / 字符（不引入真实 tokenizer 依赖），记入测试注释；触线 ≈6K tokens 须人工决策提预算或瘦身，延续 #304 / #693 契约膨胀护栏传统。净效果：契约单次拉取 ~14.0K → ~5.1K tokens（-63%），每迁移会话净省 ≈8K tokens。

### 7. 契约自举面：两端点同路豁免门禁

`/api/v1/contract` 与 `/api/v1/openapi.json` 同属契约自举端点（不含用户数据、不触 DB），在加密锁定门与启动失败门同路豁免——旧提示词会话与新一两会话在锁定期间都能发现契约面。

## 后果

- AI 迁移会话上下文成本显著下降；契约教学单一权威归导入知识，端点描述不再与知识复述。
- 方言形状成为对外承诺：字段 `?` 后缀、`-` 占位、图例文本演进须随版本标记（`v`）协商，后续演进先 bump 版本再改形状。
- utoipa 侧新 schema 形态（如 `items: false`、组合类型新用法）投影时兜底为 `obj` 并留测试盯防，扩展点集中在壳层投影函数一处。
