# ADR 0014: 物品（Item）使用成本独立领域

- 状态：已接受
- 日期：2026-08-27
- 作者：Ledger 项目

## 背景

用户想要"看一个东西从购买到今天平均每天花多少钱"（平均使用成本）。现有模型里，购买一件耐用品只是一笔 `kind='expense'` 的一次性交易，系统并不知道"这个东西还在我手里、我用了它 N 天"。词汇表中没有任何"我拥有的、随时间持续存在的东西"的概念——参考数据（账户/分类/币种，字典）、交易流水（Transaction，一次性资金变动）、投资域（Instrument/Holding，证券）都不承载它。

## 决策

1. **新增独立领域实体 Item（物品）**：用户拥有并使用的耐用实物，不等于一笔交易（Transaction）、一个账户（Account）或一种金融标的（Instrument）。见 CONTEXT.md `Item` 条目。
2. **物品自包含总成本**：一个 `total_cost_cents`，基础成本在有关联购买交易时自动带出，后续花费（维修/配件/运费）由用户编辑总数累加。**不**由系统对多笔关联交易求和——物品是它自己度量的单一来源，避免与账本交易产生双向纠缠。
3. **可选关联购买交易**：仅为自动带出成本/日期与溯源，不建立"交易→物品"的反向引用；允许没有对应交易的物品（赠品/旧物）。
4. **生命周期**：`in_use`（在用，摊到今天）/ `disposed`（已处置，摊到处置日，可选残值——分子=成本−残值）。预期寿命摊销作为后续扩展。
5. **金额复用 Amount 接缝**：整数分 + 币种 + `convert_to_native` 折算默认币种（与交易同口径，不另写金额口径）。
6. **数据分类 = 独立领域，不是参考数据**：物品有自己的 store/查询，不入 `useReferenceStore`（那不是"可选值字典"）；物品写入发 `ledger:changed`（沿用粗粒度失效）。
7. **UI = 新增"物品"侧边栏视图**（镜像 Investments 视图）+ dashboard 一张汇总卡；MVP 不做 AI API `/items` 端点。

## 理由

1. **耐用品是与一次性交易本质不同的概念**：它有身份（跨时间持续存在）、有生命周期（在用/终了）、可聚合多笔相关投入。放交易派生表达不了"这个物品持续存在"，做成独立实体才契合它的本质。
2. **自包含成本避免双账**：物品的成本与账本记账是两条线——账本记"花了这笔钱"（进报表/预算），物品记录"这件的持有成本"。若从交易求和，会逼着每笔后续花费都成为账本交易，且与手工记录产生两条事实源。自包含让每件物品的度量只有它自己一个权威。
3. **复用现有接缝**：金额走 Amount 接缝、失效走 `ledger:changed`，与既有约定一致（AGENTS.md 要求金额一律经模块接口，不另写口径）。

## 代价

1. **与账本存在语义上的"双记录"**：同一笔购买既是一笔 expense 交易，又可能是物品的基础成本来源。二者服务于不同目的（预算 vs 持有成本），但用户需理解这是两条线。
2. **后续花费需手工编辑总数**：不能"记一笔维修账就自动摊入"，对希望全自动的用户多一步手工。
3. **新增实体带来一套模型/命令/表/UI/测试**：遵循补 BDD feature、Vitest、`commands.rs` 注册、`src/api/index.ts` 加方法的既有约定。

## 替代方案

- **交易派生/标注**（按分类分组或交易打标算摊薄）：表达不了"物品持续存在"，无法处理后续投入与残值，放弃。
- **从关联交易求和**：全自动但双事实源 + 逼着每笔后续花费都入账，且与账本双向纠缠，放弃（决策 #2）。
- **物品进参考数据 store**：污染"字典"语义与重拉逻辑，且物品低于参考数据的变更频率假设，放弃（决策 #6）。
