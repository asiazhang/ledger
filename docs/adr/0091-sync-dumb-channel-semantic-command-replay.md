# ADR-0091: 多端同步——网盘哑通道 + 语义命令 OpLog 确定性重放

- 状态：已接受
- 日期：2026-09-08
- 作者：Ledger 项目
- 关联：ADR-0074（Android 工程）、ADR-0056（后端分层，域不依赖壳）、ADR-0067（余额缓存整体重算）、ADR-0016 / 0017 / 0075（备份调度与加密模式 / 主口令机制）、ADR-0024（定时计划期次）、ADR-0089（多账本经独立库文件）；备份域词汇表「备份 ≠ 同步」的既有划界

## 背景

应用当前是单机桌面账本（Tauri + 单 SQLite 文件），目标是桌面 + 手机（Android，ADR-0074 已立项）多端使用同一份账本，但不想自建服务端。可选通道只剩「哑」路径：网盘目录只负责搬字节，理解不了内容；账本是财务事实，同步零丢失（并发写入的数据全部存活）是硬约束；而真实使用模式是单活跃设备、并发罕见。域层已与壳解耦（ADR-0056），域引擎可编译进移动目标。

## 决策

### 1. 通道与拓扑：哑文件通道，无服务端

网盘目录（WebDAV / 本地网盘文件夹等）作为 Transport（同步通道）抽象的后端，只搬运同步文件，不做任何合并与冲突处理；智能全在各端。

- **备选与否决**：纯 P2P 直连——工程量大（发现、穿透、移动端后台限制）且只解决通道不解决冲突；自建服务端——用户明确排除。

### 2. 复制模型：语义命令 OpLog，经既有写入接缝重放

各端本地追加 OpLog（操作日志），op 的载荷是 DomainCommand（语义命令）——与现有写入接缝同语义的域级命令；接收端经同一接缝 Replay（重放）。重放是行为编排之外的新写入入口，接缝契约与批量导入同等待遇。零丢失由复制模型保证：并发 op 全部存活，输赢只在同字段裁决中产生。

- **备选与否决**：全库快照轮替——并发写会撞车甚至损坏 SQLite 文件，且必然丢一边；行级变更同步——绕过写入接缝，余额缓存重算、kind 折算、删除清理副作用等不变量要在各端重复实现；CRDT 存储层（cr-sqlite / Automerge）——与既有 schema 和接缝整合等于重做存储层，为罕见并发付整个存储层的代价不成比例。

### 3. 确定性重放：源端折算 + 账本级本位币

同一命令在任意端重放必须落出同一结果。折算在记账端一次性完成，折算输入与结果随 op 携带（源端折算），重放不依赖本地汇率表状态；DefaultCurrency 的后端本位币基准升格为账本级设置（LedgerLevelSetting，见参考数据与设置域），全设备强制一致——它是 native 口径唯一的根据。重放按 op 标识幂等，重复到达不产生第二次效果。

### 4. 全序与 LWW：逻辑时钟 + DeviceId，无裁决 UI

跨端 op 按 (逻辑时钟, DeviceId) 排出全序；同实体同字段的并发编辑取序末者（LWW），v1 不做冲突裁决 UI，输者仍在 OpLog 中可审计。为「同时改一个备注」做用户裁决界面，工程与体验都不值。

- **备选与否决**：冲突弹窗让用户挑——为罕见并发支付持续体验税，且 op-log 天然留痕、可追溯。

### 5. 计划期次防双扣：OccurrenceKey

定时计划的自动执行（含追补）在多端同时运行会产生同一期次的重复触发；期次触发 op 以 OccurrenceKey（plan_id + 期次标识）做确定性幂等，重放端去重，同一期只落一次。与 AI 导入域 IdempotencyKey 同构。

### 6. 不可重放 op：挂起 + 码化错误，不静默兜底

外键依赖失败（A 端删除账户、B 端往该账户记账）与 schema 版本偏斜（op 记录产生时 schema 版本；旧命令重放到新 schema、或旧端收到新命令）统一走 ParkedOp（挂起操作）：进挂起队列、码化错误通知用户裁决、不阻塞其余重放、不自动复活已删账户。OpLog 只增不改，与 migration 纪律同构。

### 7. 端与引擎：共享 Rust 域引擎，移动端全功能对等

桌面（Tauri）与 Android（ADR-0074）共享同一套 Rust 域引擎——零丢失合并的前提是每端本地重放 op 且遵守同一套不变量，这只有共享域引擎才便宜；ADR-0056 已保证域不依赖壳。移动端经 Tauri 2 mobile 全功能对等，v1 只做 Android 单平台。

### 8. 加密：SyncEnvelope 整包信封加密

通道上的整包（Checkpoint + OpLog 文件）以 SyncEnvelope（同步信封）加密，密钥由主口令派生，复用备份域加密模式 / 主口令机制；未开加密模式时明文同步并在界面显著提示。账本数据躺在网盘上，端侧加密不让步。

### 9. 同步边界与 Checkpoint

SyncBoundary（同步边界）与 Backup/Restore 迁移边界对齐：各业务域数据同步，界面状态与设备偏好不同步；唯一升格成员是本位币基准（决策 3）。Checkpoint（检查点快照 = 全量快照 + 各流已应用位点）负责新端引导与 OpLog 截断。

## 后果

- DomainCommand 面成为跨端契约：新增或修改写入命令须保持 op 可序列化且向后兼容（旧日志可重放），与「已发布契约只增不改」纪律同构；破坏性演进需版本协商。
- 余额缓存（ADR-0067）等派生数据不进日志，各端经既有接缝重算，「实时计算为审计权威」原则自然延伸到同步场景。
- Transport 的 v1 后端选择（Android 无 iCloud 容器可用）与同步触发时机是可逆工程决策，不在此记录；多账本（ADR-0089）落地后，同步数据按账本走、每库一份，是其边界的自然延伸。
- 实施分期与工单分解后续进行；本 ADR 只记录架构决策。
