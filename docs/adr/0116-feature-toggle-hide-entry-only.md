# ADR 0116: 功能开关——关闭只隐藏入口，与组内收纳两层正交

- 状态：已接受
- 日期：2026-09-13
- 作者：Ledger 项目
- 关联：修订 ADR-0022（设置页新增「功能」Tab）；与 ADR-0063（组内收纳）两层正交；收窄金额隐私模式「不进设置页」纪律的适用范围；词汇表：参考数据与设置域「功能开关」、界面状态与交互域「组内收纳」「ViewShortcut」「侧栏分组」；实现跟踪见 spec #1237

## 背景

功能面持续扩张：侧栏已是「概览 + 三组 + AI + 设置」，设置页五个 Tab。ADR-0063 的组内收纳只解「这个视图在组里的什么位置」，解不了「我根本不做投资，不想在侧栏看到它」——用户不需要的功能仍持续占据导航空间。**位置**与**存在**是两个问题。

用户诉求：设置页提供功能开关，允许关闭不常用的功能，并为每个功能写一句简介。

## 决策

### 1. 关闭 = 仅隐藏入口

关闭一个功能不删数据、不停能力：余额、净资产、预算进度、报表等派生口径照旧把该功能的数据算在内；后台行为（如定时计划的自动执行）照旧运行；AI 导入等外部写入面照旧可用。关闭改变的是「这个功能的入口在不在界面上」，不是「这个功能存不存在」。

### 2. 可选清单是开发者策展闭集

- **可关九项**：预算、报表、定时、商户、投资、物品、保单、实物资产、保司。
- **不可关六项**：概览、交易、账户、搜索、AI 导入、设置。

不可关的理由分两类：机制必需——交易与账户是记账动线的基本依赖，设置承载开关本体（关掉即无回入口，属死锁）；定位必需——概览是启动落地页，搜索与 AI 导入是随时回头可用的检索与导入面。

追加或移除成员沿用 ADR-0063 决策 3 的开发者清单机制：改清单 = 修订本 ADR。

### 3. 与组内收纳两层正交

收纳管「在组内哪个位置」，功能开关管「在不在应用里」。关闭的功能不进侧栏、不进该组「更多」页签、不占键位；但**关闭不改写收纳清单**——清单仍是收纳成员资格与顺序的唯一事实源（ADR-0063 决策 5），重新打开即回到原位置。

### 4. 入口消失、引用放行

关闭后消失的是该功能**自身的入口**：侧栏项、组「更多」页签、设置页对应 Tab、以及**组内新建入口**（关闭投资后交易页新建菜单的买入/卖出项与对应裸键）。判据是这条路径在做什么——新建买入是在向投资功能写入新数据的入口，属入口侧。

反之，**其他域对该功能已有数据的引用一律照常**：交易列表的来源列、持仓/分类/商户等下钻、带实体定位参数的深链、按 kind 筛选已有交易，全部不受关闭影响。判据同样简单：带实体定位参数的访问是引用，裸访问是入口；复用既有实体定位参数约定，不新造机制。

### 5. 落点回退 = 概览

关闭后该功能的裸路由重定向到概览。上次视图恰为已关闭功能时同样回退概览——概览不可关，恒为安全落点，不需要分级规则。

### 6. 设备级持久化，跨账本共享

按 ADR-0017 判定：只被前端消费、不改业务语义、随本机而不随账本迁移 → 设备偏好落 localStorage，与侧栏顺序、收纳清单同族同归宿，跨账本共享。**不**进 `app_settings`：那会把它升格为随备份迁移、跨设备一致的账本级设置，与「关掉我眼前碍事的功能」的预期不符。

### 7. 设置页新增「功能」Tab（修订 ADR-0022）

九项开关各配一句简介，体量独立成页，插在「关于」之前。ADR-0022「不随手开新 Tab」收窄为「体量不足以独立成页的并入既有 Tab」；Tab 分域原则与「关于」恒在末位不变。先例：定时计划域的一个设备偏好开关已单独占「定时」Tab（issue #308）。

### 8. 不设确认、不设拦截

关闭是非破坏、可逆动作，按 ADR-0078 的分级连轻量确认都不需要；「功能仍在运行」这类事实由**该功能的简介文案**明示（例如定时那条写明「关闭只隐藏入口，已有计划仍按既有设置执行」），不靠弹窗或置灰拦截承担。

## 考虑过的替代方案

- **关闭 = 停用能力**（后端拒绝该域写入、停自动执行、AI 导入跳过）：否决。这会同时撼动交易写入、自动执行、AI 导入、同步重放四条入口的一致性契约，必须升级为账本级 + 同步语义，并让跨域聚合出现「数据在但口径变了」的隐性差异（实物资产计入净资产第三腿、投资决定净值）。
- **硬拦截**（存在启用计划且自动执行开启时不允许关闭）：否决。关闭非破坏、可逆，用结构性不变量级别的置灰过重；知情权由静态文案承担即可。
- **彻底关闭**（引用一并置灰、所有路径重定向）：否决。会让投资域的开关去削掉交易域来源列的信息——来源列是交易域的数据展示，不是投资域的入口，违反「关闭只影响本功能」的边界。
- **收纳扩展出「完全隐藏」档**：否决。把两层语义挤进同一份清单，「移入更多」的含义随即分叉，且关闭将污染用户既有收纳清单。
- **可关清单放开到任何导航条目**（含设置）：否决。立刻需要设计「关掉设置后如何恢复」的逃生舱，收益为零。
- **开关按账本隔离或进 `app_settings`**：否决。与紧邻的收纳清单（跨账本共享）产生认知断裂；进 KV 表则把它升格为跨设备真值。

## 后果

- **键位带不变形**：关闭的功能不占键位，本组带内留空键待命（ADR-0065 的固定键位带推导不变），不跨组压缩。
- **金额隐私模式的纪律收窄**（issue #566 / spec #564）：其「不进设置页、不为低频路径扩配置面」的理由收窄为——**临时态开关**（投屏/演示期一键遮蔽，用完即走）不进设置页；**结构性配置**（决定长期导航结构）进设置页。两者判据不同，不构成冲突。
- **数据面零改动**：无 schema、无迁移、无 API 契约、无命令面变化，纯前端信息架构；不触及发布边界。
- **验收须含接线型负向条目**：删除「关闭过滤」接线 → 至少一条测试变红，断言对准用户可观察结果（侧栏 / 「更多」页 / 设置 Tab 中入口消失、裸路由落回概览、引用路径仍可达），不对准线程或函数调用形状（ADR-0087）。
