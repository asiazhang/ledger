# ADR-0122: 现价刷新与价格历史解耦——历史回填改后台自动补全（无用户入口、静默计数、额度让路、单只原子）

- 状态：已接受（grilling 定稿，2026-09-15；实现随实施票落地）
- 日期：2026-09-15
- 作者：Ledger 项目
- 关联：ADR-0019（K 线近两年回填 + 周采样；本裁决**推翻**其「回填历史同时也是刷现价、不存在两条刷新通道」的口径）；ADR-0038 决策 6（净值水位增量与首刷判据——本裁决为其补上「单只写入整只原子」的前提）；ADR-0081 决策 3（全量字典同步退役）；ADR-0095（同步进度事件与分母口径——标的级口径维持，「首刷深回填」的页级明细随本裁决迁至后台任务）；ADR-0069 决策 4 / ADR-0120（网络等待不进连接锁）；ADR-0032 / ADR-0073（置脏与统一写入口）；ADR-0112 决策 5（下层定义注册点、上层注册实现、壳层启动接线——后台任务的接线形态）；ADR-0121（行情批量取数面）；词汇表：投资域「价格历史后台补全」「PriceHistory」「InstrumentInfoSync」「价格过期提示」

## 背景

ADR-0019 定下「采集单通道」：回填历史的那次请求同时就是刷现价的那次请求，因此不存在两条刷新通道。这条口径在标的数少、历史已回填的账本上成立；在真实账本上，它让每次同步都为每只标的重走一次「是否首刷」的判断，而覆盖面自 issue #827 放开到「库内全部标的」之后，全库标的（含已清仓、纯建档未交易）每次都在名单里。ADR-0121 把现价刷新压到常数级请求之后，逐标的请求只剩「补历史」一个理由——耦合失去了它的理由。

伴随的既有缺陷：首刷判据是「磁盘上有没有历史行」这个布尔量，而写入是逐周点自动提交的。单只基金的回填若在途中被打断（应用退出、网络失败），会留下半根历史，此后「有历史序列」恒为真，缺失的早期历史**永远不会再补**；部分页被风控拦截时更隐蔽——代码只记警告就继续落库。这是静默数据缺失，而后台化会让「打断」从异常变成常态。

## 决策

### 1. 解耦：日常只刷现价，历史由独立过程采集

日常刷新只承担现价（走 ADR-0121 的批量取数面）；价格历史由独立的后台补全采集。价格历史的覆盖面、周采样口径（每周至多一条、取该周最后一个有报价交易日、整周覆盖幂等）与窗口（近两年）全部不变——改变的只是「何时采集、谁触发」。（本句只辖**标的**价格；汇率序列的窗口与来源自 2026-09-19 起独立于标的，见 ADR-0019 修订记录）

### 2. 当周点位由现价刷新的批量取数直接落采样，逐只采集只服务首刷与缺周点

批量取数面每次刷新都已携带每只基金的当日单位净值与净值日期（场内通道携带最新价），而周采样要的正是「该周最后一个有报价交易日的价格」。因此**当周采样点由日常现价刷新直接落库**，不另发逐只请求；逐只采集只服务两种情形——**首刷**（没有任何历史序列，取近两年窗口）与**缺周点补齐**（水位落后当前自然周超过一周，例如应用几周未开）。若不这样切分，每日全库逐只请求会把刚降下来的秒级日常重新推回分钟级。

### 3. 后台补全：无用户入口、自动触发、跑到队列空

价格历史后台补全由系统自动触发：应用启动后延迟启动一次，此后每个自然日窗口再跑一次，跑到队列空为止。**不给用户任何触发入口**：「同步标的信息」按钮与后台每日现价刷新都只刷现价，不再承担首刷。（同日例外：汇率序列另设设置页手动同步与每日自动两路，理由见 ADR-0019 修订记录）

### 4. 静默可见：只给纯计数

后台补全有且只有一个用户可见面：进行中的标的级完成计数。它不占用全局忙碌条、不打断任何操作、不可点、不改变任何页面的可用性，终态静默收起。标的级进度口径（分母 = 有通道标的数、跳过行不计）与 ADR-0095 同源；基金首刷的页级明细随首刷深回填一并迁到本任务——它服务的是逐只翻页的长等待，而现价刷新已无长等待。

### 5. 走势空态三态化

走势面板的空态不再指向按钮（否则是按了没反应的死路）：按补全状态分三态——**补全中**（带计数）/ **补全失败待重试** / **无数据**（该标的确实没有可采的历史序列，如查无此码）。

### 6. 额度让路与在途槽位分离

后台补全与前台请求共享同一全局限速器（总量不超数据源可承受量级），但前台请求在途时后台退让；后台补全**不占用**「用户动作在途唯一」的槽位——那条承诺是为用户可见动作防重复点击而设，不该顺带管辖系统自己的任务。

### 7. 续做靠派生事实，不建任务状态

补全队列 = 「有价格通道但历史不完整」这一派生事实，不落任务表、不新增持久状态。应用退出即硬停，下次启动重新挑选未完成的继续——双写即双份真相，而派生事实天然自愈。

### 8. 单只原子：一只一事务

单只标的的历史回填改为**整只一次提交**（全成或全不成）：失败或中断保持「历史不完整」，下次自然重试。由此「有历史」与「历史完整」重新等价——首刷判据（ADR-0038 决策 6）依赖的正是这个等价。被拦截的部分页同理：宁可整只留空重试，不留半根历史。

### 9. 覆盖面与排队顺序

覆盖面保持「库内全部标的」（issue #827 不变）；排队顺序持仓优先——先让用户会点开走势图的标的可用。

## 否决

- **维持现价与历史耦合**：耦合的唯一收益是省一次请求，而 ADR-0121 之后逐标的请求只剩补历史一个理由；耦合的代价是每次同步都为全库重走首刷判断。
- **给用户一个「补齐历史」入口，或让同步按钮插队**：首刷全库的地板约数分钟量级且一次性，用户等得起；为几分钟的等待引入一套插队语义与一条新入口，是机制税。
- **让后台任务占用全局忙碌条或确定进度条**：系统自己的任务占用用户注意力，与「不打断操作」的目标相反。
- **新建持久任务队列 / 断点表**：队列可由派生事实重建，持久化即第二份真相；进程退出后没有「必须保住」的状态可丢。
- **只在用户打开某个标的走势图时按需回填那一只**：组合走势需要全库历史，按需回填会把「打开投资页」变成串行等待，首次进入要等 N 只标的各自翻页。
- **退出时等后台任务跑完**：退出不该被网络等待拖住；单只原子已保证被打断不留半根历史。
- **先做后台化、后修半根历史**：后台化会把「打断」变成常态，此时不修等于批量制造静默缺失；修复是本裁决的前提而非附带。
- **每日对全库逐只跑一次增量**：会把已降到秒级的日常重新推回分钟级；当周点位改由现价刷新的批量取数落采样（决策 2）。

## 后果

- 用户可见：首次同步后现价立刻可用，走势历史在数分钟内由后台补齐；空态文案三态化（中英同步）。
- 词汇表修订：「PriceHistory」的「采集单通道」「回填历史同时也是刷现价」表述退场；「InstrumentInfoSync」收窄为现价刷新（批量取数面 + 降级 + 手动与每日后台两种触发）；新增「价格历史后台补全」；「价格过期提示」补一句与本任务的分工。
- ADR-0019 的上述口径被本裁决推翻；ADR-0038 决策 6 的首刷判据维持，前提补为「单只写入整只原子」；ADR-0095 的标的级分母口径维持，页级明细与「首刷深回填」的归属迁至本任务。
- 投递纪律：补全编排与其进度事件归行情同步域；启动接线收进壳层既有的后台服务单点（与自动备份调度、多端同步触发同一名单守门），新增后台任务必须进该单点，否则守门脚本变红。
- 新增三条守门判据：①删除后台补全的启动接线 → 历史不再补齐，接线型断言红；②回填改为逐周点提交 → 中断用例留下半根历史，测试红；③后台任务占用前台在途槽位 → 「前台同步不被后台任务拒绝」的断言红。
- 首次开应用的数分钟内，投资页走势曲线可能只有部分标的有点——这是本裁决明确接受的中间态，由空态三态与计数解释。
