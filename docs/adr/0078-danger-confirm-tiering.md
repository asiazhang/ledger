# ADR-0078: 危险操作确认应用内分级——原生 confirm 清零与 error/warning 两级形态

- 状态：已接受（已实施：试点 #650 落地封装与设置页加密卡两处，#652 清零剩余四处）
- 日期：2026-09-05
- 作者：Ledger 项目
- 关联：ADR-0075（决策 2/7 应用内确认弹窗先例与无后门口径）；ADR-0035（弹层注册表——AppModal 上报，新封装零新机制继承）；ADR-0007（RestoreSafetyBackup，恢复确认的兜底语义）；ADR-0016（受管备份滚动清理，清理确认的常规语义）

## 背景

危险操作（不可逆、破坏性或高风险配置转换）的确认形态在仓库内分裂为两套。ADR-0075 决策 2/7
已把开启加密与恢复备份的确认升级为应用内弹窗（EnableEncryptionConfirmModal 红色确认、
RestoreConfirmModal 跨模式警告与口令就地重试），理由是系统原生 confirm 对话框无法承载后果
说明、加粗警示与就地重试等语义；但同批落地后遗留五处危险确认仍走原生 `confirm()`——设置页
四处（修改主口令、关闭加密、手动清理备份、接管已有库）加解锁屏一处（忘记口令重置）。其中
修改主口令与开启加密风险同级（遗忘新口令同样数据不可读），确认强度却是最弱一档；两种确认
形态在同一设置页混用，视觉与交互语言分裂。危险相关控件的视觉权重也与操作危险度、使用频率
错位：恢复入口 error 实心大按钮常驻，而恢复卡的破坏性警示文字是全页对比度最低的灰字
（`NText` depth 3），清理备份（不可恢复的删除）是默认灰小按钮。经 grilling 定稿如下。

## 决策

### 1. 形态收口：模态危险确认一律应用内弹窗，原生 confirm 清零

- 审计时点全部五处原生 `confirm()`（`useBackup.ts` 清理、`DataLocationSettings.vue` 接管库、
  `EncryptionSettings.vue` 修改主口令与关闭加密、`UnlockScreen.vue` 忘记口令重置）迁入应用内
  弹窗；此后新增危险操作不得使用系统对话框确认。plugin-dialog 依赖保留（`open`/`save` 的
  文件选择仍在用），仅 `confirm` 用法清零。
- 封装基于既有 AppModal 薄封装：遮罩不关、✕/ESC 关闭与弹层注册表上报自动继承，零新弹层机制。
- **备选与否决**：继续原生 confirm（承载不了分级视觉与后果说明，样式不受控、与 i18n 字体
  不一致）；各调用点手写 AppModal（六处复制粘贴，视觉漂移，测试面重复）。

### 2. 两级形态：error 与 warning，判据是「错误执行的代价与可回退性」

- **error 级**：不可逆，或回退需依赖用户无感知的隐藏通道，或核心数据面临不可读风险。成员：
  开启加密、修改主口令（遗忘口令即数据不可读、无找回手段，与开启加密同级）、忘记口令重置
  （清空数据）、恢复备份（替换当前全部数据；恢复安全备份在应用数据目录、命名对用户不可见，
  不构成用户认知内的回退通道）。形态：红色警示块（NAlert error）＋加粗后果句＋红色确认按钮；
  后果说明必选。恢复备份为独立组件（口令输入＋失败就地重试，ADR-0075 决策 7 在案），视觉与
  error 级对齐，不迁入共享封装。
- **warning 级**：破坏性但有兜底或影响可再操作。成员：关闭加密（旧密文副本保留、可再开启）、
  手动清理备份（滚动清理是 ADR-0016 常规语义，删除的是可再生的备份产物）、接管已有库
  （原位置库文件保留，无破坏）。形态：warning 色确认按钮＋后果与兜底说明。
- **备选与否决**：单一形态加重警示（低危确认被迫承受红色恐吓，狼来了效应）；按域各定各级
  （跨页不一致正是本决策要消灭的对象）。

### 3. 共享封装：AppDangerConfirmModal 承载纯确认场景

- props：level（error | warning）、标题、说明段、加粗警示段（error 级常用）、确认/取消文案、
  submitting；纯确认、不带输入。五个迁移点（修改主口令、关闭加密、清理备份、接管库、忘记
  口令重置）迁入，EnableEncryptionConfirmModal 一并迁入并卸任独立组件。
- **范围边界**：本决策只收口**模态危险确认**。RestoreConfirmModal 保持独立（见决策 2）；
  行级删除的气泡确认（AppPopconfirm，预算/物品/实物资产/保单/商户/分类/计划行在用）是既有
  应用内轻量形态，不在本决策范围。

### 4. 危险视觉语言按「使用频率 × 不可逆度」重排

- 按钮存在感与两因子对齐：恢复入口按钮从 error 实心降为 default 形态（红色警示由确认弹窗
  承载，双闸不变——恢复前自动安全备份＋确认弹窗）；恢复卡警示文字从最低对比度灰字升为
  NAlert 警示块；清理按钮升为 warning 次要形态。
- 上限调小立即清理**不确认**维持不变（ADR-0016 既有语义：滚动清理是常规行为；数字输入框
  blur/回车提交，无键入中间态误触发）。

## 代价与边界

1. 实施面全部在前端：新组件＋i18n 文案＋六处调用点迁移＋三处视觉重排；无后端契约、schema、
   AI API 变化。主口令最小长度（≥8，走 ADR-0058 字段错误态）与设置页其余人体工学修正
   （复制通道、布局限宽、自动解锁交互、卡片顺序等）是本批 grilling 的同批实现清单，不属本
   ADR 决策面。
2. 原生对话框模态确认自此在本仓库无存量、不容新增；评审新增 `confirm()` 引用应被拒绝。
3. 本决策只定分级判据与形态，不定文案成稿（实施时按 i18n 既有资源风格拟稿）与组件文件
   目录（在仓库既有薄封装惯例内落位）。
