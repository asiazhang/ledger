## 背景

多端同步轮次（SyncRound，见多端同步域）在主连接锁内完成全部通道网络等待：三个生产入口——手动「立即同步」、打开应用即同步、桌面低频轮询 + 写后触发——都先拿唯一的主连接锁，再由轮次编排持 `&Connection` 依次做完读位点、逐段上传、manifest 读写、逐流读、逐段下载、逐条重放、落「上次成功同步时刻」。

这与 ADR-0069 决策 4 的明文纪律正面冲突：网络等待期间，本地记账、批量导入、定时追补与读命令全部排队。冲突之所以留到今天，是因为轮次侧的明文决策另有出处——多端同步域 SyncRound 词条的边界、壳层同步命令模块的调用契约、ADR-0098 的触发时序口径——都写着「轮次期间持主连接锁」，理由是「通道轮次的发布 / 拉取 / 重放本就要求互斥，Checkpoint 成对约束同源」。ADR-0069 决策 4 的纪律在标的信息同步上已被 #1276 收窄并守门化（分段取锁、整体裁决），轮次是同一根因的最后一个大现场；spec #1274 把它列为范围外单独立项，#1278 盘点给出的分类是**需裁决**（分析倾向：网络部分属纯网络等待、数据库步骤保持互斥）。

两方证据都成立，取舍点只有一处：轮次顺序性到底由**连接锁**承接，还是由**轮次自身的互斥**承接。

**支持整轮持锁的证据**：①manifest 是通道上唯一整体替换的文件，读-改-写若并发会丢更新，锁是当时唯一的串行手段；②位点与快照「同刻成对」的既有约束与轮次同源同锁；③「失败上抛不产生部分本地状态」的表述以整轮单锁为前提；④三个触发源彼此独立，只靠这把锁串行。

**支持出锁的证据**：①网络叶子（manifest GET/PUT、段 PUT/GET）签名不含连接、不消费连接；②TotalOrder 是批次内确定性排序，判定键 `(逻辑时钟, DeviceId)` 全量携带于 op 信封，不依赖本机状态与实时互斥；③重放逐条原子（命令执行与 op 落日志同事务），归宿（应用 / 期次去重 / LWW 压制 / 已知跳过 / 挂起）保证重复与乱序投递安全；④#1276 已用「分段取锁、整体裁决」把同类网络路径移出锁并上线守门；⑤ADR-0117 落地后读路径已不经写者闸门，整轮持锁此刻挡的是本地写路径。

## 决策

### 1. 轮次网络等待出锁：判定为纯网络等待

轮次内的通道网络 I/O（manifest 读 / 写、段上传、段下载）**不消费连接**，不构成 TotalOrder 或重放的顺序性要求，一律在连接锁外完成。ADR-0069 决策 4「网络往返任何形状下不得进锁」对轮次同样成立——轮次不享有例外。

「须在单连接互斥锁内」的旧表述在多端同步域 SyncRound 词条与壳层同步命令模块注释两处的收窄口径见决策 7。

### 2. 连接锁只盖数据库步骤：轮次分段取锁

轮次拆成互斥段与网络段交替，**每一处消费连接的动作各自短取一次锁**，不再是「一轮一次长锁」：

| 段 | 内容 | 持连接锁 |
|---|---|---|
| 读段 | 本机 DeviceId、位点、自己流待发布 op 的读取 | 是（短） |
| 重放段 | 逐段下载后对已解封 op 的重放（逐条事务） | 是（逐条 / 逐段短取） |
| 落库段 | 「上次成功同步时刻」的设置写入 | 是（短） |
| 通道段 | manifest 读 / 写、段上传、段下载、封包与解封（含 KDF） | 否 |

取锁失败的语义：任一段取不到连接锁即**整体放弃本轮**（自动轮次静默跳过、手动轮次上抛）——放弃只终止后续段，此前已提交的重放与已上传的段按决策 6 各自原子留存（「放弃」不是回滚前缀）；下一轮按既有幂等续作。

### 3. 轮次在途互斥：轮次顺序性的承接者不再是连接锁

三个触发源彼此独立（手动、打开即同步、桌面轮询 / 写后触发），此前只靠连接锁串行。出锁后必须由轮次自身的互斥承接顺序性，收口为域内单点**轮次在途互斥**：

- 同端同库任一时刻**至多一轮在途**；
- manifest 的读-改-写（含随后的段命名与位点推进序列）由轮次在途互斥独占，丢更新从「靠下一轮归并自愈」升级为结构性不发生；通道层既有的「并发整体替换由下一轮再发布自愈」纪律保留为**纵深兜底**，不因本裁决撤销；
- 手动入口在途时**不启动第二次**：重复触发复用唯一在途轮次，与 ADR-0095 前端「进行中重复触发复用唯一那次在途同步」的既有口径同款；回显形态（等待并交出同一轮次报告 / 即时返回「已在同步中」状态）随实施票定，但用户可见语义是「重复触发不产生第二轮」；
- 轮次在途互斥与本地写路径无关：本地写不被轮次在途挡住，轮次在途也不放弃既有「拿不到连接锁即跳过」的本地写让路口径。

### 4. 入口形态：手动走分段写入口，调度侧同形分段取锁

手动「立即同步」复用 #1276 已落地的分段写入口形态（分段取锁、整体裁决）：仍是**一个写操作身份、一次提交点置脏、一次信号发射**，跨分段累积的「是否实际写入过账本数据」在整体裁决点一次性生效；不再经整轮持锁的调用形态。

调度侧（打开即同步、低频轮询、写后触发）与手动入口同形：每段各自取锁，任一段拿不到锁即放弃本轮（既有「拿不到锁就跳过本轮、不阻塞业务写」的口径保留）。

### 5. 交错粒度：保持逐段下载 → 逐段重放

不改为「先整轮下载、再整轮重放」：逐段交替使内存占用以单段为界（段容量有界），失败中途的带宽浪费以段为界；重放按段短取锁即可满足互斥。取锁次数的增加是毫秒级成本，不足以换取整轮内存驻留。

### 6. 失败语义重述：整轮单锁前提退场，三分表述接手

旧表述「失败上抛不产生部分本地状态」以整轮单锁为前提，按下列三分重述：

- **已上传段原子**：段按内容时钟区间命名、op 只增不改，重传同段内容确定等同——清单写回失败或中途放弃后重试，上传断点自然续作；
- **已重放 op 逐条原子**：命令执行与 op 落日志同事务，失败点之前的重放已提交、失败点之后未发生，重投递按既有归宿（应用 / 期次去重 / LWW 压制 / 已知跳过 / 挂起）幂等收敛；
- **manifest 回写失败由下一轮归并续作自愈**（通道既有纪律，本裁决不新增机制）；
- 「上次成功同步时刻」只在整轮成功后的整体裁决点落库，中途放弃 / 失败不更新。

### 7. 配套明文文字的修订清单与载体

本裁决要求下列文字随之修订，**载体是实施票 #1339**（不在本裁决票内落地）：①多端同步域 SyncRound 词条的「轮次期间持主连接锁」边界；②壳层同步命令模块中「轮次期间持主连接锁」的调用契约注释；③通道层调用契约与 ADR-0098 决策 2 中「与轮次同一互斥约束」「轮次拿锁后读」的措辞。

**载体分离的理由**：词汇表与契约注释描述的是可验证行为，两者与行为不一致时以行为为准（见 `CONTEXT-MAP.md` 结构约定「行为以代码为唯一事实来源」）；先改文字后改行为会让文档短暂失真。#1276 把 InstrumentInfoSync 词条边界随实现票改、#1279 → #1280 把路线 B 的决策与实施分票，是同一先例。

### 8. 边界：本裁决只辖轮次

- Checkpoint 发布（#1284）与引导快照下载（#1285）是独立现场：它们的成对性约束只为「快照产出段」而立，上传 / 下载属网络等待；本裁决给出的判据（网络出锁、成对性只要求产出段）是其重述依据，但两条现场的裁决与文字修订各归其票。
- 预检读出锁（#1283）不依赖本裁决，可先行。
- 通道布局、manifest 归并纪律、信封形态、触发时机参数、Checkpoint 引导语义、挂起语义全部不变。

## 否决（防重复提案）

- **维持整轮持锁**：需要推翻 ADR-0069 决策 4 与 #1276 的三重守门，且 ADR-0117 落地后轮次整轮持锁挡的是本地写路径（记账 / 导入 / 追补），代价与收益不对称——出锁不产生正确性损失（重放逐条原子 + 段幂等 + manifest 归并自愈），而轮次时长由网络决定、不可控。若将来出现「manifest 丢更新不可自愈」的真实反例，回退点是给 manifest 加条件写（ETag / If-Match 一类），不是回到整轮持锁。
- **manifest 读-改-写也出锁、且不做轮次在途互斥**：把「同端两轮时间重叠导致 manifest 丢更新」从理论窗口变成常态（三个触发源彼此独立），丢更新只靠下一轮自愈；省下的只是一次进程内互斥，不值。
- **先整轮下载后整轮重放**：内存随积压量增长、失败中途带宽浪费更大，换来的只是少几次毫秒级取锁。
- **为网络隔离引入专用线程 / 端口反转**：网络叶子本就不消费连接，专用执行体解决的是调度与生命周期，不是本裁决的形状问题；ADR-0112 决策 5 已定「不为消除合法依赖引入端口 / 事件反转」，同类机制不因本轮次裁决翻案。
- **仍借连接锁串行轮次（只把网络挪出锁）**：连接锁是本地读写互斥，借它串行同端两轮会让本地写再次被整轮时长挡住，与出锁目标自相矛盾；轮次互斥须由独立守卫承接。

## 后果

- 裁决落地后（随实施票 #1339），多端同步轮次在途时本地记账、批量导入、定时追补与读不再被整轮同步挡住；同步自身的进度、挂起与失败语义不变。
- 新增一条接线型约束：全部轮次入口（手动、打开即同步、低频轮询、写后触发）都须经轮次在途互斥。实施票须以「删除接线即变红」的负向判据钉住（ADR-0087）。
- 轮次的段边界成为新的评审面：新增轮次步骤必须显式归类为「数据库段（取锁）」或「网络段（出锁）」——分类缺失即 ADR-0069 决策 4 的旧退化路径重现。
- 失败语义的表述变长（三分），评审按段核对，不再有「整轮单锁」这一句兜底。
- 实施票 #1339 同时修订决策 7 列出的三处文字，并补上守门（连接锁跨度探针已有，#1276 引入）与负向判据。
