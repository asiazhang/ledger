# ADR 0026: 余额调整采用黑洞转账机制

- 状态：已接受
- 日期：2026-09-15
- 作者：Ledger 项目

## 背景

账户界面新增「调整余额」功能（对账后把余额校准到目标值）需要选择实现机制。候选：① 差额回填 `initial_balance_cents`（期初余额锚点）；② 新增 kind `adjust`（闭集扩列，已发布 schema 只增不改）；③ 借用 income/expense + 专属分类；④ 生成一笔与黑洞账户（AI 导入域 BlackHoleAccount）之间的转账。

## 决策

采用 **④ 黑洞转账**：目标余额 − 当前实时余额 = Δ，Δ>0 从「无」转入、Δ<0 转出至「无」，交易币种取目标账户自身币种；删除该转账即撤销调整。黑洞账户缺失币种时运行时按需自动创建（`无(XXX)`、type=`other`、`is_hidden=1`，与种子同形）。调整日期默认今天、可改。

## 理由

「调整余额」在领域上就是「钱凭空出现/消失」，与黑洞账户既有语义（承接来源不明资金变动）完全同构——AI 导入中 `资金账户=无` 的交易已走同一通道，不引入第二口径。且：零 schema 改动（①②都需要动数据模型，②还要扩 kind 闭集与符号矩阵）；不污染收支统计（transfer 不进 expense_net/income_net，③被否的主因）；留痕可撤销（①无痕，期初余额被静默覆盖，放弃的主因）；仪表盘余额合计排除黑洞账户，不受影响。

## 代价

1. 交易列表会多一条与「无」的转账记录——视为 feature（可见即可撤销），但用户需理解「无」的含义。
2. 「把余额改成 X」后若账户还有待导入的历史交易，口径以实时计算为准，调整不锁定余额。

## 替代方案

- **① 差额回填期初余额**：最简单，但无痕、「期初余额」语义被覆盖，将来若需追溯无法升级恢复，放弃。
- **② 新增 kind `adjust`**：留痕最完整，但已发布 kind 闭集扩列需迁移改 CHECK + Amount 接缝矩阵加行 + AI 导入知识同步，成本远超收益，放弃。
- **③ 借用收支分类**：不动 schema，但污染收支统计报表，直接放弃。
