# ADR 0087: 测试三层权威层——域语义归域单测、壳语义归 API 集成测试、旅程归 e2e BDD

- 状态：已接受（grilling 定稿，2026-09-07 两轮）
- 日期：2026-09-07
- 作者：Ledger 项目
- 关联：spec #730（本文档来源，测试架构评审 2026-09-06 姊妹 spec #728–#732 之一）；#732（无效测试清理——错误契约删除分工见决策 6）；ADR-0084（统一测试数据库工厂——API 集成造数的静态基线）；ADR-0086（公开写入口（测试侧）——e2e 造数纪律，本决策 API 侧与之同构）；ADR-0056（后端域/壳/基础设施分层——测试划界随产品分层）；ADR-0050（错误码化只增不改——契约代表的契约面）

## 背景

测试架构评审（2026-09-06）发现同一域行为在两三层各测一遍：lot 清理域语义在 API 集成测试展开约 90 行且直调 `create_transaction_internal` 凑场景；金额折算在 API 层插真实汇率重算断言精确值（域测中折算是通篇主题）；余额按类型计入矩阵域测已有全类型清单，e2e 却直插分红流水凑场景再验一遍；迁移链路 API 侧 588 行与 e2e 224 行近乎平行复刻；「交易不存在」同一错误场景在三个层四处断言。重复的根因不是谁多写了一个测试，而是三层各自的职责从未明文划清，新测试默认复制错误层位的样板。

grilling（2026-09-07）对评审草稿修正三处（以代码为准）：

1. 「迁移编排」真相：域内写入编排（TransactionBatch 批量写入、幂等键、批次汇总）与投资买卖域语义（建仓、FIFO、PnL、折算）的域测权威覆盖**均已存在**；两层近乎复刻的只是「搜索→建标的→批量导入→读回」链路，而链路是用户操作序列，产品代码中**没有单一编排函数**可供域测驱动——链路权威归 e2e 旅程，不是域单测补新用例。
2. 评审所记「直调内部创建函数」坐实为未公开内部函数（名即 `…_internal`）；造数替代形态 = 统一测试数据库工厂（ADR-0084）静态基线 + 域层公开函数行为前置，与 e2e「公开写入口（测试侧）」纪律同构，零新机制。
3. 错误契约删除主导权：#730 与 #732 原文互相矛盾（各说归对方），定稿为 #730 主导删除、#732 只处理「断言强度为零」类，两票共享核对清单。

## 决策

1. **三层权威**：Rust 侧测试分三层——域单测、API 集成测试、e2e BDD，每层只断言所在层的 interface；断言归属的判定标准是「这条断言失败时，修复应落在哪一层」。域行为唯一权威 = 域单测（写入编排、金额折算、余额按类型计入、删除清理副作用、查询语义）；API 集成测试只测壳三件套（参数解包、状态码、错误码）与壳层接线（门禁行为、信号交接、桩注入装配）；e2e BDD 只测跨模块用户旅程与门禁交互。同一域行为只允许一个权威层，跨层重复覆盖即回潮，其余层至多保留视角性少量断言。术语正名：「API 集成测试」为唯一名（spec 原行文「HTTP 集成测试」废弃）。
2. **接线证明**：API 集成测试中域语义允许出现的唯一形态——一步可观察证明：请求经接口进入写入接缝并产生直接可观察结果（创建返回成功且资源可读、删除返回成功且再读不存在）。存在性的出现与消失属证明范围；折算数值、余额数值、清理明细行、状态派生等域结果细节不属证明范围，归域单测，展开即越层。
3. **API 集成造数纪律**：静态基线走统一测试数据库工厂（ADR-0084），行为前置经域层公开函数；禁调未公开内部函数。与 ADR-0086 e2e「公开写入口（测试侧）」纪律同构、分层互斥、互不消费。
4. **e2e 凑场景三分法**：纯复刻（域测已有权威覆盖）→ 整场景删除；有旅程价值 → 保留场景、造数改经公开写入口；仅断言重复 → 删断言留场景。「不改 BDD 场景措辞」约束解释为不重写保留场景的业务语言与场景名，整场景删除不属「改措辞」。旅程收缩线与接线证明同构：旅程终态可断言（持仓读回、余额读回），中间域细节不展开（每笔 PnL 精确值、批次去重明细、成本锚定值）。
5. **迁移链路编排权威 = e2e BDD 旅程**（背景修正 1 的结论）：API 侧收缩为按端点壳三件套 + 接线证明（400-not-500 之类错误形态断言保留、域语义展开删除）；e2e 保留旅程、收缩域语义精确值断言。
6. **错误码契约唯一化**：错误码契约测试维持「锁定三代表形态（400 无参、400 带参、404）、只增不改」声明，是 API 层错误 **HTTP 形态**的唯一权威；错误**语义**（错误枚举与触发条件）的权威归域单测错误枚举测试。场景文件仅在错误路径是主语义（该用例的存在理由）时保留最小断言，顺带断言一律删除。重复断言删除由 #730 子票主导执行，#732 只处理断言强度为零类；两票共享核对清单。
7. **修剪判据与范围**：先补后删——每个被删断言须先在权威层找到或补出等价覆盖，逐条核对清单随 PR（被删断言 → 权威层等价坐标，或标注移交 #732）；验收定性：全量测试保持绿 + 清单逐条有着落；「测试总量下降」是结果性指标，不设数值门槛。修剪范围以评审证据为界（lot 清理、折算、余额矩阵、迁移链路四主题 + 错误契约重复断言），全库按新规则扫荡另立后续 spec。

## 备选与否决

- **迁移链路补域测编排用例**（权威放域单测）：链路是用户操作序列、产品代码无单一编排接缝，域测只能按序调公开函数复刻旅程——层位错置；域内各环节已各有权威覆盖。
- **API 集成造数只走 HTTP 端点自举**：部分前置状态经接口不可达或多步凑取成本高；种子工厂 + 公开函数与 ADR-0084/0086 既有接缝衔接。
- **契约代表扩为全错误码清单**：退化为第二份错误枚举测试，重新制造跨层重复，违背唯一权威。
- **全库一次性按新规则扫荡**：涉及数十个 feature 的生死判定，单次改动风险高；规则先立、证据先修，扫荡待规则运行一段后另立 spec。
- **沿用「HTTP 集成测试」正名**：一词二名违术语全库唯一；既有文档与 ADR-0084 已用「API 集成」。

## 影响

- 修剪落地后：lot 清理、折算、迁移链路的跨层重复删除，API 集成场景文件短小、意图明确；域语义变更只改权威层一处，口径漂移无处藏身。
- 新测试默认落点随 AGENTS.md 测试小节改写生效：域行为 → 域单测；壳行为 → API 集成测试；跨模块旅程 → e2e BDD。
- 词汇落测试基础设施域（`CONTEXT-testing.md` 新增测试三层与权威层、壳三件套、接线证明、错误码契约代表四条）。
- 产品代码、schema、IPC/HTTP 契约零变化；「已发布契约只增不改」不受影响。
- 落地：spec #730 子票 T1–T4（拆分见 issue 正文）。
