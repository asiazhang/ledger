# ADR 0085: 前端 invoke 测试接缝唯一化——组装接线一体入口、全局清理与未命中报错基座、手写桩全量迁移

- 状态：已接受
- 日期：2026-09-07
- 作者：Ledger 项目
- 关联：issue #727（spec，grilling 定稿）；实施票 #746（深化与全局基座）、#747/#748/#749（迁移批次 A/B/C）、#750（收尾与守门）；同批测试架构评审姊妹 spec #728/#729/#730/#731/#732；先例 #725（参考替身收口）、#726（重复桩守门）

## 背景

前端 142 个测试文件中，54 个各自手写 invoke 命令分发桩（264 处命令名分支；本地布线包装 `baseInvoke` ×22、`stubInvoke` ×5、`mockBaseCommands` ×4），7 个文件自造了与共享帮手同语义的本地副本。共享帮手 `invokeHandler`（9 个使用者）已有「defaults + overrides + 参考数据兜底 + 未命中 reject」语义但只组装不接线，调用方还得自己挂替身；`stubReferenceInvoke`（#725 产物）组装接线一体却只覆盖参考命令。全局壳层零钩子：桩复位散在 74 文件、本地存储清空 36 文件、文档体清空 33 文件、消息断言实例自建 11 文件；全局 invoke 替身无默认实现，未布线命令返回 undefined 后以产品代码 TypeError 崩溃，难定位到命令名。9 个帮手使用者仍在 defaults 表手工重列 5 个参考命令（兜底已内建），28 文件枚举 `list_currencies`；按钮查找同构副本 ≥6 份、内联写法 20 文件 75 处。改动热度：设置域测试文件近 4 个月 31 次改动居全部测试文件之首。来源：测试架构评审（2026-09-06，产出 #727–#732）。

## 决策

1. **唯一接缝，组装接线一体**：invoke 测试布线收敛为唯一定义点，一次调用内部完成替身挂载与每测清理注册，返回分发器供一次性覆盖与调用事实断言（`stubReferenceInvoke` 已验证的形态）；既有求值序不变——overrides 表 → defaults 表 → 参考数据兜底 → 未命中 reject，既有使用者语义零迁移成本。defaults 表只收静态值（命令契约快照）、overrides 表可含函数（计数、按参分支、一次性失败）的两表分工是接口语义的一部分，保持。spec 初稿「三个动词」措辞按现实对齐为单入口两表。新出口函数命名实现自定，术语锚定词汇表「invoke 测试接缝」。

2. **清理四件套入全局壳层**：桩复位、本地存储清空、状态容器重置、消息接口清零（随同文档体清空与组件卸载）由全局壳层每测自动执行，对全部测试文件生效；测试文件级同类样板随迁移删除。这是把散在 74/36/33/11 个文件的清理实现沉回共享层，个别文件若依赖跨测隐式状态会被全量保持绿判据暴露，就地修。

3. **未命中报错基座下沉全局**：全局替身默认实现 = 按命令名 reject「unexpected invoke: <命令名>」（全局 beforeEach 桩复位后重挂）。这是本决策集对未走接缝测试的唯一行为变化：从 undefined 引发的 TypeError 崩溃变为报出命令名的明确拒绝，纯改善；走接缝的测试覆盖之。

4. **消息替身改每测稳定实例**：消息接口全局替身从「每次调用返回新实例」改为「每测发放同一稳定实例 + 全局自动清零」，经测试助手出口获取。仍是全局替身统一替换，只变发放策略，不动 ADR-0084 所依赖的全局替身机制本身；11 个文件自建稳定实例的样板随迁移删除。

5. **参考数据预热分两层**：桩层兜底必做——五个参考字典列表命令由接缝内建规范夹具（含正常行与软删行）应答，测试不得在 defaults 表重复枚举（守门禁止）；store 层预热（预载刷新）做成 opt-in 参数、默认关——刷新时序与断言耦合，默认开启会破坏「迁移纯机械替换」判据。

6. **DOM 助手收口、flushPromises 不包装**：按钮查找（文本 / body-teleport / data-testid 三变体）与输入查找家族收进测试辅助层单一出口；异步冲刷维持直连官方导入——直连不是布线噪音，包装反增间接层。

7. **目录级共享文件薄壳化**：测试目录共享文件只承载本目录特有夹具与编排组合，通用能力一律上收测试辅助层，禁止薄壳再生长通用能力（防共享层双轨生长）。与 #728（Rust 测试数据库工厂）「域薄皮 + 通用上收」的分层关系同构。

8. **迁移策略：纯机械替换 + 先热后冷**：以「全量既有测试保持绿」为行为等价判据，迁移不引入断言语义变化；唯一例外通道是隐式依赖显式化（依赖 undefined 态的用例被未命中报错基座变红后按语义补布线）。批次顺序先热后冷：批次 A = 设置域 7 文件（最热，兼任接口试金石，缺陷回深化票修）；批次 B = 三个目录级共享目录薄壳化；批次 C = 根目录余量（可拆多个 PR）。**领域数据工厂（造交易/计划/账户构造器）不并入本 spec**——构造器签名设计属语义工作，混入会破坏机械等价判据，另立 spec（与 #728 平行）。

9. **防回潮守门**：迁移全部完成后给既有守门脚本 `scripts/check-test-stubs.ts` 增规则——测试辅助出口之外禁止手写 invoke 分发桩形态与本地布线包装定义（特征串以迁移完成后残余形态为准）；豁免范围与既有规则 1 相同（测试辅助目录自身）。新建独立守门脚本的路线不取——守门规则同域聚合在一处便于维护（#726 规则 2 先例）。

## 被排除路线（防重提）

- **维持各测试自布线（现状）**：同一分发语义 54 个定义点，命令契约一变 55 处机械跟改，新测试面对布线决策而非行为断言——正是本决策要消除的形态。
- **builder 式三动词 API**：与既有单函数两参形态不符，9 个既有使用者零收益；「三动词」仅是 spec 初稿措辞，现实语义由单入口两表承载。
- **数据工厂并入本 spec**：见决策 8，机械等价判据优先。
- **清理只进接缝、不进全局**：未走接缝的测试继续互相污染，用户故事 5（用例间交叉污染不再因遗漏清理发生）只兑现一半。
- **flushPromises 包装**：见决策 6。
- **未命中保持静默 undefined 态**：崩溃信息不含命令名，排查成本高；「静默通过」风险虽低但报错基座同时提供「命令面显式声明」语义。

## 代价与边界

1. 迁移期新旧双轨并存（薄别名兼容既有使用者），由 #750 收尾删除；收尾前守门规则 3 不启用，双轨窗口期内共享层可能被再抄本地副本——以批次推进节奏控制窗口时长。
2. 全局清理使「文件间隐式共享状态」无所遁形：个别文件可能暴露对执行顺序或模块级状态的依赖，需就地修；这是显式化收益而非回归。
3. 未接线测试若被测组件真调未布线命令，行为从 undefined 崩溃变为含命令名拒绝——两者都是红，后者可诊断；不存在「原本绿、现在红」的静默面。
4. 目录薄壳的「禁长通用能力」无自动守门（规则 3 只禁手写分发桩与本地包装），靠评审约定维持；若薄壳再次膨胀，升级守门规则的选项保留。
