# ADR 0025: 物品创建唯一入口与自包含成本

- 状态：已接受
- 日期：2026-08-28
- 作者：Ledger 项目

## 背景

ADR-0014 已定物品（Item）为独立领域实体、自包含总成本、金额复用 Amount 接缝。但「物品从哪来、是否允许无交易物品、成本如何聚合」这组**创建侧语义**当时未完全定稿，ADR-0014 决策 #3 表述为「关联购买交易**可选**、允许没有对应交易的物品（赠品/旧物）」。

#113 修订后明确：**创建唯一入口 = 交易右键「加入物品」+ 确认弹窗**，`source_transaction_id` **必填**，无交易物品**不可录入**，且不建「交易→物品」反向引用。本 ADR 记录该修订，并**修正 ADR-0014 决策 #3**（可选 → 必填）。

## 决策

1. **创建唯一入口 = 交易右键 + 确认弹窗**：前端在交易列表对 `expense` 交易右键「加入物品」，确认弹窗自动带出购买日期 / 基础成本 / 币种（名称默认取交易备注、可微调），确认后调创建命令。**不提供任何手动新建物品的表单。**
2. **`source_transaction_id` 必填、唯一**：后端强制校验——交易存在且未删除、为 `expense`、**同一交易不可重复创建物品**（溯源唯一）。
3. **无交易物品不可录入**：赠品、旧物等无对应购买交易的物品不建库；物品必须源自一笔 `expense` 购买交易。
4. **自包含总成本（不自动求和）**：`total_cost_cents` 创建时从购买交易带出，后续花费（维修/配件/运费）由用户**编辑总数**累加；**不**由系统对多笔交易求和，也**不**建立「交易→物品」反向引用。
5. **修正 ADR-0014**：决策 #3 由「可选关联、允许无交易物品」修订为「必填溯源、无交易物品不可录入」。ADR-0014 的其余决策（独立实体、自包含成本、金额接缝、独立领域、UI 视图、不发 AI HTTP API）维持不变。

## 理由

1. **为什么不做手动创建 / 无交易物品**：物品是「拥有某件耐用品」的持有成本载体，不是随意字典项；无购买交易的物品（赠品/旧物）缺少成本与日期来源，强行录入会让「每天成本」主观失真。强制从交易创建，天然携带金额/日期/币种，避免二次输入出错，也保证「每天成本」分母复现口径一致（#113 US3/US14）。
2. **为什么不做交易累加后续花费**：后续花费（维修/配件/运费）若从交易自动累加，会逼着每笔后续投入都成为账本交易，且与手工记录产生双事实源（AGENTS.md 反对另立口径）。自包含 + 编辑总数，让每件物品只有它自己一个权威。
3. **为什么自包含总成本不自动求和**：与 #2 同理——避免双事实源与账本双向纠缠；物品成本与账本记账是两条线（预算 vs 持有成本），各自服务不同目的（见 #113 双记录语义提醒）。

## 代价

1. **无交易物品（赠品/旧物）不可录入**：想跟踪而没有购买交易的物品需先补一笔 `expense` 交易，或放弃跟踪。
2. **后续花费需手工编辑总数**：不能「记一笔维修账就自动摊入」，对希望全自动的用户多一步手工。
3. **与当前实现存在偏差**：现码字段为 `purchase_transaction_id`（可空）且保留手动表单，需由对应实现票对齐（见 CONTEXT-item.md「与代码的差异」）。

## 替代方案

- **允许无交易物品**（赠品/旧物可录入）：能覆盖更多场景，但缺成本/日期来源、口径失真，且与「持有成本复现」目标冲突，放弃（决策 #3）。
- **从交易自动求和累加**：全自动但双事实源 + 逼着每笔后续投入入账 + 与账本双向纠缠，放弃（决策 #4，ADR-0014 同理由）。
- **保留手动新建表单**：与「创建唯一入口」语义冲突，会绕过溯源校验、产出无交易物品，放弃（决策 #1）。
