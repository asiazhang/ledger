# ADR-0069: 后端 DB 调用 async 化——单连接互斥锁保留 + 统一阻塞线程池 helper（形状乙）

- 状态：已接受
- 日期：2026-09-04
- 作者：Ledger 项目
- 关联：spec #498（拷问与定型）、#501 / #502 / #503（三批迁移实施）、#504（收口复核票）；ADR-0032（连接层统一写入口，复核结论见下：语义零改动）、ADR-0009（连接级耗时 hook，归因约定按其预告系统化）、ADR-0060（易 panic 门禁，async 宏豁免随之扩容并整体复核）；边界先例 ADR-0047（命令注册扫描面不变）、ADR-0033（事务编排接缝不动）、ADR-0054（信号主线程非阻塞投递，阻塞线程发射安全）；前端配套 GlobalBusyBar 与本 ADR 解耦交付，词汇表见界面状态与交互域

## 背景

两条同源的缺口，由同一次拷问定型（spec #498）：

**防未来慢查询**：绝大多数 IPC 命令在界面事件循环线程同步执行 DB 调用，HTTP handlers 在 async 上下文内联持锁执行毫秒级 DB 调用、占用 tokio worker。今天查询快所以无感——V016–V018（ADR-0068 背景所述三层修复）把 50 万笔库的已知慢项压回 200ms 内——但索引与缓存只覆盖已知的读路径，数据量继续增长后任何一条长尾慢查询冻结的是整个界面，性能防线（ADR-0067 缓存、ADR-0068 门禁）都拦截不了「执行位置错误」这一层。

**工程质量**：命令层存在「长任务记得丢阻塞线程池、网络往返在连接锁外」的口口相传纪律——有注释、无机制；哪些命令会阻塞主线程全靠读代码；AI 编程助手模仿现状生成新命令时会把同步样板带回来。这条纪律随数据增长会从注释变成事故。

目标形态的候选有三：引入第三方异步驱动（tokio-rusqlite）、自建专用 DB 线程句柄（拷问期内部命名「形状甲」）、保留连接形态 + 统一 helper 把 DB 闭包放进阻塞线程池（「形状乙」）。拷问的裁定与两条否决理由记录于本 ADR，防止重复提案。

## 决策

### 1. 形状乙：连接形态不动，DB 闭包经统一 helper 进阻塞线程池

- **单连接 + 互斥锁形态原样保留**（`Arc<Mutex<Connection>>`，ADR-0009 所记形态）：不做连接池、不做专用线程，锁语义与既有审计结论继续有效；
- **连接层统一写入口零改动**（ADR-0032）：写路径仍在 `db::write` 闭包内置脏，提交点（闭包成功且 `is_autocommit()`）结构原样；
- **新增连接层统一 DB 调用 helper `db::run_db`**：内部 `tauri::async_runtime::spawn_blocking`（显式句柄）把 DB 闭包放进 tauri 全局运行时的阻塞线程池，事件循环线程与 tokio worker 不再被 DB 调用占用。显式句柄保证从 HTTP 壳自建运行时调用亦安全——返回的 JoinHandle 是跨运行时 future，生产先例 `fetch_fund_detail_for_api`；
- **零新依赖**：helper 只用既有 tauri 运行时能力，供应链与版本配对风险为零。

### 2. 迁移面：全部触碰 DB 的命令与 handlers 经 helper；不触 DB 者保留原形态

三批迁移（#501 参考数据与核心查询、#502 交易与计划域、#503 投资与基础设施 + HTTP handlers）已合入。收口扫描口径：`#[tauri::command]` 逐个分类、HTTP handlers 逐个分类，凡触 DB 而不经 `run_db` 即残留。扫描结论（#504 复核，rg 可机械重放）：

- **IPC 命令**：18 个命令壳文件的触 DB 命令全部 async 化并经 helper；写路径信号在 await 后发射（ADR-0044 映射单点不变，ADR-0054 主线程非阻塞投递使阻塞线程发射安全）；
- **保留同步形态的命令（六个，均不触 DB，sweep 逐个判定）**：`sync_instruments`（发射后不管长任务：分离线程逐页推进，连接经访问器按页短暂获取，网络拉取与进度推送不持锁）、`cancel_sync_instruments`（纯原子标志位）、`set_auto_execution_enabled`（设备级运行时镜像推送）、`get_ai_prompt`（内存常量克隆）、`open_log_dir`（即发即忘系统调用）、`restart_app`（系统控制）；
- **HTTP handlers**：触 DB 端点全部 async 化并经 helper（`run_db` 端点名用 `METHOD /path` 身份格式，与 `HTTP_ENDPOINT_WRITE_OPS` 声明表同款）；不触 DB 端点形态不变——`GET /funds/{code}`（实时网络往返，分钟级阻塞拉取在连接锁外完成）、`GET /import/knowledge` 与 OpenAPI 文档（静态内容）。

### 3. SQL 归因显式跨线程：helper 重建/携带 span

spawn_blocking 不自动携带线程局部上下文，ADR-0009「同步命令与 wrapper 同线程」的归因假设在 async 命令上不再成立。helper 统一显式处理：捕获调用点 dispatcher 与当前 span 随闭包带入阻塞线程；IPC 异步命令无活动 span 时在闭包内重建命令 span（`info_span!("command", command)`，先例 `sync_holding_prices`）；HTTP handlers 在 tower_http 请求 span 内运行，span 随闭包跨线程不漂移（API 集成测试 `test_http_sql_duration_attributed_to_request_span` 钉死的行为）。这既是 ADR-0009 决策 4「若异步命令丢归因，对热点函数手包 span 兜底」预告的系统化——兜底从逐点手包升级为 helper 内单点自动，ADR-0009 其余判定不变。

### 4. 慢闭包纪律维持明文，形状不改变其地位

分钟级阻塞网络往返（基金详情查询先例：单请求叠加限流冷却重试最长可达分钟级）在连接锁外完成，任何形状下不得进锁。形状乙没有引入机制化守门——该纪律继续靠模块注释 + 评审 + 慢查询日志（ADR-0009）兜底；迁移时逐文件核对（#503 验收项），结论：无阻塞网络往返进锁的残留。

### 5. 接缝契约零改动

域层函数签名、事务编排、Writer 接缝、定时执行、批量导入、投资路径全部不变；命令注册表（ADR-0047）扫描面不变——不加命令只改形态；IPC/HTTP 对外契约、错误码、schema、迁移全部零变化。闭包的业务 `Result` 原样传播（错误契约不变），闭包 panic（JoinError）归一化为 `AppError::Io`，与既有 `spawn_blocking` 先例同形。回归契约：BDD e2e 与 API 集成测试不改一行断言全绿；helper 另有纯单测钉住闭包执行、Result 传播与上下文传播（`db::tests::run_db`）。

## 否决（防重复提案）

- **否决 tokio-rusqlite（第三方异步驱动）**：上游最新版仍只支持 rusqlite ^0.37，本项目已在 0.40——为换异步驱动而降级连接库方向颠倒，等上游跟进则时间表不可控；且该 crate 本体即「专用线程 + 通道」百余行胶水，引入库相对自建无实质能力增益，却背上版本配对僵局的长期成本。**除非上游支持项目现行 rusqlite 版本，或项目出现连接池等真实多连接需求，不再重议**。
- **否决自建专用线程句柄（形状甲）**：单 DB 线程 + 通道形态。① 闭包 panic 打死 DB 线程，需另定线程重生语义（panic 恢复 + 状态重建）——凭空新增一类自愈机制；② 测试世界需适配运行时，BDD 与 API 集成测试的调用路径全部改造；③ 其宣称的类型安全优势经拷问证伪：慢闭包阻塞整条 DB 通道的问题两种形状同在，「网络 IO 锁外」纪律任何形状都得守——类型系统对这两条都无能为力，优势不成立。对照形状乙：线程池由 tokio 管理，panic 只损单任务、线程池自愈，测试世界零改造（阻塞线程池上跑闭包对测试透明）。

## 复核结论

- **ADR-0032（连接层统一写入口）**：语义零改动。`run_db` 只改闭包的执行线程，写路径仍在 `db::write` 内置脏，豁免清单（`app_settings` 单点、Restore 路径）不变；既有置脏 BDD 场景不改断言全绿即复核证据。
- **ADR-0009（连接级耗时 hook）**：trace_v2 hook 随连接存在，阻塞线程上的 SQL 照常记录，挂载点与阈值语义不变；变化仅归因方式——同线程假设由决策 3 的显式跨线程传播替代（该替代本就是 ADR-0009 预留的方向）。
- **ADR-0060（易 panic 门禁）**：tauri 宏为 async 命令生成 `unreachable!()` 探针且宏不透传逐点 allow，命令壳文件级豁免随之扩容至 18 个文件（明细见 ADR-0060 宏生成代码条目）；属上游缺陷的已知代价，tauri 修复后移除。A 类四处临时豁免已经 #433 / #434 结构性消除摘除，与本迁移无关。

## 后果

- 事件循环线程与 tokio worker 零 DB 占用：长尾慢查询从「冻结整个界面」降级为「单个命令慢」，与 ADR-0067（余额缓存）、ADR-0068（性能门禁）共同构成大数量下的体验防线。
- 「哪些命令会阻塞主线程」不再靠口口相传：触 DB 命令与 handlers 只有一种 async 形态可模仿，新命令默认经 helper，AI 助手与新人不再带回同步样板。
- 新增一条隐性约定：异步命令的 SQL 归因依赖 helper 的 span 重建/传播，绕过 helper 直连 `spawn_blocking` 跑 DB 闭包会丢归因——评审时按「触 DB 必经 helper」把关。
- 保留同步形态的六个命令是不触 DB 的刻意判定而非遗漏（清单见决策 2）；后续给它们加 DB 工作面时须一并 async 化。
- 零行为回归由既有测试面钉住（BDD e2e + API 集成测试 + helper 纯单测），迁移全程未改一行测试断言。
