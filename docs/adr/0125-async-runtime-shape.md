# ADR-0125: 全异步运行时形态——异步 DB 门面（写读两线程）+ 行情同步域异步化

- 状态：已接受（2026-09-16 评审定稿；实施中——拆票、里程碑与验收判据见 spec #1406；实施已落地：issue #1408 门面核心与契约承接、issue #1409 换连与引导承接——换连仍走成对原语，门面按槽内换连代次复位连接不可信标记）。本条修订 ADR-0069 的「形状甲」否决与否决 tokio-rusqlite 的理由，并承接 ADR-0117 的实现形态
- 日期：2026-09-16
- 作者：Ledger 项目
- 关联：**修订 ADR-0069**（否决段「形状甲（自建专用线程句柄）」的 ①panic 重生语义、②测试世界适配两条由本 ADR 逐条回答后失效，③维持；tokio-rusqlite 否决维持、理由改写为「自建门面已满足需求」）；**承接 ADR-0117**（读写分离的不变量不变，实现形态改为异步 DB 门面的写线程 / 读线程；换连仍走该 ADR 决策 3 的成对原语）；ADR-0032（连接层统一写入口换「已持锁」形态，置脏语义与豁免清单不变）；ADR-0069 决策 4（「网络往返不得进锁」纪律与三重守门不变，前提换形态）、ADR-0120 决策 4（轮次逐段短取锁 + 超时放弃本轮——门面第一版不提供可撤销作业，故该路径留在豁免台账）；ADR-0121 决策 5（限速器自适应与前后台让行）；ADR-0104 / ADR-0111（读入口仪式与基础设施定位不变——读入口消费的句柄类型改由门面承接）；ADR-0054 / ADR-0095（失效信号与同步进度的主线程非阻塞投递不变）；ADR-0060（`catch_unwind` 不属六件套门禁，无需豁免）；ADR-0087（负向判据强度）；issue #1403（触发本裁决的缺陷）、PR #1404（过渡修复）、#1405（多端同步侧同根因残余点）、spec #1406（本裁决的 spec）；机制术语「异步 DB 门面 / DB 写线程 / DB 读线程 / 作业 / 连接槽」以本 ADR 为唯一解释处，不进业务词汇表（ADR-0117 对「写连接 / 读连接」的同款判定、ADR-0104 决策 8 先例）

## 背景

后端今天有四种执行环境并存：async 壳（Tauri async 命令与 axum handlers）、同步业务域（行情同步编排与 rusqlite 数据访问）、tokio 阻塞线程池（统一 DB 调用 helper `run_db` 把 DB 与阻塞网络闭包送出异步上下文）、以及各业务域自建的 OS 线程（价格历史后台补全、每日现价刷新、多端同步轮询）。

四种环境之间的正确性依赖一条**隐性纪律**：阻塞资源（rusqlite 连接、reqwest 阻塞客户端、自建 tokio Runtime）只在异步上下文之外构造、使用与销毁。这条纪律的来源是运行时的线程局部契约，编译器看不见：

- tokio 运行时线程（worker 与 `block_on` 所在线程）处于 runtime-entered 状态；阻塞池线程只 `Handle::enter()`（设 current handle，不置 runtime-entered）——「此处能不能阻塞」由线程局部状态决定；
- reqwest 阻塞客户端自持一个运行时线程，其构造路径（debug 断言）与每次请求等待都会检查调用线程状态，命中即 panic（`Cannot drop a runtime in a context where blocking is not allowed`）；
- rusqlite 是同步引擎，DB 闭包只能整体移到别的线程执行。

纪律退化的代价已经付过一次：标的信息同步命令在异步命令体里构造生产通道束（#1276 引入），dev 构建下点同步必 panic；且因 `invoke` 的应答任务被 panic 打死，前端 Promise 永不 resolve，同步按钮停在 loading（#1403）。更麻烦的是**退化不可见**：出问题的分支是生产分支，测试全部注入桩通道束，那句 debug 断言流水线上从未响过。

栈本身（Tauri V2 / axum / tokio）已是异步，同步岛是自加的层。每多一层，就多一条只能靠评审与偶然 panic 守住的纪律。

## 决策

### 1. 异步 DB 门面：专用线程 + 通道，写线程与读线程各一条

基础设施 crate 提供异步数据访问门面：写 / 读两条专用 DB 线程，作业（闭包）经通道送入、结果经 oneshot 回传，调用方 `await` 结果。**写线程与读线程各一条**——读侧独立连接不得与写侧共线程，否则长写事务会把读排在后面，正是 ADR-0117 修掉的退化。

连接槽与构造点保持原形：`DbState` 的写 / 读两个共享句柄与成对构造点不变（测试世界与全部调用面因此不必改形状，见决策 4）。**门面线程为整个作业持有槽锁**，并把 `&Connection` 交给作业闭包——取用独占收在门面线程内，作业闭包内再取同一槽即自死锁，由「已持锁」形态的写入口（决策 2）与结构守门（决策 8）双重挡住。内存库两条槽同指一个连接，测试语义与单连接时代一致。

连接池不在第一版：ADR-0069 预留的「出现连接池等真实多连接需求可重议」口子维持，真出现多连接需求时另案重议。

### 2. 门面承接既有契约，调用方语义不变

- **连接成对换入换出**（引导序列、解锁、重置、恢复的换连）：**仍走 ADR-0117 决策 3 的成对原语，不改为门面作业**。换连经同一连接槽互斥体与门面线程互斥，语义上不需要排队；且两处形态作业表达不了——引导序列的连接换入发生在门面启动之前，恢复路径的槽级换出没有 `DbState` 句柄（ADR-0117 决策 4 明载的豁免）。既有换连收口守门（boot / encryption / backup 白名单）原样保留。换连承接的实施形态（issue #1409）：换连原语在槽锁内抬高该槽的**换连代次**，门面 DB 线程取锁后比对代次来识别换连，并据此复位连接不可信标记（决策 3 的「退役 / 重建该连接」）；
- **提交点后置动作**（置脏与写时到期检查）：作业在事务提交后由 DB 线程调用，语义与统一写入口今天的提交点复核同源；连接层统一写入口（ADR-0032）换成「接收已持锁连接」的形态，置脏单点与既有豁免清单不变；
- **分段取锁与整体裁决**（一个写操作身份、一次置脏、一次信号）：形态不变，只是「每一段取连接」由门面作业取代；
- **SQL 耗时与 span 归因**：跨线程携带 dispatcher 与 span 的既有约定在门面内承接，归因口径不变；
- **锁跨度探针**：语义从「持有互斥锁时长」变为「作业占用 DB 线程时长」，阈值与告警口径不变；
- **读形态但闭包内含惰性写的命令**（缓存自愈、拼音惰性回填、漂移修复一类，ADR-0117 已逐命令留痕）：沿用该 ADR 的甄别结论走写槽，本裁决不重开甄别。

### 3. 作业 panic 语义：回滚 + fail-loud 上报，DB 线程不死（回答 ADR-0069 否决理由①）

作业外围 `catch_unwind`，且**捕获点位于连接槽守卫的作用域之内**——panic 在守卫正常释放之前被拦下，互斥体因此不中毒。这是「panic 不再毒化后续访问」这项收益的机制前提：今天闭包 panic 会毒化连接互斥体，此后所有 DB 调用一起失败。

panic 之后：回滚未提交事务 → 错误经通道 fail-loud 上报给调用方 → DB 线程继续服务；既不静默重启也不静默吞掉。**回滚失败或连接状态已不可信**时，记错误日志并把该连接标记不可信，后续作业一律 fail-loud 报同一错误，不静默恢复服务；是否退役或重建该连接由实施票按现场判定，本裁决只承诺「不静默」。

### 4. 测试世界：既有断言与测试世界构造零改动（回答 ADR-0069 否决理由②）

内存库工厂、BDD world 与集成测试的**断言与构造零改造**：连接槽、成对构造点与内存库形态保持原形，线程化收在门面内部。ADR-0069 当年把「测试世界需适配运行时」列为否决理由之一，本 ADR 以此消解这项代价。

「零改动」的适用面到此为止：命令层与入口层的调用点要从「取连接句柄」改为「投门面作业」（机械替换），这部分改造随里程碑一显式记账，不计入测试世界。

### 5. 行情同步域异步化：HTTP 面换 reqwest async，编排 async 化

行情同步域的 HTTP 面换 reqwest async 客户端（不再自持运行时线程），逐标的通道与批量取数面的闭包类型随之 async 化，编排（标的信息同步、基金现价刷新、基金历史回填、批量取数面、每日现价刷新、价格历史补全）async 化，网络等待以 `await` 表达。

编排取连接的唯一通道（作用域会话接缝 `ScopedSession`）改 async 形态，成为「行情域异步化」与「DB 形态」之间的**稳定边界**：其实现可以是阻塞线程池（过渡态）或异步 DB 门面（目标态），编排侧零分叉。该接缝的生产实现（命令壳侧与域内后台侧）随接缝收敛，后台车道的连接取用不再直锁连接槽。

### 6. 限速器与让行：异步化但保强串行

限速器的自适应间隔与前后台共享不变；**锁的粒度也不变**——仍从发请求前一直持有到响应处理完，只是互斥体换成可在 `.await` 之间持有的异步互斥体（`std` 守卫跨 `await` 持有会让 future 失去 `Send`，形态上必须换）。让行语义（前台请求在途时后台等待归零）保留，自旋归零等待保留，只把睡眠原语换成异步睡眠。数据源风控是外部风险，不拿它换架构整洁。

**取消语义**：在途请求的 future 被 drop 时守卫随之释放、下一请求可立即进入——「相邻请求间隔」由发送前打的时间戳保证仍在，但服务端侧可能出现 1 个重叠在途请求。本裁决明确接受这项残余风险，以换取不引入新的调度机制（见否决段）。

### 7. 后台车道与两壳接缝随行收敛

价格历史后台补全与每日现价刷新改为挂全局运行时的 async 任务（启动延迟与自然日窗口用异步定时），去掉各自自建 OS 线程。**接线形态不变**：仍以既有 `start_*<R: Runtime>(app)` 签名与「进程级单次拉起守卫」形态在域内挂载，执行器用 `tauri::async_runtime`——行情域 crate 已生产依赖 tauri（进度发射器接缝），不新增依赖、不新增反向接线。

HTTP 壳的两条行情获取接缝与投资域「按代码查询 / 创建」注入的 fetch 闭包 async 化，壳内的阻塞包装与 JoinError 归一化整层删除。

### 8. 守门：结构禁令 + 负向判据 + 生产分支覆盖

- **连接槽独占禁令**：生产面连接槽 `lock()` 只允许出现在门面与壳层统一入口。**豁免台账**（有技术原因的豁免，不是范围偷懒）：多端同步调度侧的轮次连接（逐段短取锁 + 超时放弃本轮，ADR-0120 决策 4）、备份自动调度与追补（同款超时放弃语义），以及测试面。豁免的**技术原因**：门面第一版不提供可撤销作业（见否决段），而这两处的语义是「取不到就放弃本轮」，排队式门面给不出等价物。豁免写进守门白名单并配**死条目断言**（白名单项必须有命中），与既有换连守门同址同形制；
- **阻塞客户端禁令**：生产面 `reqwest::blocking` 零命中（迁移完成后由源码扫描守门）；
- **负向判据**：限速串行与让行被绕过即红；门面独占守门被删除即红；panic 后门面仍可服务——关掉作业外围 `catch_unwind` 即红（ADR-0087 断言强度）；
- **生产分支覆盖**：不注入桩的命令路径纳入测试——#1403 的教训是「生产分支在测试面不可达时，纪律退化可以一路合入主干」；
- **扫描根**：壳层源码全递归（旁路点就在壳层子目录与命令目录内，与既有换连守门的非递归取舍不同）加基础设施 `db` 区之外的生产 crate；文本级扫描的别名盲区靠评审兜底，与既有 bypass 守门同款取舍。

### 9. 否决处置与本裁决不改的形态

- **不引 tokio-rusqlite**：自建门面已满足需求，不必再背一个只能配旧版 rusqlite 的依赖（理由改写；原「上游版本跟上可重议」口子保留）；
- **迁移完成后删除阻塞 HTTP 客户端**：同一能力只留一种形态，否则纪律要守两遍；
- **本裁决不改的自建线程 / 运行时**（目标形态达成后仍在，逐条留痕）：多端同步调度侧（S3 桥自建运行时 + 低频轮询线程，同根因残余点 #1405 另案）、备份自动调度线程、日志与其它壳层机制。因此「阻塞资源不再出现在异步上下文」的适用范围收窄为 **DB 访问路径与行情同步域**——这两处由门面与 async 客户端在结构上消掉，其余各处仍靠各自守门与评审。

## 否决（防重复提案）

- **否决「保持现状 + 靠评审守线程归属纪律」**：这条纪律已经用一次用户可见 panic 证明守不住（#1403），且生产分支在测试面不可达让退化不可见。
- **否决「只把行情域 HTTP 面异步化、DB 留在阻塞线程池」**：半程形态要同时维护两套纪律（异步等待与阻塞池线程归属），只拿到一半收益。
- **否决「第一版上 DB 连接池」**：写读两线程已满足现状；连接池要处理并发连接语义与 SQLite 单写者约束的组合，无真实需求不引入。
- **否决「第一版把换连改成门面作业」**：引导序列换入发生在门面启动之前、恢复路径的槽级换出没有 `DbState` 句柄，作业形态表达不了这两处；成对原语已由连接槽互斥体保证互斥，改成作业只增加排队与启动次序约束（决策 2）。
- **否决「第一版在门面内做可撤销作业」**（限时等待 + 放弃、排队中可取消）：这是承接轮次取锁放弃语义的唯一正解，但要引入「排队中可取消 / 执行中不可取消」的新机制与配套测试；本裁决不引半成品取消语义，代之以决策 8 的豁免台账，把该机制留给多端同步域异步化另案。

## 后果与风险

- **收益**：DB 访问与行情域内的阻塞构造在结构上消失（这类 panic 不再可能）；每个阻塞客户端一个运行时线程的开销消失；壳内包装层与后台自建线程减少；DB 作业 panic 不再毒化后续访问；命令层与统一入口的 DB 取用统一收到门面。
- **风险**：DB 门面是地基重写（基础设施 crate 是全部业务域 crate 的底座），波及换连消费面、提交点钩子、span 归因、探针与测试世界——必须分里程碑交付，且以「既有断言与测试世界构造零改动全绿」作为里程碑一的硬验收证据。
- **风险**：限速器异步化若削弱串行保证，代价落在数据源风控（外部不可控），故本 ADR 明确「保强串行」并配负向判据；取消路径上的 1 个服务端重叠请求是已接受的残余风险（决策 6）。
- **过渡态**：里程碑一只改 DB 形态、里程碑二才收行情域，中间必然出现「门面 + 阻塞客户端」并存。本裁决**允许并存且不设时间表**，退出条件唯一——#1414 的全部前置关闭；过渡期间两种形态各自有守门（阻塞客户端靠生产分支覆盖，门面靠独占禁令），不出现「无守门的形态」。
- **边界**：IPC 与 HTTP 契约、错误码、schema、迁移、前端可见行为零变化。

## 里程碑（随 spec #1406 拆票）

- **里程碑一：异步 DB 门面**——门面实现（写读两线程、作业取用独占、panic 恢复）、契约承接（换连原语沿用 / 提交点 / 分段裁决 / span / 探针）、统一入口与命令层直锁改道、测试世界零改造验收、守门（独占禁令 + 阻塞客户端禁令）。
- **里程碑二：行情同步域异步化与接缝收敛**——HTTP 面换 async、编排 async 化、接缝 async 化、后台车道转 async 任务、壳内包装删除。
- **收尾**：删阻塞客户端与过渡构造点、ADR 指针去过渡态措辞、守门定稿（拆票见 spec #1406）。
