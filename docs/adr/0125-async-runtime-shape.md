## 背景

后端今天有四种执行环境并存：async 壳（Tauri async 命令与 axum handlers）、同步业务域（行情同步编排与 rusqlite 数据访问）、tokio 阻塞线程池（统一 DB 调用 helper `run_db` 把 DB 与阻塞网络闭包送出异步上下文）、以及各业务域自建的 OS 线程（价格历史后台补全、每日现价刷新、多端同步轮询）。

四种环境之间的正确性依赖一条**隐性纪律**：阻塞资源（rusqlite 连接、reqwest 阻塞客户端、自建 tokio Runtime）只在异步上下文之外构造、使用与销毁。这条纪律的来源是运行时的线程局部契约，编译器看不见：

- tokio 运行时线程（worker 与 `block_on` 所在线程）处于 runtime-entered 状态；阻塞池线程只 `Handle::enter()`（设 current handle，不置 runtime-entered）——「此处能不能阻塞」由线程局部状态决定；
- reqwest 阻塞客户端自持一个运行时线程，其构造路径（debug 断言）与每次请求等待都会检查调用线程状态，命中即 panic（`Cannot drop a runtime in a context where blocking is not allowed`）；
- rusqlite 是同步引擎，DB 闭包只能整体移到别的线程执行。

纪律退化的代价已经付过一次：标的信息同步命令在异步命令体里构造生产通道束（#1276 引入），dev 构建下点同步必 panic；且因 `invoke` 的应答任务被 panic 打死，前端 Promise 永不 resolve，同步按钮停在 loading（#1403）。更麻烦的是**退化不可见**：出问题的分支是生产分支，测试全部注入桩通道束，那句 debug 断言流水线上从未响过。

栈本身（Tauri V2 / axum / tokio）已是异步，同步岛是自加的层。每多一层，就多一条只能靠评审与偶然 panic 守住的纪律。

## 决策

### 1. 异步 DB 门面：专用线程 + 通道，写线程与读线程各一条

基础设施 crate 提供异步数据访问门面：写 / 读两条专用 DB 线程，作业（闭包）经通道送入、结果经 oneshot 回传，调用方 `await` 结果。**写线程与读线程各一条**——读侧独立连接不得与写侧共线程，否则长写事务会把读排在后面，正是 ADR-0117 修掉的退化。

连接槽与构造点保持原形：`DbState` 的写 / 读两个共享句柄与成对构造点不变（测试世界与全部调用面因此不必改形状，见决策 4）。**门面线程为整个作业持有槽锁**，并把 `&Connection` 交给作业闭包——取用独占收在门面线程内，作业闭包内再取同一槽即自死锁，由「已持锁」形态的写入口（决策 2）与结构守门（决策 8）双重挡住。内存库两条槽同指一个连接，测试语义与单连接时代一致。

连接池不在第一版：ADR-0069 预留的「出现连接池等真实多连接需求可重议」口子维持，真出现多连接需求时另案重议。

### 2. 门面承接既有契约，调用方语义不变

- **连接成对换入换出**（引导序列、解锁、重置、恢复的换连）：**仍走 ADR-0117 决策 3 的成对原语，不改为门面作业**。换连经同一连接槽互斥体与门面线程互斥，语义上不需要排队；且两处形态作业表达不了——引导序列的连接换入发生在门面启动之前，恢复路径的槽级换出没有 `DbState` 句柄（ADR-0117 决策 4 明载的豁免）。既有换连收口守门（boot / encryption / backup 白名单）原样保留。换连承接的实施形态（issue #1409）：换连原语在槽锁内抬高该槽的**换连代次**，门面 DB 线程取锁后比对代次来识别换连，并据此复位连接不可信标记（决策 3 的「退役 / 重建该连接」）；
- **提交点后置动作**（置脏与写时到期检查）：作业在事务提交后由 DB 线程调用，语义与统一写入口今天的提交点复核同源；连接层统一写入口（ADR-0032）换成「接收已持锁连接」的形态，置脏单点与既有豁免清单不变；
- **分段取锁与整体裁决**（一个写操作身份、一次置脏、一次信号）：形态不变，只是「每一段取连接」由门面作业取代；
- **SQL 耗时与 span 归因**：跨线程携带 dispatcher 与 span 的既有约定在门面内承接，归因口径不变；
- **锁跨度探针**：语义从「持有互斥锁时长」变为「作业占用 DB 线程时长」，阈值与告警口径不变；
- **读形态但闭包内含惰性写的命令**（缓存自愈、拼音惰性回填、漂移修复一类，ADR-0117 已逐命令留痕）：沿用该 ADR 的甄别结论走写槽，本裁决不重开甄别。

### 3. 作业 panic 语义：回滚 + fail-loud 上报，DB 线程不死（回答 ADR-0069 否决理由①）

作业外围 `catch_unwind`，且**捕获点位于连接槽守卫的作用域之内**——panic 在守卫正常释放之前被拦下，互斥体因此不中毒。这是「panic 不再毒化后续访问」这项收益的机制前提：今天闭包 panic 会毒化连接互斥体，此后所有 DB 调用一起失败。

panic 之后：回滚未提交事务 → 错误经通道 fail-loud 上报给调用方 → DB 线程继续服务；既不静默重启也不静默吞掉。**回滚失败或连接状态已不可信**时，记错误日志并把该连接标记不可信，后续作业一律 fail-loud 报同一错误，不静默恢复服务；是否退役或重建该连接由实施票按现场判定，本裁决只承诺「不静默」。

### 4. 测试世界：既有断言与测试世界构造零改动（回答 ADR-0069 否决理由②）

内存库工厂、BDD world 与集成测试的**断言与构造零改造**：连接槽、成对构造点与内存库形态保持原形，线程化收在门面内部。ADR-0069 当年把「测试世界需适配运行时」列为否决理由之一，本 ADR 以此消解这项代价。

「零改动」的适用面到此为止：命令层与入口层的调用点要从「取连接句柄」改为「投门面作业」（机械替换），这部分改造随里程碑一显式记账，不计入测试世界。

### 5. 行情同步域异步化：HTTP 面换 reqwest async，编排 async 化

行情同步域的 HTTP 面换 reqwest async 客户端（不再自持运行时线程），逐标的通道与批量取数面的闭包类型随之 async 化，编排（标的信息同步、基金现价刷新、基金历史回填、批量取数面、每日现价刷新、价格历史补全）async 化，网络等待以 `await` 表达。

**修订注记（issue #1411 实施落地，2026-09-17）**：本决策按两层落地——#1411 先换 HTTP 面与等待原语（reqwest async 客户端、`Pacer::wait` / 让行自旋换异步睡眠、pacer 互斥体换 `tokio::sync::Mutex`），通道闭包与编排的 async 化随 #1412 的 `ScopedSession` 接缝一并收敛。**#1411 的过渡态以同步桥（`http::block_on`，住 http 层单点）驱动异步核心**：编排与闭包类型在本票保持同步形状，使既有通道束单测（桩闭包构造）零改动；#1412 把编排改 async 后桥删除、闭包类型随之 async 化。限速自适应、前后台共享与强串行在过渡期原样成立。

**修订注记（issue #1413 实施落地，2026-09-17）**：两壳生产入口已改 `async fn`（网络等待以 `await` 表达），#1411 的过渡同步桥拆除——本层生产面不再有任何阻塞驱动点，守门断言生产面零 `block_on`（market-sync 域内源码扫描）；投资域「按代码查询」（添加投资标的查询阶段）注入的 fetch 闭包改 async 形态（闭包返回 future，生产命令直接 await 驱动，不再经阻塞池）；「按代码创建」（`add_fund_by_code_with`）保持同步形状并留痕：其注入闭包在全部消费方都是锁外已拉取报价的同步回放（生产）或离线桩（测试 / BDD），不承载网络等待，而连接与拉取交织的形状一旦 async 化连接守卫必然跨 `await` 持有——同步形状即「连接不跨网络等待」的结构保证；IPC 壳的 `spawn_blocking` 包装与 JoinError 归一化（「任务执行失败」错误消息）整层删除；HTTP 壳的 `FundQuoteFetcher` / `StockQuoteFetcher` 改 async 闭包类型，生产分支在异步上下文直接 `await`。生产分支触真实网络、测试面不可达（全部行情端点集成测试离线驱动），「改回阻塞包装即红」的负向判据由壳层源码扫描守门承接（先例 #959/#961）。

**修订注记（issue #1412 实施落地，2026-09-17）**：编排与闭包类型已 async 化——通道束闭包返回装箱 future，网络等待以 `.await` 表达；`ScopedSession` 改 async 形态（RPITIT 返回 `impl Future + Send`），生产实现 = 门面写槽裸作业会话（`FacadeWriteSession`，命令壳侧与域内后台车道各自持句柄构造，后台车道的连接取用不再直锁连接槽，收尾置脏同改门面作业）；命令壳走 async 分段入口（`write_entry_segmented_async`：闭包 future 在调用方异步任务上轮询，每段取连接投门面作业），同步桥自此只余两壳生产入口（`fetch_stock_quote_production` / `fetch_fund_quote_production`，投资域注入接缝与 HTTP 壳的同步签名，async 化随 issue #1413）与测试驱动在用。#1411 注记「桥删除」按此收敛为「桥缩面」；负向判据的「生产通道束闭包不可注入」随闭包 async 化解除（桩束可门控真实在途）。「生产接线被绕过」的行为判据仍以决策 8 末条的生产分支覆盖承接。**负向判据范围留痕**：本票的「并发即红」判据打在 HTTP 原语面（共享 pacer 锁 + 让行原语），生产通道束闭包（住 `channels.rs` / `bulk.rs`，硬连真实主机与进程级单例）在本票形状下不可注入，故「生产接线被绕过」暂无行为判据——随 #1412 闭包类型 async 化与生产路径覆盖（ADR-0125 决策 8 末条）一并补上。

**修订注记（issue #1413 实施落地，2026-09-17）**：两壳行情接缝（`FundQuoteFetcher` / `StockQuoteFetcher` 与投资域「按代码查询/创建」注入闭包）async 化，壳内阻塞包装与 JoinError 归一化整层删除；同步桥拆除，#1403 的过渡构造点（生产通道束在写闭包内构造）随命令体 async 化整体消失——本决策的过渡态到此全部结束。生产通道束闭包恢复可注入（async 桩束可门控真实在途），「生产接线被绕过」的行为判据与生产分支覆盖（决策 8 末条）就位。

**修订注记（issue #1414 收尾，2026-09-17）**：过渡措辞收口——目标形态已是唯一形态，本 ADR 历史注记中的过渡态描述仅作迁移史留痕，不构成现役歧义。

编排取连接的唯一通道（作用域会话接缝 `ScopedSession`）改 async 形态，成为「行情域异步化」与「DB 形态」之间的**稳定边界**：编排侧只认本接缝，底层实现可整体更替而编排零分叉（#1411 过渡期的阻塞线程池实现已随同步桥拆除，现役生产实现唯一——异步 DB 门面写槽裸作业）。该接缝的生产实现（命令壳侧与域内后台侧）随接缝收敛，后台车道的连接取用不再直锁连接槽。

### 6. 限速器与让行：异步化但保强串行

限速器的自适应间隔与前后台共享不变；**锁的粒度也不变**——仍从发请求前一直持有到响应处理完，只是互斥体换成可在 `.await` 之间持有的异步互斥体（`std` 守卫跨 `await` 持有会让 future 失去 `Send`，形态上必须换）。让行语义（前台请求在途时后台等待归零）保留，自旋归零等待保留，只把睡眠原语换成异步睡眠。数据源风控是外部风险，不拿它换架构整洁。

**取消语义**：在途请求的 future 被 drop 时守卫随之释放、下一请求可立即进入——「相邻请求间隔」由发送前打的时间戳保证仍在，但服务端侧可能出现 1 个重叠在途请求。本裁决明确接受这项残余风险，以换取不引入新的调度机制（见否决段）。

### 7. 后台车道与两壳接缝随行收敛

价格历史后台补全与每日现价刷新改为挂全局运行时的 async 任务（启动延迟与自然日窗口用异步定时），去掉各自自建 OS 线程。**接线形态不变**：仍以既有 `start_*<R: Runtime>(app)` 签名与「进程级单次拉起守卫」形态在域内挂载，执行器用 `tauri::async_runtime`——行情域 crate 已生产依赖 tauri（进度发射器接缝），不新增依赖、不新增反向接线。

**修订注记（issue #1413 实施落地，2026-09-17）**：两条车道已转 `tauri::async_runtime::spawn` 拉起的 async 任务（启动延迟与自然日窗口用 `tokio::time::sleep`），巡检循环、每轮门检、后台让行 / 额度共享 / 静默标的级计数与收尾裁决语义零变化（收尾置脏同步改门面异步作业，不再用阻塞等待形态）；启动接线两测（每日刷新、历史补全）零改动全绿。「改回自建线程即红」由 `scripts/check-background-services.ts` 的车道执行器守门承接（两车道文件必须含异步执行器与异步定时接线、行情域生产面零 `thread::spawn`），与域内源码扫描守门（车道 / 同步桥两测）互补。

HTTP 壳的两条行情获取接缝与投资域「按代码查询 / 创建」注入的 fetch 闭包 async 化，壳内的阻塞包装与 JoinError 归一化整层删除。

### 8. 守门：结构禁令 + 负向判据 + 生产分支覆盖

- **连接槽独占禁令**：生产面连接槽 `lock()` 只允许出现在门面与壳层统一入口。**豁免台账**（有技术原因的豁免，不是范围偷懒）：多端同步调度侧的轮次连接（逐段短取锁 + 超时放弃本轮，ADR-0120 决策 4）、备份自动调度与追补（同款超时放弃语义），以及测试面。豁免的**技术原因**：门面第一版不提供可撤销作业（见否决段），而这两处的语义是「取不到就放弃本轮」，排队式门面给不出等价物。豁免写进守门白名单并配**死条目断言**（白名单项必须有命中），与既有换连守门同址同形制；
- **阻塞客户端禁令**：生产面 `reqwest::blocking` 零命中，由源码扫描守门（已定稿，收尾 issue #1414 落地：守门住根包 `blocking_client_guard`，扫描根 = 壳层源码全递归 + 全部生产 crate 源码，测试面不进面；无豁免台账——零命中是闭集规格，文本级扫描的别名盲区靠评审兜底）；
- **负向判据**：限速串行与让行被绕过即红；门面独占守门被删除即红；panic 后门面仍可服务——关掉作业外围 `catch_unwind` 即红（ADR-0087 断言强度）；
- **生产分支覆盖**：不注入桩的命令路径纳入测试——#1403 的教训是「生产分支在测试面不可达时，纪律退化可以一路合入主干」；
- **扫描根**：壳层源码全递归（旁路点就在壳层子目录与命令目录内，与既有换连守门的非递归取舍不同）加基础设施 `db` 区之外的生产 crate——「db 区之外」的豁免仅辖连接槽独占禁令（db 区是门面与连接层正住址，取槽锁在那里合法），阻塞客户端禁令在门面与连接层同样无合法住址、扫描面取全域（收尾注记，issue #1414）；文本级扫描的别名盲区靠评审兜底，与既有 bypass 守门同款取舍。

**修订注记（issue #1410 实施落地，2026-09-17）**：连接槽独占守门住壳层根包 `db_slot_guard`（`#[cfg(test)]` 源码扫描，与 ADR-0104 决策 6 的锁仪式反向守门同址同形制），判定形态 = 壳层标准锁行，扫描面 = 壳层 `src/**` 全递归 + 基础设施非 `db` 区；反向半边断言门面本体（基础设施 `db` 区的门面模块）仍持有取槽锁的唯一实现。实施期豁免台账（白名单 + 死条目断言）逐条如下：

- **壳层统一写入口 · 分段形态**（本决策首句「只允许出现在门面与壳层统一入口」的落点）：**行情同步半边已随 #1412 改走门面裸作业**（async 分段入口 + `FacadeWriteSession`，该半边的直锁与 #1410 预告的退役就此落地）；**同步轮次半边保留直锁**——`sync_now` 的轮次连接接缝（同步域 `RoundConn`，ADR-0120 决策 4）闭包借用轮次现场，不满足门面作业要求的 `Send + 'static`，同步域异步化（同根因残余点 #1405 另案）前仍走直锁，写槽访问器随之保留。收尾裁决（提交点置脏）已是门面作业，分段锁跨度与 #1276 判据不变；
- **备份侧**：恢复的**分支锁**（主连接可选，启动失败接管现场无连接不持锁，issue #601——锁形态超出门面单作业形状）+ 自动备份首次兜底的取槽点（`backup::lock_conn_with_timeout`，与自动调度同款「取不到就放弃本轮」，即本决策豁免台账的原条目）；
- **引导段接缝**（`MainConnSegments`，issue #1285）：整库换入需 `&mut Connection`，门面作业只递 `&Connection`——本决策豁免台账与 ADR-0117 决策 3/4 的槽级换入例外同源。

多端同步调度侧的轮次连接与备份自动调度 / 追补实现住各自域 crate（不在本守门扫描面上），它们的「取不到就放弃本轮」语义由域侧自身守门与评审承接，故不在壳层豁免台账里出现（不进死条目断言）。

守门另含三条规则：门面本体（基础设施 `db` 区的门面模块）必须仍持有取槽锁的唯一实现（住址不可达即红）；首次登记分支必须安装进程级门面（接线型判据以源码扫描守门替代行为断言——进程级门面的可观察差异只出现在故障恢复态，healthy 路径下惰性门面行为等价，ADR-0087 允许接线以源码扫描守门）；壳层生产面零命中取锁写入口 `db::write`（迁移期辖存量消费方改道核对；**收尾注记（issue #1414）**：行情域后台两条车道已随 #1412/#1413 迁完，本规则转为常设——壳层出现 `db::write` 即回潮；全仓生产面已无该形态调用点，取锁写入口本体的退役随同步域异步化另案评估）。这意味着决策 2 的「连接层统一写入口换已持锁形态」已全域达成。

**修订注记（issue #1438 实施落地，2026-09-17）**：取锁写入口本体（`runtime::write` 与 `DbState::write`）已退役删除——`write_locked` 是统一写入口的唯一形态，生产面经门面写作业、测试面自取槽锁直呼（存量测试消费方已同步改道）。`db_slot_guard` 的 `db::write(` 文本规则保留为**常设回潮哨兵**（同名再入编译即错；守门扫描面内辖另址重建与字符串拼接路径，别名盲区靠评审兜底）；`write_locked` 本体不在退役范围（门面与统一写入口共用的提交点单点）。多端同步侧的 `RoundConn` 直锁半边（#1405）与本退役正交，仍按豁免台账保留。

**修订注记（issue #1415 实施落地，2026-09-17）**：本决策第一段（豁免台账）的连接槽取用豁免，**备份域一侧已退役**。补上的机制是门面内的**限时等待与弃权**（`db::job_gate`，与作业模型同住 `db` 区）：作业带一枚状态门，状态机 `Queued → Waiting（已认领、正等连接槽、作业体未开始）→ Running（作业体执行中）`，调用方在时限到达时对门求弃权——**作业体尚未开始时弃权成立**（作业不执行、零副作用，调用方得 `LockOutcome::Abandoned`），**开始执行后弃权不生效**（执行中不可撤销，维持本裁决否决段的「不引半成品取消语义」）。弃权窗口刻意覆盖「等连接槽」这整段：把窗口截在作业认领处，调用方仍会陪一个阻塞在槽锁上的 DB 线程等到底，「取不到就放弃本轮」就名存实亡。由此三处备份域取用点改走门面限时等待写槽裸作业（`DbWriteHandle::run_raw_blocking_within`）：调度线程的单轮（到期备份 + 追补共用一个作业，逐字保持「单一 tick 双判定」）、退出兜底、壳层首次兜底；`db_slot_guard` 台账里备份侧那条自动兜底描述随之收窄为只剩恢复的**分支锁**（主连接可选，issue #601）。**仍留在台账**：多端同步调度侧的轮次连接（`ledger_backup::lock_conn_with_timeout` 的直锁形态，`RoundConn` 接缝闭包借用轮次现场、不满足作业的 `Send + 'static`）、恢复分支锁与引导段接缝——同步侧收编随本裁决第 9 条的多端同步域异步化另案（#1405 一簇）一并评估。

实施形状：门面本体（工作线程、作业模型、panic 恢复）与句柄 / 接线（类型化读 / 写句柄、连接槽对、进程级安装登记）按 ADR-0111 决策 2 的 `db/` 分文件规则分住两模块，限时等待与弃权原语自 #1415 起住第三模块 `job_gate`（状态门与 `LockOutcome`，作业模型消费）；句柄对外的唯一构造面是 `DbSlotPair` 的方向化方法（`write_handle` / `read_handle`），槽对同时是登记键的来源（写槽分配地址）。

### 9. 否决处置与本裁决不改的形态

- **不引 tokio-rusqlite**：自建门面已满足需求，不必再背一个只能配旧版 rusqlite 的依赖（理由改写；原「上游版本跟上可重议」口子保留）；
- **迁移完成后删除阻塞 HTTP 客户端**：同一能力只留一种形态，否则纪律要守两遍；
- **本裁决不改的自建线程 / 运行时**（目标形态达成后仍在，逐条留痕）：多端同步调度侧（S3 桥自建运行时 + 低频轮询线程，同根因残余点 #1405 另案）、备份自动调度线程、日志与其它壳层机制。因此「阻塞资源不再出现在异步上下文」的适用范围收窄为 **DB 访问路径与行情同步域**——这两处由门面与 async 客户端在结构上消掉，其余各处仍靠各自守门与评审。

## 否决（防重复提案）

- **否决「保持现状 + 靠评审守线程归属纪律」**：这条纪律已经用一次用户可见 panic 证明守不住（#1403），且生产分支在测试面不可达让退化不可见。
- **否决「只把行情域 HTTP 面异步化、DB 留在阻塞线程池」**：半程形态要同时维护两套纪律（异步等待与阻塞池线程归属），只拿到一半收益。
- **否决「第一版上 DB 连接池」**：写读两线程已满足现状；连接池要处理并发连接语义与 SQLite 单写者约束的组合，无真实需求不引入。
- **否决「第一版把换连改成门面作业」**：引导序列换入发生在门面启动之前、恢复路径的槽级换出没有 `DbState` 句柄，作业形态表达不了这两处；成对原语已由连接槽互斥体保证互斥，改成作业只增加排队与启动次序约束（决策 2）。
- **否决「第一版在门面内做可撤销作业」**（限时等待 + 放弃、排队中可取消）：这是承接轮次取锁放弃语义的唯一正解，但要引入「排队中可取消 / 执行中不可取消」的新机制与配套测试；本裁决不引半成品取消语义，代之以决策 8 的豁免台账，把该机制留给多端同步域异步化另案。

## 后果与风险

- **收益**：DB 访问与行情域内的阻塞构造在结构上消失（这类 panic 不再可能）；每个阻塞客户端一个运行时线程的开销消失；壳内包装层与后台自建线程减少；DB 作业 panic 不再毒化后续访问；命令层与统一入口的 DB 取用统一收到门面。
- **风险**：DB 门面是地基重写（基础设施 crate 是全部业务域 crate 的底座），波及换连消费面、提交点钩子、span 归因、探针与测试世界——必须分里程碑交付，且以「既有断言与测试世界构造零改动全绿」作为里程碑一的硬验收证据。
- **风险**：限速器异步化若削弱串行保证，代价落在数据源风控（外部不可控），故本 ADR 明确「保强串行」并配负向判据；取消路径上的 1 个服务端重叠请求是已接受的残余风险（决策 6）。
- **过渡态（已关闭，issue #1414）**：里程碑一只改 DB 形态、里程碑二才收行情域，中间出现过的「门面 + 阻塞客户端」并存已随收尾票结束——并存期两种形态各自有守门（阻塞客户端靠生产分支覆盖，门面靠独占禁令），未出现「无守门的形态」；收尾后阻塞客户端删除、禁令定稿为源码扫描守门，纪律面只剩异步形态一套。
- **边界**：IPC 与 HTTP 契约、错误码、schema、迁移、前端可见行为零变化。

## 里程碑（随 spec #1406 拆票，全部落地）

- **里程碑一：异步 DB 门面（#1408–#1410，已落地）**——门面实现（写读两线程、作业取用独占、panic 恢复）、契约承接（换连原语沿用 / 提交点 / 分段裁决 / span / 探针）、统一入口与命令层直锁改道、测试世界零改造验收、守门（独占禁令 + 阻塞客户端禁令）。
- **里程碑二：行情同步域异步化与接缝收敛（#1411–#1413，已落地）**——HTTP 面换 async、编排 async 化、接缝 async 化、后台车道转 async 任务、壳内包装删除。
- **收尾（#1414，已落地）**：删阻塞客户端与过渡构造点、ADR 指针去过渡态措辞、阻塞客户端禁令守门定稿（源码扫描）。
