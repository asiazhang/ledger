# ADR-0134: 通用 kind 写入守卫「交易币种 == 账户币种」——余额币种口径的前提升为强制不变量

- 状态：已接受
- 日期：2026-09-24
- 作者：Ledger 项目
- 关联：#1769（余额改按账户币种累计，本决策的前提）、ADR-0011（金额模型与折算基准）、ADR-0067（余额缓存）、ADR-0096 决策 4（出资账户币种一致先例）、ADR-0109（dividend 到账账户币种一致先例）、ADR-0105（写入协议 Local / Replay 两形态）、ADR-0091（同步重放与 ParkedOp）、ADR-0050（错误码契约）、ADR-0058（字段错误态）；#1770

## 背景

#1769 把余额口径改为按账户币种（现金腿 `amount_cents`）累计，其正确性前提是「账户 `currency_code` 唯一、所有现金腿金额本就是账户币种金额」——该前提此前只是隐含约定，无一处强制：

- 通用 kind（income / expense / transfer / refund）写入面（transaction 域 Writer 接缝的 normalize）只校验金额正性、transfer 目标账户、refund 继承等，无币种一致性比对；
- 前端收支 / 转账 / 退款与分期 / 订阅表单的币种字段与账户选择解耦（币种自由下拉、无账户联动）；
- AI 导入知识只教「中文币种名 → code 映射」，无账户币种约束；
- HTTP / 批量 API 载荷原样透传。

不一致行落库后无任何提示，静默污染按账户币种累计的余额；定时分期 / 订阅计划币种填错则每期执行报错、期次永远 pending。既有守卫只有三处——出资账户（`funding.currency-mismatch`）、dividend 到账账户（`trade.dividend-currency-mismatch`）、定时转账两端（`scheduled-plan.currency-mismatch`）——通用 kind 与手动转账是同一规则的缺口。

## 决策

1. **通用 kind 写入守卫**：income / expense / transfer / refund 的创建与修改强制「交易币种 == 所涉账户币种」；transfer 要求转出与转入两端账户币种一致且等于交易币种。违反报码化错误 `transaction.currency-mismatch`（单码双条件，params 带期望 / 实际币种供 zh / en 模板插值，模板落 i18n errors 域既有 transaction 节）。refund 因继承原支出账户 / 币种天然一致，守卫照跑（防御性）。
2. **双落点同码同文案**：Writer 接缝 normalize（创建 / 修改；修改为全字段替换按新值验，存量脏行改一致即放行）+ 同步重放臂（protocol 的 replay_assembly 对通用 kind 同款判定，失败写 ParkedOp 挂起、不中断批次——dividend 重放臂先例）。手动、批量导入、HTTP / AI、定时引擎、余额调整、同步重放全部写入口由此覆盖。
3. **否决「明确允许跨币种 + 重定义余额口径」**：单笔两种币种的腿在 schema 只增约束下要加列、定折算时点、重述余额与净资产口径，收益只是省一次按账户币种记账。
4. **跨币种场景裁决**：跨币种转账（换汇）不做，拆两笔或余额调整兜底，需求另立票；外币刷卡按账户币种（入账金额）记——与 dividend「后端不折算，用户自行换汇或选对账户」同一哲学。定时转账既有 `scheduled-plan.currency-mismatch` 守卫与本决策天然对齐。
5. **前端联动 + 锁定**（先例：投资表单、定时转账页签）：收支 / 转账 / 退款 / 分期 / 订阅表单币种 = 所选账户币种（computed），下拉锁定；账户未选回落展示币种偏好；转账两端币种不一致以字段错误态即时阻止提交，后端守卫降为契约兜底。展示币种偏好的「新表单预选币种」职责收窄为无账户上下文的预选 / 回落。
6. **AI 导入知识前置教学**：导入知识补「落账币种必须等于目标账户币种」与换汇拆记指引，避免 LLM 错误重试环。
7. **存量脏行不设专项工具**：发现靠 AI 读回对账（余额按账户币种计，脏行必然对不齐而挂起导入）；修复走编辑 / AI API 逐行改一致。守卫上线前已同步出去的跨币种 op 在升级设备重放时挂 ParkedOp 待人工裁决——接受该窗口代价（单用户多设备、概率极低）；排查 SQL 附 issue 关票说明。

## 理由

- #1769 之后「所有现金腿金额即账户币种金额」是余额正确性的前提，守卫把隐含约定升为强制不变量，静默污染从根上消失；错误暴露时点越早成本越低——录入时（前端联动）优于提交后（报错）远优于落库后（余额污染）。
- 出资账户、dividend 到账、定时转账三处已确立「币种一致 + 后端不折算」哲学，本决策补齐最后缺口后全入口对齐，不给「转账可以跨币种」留第二口径。

## 代价

1. 换汇与外币刷卡需手工按账户币种换算记账。
2. 守卫上线前同步出去的跨币种 op 在升级设备重放被挂起，需人工裁决。
3. 定时分期 / 订阅计划若币种填错，期次执行报错保持 pending，直至计划修正（前端联动防新增）。
4. 前端五处表单加联动，表单逻辑略增。
