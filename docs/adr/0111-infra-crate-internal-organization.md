# ADR-0111: infra crate 内部组织与定位口径——可守门的两条承诺与三区结构

- 状态：已接受（正文已按 #1108 壳机制迁出、#1330 `serde_util`、#1591 声明投影与 #2204 决策记录并入现行态收敛）
- 日期：2026-09-12（现行态收敛：2026-11-21）
- 作者：Ledger 项目
- 关联：ADR-0056 / ADR-0071 / ADR-0112（crate 分层与守门家族——本文只定 `ledger-infra` 内部形状，不碰拆分轴）；ADR-0073 / ADR-0104（壳层统一读写入口，现住根包 `src/shell_support/`）；ADR-0089（引导层）；ADR-0044 / ADR-0102（失效信号与 `WriteOp` 闭集单点）；ADR-0100（schema 漂移守卫）；ADR-0145（代码注释禁令与注记住址）；#1108 / #1330 / #1489 / #1591 / #2204

## 背景

`ledger-infra` 早期以「无域语义」立身，但该表述既解释不了为单点收口而存在的 `WriteOp` / `SettingKey` / 账本登记引导不变量，也给不出可机械守门的边界；同时 `db/mod.rs` 堆积七类职责，壳层机制一度暂住其中。需为基础设施建立可守门的定位口径与清晰的内部三区结构。

## 决策

### 1. 定位口径：可守门的两条承诺

`ledger-infra` 只承诺两条（废止模糊的「无域语义」表述）：
1. **不依赖任何域 crate**：由 Cargo 依赖图编译期强制，结构守门核对生产依赖。
2. **不定义账本数据的口径与规则**：交易、余额、净资产、预算、投资等语义与算术一律归域；基础设施不得对账本数据表执行 DML（机械扫描守门，迁移文件与 schema 守卫按职责免扫）。

在此之上，允许承载三类内容：跨层共享机制、引导层不变量（建连前必须成立且不涉账本数据）、以及单点收口闭集与键名表（`WriteOp`、失效信号名、`SettingKey`）。

### 2. crate 内三区与共享接缝

原暂住的 `shell_support/`（`write_entry` / `read_entry` / `redact` / `logger`）已随 #1108 迁回根包 `src/shell_support/`，基础设施不再承载只被壳层消费的机制，现为**三区 + 共享接缝**：

- **原语区（顶层单文件）**：`error`、`fs_util`、`closed_set`、`ids`（时间与 UUID 工厂）、`serde_util`（#1330，wire 入参「键缺席 vs `null`」三态 `double_option` 反序列化器）。
  - **`new_uuid` 取值契约（#1489 / #2204）**：UUID v7 **进程内严格单调**（同毫秒内连续生成亦严格递增），作为全仓读路径同日/同刻插入序破平键的前提，不得回退为同毫秒低位随机。
- **`db/`**：库与连接机制（迁移、建连/重置/完整性、查询助手、事务原语、schema 守卫、耗时 hook、连接层写入口与 `DbState`），按职责分文件、`mod.rs` 只声明与再导出。
- **`boot/`**：引导层实名地址（启动处置判定、数据位置与账本注册表、加密与口令缓存）。
- **共享接缝（顶层）**：`events`（失效信号投递机制与常量）、`signals/`（`WriteOp` 到失效信号的映射，测试外挂）、`settings`（`app_settings` KV 与键名闭集）。

### 3. 文件粒度与内部单向分层

- **文件粒度**：顶层单文件 = 单一模块子系统；出现第二模块或第二类职责即升目录，测试随生产模块外挂（`db/tests/`、`signals/tests/`）。
- **内部单向分层**：**原语 ← `db/` ← `boot/`**（共享接缝可被各层引用）；结构守门以子目录级反向依赖断言强制 `db/` 不得引用 `boot/` 或 `signals/`。

### 4. 守门与构建可见性

- **模块声明投影（#1591）**：expected 由 `infra/src/lib.rs` 的 `mod` 声明投影（原 `INFRA_MODULES` 手写登记表退役），磁盘孤儿模块文件/目录即红，`#[path]` / `include!` / 未识别属性链 fail loud。
- **账本表 DML 禁令**：静态扫描禁止基础设施对账本业务表执行 DML（迁移与 schema 守卫免扫）。
- **`test_utils` 构建隔离与同 crate 硬约束（#1132 / #2204）**：测试器具以 `cfg(test)` / `test-utils` feature 隔离出生产编译；必须留在 `ledger-infra` 同 crate 而非经 dev-dependency 环外置——否则下游消费方会拿到两份不兼容的基础设施类型实例（#1088 实测）。
- **HTTP 错误投影 feature 门**：`axum::IntoResponse for AppError` 加 feature 门仅壳侧启用，避免域 crate 编入 `axum` 传递依赖。

### 5. 术语约定

`events` 与 `signals` 仅作实现名保留；领域术语统一为**失效信号**，家族定义归核心交易域词汇表（成员带域限定词）。

## 备选与否决

- **沿用「无域语义」并把闭集/引导不变量清出基础设施**：会推翻 ADR-0044 单点收口，或打破「建连前可读账本注册表」的引导硬约束，否决。
- **`error` 拆为目录**：单一错误类型家族无拆目录收益，否决。
- **通过 dev-dependency 环把 `test_utils` 抽离到外部 crate**：制造双类型实例不兼容，否决。

## 后果

- 「某模块是否该进 `ledger-infra`」具备两条可机械验证的标尺，内部依赖方向与账本表 DML 边界由守门脚本持续锁定。
- 只被壳层消费的机制直接归根包 `src/shell_support/`，不再经基础设施过渡。
