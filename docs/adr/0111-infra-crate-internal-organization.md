# ADR-0111: infra crate 内部组织与定位口径——跨层共享内核、引导层与壳机制暂住

- 状态：已接受（grilling 定稿 2026-09-12；实施按「后续票」段拆票，本文不直接改代码）
- 日期：2026-09-12
- 作者：Ledger 项目
- 关联：spec #1086（crate 拆分 P0–P5——本文只定 crate 内部形状，不碰拆分轴）；issue #1111（crate 拆分 ADR 与分层指导同步——相邻但不同轴的记录；ADR 编号与 issue 编号命名空间无关）；细化 ADR-0056 决策 1 的「无域语义」定性、ADR-0071 的守门对象；修订 ADR-0073 / ADR-0104 的模块住址（接缝契约不动）；引用 ADR-0089（引导层）、ADR-0044 / ADR-0102（失效信号映射与 `WriteOp` 闭集单点）、ADR-0069 / ADR-0032（阻塞线程池 helper、置脏单点）、ADR-0100（schema 漂移守卫）

## 背景

`ledger-infra`（spec #1086 / issue #1087–#1088）以「无域语义、被所有层消费」立身，实际装的是三类东西：

- **无域原语**：错误、文件原子操作、闭集宏，以及数据库连接、迁移、通用查询助手、事务原语、schema 守卫、耗时 hook；
- **域语义承载物**：`WriteOp` 的 61 个业务动作变体、`SettingKey` 的域键名、账本登记的业务不变量；
- **壳层机制**：壳层统一读/写入口、IPC 载荷脱敏、日志初始化，以及只被壳层消费的事件发射面。

同时 `db/mod.rs` 一个文件承担七类职责（迁移链、建连与重置、时间与 UUID、连接层写入口、提交点后置钩子注册、阻塞线程池 helper、`DbState`），是全仓单文件历史改动次数最多的文件；已归位的模块还有两种目录形状（`db/` 是目录，`signals.rs` 是文件却带一个只放测试的兄弟目录）。

根因不是某次搬迁做错了，而是「无域语义」这句定性既解释不了 `WriteOp` 这类为单点收口而存在的域动作闭集，也给不出可检验的边界——守门脚本因此只能登记路径存在性，无法判定新模块该不该进来。

## 决策

### 1. 定位口径：从「无域语义」改为可守门的两条

`ledger-infra` 只承诺两条：

- **不依赖任何域 crate**——编译期由 Cargo 依赖图强制，守门脚本核对生产依赖；
- **不定义账本数据的口径与规则**——交易、账户余额、净资产、预算、投资等账本数据的语义与算术一律归域，基础设施不得对账本数据表执行 DML（机械判据见决策 5，迁移文件与 schema 守卫按其职责免扫）。

在此之上，基础设施**允许**承载三类内容：跨层共享机制、引导层不变量（打开任何库之前必须成立、且与账本数据无关的那部分），以及为单点收口而存在的闭集与键名表（`WriteOp`、失效信号名、`SettingKey` 等）。

「无域语义」不再作为判据使用：它既覆盖不了后两类，也让 ADR-0071 真正要守的那条边——余额与净资产口径回流基础设施——失去精确表述。

### 2. crate 内四区与共享接缝

- **原语区**（顶层单文件）：`error`、`fs_util`、`closed_set`、`ids`。时间与身份工厂（当前时刻、ISO 格式、UUID v7 与 v5 派生）从 `db/mod.rs` 升到顶层——它不是数据库关切，且文件工具引用它时不应穿透 `db/`。
- **`db/`**：库文件与连接机制的收敛地——迁移、建连/重置/完整性检查、通用查询助手、事务原语、schema 守卫、耗时 hook、连接层写入口与阻塞线程池 helper、`DbState`。按职责拆为独立文件，`mod.rs` 只做声明与再导出。
- **`boot/`**：引导层的实名地址（ADR-0089 决策 2 的「引导层」落到目录名）——启动处置判定、数据位置与账本注册表、加密与口令缓存。`db/` 不再包含引导层模块，依赖方向为 `boot → db`。
- **`shell_support/`（暂住）**：只被壳层消费的机制——壳层统一读/写入口、IPC 载荷脱敏、日志初始化。它们的正住址是壳层（#1086 P5），在壳层收敛落地前暂住本 crate；文档口径一律写「壳机制暂住」，不得作为基础设施范式被引用。
- **共享接缝**（顶层）：`events`（失效信号投递机制与线格式常量）、`signals/`（写操作身份到失效信号的映射，升为目录模块、测试外挂）、`settings`（`app_settings` KV 归口与键名闭集）。`events` 与 `DbState` 的消费方跨出壳层（备份域、同步域），不随壳机制分组。

### 3. 文件粒度规则

顶层单文件 = 只有一个模块的子系统；出现第 2 个模块或第 2 类职责时升为目录。这条规则解释现行形状：`error`（单一类型的家，含码化构造与序列化）是文件，`db/`、`signals/`、`boot/`、`shell_support/` 是目录。测试随生产模块外挂（`db/tests/`、`signals/tests/` 同形）。

### 4. crate 内分层与守门

显式分层：原语 ← `db/` ← `boot/` ← `shell_support/`；`events` / `signals` / `settings` 是被各层引用的共享接缝。守门脚本新增子目录级反向依赖断言：`db/` 不得引用 `boot/`、`shell_support/`、`signals/`；`boot/` 不得引用 `shell_support/`。理由与 ADR-0056 同源——注释自律在真实收益面前已被判定失效。

### 5. 守门补强

- `INFRA_MODULES` 与实际模块**双向全等**（含 `lib.rs`；目录型条目覆盖其全部子目录），不再是「登记路径存在性」的单向清单；
- 新增「基础设施不得对账本数据表执行 DML」扫描（迁移与 schema 守卫免扫）；
- `test_utils`（测试器具）加 `cfg` 门移出生产编译，其「生产路径不得消费」由构建形态保证，而非注释约定；
- HTTP 错误响应投影（`axum::IntoResponse for AppError`，孤儿规则要求实现与错误类型同 crate）加 feature 门，只有壳侧启用——避免每出现一个域 crate 就编入 `axum` 及其传递依赖。

### 6. 术语：失效信号是唯一领域术语

`events` 与 `signals` 描述的是同一机制的两次表示（信号名常量与投递机制 / 身份到信号的映射表）。领域术语统一为**失效信号**，家族定义归核心交易域词汇表，成员带域限定词（参考失效信号 / 价格失效信号 / 备份信号）。`events`、`signals` 是实现名，不改名——改名的收益是导航，成本是全部调用点与守门清单，而歧义来自概念而非路径。

### 7. 与 #1086 / #1111 的边界

本文只定 crate 内部形状与定位口径，不碰 #1086 的拆分轴与 P0–P5 顺序。#1111 负责把分层 ADR 从「目录分层」修订为「crate 分层」、记录认许边在 crate 边界下的新形态、修订测试工厂 ADR 前提。两者交叉引用；AGENTS.md 的分层指导按「crate 分层归 #1111 / crate 内部组织归本文」切分。词汇表改动严格限定为语义措辞与术语家族，不含任何路径或 crate 信息，与 #1111 的「领域词汇表地图不动」不冲突。

## 备选与否决

- **保持「无域语义」定性、把带域语义的模块清出去**：失效信号映射表是 ADR-0044 要的单点收口，拆散回各域正好推翻它；账本登记的不变量必须在无任何数据库连接时可执行，而域目录未来独立成 crate 后基础设施不能依赖它。清出去要么造出反向依赖，要么把引导编排上提到壳层，改动面远超收益。
- **把壳机制立即搬到根包**：#1086 P5 要造壳层 crate，现在搬等于搬两次，违背本仓「一次搬迁、可机械核对、带检查点」的既有纪律。分组加口径修正已能消除「被当基础设施模仿」的失效模式。
- **账本登记不变量迁域**：理由同上，撞「打开任何库之前必须可读」的硬约束。
- **`error` 拆成目录**：与日志模块同量级，是单一家族的自然粒度；拆目录只增加跳转层级。

## 后果

- 「某模块属不属于基础设施」有了可判定的两条，新模块进场不再依赖评审记忆；
- `db/` 成为纯库与连接机制目录，`boot/` 成为引导层的实名地址，`shell_support/` 的暂住状态可被一次性识别与整体迁出；
- 守门脚本从「路径登记」升级为「形状全等 + 块间方向 + 数据口径边界」三层判据；
- 既有接缝契约（ADR-0073 / ADR-0104 的发射时序、锁失败归一化、`Outcome` 证据形态；ADR-0032 置脏单点；ADR-0044 映射单点）逐条不变。
