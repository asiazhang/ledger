# ADR-0092: transfer 放开携带商户——借贷转账可关联商户

- 状态：已接受（修订 ADR-0053 决策 2 的商户部分，其余决策维持不变）
- 日期：2026-09-08
- 作者：Ledger 项目
- 关联：ADR-0028（交易对手方统一为商户）、ADR-0053（个人间借贷复用转账）、ADR-0011（金额模型与度量矩阵）

## 背景

ADR-0053 决策 2 以「商户语义（花给谁/收入来自谁）与借贷对手方（谁欠我/我欠谁）不同构」排除借贷挂商户：检索只能靠备注手打人名、详情无关联展示位。真实场景中同一对手方常是双重身份——既是商户字典里的往来对象（已有收支流水的店家），又是借贷对手（如借出款对象魏有鼎）：借贷交易缺商户关联后，按人检索依赖备注文本的自觉一致（恰是 ADR-0053 代价 2 批评过的依赖），商户视角的往来图景缺借贷一腿。

重审发现原排除的执行成本已不存在：schema 层 `merchant_id` 可空、无 kind 约束（放开无需改表）；报表免疫由度量矩阵结构性保证（transfer 的 `expense_net` / `income_net` 恒为 0，商户排行口径天然不受影响）；商户字典「关联交易条数」本就是全 kind 忠实计数。排除的实际依托只剩行为层一行准入判定（`transaction.merchant-unsupported`）。

## 决策

1. **准入集扩展**：可携带商户的 kind 从 `income` / `expense` / `refund` 扩展至含 `transfer`；行为层收口仍是纯 kind 判定（单点，不引入账户类型条件），`buy` / `sell` / `dividend` / `split` 维持拒绝。schema 零改动、无迁移、无发布边界问题。
2. **语义完全同构**：`merchant_id` / `merchant_name` / 未命中即建对 `transfer` 与 `income` / `expense` 同构，不设「仅限既有引用」之类的 kind 特例；商户名解析、即建防碎商户、修改路径「保持历史引用」语义自然共用同一段代码。
3. **商户定义拓宽**：Merchant 从「付款对象与收入来源」拓宽为「交易资金对手方」——消费/收入回答「花给了谁、收入来自谁」，借贷转账回答「这笔借贷与谁相关」（词汇表同步修订）。
4. **前端口径**：借出/借入表单加商户输入（与支出表单同款自由文本即建，经 TransactionInput 装配器矩阵加行）；普通转账表单不暴露商户输入位。API 层能力统一，UI 暴露面由装配矩阵裁剪。
5. **形态退化保留商户**：带商户的借贷转账经编辑把借贷账户换成普通账户、形态退回普通转账时，行上商户随行保留（不静默清数据）；普通转账表单看不到商户输入位属已知次要不便，详情展示与搜索不受影响。
6. **ScheduledTransfer 仍不挂商户**：ADR-0028 决策 3 的边界维持，定时转账形态不加商户字段，留待真实痛点（比照 ADR-0053 决策 5「入口零代码 → 痛点兑现」的节奏）。
7. **AI 导入永不挂**：借贷落账约定不变（receivable/debt 账户 + transfer），AI 不输出商户字段、不为借贷对手建商户；导入知识中「transfer 携带商户会被拒绝」的表述随行为变更同票修订。商户关联一律人工——「借出·前缀」命名约定是用户自觉纪律，AI 的确定性解析不建立在自觉约定上，且同名不同人（ADR-0028 代价 3）使自动挂存在错关联风险。

## 理由

- **为什么统一放开而不是仅借贷放开**：准入判定若从纯 kind 变成 kind + 账户类型条件，行为层收口就要依赖借贷这一派生视角（ADR-0053 决策 5：识别唯一依据是两端账户类型），批量导入、AI、同步重放共用的同一收口全部吃进复合规则；统一放开是准入集加一项，报表零污染由度量矩阵结构性保证，不需要规则去保护。
- **为什么不维持现状**：检索靠备注依赖用户自觉一致，详情无关联位是真实展示缺口；二者恰是商户关联的直接收益——交易搜索覆盖商户名、即时读取当前商户名，挂上即可搜、改名即刻生效。
- **为什么一人一账户不变**：账户承载未清金额口径（谁欠我多少）是商户行给不了的；商户关联是检索与展示指针，是补充不是替代——原决策 2 的账户承载部分全部保留，仅解除「不以商户标记对手方」的禁止。

## 代价

1. 同一对手方以商户行 + 借贷账户两处表示，名字无外键联动（商户改名不回刷账户名，反之亦然）——与 ADR-0028 代价 3 同款的字典表示边界，接受。
2. 普通转账在 API 层可携带商户而表单不暴露，能力大于暴露面；不做后端二次禁止，文档以「表单不暴露」为口径。
3. 借贷表单即建可能为纯借贷对手方产生商户行——与支出表单建一次性商户同一性质的用户选择权，不设限。
