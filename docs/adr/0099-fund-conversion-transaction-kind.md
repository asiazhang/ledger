# ADR-0099: 基金转换（convert）交易类型——第 9 种 kind、结转成本与零余额扰动

- 状态：已接受（schema 已落地于 issue #977；行为层 / 前端 / 契约随 #978 起的实现票落地）
- 日期：2026-09-10
- 作者：Ledger 项目
- 关联：ADR-0011（kind→度量矩阵与 raw/native 金额分离，扩列须同步矩阵）、ADR-0013 / 0033（行为层单点穷尽分派与编排入口、事务所有权）、ADR-0038（场外基金一等标的：复用 buy/sell、金额权威单价反算）、ADR-0067（余额与净资产持久化缓存：写路径整体重算）、ADR-0091（同步 op 语义、载荷只增与挂起队列）、ADR-0096（出资账户准入闭集）、ADR-0097（删除语义修订：revert 与级联先例）、ADR-0050（码化错误）、ADR-0081 / 0082 / 0038（1.0 前就地修改已发布迁移 + 两级 BREAKING 标记的既有裁定）、spec #973、issue #977

## 背景

场外基金平台的**基金转换**（把持有的 A 基金份额换成 B 基金份额，钱不进银行卡、也不进投资账户现金池）在账本里无法表达：`kind` 闭集里没有对应类型，只能用「卖出 + 买入（黑洞账户出资）」两笔借位落账。由此产生四个用户可见的口径伤害：

1. 界面把转换显示成「买入」，两腿互不关联；
2. 转出端被记成真实卖出，盈亏页凭空多一笔已实现盈亏；
3. 转入标的的持仓成本被按**转入日市值**重置而非沿用原始成本（实测一笔凭空多出 24.99 元），转换越频繁失真越大；
4. 黑洞账户被当成现金流出口，进一步污染它「未知/期初」的语义（现存约 97.79 万元历史噪声）。

存量事实：已落账 3 笔借位记录需要纠错；待迁移快照里还有 144 笔转换单（137 笔带完整转入端数据）。

**为什么是 ADR 级**：`kind` 是编译期闭集，`kind → 度量矩阵`是全库金额口径的唯一真源（ADR-0011）。扩列会牵动行为层穷尽分派、账户余额不变性、已实现盈亏闭合不变式、多端同步载荷兼容与 AI 契约；而「转入成本按转出批次**结转**而非按转入日市值重置」是货真价实的取舍，且转换的 FIFO 消耗状态在后续交易发生后不可重建——这决定了必须新增一张审计表，推翻「零 schema 改动」的可能。改主意的代价大，事后不看记录无法理解为什么多一张表、为什么金额要服务端重算，故立 ADR。

## 决策

### 1. 第 9 种 kind `convert`：一笔一行、两腿同记录、无现金腿

wire 值 / DB CHECK / 同步载荷 / i18n key 统一 `convert`。一笔转换 = **一条** `transactions` 记录，同时表达转出腿与转入腿（「A → B」），没有任何现金进出：六个金额度量系数全 0（与 `split` 同臂），落账前后**全部**账户余额（含黑洞账户）完全不变。**行金额锚点 = 转出腿结转成本**（原文「`amount_cents` / `amount_native_cents` 恒为 0」为过期表述，2026-09-12 grilling 复核就地改正：结转成本是审计与列表金额列的锚点，不是现金）。标的类型不限（基金之外换股/合并同构适用）。

守卫（与既有 kind 同款收口在行为层，不设库层 kind↔列矩阵约束）：两标的必须不同、同属一个投资账户、转出份额不得超当前持仓（同 sell）；convert 不在出资账户准入闭集内（ADR-0096 既有「不能携带出资账户」错误天然拒绝）。~~`dividend` / `split` 维持显式「暂不支持」拒绝~~（2026-09-12 修订：两者已分别由 ADR-0106 / ADR-0109 激活，见文末修订记录）。

> **修订（ADR-0106）**：`split` 已激活为**份额调整**（单标的、非现金、带符号份额变动），本节「维持显式拒绝」自 ADR-0106 起只对 `dividend` 成立；`convert` 与 `split` 同为「无现金腿」家族，成本重述与回退依据见 ADR-0106。

### 2. 存储形态：`security_transactions` 扩 4 个可空列 + 转出消耗表

`security_transactions` 扩 `to_instrument_id`（命名对齐 transfer 的 `to_account_id` 惯例）/ `to_quantity` / `out_amount_cents` / `in_amount_cents`，`action` CHECK 纳入 `'convert'`。convert 行：`instrument_id` = 转出标的、`quantity` = 转出份额、`price_cents` = 反算的展示单价（金额权威、单价反算，与场外基金 buy/sell 同款）、`fee_cents` = 手续费。

新增**转出消耗表** `security_lot_conversions`（`transaction_id` / `lot_id` / `quantity` / `cost_per_unit_cents` / `cost_cents`）承载转出腿逐批次消耗：它是修改回退 / 删除精确回补的**唯一依据**（转出时的 FIFO 状态在后续交易发生后不可重建），也是分批结转成本的审计载体。转入批次经既有批次表的买入锚点列锚定 convert 明细行，既有唯一键天然满足。

### 3. 成本结转：转入批次成本 = 被消耗转出批次原始成本

convert 行金额占位 0 提交，服务端按 FIFO 消耗算出结转成本后写入（与 buy/sell「金额占位、服务端重算」同款）；既有「耗尽批次成本闭合」机制**零改动**，转换批次耗尽时闭合到结转成本、精确到分。一笔转换单拆多腿时按各腿转出金额占比分摊、尾差末腿；每份成本 = 结转成本 ÷ 转入份额，单次舍入（价格刻度万分位，ADR-0038）。列表展示金额读扩展字段（转出金额），不读锚点。

### 4. 零盈亏与余额不变；全库不变式改写

转换本身对已实现盈亏贡献**恒为 0**；手续费如实记录在转换记录上，不进支出报表、不摊入持仓成本。全库不变式由原式改写为：

> 全平仓后 Σ 已实现盈亏 = Σ 卖出金额 − Σ 买入金额 − **Σ 转换结转成本**

无转换批次时退化为原式（转出标的视角的成本流出项读转出消耗表、转入标的视角的成本注入项即 convert 行金额，两者全库恒等）。

### 5. 行为分派与守卫：五处穷尽 match 全链路接入

行为层分派末臂从 `dividend`/`split` 拆出 `convert` 臂、委托投资域（沿用 ADR-0013 的薄而穷尽 match，不引入注册表）。`prepare` / `apply` / `revert` / `release_for_delete` / `replay_plan` 五处穷尽 match 全部接入；`revert` 复用 buy 清理语义（转出腿回补 + 转入批次在用占用守卫后清理）。**PUT（全字段替换）禁止从 / 到 convert 的 kind 变更**，返回新码化错误——纠错只有「软删 + 重建」一条窄路；buy/sell 与普通 kind 的既有互变能力不动。

推算与视图：时点持仓推算转出腿取负、转入腿取正（模块内部改动，兑现「公司行为落地时只改本模块内部」的注释承诺）；持仓视图冻结不动、批次驱动自动跟随；组合走势、净资产、可投资资产、持仓标的谓词自动跟随。

### 6. 同步：载荷只增、成本随命令携带、旧端挂起

同步命令载荷新增**可选**成员 `ConvertCommandFields`（`quantity` / `to_instrument_id` / `to_quantity` / `out_amount_cents` / `in_amount_cents` / `fee_cents` / `carried_cost_cents`）——「只增不改」纪律（ADR-0091）。`carried_cost_cents` 由源端算好随命令携带、重放端本地重建 FIFO 快照（既有「成本随命令携带、快照本端重建」先例）。旧版本设备经 op schema 版本硬检查与 kind 防御臂**双保险**挂起（ParkedOp），不静默错账。

### 7. AI 契约与导入知识：只增 4 个可选字段

提交走既有批量导入端点，`TransactionInput` 只增 `to_instrument_id` / `to_quantity` / `out_amount_cents` / `in_amount_cents` 四个可选字段；契约经运行时自描述自动带出。kind 闭集精确断言锁与 20KB 体积预算锁（ADR-0090）随 `convert` 同步更新；导入知识新增「基金转换」教学节（快照字段位置、单腿一条记录、腿序幂等键、金额占比分摊、余额不变对账口径、纠错步骤；多腿转出份额「逐腿直读 / 金额占比拆分」两写）。「dividend/split 不受支持」文案保留。

> **修订（ADR-0106）**：`split`（份额调整）获得同等待遇——导入知识新增份额调整教学节，能力文案改为「`split` 可用 / `dividend` 仍拒绝」。本节对 `dividend` 保留的部分不变。

### 8. 前端形态

类型标签 i18n「转换 / Convert」；PC 列表与移动卡片金额列显示转出金额；筛选闭集自动纳入；详情/编辑弹窗显示「A → B」两侧标的、份额、金额、手续费与结转成本；新增转换表单组件与 composable（复用标的远程搜索、账户选择、金额元转分接缝）。**不做基金/非基金形态分流**——转换天然只有确认单一种录入形态，份额 + 金额恒为权威输入。前端按 kind 穷尽的记录类型（字段矩阵、语义色、标签色、存在性穷尽表等）编译强制点逐点补齐。

> **修订（ADR-0106 / #1048）**：产品定位以 AI 记账为主，「无现金腿」kind 在 UI 上不再体现操作按钮——convert 的创建入口、编辑与软删入口撤下，只保留列表 / 筛选 / 只读详情；本节交付的可编辑表单形态由 #1048 反转，筛选闭集保留不变（否则 AI 落库的记录不可见、不可筛）。裁决记录见 ADR-0106 决策 10。

### 9. schema 发布边界：**就地修改 V001/V002** + 两级 BREAKING 标记，存量库不自动升级

本票（#977）只落 schema，达成的形态是：`V001` 的 `transactions.kind` CHECK 与 `V002` 的 `security_transactions.action` CHECK 各自就地扩集，`V002` 就地新增 4 列与 `security_lot_conversions`。

**为什么不写一个新迁移**（本条是本文替换先期方案后新增的决策）：新迁移要让 SQLite 接受新 CHECK 只能走官方「重建表」程序，而 `transactions` 是枢纽表——重建需在**迁移事务外**关闭 `PRAGMA foreign_keys`（事务内是静默 no-op，否则 `DROP TABLE` 会级联删除 / 置空子表行）、全量复原其 19 条索引与搜索拼音冗余列、补 `ANALYZE`，并为「存量升级路径」单独造一套重建与回滚测试；换来的只是「新旧库同一条升级路径」。本仓 1.0 前已三次接受同一取舍（ADR-0038 价格刻度、ADR-0081 market 闭集、ADR-0082 保司换轨，均「仅全新安装生效；存量库须重建库」）。故选择**就地修改 + 两级 BREAKING 标记**（两个迁移文件头部【就地修改注记】+ `CHANGELOG` Unreleased BREAKING 条目，纪律见 `AGENTS.md` 发布约定），代价明确：**存量库不重跑 V001/V002、拿不到 convert schema，须经 `scripts/db-reset.sh` 重建库**，不提供自动升级，spec #973 原「存量升级得到同一最终 schema」验收项随之退场。

存量纠错口径不变（执行主体在迁移侧环境）：已落账 3 组「假卖出 + 假买入」按**软删（buy 删除级联软删其在用 sell）→ 重建 convert → 按快照重导被级联的后续卖出**完成，下游已实现盈亏随重建按结转成本自动重算；全程走契约接口，「不删后重导」纪律不变。

## 备选与否决

- **继续借位落账（卖出 + 黑洞买入）**：即现状，四条口径伤害全在；转换越频繁成本越失真，黑洞语义持续被污染。
- **复用 sell + buy 并互相关联标记**：仍是两条真流水，盈亏页照样多出已实现盈亏、成本照样按转入日市值重置；关联标记只解决呈现，不解决口径。
- **新建独立表承载转换（不动 `security_transactions`）**：转换的「买入侧」无法进入既有持仓批次 / 视图 / 走势链路，等于在投资域造第二套持仓口径。
- **复用 `security_lot_sales` 承载转出消耗**：转换零盈亏，写入的匹配行会是假匹配，污染已实现盈亏明细（该表是 `realized_pnl` 的审计来源）。
- **成本按转入日市值重置**：实现最省（转入腿按普通 buy 落账即得），但成本与未实现盈亏随每次转换漂移——正是要修的伤害之一。
- **写新迁移重建 `transactions` / `security_transactions`**：见决策 9，成本集中在重建程序、外键开关越出迁移事务、19 条索引与冗余列复原、以及为存量路径单独造测试；本轮否决，改走就地修改 + BREAKING。
- **同时实现 `dividend` / `split`**：三者的领域语义（现金分红计税、拆股比例调整全部持仓批次）互不相干，合并扩大一次 BREAKING 面；维持显式拒绝，送股另立议题。
- **把转换记成 `transfer`（两端视为账户）**：基金标的不是账户，会同时破坏账户语义与持仓链路（ADR-0053 把借贷收进 transfer 是因为两端**确实是账户**）。
- **快照多腿拆成多条记录**：与「一笔转换 = 一条记录」的呈现与幂等键约定冲突；改由「逐腿直读 / 金额占比拆分」两写承载。

## 影响

- **schema（issue #977 已落地）**：`V001` `transactions.kind` CHECK 9 种；`V002` `security_transactions.action` CHECK 含 `convert` + 4 个可空列 + `security_lot_conversions` + 两条外键级联索引；`docs/model/README.md` 实体图与 Migration 索引同步。存量库须重建库（决策 9）。
- **待落地（#978 起）**：行为层五处穷尽 match 与守卫、投资域 `prepare`/`apply`/`revert`/`release_for_delete` 四出口、`TransactionKind` 枚举与度量矩阵加行（六系数全 0）、PUT 禁改 kind 的码化错误与错误模板、时点持仓推算双方向、批量导入 4 个可选字段与两处契约锁、导入知识教学节、前端表单与展示/筛选闭集、同步 `ConvertCommandFields` 与挂起测试。
- **词汇表同步（随行为层票落地）**：核心交易域 kind 闭集 8 → 9 与度量矩阵 `convert` 行、投资域「基金转换（Conversion）」词条与推算口径、AI 导入域能力清单。本票只落 schema，词汇表**尚未**同步（术语定义随行为可用而生效，避免文档领先于代码）。
- **无新增域间横向边**：convert 复用既有「核心交易域 → 投资域」分派边（ADR-0013 / 0071），新表归投资域，分层方向不变。
- **不变式**：决策 4 的闭合式随实现票改为绑定测试；余额缓存「回填 == 实时」对拍（ADR-0067）自动覆盖转换行（六系数 0，重算值不变）。
- **遗留假设（迁移侧环境就绪时验证，证伪按 ADR 修订流程更新）**：快照转入份额为扣费后净份额；多腿逐腿转出份额有无。
