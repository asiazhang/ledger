# ADR 0142: 账户归档——账本级收纳态，独立标志、读面零过滤、不动任何金额口径

- 状态：已接受（决策入档；实现随实施票落地）
- 日期：2026-10-18
- 作者：Ledger 项目
- 关联：ADR-0026（余额调整走黑洞转账——「隐藏」的现役占用者）、ADR-0053（借贷复用 transfer 与 receivable / debt 账户——本决策的起因）、ADR-0067（余额与净资产缓存口径不动）、ADR-0091（同步 op 载荷只增不改、ParkedOp 归宿）、ADR-0116（关闭只隐藏入口——「收纳不是停用」同款哲学）、ADR-0119（账户档案列只增迁移先例）、ADR-0133（储蓄目标「达成与归档」——归档词义的第一个载体与目标账户守卫）、ADR-0136（设备级视图偏好——本 ADR 划清「账本事实」与「看表口味」）；词汇表：参考数据与设置域「账户归档」（随本 ADR 入档）；修正核心交易域「债权债务往来」净资产守恒条的旧表述
- 来源：grill-with-docs 三轮裁决（2026-10-18）

## 背景

借贷由账户承载，余额即对该对手方的未清金额（ADR-0053）。一笔借贷还清后余额归零，账户本身却永久留在账户列表与每一个账户选择器里：账户页按创建时间列着十来条「借出·张三」，下拉里同样要滚过它们。

用户诉求：给账户一个**手动收纳**动作，把已结清的借贷从眼前挪走，但历史必须还在。

现状的三条现成路径全不成立：

1. **删除**。账户软删后账户读命令不再返回它，参考数据的名称映射因此也拿不到名字——历史流水渲染「-」且不可下钻，定时计划三处回退显示裸 `account_id`。删掉一个结清的借贷等于烧掉它的历史；删除本身也没有任何引用守卫。
2. **复用黑洞账户的隐藏标志**。该标志是黑洞占位账户的专属语义，并带两处硬绑定：黑洞查找按「同币种最早的一行隐藏」命中（余额调整的对手方、按需即建都靠它），且黑洞账户**故意**不进名称映射（历史渲染「-」是设计）。复用它，会让用户归档一张 CNY 银行卡之后成为「无(CNY)」的候选，也会让归档账户的历史名字一并消失。
3. **做成设备级视图偏好**（ADR-0136 先例）。「这笔借贷已结清」是账本事实，不是看表口味；一台机归档、另一台仍列着，用户只会认为同步坏了。

同时，词汇表里已有一句陈旧断言：核心交易域净资产守恒条写着「不想把借出款计入『我现在有多少钱』的用户可隐藏该账户」——它把一个**不存在的入口**写成文档事实，并暗示「隐藏 = 退出净资产」。

## 决策

### 1. 语义：归档是收纳态，不承载任何金额语义

归档只收窄两处呈现：**新建 / 编辑的账户选择面**与**账户页主表**。余额、余额合计、净资产、报表、搜索、投资与目标口径一律不动——归档账户的余额继续计入净资产与合计，账户页「已归档」分区按同一份快照展示行与合计。要让借出款退出净资产，走既有坏账核销（余额调整归零：净资产忠实下降、不计收支），不靠归档。

同一决策下，归档**不是停用**：指向该账户的进行中定时计划照常执行，AI 导入照常落账。受限的只有「用户从界面挑账户」这一件事。

### 2. 独立标志，黑洞隐藏标志语义不动

`accounts` 新增归档标志（布尔、默认假、只增迁移），与既有的隐藏标志、软删标志同形；黑洞隐藏标志的语义与消费面一字不动。不新增归档时间戳：行上的更新时间已有，多一列要多带一份同步载荷、多一次「要不要展示归档时间」的决策，当前没有消费者。

已归档行的动作集收窄为「恢复」——编辑、调整余额、删除都要先恢复，避免在一张看不见全貌的卡上改钱。

### 3. 归账本，不归设备偏好

归档状态是账本数据：落账户行、随同步 op 复制到各端、进备份、对 AI 契约可读。与 ADR-0136 的设备级视图偏好分家——那条管「我看表的口味」，这条管「这笔借贷结清了」。

### 4. 读面零过滤，排除只发生在选项构造层

账户读命令继续返回归档账户（带标志），不做归档过滤。理由是决策 1 的直接推论：名称映射必须拿到归档账户，「历史照常显示名字、照常可下钻」才成立。账户页拿到同一份余额快照后在前端分组（与储蓄目标分组先例同形，各自的派生集互不重算）。

排除收口在参考数据的单一派生「可选择的账户」（= 账户去归档），所有选项构造点消费它；「当前已选值是归档账户」的补值（选项并回当前值并标「已归档」）收口成一个小工具，供编辑流水、编辑计划与交易页筛选下拉共用。

后端不拦截对归档账户的写入：归档不是停用（决策 1），拦写入只会为 AI 导入与既有计划制造无收益的失败面。

### 5. 写面契约：新同步命令 + HTTP 可选键，账户修改命令载荷不动

- 同步：新增账户命令变体 `SetArchived`（幂等，LWW 裁决域仍是单个账户）。**不往既有修改命令的载荷塞字段**——该载荷是「落定值」语义（信用卡三件套缺键即置空），旧日志重放会把归档态刷回未归档。
- HTTP：`PUT /api/v1/accounts/{id}` 追加可选键（键缺席 = 不改，沿用信用卡三字段的三态先例），不开新端点。
- AI：账户列表与余额只增归档标志用于对账辨识，**不给 AI 归档写权限**——导入链路不该顺手收纳账户。

### 6. 守卫：只拦「挂在目标上」，其余给真话

- **绑定储蓄目标的账户拒绝归档**（码化错误，指向目标自己的归档）。目标进度 = 专属账户余额，账户归档会把「进度 = 余额」的读口径打成两套收纳语义。
- **被进行中计划引用不阻断**，归档时提示计划数量——归档不停用（决策 1）。
- **余额非零允许归档**，确认框显示当前余额并声明「仍计入净资产与合计」。结清借贷余额本就是零，这条几乎不触发；用「显式而非静默」处理例外，不用拒绝为合理状态挡路（「留几块钱防销户」就是合理状态）。
- 账户类型不设白名单：任意类型都可归档（旧银行卡、弃用钱包与结清借贷是同一诉求）。

### 7. 术语：复用「归档」，不新造「隐藏账户」

账户归档与储蓄目标归档是同一词义（不删任何东西、退出默认列表、可查、恢复与删除是独立动作）在账户上的第二个载体。词条落参考数据与设置域；「隐藏」继续专指黑洞占位与金额掩码，不承接第四个含义。

### 8. 修正陈旧的净资产断言

核心交易域净资产守恒条改为「归档不改净资产；要让借出款退出净资产，走坏账核销」——文档与决策 1 对齐，不再承诺一个不存在的入口。

## 理由

- **收纳与核销分家**是唯一不会静默改数的形态。若归档同时退出净资产，归档一个还有余额的账户就等于无声改写净资产读数；而「这笔钱我认了、从我的钱里拿掉」在仓库里已有专门动作（余额调整归零、忠实下降、不计收支）。
- **独立标志是唯一不踩黑洞路径的形态**。黑洞的两处硬绑定都被 AI 对账与余额调整依赖，任何「一名两义」的复用都会把用户账户卷进「无(币种)」的解析链。
- **读面零过滤是「历史可读」的必要条件**，也是「归档 = 收纳」在数据流上唯一成立的形状：过滤若住在后端读命令，名称映射注定拿不到账户，历史必然断链——删除的现状即是实证。
- **账本事实归账本**：只有跨端一致的读写面才配承载「这笔账结束了」。

## 代价

- 账户页的合计从「一屏加一遍」变成「普通账户 + 目标账户 + 已归档」三段；已归档区默认折叠，靠标题行的数量与合计保住可对账性，但漏看折叠区的用户可能一时找不到某个账户的钱。
- 全部选项构造点必须改到「可选择的账户」派生上，遗漏一处即出现「下拉里还能选到归档账户」；交付需附逐点判定表（选择面 / 展示面）。编辑面补值是新增的横切小件。
- 归档与黑洞隐藏、金额隐私掩码、ADR-0136 的流水隐藏共处一词多义的边缘，只能靠词汇表「别名」段与界面文案（归档 / 已归档 / 恢复）区分。
- 同步载荷新增一个命令变体：旧版本端遇到未知动作按既有行为落 ParkedOp，跨版本混用期间归档态不传播。

## 替代方案

- **复用黑洞隐藏标志**：两处硬绑定 + 历史断链，否决。
- **归档即退出净资产**（让隐藏承担「我不想算这笔钱」）：静默改读数，且与坏账核销职责重叠，否决。
- **设备级视图偏好**：一台机归档另一台不归档，与「账本已结清」冲突，否决。
- **在既有修改命令载荷追加归档标志**：旧日志重放会把归档刷回未归档，否决。
- **后端读命令过滤归档账户**：名称映射拿不到账户、历史断链，否决。
- **只允许借贷账户归档**：机制本身不区分类型，为将来的「旧银行卡」再开一次口子更贵，否决。
- **非零余额拒绝归档**：为合理状态挡路，否决。
- **绑定目标的账户也允许归档**：目标进度与账户收纳两套语义打架，否决。

## 影响

- schema：账户表只增一列（布尔、默认假），无数据迁移、无 BREAKING；新旧库双向可读。
- 契约：账户读面只增字段（IPC / HTTP / AI 自描述契约面），`PUT` 追加可选键，同步新增一个命令变体；零 BREAKING。
- 词汇表同步：参考数据与设置域新增「账户归档」词条；核心交易域净资产守恒条修正；地图条目主题追加。
- 实施拆票建议（三票串行，契约依赖域 DTO、前端依赖契约类型）：① 迁移 + 域写编排（归档 / 恢复、幂等、重放）+ 目标绑定守卫 + 域单测；② 契约只增（IPC / HTTP / AI 与可选键）+ API 集成测试；③ 前端「可选择账户」派生 + 选项收口 + 编辑面补值 + 账户页三分组 + i18n 文案 + Vitest。
