# ADR 0032: 置脏触发收口连接层统一写入口（默认置脏 + 集中豁免）

- 状态：已接受
- 日期：2026-08-29
- 作者：Ledger 项目
- 关联：issue #173（spec）；部分修订 ADR-0016 决策 2 的置脏挂钩点清单

## 背景

自动备份的脏标记（DirtyMarker，ADR-0016「写时顺带检查」）由每个写路径手动调用 `auto_backup::on_write(conn)` 触发，实测散布 11 个文件、24 个调用点（spec 成稿时估 9/17，已过时）。`on_write` 本身是深模块（置脏 + 按 `is_autocommit()` 推迟到期检查），但触发协议是「调用方记忆」型浅接缝：漏一处 = 静默丢一次备份，无编译期防护；且审计发现 budget（预算）域写路径完全没有挂钩——只改预算时既不写时置脏、轮询也因脏标记未置而不备份，属现有缺口而非有意排除。目标：写路径对备份域零感知，新增写路径不可能漏。

## 决策

1. **置脏触发收口连接层统一写入口 wrapper**（如 `db.write(|conn| ...)`）：锁连接 → 执行闭包 → 闭包 Ok 且 `is_autocommit()`（事务已提交）时单点执行 `mark_dirty` + 到期检查（即 `on_write` 语义整体迁入）。各写路径的 `on_write` 调用点清零，业务代码对备份域零感知。
2. **口径：默认置脏 + 集中豁免，而非白名单等价复刻**。语义锚：**DirtyMarker 跟踪账本数据变化（交易、参考数据、市场数据、物品、预算……），配置与调度状态不算「数据变化」**。豁免清单集中一处：设置与调度状态写入（`app_settings` 全表，经 `settings.rs` 单点收口）与恢复（Restore）路径。默认置脏顺带修复 budget 缺口（行为超出现有 24 个调用点，属有意的行为修正而非破坏）。
3. **薄 wrapper 边界**：只做「锁 + 写后置脏/检查」，不接管事务管理（裸 `BEGIN/COMMIT/ROLLBACK` 写法保留）。「事务内推迟、提交后补上」由结构保证：闭包 Ok 后 `is_autocommit()` 复核即提交点，原三处「COMMIT 后补调」注释与调用点删除；闭包 Err 不置脏（与今天「事务内 mark_dirty 随事务回滚」等价）。
4. **否决连接级 hook 路线**（rusqlite `update_hook` + `commit_hook`）：① 回调内禁止同连接 SQL 调用，`mark_dirty` 与 VACUUM INTO 须挪调度线程异步执行，「提交后补上」退化为跨线程时序问题；② `update_hook` 只报告表名 + rowid，`app_settings` 是 KV 表键名不可见，豁免只能整表粗化；③ hook 自身的「回调禁 SQL」「只覆盖行级 DML」又是一条口口相传的微妙规则——把「调用方记忆」换成「hook 作者记忆」，违背本决策「规则单点化」的初衷。`trace_v2`（ADR-0009）不受影响，耗时日志等其他横切机制的收口如走 wrapper，单独开票。

## 代价

1. **一次性迁移面大**：所有写路径从裸 `conn.lock()` 迁到 wrapper，迁移期漏改一处的风险靠 rg 审计裸 `conn.execute` 写语句兜底——属一次性成本，此后新增写路径默认走 wrapper 即不可能漏。
2. **`app_settings` 全表豁免是粗粒度**：未来若出现「写 `app_settings` 且应置脏」的需求需重新开口子；目前领域上不存在（设置不是账本数据）。
3. **budget 置脏为行为变更**：只改预算现在会触发写时备份检查与次日备份——有意修复，由 e2e 场景钉住。

## 替代方案

- **白名单等价复刻**（连接层枚举「哪些操作算业务写」）：与今天逐点等价，但新写路径默认不置脏，记忆负担只是从 24 处挪到 1 处，「不可能漏」落空；且会原样复刻 budget 缺口。否决。
- **hook 路线**：见决策 4。否决。
- **调用点显式 opt-out API**（`db.write_without_dirty`）：settings.rs 是通用 KV 收口、不知调用方语义，opt-out 须下推到每个设置调用方，豁免重新散布。否决。

## 影响

- spec #173 据此实施；`on_write` 公开调用点清零，24 处（含三处「COMMIT 后补调」）全部删除。
- 测试：现有 backup.feature 6 个场景保持通过；新增 budget 写入置脏、批量导入失败回滚不置脏、设置写入不置脏三场景。
- ADR-0016 决策 2 的挂钩点清单与排除项由本决策的「默认置脏 + 集中豁免」承接，触发模型（轮询 + 写时顺带检查）不变。
