# ADR-0102: WriteOp 闭集单一化——宏同体派生，ALL 与 ident 手抄映射消亡

- 状态：已接受（grilling 定稿，2026-09-11）
- 日期：2026-09-11
- 作者：Ledger 项目
- 关联：#1011（spec 与实施票，架构走查 2026-09-11 候选 9）；ADR-0044（信号映射单点与穷尽 match 不动，本决策只换闭集表示的维护形态）；ADR-0047（命令注册单一来源——「单一来源」同系先例与 build.rs 路线对照）；ADR-0073（「消费方仅测试不抬编译期」原则——本决策沿用并重申其两条否决）；#1022（邻里弱点候选票）

## 背景

写操作身份闭集 `WriteOp`（61 变体，ADR-0044 决策 2 的跨壳强类型键）存在三份表示：enum 本体（真源）、`WriteOp::ALL` 手抄清单（信号守门「孤儿身份核对」的遍历种子）、`signals_cross_check::parse_write_op` 手写「ident → 变体」映射（调用点扫描提取的字符串映射回变体）。`ALL` 的文档自认「enum 新增变体而漏登本清单不会报错」——守门与被守门对象共享同一弱点，且弱点已成真：grilling 当日核实 `parse_write_op` 实为 60 臂、缺 `SetLogLevel` 一臂，因该身份恰走例外白名单的类型化路径、从不流经字符串 parse 而长期静默。「漏登不报错」不是假想而是现状。

三条失败链的响度并不对等：新增变体漏改 `signals_for` 是编译红（穷尽 match）、漏改 `parse_write_op` 在该身份流经扫描时测试红、唯独漏登 `ALL` 完全静默——孤儿核对对这个变体失明。守门种子的完备性靠「清单紧邻 enum、同步义务就地可查」的纪律维持，与 ADR-0047 消灭的「漏注册靠评审人肉」同构。

## 决策

1. **闭集单一来源 = `write_op_set!` 声明宏的调用清单**，宏定义与调用就地放 `signals.rs`（局部性即卖点）。宏同体生成三产物：`enum WriteOp`（derive 原样、变体 `///` 文档经 `$($meta:meta)*` 原位透传，rustdoc 不变）、`pub const ALL: &[WriteOp]`（定长数组改切片，长度标注维护点随之消亡）、`pub(crate) fn from_ident(&str) -> Option<WriteOp>`。清单即 enum 本体——三份表示收敛为一份，漂移**不可表达**（构造性保证），而非「可检测」。域分组注释（「── 参考数据四表 ──」行）保留在宏调用内作纯注释。
2. **`parse_write_op` 消亡**：`signals_cross_check` 扫描提取的 ident 改经 `from_ident` 映射；提取到非变体文本（扫描器具自身漂移）以断言失败报「扫描提取漂移」。原 panic 话术中「enum 新增变体须同步 parse_write_op 与 WriteOp::ALL」的同步义务整体消亡。
3. **机制选型：声明宏，非 build.rs 生成**。`ALL` 与 `parse_write_op` 的全部消费方都是测试侧（孤儿身份核对与派生声明表，`rg` 核实无生产消费点），ADR-0073 决策 5 已立「声明表的唯一消费方就是交叉核对测试，函数体扫描不必抬到编译期」的原则；ADR-0047 的 build.rs 扫描由 `generate_handler!` 的生产消费方所迫，此处无该约束。宏相对 build.rs 生成少两样东西：扫描器（其正确性风险类整体消失——生成路线的「fail loud 纪律」仍是「检测器正确」前提下的保证）与构建接线（`rerun-if-changed`、双消费点 `include!` 均不需要）。代价是引入仓内首个自定义声明宏（src-tauri 零先例），模式成本一次性支付。
4. **壳声明守门不升级（重申 ADR-0073 否决）**：「哪个壳声明哪个身份」维持调用点字面量 + 文本扫描守门，不改为编译期类型检查——升级路径要么 build.rs 扫 `write_entry` 调用点（ADR-0073 决策 5 显式否决的「函数体扫描的脆弱形态抬到编译期」），要么复活手写声明表（翻案刚删的约 190 行）。文本扫描的残留弱点（别名改写不可达）维持 ADR-0073 已接受的评审兜底；未来真出现文本扫描漏过的 bug，才是重开此决策的证据。
5. **例外白名单零随动 + 一条顺带核对**：白名单条目直接持类型化变体（enum 引用），本就不是漂移面，无需迁移；但其命令名字符串此前无「仍真实存在」守门——命令改名后旧条目静默残留为死条目。补「白名单名字 ⊆ `IPC_COMMAND_MANIFEST`」一条核对（`startup_gate_allowlists_only_contain_registered_commands` 同款器具）。

## 理由

- **保证等级的差距是选型的决定项**：宏清单即 enum，`ALL` 与 `from_ident` 由同一 token 流展开，不存在第二份事实可供漂移；build.rs 生成与测试期互核都把保证押在「检测器正确」上，且 build.rs 路线与 ADR-0073 的消费方原则相抵（同日走查的 ADR-0101 否决 build.rs 扫描路线的推理一致）。
- **定长数组 `[WriteOp; 61]` 的长度标注本身是微型维护点**（漏改编译红，但每次新增都要记得改）；切片形态下消费方（仅 `for op in WriteOp::ALL` 迭代）零适配。
- **`SetLogLevel` 活体漂移的处置**：构造性消灭，无需单独修复——`from_ident` 由宏展开即完备，「缺失臂」这一失败类不复存在；实施报告仍须显式记录此发现。

## 代价

1. 仓内首个自定义声明宏（src-tauri 零先例）：模式引入成本一次性支付；展开调试依赖 `cargo expand`（清单形态简单：变体 ident + 文档，预期罕见）。
2. 域分组注释从 enum 定义体移入宏调用，纯注释保留可读性、不进 rustdoc。
3. `ALL` 类型变化（数组 → 切片）触及消费方签名——已核实消费方仅迭代，零适配。

## 替代方案（防重提）

- **build.rs 文本扫描生成**（#1011 原案，ADR-0047 同款）：与 ADR-0073「消费方仅测试不抬编译期」原则相抵；第二台扫描器的形态维护与正确性风险换不来宏所无的能力。被决策 3 翻案。
- **测试期互核（三份保留、漂移即红）**：`signals_cross_check` 现成扫描器具扫 enum 文本，断言 `ALL` ⊇ 全部变体、parse 臂全覆盖——约 40 行、零新机制，漂移从静默变测试红（CI `cargo test --lib` 为 merge 门槛，红即阻断）；但放弃「新增写操作只改一处」，三份表示与三处同步义务永续。作为宏被否决时的保守候补记录在案。
- **strum derive（`EnumIter`/`EnumString`）**：构造性保证同宏，引入新依赖族、`ALL` 从 const 变迭代器；对两个小派生面而言收益不抵依赖。
- **纯语言内判别式断言**（enum 末变体标记 + `(标记 as usize) + 1 == ALL.len()` 的 const assert）：在标记之后追加变体且漏登 `ALL` 时失明——追加恰是最常见编辑，验证有洞，否决。
- **壳声明守门升级为类型检查**：见决策 4，重申 ADR-0073 否决。

## 后果

- 新增写操作只改两处且各有强制：宏清单加变体（一处）、`signals_for` 加映射臂（穷尽 match 编译期强制，保持显式决策行——映射知识不随宏生成，ADR-0044 地位不变）；「漏登 ALL」「漏 parse」失败类整体消亡，孤儿核对的种子完备性由构造保证。
- 邻里弱点确认存在、本决策不触及：`TransactionKind::ALL`（9 变体）与 `InstrumentType::ALL`（5 变体）同为「enum + 手抄 ALL」双份表示（无字符串第三份，痛面较窄），立 #1022 候选票待 grilling、原生 blocked-by 本票（宏模式先例在前，方案才有依据）。
- 机制术语（`write_op_set!` / `from_ident` / 构造性保证）以本 ADR 为唯一解释处，不进 `docs/contexts/`（ADR-0047 决策 6 先例）。
