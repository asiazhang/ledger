# ADR-0011: 交易 kind→度量归属与 raw/native 金额分离收口为 transaction 领域模块

- 状态：已接受（正文已按 ADR-0099 / 0108 与 #1539 / #1549 / #1676 / #1769 现行态收敛）
- 日期：2026-08-25（现行态收敛：2026-09-24）
- 作者：Ledger 项目
- 关联：ADR-0013 / ADR-0033 / ADR-0105（写入编排与协议）；ADR-0019（汇率历史序列）；ADR-0067（余额缓存消费 `account_flow`）；ADR-0099 / ADR-0106 / ADR-0109（`convert` / `split` / `dividend` kind）；ADR-0108（`TransactionKind` 闭集宏单一化）；#1262（坐标收敛至 crate 级）；#1539 / #1549 / #1676 / #1769

## 背景

早期「交易落库」与「金额折算」散落在多个命令与查询模块：`INSERT INTO transactions` 列清单多处复制、`CASE WHEN` 金额口径散落余额/报表/预算三处、退款（`refund`）在余额（`+`）与支出净额（`−`）间符号冲突无法用单一符号表达，且定时引擎曾绕过折算静默存错外币本位币金额。因此将交易写入与金额口径统一收口至 `ledger-transaction` 领域 crate。

## 决策

### 1. `ledger-transaction` 领域模块为唯一真源（两道接缝）

- **Writer 接缝**：收口列映射、字段归一化、本位币折算与行写入（`normalize` / `insert_row` / `update_row`）；全部写入路径（创建/修改、投资交易、定时引擎、批量导入、同步重放）统一经其落库，审计字段与版本递增单点生成。
- **Amount 接缝**：收口 `TransactionKind` 闭集（9 种，ADR-0108 宏单一化）、kind→度量矩阵，以及两个显式具名折算入口——当期折算 `convert_to_native_current` 与交易日折算 `convert_to_native_on_trade_date`（不设隐式默认，调用方显式选择）。

### 2. raw/native 分离与折算规则（#1539 / #1549 / #1676）

- `amount_cents` 为原币金额，`amount_native_cents` 为折算至全局默认币种（DefaultCurrency，账本级设置，缺省 `CNY`）的本位币金额，**折算基准与账户币种无关**，正反向汇率兜底，缺汇率报错绝不静默混币种。
- **写路径折算时点恒取交易日期**：按交易所属 ISO 周命中汇率历史序列 `fx_rate_history`（ADR-0019），写入契约允许逐笔显式给出汇率，优先级为 **显式汇率 > 序列命中 > 报错**（非法显式值或同币种携带显式值一律码化报错拒落库）。每笔折算来源随行留痕（`fx_rate_used` 等）；编辑未改币种/金额/日期时沿用行内留痕，不重查序列。
- **读写折算边界受守门保护（#1676）**：当期汇率表只服务读路径当期估值（持仓市值、净资产、实物资产估值），`convert_to_native_current` 的生产调用方闭集入 `check-structure.ts` 认许边守门；写路径由负向断言守护不得退回当期折算；无现金腿 kind（如 `split`）经 Amount 接缝显式零腿构造，不经折算入口。

### 3. kind→度量矩阵（含取数列维度，#1769）

单一矩阵同时驱动服务端聚合 SQL 片段（`*_expr`）与行级 Rust 助手（`signed_amount`），全仓口径只维护一处（含 9 种 kind，保单域另派生 `policy_premium` / `policy_inflow`）：

| kind | account_flow（取原币） | expense_net（取本位币） | income_net（取本位币） | refund_gross（取本位币） |
|---|---|---|---|---|
| income | + | 0 | + | 0 |
| expense | − | + | 0 | 0 |
| transfer | account_id=− / to_account_id=+ | 0 | 0 | 0 |
| refund | + | − | 0 | + |
| buy | − | 0 | 0 | 0 |
| sell | + | 0 | 0 | 0 |
| dividend | + | 0 | + | 0 |
| split | 0 | 0 | 0 | 0 |
| convert | 0 | 0 | 0 | 0 |

- **取数列分界（#1769 修正）**：`account_flow`（账户余额口径，ADR-0067 缓存与实时计算共用）取**账户币种原币金额**（修复早期按本位币累计导致外币余额错误与净资产二次折算的缺陷）；经营收支与报表度量取本位币金额；净资产等跨账户汇总在汇总层按账户币种统一折回本位币。
- 净值恒等式单点定义：`expense_net = expense_gross − refund_gross`，月度汇总毛值由此导出，不另立度量。
- `buy`/`sell`/`convert`/`split` 属资本变动，不计入经营收支；`dividend` 计入 `income_net`。

## 理由

- 按度量分别定义符号直接化解 `refund` 在余额、支出净额与退款毛额三处的符号冲突，消除分散 `CASE WHEN` 漂移。
- 交易日折算 + 显式优先级 + 留痕保证历史本位币金额忠实反映当时汇率（当期折算曾令历史港币流水偏差近 5%），且历史行编辑不因远古数据源缺席而卡死。
- `account_flow` 取原币确保账户余额与账户唯一币种严格一致，跨账户汇总基准交由上层汇总统一折算。

## 备选与否决

- **保留各处手写 SQL / 单一 kind 符号加特判**：持续漂移且无法同时满足退款多度量，否决。
- **以账户币种作为本位币折算基准**：跨账户汇总口径漂移，否决。
- **写路径用当期汇率折算 / 合并为单一折算入口加模式参数**：前者扭曲历史金额，后者降低调用点可读性且无编译期防错收益，否决。
- **将投资 kind 归一化塞进 Writer**：制造交易域对投资域的反向依赖，否决（后续编排与接缝反转见 ADR-0013 / ADR-0105 / ADR-0112）。

## 后果

- 写路径依赖该交易周的汇率历史已同步或调用方显式传汇率，缺料即显式报错、不静默降级。
- 余额、报表、预算、定时引擎、批量导入与投资写入共享唯一矩阵与写入入口，新增 kind 或调整口径收敛于单一维护点。
