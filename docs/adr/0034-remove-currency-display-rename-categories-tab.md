# ADR 0034: 移除设置页「支持币种」只读展示，「分类与币种」Tab 更名「分类」

- 状态：已接受
- 日期：2026-08-30
- 作者：Ledger 项目
- 关系：部分修订 ADR-0022（Tab 格局中的 pane 名称与内容），其分域原则不变

## 背景

设置页「分类与币种」Tab 内的「支持币种」表格是 `currencies` 参考表的只读展示：数据来自种子迁移（11 种内置币种），应用与 AI 导入侧都只有读取能力（后端仅 `list_currencies` 命令；HTTP API 仅 `GET /api/v1/currencies` 供 AI 查询合法代码），UI 上不存在任何增删改。默认币种（唯一的币种偏好类设置）已按 ADR-0022 迁入「通用」。

于是这张表格在设置页里什么也维护不了、什么也操作不了——与「参考数据维护」的 Tab 定位相悖，只读展示还把「分类与币种」Tab 名撑成了一个不再成立的名字。项目所有者判定：无意义，删除。

## 决策

1. **删除「支持币种」只读展示**：`CurrencySettings` 组件及其在设置页的挂载点移除。
2. **Tab 更名**：「分类与币种」→「分类」（pane `name` 同步 `categories-currencies` → `categories`），pane 内只剩分类管理器。Tab 名必须与内容一致。
3. **币种字典不动**：`currencies` 参考表、`list_currencies` 命令、`GET /api/v1/currencies`、reference store 的 `currencies` / `currencyMap` 全部保留——币种字典仍是账户 / 交易 / 表单下拉的选项来源、`formatAmount` 符号与小数位格式化的依据、外键约束（`accounts / transactions / items / exchange_rates` 的 `currency_code`）的锚点。本决策只撤「展示」，不动「字典」。
4. **自定义币种留待真需求**：未来若出现种子外币种（如泰铢、新台币）的真实需求，再做 `create_currency` 命令与管理界面，届时币种维护 UI 以何种形态回归（独立 Tab / 分类 Tab 子页签）另行决策；在此之前不预留空壳入口。

## 理由

- 设置页的每个控件都应可操作，只读表格打破这一直觉；ADR-0022 把该 pane 定位为「参考数据维护」，只读展示不维护任何东西，属定位错配。
- 删除展示的成本几乎为零（字典本体与全部消费方不动），而保留的成本是持续的困惑：用户面对一张不能操作的表，开发者面对一个名不副实的 Tab。

## 代价与边界

- 用户失去应用内查看「支持哪些币种」的入口（可观测性小损）：合法币种仍可经账户 / 记账表单 / 默认币种下拉间接感知，AI 可经 `GET /api/v1/currencies` 全量查询。
- ADR-0022 描述的 Tab 格局由此部分修订（名称与 pane 内容）；其按领域分域、「关于」末位、轻量判定等原则均不变。
