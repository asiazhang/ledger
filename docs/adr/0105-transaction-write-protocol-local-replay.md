# ADR-0105: 交易写入协议——create/update 单正文，Local / Replay 形态闭集承载双写差异

- 状态：已接受（grilling 定稿，2026-09-11）
- 日期：2026-09-11
- 作者：Ledger 项目
- 关联：#1004（spec 与实施票，架构走查 2026-09-11 候选 2、走查 Top recommendation）；ADR-0013 / 0033（行为层单点穷尽分派与编排入口、事务所有权——本决策细化其承载形态，不翻案）；ADR-0091（哑通道 + 语义命令重放——重放语义零变化）；ADR-0099 决策 5 / 6（convert kind 变更守卫与重放结转成本比对——语义零变化）；ADR-0097（删除级联语义——delete 现状保持）；ADR-0060（panic 门禁——防御臂写法）；ADR-0087（断言强度——载体选型与测试判分的依据）；ADR-0102（机制词不进词汇表的先例）；#1003（事务原语基础设施化，先行票）、#1005（investment lots / unwind 深模块，先行票）

## 背景

交易的写入 grammar——守卫 → 回退（修改路径）→ 计划装配 → 落库 → 应用副作用 → op 产出——在 create 与 update 两条正文里各拼写一遍：本地正文（`create` / `update` 编排入口的协议函数）与重放正文（`replay_create` / `replay_update`）平行演进，四笔刻意差异（id 来源、计划装配来源、op 发射、存活校验）只活在注释里。kind 守卫（dividend / split 显式拒绝）与「进/出 convert 的 kind 变更禁止」（ADR-0099 决策 5）在两侧各写一份，同码同文案靠纪律维持；基金转换落地（#978–980）已经付过一次「一张票必须同时改两侧、漏一处不报错」的变更税，dividend / split 落地（ADR-0099 明示的预留开口）还将再付一次。

一个先例已在：delete 路径经 `OpEmission`（Local / Replay 二值闭集）单正文承载双形态——op 发射差异已是形态参数，证明该形态在本仓可行且稳定。

grilling 核实校准的两个事实：

1. **存活校验的不对称比「重放多了个校验」更深**：本地路径对账户引用没有任何显式存活校验——归一化不查、外键只挡硬删后的不存在，往**软删**账户记账本地可落库（靠前端守住）；重放侧查 `is_deleted=0`，是 ParkedOp「不自动复活已删数据」契约的组成部分。两侧语义真不同，不是漏写。
2. **trade.rs 的四份 FIFO 取批 + 超额守卫拷贝已归 #1005**（`lots::plan` 内化守卫、`unwind` 收编 revert/release 模板），不在本票范围；issue「涉及模块」的后四行随 #1005 落地消失。

## 决策

### 1. 范围：create / update 收进协议本体，按入口各一；delete 保持现状

create 与 update 各自的顺序契约收进单正文**协议函数**，Local / Replay 作为两形态承载差异。协议按入口各一（创建协议、修改协议）——两者顺序真不同（修改多「读旧行 → convert kind 变更守卫 → 回退」），塞进单函数要靠入口参数分支、match 点翻倍，违背 locality。issue 标题「一个写入协议」读作「写入 grammar 不再双写」，非「单一函数」。delete 的 grammar 不重塑（无行为收益的搬移），后续值得与否另评估。

### 2. 载体：形态闭集参数（`OpEmission` 推广合一），协议在分歧点 match

差异载体 = Local / Replay 二值闭集枚举，由 delete 的 `OpEmission` 改名推广而来——协议与 delete 路径共用同一枚举，不留第二份同义区分（同文件两枚举表达同一区分，正是本票要消灭的双源形状）。协议在每个分歧点 match 形态：

- **计划装配来源**：本地按输入重折算（归一化 + 本位币折算 + 商户即建证据）；重放按命令携带行装配（投资域重放形态计划，不重折算，源端折算 ADR-0091 决策 3）；
- **id 来源**：落库时本端生成 vs 随命令携带（两端收敛同一行）；
- **op 发射**：本地逐笔留痕 vs 重放不产本地 op（CONTEXT-sync 契约④）；
- **存活校验**：重放独有（决策 4）。

- **备选与否决**：
  - **trait 泛型两 impl**（静态分派、差异成接口、非法组合编译不可表达）：收益诱人但付不回——其独有收益「接缝可被测试替身跨过」在本仓不成立：协议步骤全是 SQLite 操作，替身 adapter 只买得到调用序列断言，恰是 ADR-0087 断言强度纪律不对准的「函数调用形状」；形态对称性由单正文编译期构造保证，不需要替身兜底。且与仓库品味一致：ADR-0013 拒 trait 注册表（薄 match 优于间接层），ADR-0101 的 trait 是为跨域 14 绑定付的代价，模块内两态闭集不构成该代价的理由。防重提。
  - **最小抽取**（只共享守卫函数，正文保留）：差异继续活在正文里，本票核心痛点不解决。
  - **单函数协议 + 入口参数**：见决策 1，否决。

### 3. 守卫单点：kind 守卫与 convert kind 变更禁止进协议本体

dividend / split 显式拒绝（同码同文案）与进/出 convert 的 kind 变更禁止（ADR-0099 决策 5）从两侧正文收进协议单点；穷尽 match 的兜底臂沿 ADR-0060 现行写法（同码错误表达不可达态，不引入 panic 构造）。`writer::normalize` 对非通用 kind 的防御性拒绝（ADR-0013 决策 5）保持不动。

### 4. 存活校验保持不对称，差异进载体并注明缘由

重放形态的账户存活校验（含出资端）保持原样——它是 ParkedOp 契约（不自动复活已删数据、往已删账户记账挂起待裁决）的组成部分。本地形态**不补**校验：本地侧口子（往软删账户落账）由前端守住，后端补守卫属用户可见行为变化（原本能落的账开始报错），超出本票「重构零行为变化」目标；口子登记在案，关闭与否另立缺陷票，不夹带。

### 5. 事务落点：协议本体自持「保证处于事务中」

嵌套感知事务（ADR-0033 决策 2）的落点从三入口收进协议本体：创建/修改协议自持 `ensure_transaction`，入口与 `replay_command` 双双薄化；delete 维持入口持有现状。裁决本身不变（嵌套感知、「事务知识归行为层」），变的是落点。同步引擎的外层事务照旧（嵌套加入、无害），「命令执行 + op 落日志 + 位点推进」同事务的原子性不受影响。事务原语消费 #1003 落地后的基础设施形态（`db::tx_scope`）。

### 6. 投资域边界：本票不碰 trade.rs

FIFO 取批 + 超额守卫四份拷贝与 revert / release 模板归 #1005（已定稿：`lots` / `unwind` 两个深模块）；其 `unwind::remove(mode: Update | Delete)` 是**入口形态轴**，与本票的 Local / Replay 形态枚举同名不同义，防混淆注记在案。`prepare` 与 `replay_plan` / `replay_convert_plan` 的镜像收敛待 #1004 + #1005 均落地后走查残留再定——#1005 后两侧装配都消费 `lots::plan`，剩余双写面预计大幅缩水，是否仍值一票届时再判。

### 7. 测试判分：契约属于谁，测试写在哪层

- **协议级**（对收口点断言一次，两形态参数化跑同集）：顺序契约、kind 守卫同码同文案、op 发射开关、错误码契约；
- **形态级**：Local 的 op 载荷形状与 id 生成；Replay 的 id 携带、存活校验挂起联动、「重放不产本地 op」；
- **不写调用形状断言**（ADR-0087）；形态对称性不靠测试兜底——由编译期单正文构造保证。

存量 `transaction/tests/behavior.rs`、`transaction/tests/oplog.rs` 与 `sync_engine/tests/*` 的逐条归层清单随 spec 定案。

### 8. 附带定案

- 修改协议的旧行读取取**并集**：本地需要的商户/保单与重放需要的 kind 一次读出（重放多读两列无可观察影响），协议内单次读取。
- 实施顺序：**#1003 → #1005 → 本票**（两先行票都动 behavior.rs；#1005 后回退步骤已是 `unwind::remove` 单调用，协议的回退步骤更干净；#1003 后事务原语直取基础设施）。

## 理由

1. **双写的单价已被实测**：convert 落地为塞进第 9 种 kind 同时改两侧正文与投资域镜像；守卫与顺序的每次演进都在付「漏一处不报错」的税。单正文让「守卫与顺序改动一处生效」从纪律变构造。
2. **形态闭集参数是仓内已验证的形态**：delete 的 `OpEmission` 先例证明二值闭集 + 分歧点 match 足以承载双形态，机制零新增；trait 的边际收益（接口化、非法态编译化）在两态规模下买不到，且其测试面收益与 ADR-0087 相抵。
3. **事务落点进协议是 ADR-0033 方向的自然延伸**：「保证处于事务中」的知识跟协议走而非跟入口走；嵌套感知使引擎外层与协议内层天然合成一个事务，语义零变化。

## 代价

1. delete 与协议共用枚举但 grammar 不重塑——同一文件内 delete 仍是旧形状「参照实现」，与协议函数并存至后续评估。
2. 本地往软删账户落账的口子保留（决策 4），缺陷票承接。
3. 枚举改名触碰 delete 路径的类型名与注释（机械改动，行为零变化）。
4. 协议函数签名携带形态枚举，入口薄壳多传一个值——可忽略。

## 后果

- 新增或修改守卫 / 顺序 / 错误码只改一处；dividend / split 落地（ADR-0099 预留开口）不再双写。
- 词汇表收「写入协议（Write Protocol）」词条（CONTEXT-core）；机制词（枚举名、协议函数名）以本 ADR 为唯一解释处（ADR-0102 先例）；CONTEXT-sync 的 Replay 词条补指针，不重定义。
- 投资域镜像的剩余痛面在 #1004 + #1005 落地后走查，届时不值一票即销账。
