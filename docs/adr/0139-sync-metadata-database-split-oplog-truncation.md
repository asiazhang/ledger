# ADR-0139: 同步元数据拆库（sync.db 独立于主库）与 OpLog 截断放开

- 状态：已接受（裁决票 issue #1858 定稿；本 ADR 裁决双库布局与截断语义，行为改动随实施票落地——拆库本体归 #1858，截断启用与水位上报另立实施票，见「决策 10」）
- 日期：2026-09-28
- 作者：Ledger 项目
- 关联：**ADR-0091**（决策 6 的「OpLog 只增不改」纪律与决策 9 的 Checkpoint 语义——快照整库形态与截断默认不启用由本裁决修订）；**ADR-0117 决策 6**（WAL 边界「本决策不含 WAL」——本裁决的跨库原子性前提与它互为约束，见决策 2）；ADR-0120（轮次分段取锁——截断触发的落库段归位，见决策 8）；ADR-0098（触发编排）；ADR-0089（多账本独立库文件先例）；ADR-0087（断言强度，实施票负向判据依据）；issue #1858（本裁决）、#857（被推翻的「v1 永不截断」裁决）、#855（V020 引入 OpLog）

## 背景

`sync_ops` 及其索引约 26 MB，占生效主库体积约 1/3（#1858 实测：78 MB 主库，29,616 行 op 不足 20 天累积，payload 15 MB），是主库中唯一**只增不减、与账本规模无关**的增长源——按当前速度年增约 400 MB，备份体积、一致性快照耗时、异端重放成本全部为它买单，而账本数据本身年增长仅个位数 MB。#857 当时以「增长量级 ≈ 几十 MB/年、简单性优先」钉死 v1 永不截断，该量级估计已与实测脱节。

拆库在数据上自洽：V020 即刻意不设跨表外键（`device_id` 无外键、`entity` 开放枚举、payload 自带源端折算结果），取证确认全部同步元数据 SQL 均单表语句、无跨库 JOIN、无触发器，拆分不产生悬挂引用，读路径几乎零改动。

两个裁决前提取证（#1858 设计前完成）：

1. **原子性前提成立但绑定非 WAL**：生产建连不设 journal_mode，主库维持 rollback journal（DELETE）+ synchronous=FULL（#1729 评估维持不切 WAL，ADR-0117 决策 6 明示边界不含 WAL）。SQLite 在非 WAL 下跨 ATTACH 库事务由 master journal 保证**集合级原子**——「业务写入 + op 落日志 + 逻辑时钟推进」同生共死的既有契约在双库布局下成立；若切 WAL，该保证消失（各库分别原子、集合不原子）。
2. **范围外缺陷（先行独立票修复）**：投资域简单写（汇率、现价、删标的、建档改名、手动报价）与本位币设置路径的「业务写 + op 追加」无事务包裹——生产 IPC 统一写入口不开启事务，实际逐语句 autocommit，违反 V020 以来的同事务纪律；且全仓无「业务写失败 ⇒ op 必不存在」的逐域断言。此缺陷与拆库无关（现状已违约），先于拆库实施单独修复，避免验收面失控。

截断是否随拆库一并放开，是本裁决的第二决策点：拆库只解除日志对主库的拖累，日志自身无界增长仍在；用户裁决「要优化就从设计上彻底优化」，连截断一起放开。

## 决策

### 1. 双库布局：四表闭集迁出主库

`sync_device`、`sync_ops`、`sync_parked_ops`、`sync_stream_positions` 四表整体迁出主库，落独立库文件 `sync.db`（多端同步域新词条**同步元数据库（SyncDatabase）**），经 ATTACH 挂载；主库只存账本数据。`sync_device` 单行随迁，避免设备标识跨库引用。

**清单边界（防漏网误搬）**：`app_settings` 的 `sync.channel.config`（设备偏好）与 `sync.last_sync_at`（运行时状态）留主库设置面；业务主表自带的 `device_id / version / is_deleted` 同步审计列（V001 即有）是业务表自身列，不属同步元数据表。四表即闭集。

### 2. 事务边界：单一事务覆盖两库，以非 WAL 为前提

「业务写入 + op 落日志 + 逻辑时钟推进」维持覆盖 main + attached 的单一事务提交/回滚，重放侧「命令执行 + 外来 op 落日志」同款。**该集合级原子性以主库非 WAL 为前提**（master journal 机制）：本裁决与 ADR-0117 决策 6 互为约束——未来任何切 WAL 提案必须先重审拆库原子性，两侧 ADR 互相引用，防止单边翻案。

实施判据两条：

- 跨库原子性测试必须用**文件库**（main 为 `:memory:` 时跨库事务无集合级原子保证，内存库测不出真实语义）；现有内存库测试模板需开文件库变体承载此类断言。
- 逐域补「业务写失败 ⇒ op 必不存在」断言（验收随缺陷先行票与拆库票分摊），断言对准可观察结果（ADR-0087）。

### 3. 加密与连接：同形态同密钥、成对连接均挂载

`sync.db` 与主库**同加密形态、同口令派生密钥**（SQLCipher 带密钥挂载；无密钥挂载必然失败，主库加密转换时两库同步转换）。写连接与只读连接（ADR-0117 成对连接）在建连收尾单点各自挂载，只读侧以只读形态挂载。挂载失败按码化错误显式报错，不静默降级。

### 4. 迁移：单链双库，主库迁移链是唯一事实源

主库迁移链（`user_version` 追踪、每迁移单事务、全新安装从零顺序跑）继续作为唯一 schema 事实源：搬迁以**一个新编号迁移**完成「挂载 sync.db + 建四表 + 搬数据 + DROP 主库同名表」（非 WAL master journal 背书下单迁移原子）；后续同步元数据 schema 演进继续走主库链新编号。迁移框架需支持**事务外挂载**（ATTACH 不能在事务内执行——runner 前置挂载或等效机制）。`schema_guard` 漂移守卫扩为双库校验。否决 sync.db 独立版本链：搬迁天然跨库，双链引入先后编排与失败恢复复杂度，且 v1 无独立打开 sync.db 的场景。

### 5. Checkpoint 快照双文件成对与跨版本引导

快照从「整库单文件」改为**业务快照 + 同步元数据快照同刻成对产出**（均在单连接互斥锁内、非事务路径，`VACUUM INTO` 逐库执行），通道 manifest 检查点指针扩为双指针；「位点与快照须同刻成对」约束不变，「文件即真相」语义保留。引导按快照形态归位：

- **新版端引导旧版端单文件快照**（旧形态内含四表）：引导代码按表来源拆归两库，兼容期保留；
- **旧版端拿到新双文件快照**：引导前置校验显式报「对端版本过旧」类码化错误，不模糊失败。

### 6. 应用内备份与恢复双库成对

Backup/Restore 与 AutoBackup 的备份产物扩为主库 + sync.db 成对（同加密形态继承），恢复即整个世界含同步身份（设备标识、位点、日志）一致回滚——通道段永不删除 + 重放幂等兜底位点回滚窗口。备份设置可提供排除 sync.db 的轻量形态作为实现可选项（默认双库）。恢复后同步身份随库回滚、无缝续同步，不引入「以新设备身份重新加入」的恢复路径。

### 7. 容灾：sync.db 不纳入外部备份脚本

用户自备容灾通道（如对象存储备份脚本）只备主库。已知接受面显式记录：单端用户丢失 sync.db 即丢失 op 审计历史（账本数据零损失，同步自愈以首轮全量重投为代价）；多端用户各端日志互为副本、截断放开后 sync.db 有界，应用内备份（决策 6）已提供本机副本链。

### 8. 截断放开：推翻 #857 的「默认不启用」

OpLog 截断从「机制随票实现但默认不启用」改为**启用**：

- **水位公式**（沿用 #857 已设计口径，落地为通道层义务）：安全水位 = 各端上报位点的最小值，并入已并入对端可达 Checkpoint 覆盖校正；**上报承载在 manifest**（各端每轮回写 manifest 时顺带声明本机对各流的已应用位点），复用 manifest 整体替换与轮次在途互斥的既有纪律。位点不走数据面（特殊 op 会污染 DomainCommand 语义）。
- **触发**：成功轮次落库段（ADR-0120 决策 2 的落库段，现落「上次成功同步时刻」处）顺带检查水位，达标即自动截断自己的流——无用户开关、无保留期保护；三硬约束不变（只有来源设备有权截断自己的流、只删位点之前、挂起 op 不在日志天然不被截）。
- **已知接受面**：审计历史随截断流失；升级用户升级后首次达标即触发历史性截断（一次性流失时刻）；离线端/退役设备流的水位冻结使截断延迟（安全侧保守，只影响瘦身及时性）——v1 不做设备退场机制。
- **单端/未配同步世界不截断**：水位不可证（无对端声明、无并入 Checkpoint 证据）即不删，截断只在同步世界内发生。

### 9. 边界：通道段生命周期不动

通道上的段**仍永不删除**。删除权晚于本地截断授予：本地截错可从通道段恢复，段删错无救（只剩 Checkpoint 全量兜底），删除安全条件（全端位点越过 + Checkpoint 可达）与对象存储生命周期规则是更晚的另一档裁决。通道段无界增长（用户自付存储费）记为已识别后续方向，另立票。

### 10. 配套文字修订清单与载体

本裁决随裁决票同步落地的文字：多端同步域词条修订（SyncDatabase 新增；Checkpoint 截断段与快照形态、OpLog 截断例外、Transport 通道段措辞、SyncRound 落库段触发点的修订）与 `CONTEXT-MAP.md` 条目同步。行为改动与配套测试分票落地：**拆库本体归 #1858**（双库布局、迁移、加密、备份恢复、checkpoint 双文件、原子性测试，含「删除接线即变红」负向判据）；**截断启用（水位上报 + 触发调度）另立实施票**，依赖拆库落地后的通道形态；**投资域/本位币事务包裹缺陷先行独立票**。

## 否决（防重复提案）

- **维持永不截断**：量级估计已被实测推翻（年增 400 MB 而非几十 MB），拆库后 sync.db 独立无界增长只是把焦虑换了个文件；截断的安全机制（三硬约束 + 位点安全义务）#857 时已实现，缺的只是水位上报——放开是补齐而非新建。
- **位点作为特殊 op 走数据面上报水位**：污染 DomainCommand 语义（位点不是域命令），且给 op 流增加非命令流量；manifest 是通道元数据的既定归口。
- **手动截断入口 / 保留期保护**：安全条件是机制性的，交给人判断制造「该截不截 / 乱截」双风险；保留期是复杂度回归。
- **sync.db 独立迁移链**：见决策 4。
- **切 WAL 后以补偿协议维持跨库原子性**（启动对账、孤儿 op 检测一类）：把集合原子降为「最终一致 + 补偿」，违背「日志与账本同生共死」的既有契约品味；正确解是切 WAL 提案先重审拆库（决策 2 互锁）。
- **checkpoint 单文件容器**（引导时 SQL 级重组两库进一个文件）：每次快照多一次重组编排，「文件即真相」变弱（文件需解释才等于状态）；双文件成对 + manifest 双指针更直。

## 后果

- 主库立即减重约 26 MB 并回归账本数据线性增长；备份体积、一致性快照耗时与主库解耦（应用内备份按决策 6 仍成对含 sync.db，其体积随截断放开收敛为有界）。
- 新增一条架构耦合：**跨库事务原子性 ⇔ 非 WAL**。任何 WAL 提案进入评估即触发 ADR-0139 重审；评审双库写路径时按此核对。
- 新增接线型约束：全部 op 产出调用点（各域写入口、重放、期次触发）必须在覆盖两库的单一事务内——实施票以逐域「业务写失败 ⇒ op 不存在」断言与「删除事务包裹即变红」负向判据钉住（ADR-0087）。
- 引导与备份产物从单文件变为成对产物，产物形态校验与跨版本引导兼容进入评审面；旧形态兼容期随旧版本端自然消亡。
- 截断放开后 sync.db 有界；水位上报使 manifest 多承载每端位点声明，manifest 归并自愈纪律覆盖之。
- 审计历史从「永久」变为「截至安全水位」，已在决策 8 显式接受并随词条声明；对 op 历史的分析需求以 Checkpoint 存档为替代来源（如需）。
