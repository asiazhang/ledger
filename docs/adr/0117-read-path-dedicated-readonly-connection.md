# ADR-0117: 读路径独立只读连接（路线 B）——长写事务不再挡读，不含 WAL 与连接池

- 状态：已接受并落地（#1280 实施；已由 ADR-0125 异步 DB 门面的写/读线程承接，#1410/#1414；存量读路径甄别随 #1726/#1727 收窄为两条；正文已按现行态收敛）
- 日期：2026-09-13（现行态收敛：2026-09-23）
- 作者：Ledger 项目
- 关联：修订 ADR-0069 决策 1（单连接 → 写连接 + 固定只读连接）；部分推翻 issue #147 方案 b 否决中的「第二只读连接」（维持 WAL 否决）；被 ADR-0125（全异步 DB 门面写/读专用线程）承接；ADR-0104（`read_entry` 仪式契约不变）；ADR-0075（加密口令与整库转换）；ADR-0080（原位重引导）；ADR-0114（跨账本只读连接先例）；#1274 / #1280 / #1410 / #1414 / #1726 / #1727

## 背景

早期单连接形态（ADR-0009 / ADR-0069）下，所有读写共用一条 SQLite 连接与同一把互斥锁：任意长写事务（批量导入、同步重放、定时追补、行情落库）持锁期间，全部读命令被应用层互斥锁**无界阻塞**。spec #1274 在路线 A（收窄写侧锁跨度）之外另立路线 B（本 ADR）：将读侧结构性移出写者闸门。机制术语「写连接 / 读连接」以本 ADR 为唯一解释处，不进业务词汇表。

## 决策

### 1. 两连接固定形态（写连接 + 独立只读连接）

- 在写连接之外另建一条指向同一库文件的**固定只读连接**，挂统一 `busy_timeout`（5s）；写连接维持单写者互斥。
- 在 rollback journal 模式（本决策不引入 WAL）下由 SQLite 文件锁仲裁：写事务进行中（RESERVED 锁）读连接照常读，不再被长写事务阻塞；仅写事务提交或 cache spill 取 EXCLUSIVE 锁瞬间由 `busy_timeout` 有界等待，超时显式返回码化错误。
- **异步门面承接（ADR-0125，#1410/#1414）**：读写分离现由异步 DB 门面的写线程与读线程分别独占持有；`read_entry` 消费门面读句柄、`write_entry` 消费门面写句柄。
- **存量读路径只读甄别**：闭包内含惰性写副作用的读形态命令走写槽读形态入口 `read_entry_on_write`（类型层禁止把写槽喂给 `read_entry`）。现役名单仅两条：`dashboard_overview`（余额缓存自愈 UPSERT）与 `audit_balance_cache`（漂移修复 UPSERT）；`search_transactions` 已随 #1726/#1727 拼音退役拆除惰性回填，转为纯读连接。

### 2. 密文库口令获取：换连点同源成对，不新增口令来源

- 两条连接各自完成 `PRAGMA key` 密钥注入（ADR-0075 决策 3），读连接消费换连点在场且已验证的主口令（手输解锁或解锁屏自动解锁读取的钥匙串缓存），**不在读连接建连时独立触发钥匙串/生物门读取**。
- `SessionEnvelope` 仍只服务同步轮次封包（ADR-0098），不承担读连接口令缓存职责；改口令/关闭加密后经原位重引导对称重建。

### 3. 四条路径的成对换入/换出协议（单点、fail-closed）

换连仍走既有成对换连原语（不改为门面作业，ADR-0125）；门翻转保持 fail-closed（进锁定/失败先立门再占位化换出，回就绪先成对换入再开门）；**读连接缺失时读命令报码化错误，严禁静默回落写连接**：

| 路径 | 换出（旧读连接） | 换入（新读连接） | 失败语义 |
|---|---|---|---|
| **加密解锁** | 初始即占位态 | 口令验证通过后与写连接成对原位换入再开门 | 口令错则双占位、保持锁定（无限重试） |
| **恢复（Restore）** | 替换库文件成功后**立即占位换出**（防 rename 后旧连接继续读旧 inode 陈旧数据） | 原位重引导（ADR-0080）按新库成对换入 | 恢复失败原库与旧连接不动；重引导失败落恢复屏 |
| **数据搬迁** | 运行期不动活动库；补做搬迁成功后由原位重引导接管 | 重引导按目标位置成对换入 | 补做搬迁失败不阻断解锁，按现状换入 |
| **加密转换** | 转换期间读旧库照常可用；原子替换成功后立即占位换出 | 原位重引导成对换入 | 转换失败原库不动、不换出 |

同族路径（重置、账本切换）按同一成对协议跟随；建连收尾单点（密钥注入 → 外键 → 耗时 hook → `busy_timeout` 5s）扩出只读形态，禁止调用点私建第二条连接（源扫描守门钉住）。

### 4. 备份不受影响

应用内备份通过 `VACUUM INTO` 从写连接生成一致快照，恢复安全备份发生在持写锁静止窗口内；只读连接不改变备份一致性、加密继承与跨设备可移植性（ADR-0075）。

### 5. WAL 与连接池边界（明确不做，设可检验升级条件）

- **不含 WAL，不含读连接池**：单写多读桌面场景下固定一条读连接已足够；WAL 会引入 `-wal`/`-shm` 边车文件，牵动备份、恢复、搬迁、重置与跨设备拷库全部文件形态（损害 ADR-0075 决策 7「模式随文件走」的简单性，且与 ADR-0139 跨库原子性互锁）。
- **WAL 升级触发条件**：仅当真实出现长于 `busy_timeout` 的写事务/提交窗口致读命令可感知失败，或出现「写事务期间要求无界读可用」的真实需求时，另行修订本 ADR 评估；读连接池不设触发条件。

## 与既有裁决的关系

- **issue #147**：推翻其对「第二只读连接」的否决（结构性防挡读优于事后衡量卡顿），维持其 WAL 否决与锁粒度收窄纪律。
- **ADR-0069**：修订决策 1 为两连接形态并承接其「真实多连接需求可重议」口子（结论仍是自建固定连接，继续否决 `tokio-rusqlite`）。
- **ADR-0104 / 0075 / 0080 / 0114 / 0125**：`read_entry` 仪式契约与加密/重引导语义不变；ADR-0125 在本读写分离基础上进一步将锁与线程模型升级为写/读异步门面。

## 备选与否决

- **`RwLock` 替代互斥锁**：`rusqlite::Connection` 非 `Sync`（类型层不成立），且应用层锁无法将读移出写者闸门，否决。
- **一步到位上连接池 + WAL**：提前支付全部边车文件与池化复杂度，无对应需求证据，否决。
- **`tokio-rusqlite`**：版本滞后且只解决线程占用，与读写文件级分离正交，否决。

## 后果

- 长写事务不再阻塞读命令，提交瞬间等待由 5s `busy_timeout` 有界化。
- 每账本连接数与换连面翻倍，由成对换连单点、类型分槽（`read_entry` vs `read_entry_on_write`）与接线负向测试防止漏换或陈旧读。
- 「读路径无写」成为运行期硬约束，误入隐藏写会在只读连接上即时暴露。
