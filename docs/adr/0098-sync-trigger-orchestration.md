# ADR-0098: 同步触发编排——打开即同步、低频轮询与写后即时上传

- 状态：已接受
- 日期：2026-09-10
- 作者：Ledger 项目
- 关联：ADR-0091（多端同步总决策；本文是其「触发」面的取舍留痕，ADR-0091「后果」段已明言触发时机与 v1 通道后端是**可逆工程决策、不记入该 ADR**）、ADR-0016 / 0042（自动备份与定时追补的轮询线程先例）、ADR-0032（连接层写入口提交点——写后触发的挂接位置）、ADR-0075 决策 3（钥匙串读取带生物认证门）、ADR-0069（阻塞 IO 进阻塞线程池）、issue #863

## 背景

ADR-0091 决策 9 定了触发的**语义**：打开应用即同步、桌面运行期低频轮询、手动「立即同步」，Android 后台不承诺、打开即同步兜底。它刻意没定**工程参数**（周期多长、写后是否每次触网、密文库自动轮询从哪拿口令），因为这些是可逆的，改主意的代价只是换个数或换条路径。

#862 落地后，同步只能手动触发；#863 把触发编排补齐。补齐时必须回答三个 ADR-0091 没回答的问题，而三者的答案都不显然：

1. **轮询周期**——短了空转成本高，长了「对端改了数据」迟迟不生效；
2. **写后即时上传**——字面理解是「每写一笔就传一次」，批量导入会变成 N 次触网；
3. **密文库自动轮询的口令来源**——钥匙串读取在发布构建下带 LocalAuthentication 门（ADR-0075 决策 3），后台线程读钥匙串会弹 Touch ID。

## 决策

### 1. 轮询周期：10 分钟，与自动备份同量级

`POLL_INTERVAL = 10min`，与自动备份调度线程的检查周期一致（ADR-0016 修订注记：30 → 10 分钟）。理由是同一条：**低频兜底，不追求实时**。轮询只解决「对端有新数据」与「写后触发失败后重试」，日常时效由写后即时上传承担（决策 2）；每轮开销是「拿锁 + 读一行设置 + 一次 manifest GET」，毫秒到亚秒级，10 分钟一次可忽略。

取舍：更短（如 1 分钟）在多数网盘上会把「低频」变成「常驻请求」，且与「无自建服务端、尽力而为」的定位不符；更长（如 1 小时）则写后失败的重试窗口过宽。

### 2. 写后即时上传：提交点信号 + 去抖合流（5 秒窗口）

「写 op 后即时入队上传」实现为：**连接层统一写入口的提交点发一个信号**（与置脏同一位置，ADR-0032），**调度线程在 5 秒静默窗口后跑一轮**。

- 触发点选提交点而非各写路径：所有业务写入（IPC / HTTP / 批量导入 / 重放）天然覆盖，各写路径对同步域零接线、零感知——与 ADR-0032 置脏同款收口理由。
- 信号**非阻塞**（无界通道投递即返回），写路径不等网络。
- 去抖合流在调度线程侧：连续记账（批量导入、连续录入）合流成一轮，且**最后一次写之后仍会跑一轮**（窗口内继续吸收写信号，静默 5 秒才执行），最后一批 op 不会漏。

取舍：不用「每次写都跑一轮」——批量导入 500 笔会变成 500 次触网；不用「更长窗口」——5 秒对「记完账切到手机」的体感已经够快，且不显著增加触网次数。

### 3. 密文库自动轮询：进程级会话口令，不读钥匙串

解锁密文库成功、一次成功的手动同步、用户设置「本机记住主口令」三处把口令记入**进程级会话单例**；自动轮次（打开即同步、轮询、写后）从会话单例取信封模式：有口令则封包，无则按明文形态跑。

- **不读钥匙串**：钥匙串读取在发布构建下先过 LocalAuthentication 应用层门（ADR-0075 决策 3 / issue #866），后台线程读它会弹 Touch ID——后台轮询不得弹交互。
- 无会话口令时按明文形态跑：明文库的正常形态；密文库未解锁时业务 IPC 本就不可达（门禁拦截），轮次也不会跑。若密文库在会话中尚无口令（极端时序），自动轮次按明文形态跑会与「密文库段应为密文」不符——**这条边界由「解锁先于一切业务读写」保证不发生**，代价是自动轮次在未解锁窗口内跳过而非报错（更符合「打开应用即同步、失败不打扰」的定位）。
- 会话口令活到进程结束或下次引导换库（忘记口令重置、关闭加密、切换账本经原位重引导时清空）。

取舍：不用「钥匙串读一次缓存在进程内」——那仍会在第一次自动轮询时弹门（解锁后首次自动轮询恰是用户刚看到主界面时，弹窗突兀）；不用「后台线程拒绝跑密文库」——密文库用户就失去了打开即同步。

### 4. 自动轮询不做新端引导

`fetch_checkpoint` / `bootstrap_from_checkpoint` 的**壳层编排**（设置页「从通道引导本端」向导）不在本决策范围：引导是**整库换入**的重动作，必须是用户显式发起的向导流程（与 Restore 同款），不能挂在自动轮询上。自动轮次只做增量交换（发布自己流 + 拉取他人流）。

留痕动机：#862 的评审登记过这个缺口（`channel.rs` 注释曾指向「#862 壳层加入向导」而验收未含），本 ADR 明确它**不属于**触发编排，避免下一位读者以为自动同步会替用户完成引导。缺口仍在（带存量数据的旧端作为新端加入时需要它），但归属是壳层向导功能而非本票。

## 备选与否决

- **每次写后都跑一轮**：批量导入场景触网 N 次，且与「低频」定位冲突；去抖合流以 5 秒延迟换掉这个成本。
- **写后触发走独立线程 + 进程内互斥**：与轮询线程并发触网需要额外互斥；单线程承载两条触发路径天然串行。
- **轮询周期与自动备份共用一个线程**：两者职责不同（备份写产物、同步触网），合线程会把同步的网络阻塞带进备份的日界判定；各自单线程、各持单次拉起守卫更简单。
- **密文库自动轮询读钥匙串**：会弹 Touch ID，违反「后台不得弹交互」。
- **把触发时机与周期写进 ADR-0091**：ADR-0091 明言这两项是可逆工程决策、不记入该 ADR；本 ADR 只承载取舍留痕，便于将来改参数时找到理由。
- **自动轮次里做新端引导**：整库换入不是后台动作，见决策 4。

## 影响

- `src-tauri/src/sync_engine/trigger.rs` 成为触发编排的单点：通道配置与构库、轮次编排、会话信封形态、三条触发入口。壳层（`commands/sync_channel.rs`）退化为参数解包 + 一行调用（通道配置读取与构库校验从 #862 的壳层实现上收进域）。
- 连接层提交点（`db::write` 的 `after_commit`）新增一次非阻塞投递；未拉起同步调度或未配置通道时零动作，单测环境零影响。
- `db::passphrase_cache` 新增进程级会话口令（`set_session_passphrase` / `clear_session_passphrase` / `session_passphrase`）；调用点：解锁成功、手动同步成功、设置记住口令、忘记口令重置、关闭加密。
- 用户可见行为：打开应用后自动同步；运行期每 10 分钟一次；记完账约 5 秒后自动上传；密文库自动同步不弹 Touch ID；同步失败静默（本地记账不受影响），状态与挂起明细在设置页同步卡片可见。
- 参数调整（周期、去抖窗口）只改本模块常量，无 schema / 契约影响。
