# ADR-0030: 交易列表过滤收进 TransactionFilter 深模块

- 状态：已接受
- 日期：2026-08-29
- 作者：Ledger 项目
- 关联：issue #171（spec）

## 背景

交易列表视图（约 700 行）的过滤逻辑由时序标志交织出隐式状态机：`firstApply`（首刷防双刷）、`urlAccountSettled` / `urlMerchantSettled`（URL 参数结算标记）、`applyAccountParam` / `applyMerchantParam`（两条约 28 行的逐行镜像解析函数），加上依赖参考数据就绪状态的第二个 watch 补判；「翻回第一页并刷新」样板散布 7 处。真实的 bug 风险（双刷、补判覆盖用户手动改动）全藏在标志的调用时序里，而现有 1700+ 行组件测试绕过接口测时序——测试面与调用面不一致。issue #171 决定抽一个 TransactionFilter 深模块，本 ADR 沉淀 grilling 确认的接缝与规则。

## 决策

1. **新增前端 composable `useTransactionFilter`（工厂形态）**：每次调用返回独立实例，置于 `src/composables/` 层。接口收敛为 `setFilter(patch)`（声明部分过滤意图，立即生效）、`resetFilters()`（回默认态）、`refresh()`（外部数据变化：重拉 + 翻回第一页，不动筛选）+ 可观察状态（filters、page、pageSize、refresh 版本号）；无其他公开面。选工厂而非单例：未来第二个消费者（如搜索页）需要独立实例，避免分页与补判状态串扰。
2. **URL 下钻参数收成一张参数表**：`?account=` / `?merchant=` 的解析、校验、补判、让位对每个维度同规则处理，视图不再感知下钻参数有几个；两条镜像链路消灭。URL **只读不写回**（组件状态是唯一事实源，延续 #96 决策 3/4），路由变化由视图监听后递给模块。
3. **字段级让位**：补判遇用户已手动改动**同一维度**则让位，其他维度的补判照常生效（改了日期不连累账户补判）。URL 参数**至多消费一次**（无论应用还是让位，标记即结算），后续参考数据重拉（`ledger:changed` → status 再次 ready）不重放。
4. **复位契约保留现状**（#96 决策 3）：下钻进入且两个维度均无有效参数时，复位日期/类型；query 变化（含导航清除 query）时对应维度同步清空。
5. **模块内部消费 Reference Data store**：就绪时序由模块自己 watch `reference.status`，**不**向调用方暴露 `ready(参考数据)` 通知接口——这是对 spec 原案（接口含 ready 通知）的刻意偏离。
6. **模块只产出请求参数与版本信号**：请求发起、loading、行数据仍归视图；「统一出口」指模块内部统一产生「page=1 + 版本 bump」，翻页归零 + 刷新全仓仅此一处，双刷由出口唯一性消灭。分页参数（page/pageSize）归模块所有。
7. **测试策略转移**：模块测试打接口（意图 → 状态终态与请求参数），不测标志变量与 watch 拓扑；组件测试收缩为冒烟级（渲染与交互路由），可迁移的时序用例迁到模块接口测试，其余删除。

## 理由

- **为什么工厂而非视图私有模块**：它本质是「带可观察状态的逻辑单元」，composable 是天然载体；视图私有可能阻碍复用，独立 `src/modules/` 目录在仓库无先例。
- **为什么内部消费 store 而非 ready 注入**：深模块的方向是少一个调用方义务、就绪时序彻底内化；全仓原本只有 TransactionsView 用 watch status 等就绪（其他消费方一律 `ensureFresh()`），pinia store 在测试里本就是标准 mock 点（`createTestingPinia`），注入的解耦收益不抵接口膨胀的代价。
- **为什么字段级而非全局让位**：URL 参数只主张「账户/商户」各自一个维度；「我点了下钻就该看到那个实体的流水，除非我自己又动了同一维度的筛选」是最直观的产品语义，且让状态机从全局闩锁降为字段级事实比较。
- **为什么不写回 URL**：写回改变用户可感知行为（历史记录、复制链接语义），超出本 issue「契约不变」的等价重构边界；URL 同步若要做，另立需求另行 grilling。
- **为什么不合并 refresh 与 setFilter**：「重拉数据」和「改筛选」是两个不同意图；合并会让「改筛选必翻页」与「回填不丢上下文」互相纠缠，空补丁 hack 难读。

## 代价

1. 模块与 Reference Data store 建立静态耦合——参考数据本就是全库单例字典，耦合面可接受。
2. 组件测试大幅收缩：1000+ 行时序测试中不可迁移的用例将被删除，行为保障转移到模块接口测试。
3. `refresh()` 语义固定为「重拉 + 翻回第一页」；未来若出现「不翻页的静默重拉」需求，需扩展接口而非复用现语义。
