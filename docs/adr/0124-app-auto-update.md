# ADR 0124: 应用自动更新——桌面三平台 Tauri updater、GitHub 静态清单、全询问式与更新前备份

- 状态：已接受（grilling 定稿 2026-09-16；实施按后续票拆解，本文不直接改代码）
- 日期：2026-09-16
- 作者：Ledger 项目
- 关联：ADR-0066（跨平台发布；其缓行项「应用内自动更新」由本文收回，见其修订注记）、ADR-0074（Android 发布）、ADR-0007 / ADR-0016（备份机制）、ADR-0017（轻量设置项）、ADR-0050（错误本地化）、ADR-0078（分级确认）、ADR-0087（测试三层）、ADR-0111（壳层机制归位判据）；词汇表见应用更新域与备份与数据文件域

## 背景

发布矩阵已覆盖 macOS arm64（DMG，已签名公证）、Windows x64（NSIS）、Linux x64（deb + AppImage）与 Android（APK），产物汇总进单一 GitHub Release（ADR-0066 / ADR-0074）。ADR-0066 曾把「应用内自动更新（Tauri updater）」列入缓行清单——彼时发布即终点，用户升级靠手动下载安装包。本地数据库迁移单向前进（SQLite user_version 只升不降），多端同步下设备版本混用是常态，升级通道缺位既是用户升级率的瓶颈，也是「旧版长期滞留」的隐患。本 ADR 收回该缓行项，固定自动更新的范围、基建、交互与数据安全接缝。

## 决策

### 1. 平台范围：桌面三平台自更新，deb 与 Android 降级为发布页引导

macOS、Windows（NSIS）、Linux（AppImage）经官方 updater 插件自更新，更新单元为应用整体（前端与后端一体）。deb 与 Android 无更新器可消费的工件，更新入口降级为「打开发布页」引导，不冒充可自更新。**备选与否决**：Linux 整体手动——放弃 AppImage 自更新无收益；Android 自研下载提示——移动端更新通道在 MVP 边界外，需求出现另立。

### 2. 更新源：GitHub Releases 静态清单，端点数组留镜像扩展位

更新清单（latest.json）由发布流程在 publish 阶段生成并上传，客户端以静态端点查询——发布即更新源，不引入动态更新服务。端点以数组配置、按序尝试，为镜像 fallback 预留扩展位（后续加镜像不改代码）。检查请求携带当前版本、平台与架构（updater 固有），仅此而已。**备选与否决**：自建动态端点——运维负担买不到当前规模下的收益；tauri-action 全托管——ADR-0066 决策 3 已否决，维持手写 publish 路线。

### 3. 更新签名：minisign 式密钥对，公钥烧入客户端

更新工件强制离线签名，更新器验签通过才安装。公钥随应用发行——已发行客户端无法换锁，这是全程最硬的不可逆点；私钥入 CI secrets 并离线备份一份，泄漏即需重建信任链。更新签名与平台代码签名正交：前者证明「更新来自发布者」，后者证明「二进制可在平台安全运行」；Windows/Linux 平台代码签名仍缓行（ADR-0066 决策 4 现状），macOS 已另行完成 Developer ID 签名与公证。

### 4. 检查与提醒：启动延迟静默检查 + 手动检查，全询问式流程

启动后延迟静默检查，设置页随时手动检查；后台检查失败静默，手动检查失败就地报错（码化错误，ADR-0050）。发现新版本走全询问式流程：提醒弹层（含发布说明）→ 用户确认 → 下载（带进度）→ 确认后安装并重启；永不静默下载、永不静默安装。每个新版本至多自动提醒一次（「已提醒版本」记忆），待更新期间不反复打扰；设置页手动检查不受该记忆限制。**备选与否决**：每次启动都提醒——日常高频打开的应用会在整个待更新周期内骚扰；周期轮询——单机应用无收益；静默安装——记账数据的敏感度下，用户对「装了什么、何时重启」必须有完全控制权。

### 5. 兼容性立场：不设强制升级门槛

不引入「最低可用版本」闸门：迁移单向前进与多端混版的现实由更新清单的发布说明承载兼容性警告，由更新前备份（决策 6）兜底数据安全。**否决「现在就做门槛」**：为尚不存在的场景（旧版读到新 schema 的真实损坏路径）支付清单协议与强制流程的复杂度；该路径实证出现时另立 ADR。

### 6. 更新前备份：旧版内、安装确认后，仅活动账本，同族恢复安全备份

安装确认后、旧版退出前，由旧版自动为当前活动账本创建「更新前备份」（术语归备份域）：与恢复安全备份同族——系统自动创建与命名、独立于用户备份目录存放、不占备份保留上限配额、不标脏；覆盖式保留最近一份，不无限堆积；备份失败即中止更新并报错。范围限当前活动账本：未解锁账本没有可用连接（SQLCipher 整库加密，凭主口令才可读），全账本备份会引入「部分覆盖 + 提示」的复杂状态；非活动账本沿各自既有备份节奏。**备选与否决**：新版启动、迁移前备份——覆盖时机更精确，但把备份失败变成「应用打不开」的新启动失败模式；全账本备份——撞锁定账本之墙。

### 7. 代码归属：壳层机制

检查/下载/安装命令住根包壳层，前端面住壳层跨域件；不进基础设施 crate（ADR-0111 归位判据：只被壳层消费的机制归壳层），不立业务域 crate（无账本语义），不立壳内域目录。界面遵守既有约定：提醒与确认弹层接入 Overlay 体系与分级确认（ADR-0078）；更新入口按桌面专属管理动作对待（移动端呈现发布页引导）。启动延迟检查纳入后台服务成对拉起守门。

### 8. 设备偏好：轻量设置项承载

自动检查开关与「已提醒版本」记忆都是设备本机偏好，归轻量设置项（ADR-0017）：设备级、不随 Backup/Restore 迁移、不经账本数据分发；新装默认开启自动检查。不为此新增账本级设置。

### 9. 版本通道：单 stable

不引入 alpha/beta 通道 machinery；通道需求（外部贡献者测试面、灰度发布）出现时另立。

### 10. 发布流水线：手写 publish 生成清单与签名，密钥配置为一次性人工步骤

沿 ADR-0066 决策 3 的手写 publish 路线：publish 阶段新增「生成并上传更新清单与各平台 .sig 签名文件」步骤；macOS 补更新工件（.app.tar.gz）的公证接线。更新签名密钥对的生成与 secrets 配置是一次性人工操作，交付时附操作清单。首个带更新器的版本起清单才存在，更早版本无更新通道、无需回填。

## 后果

- 测试边界按测试三层（ADR-0087）：检查/下载/安装的壳行为归 API 集成测试，更新源以本地 mock 端点承载（不依赖真实 GitHub）；设置页与提醒逻辑归前端 Vitest；真实 GitHub 链路为手动冒烟清单，CI 不测外部服务。
- Windows 静默安装未经平台代码签名的安装器：交互安装的 SmartScreen 警告不直接适用于静默更新路径，但平台签名缓行的信任缺口仍在；出现真实用户反馈再重开 ADR-0066 决策 4。
- 词汇表新立应用更新分域（自动更新、更新检查、更新清单、更新工件、更新签名），「更新前备份」归备份域（谁定义、谁消费）。与 ADR-0066「构建/发布不进词汇表」的分界：自动更新是有运行时行为与界面面的用户可见功能，不是纯构建基建。
- 用户升级率与清单可达性（GitHub 直连）在首个发布周期观察；国内直连不可达的反馈达到阈值时，启用端点镜像（决策 2 的预留扩展位），不改代码。
