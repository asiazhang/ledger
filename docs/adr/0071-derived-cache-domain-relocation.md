# ADR 0071: 派生缓存归域——余额与净资产口径迁出基础设施（修订 ADR-0059 §5）

- 状态：已接受
- 日期：2026-09-04
- 作者：Ledger 项目
- 关联：spec #518（architecture review 2026-09-04 七项候选之首）；修订对象 ADR-0059 §5；前置 ADR-0056（三层定义与守门）、ADR-0059（模型域化与允许边）、ADR-0067（派生缓存语义）、ADR-0020（净资产口径）、#404（账户域归位，欠账注释出处）；#538（守门扩展实施票，含 §6 勘误注记）；后续「受影响账户集合收口」spec 的纯函数落点

## 背景

余额与净资产是全 App 消费最广的两个口径，但其实现不住域里——这是记录在案的裁决而非疏忽：#404 账户域归位时余额引擎留驻 `db/`，ADR-0059 §5（2026-09-03）把「基础设施消费域类型」认许为允许边，并明言「既定裁决不翻案」。代价随 V017 上线显性化：

- **口径散布**：净资产五个构成字段（本位币、总额、三腿分项）在 `db/net_worth.rs` 的 `CachedNetWorth`、`dashboard/model.rs` 的 `DashboardOverview`、`dashboard/mod.rs` 的桥接转换三处同形定义——ADR-0064 新增实物资产第三腿时三处全动，前科成立；确认「余额怎么算」需跨三分层跳四五个文件。
- **热区演进**：`db/balance.rs` 与 `db/net_worth.rs` 正处 V017 性能热区，口径散布与依赖成本随每次改动放大。
- **自认欠账**：`db/balance.rs`（「账户域归位 #404 时随迁」）与 `accounts/core.rs`（「#405 先行下沉，#404 归位时随迁」）两处注释自认迁移意图。

架构评审（2026-09-04）将归域列为七项候选之首。本 ADR 显式翻案——**翻的是记录在案的裁决，按纪律留痕而非静默变更**。

## 决策

### 1. 翻案声明与文档同步

推翻 ADR-0059 §5 的两个判定：①「余额计算引擎留驻基础设施单点」；②「结构守门维持只禁『依赖壳』一个方向」。ADR-0059 正文不重写，状态区加修订注记（先例：ADR-0059 修订 ADR-0056 的手法）。随最后一个使用者（余额/净资产缓存）迁出，「基础设施→域类型消费」允许边不再有实例；本文是派生缓存归域的唯一决策来源。

### 2. 余额口径模块整体迁入账户域

`db/balance.rs` 整文件 git mv 为 `accounts/balance.rs`：口径表达式消费（`transaction::amount::account_flow_expr`）、整体重算刷新、账户余额清单读取、实时权威计算（`compute_balance` 等）一个模块命中。对外函数签名不变；ADR-0067 的两条契约——写路径同事务整体重算（禁止增量加减）、缓存缺失报码化错误不静默回退——一字不动。

### 3. 净资产缓存收敛仪表盘域

`CachedNetWorth` 消亡，`DashboardOverview` 成为净资产构成五字段的唯一定义；指纹推导（贡献表 `MAX(updated_at)` 拼接）、读探针、缓存回填写整块迁 `dashboard/net_worth.rs`，`From<&CachedNetWorth>` 桥接与反向打包转换消亡。净资产缓存访问接缝签名随结构收敛改写；`dashboard_overview` IPC/HTTP/信号契约零变化。

### 4. 基础设施退回零业务语义

`db/` 保留连接、迁移、通用查询工具、data_location、perf_trace；两缓存模块的 SQL 全部随域走。域自持 SQL 是其余 13 个域的常规形状，`db/` 里的余额 SQL 本就是自认例外；**不建「通用缓存行管道」**——两个使用点不构成公共抽象（先例：ADR-0059 §2 不建共享模型残留模块）。

### 5. transaction ⇄ accounts 回边显式认许

迁移后 `transaction::writer/behavior` 调 `accounts::balance` 刷新（新边），`accounts::balance` 反向消费 `transaction::amount` 表达式真源——账户域与核心交易域成横向互依。这是设计意图而非副作用：ADR-0067 同事务约束排除信号/异步替代；「受影响账户集合收口」本就计划把推导落进余额模块。记录为「**核心交易仅在写路径为账户域维护余额缓存**」。依赖方向目标据此从「严格单向」修正为：infra→域业务边归零且可机械守门；域间横向边显式化、逐条留痕。

### 6. 结构守门扩展：infra→域扫描

`scripts/check-structure.js` 新增白名单基础设施条目内的「infra→域」文本级扫描，形态与现有 `commands::` 扫描同款（掩码注释与字符串后匹配域模块路径，fail loud）。迁移落地当天天然全绿——迁移前全基础设施仅 `db/balance.rs` 两行域 import。外挂测试继续豁免（ADR-0056 决策 5）。

> **勘误（2026-09-05，#538 实施时，维护者裁决）**：「落地即全绿」原前提漏数一条现存边——`db/mod.rs` 的 `after_commit`（ADR-0032 连接层统一写入口置脏单点，#246）以代码调用 `crate::backup::{mark_dirty, shared_prefs, run_due_backup}` 三处，早于本文写作，上句「仅 db/balance.rs 两行」数漏。裁决：扫描按全路径形态落地（含内联全限定路径、别名引入与模块自身导入；限定 crate 根前缀以避开 std::sync 撞名），该边作为首条「认许边」逐条留痕于守门脚本 `INFRA_DOMAIN_ALLOWED_EDGES`——精确到文件 + 目标域、附 ADR 指针，与白名单同属「已验证事实固化为规格」；清单之外的基础设施→域引用一律红。

### 7. 词汇表不动

NetWorth 口径词条留投资域词汇表——排除投资账户余额防重复计数的边界讨论天然属投资域话题；仪表盘域承载读模型结构与缓存 SQL，口径语义与实现住址各司其职，互不迁移。

## 测试与验收

- 零语义变化重构，验收 = 既有测试一行断言不改全绿（先例：ADR-0056 逐域搬迁「零语义变化 + 机械核对 diff」）。
- **测试面零切分**（事实修正 spec 的「随迁」假设：账户域与仪表盘域今日并无自持的余额/净资产测试）：V017 迁移回填测试留 `db/tests/`（被测对象是迁移，属基础设施）；缓存行为套件留 `transaction/tests/balance_cache.rs`（被测对象是交易写入行为；跨域 import 外挂测试合法，ADR-0056 决策 5）。随迁只有 import 改写。
- OpenAPI 契约 diff 为空（先例 ADR-0059 §7）；无 schema、迁移、AI API 契约变化，无 CHANGELOG BREAKING 条目。
- 迁移纪律：整文件 git mv、文档提交先行、一域一提交（①账户域 ②仪表盘域 ③守门扩展）、每提交 `check.sh` 全绿。

## 备选与否决

- **维持现状（ADR-0059 允许边）**：自认欠账 + 热区演进 + 三处定义前科，成本随每次热区改动放大；否决。
- **只收敛净资产结构、不动余额住址**：三处定义消了，欠账注释与后续 spec 落点仍在；否决。
- **基础设施建「通用缓存行管道」（指纹/按行读写参数化）**：两个使用点建共享管道，无第三使用者，与 ADR-0059 §2「使用矩阵证实无公共抽象」先例冲突；否决。
- **刷新接缝留基础设施半步走**：「余额怎么算」继续劈两半，违背导航目标；否决。
- **独立「余额域」**：为单模块立域过重，余额语义本属账户；否决。
- **NetWorth 词条随结构迁仪表盘**：口径语义（第三腿边界、负债符号）是投资域讨论；否决。

## 影响

- 「余额怎么算」在 `accounts/balance.rs`、「净资产怎么算」在 `dashboard/net_worth.rs` 一次命中；新增净资产构成腿只改一个结构体。
- 基础设施业务语义归零且入守门；新增一条显式认许的 transaction→accounts 写路径边。
- 「受影响账户集合收口」spec 的纯函数落点就绪。
- 零影响面：schema、迁移、IPC/HTTP 契约、命令注册清单、前端类型全部不变。
