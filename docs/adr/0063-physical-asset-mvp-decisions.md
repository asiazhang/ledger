# ADR 0063: 实物资产域 MVP 决策——估值档案 / 只追加估值历史 / 处置与软删 / 净资产第三腿 / 入口收纳

- 编号注记：spec #465 成文时引用本决策为「ADR-0062」，该编号后被性能基准 ADR（#470）占用，本决策顺延为 0063，语义即 spec 所指的实物资产 MVP 决策。

## 背景

Ledger 没有任何地方登记房产、车子这类大件实物：物品域只回答「从购买到今天平均每天花多少钱」（使用成本摊薄，ADR-0014），投资域只承载证券持仓。资产侧净资产只算账户余额加持仓市值，房车这样的真实财富完全缺席。经设计评审确定实物资产域 MVP 范围与一批跨域决策，本文记录决策与取舍。业务语义见实物资产分域词汇表 `docs/contexts/CONTEXT-physical-asset.md`。

## 决策

### 1. 单列小域，与物品域按「要不要跟踪市值」互斥分家

- 新增实物资产实体（PhysicalAsset），回答「我有哪几件大件、各值多少钱、家底合计多少」；与物品域 Item 的分界是**要不要跟踪市值**——物品摊薄使用成本（分母是天数），实物资产维护市值档案（分子是估值）；同一件东西不应两边都建。
- 单列小域先例：物品（ADR-0014）、预算（ADR-0029）、保单（ADR-0051）。**黄金等贵金属不在范围**：有真实需求时先评估投资域自建标的 + 手动报价承载（ADR-0036 已有该能力），不为本域再造报价机制。
- **备选与否决**：并入物品域加市值字段——两种价值语义（成本摊薄 vs 市值档案）互相污染；并入投资域——无行情同步诉求的实物挂证券模型是错配。

### 2. 估值全手动、只追加历史行，无买卖资金流挂钩

- 估值完全手动更新：每次估值（日期 + 币种金额）落一条**新历史行**，旧值保留不覆盖；当前估值 = 最新一条（估值日期最新，同日按插入序）。系统不做自动折旧或增值——价值判断始终由用户掌握。
- 估值日期缺省今天、允许补录过去日期（事后整理），**未来日期显式拒绝**（估值是已发生的判断）。
- 买卖资金流挂钩（交易溯源、资产账户、买卖/核销编排）三条路径均已评估并否决留档：实物买卖多数不进账本账、核销会撕裂账户余额口径、资产账户与现有账户体系冲突。未来诉求回归时再复活。
- **备选与否决**：估值可改写（覆盖最新一条）——历史丢失，违背档案语义；只存当前值不留历史——估值走势等后续诉求无原料，且「改错无法找回」。

### 3. Schema：两张新表、纯新增迁移

- `physical_assets`（资产表）：名称必填、购买日期 / 购买价 + 币种可空、状态（holding / disposed）、处置日期（已处置必填）、处置价 + 币种可空、软删标志、审计时间戳与多端同步字段；处置列随 T1 迁移一次建全（已发布迁移只增不改，T3 处置路径直接写入）。
- `physical_asset_valuations`（估值历史表）：资产外键（**CASCADE**——只追加的扩展行依附父行存续，先例证券批次）、估值日期、金额（整数分）、币种；只追加不改写，无更新语义，故不携带 version / updated_at / is_deleted，仅留 created_at / device_id 审计。
- 币种外键 **RESTRICT**（币种是种子权威字典，先例交易币种列）。
- **备选与否决**：当前估值冗余落资产表——第二口径，「当前 = 最新一条」已可高效查询（索引 + 子查询）；估值历史无外键约束——孤儿行风险，扩展行语义要求强关联。

### 4. 建档：名称与估值必填，购买信息可选

- 必填只有两样：名称（trim 非空）与当前估值（即第一条估值历史行，缺失显式报错、错误码化）——「三十秒录完一件资产」；购买日期、购买价 + 币种全部可选。
- 可选金额与币种**成对**（先例保单保额，ADR-0051）：金额存在时币种必填且须存在，金额缺省时币种忽略存空，不产生只有币种的半挂状态。
- 估值与购买价币种在前端预选默认币种（DefaultCurrency 设备偏好）；建档估值日期缺省今天。
- 编辑（名称 / 购买信息）全量替换；**估值不走编辑**——走更新估值（追加历史行），编辑表单不含估值字段。

### 5. 处置与软删（T3）

- **处置 = 状态标记**：状态转 disposed，处置日期必填、处置价 + 币种可选纯记录；已处置不进默认列表、不进在持合计与净资产，档案保留可经「已处置」筛选回看。列表默认只看在持资产，状态筛选参数随 T1 命令面一次留足。
- **删除 = 软删**：`is_deleted` 标志，不进列表与合计，数据与估值历史保留（误删有后悔药，与全库软删约定一致）；估值历史行不软删、随资产行可见性一体过滤。
- **备选与否决**：处置即删除——档案语义丢失（「这车卖了 8 万」无处安放）；处置价必填——卖房卖车常有抵债/赠与等无价场景。

### 6. 净资产第三腿（T4）

- 概览净资产扩 Σ 在持实物资产估值：每件估值经 Amount 接缝折算到默认币种（**当期汇率**，与核心流水 MVP 折算口径一致，不用历史汇率），缺汇率错误上抛（中文错误信息），不静默漏算。
- 已处置 / 软删资产不计入；可投资资产（财务自由度分子，ADR-0048）不受实物资产影响——「能钱生钱的资产」口径不被大件污染。
- **备选与否决**：历史汇率折算——估值本身已是某时点判断，再锁历史汇率过度精确；缺汇率按零计——净资产数字静默失真，违背「永远知道数字是完整的」。

### 7. 入口收纳「更多」页签（ADR-0055）

- 实物资产是典型低频维护视图（不在日常记账动线上），按 ADR-0055 开发者清单判定入「更多」聚合页为第三个页签（保单、商户之后），页签态走路由 query 单字段；不占侧栏位、不占键位。
- 界面 = 列表（状态筛选 + 在持合计卡）+ 建档 / 编辑弹窗 + 更新估值弹窗 + 处置弹窗 + 删除确认；估值历史展示界面 MVP 不做（列表 / 详情只消费当前估值，历史行已留原料）。

### 8. 错误码与文案

- 用户可见错误全部走码化构造器（`physical-asset.<条件>`，kebab-case，ADR-0050），zh / en 错误模板同步；界面文案按域分文件（zh-CN / en-US，含「更多」页页签名，ADR-0049）。

## 后果

- schema：新增实物资产与估值历史两张表（纯新增，相对 v0.3.0 无已发布面修改）。
- 词汇表：新增实物资产分域（实物资产 / 估值 / 估值历史 / 处置四词条）。
- 信号：写操作复用 `ledger:changed` 同名事件的独立域订阅者（物品 / 保单先例，ADR-0044 收编登记）。
- 净资产数字变大（建资产）与变小（处置 / 删除）是预期行为；报表 / 预算等流水口径零影响（本域不产交易流水）。
- 缓行清单：黄金等贵金属、买卖资金流挂钩、估值走势图与合计历史曲线、资产类型闭集与图标、负债联动（估值 − 贷款余额）、AI 导入识别建档、HTTP API 面（本域纯 IPC）。
