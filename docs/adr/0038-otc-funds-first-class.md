# ADR 0038: 场外基金一等标的——复用 Instrument 与 buy/sell，净值入价格线，价格刻度万分位

- 状态：已接受
- 日期：2026-08-30
- 作者：Ledger 项目
- 关联：扩展 ADR-0019（价格通道覆盖面从股票扩至股票+基金）；ADR-0036（基金按代码添加是其自建标的的按代码增强形态，来源 = 手动）；AI 侧配套见 ADR-0039；词汇表：投资域 Instrument / MarketPrice / PriceHistory / 价格刻度 / HoldingPriceSync / 价格失效信号 / Investment

## 背景

Instrument 类型闭集虽含「基金」，但基金至今是无行情来源的二等标的：手动盲建、无价格通道、增量同步跳过。需求是让国内场外公募基金（支付宝/天天基金渠道的申赎式基金，人民币份额）成为一等标的：有净值行情、有申赎记录、进持仓/盈亏/走势/净资产。三道坎：净值 4 位小数 vs 价格列「分」刻度；申赎语义 vs buy/sell kind；发布冻结 vs 刻度修改。经 grilling 定案如下。

## 决策

1. **复用 Instrument，零枚举改动**：类型 fund、市场恒 unknown——场外基金没有交易所市场概念，基金代码（6 位）无市场前缀规律（2021 年国标起与登记机构脱钩），纯字典键；`UNIQUE(symbol, instrument_type)` 与股票代码天然隔离。入口 = 手动输代码、按代码即拉东方财富详情回填（名称/类型/最新净值）；不做基金全量同步（全市场 2 万+只、录入频率极低，批量无价值）；来源标记 = 手动（ADR-0036 同路；修订：ADR-0036 自建白名单缩为债券/ETF/其他后，**fund 类型的唯一创建入口即本决策的按代码即拉**，自由文本代码无从产生自编 6 位 fund 行）。
2. **申赎复用 buy/sell，不新增 kind**：申购 = buy、赎回 = sell（数量 = 确认份额、单价 = 成交日净值、手续费 = 申购/赎回费），时点持仓推算、卖出 FIFO 匹配、盈亏页、走势全部自动工作。录入按确认后结果：忽略未知价与 T+1 在途，金额与确认份额为权威输入（表单两字段必填，从确认单抄写）、单价由其反算；不做在途/确认中状态。范围边界：仅场外申赎式公募（QDII 人民币份额天然兼容）；ETF 已有股票通道不重复；货币基金（净值恒 1、收益靠结转份额）明确排除。
3. **单位净值即价格**：净值入 MarketPrice + PriceHistory 既有承载线（币种人民币；现价 = 最新公布单位净值，并记录净值日期），市值/未实现盈亏/组合走势/净资产折算自动纳入；回填深度与股票对齐（近两年周线）。沿用「价格」称谓（与手动报价「统一为价格」同一哲学）；组合走势仍不称「净值走势」，单只基金的净值序列可以。
4. **价格刻度就地重定义为万分之一元**：`price_cents` 列名保留（就地改名会让新旧库列名分叉、SQL 得写两份）、刻度从「分」重定义为 0.0001 元，波及四列：`market_prices.price_cents`、`price_history.price_cents`、`security_transactions.price_cents`、`security_lots.cost_per_unit_cents`（基金每份成本同为 4 位小数，只改前两处会造成同语义双刻度）。V002/V010 就地修改，发布时按约定两级 BREAKING 标记（迁移文件头注记指向 CHANGELOG 版本 + CHANGELOG 对应版本 BREAKING 条目）。净值日期列不走就地修改，以新迁移增列（ADD COLUMN 对存量库正常前进，无需 BREAKING）。
5. **存量库分类处置**：迁移版本号无法区分「跑过旧 V002」与「跑过新 V002」的库，无可靠嗅探点，不做自动修复。可重建缓存（`market_prices` / `price_history` / `fx_rate_history`——历史回填窗口本就两年，清空重同步零损失）清空后重新同步；确定性派生的真实记录（`security_transactions.price_cents`、`security_lots.cost_per_unit_cents`，由金额/份额/费用可重算）由 `scripts/` 一次性 ×100 脚本修正（存量库量级为开发者本人一台设备）。
6. **净值同步并入 HoldingPriceSync 分区**：后端分区扩为 stock + fund；fund 分区走东方财富 f10/lsjz 通道（每基金独立请求，无批量接口；需 Referer 头，复用既有 HTTP 层主机池/限流），以现价缓存的净值日期为水位——首次回填近两年（约 11 页/只），此后每只一页增量；进度/取消/价格失效信号全复用。代码非 6 位数字的基金行（名称充代码等）查不到净值，计入「跳过 M 只」。**6 位纯数字判定的安全前提是入口收口**：fund 创建唯一入口 = 按代码即拉（决策 1，东财校验），AI 端点 fund 创建经东财校验拒绝查无此码（ADR-0039）——自编 6 位代码的 fund 行无产生通道，「按代码格式判定拉取」不会误拉他人基金。
7. **基金分红不做专门承载**：现金分红手工记账、红利再投以 0 手续费的 buy 手工模拟——与「推算仅认 buy/sell」口径天然兼容；放开 dividend kind 留另行议题。

## 理由

- 复用整条持仓管线（Holding / `v_holdings` / InvestedInstrument / 时点持仓 / 净资产）是最大赢家：基金申赎与股票买卖在账务上同构（数量 × 单价 ± 手续费 = 金额），kind 层面区分基金/股票无记账价值（标的类型已区分）；新 kind 要贯穿 Amount 矩阵、行为层、推算模块，无对应语义收益。
- 净值满足价格的账务定义「一单位标的值多少钱」；与 ADR-0036 手动报价对且慢组合净值的处理同一哲学（统一为价格，不引入第二语义）。
- 金额权威使成本与已实现盈亏全程锚定整分金额、零误差；万分位刻度是为市值显示与净值展示的保真（按分舍入会引入最高约 0.5% 的市值噪声，污染持仓/净资产/走势三处消费方）——这是本应用金额整数分纪律的延伸。
- 水位把增量同步成本从 O(11 请求/只) 压到 O(1/只)；lsjz 支持日期区间查询是前提。
- 就地改刻度优于加列：加列需视图重建（`v_holdings` 表达式改 COALESCE）+ 双列语义并存 + 读写两处换算；就地改在「存量库分叉被接受 + BREAKING 标记」的既有发布约定内成本最低、语义最干净（代价见决策 5）。

## 代价

- `price_cents` 名不副实：列注释与词汇表「价格刻度」词条钉住真实刻度，读代码者须知。
- 存量库需一次性人工处置（跑 ×100 脚本 + 重新同步），未处置前价格显示 100 倍错乱。
- lsjz 每基金独立请求且需 Referer 头，基金多时同步耗时线性增长（限流下约 1 秒/只/页）。
- 盘中估值不可见（fundgz 估值接口已下线；记账只需公布净值）；T 日净值 T+1 公布，配合「份额必填」决策，当天想记的用户需 T+1 补录。

## 替代方案

- 新 kind（purchase/redeem）：贯穿全链路、无语义收益，否决。
- 基金独立表 + 独立持仓管线：复制持仓/盈亏/折算/走势，净资产与持仓页合并两来源，否决。
- 加万分位列 + `v_holdings` 视图重建：语义诚实但双列并存、视图表达式复杂化；用户裁定发布约定下就地修改可接受后，就地改更省，否决。
- `price_cents` 刻度按类型解释（基金行存万分位）：列名说谎且刻度隐式，否决。
- 接受按分舍入（金额权威下仅市值显示有噪声）：精度是本应用的纪律，约 0.5% 噪声不值得，否决。
- 做在途/确认中状态：挂起-转正生命周期复杂度高、MVP 收益低，「份额必填」消解，否决。
- 基金全量同步：2 万+只字典无批量价值，否决（ADR-0015 职责切分同理）。
- 支持货币基金：净值恒 1、收益靠结转份额，形态特例污染净值/盈亏口径，否决（可用「其他」类型标的手工凑合）。
