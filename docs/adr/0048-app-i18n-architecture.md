# ADR-0048: 应用国际化（i18n）——vue-i18n Composition 模式 + 语言判定链 + 不随语言清单

- 状态：已接受
- 日期：2026-09-02
- 作者：Ledger 项目
- 关联：issue #342（spec）、#345（基建）、#346（数字分组）；词汇表「数字分组」（核心交易域）、「界面语言」「轻量设置项」（参考数据与设置域）

## 背景

应用是事实上的「中英混血」：业务文案硬编码中文（约百余篇前端文件），而 UI 组件库
（日期选择器、分页）的内置文案是英文默认值——不通中文的用户无法使用，中文用户也会看到
混杂的英文碎片。应用此前没有任何 i18n 机制（无翻译函数、无 locale 检测）。语言偏好天然
是「这台设备的偏好」：同一账本在不同设备上可以用不同界面语言，不应随 Backup/Restore
迁移到新设备。

## 决策

1. **选型 vue-i18n Composition 模式（legacy: false）**：中文 `zh-CN` 是源语言与回退语言，
   首批新增 `en-US`；架构按可加任意语言设计（新增语言 = 新增一份域拆分文案目录 + 过既有校验）。
   组件不另建组件级 scope，统一经 i18n 模块导出的模块级 `t()` 消费全局 Composer：
   渲染/计算属性等响应式上下文中调用自动追踪 locale 变化（切换即时重渲染），普通模块
   （列定义、菜单构造器）与组件同一入口；既有测试挂载零改动（测试环境不初始化语言，恒中文）。
2. **文案资源按域拆分 JSON**（common + 各视图域各一份，key 形如 `<域>.<用途>`），源语言
   eager 加载，非当前 locale 经动态 import 懒加载（切换时才拉取）；不做按视图代码分割。
   中文文案由现有硬编码原样抽取（中文用户全程无感），英文首批新译；过渡期混合状态可接受。
3. **语言判定链：手动覆盖 > 系统语言 > zh-CN**。手动覆盖是轻量设置项（ADR-0017 口径：
   前端 localStorage 单一来源、不随 Backup/Restore 迁移、改动即时生效，与外观主题同构），
   取值 `system` / `zh-CN` / `en-US`，`system` 表示无覆盖；系统语言按 navigator.language
   主子标签以 `en` 开头判定 `en-US`，其余一律回退 `zh-CN`（源语言兜底）。应用启动在首帧前
   await 初始化完成（英文系统用户不闪中文），切换运行中即时生效、无需重启。
4. **UI 组件库内置文案随应用语言**：经 NConfigProvider 的 `locale` / `date-locale` 注入
   naive-ui 语言包，随当前语言响应式切换——顺带消除既有组件文案中英混杂（此前组件默认英文）。
5. **回退与告警**：未翻译 key 回退显示中文原文（fallbackLocale = zh-CN），绝不显示 key 代号；
   开发模式下当前 locale 缺 key 打控制台告警（含已回退中文的情形——漏翻在写代码时暴露），
   生产环境静默回退。
6. **key 集合全等校验入质量门槛**：`scripts/check-i18n-keys.js` 比对源语言与其余各 locale
   的 key 集合双向全等，任一方向孤儿非零退出（仿命令集双向全等校验先例，ADR-0047），
   挂入 check.sh 与 CI。漏翻由此成为合入前可拦截的事实。
7. **不随语言清单（数据口径稳定性，刻意不变）**：
   - **姓名排序**保持中文拼音序、**拼音可搜下拉**保留——界面语言不改变数据检索行为；
   - **周起始日固定周一**——周汇总与走势图分桶口径在不同语言下分组结果一致；
   - **绝对日期固定 ISO 短格式**（如 2025-01-15）——无歧义、表格对齐可排序；
   - **金额输入解析**不受显示语言影响（录入行为两语言完全一致）；
   - **导出/备份文件内容**不随界面语言变化（机器可读路径稳定可解析）；
   - **数字分组随界面语言**（中文每 4 位、英文每 3 位）是唯一随语言的数字口径，
     见词汇表「数字分组」与 #346。
8. **种子/预置数据、AI 导入提示词与 knowledge 文本的多语言不在范围内**（未来方向：
   新库初始化时按当前 locale 选种子语言，存量库不动）。

## 理由

- vue-i18n 是 Vue 生态事实标准，Composition 模式与既有 `<script setup>` 风格一致；
  懒加载与 fallback 是其原生能力，不自建机制。
- 模块级 `t()` 而非组件内 `useI18n()`：本项目大量文案在普通模块/构造器函数中
  （列定义、菜单选项、确认文案构造器），组件级接缝会迫使它们层层传参；全局 Composer
  在响应式上下文中的追踪语义使切换即时生效不受影响，且测试无需给每个 mount 注入插件
  ——既有中文断言测试（数百处）零改动是本次迁移可行性的前提。
- 语言判定链三层结构让「跟随系统」成为显式可选项而非缺失值：用户清除覆盖即可回到跟随系统，
  而不是丢失配置。

## 代价与边界

- 双语言文案永不同步漂移的空间由校验脚本拦截，但「key 相等」不保证「译文质量」——
  译文质量靠评审。
- 模块级单例在测试间共享状态：i18n 行为测试经 `vi.resetModules` 取全新模块，
  业务测试不触碰语言状态（恒中文默认值）。
- vue-i18n 消息语法保留字（`@`、`|`、`{`/`}`）在文案字面量中需转义，抽取时注意。
- 跟随系统的语言判定在 webview 内依赖 navigator.language，平台差异（如 Windows 多语言
  排序）不做特判，以首个子标签为准。
