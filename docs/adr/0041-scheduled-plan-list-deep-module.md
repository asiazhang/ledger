# ADR-0041: 计划清单收进 ScheduledPlanList 深模块——三页签薄适配器化，计划表单独立接缝

- 状态：已接受
- 日期：2026-08-30
- 作者：Ledger 项目
- 关联：issue #317（决策沉淀）、#309（spec，同日 grilling 三轮收敛定型）；先例 ADR-0030（TransactionFilter 深模块，接口纪律与测试策略沿其房式）；ADR-0024（Plan Lifecycle 后端唯一事实）；ADR-0023 决策三（订阅金额不可编辑）；ADR-0035（弹层注册表，本决策的弹层纯度边界）；词汇表：界面状态与交互域 ScheduledPlanList（计划清单）词条

## 背景

「定时」页三个页签（订阅、分期、定时转账）是同一套「计划清单」交互的三份手工复制：三个组件合计约 1782 行、约六成逐字同构。复制漂移已经现网发生——其一，周期标签漂移：定时转账**新建表单**的周期下拉用「天/周/月/年」，分期与订阅表单用「每天/每周/每月/每年」，同一应用像三套拼装的功能（列表列口径三个页签本就一致，漂移只在转账表单下拉）；其二，分期计划按 Plan Lifecycle 自然完成后从清单中消失且无任何入口可见——定时转账页签修过的「已完成」过滤没有同步到分期。维护侧，三种计划形态共享的编排逻辑（清单加载与刷新、状态过滤、暂停/恢复/取消、商户解析、周期选项）在三个组件里各复制一份：修一个商户解析竞态要检查三处是否同款病灶，给三种形态加公共字段要碰多处；想测 Plan Lifecycle 操作只能整组件挂载并铺 UI mock，三个组件的测试合计约 2000 行，先于实现突破「超 800 行才拆目录」的仓库约定。issue #309 经 grilling 定型「清单 + 表单」双接缝方案，本 ADR 沉淀确认的接缝与规则。

## 决策

1. **双接缝（本决策唯一新增接缝面）**：
   - **ScheduledPlanList 计划清单模块**：前端 composable（工厂形态，每次调用独立实例），以计划形态为参数。工厂入参：计划形态、详情→行模型的形态扩展器（分期取完成期数/金额，转账与订阅取最早 pending 期次等）、加载错误文案、生命周期变更后回调（订阅注入订阅花费刷新）、详情动作回调（打开计划详情弹窗）。返回面三组：只读状态（行列表、loading、状态过滤值、刷新版本号）；派生与选项（按形态的状态过滤选项集、单源周期选项表与周期标签函数）；动作（清单加载/刷新、生命周期变更含成功/失败提示、行操作描述符构建——描述符含标签、按 Plan Lifecycle 状态的可用性、run 动作）。深模块纪律照 TransactionFilter 先例（ADR-0030）：少一个调用方义务、时序彻底内化、模块只产出可观察状态与动作。
   - **ScheduledPlanForm 计划表单接缝**：计划域私有，仅三个页签消费。承载三种新建表单的公共草稿字段（备注/账户/分类/商户/币种/周期三字段/开始日）、表单重置、商户解析（含「新建商户重名 → 兜底强制重拉 → 按名复用」竞态处理整套；编辑路径传「编辑中商户 id」保留软删兜底分支）与公共 payload 组装（创建入参的公共字段部分）。表单校验与形态特化字段组装（分期总额/期数、转账转入账户）留适配器。
2. **纪律门槛（模块防上帝化）**：清单模块内的形态分支只允许表达「能力有无」（如无商户能力的形态不暴露商户面）；形态特化计算体（期数预览、币种跟随、转入账户过滤）一律不进模块，超标即上移适配器。
3. **弹层纯度**：清单模块不引用任何组件、不接弹层注册表（ADR-0035）；行操作描述符由适配器渲染，确认弹层按弹层封装纪律留在适配器——弹层注册表的上报发生在封装组件实例作用域，无组件上下文的模块接不进去，也不该接。
4. **状态标签不迁入模块**：全仓已单源的定时计划状态文案工具（订阅清单与订阅花费面板共用）继续作唯一来源，模块直接复用，不造第二处。
5. **跨域表单共享接缝不动**：现有跨域表单共享 composable 有 7 个消费方（分类/退款/转账/投资四个表单 + 三个计划页签），接口与实现一字不改；计划域表单接缝独立新立，避免计划域私有逻辑泄入跨域接缝、其他域表单跟着陪绑。
6. **Plan Lifecycle 语义后端唯一事实（ADR-0024）**：模块只消费状态集合与变更规则、不重定义；订阅金额不可编辑、改价 = 取消旧计划 + 新建（ADR-0023 决策三）维持。
7. **三个页签 = 薄适配器（原地收缩）**：真差异显式留在各页签——分期：期数预览（含尾差文案）与进度列；转账：同币种转入过滤、币种跟随与跨币种清空、一次性/周期期数语义；订阅：商户挂靠、编辑弹窗（仅金额以外字段）、订阅花费面板及其刷新。列定义与单元格渲染（参考数据名称解析）留适配器。
8. **行为等价边界 = 零未声明变化**：显式声明的用户可见变化仅两处——① 转账新建表单周期下拉四词「天/周/月/年」→「每天/每周/每月/每年」（三个页签的列表列口径本就一致，不变）；② 分期清单状态过滤补「已完成」项（缺陷修复：完成的分期计划此前从清单消失且无入口可见）。其余列、操作、表单、提示文案、排序全部维持现状。
9. **迁移三步、每步独立可停**：步 1 = 清单模块 + 转账页签切入（最小风险先拿到可验收的等价物）；步 2 = 订阅；步 3 = 分期（最复杂，检验抽象）。每步一个独立提交，中途可停。
10. **测试策略转移（ADR-0030 决策 7 同款条款）**：测试接缝 = 上述两个新接缝的模块接口，只测外部可观察行为——意图（加载/过滤/暂停/恢复/取消/商户解析/公共 payload 组装）→ 状态终态与发出的调用参数，不断言内部 watch 拓扑与标志变量；三页签现有测试中可迁移的状态机/时序用例迁到模块接口测试，组件测试收缩为渲染与交互冒烟，不可迁移的用例删除并在迁移提交中记录用例名与不可迁移理由，杜绝悄悄丢覆盖；商户解析竞态用例（创建商户重名 → 兜底强制重拉 → 按名复用）从组件测试迁到计划表单接缝测试；计划详情弹窗与父视图的既有测试不动；清单模块测试沿用 TransactionFilter 先例技法——最小挂载壳直打工厂实例、刷新版本号镜像记录请求参数（ADR-0030）。迁移期允许旧测试与新测试并存，页签逐个切换。

## 理由

- **为什么双接缝而非把表单也塞进清单模块**：spec 原案把商户解析与公共表单字段放进清单模块，经 grilling 对照代码推翻——清单（持久可观察状态）与表单草稿（瞬态）是两种生命周期，合进一个模块会让接口横跨两类状态、面和纪律同时膨胀；而跨域表单共享接缝有 7 个消费方，不可用作计划域私有深化（计划域逻辑泄入等于让其他域表单陪绑计划域演进），故在「清单」之外独立新立计划域表单接缝。
- **为什么纪律门槛写死「能力有无」**：模块以计划形态为参数，最容易的漂移方向就是把形态特化计算体（期数预览、币种跟随）逐步搬进模块换「复用」，模块随之上帝化、第四种形态的接入成本回升为复制级；把分支表达力锁死在能力有无，差异被迫显式留在适配器，可见可审。
- **为什么弹层纯度**：弹层注册表的上报接线依赖组件实例作用域（ADR-0035 接线要点），无组件上下文的 composable 接注册表要么拖入组件依赖、要么伪造上报；确认弹层留在适配器，与「应用内弹层一律经封装组件」的既有纪律天然对齐。
- **为什么状态标签不迁**：它已全仓单源（订阅花费面板是第二消费方），迁入清单模块反而制造第二处映射，恰与收敛目的相反。
- **为什么两处可见变化要显式列出**：它们正是复制漂移的现症证据、本收敛的动机本身；显式声明既锁死「等价重构」的验收边界（此外零变化），也防止实施时顺手多改。
- **为什么转账先行、分期殿后**：转账差异最小（同币种过滤与币种跟随），先用它验证模块接口形状并拿到可验收等价物；分期最复杂（期数预览/进度、自然完成态），放最后检验抽象是否够用，抽象不合意时前两步已落袋、返工面最小。

## 代价与边界

1. 迁移期旧测试与新测试并存，页签逐个切换，测试文件短期冗余；不可迁移用例删除时须随提交记录用例名与理由。
2. 适配器承担回调注入义务（生命周期变更后回调、详情动作回调），工厂接口面比零回调形态宽——这是「形态差异留适配器」的对价。
3. 跨域表单共享接缝的消费方从 7 回落至 4（三个页签的消费转入计划域表单接缝）；其接口与实现不动，消费面自然收缩。
4. 本决策只定接缝与纪律，不定实现文件名与目录——实施票在仓库既有命名约定（多词 `.ts` 模块 kebab-case、超 800 行测试拆目录）内自行落位。
5. 清单加载/刷新与生命周期变更的异步样板是否顺带迁入 Loadable（ADR-0040 决策 6 预留的顺带迁移点），由实施票自行裁量，不构成本决策等价边界的内容。
