# ADR-0110: 导入知识分级自足——知识索引 + 投资分域知识节（AI 记账升为一等场景）

- 状态：已接受（grilling 定稿，2026-09-12）
- 日期：2026-09-12
- 作者：Ledger 项目
- 关联：#1120（实现票）；ADR-0090（契约双投影与「一次拉取即自足」；本 ADR 将其收窄为契约侧价值）；ADR-0010（只增不改与新增端点合规面）；ADR-0087（断言强度与接线型负向条目）；ADR-0106 / ADR-0109（把 AI 记账写作主要写入面的既有定位）；issue #286（提示词 / 知识分界红线）

## 背景

入口提示词把 AI API 的主场景写成「把历史账本数据迁移进开源记账」，但真实使用里还有另一等场景：**AI 记账**——把支付宝 / 京东 / 淘宝等日常消费账单交给 AI 逐行记入，多数行是普通收支，与投资无关。

现状对这类会话收取了不必要的整份静态阅读。导入知识是单个编译期常量、无分节寻址，实测 20,228 B（≈6.2K tokens），其中投资五节（投资交易 / 基金申赎 / 基金转换 / 份额调整 / 现金分红）占 12,714 B（62.8%）。记账会话必须整份拉取，而其中六成内容与它无关；且没有任何一处教 AI「非投资账本可以跳过投资节」。

契约侧不做同样的切分：`/api/v1/contract` 是 ApiDoc 的机械投影，投资可干净切出的部分只有 4,793 B（22%），更大部分（投资字段 3,940 B）与核心写入共用同一 schema，切走只能靠复制或撕裂写入契约。ADR-0090 已把「一次拉取即自足」写成契约侧价值，本次不动契约。

## 决策

1. **「AI 记账」升为一等会话形态**，与「数据迁移」并列：同一 AI API、同一写入面，区别在覆盖范围与对账强度——迁移是全量、覆盖范围内每行读回核对；记账是日常增量、投资知识按需读取。（域名「AI 导入」本次不改名，先落决策再单独议。）
2. **导入知识从「一次拉取即自足」改为分级自足**：`GET /api/v1/import/knowledge` 返回知识索引 + 全部非投资节（实测 7,514 B）；投资五节迁至新端点 `GET /api/v1/import/knowledge/investment`（实测 12,714 B）。不保留全文副本——导入知识是单一权威**集合**（索引 + 分域知识节），不是单一文本。
3. **索引承载触发规则，且是唯一陈述点**：知识索引逐节给出名称、一句话语义与「何时需要」；投资条目写明行驱动、整场黏住的触发——会话中一旦出现投资类 kind 或标的，即须读取投资节，且投资的对账与纠错口径一并补读。基础知识只保留一句带停止标志的指针（投资类 kind 不得套用普通收支写法），不复述规则。
4. **跨切面投资语义随投资节迁移**：核心侧的 kind 清单、商户规则对投资 kind 的排除、对账读回的投资过滤与来源口径、纠错节的投资删除级联，全部由投资节承载，核心只留指针。同一规则不得两处陈述。
5. **已发布教学正文允许做减法**：该端点自 v0.1.0 发布，但正文在 0.5.0 / 0.6.0 / Unreleased 反复增改，无体积与形状锁；消费方是本 App 同版本分发的 AI 会话，不存在跨版本固定客户端。端点的身份与媒体类型不变，属非 BREAKING；这是本项目第一次对已发布教学正文做减法，此前只有增补与改写。
6. **入口提示词只改措辞、不加取数步骤**：承认记账场景（「迁移为主直录为辅」的说法退役），触发仍由知识索引单点承载，维持「入口骨架零细节」的骨架锁精神。
7. **契约侧零改动**：`/contract` 与 `openapi.json` 形状不变，新端点作为纯增量进入两投影与既有端点覆盖清单。
8. **验收以负向条目为准**：投资关键词锁拆为新端点独立测试；删掉基础知识的投资索引条目、或删掉投资节端点接线，必须至少使一条测试报红（ADR-0087）。

## 理由

- **收益集中在知识侧而非契约侧**：记账会话净省 12,714 B（知识的 62.8%），而契约侧可切部分只有 4,793 B 且要动已发布的方言形状。同样的工时投在知识侧更便宜。
- **保留单次自足的主路径**：基础响应仍是「索引 + 非投资节」而不是只给索引——记账会话一次拉取即覆盖全部所需；只有真正出现投资行时才多一次往返。ADR-0090 的自足价值在主路径上被保留，只在分支路径上让位给按需。
- **单一权威优先于兼容副本**：知识侧若保留全文副本，两处必然漂移（#286 红线）。既然消费方随 App 同版本，减法比副本安全。
- **静默写坏是唯一严重的失败模式**：跳读投资节的后果不是报错而是错账。因此触发必须写成可判定的行条件、且黏住整场会话，并配一句停止标志。

## 替代方案（防重提）

- **另开精简端点、保留 `/import/knowledge` 全文**：造出两份会漂移的知识文本，违背单一权威（#286 红线）。否决。
- **查询参数寻址（`?section=`）**：分节在契约发现面不可见，AI 无法从端点清单得知存在投资节；端点身份不清晰。否决。
- **基础响应只返回索引、逐节全部按需取**：把最常见的记账路径从一次往返变成 2–4 次，且每次都可能漏取。否决。
- **拆 `/api/v1/contract`**：已发布方言形状变更需 bump `v`，投资切片仅 22% 且与核心共用写入 schema；ADR-0090 的自足价值正作用在主路径上。否决。
- **五个投资节各立端点**：五节互相引用（转换与份额的份额语义、分红与累计收益），拆开必然多取且易漏。否决。
- **入口提示词加条件取数步骤**：触发规则出现第二陈述点，且稀释骨架锁的零细节精神。否决。
- **本轮连域名一起改**：把决策落地与一次全库文档搬迁耦在一起，验证成本翻倍。暂缓（另行议题）。
- **由工具 / App 预判账单是否含投资并主动提示**：比行驱动触发更可靠，但要求上游知道账单内容。暂缓（后续增强）。

## 代价

1. 「导入知识 = 单一文本」的直觉被打破：读者需要理解「索引 + 分域节」才算完整；词汇表以知识索引 / 分域知识节两条词条承载。
2. 漏读投资节仍可能发生（AI 忽略索引），护栏只降低概率、不消除；这是本设计接受的残余风险。
3. 新端点进入两投影：标准投影实测 46,394 B / 48KB，余量约 2.7KB，实现时须核对；紧凑方言余量充足。
4. 知识关键词锁测试需从单清单重构为「基础知识 + 投资节」双端点，测试改造本身是这次改动的一部分。

## 后果

- `/api/v1/import/knowledge` 的返回体缩小约 62.8%；新增 `GET /api/v1/import/knowledge/investment`，属纯增量端点、无 BREAKING。
- 相关词汇表条目：AI 导入域新增 AI 记账、知识索引、分域知识节，修订 AI API 场景句、AIPrompt 边界与导入知识定义（单一权威文本 → 集合）。
- ADR-0090 的「一次拉取即自足」收窄为契约侧价值，正文以修订指针标注，不改其决策。
- 实现另票 #1120：拆知识文档、加端点、提示词措辞、测试双端点化，均按 AGENTS.md 的 issue + worktree + PR 流程进行。
