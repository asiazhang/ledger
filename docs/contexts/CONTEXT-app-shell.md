# 领域词汇表：应用壳

> Ledger 领域词汇表的应用壳分域。全部分域与彼此关系见 `CONTEXT-MAP.md`；决策记录见 `docs/adr/`（ADR-0145 / ADR-0146 / ADR-0147）。
> 跨域术语不复制定义：壳层分层与依赖方向纪律见 ADR-0112（结构导航归 AGENTS.md，不在此重复）；快捷键、弹层抑制、输入轴等交互语义见界面状态与交互域 `CONTEXT-ui-interaction.md`；更新机制见应用更新域 `CONTEXT-app-update.md`。
> 若与代码行为冲突，以代码为准并同步修正本文件。

## 原生壳（Native Shell App）

- **定义**：以 Native Shell（NSH）框架 Rust 模式构建的下一任应用壳——同进程宿主 UI 与全部业务域 crate，UI 直调域服务、不经 IPC 命令边界；Linux 上以 GTK4 原生控件渲染，绕开 WebKitGTK（ADR-0145）。
- **边界**：
  - 是壳层的下一任承载者、不是新分层：依赖方向沿用壳→域→基础设施→协议，换壳不改分层纪律。
  - UI 保真口径＝布局靠拢 web 版（间距 / 排布 / 信息层级，对照物见「Web 参照前端」）、控件形态 GTK 原生、交互语义不变：快捷键、页签状态保留、弹层关闭语义、输入轴与系统返回语义等行为逐项跨栈保真，观感从平台控件、不复刻旧 UI 库（口径修订见 ADR-0145 修订注记 2026-11-10）。
  - 选择类控件经封装族消费（ui-kit `App*` 封装族的 NSH 后继，含自建日期选择器与下拉），视图层不直连框架缺件。
  - 与多端同步域无交叉：同步协议与域引擎随壳整体复用，同步语义零改动；金额与折算口径仍以核心交易域为唯一真源，展示格式化逻辑在壳内重生而非另立口径。
  - Rust 模式为准（无 JS VM）；TSX 仅容许作立桩期速写板，不进产品形态。
- **别名**：不使用「native shell」指代 NSH 之外的方案；不使用「新前端」（Web 技术栈语境词，迁移后无前端/后端进程界）。

## 双壳并存期（Dual-Shell Migration Window）

- **定义**：从原生壳首个视图立桩起、到逐平台切换发布轨道为止的迁移期——Tauri 壳与原生壳在同一 workspace 并存构建（ADR-0145）。
- **边界**：
  - Tauri 壳是唯一对外发版产品，直至原生壳逐平台达到平价；平价核对基线＝IPC 命令清单＋BDD 场景清单（两者随旧壳退役、转作迁移核对表）。
  - 域接缝两侧同构有冻结点：冻结点（新壳覆盖交易列表、交易表单族、概览三主路径，ADR-0145 修订注记 2026-11-07）之前，新增域读写能力两壳消费方同步接线、命令核对表兜住遗漏；冻结点后新功能只进原生壳，旧壳仅修数据正确性缺陷。
  - 随旧壳终局退役的机制：BDD e2e、自动更新、浏览器开发模式、命令注册扫描与调用面校验。
  - 迁移顺序以立桩视图定基调：交易列表页（大表格＋快捷键＋IME）先行，验收＝硬伤清单各项在新壳可感知消失。
  - 终局注记（拆票③裁决，spec #2075）：并存期以一体切轨终结——旧壳、IPC 命令层与 Web 基建一体退役，原生壳升唯一产品（Linux 桌面）与 workspace 根包，不走「逐平台平价切换」；切轨后 web 前端以「Web 参照前端」形态保留，不属本词条射程（非产品形态）。
- **别名**：不使用「过渡期」（无界表述，不指明两壳各自的地位）。

## Web 参照前端（Web Reference Frontend）

- **定义**：整体保留在仓库中的 web 前端（Vue / naive-ui / pnpm workspace 全家），仅经浏览器开发模式与替身后端（ADR-0143）运行的非产品形态界面，作原生壳布局对齐的活体对照物（ADR-0145 修订注记 2026-11-10，spec #2075）。
- **边界**：
  - 不连真数据：mock 后端是参照界面的唯一后端实现，mock 不追真后端行为，数据真实度以 mock 覆盖面为限；HTTP 桥连真数据方案显式出范围。
  - 非产品形态：不对外发版、不承载真实记账；双壳并存期纪律（同步接线、平价核对）不延伸到参照前端；旧壳的产品身份随一体切轨退役，web 前端仅存参照身份。
  - 布局对照基准：原生壳 UI 保真口径「布局靠拢 web 版」的对照物即本条目；布局差异先全视图盘点产出核对表、再逐视图对齐（不阻塞切轨）。
- **别名**：不使用「旧前端」「旧版界面」指代（存续身份是参照物，不是待退役遗留物）；UI 保真口径表述中的「web 版」指本条目。

## 首启引导（First-Run Onboarding）

- **定义**：启动竖井在「账本注册表未配置（含损坏回退）且解析落点无账本库」现场呈现的引导界面，双动作指定账本——「新建账本」（落默认数据目录，确认对话明示完整路径后建库）与「打开已有账本」（目录选择器）；选定即本次启动打开，登记与活动指针即时写入账本注册表（见参考数据与设置域「账本（Book）」「默认数据目录」），非搬迁的「意图下次启动生效」（ADR-0146）。
- **边界**：
  - 现场闭集 = 注册表未解析出有库落点；注册表已配置但活动本缺库走失败态 + 「选择账本库目录…」入口（ADR-0146 决策 4），未配置但默认数据目录已有库（升级现场）直接打开——均不经本界面。
  - 选定并进入主界面后不再回归：后续换本 / 搬迁走设置面数据存储位置卡；首启新建首本直落默认数据目录，「新建账本子目录」的多本管理另票。
  - 是对旧壳「首次运行静默在默认目录新建」的有意偏离：库落点与「这是一本新账」的事实须让用户知情（ADR-0146 理由段）。
- **别名**：不使用「初始化向导」「欢迎页」指代；「引导层」指基础设施 boot 区，与本词条无涉。

## 主题令牌（Theme Tokens）

- **定义**：原生壳视觉常量的唯一来源——`nsh.json` 主题文件（shadcn `cssVars` 格式）定义的语义令牌闭集，亮暗双态齐全；shadcn 标准 UI 语义名与本仓自有令牌（走势主色、危险/警告、盈亏涨跌、图表系列色）同表承载，视图经 `theme().color(…)` 与令牌类消费（ADR-0147）。
- **边界**：
  - **出厂基线，不是运行时状态**：答「出厂观感是什么」；设备级亮暗选择归参考数据与设置域外观设置（答「这台设备用亮还是暗」），两层正交、互不取代。
  - **与界面状态与交互域 Design Tokens（ADR-0093）划界**：后者是 Web 参照前端的中性常量来源（只收中性设计常量、业务语义色归 Appearance 接缝），随参照形态存续；两栈各自单一来源，跨栈视觉同源一致性不再是目标。
  - **派生方向单向**：视图与封装件是令牌消费方，不持独立副本（与 ADR-0093 派生纪律同源）。
- **别名**：不使用「Design Tokens」指代本词条（该名已被界面域占用，语境是 Web 参照前端）；不使用「调色板」（palette 是令牌的取值集，不是令牌本体）。

## 视觉规约（Visual Design Spec）

- **定义**：`docs/DESIGN.md` 承载的本仓视觉唯一真源——原则、色彩、字阶、形状间距、表面层级与组件规格的成文规约，叠于 NSH 官方设计指南之上：指南管「无论长什么样必须为真的事」，本规约管「本仓长什么样」，相左时本规约赢（ADR-0147）。
- **边界**：
  - **视图零裸值纪律的挂账处**：颜色走主题令牌、字号走字阶、圆角间距走尺度；例外（图表数据色、密集表格行高等）必须在规约中挂账。
  - **冲突裁决**：规约与代码不一致时按可验证行为修正规约（仓库通则）。
- **别名**：不使用「设计文档」「UI 规范」泛称。

## 壳内 ui 层（App Styled Layer）

- **定义**：原生壳视图与 NSH 基元之间的封装层——一文件一件、variant + size 有限 API、样式内聚件内；视图只组合封装件与设计常量，不裸写颜色/字号/圆角/内边距（ADR-0147）。
- **边界**：
  - **蓝图取 NSH 官方正典，现状双轨过渡**：设计常量模块（字阶/间距/圆角唯一来源）先行止血，既有选择类封装族（ADR-0118 的 NSH 后继，见「原生壳」词条边界）是本层雏形，视图随触碰渐进收口。
  - **消费面纪律与界面域同源**：选择类控件经封装族消费、视图不直连框架缺件。
- **别名**：不使用「组件库」（NSH 基元是框架层，本层是 app 自有样式层）；不使用「样式方案」指代本层（该名已被界面域占用，语境是 Web 参照前端）。
