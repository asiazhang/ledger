# 领域词汇表：备份与数据文件

> Ledger 领域词汇表的备份与数据文件分域。全部分域与彼此关系见 `CONTEXT-MAP.md`；决策记录见 `docs/adr/`（ADR-0007 / ADR-0016 / ADR-0018 等）。
> 跨域共享术语（DefaultCurrency、AppSettings、ViewState 等）见核心交易域 `CONTEXT-core.md`、参考数据与设置域 `CONTEXT-reference-settings.md`、界面状态与交互域 `CONTEXT-ui-interaction.md`，本文不复制定义。
> 若与代码行为冲突，以代码为准并同步修正本文件。

## Backup（备份）

- **定义**：账本数据库的完整文件级快照，产物为包含数据库文件与元数据（备份时间、应用版本、schema 版本、来源标记）的 zip 包。触发方式分两种：用户手动触发（ManualTrigger 语境，见 BackupTrigger / ManagedBackup），或系统自动定时触发（AutoBackup）。
- **边界**：
  - 是文件级快照，不是语义级导出：不按记录或表选择内容，恢复即整库还原。
  - 与 AI 导入域的 Import（AI 驱动的语义级写入）和投资域行情同步（InstrumentSync 全量同步 / HoldingPriceSync 增量同步）是三条互不交叉的数据通道：恢复 ≠ 导入，备份 ≠ 同步。
  - 不含界面状态与偏好（界面状态与交互域 WindowState、ViewState、参考数据与设置域 Appearance、核心交易域 DefaultCurrency 等），那些属设备本地偏好，不随备份迁移。
  - 产物加密随源库走：密文库的备份为密文（`VACUUM INTO` 继承加密与密钥，见加密模式词条），元数据以可选 `encrypted` 标记记录，缺标记的旧备份视为明文（向后兼容，列表与恢复不报错）；产物仍由用户自行妥善保管。
  - 产物内容与格式由手动与自动共用一套机制（文件级快照打包，见 ADR-0007 / ADR-0016）；两类备份仅触发来源与命名前缀不同，并以元数据来源标记显式区分手动/自动（issue #127）；旧版本备份缺该标记时按手动处理，列表与恢复不报错。
- **别名**：不使用"导出"（语义级、可选择性）、"快照"（偏技术）等词。

## Restore（恢复）

- **定义**：用一份 Backup 快照替换当前数据库的破坏性操作，执行前自动为当前数据创建 RestoreSafetyBackup。
- **边界**：
  - 替换式还原，不是合并式导入（合并属于 AI 导入域 Import 通道的职责）。
  - 备份来自更高版本应用时拒绝恢复；来自旧版本时允许，恢复后自动迁移升级。
  - 恢复成功后应用自动重启，以全新状态加载数据。
- **别名**：不使用"导入"（语义级写入，与恢复是两种操作）。

## RestoreSafetyBackup（恢复安全备份）

- **定义**：Restore 执行前，系统自动为当前数据库创建的备份，用于恢复出错时回滚。
- **边界**：由系统自动创建、自动命名，用户无需干预；与用户手动创建的 Backup 存放位置不同。

## BackupDirectory（备份目录）

- **定义**：用户配置的默认备份存放位置；配置后"一键备份"直接写入该目录，无需每次选择。
- **边界**：属设备本地偏好（与参考数据与设置域 Appearance、核心交易域 DefaultCurrency 同类），不进入 `ledger.db`，也不随 Backup/Restore 迁移。
- **别名**：不使用"导出目录"（备份 ≠ 导出）。

## BackupRetentionLimit（备份保留上限）

- **定义**：用户可配置的受管备份最大保留数量，默认 30，可调范围 1–100。
- **边界**：
  - 属设备本地偏好（与 BackupDirectory 同类），不进入 `ledger.db`，也不随 Backup/Restore 迁移。
  - 只约束 ManagedBackup（受管备份）；ManualBackup（另存备份）不受约束。
  - 手动与自动触发的 ManagedBackup 同等对待、共享同一上限：最旧淘汰，不区分来源（ADR-0016）。
  - 上限调小时立即滚动清理到新值；受管备份写入后自动滚动清理。
- **别名**：不使用"最大保存文件个数"（口语化）、"保留策略"（偏宽泛）。

## BackupPruning（备份滚动清理）

- **定义**：把 ManagedBackup 数量修剪到 BackupRetentionLimit 之内的过程：删除最旧的超出部分。
- **边界**：
  - 触发点：任何一次成功写入且落点为受管备份之后；上限调小时立即执行。
  - 排序以备份文件名时间戳为准，解析失败回退文件修改时间。
  - 删除失败的文件跳过并报告，不中断其余清理。
  - 与 RestoreSafetyBackup（恢复安全备份）无关：后者在应用数据目录、命名不同，不受清理影响。

## ManagedBackup（受管备份）

- **定义**：位于配置的 BackupDirectory 内、按受管命名规则（手动/自动两类前缀，见 BackupTrigger）生成的备份文件；受 BackupRetentionLimit 约束。
- **边界**：
  - 来源分两类：手动（一键备份 / 使用默认文件名存入备份目录的"另存为"）与自动（AutoBackup）。
  - 两类受管备份在配额与滚动清理上同等对待（共享 BackupRetentionLimit，最旧淘汰，不区分来源，ADR-0016）。
  - 改名后不属于受管备份；不受管（另存到其它位置或改名）的文件永不被自动清理。
  - 受管判定按文件名前缀识别（后端与前端各持一份前缀常量并保持一致，ADR-0016 已接受该取舍）。
- **别名**：不使用"自动备份"（那是 BackupTrigger 的自动来源，不是"受管"的同义）。

## ManualBackup（另存备份）

- **定义**：用户通过"另存为…"主动选择存放位置或文件名的备份文件。
- **边界**：若写入配置的 BackupDirectory 且文件名符合受管命名规则，则视为 ManagedBackup；否则不受 BackupRetentionLimit 约束，永不被自动删除。

## BackupTrigger（备份触发来源）

- **定义**：区分一次 Backup 由谁发起的概念维度——**手动**（用户经设置页"一键备份/另存为"主动触发）或**自动**（AutoBackup 引擎按调度规则触发）。
- **边界**：
  - 手动/自动只影响命名前缀与备份内元数据的来源标记；产物格式、恢复流程、受管属性完全一致（ADR-0016）。
  - 恢复安全备份（RestoreSafetyBackup）是系统自动创建但**不属于** AutoBackup（不经调度器、不标脏、不占配额、独立存放位置）。
- **别名**：不使用"来源"（过于宽泛）、"自动/手动备份"口语（正式术语为"备份触发来源"）。

## AutoBackup（自动备份）

- **定义**：由应用内置调度器按周期自动触发的 Backup，目标是让"数据有变化时不至于长期无备份"——用户忘了手动备份也不丢数据。触发条件为"今天（本地自然日）尚未自动备份过，且自上次备份以来数据有变化（DirtyMarker）"。
- **边界**：
  - 频率上限为本地自然日每天最多一次（ADR-0016 修订：原「距上次备份 ≥24 小时」的滚动间隔）；「今天」取本地时区，与定时追补、订阅花费总览同口径。检查周期短（10 分钟轮询 + 写时顺带检查，ADR-0016 修订注记：原 30 分钟；同一轮询另承载定时计划域 Auto Execution（自动执行·追补）的到期判定，ADR-0042），先到先触发：当天第一个命中触发的入口执行备份，其余入口当天静默跳过。
  - 只在应用运行期间生效；系统休眠时调度暂停，唤醒后由短周期轮询在 10 分钟内补上。应用退出时若脏且当天尚未备份则兜底备份一次（ADR-0016 修订：原「不受每日约束」，现与到期、首次兜底同受日界门约束）。
  - 当天已备份后的后续改动当天不再有备份，次日第一个触发点补上（跳过而非覆盖当天文件，最坏丢失窗口约一天）；手动备份不计入「今天已备份」。
  - 首次启动若备份列表为空（不分手动/自动）且当天尚未备份过，则立即备份一次，保证装上当天就有一份。
  - BackupDirectory 未配置时自动备份静默不执行，设置页提示引导配置。
  - 自动备份的开关与调度状态（DirtyMarker、上次自动备份时刻）存于 `ledger.db` 的 AppSettings 表（参考数据与设置域，后端权威，ADR-0016/0017），随 Backup/Restore 迁移；日界判定由该时刻换算本地日期得出。备份目录与保留上限仍属设备本地偏好。
  - 自动备份产物命名时间戳为本地时间，与手动备份命名一致（ADR-0016 修订：原 UTC）；存量 UTC 命名产物不迁移，随滚动清理自然淘汰。
  - 失败不重试（保留 DirtyMarker，下个周期重试），成功不通知用户；产物同为 ManagedBackup，参与滚动清理。
  - 备份产物变更（自动备份完成 / 受管备份清理）成功后发出无 payload 的 `ledger:backups-changed` 信号（issue #129，与参考数据与设置域参考失效信号 `ledger:changed` 平行）；前端设置页订阅该信号自动刷新备份列表与自动备份状态。
- **别名**：不使用"定时备份"（偏计划任务语义）、"自动定时备份"（啰嗦，正式术语"自动备份"）。

## 加密模式（Encryption Mode）

- **定义**：库文件的文件级加密属性，由用户在设置页显式开启（opt-in）：开启时应用把整库一次性转换为加密文件，此后该文件及由它派生的备份、搬迁产物都是密文。加密状态随文件走（文件即真相）：启动读库文件头 16 字节即可判定明文/密文，不进任何库外引导状态；空文件视为明文新装（决策依据 ADR-0075）。
- **边界**：
  - 威胁模型是静态数据保护（设备丢失、被物理接触、文件或备份被拷走后的直接阅读），不防运行期访问；存量明文库不受影响，新装默认明文。
  - 开关双向、口令可轮换，共用同一套整库转换机制（ADR-0075 决策 6）：先产出并验证新库、原子替换、旧文件按重置命名语义保留副本（开启时副本为明文；关闭/改口令时副本为密文，仍凭旧口令可开）；中途失败原库原样保留，不存在半加密状态。关闭加密与修改主口令都需当前主口令（文件级机制凭口令读取密文库）。
  - 加密库的备份产物天然是密文，备份/恢复/搬迁三条路径零改动（`VACUUM INTO` 继承源库加密与密钥）；恢复安全备份是文件级拷贝，同样继承密文。备份列表以加密标记驱动锁形标记（backup.json 可选 `encrypted` 字段，备份时探测写入；旧备份缺标记视为明文——zip 格式纯增量，向后兼容）；跨模式恢复允许，恢复确认弹窗在当前模式与备份模式不一致时显著警告，密文备份恢复需输入该备份的主口令（口令错误可就地重试）；恢复后应用自动重启，由启动探测（决策 4）接管实际模式。
  - 设置归属：加密模式是文件属性，不进任何设置表；设置页卡片只是开关入口。
- **别名**：不使用"数据库加密"（偏引擎能力，用户视角是库文件属性）、"安全模式"（含义过宽）。

## 主口令（Master Passphrase）

- **定义**：用户开启加密模式时设置的个人口令，密钥由它经密钥派生函数导出，口令本身**永不落盘**（不进库文件、不进任何配置）；它是读取加密数据的唯一凭证。用户可见错误条件（口令错误、文件损坏、库缺失等）以码化错误返回（见核心交易域错误码），前端按码本地化。
- **边界**：
  - 无后门：忘记主口令即数据永久不可读，不提供密钥导出/恢复文件；唯一逃生门是重置为全新空库，旧库保留为密文副本。
  - 验收形态：口令仅经解锁/开启加密/关闭加密/修改主口令/忘记口令重置命令面提交；审计日志与 trace 输出不落口令。
  - 「忘记口令」入口（issue #573）：解锁屏常驻入口 → 明确的无后门后果说明（数据不可恢复）→ 二次确认 → 重置为全新明文空库（旧库按既有重置命名语义保留为密文副本，副本无密钥不可读，日后想起口令仍可救回）；重置后应用原地回到明文模式，可再次走开启加密流程。
  - 「本机记住主口令」已落地（issue #574），正式术语为**自动解锁**，见该词条。
- **别名**：不使用"密码"（与网站账号密码混淆）、"密钥"（密钥是派生产物，不是口令本体）、"加密口令"。

## 解锁（Unlock）

- **定义**：加密模式下每次启动时凭主口令打开密文库的动作：启动探测发现密文库后，用户在解锁屏手输主口令完成；解锁成功是业务可用的起点——自动备份调度（含同轮承载的定时计划追补）与外部 HTTP 导入面都在解锁后才运行/可用。
- **边界**：
  - 口令错误 ≠ 库损坏：两者在密码学上同形（均为「读不出有效库」），由文件头探测区分——头为密文即视为等待口令，错误口令提示可重试；凭口令打开成功但完整性检查失败才报文件损坏。文案可区分、经 i18n。
  - 解锁失败**无限重试**，不锁定、不改动库文件任何字节。
  - 有自动解锁缓存时，启动经系统钥匙串取回主口令自动通过（macOS 先过 Touch ID，见「自动解锁」词条）；无缓存或取回/认证失败一律回退手输，解锁通道不受影响。
  - 解锁成功后，启动期因缺口令而推迟的 DataLocation 搬迁（见参考数据与设置域 DataLocation）以主口令补做；补做成功后应用重启，由启动引导接管目标位置。
  - 解锁屏常驻「忘记口令」入口（issue #573，见主口令词条）：解锁失败不是死局，逃生门重置不需要、也无法提供口令验证。
  - 明文库启动路径零改动：探测为明文/空文件时不进入解锁屏，一切行为与无加密能力时一致。
- **别名**：不使用"登录"（无用户账号体系）、"验证密码"（解锁是打开库文件，不是身份验证会话）。

## 自动解锁（Auto Unlock）

- **定义**：加密模式下把主口令缓存进本机系统钥匙串、下次启动免手输的设备本地便利能力（issue #574）；钥匙串只缓存主口令本体、不持派生密钥，密钥仍由口令派生（ADR-0075 决策 3）。
- **边界**：
  - 仅本机生效：开关偏好是轻量设置项（localStorage，见参考数据与设置域「轻量设置项」），不随 Backup/Restore 迁移；换机或在其它设备恢复备份仍需手输。
  - 平台支持面 v1 仅 macOS：读取缓存前需先通过 Touch ID——生物认证是取回口令的关卡，不是密码学原语；不支持平台隐藏该选项、回退每次手输。
  - 平台之内还受**运行形态**（应用二进制以何种签名形态运行）约束：钥匙串生物门条目要求进程持 **Apple 签发证书**（免费 Apple ID 的 Apple Development 与付费 Developer ID 同属此类）背书的钥匙串 entitlement，**ad-hoc 构建**（未接入签名身份的构建产物）建立/读取一律失败；相关提示须区分「平台不支持」与「当前构建受限」，不作笼统「不支持」。运行形态只影响取回关卡可用性，不改变本词条安全模型：缓存仍是主口令本体、密钥仍由口令派生（issue #645）。
  - 开启需凭当前主口令建立缓存，关闭即清缓存恢复手输；自动解锁失败（缓存缺失、认证不通过）一律回退手输，不阻断解锁。
  - 开关入口在设置页加密卡片；UI 文案统一为「自动解锁」（现行「启动时自动解锁」等变体随实现收口，见 ADR-0078 同批清单）。
- **别名**：不使用「本机记住主口令」（实现机制描述，非用户语义）、「记住密码」（与账号密码混淆）、「免密登录」（无账号体系）。

## DirtyMarker（脏标记）

- **定义**：记录"自上次备份以来数据是否有变化"的布尔状态，是 AutoBackup 决定"到点是否真正执行备份"的唯一依据。
- **边界**：
  - 置真：任何一次业务写库成功后自动置真，写路径对备份域零感知（触发机制收口于连接层，issue #173）；不依赖各写路径逐点调用。备份成功后清真。预算（Budget）、定时计划与行情同步等所有业务域写入同属置真范围（预算为 #245 修复钉住，定时计划/行情同步为 #246 审计补齐）。
    - 置真豁免（内部写不置真）：设置与调度状态写入（AppSettings 全表）与恢复（Restore）路径——语义锚：DirtyMarker 跟踪**账本数据**变化，配置与调度状态不算「数据变化」。豁免清单集中一处显式维护，不散布于各写路径（ADR-0032）。
  - 恢复（Restore）成功后重置：恢复本身生成了 RestoreSafetyBackup，数据刚被校验，不产生"恢复后立即备份"。
  - 调度器自身的状态写入（开关/到期时间）不置真，避免自触发。
  - 失败保留：备份失败不清真，下个周期重试（ADR-0016）。
  - 属调度状态，存于 AppSettings 表（自动备份专用键）。
- **别名**：不使用"脏位"（偏底层实现）、"变更标记"（含糊）。
