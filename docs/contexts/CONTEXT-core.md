# 领域词汇表：核心交易

> Ledger 领域词汇表的核心交易分域。全部分域与彼此关系见 `CONTEXT-MAP.md`；决策记录见 `docs/adr/`。
> 本分域定义被所有域消费的共享术语（Transaction、Amount Model、Transaction Kind Mapping、Category、DefaultCurrency 等）；其他分域以「见核心交易域 X」引用，不复制定义。
> 若与代码行为冲突，以代码为准并同步修正本文件。

## Transaction（交易流水）

- **定义**：一笔实际发生的资金变动，已存在于 V001；在定时交易语境下，它是定时计划域 `ScheduledTransaction` 的某期执行产物。
- **kind（交易类型，闭集 8 种）**：
  - `income`（收入）/ `expense`（支出）：日常收支。
  - `transfer`（转账）：`account_id` 转出、`to_account_id` 转入。
  - `refund`（退款）：关联原支出交易（`refund_of_transaction_id`），账户/币种/分类继承原支出。
  - `buy`（买入证券）/ `sell`（卖出证券）：资本变动，关联投资持仓（见投资域 Instrument / Holding）。
  - `dividend`（现金分红）：计入收入。
  - `split`（拆股/送股）：现金影响恒为 0。
  - **每种 kind 对各金额度量的符号归属见 Transaction Kind Mapping；交易行写入与校验收口在 Writer 接缝。**
  - **kind 为闭集（8 种），行为收敛分派在行为层**：每类 kind 的校验/归一化/应用副作用/回退在行为层单点分派——通用 kind 走 Writer 接缝，buy/sell 委托投资域 prepare / apply / revert 三件套，不再散落多处按 kind 分支（issue #72）。
  - **行为层编排入口（创建 / 修改 / 删除）**：行为层对外只暴露三个编排入口（连接 + 输入进，见 issue #169）——回退 → 计划 → 落库 → 应用的顺序契约、事务边界、守卫文案全部内化为实现细节（计划/应用为模块私有，回退直接委托投资域三件套的 revert、不另设转发层），调用方不再持有顺序与事务知识。
  - **嵌套感知事务**：编排入口的事务规则是「保证处于事务中」——连接不在事务中则自持事务（中途失败整体回滚，无中间态泄漏）；已在事务中（如批量导入的外层批次事务）则加入外层、失败直接返回错误、回滚由外层持有者负责。单条协议的事务知识归行为层，批次原子性是批量编排的独立关注点、留在批量层。
  - **`dividend` / `split` 已声明但未实现（MVP）**：经交易接口（创建/修改）显式返回「暂不支持」错误，不落库、不静默误记。
  - **买入守卫文案按入口内化**：buy 已有部分卖出的守卫拒绝文案是行为层各编排入口的实现细节（修改/删除各持自己的措辞，创建不触发守卫），不由调用方作为参数传入——同一入口同一文案、不随调用方漂移（issue #169）。
- **列表呈现边界**：
  - 交易列表按 `date` 倒序呈现（最新在前）。
  - 采用服务端 offset 分页：一次只取当前页交易，并返回满足筛选条件的交易总数（"共 N 条"）。
  - 翻页浏览期间新增交易会使列表整体前移，后续页可能看到条目重复或遗漏——这是已知行为，不是数据错误；重新进入列表即恢复一致。
  - 筛选条件变化时总数随之变化，分页始终基于筛选后的结果。

## TransactionInput 装配器

- **定义**：前端「记一笔」写入路径的唯一装配接缝——各交易表单形态（支出/收入、转账、退款、买入/卖出）的表单状态进、完整 `TransactionInput` 出（issue #167）。同步纯函数；商户解析与语义校验不在此接缝（留表单层）。
- **边界**：
  - **per-kind 字段矩阵**：各 kind 填什么、留什么空（含 buy/sell 金额置零、关联留空与 refund 的占位语义）收敛于矩阵一处；新增表单形态只改矩阵。基金申赎形态（issue #302）覆写金额置零——落确认单权威金额、单价不落 wire（录入权威语义见投资域 Investment）。
  - **金额转换单点**：元转分全仓只有一处实现（消浮点误差口径），任何表单不再手写换算。
  - **日期转换单点**：本地日历日语义（用户所选日的本地零点取日期），不走 UTC 截断——本地 0–8 点记的账归属当天。
  - **两路同构**：同一装配结果供创建与修改共用；非法输入 fail fast 显式报错、不静默兜底（与 dividend/split 的「显式拒绝」同一原则）。
  - **与 Writer 接缝的关系**：装配器是前端进程内唯一新增接缝，落库侧继续走 Writer 接缝（wire 契约不动）。
- **别名**：不使用「表单装配层」「输入构造器」。

## InvolvingAccount（涉及账户）

- **定义**：一笔 `Transaction` 与某个账户的关系视角——`account_id`（转出账户）或 `to_account_id`（转入账户）任一命中即算该交易涉及该账户。是交易列表按账户过滤、AI 读回按账户对账的统一口径。
- **边界**：
  - 过滤语义：转出或转入任一端命中即算；普通收支只命中一端，转账两端（转出 + 转入）都命中。
  - 与"转出账户"对照：转出账户特指 `account_id` 指向的账户（支出/转账的扣款侧、收入的收款侧）；涉及账户更宽，覆盖交易两端——转账的转入侧只在涉及账户语义下可按账户检索到（`to_account_id` 仅转账使用）。
  - 用途：交易页账户过滤（账户名下钻与手动下拉共用同一语义，issues #97–#99）、AI 导入域交易读回的按涉及账户过滤、AI 读回对账按账户核对（见 AI 导入域 AIReadbackVerification）。
  - 是既有 `account_id`（仅转出账户）过滤之外**新增**的维度，不改旧字段语义（发布冻结只增不改）。
- **别名**：不使用"相关账户"（含糊）、"关联账户"（易与数据库外键"关联"混淆）。

## Amount Model（金额模型）

**raw/native 分离（`transactions` 行级）**：
- `amount_cents`：原始币种金额；`amount_native_cents`：本位币金额（折算到全局默认币种 DefaultCurrency）。
- 折算单点执行：与默认币种同币种原样保留；否则经汇率表真实折算（正反向汇率兜底），缺汇率报错、不静默混币种。口径归属见 ADR-0011。
- 折算基准为全局默认币种、与账户币种无关，避免跨账户汇总口径漂移。
- 四个具名度量（`account_flow` / `expense_net` / `income_net` / `refund_gross`）对 8 种 kind 的符号归属见 Transaction Kind Mapping。

**分期金额计算（ScheduledTransaction）**：每期金额固定的 MVP 决策与尾差计算规则见 ADR-0024「分期金额计算规则」（MVP 不支持每期金额不同、不支持 subscription 中途涨价）。

## Transaction Kind Mapping（交易类型映射）

**ScheduledTransaction → Transaction 生成映射（用户不可配置）**：
- `installment` → `expense`
- `subscription` → `expense`
- `scheduled_transfer` → `transfer`

**kind → 金额度量符号归属矩阵**（8 种 kind × 四个具名度量，全库唯一口径）：

| kind | account_flow | expense_net | income_net | refund_gross |
|------|------|------|------|------|
| income | + | 0 | + | 0 |
| expense | − | + | 0 | 0 |
| transfer | account_id=− / to_account_id=+ | 0 | 0 | 0 |
| refund | + | − | 0 | + |
| buy | − | 0 | 0 | 0 |
| sell | + | 0 | 0 | 0 |
| dividend | + | 0 | + | 0 |
| split | 0 | 0 | 0 | 0 |

- `account_flow`（账户现金流动）：余额口径，某账户视角的现金出入；transfer 按侧取号。
- 账户余额读持久化缓存（ADR-0067）：每账户一行缓存行，写路径在引发写入的同一事务内对受影响账户整体重算回写，账户列表/余额页等读出口读缓存；缓存行为派生数据，缺失或漂移经手动审计命令修复，实时聚合仅作审计与测试的权威比对。
- `expense_net`（支出净额）= 毛支出 − 退款；buy/sell 属资本变动，不计入经营收支。
- `income_net`（收入净额）= 收入 + 分红。
- `refund_gross`（退款毛额）：独立成列，毛值/净值并存展示。
- 净值恒等式（一处定义）：支出净额 = 毛支出 − 退款毛额，月度汇总毛值由此导出。

## 债权债务往来（借出/借入）

- **定义**：个人间借贷（朋友/家人之间的借出、借入与还款）的记账约定——**不新增交易类型，复用 `transfer` 与账户类型 `receivable`（借出款）/ `debt`（负债）承载**，kind 闭集保持 8 种（ADR-0053）。
- **边界**：
  - **落账映射**：借出 = 转账 自资金账户转入 receivable 账户；借入 = 转账 自 debt 账户转入资金账户；还款/收回 = 反向转账，部分还款即多笔。账户实时余额即对该对手方的未清金额。
  - **呈现层（录入入口与列表文案，issue #374 兑现 ADR-0053 决策 5）**：借贷在界面有自己的入口与文案，但只是 transfer 的**派生视角**、识别唯一依据是两端账户类型——方向判定（借出/收回/借入/还款/普通转账五态）收口单一纯函数，录入表单（方向预置与切换）、列表类型标签、编辑形态识别三处消费同一函数。「记一笔」新增「借出」「借入」入口，表单按方向过滤账户选择（借出/收回：资金账户 ↔ 借出款账户；借入/还款：负债账户 ↔ 资金账户）并可切换到反向方向，提交产物与转账同构（经 TransactionInput 装配器、写入命令与转账相同）；列表对借贷转账显示四方向专属文案、普通转账不变，账户类型正确的历史借贷自动获得借贷文案（实时派生、无数据迁移）；**对端账户类型取不到（黑洞 is_hidden 占位、已删、不可查）时方向仍由借贷侧（debt/receivable）排出——借贷语义由借贷账户决定，不对端是否可查而退回普通转账**（迁移历史里借贷转入方为黑洞占位的场景由此正确显示借贷文案）；类型填错的账户不获得借贷形态（账户承载约定的自然边界）。
  - **符号口径**：receivable 余额为正表示对方尚未归还；debt 余额为负表示尚未偿还的欠款。建账时已存在的借贷经期初余额表达（既有欠款填负值、既有外借填正值）。
  - **一人一账户**：对手方（人）由账户承载、账户名即人名，命名约定「借出·张三」（应收）/「借入·李四」（欠款）；不以商户标记对手方——transfer 不可携带商户（见 Merchant），且商户语义（花给谁/收入来自谁）与借贷对手方（谁欠我/我欠谁）不同构。
  - **利息按普通收支**：收息 = `income`、付息 = `expense`，与本金转账分笔记录；不做计息机制。
  - **坏账核销 = 余额调整归零**（见参考数据与设置域 BalanceAdjustment）：对方确定不还时把 receivable 余额校准到 0，净资产忠实下降、**不计收支**——坏账是资产减值而非消费，与「资本变动不计经营收支」（Transaction Kind Mapping）同一哲学。
  - **净资产守恒**：借出/借入两端账户同向等额变动，净资产不变（见投资域 NetWorth 的忠实求和口径）；不想把借出款计入「我现在有多少钱」的用户可隐藏该账户。
  - **类型边界**：debt 承载一切欠款（个人借入与机构贷款）；`credit` 仅信用卡。
  - **AI 导入**按本约定落账（约定收口在 AI 导入域的导入知识，见 AI 导入域 AI API）。
- **别名**：不使用「应收应付」（偏企业会计）、「借还款」（不辨借贷方向）。

## Category（分类）

- **定义**：对交易（Transaction）进行归类的标签体系。两级结构：顶级分类和二级子分类，不支持三级及以上嵌套。
- **边界**：
  - 每个分类属于 `income`（收入）或 `expense`（支出）两种类型之一，子分类必须与父分类类型一致。
  - 分类具有视觉标识（图标与颜色），用于交易表单、报表、图表等场景的视觉辨识。
  - 同级内可拖拽重排，父分类变更通过编辑操作进行。
  - 软删除（`is_deleted`）单行：删除只影响该分类自身，子分类不受牵连。
- **别名**：不使用 "标签"、"类别"、"分组" 等词，统一使用 "分类"。

## Merchant（商户）

- **定义**：交易付款对象与收入来源的参考数据字典（如京东、红旗连锁、万科物业），交易（Transaction）以 `merchant_id` 引用，回答「这笔钱花给了谁、收入来自谁」；与分类正交——分类管「花在哪类」，商户管「花给谁」。
- **边界**：
  - 名字全库唯一，是精确匹配复用（upsert）的前提。
  - 软删除（`is_deleted`）：删除后不再出现在补全/新建选择列表，历史引用保留照常显示；管理列表默认只列在用商户，「显示已删」切换后已删行只读展示（无编辑/删除，条数照常、照常可下钻，issue #447）；字典行硬删时交易上的商户引用置空，交易本身不删。
  - 改名即时生效：引用指向 id，不回刷历史交易行。
  - 与分类（Category）均可选、互不替代、互不联动：一笔交易可同时有分类与商户，也可都没有。
  - 可携带商户的 kind（行为层收口）：`expense` / `refund` / `income`；`transfer` / `buy` / `sell` / `dividend` / `split` 行为层拒绝。schema 层不设 kind 限制（商户列为可选），可携带性由行为层收口。refund 与账户/币种/分类同款继承语义：自动继承原支出商户、可修改。定时计划的分期/订阅形态每期生成交易时复制商户（见定时计划域 Counterparty 指针）。
  - 关联交易条数（毛笔数，issue #445）：字典管理对每个商户实时统计引用它的未删流水条数——凡引用该商户的流水各计 1 条，不做 refund 冲销、不做净笔数；实时按流水推导、不落库，软删商户照常计数、无引用商户为 0。报表商户排名的金额口径（expense_net）不与之混淆——条数是字典管理视角的忠实计数，金额口径仍归 Amount Model。
  - 名字字典：商户只有名称一个属性（icon/color 已退役，issue #223——商户高频自动增长，视觉辨识字段只会成为低填充率噪音）；随参考数据失效机制自动重拉（见参考数据与设置域 Reference Data）。
  - 管理列表检索（issue #447）：搜索框按统一模糊搜索语义规格（见 TransactionSearch）对商户名本地过滤——字典前端全量驻留，只过滤不重排、清空恢复完整列表。
  - 建模、ADR-0024 决策点推翻与 schema 原地改（breaking change）决策见 ADR-0028。
- **别名**：不使用"交易对手"（已废弃的 Counterparty，见定时计划域指针词条）、"商家"（口语）、"收款方"（仅描述收入侧，以偏概全）。

## DefaultCurrency（默认币种）

- **定义**：用户在记账时首选的基准币种，用于展示本位币金额（`amount_native_cents`）。
- **边界**：本位币（raw/native 折算）的基准，MVP 阶段为固定值、尚无配置入口；前端侧默认币种是轻量设备偏好，决定金额展示的币种格式（小数位、符号随币种字典）与新表单预选币种，报表按本位币显示。折算语义见 Amount Model。
- **别名**：不使用"本位币"（偏会计术语）、"主币"（偏支付）。

## TransactionSearch（交易搜索）

- **定义**：用户通过文本关键字检索 `Transaction` 的功能入口，以独立视图呈现（侧边栏"搜索"入口，全局可达），MVP 阶段搜索范围仅限交易。
- **边界**：
  - 可搜索内容：交易备注 + 转出账户名 + 商户名（issue #193 纳入；分类名、转入账户名不在搜索范围）。商户名口径：搜索时即时读取当前商户名（与账户名同款），软删商户的历史交易仍可搜、改名即刻生效。
  - 金额/日期筛选与关键字 AND 组合，金额区间按本位币金额过滤（与全仓聚合口径同源，多币种下跨币种不混滤，issue #395）；结果按交易日期降序分页。
  - 搜索结果只读展示（复用交易列表的信息：日期、类型、账户、分类、金额、备注），不做增删改；需要操作时跳回交易列表。
  - 搜索词不持久化（与界面状态域 ViewState 边界一致）。
  - **时效性**：全量扫描（ADR-0027）——SQL 取候选后内存中按统一语义逐条过滤，无任何索引与一致性机制，写入立即可搜；所有搜索结果排除软删除记录（与交易列表口径一致）、即刻生效，无索引滞后窗口。
- **统一模糊搜索语义（全库唯一定义点）**：交易搜索与界面域拼音可搜下拉共同遵守的匹配规格（前后端共同契约，ADR-0027；其他域词条只指此处、不复述）：
  - 输入按空白切词，词条之间 AND；空词条恒命中。
  - 每词条对每个字段判定——**命中 = 原文连续子串（大小写不敏感）∨ 词条是该字段拼音首字母串的子序列（大小写不敏感）**。
  - **子序列匹配**：词条的每个字符按原顺序出现在目标串中即命中，允许跳字、间隔不限（如 `wy` 命中「万科物业」、`zsyh` 命中「招商银行」）；子序列命中的键集合不可枚举，与倒排索引根本不兼容，是全量扫描实现的直接原因。
  - **拼音首字母**：中文文本每个字的拼音首字母串，统一小写——中文字取拼音首字母、ASCII 字母/数字小写原样保留、标点与空格跳过；多音字按前字规则修正（「银行」→ `yh`）。前端与后端各自实现同一规则，接受生僻多音字的字库级分歧。
  - 混合输入（如「招zsyh」）无需特判：含汉字的词条对纯 ASCII 首字母串的子序列匹配必然失败，自然落到原文子串路径。
- **别名**：不使用"全局搜索"（范围并非全局，仅交易）、"全文搜索"（偏 FTS 技术含义）；"模糊搜索"可作为口语沿用（ADR-0027 文档名），正式术语为"交易搜索"。

## 耗时日志（Timing Log）

- **定义**：对数据库执行操作按耗时记录的日志机制，用于建立性能基线、定位慢路径。
- **边界**：
  - 观测单位分两层：SQL 语句级（连接级 hook 全量覆盖，含启动迁移、自动备份、定时引擎）与命令/批次级（span 归因 + 批次汇总）。
  - 默认级别只落超阈值的慢查询；全量明细需 DEBUG 级日志。
  - 日志遵循隐私约定：默认级别不记录金额等业务值（与 ADR-0006 的 INFO 级约定一致）。
- **别名**：不使用"时间日志"（含糊）、"性能日志"（偏优化手段，本机制只做观测）。

## 慢查询（Slow Query）

- **定义**：单条 SQL 执行耗时超过阈值的语句。
- **边界**：以 warn 级别记录；启动迁移、自动备份等合法慢路径也会命中，属预期信号而非故障；阈值可随观测数据调整。
- **别名**：不使用"慢 SQL"（口语沿用无妨，正式术语为"慢查询"）。

## 错误码（Error Code）

- **定义**：后端错误响应中标识错误条件的稳定码（`<域>.<条件>`，全小写 kebab-case，如 `transfer.to-account-required`），与可选插值参数 `params` 一起，供前端按界面语言本地化错误提示（ADR-0050）。
- **边界**：
  - 只增不改契约：错误序列化在既有 `kind`/`message` 之外只增 `code`/`params`，中文 `message` 原样保留、恒为权威；无码或未知码时前端降级透传原文。
  - 每个用户可见错误条件一个码；`Db`/`Parse`/`Io` 系统错误携带通用码（`db.error` 等），底层消息不入码表；码表（zh/en 模板）收在文案资源 errors 域，受 key 全等校验。
- **别名**：不使用「错误字典」「错误 ID」（code 非技术标识而是领域条件命名）。

## 数字分组（展示层口径）

- **定义**：所有数字展示的统一读数口径，分组方式随界面语言——中文整数部分从右向左每 4 位一组（`1234567.89` → `123,4567.89`），英文每 3 位一组（`1234567.89` → `1,234,567.89`），组间半角逗号分隔；小数部分连续输出不分组、去掉全部小数尾零（`98.00` → `98`、`98.50` → `98.5`，小数位全空时连小数点一起去掉），负号恒在最前。分组口径由界面语言隐含，不做独立设置项。
- **边界**：
  - 仅作用于**展示层**字符串（金额与数量的格式化共享同一核心助手）：存储仍为整数分、输入解析与导出等机器可读路径不受影响、后端零改动。
  - ≤4 位整数天然不受影响；不同币种按各自小数位格式化后再对整数部分分组。
  - 数量列（股数/份额）走同一分组规则；带小数的份额仅整数部分分组。
- **别名**：旧称「万分位分组」（彼时全 App 固定每 4 位一组）；「千分位」即英文口径，不再是冲突概念。
