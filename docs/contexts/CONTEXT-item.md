# 领域词汇表：物品

> Ledger 领域词汇表的物品分域（单列小域）。全部分域与彼此关系见 `CONTEXT-MAP.md`；决策记录见 `docs/adr/`（ADR-0014 独立领域、ADR-0025 创建唯一入口与自包含成本）。
> 跨域共享术语（Transaction、Instrument、Subscription 等）见核心交易域 `CONTEXT-core.md`、投资域 `CONTEXT-investment.md`、定时计划域 `CONTEXT-scheduled-plans.md`，本文不复制定义。
> 若与代码行为冲突，以代码为准并同步修正本文件。

> **与代码的差异（过渡态）**：本文档按 #113 修订后的**目标决策**描述，目标语义的决策权威是 ADR-0025、**现码为准绳**——溯源购买交易关联**必填**（创建时刻，后端守卫已强制，issue #207）、创建唯一入口 = 交易右键「加入物品」+ 确认弹窗、**无手动新建表单**（物品页表单已移除，issue #207）、**无交易物品不可录入**；当前实现仅剩一处过渡差异：列名仍为 `purchase_transaction_id`（目标名 `source_transaction_id`，改名及迁移另票处理），且该列仍可空（可空服务于修改语义与外键清理，必填仅约束创建时刻）。

## Item（物品）

- **定义**：用户拥有并使用的耐用实物（如手机、电脑、家具、车、家电），用于跟踪它"从购买到今天平均每天花多少钱"（使用成本摊薄）。是账本中与参考数据（账户/分类/币种，见参考数据与设置域 Reference Data）、核心交易域交易流水（Transaction）、投资域投资标的（Instrument）并列的独立领域概念，不是字典也不是一次性交易。**与 `Instrument`（金融/投资标的）严格区分**——`Instrument` 是用户可交易的股票/基金/债券等证券（见投资域），`Item` 是用户拥有的耐用实物；二字不可混用。
- **边界**：
  - 仅覆盖耐用实物，不含服务/订阅（那些是定时计划域 ScheduledTransaction / Subscription 的语义，见 Subscription）。
  - **创建唯一来源 = 一笔 `expense` 购买交易**：物品只能经交易右键「加入物品」+ 确认弹窗创建（见下「创建语义」），**无手动新建表单**；`source_transaction_id` 必填、唯一。**无交易物品（赠品、旧物等无对应购买交易的物品）不可录入。**
  - 每个物品**自包含总成本**：创建时由关联购买交易自动带出，后续花费（维修/配件/运费）由用户编辑总数累加；**不**由系统对多笔交易求和，也不基于多笔关联交易自动累加（避免与账本双向纠缠，见 Item↔Transaction 关联）。
  - 只存溯源指针（`source_transaction_id` → 购买交易），**不建立"交易→物品"的反向引用**；同一交易不可重复创建物品（溯源唯一）。
  - 生命周期：`in_use`（在用）/ `disposed`（已处置，记录处置日期 + 可选残值）。
  - 币种/金额复用核心交易域 Amount 接缝（整数分 + raw/native 折算到默认币种）。
  - 属独立领域（独立领域状态），不属于参考数据（那不是"可选值字典"）；写入后发 `ledger:changed`（粗粒度失效）。
- **别名**：不使用 "Asset / 资产"（偏会计/金融，且与投资域混淆）、"Good"、"Instrument"（那是金融标的，见 Instrument）。

## source_transaction_id（溯源购买交易）

- **定义**：物品创建时关联的 `expense` 购买交易 id，是物品**创建的唯一来源与溯源**。**必填、唯一**。
- **边界**：
  - **创建时必须提供（必填）**：后端强制校验交易存在、未删除且为 `expense`，并以该交易的日期 / 总成本 / 币种**自动带出**覆盖同名入参（确认弹窗展示为只读预填）。
  - **唯一**：同一交易不可重复创建物品（溯源唯一，避免同一笔购买对应多件物品）。"必填/唯一"仅约束**创建时刻**。
  - 只存溯源指针，**不建立"交易→物品"反向引用**；物品软删除不影响交易。
  - 创建后仅用于展示溯源；用户**编辑**时提供与原关联不同的新交易 → 换关并重新带出；不提供 → 维持现状（溯源只增不减，**不随用户编辑丢失**）。与编辑无关的**数据库级清理**：关联交易被硬删时指针置空（与核心域退款关联列同一约定）——属外键清理，不属「溯源只增不减」的编辑语义。
- **别名**：不使用"关联交易"（指向歧义，易与交易侧字段混淆）。代码侧当前为过渡字段名 `purchase_transaction_id`（见上「与代码的差异」）。

## DailyUsageCost（每天使用成本）

- **定义**：一件 Item 的平均使用成本，= 该物品分摊的总成本 ÷ 拥有天数（从购买日期到今天，或用户自选参考日；已处置物品到处置日，可选扣残值）。展示为本位币（核心交易域默认币种 DefaultCurrency）。
- **边界**：
  - 分子 = 物品总成本（基础 + 追加）；已处置且填残值时分子 = 总成本 − 残值；分子下限 0（残值 ≥ 成本或总成本异常为负时不输出负成本）。
  - 分母 = 自购买日期到"目前"的日历天数，默认取今天实时，支持用户自选参考日。
  - **参考日语义**：缺省目标日按状态取（在用 → 今天；已处置 → 处置日）；用户自选参考日时**覆盖目标日**（两种状态均生效，未来日期合法——预览「如果用满 N 天」）；参考日只改分母，**分子口径不变**（已处置物品仍扣残值，成本基准不随参考日变化）。单件重算命令为只读计算，不发失效信号。
  - 只输出"每天"一个口径（月/年由用户心理换算，避免口径发散）。
  - **跨物品合计口径**（issue #122 dashboard 汇总卡）：全部在用物品每天成本合计 = Σ 各在用物品分子（折本位币，Amount 接缝当前汇率）÷ 各自天数，收敛在物品域合计单点（不是 Σ分子 ÷ Σ天数 的加权均值）；缺汇率错误上抛，不以零计入。
- **别名**：不使用"摊销成本"（偏会计）、"折旧"（会计上特指固定资产折旧，此处是主观使用成本）。

## 创建语义（唯一入口）

- **唯一入口 = 交易右键「加入物品」+ 确认弹窗**。用户在交易列表对一笔 `expense` 交易右键，选择「加入物品」，弹出确认窗：购买日期 / 基础成本 / 币种从交易**自动带出并只读预填**，名称默认取交易备注（可微调），确认后调用创建命令。**无手动新建物品表单。**
- 后端强制校验：`source_transaction_id` 必填、交易存在且为 `expense`、**同一交易不可重复创建物品**（溯源唯一）。
- 菜单态：已建物品的交易对应菜单项**置灰禁用**（溯源唯一的界面呈现）；置灰态由物品 store 按溯源指针比对得出，不新增查询、不建反向引用。
- 语义提醒（#113 双记录）：同一笔购买既是账本里的 `expense` 交易（进报表/预算），又是该物品的基础成本来源（持有成本线）；二者服务不同目的，需要让用户理解这是两条线。
