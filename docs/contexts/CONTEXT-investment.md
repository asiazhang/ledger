# 领域词汇表：投资域

> Ledger 领域词汇表的投资域分域。全部分域与彼此关系见 `CONTEXT-MAP.md`；决策记录见 `docs/adr/`（ADR-0015 / ADR-0019 / ADR-0020 / ADR-0036 / ADR-0038 / ADR-0081 等）。
> 跨域共享术语（Transaction、Amount Model、Transaction Kind Mapping、DefaultCurrency 等）见核心交易域 `CONTEXT-core.md`，本文不复制定义。
> 若与代码行为冲突，以代码为准并同步修正本文件。

## Instrument（金融工具/标的）

- **定义**：用户可交易的金融产品，例如某只股票、某只基金、某只债券。
- **边界**：
  - 类型闭集五种：股票、基金、债券、ETF、其他。
  - 标的由显示代码与市场共同标识（市场闭集、可路由性与未知语义见市场（Market）词条，ADR-0081）。
  - 股票类标的的字典修正自 ADR-0081 起归「按代码查询/创建带回权威名称」（随用随修），自 #827 起再加「同步随行刷新」——标的信息同步时以数据源权威名称覆盖有通道行的名称（见 InstrumentInfoSync；同码自建行名称被数据源覆盖为已接受代价，ADR-0036 修订；标的全量同步入口/命令已退役，issue #698，见 InstrumentSync）；**标的创建 UI 入口唯一 =「添加投资标的」对话框**（issue #697 / spec #690；六通道修订 issue #826 / ADR-0081 决策 6）：市场必选录入通道（沪/深/港/美股/场外基金/自定义标的）——前五通道按代码查询，命中自动识别类型（行情命中 → stock、数据源类型码特征 → etf）并回填权威名称与最新价，查无此码只报错并引导切换自定义标的通道（查询未命中兜底建档已退役）；自定义标的通道零查询直接建档（见自建标的）；场外基金通道即既有按代码即拉（语义不变）。原「新建标的」独立弹窗与「添加基金」独立入口已收编退役。
  - **字典来源（DictionarySource）**：字典条目带来源标记（`source`：新建行一律 `manual`，来源随行终身不变；存量行 `eastmoney` 是换源前的历史取值，保留不迁移，ADR-0130 决策 7，见自建标的），问的是「这条字典**是谁建的**」，与价格数据的来源标记（价格从哪里来）同词表但语义正交。全量标的同步退役（ADR-0081 决策 3）后写入侧只剩手动（按代码查询/创建、自建标的、AI 创建同路），该标记的唯一功能消费是**删除准入**（仅手动行可删；存量行不因此放开为可删，ADR-0130 决策 7）——因此它**不进用户可见的标的列表**；列表展示的是价格来源（见价格通道），把内部建行标记当「来源」展示，会让「手动字典 + 自动净值」的基金行看起来自相矛盾（grilling 定稿，2026-09-12）。手动创建与字典修正正交（ADR-0036）。
  - **幂等建行**：标的字典以（symbol, 类型）为自然键幂等创建，已有行复用并按需更新名称/市场，不产生同标的多条记录（防碎片）。
  - **标的搜索**：消费统一模糊搜索语义规格（唯一定义点见核心交易域 TransactionSearch，ADR-0027），判定目标为「代码 · 名称」label 等价文本，无名称时退化为裸代码。
  - **迁移建行**：AI 迁移按「先按代码查询 → 再以真实代码创建 → 写 buy/sell」三步解析标的（约定见 AI 导入域 AI API，ADR-0081 决策 1/4）：fund/stock 真实代码创建经按代码查询增强——回填权威名称、落最新价现价（股票降级建行保留可知市场，行情恢复后价格通道仍可达）；「名称充代码」收敛为源数据确无代码时的兜底建行，此类行与自建标的同路（非同步来源），无行情通道、不参与行情同步，AI 通道亦无就地升级为真实代码的入口。
  - **场外基金标的（ADR-0038）**：类型 fund、市场恒为 unknown——场外基金没有交易所市场概念，基金代码亦无市场前缀规律，仅由 6 位代码标识；入口是手动输代码、按代码即拉查询回填（名称/类型/最新净值，见 MarketPrice），不做基金全量同步；字典来源 = 手动（自建标的的按代码增强形态，ADR-0036），与净值来自数据源并行不悖（见字典来源）。**市场恒 unknown 对全部创建通道成立**（含 AI 创建端点）——后端守卫拒绝 fund 行携带市场，不变量不因通道而异（grilling 定稿，2026-09-12）。名称充代码的基金行无真实代码，不进净值通道（仍属无行情行，见 PriceHistory）。**存在性判据 = 批量面 ∪ 官方披露**（ADR-0039 修订，2026-09-13 判据形状；#1568 换源）：新浪批量面未收录的基金（典型为已终止/清盘）经证监会基金电子披露区间查询回退识别，回填权威名称与最新披露取值（普通形态为最后一期单位净值，货基自报形态落恒定价，见价格恒定标的），不再是查无此码；本判据不判定、不标注终止状态——披露记录不携带终止状态，刻意不引入。
  - **货币基金可建**：净值通道对 fund 类型不做基金分类过滤——货币基金与普通场外基金同构（同为 6 位代码、同一净值通道、同一价格刻度），换源后基金分类无来源可依（ADR-0130 决策 8：契约字段保留、恒空并标注弃用），通道不设分类过滤；ADR-0038 原文的「明确排除」是当时的范围声明而非守卫，自此读作「承认可用」（grilling 定稿，2026-09-12）。**货币基金价格口径（ADR-0126，取代 #1342 的平坦序列口径）**：货基单位净值恒 1.0000（收益以份额结转体现），万份收益不是净值，累计净值也不入价（份额已含结转收益，再乘会重复计）——它的价格是定义性常量，因此**退出采集链路、由读侧按常量取值**，采集与取值的完整口径见价格恒定标的；货基判定由证监会基金电子披露的自报形态给出（最新披露记录「单位净值为空、万份收益与七日年化有值」，ADR-0126 决策 3 换源），信号皆缺的形态不在本口径覆盖内（详见 ADR-0038 修订记录与 ADR-0126）。
  - 标的名称（如「贵州茅台」）由按代码查询/创建带回的权威名称自动填充。
  - **投资状态**：列表返回的派生标记 = 是否为持仓标的（见 InvestedInstrument）；标的页据此展示「持仓」标记列，并可用「只看持仓」开关过滤（issue #102）。
- **别名**：不使用"证券"（偏法律概念）、"产品"（过于泛化）。不单独使用 "market_symbol" 或 "ticker"——统一使用 "symbol"。

## 市场（Market）

- **定义**：标的挂牌的交易所市场，与显示代码共同标识一只标的；后端闭集七值——沪、深、港、美股三市场（nasdaq/nyse/amex）、未知（unknown）——落库值由库层 CHECK 收口（ADR-0081），Rust 侧单点类型承载：投资域定义、行情同步域向下消费。
- **边界**：
  - **可路由与不可路由**：前六值可构造行情查询键（可路由市场），unknown 不可路由——价格通道归「无来源」（见价格通道），同步编排计入「跳过 M 只」统计提示，不走运行时报错（ADR-0081：未知市场合法落库但永无行情；手动创建未指定市场即 unknown）。
  - **美股路由聚合值不是市场成员**：`us` 是按代码查询/创建解析与行情键构造内部的路由聚合值（美股三市场共用 `us` 前缀单查询），只活在查询路由内部，不落库、不出响应、不进闭集；美股三值照填、界面折叠显示「美股」（ADR-0081 决策 2 修订）。
  - **能力随类型单点**：可路由性判定、行情/K 线查询键形态、币种按来源固定（沪/深 → 人民币、港 → 港币、美股三市场 → 美元，ADR-0081）都是市场闭集的关联能力，唯一住址在投资域的市场类型上，行情同步域向下消费（ADR-0103 同构）——跨域不存在第二份「市场 → 查询键」口径，数据源响应词汇 → 市场的解析点同理单点。
  - **场外基金市场恒 unknown**：基金没有交易所市场概念（见 Instrument 场外基金标的词条），净值通道按代码形态路由、不经市场。
- **别名**：不使用「交易所」作词条名（成员粒度不一致——沪深港各一体、美股按交易所拆三值、聚合路由又不分交易所）；不使用「区域」「地区」。

## MarketPrice（市场价格）

- **定义**：某个 Instrument **当前**的市场报价——现价缓存，即 PriceHistory 中该标的最新一条的即时映像，供持仓市值与未实现盈亏（Holding）计算消费；价格恒定标的（见价格恒定标的）是唯一例外——它没有历史行，现价就是那个常量本身。
- **边界**：
  - 仅代表"现在"：每次同步覆盖更新本条记录；历史报价序列由 PriceHistory 承载，MarketPrice 不再是价格的唯一载体。
  - 现价与币种由数据源返回（场内为腾讯行情，场外基金为新浪与证监会基金电子披露，ADR-0130 决策 2），币种按来源固定：沪/深市为人民币、港股为港币、美股三市场为美元（口径单点见市场（Market），ADR-0081）；场外基金为人民币，其现价语义 = 最新公布的**单位净值**，并记录净值日期（兼任净值同步水位，见 InstrumentInfoSync）；另记录同步时间与来源标记——价格侧来源标记按**实际取数源**取值，闭集为 `tencent`（场内）/ `sina`（场外基金净值）/ `csrc`（披露兜底取价与恒定价确认）/ `manual`（手动报价），存量行 `eastmoney` 保留为历史事实、不重写不迁移（ADR-0130 决策 7；与字典侧来源标记同词表而语义正交，见字典来源）。
  - 价格数值刻度为**万分之一元**（全投资域价格列统一口径，见价格刻度）。
- **别名**：不使用"行情"（偏实时交易概念）、"报价"（偏询价场景）、"最新价快照"。

## PriceHistory（价格历史）

- **定义**：某个 Instrument 的市场报价按周粒度累积的历史序列，用于绘制单标的走势与投资资产走势（PortfolioValueTrend），是价格在「现价」之外的第二条承载线。
- **边界**：
  - **覆盖面 = 需要采集价格的通道成员**：股票与场内 ETF 标的（有市场 + 代码即可构造行情查询，持仓或清仓均同，issue #827）经行情同步通道写入；**非恒定**的场外基金标的经净值同步通道写入（单位净值即价格，ADR-0038）；无行情来源的自建标的经手动报价通道写入（ADR-0036）。**价格恒定标的不落任何历史行**（见价格恒定标的）——它的取值在响应内按常量合成，历史表不为它记录；无任何价格写入的标的不参与价格记录与走势图。通道闭集与判定单点见价格通道（PriceChannel）。
  - **周采样**：每周至多记录一条，取该周最后一个有报价交易日的价格；整周无有效报价（停牌、节假日全周覆盖等）则该周无点，曲线跨越空档连续。一周内重复获取时以新数据**整周覆盖**（幂等），不产生重复。
  - **采集与现价解耦（ADR-0122）**：历史初始一次性回填，此后由价格历史后台补全持续累积；现价刷新走行情批量取数。原「回填历史同时也是刷现价、不存在两条刷新通道」的口径由 ADR-0122 推翻——当周采样点直接由现价刷新的批量取数落库，逐只采集只服务首刷、缺周点补齐与基金深回填。回填深度：基金覆盖到首笔持仓流水日所在周（无持仓流水则近两年，#1534）；股票/场内标的维持近两年（日 K 源深度限制，要更深须换源另立票）。
  - 已清仓标的自 #827 起恢复采集（覆盖面不再以持仓为界），历史持续累积；原「清仓后不再新增」口径随之退役。
  - 港股以港币计价、美股以美元计价，跨币种汇总走势须经 FxRateHistory 同期折算，不用当前汇率近似历史。
- **别名**：不使用"历史行情"（口语偏全市场）、"K 线"（那是数据源的原始形态，本地不保留日线）；单只基金的净值序列可称"净值走势"，但组合走势仍不称"净值走势"（混合多类资产，见 PortfolioValueTrend）。

## 价格通道（PriceChannel）

- **定义**：标的「价格从哪里来」的后端派生事实——按类型 × 市场 × 代码（恒定价格另看标的行的恒定单位价格）把库内标的分进价格写入通道的闭集判定：**行情**（股票与场内 ETF、市场已知）、**净值**（6 位真实代码的**非恒定**场外基金）、**恒定价格**（价格是定义性常量、无需采集的标的，见价格恒定标的）、**手动报价**（其余开放录价的行）、**无来源**（市场未知的股票类）。随标的读投影输出；除恒定价格外不落库，恒定价格是本闭集唯一需要持久化输入的成员。
- **边界**：
  - **判定单点在后端**，与标的信息同步的通道能力分区同源（ADR-0036/0038、issue #695）：分区即回答「价格从哪里来」——谁给它写价，或者它是否根本不需要写价（恒定价格）。消费方（单标的走势放行、标的页录价入口、采集面与过期检查面）只读该事实，不再自行按类型与市场推断——走势面板上线时的场内行情白名单与录价入口判定曾各自在前端镜像推断，场外基金一等标的定案后漂移成第二口径，issue #1060 收口。
  - **无来源 ≠ 有通道无数据**：无来源行（行情不可达且录价不开放）不提供走势，给「没有价格来源」边界说明；行情 / 净值通道行无历史数据时按补全状态给三态空态（补全中 / 补全失败待重试 / 无数据），**不再**给指向「同步标的信息」的引导（ADR-0122 决策 5）——那个动作只修现价、修不了历史；手动报价通道给「录价」引导；恒定价格通道直出常量线并给一句解释，无空态可言。
  - **用户可见口径是价格来源**：标的列表以「价格来源」列展示本词条五值（净值 / 行情 / 恒定价格 / 手动报价 / 无来源），回答用户真正会问的问题——这只标的价格能不能自动更新、要不要手动录价、还是根本不用更新；字典来源（来源标记）不进该列（grilling 定稿，2026-09-12）。
  - 与 PriceHistory 覆盖面的关系：覆盖面 = 需要采集价格的通道成员（行情 / 净值 / 手动报价，见 PriceHistory）；恒定价格成员不落历史行、由读侧按常量取值；通道本身只是「价格从哪里来」的判定，不代表已有数据。
- **别名**：不使用「行情来源」（只是五通道之一，作总称会重新遮蔽其余通道）、「数据源」（暗示外部数据源，而本概念是写入通道归属）。

## 价格恒定标的（Constant-Price Instrument）

- **定义**：价格由本地常量给出、不经过任何采集通道的标的——它的单位价格是定义性常量（不随市场波动），因此「问一次数据源」与「每天问一次数据源」都不会改变取值。货基是当前唯一成员（单位净值恒 1.0000，收益以份额结转体现，ADR-0126）。
- **边界**：
  - **恒定是价格通道的分区成员，不是通道上的叠加属性**：不存在「既是行情 / 净值通道、又是恒定价格」的标的，判定单点仍归价格通道（见价格通道），消费方不得自行按类型推断第二口径。
  - **判定事实来自官方披露自报口径，且单向**：同为 6 位代码、同一价格刻度、同一基金类型都无法区分货基与普通场外基金，唯一区分是证监会基金电子披露的自报形态——最新披露记录「单位净值为空、万份收益与七日年化有值」（ADR-0126 决策 3 换源）。该事实一经确认即长期成立——缺信号（无披露记录或最新记录为普通净值形态）不得反推为「不是恒定标的」；披露源不可信按本轮不可信处置、不落任何价格（信号缺席时落取数面的取值位，万份收益就会冒充单位净值，#1342）。
  - **退出采集链路、取值走读侧**：恒定标的不进首刷队列、不进每日逐只刷新、不落周采样点（打标后由同步编排分区排除，换源后含货基的批量面也不再触及它，ADR-0130 决策 6）；单标的走势、组合走势与收益率（MoneyWeightedReturn）在响应内按该常量取值，历史表不为它落任何行。现价缓存仍保留一条（供持仓市值、净资产等取数面消费），但不再随同步更新，其净值日期列对用户显示为空。未打标的货基仍会经逐只通道收到一次确认请求——官方披露自报形态判定门确认即打标（单向），自下一轮同步起退出采集链路（见 ADR-0126 决策 3）。
  - **价格过期对恒定标的不适用**：过期检查建立在「数据源会给出新的价格」这一前提上，恒定标的没有这个前提；提示的计数与文案一并排除它（见价格过期提示）。
  - **不是手动报价通道，也不是无来源**：手动报价由用户录入、可取任意值、可随时间变化；无来源是根本拿不到价。恒定的价格是已知的、永远不变的——三者的用户可见后果不同（录价引导 / 无来源说明 / 直出常量线 + 一句解释）。
- **别名**：不使用「恒值标的」「恒定标的」（「恒」的宾语不明——恒定的是**单位价格**，不是持有市值：货基份额结转使其市值随时间增长）；也不以「货基走势没信息量」这类描述代替本术语。

## FxRateHistory（汇率历史）

- **定义**：货币间兑换比率按周累积的历史序列，源为 ECB 参考汇率的同日两腿交叉推导；用于把非默认币种的**历史**市值折算到核心交易域 DefaultCurrency，也是核心交易域流水 raw/native 折算的取数来源（按交易所属 ISO 周命中）。
- **边界**：
  - 与参考数据与设置域 ExchangeRate（当期汇率）并存分工：历史期折算与核心交易域流水折算走 FxRateHistory，当期折算走 ExchangeRate；同期同规则（正反向兜底）。
  - 周采样与整周覆盖规则与 PriceHistory 一致；**窗口不与 PriceHistory 绑定**——按覆盖账本中最早的非本位币日期决定深度。
  - 采集由设置页手动同步与每日自动两路触发，按可重建缓存对待、不进同步日志（清空重同步零损失）。
- **别名**：不使用"历史汇率表"（易与当期表混淆指代）；可简称"汇率历史"。

## PortfolioValueTrend（投资资产走势）

- **定义**：把用户全部有价格历史的持仓在各时点的市值汇总成的时间序列视图，回答"我的投资总价值如何变化"；同一功能内也呈现单个标的自身价格序列的单标的走势。
- **边界**：
  - 组合市值 = 各持仓标的「当期持有数量 × 当期价格」之和：数量由核心交易域持仓变动流水（buy/sell、convert 两腿与 split 腿）在查询时推算（不物化每日/每周快照；排除软删除账户的流水，口径见时点持仓），价格取自 PriceHistory。份额调整（split）已落地为份额变动的真实来源，推算纳入 `+Δ` 腿；现金分红（Dividend）只有现金腿、不改变持有数量，故不入推算；未来支持送股等改变持有量的公司行为时，逐期推算必须同步纳入，否则静默失真。
  - 跨币种按 FxRateHistory 折算为核心交易域 DefaultCurrency 后汇总成一条曲线；曲线为周采样点连线。
  - 展示位置 MVP 为投资页内的走势视图（预设区间切换：1 月 / 3 月 / 1 年 / 全部；组合走势与单标的走势同视图切换）；多标的叠加对比属后续迭代。
  - **不含现金账户**：总资产走势（现金余额历史重建 + 投资市值）是明确的后续迭代，不在本概念范围内。
  - 标的在区间起点之前买入无早期价格时，曲线从首个有效采样点开始。
- **别名**：不使用"净值走势"（组合混合多类资产，该词仅适用于单只基金的价格序列；且暗示收益率口径）、"收益曲线"（混入收益率口径）、"总资产走势"（明确含现金账户的后续概念）。

## Holding（持仓）

- **定义**：用户在某个投资账户中持有的某个 Instrument 的数量及成本信息。
- **边界**：
  - 数量为当前持有数量，由各持仓批次剩余数量实时聚合；持有成本为买入总成本及其币种。
  - 现价、市值、未实现盈亏由 `v_holdings` 视图实时计算（关联最新 MarketPrice 与汇率折算到账户本位币），不落库存储。
  - 市值 = 数量 × 现价（按汇率折算）；未实现盈亏 = 账户币市值 − 账户币成本。
  - **展示词为「持仓收益」（grill-with-docs 产品裁决 2026-09-11，issue #1077）**：持仓页签的合计卡与「未实现盈亏」列、首页投资卡的对应文案用「持仓收益」指代本词条的未实现盈亏，以便与第三方基金平台（且慢等）的同名词对照；账务口径词仍是未实现盈亏，展示词不改变任何计算。
  - **持仓页签金额排序口径（issue #902）**：市值/未实现盈亏两列列头排序对**账户本位币折算值做数值直比**——多币种账户各折各的本位币，跨币种行间比较无精确语义，不为排序引入第二套折算（已接受代价）；缺价行（空值）排序恒排末尾、金额列显示「-」、不计入随过滤子集更新的合计。
  - **缺价行可执行引导（issue #1193）**：缺价行除空值展示外回落到**价格通道事实**给下一步——有通道行按通道匹配既有入口（行情/净值通道去「同步标的信息」、手动报价通道去「录价」，口径与「无来源 ≠ 有通道无数据」同源，见价格通道），无来源与通道未知行不给引导；判定只读价格通道派生事实，前端不另推第二套通道口径。
  - **持仓页签展示形态与保留粒度（issue #912 / #1192）**：行集全量拉取、前端过滤排序后经**客户端切片分页**展示（形态与页码生命周期见界面状态与交互域，页大小固定不设选择器）；净值日期独立成列（仅基金行携带，现价对应哪天的净值一眼可辨，#303），现价列单行渲染。持仓页签筛选/排序/页码与走势页签选中标的按**会话内保留**粒度处理（issue #1192，ADR-0094 默认粒度；界面状态与交互域「会话内保留」）：切走页签再回来回到离开时的样子、冷启动回默认、零写盘；ESC 复位通道与交易页/报表页同款（复位 = 页签回默认「概览」——默认落点自 spec #1532 / issue #1536 起由「盈亏」改址，见投资概览；持仓筛选清零 + 翻页归零、走势回默认组合曲线）。
  - **「现价」列名跨类型统一、值随价格通道而异（issue #1369）**：持仓表与标的列表的现价列在基金行装的是**最新公布的单位净值**（配套「净值日期」列），股票行装的是最新报价或收盘价——两者同为该标的的「当前价格」，故列名不按类型分叉；与「价格来源」列（价格通道归属）分工不同，前者答「值是多少」、后者答「这个值从哪来、会不会自动更新」。名实差异由在场口径标注承担（见「持仓收益」同款展示词纪律），不在列名上分类型改名。
- **别名**：不使用"仓位"（偏交易术语）、"库存"（偏实物）；「持仓收益」是对外展示词（见边界），不与账务口径词混用、不与「累计收益」混用。

## 份额容差（QuantityTolerance）

- **定义**：可卖出数量守卫对 f64 持仓扣减累积位误差的容忍度——绝对值 1e-6 份；sell 可卖守卫、基金转换（Conversion）转出腿同款守卫（本地录入与多端重放两形态）、份额调整（Split）缩股守卫（`|Δ| < 当前持仓` 按同一容差判定，等号仍拒绝）与 FIFO 消耗的批次耗尽判定共用同一口径（issue #1033）。
- **边界**：
  - **动机是双数量级，不是业务最小单位**：f64 逐次扣减的累积位误差在账本量级（持仓远小于千万份）约 1e-12～1e-9；数量录入粒度合同为至多四位小数（见界面状态与交互域字段错误态，issue #416），真实超卖差异 ≥ 1e-4。容差取 1e-6 居中——吞掉全部位噪声，不放过任何真实超卖。份额**没有统一刻度**（对照价格刻度），「0.01 份最小单位」不是本仓事实。
  - **守卫语义**：可卖总数 + 容差低于尝试数量才拒绝；裸比较会误拒真实全清仓（如持有 8036.109999999999、卖出 8036.11）。位误差方向随消耗顺序漂移（同链反序可差 1e-12），守卫对两种序同等容忍。错误文案中的数字按录入粒度合同展示（至多四位小数去尾零），不把位噪声原文抛给用户。
  - **耗尽判定同口径**：批次剩余不高于待消耗 + 容差即视为耗尽、整批取走——噪声偏高方向的清仓精确归零、不留尘埃批次（残差会让持仓视图永远认其为持仓）；存量尘埃批次在下次交易中自然清零，无需数据迁移。
  - **不采用整数刻度份额**：多端同步重放下「同 schema、不同语义」的载荷不可检测（触碰不静默错账底线），且份额无自然最小单位可锚定；守卫容差以极小代价覆盖全部用户可见危害。
- **别名**：不使用「精度容差」（易读成展示精度）、「容错」（掩盖故障的语义）、「超卖容忍」（放行仅限位噪声量级，真超卖仍拒绝）。

## NetWorth（净资产）

- **定义**：用户全部真实财富在某一时刻的单一合计数字（本位币）：Σ 非投资账户余额 + Σ 持仓市值 + Σ 在持实物资产估值（见实物资产域），均折算为核心交易域 DefaultCurrency 后相加。
- **边界**：
  - 由后端只读聚合经**读探针**提供（ADR-0067）：终值缓存单例行，读取时比对各贡献表时间戳指纹，命中直接返回、失配或无缓存行时实时聚合重算并回填——自愈无定时任务；账户侧余额腿沿用核心交易域余额缓存口径（符号归属见核心交易域 Transaction Kind Mapping，与账户列表/余额页一致，排除隐藏/黑洞账户——见 AI 导入域 BlackHoleAccount），投资账户余额不计入——其价值经持仓市值体现，避免同一笔资产重复计算。
  - 持仓市值取持仓视图输出的账户本位币市值，再折算到 DefaultCurrency；从未录价（或缺折算汇率）的持仓按空值语义跳过，不以零计入。
  - **实物资产估值是第三腿**（口径归实物资产域，见实物资产域 PhysicalAsset 与 ADR-0064）：只合计在持资产（已处置 / 软删不进）；估值建档必填，无「缺估值」空值语义。实物资产只进净资产、不进可投资资产（可投资资产分子不变，见 InvestableAssets）。
  - 折算遇缺失汇率让错误上抛（中文错误信息），不静默返回不完整的合计数字。
  - 负债账户按 `account_flow` 现行符号忠实求和，不在净资产层强制取负。
  - 「总资产走势」（净资产的时间序列，现金余额历史重建 + 市值）是明确的后续迭代，不在本概念范围内。
- **别名**：不使用"总资产"（与「总资产走势」既有预留概念区分，避免同一页面两套口径混淆）、"净值"（基金净值语义不同）。

## InvestableAssets（可投资资产）

- **定义**：能产生被动收益的资产合计（本位币）：Σ 持仓市值 + Σ 投资账户余额，均折算为核心交易域 DefaultCurrency——财务自由度（FinancialFreedom）的分子（ADR-0048）。
- **边界**：
  - **与 NetWorth 的边界差异**：净资产排除投资账户余额，是防止其价值与持仓市值重复计入同一笔资产；可投资资产计入投资账户余额，是因为账户里未投入的现金（「子弹」）不被持仓市值体现，漏算会低估真正能产生被动收益的资产。两者并存不冲突，消费者按问题选口径（「能钱生钱的有多少」vs「全部家当有多少」）。
  - **生活现金/储蓄/电子钱包等非投资账户不计入**：计入会让生活费虚增自由度。
  - **排除隐藏账户**（含黑洞账户，见 AI 导入域 BlackHoleAccount）：隐藏投资账户的现金与持仓一并不进分子，归档/黑洞类账户不扭曲指标；**负债既不计入也不抵扣**——指标聚焦资产侧，口径简单可解释。
  - 从未录价（或缺价格币→账户币折算汇率）的持仓按空值语义跳过（同 NetWorth 的视图口径），不以零计入；折算到本位币一腿遇缺失汇率让错误上抛（中文错误信息），不静默返回缺料的数字。
  - **消费面三处、口径单点一份**：财务自由度（FinancialFreedom）的分子、跨账本投资汇总（CrossBookInvestmentSummary）的「可投资资产」列，以及投资概览（InvestmentOverview）页签的合计与两腿拆分（ADR-0131）——三处消费同一口径单点，两腿拆分（投资账户现金 / 持仓市值）不新增第二份表达式，原合计恒为两腿之和。
- **别名**：不使用"投资资产"（易与 Investment 混淆）、"总资产"（那是含生活资产与负债的净资产口径，见 NetWorth 别名边界）。

## FinancialFreedom（财务自由度）

- **定义**：可投资资产（InvestableAssets）对年度支出水平的覆盖程度（本位币百分比）：自由度 = 可投资资产 × 3% 安全提取率 ÷ 年度预算总额（见预算域 AnnualBudgetTotal）× 100%，≥100% 即财务自由；后端只读实时计算，不落库存储（ADR-0048）。
- **边界**：
  - **3% 安全提取率是常量**（保守于教科书 4%，达标线更扎实），单点收口在后端，不开放用户配置；调整先修订 ADR-0048。
  - **覆盖年数 = 可投资资产 ÷ 年度预算总额**，与自由度是同一刻度的两种表述（「每年能提多少」与「能躺几年」）；两者均保留一位小数。
  - **未设预算时照常返回零分母**，不回退实际支出——占位引导（「设置预算后解锁」）归展示层，口径层不引入第二分母。
  - **阶段标签（积累期 / 接近自由 / 财务自由）与阈值归界面层派生**：分档是展示文案而非口径，后端只输出百分比本身。
  - 买卖投资、录入报价、编辑预算后即时反映（命令实时聚合，无快照可过期）。
- **别名**：不使用"FIRE 指数"（社群口语）、"自由率"。

## 跨账本投资汇总（CrossBookInvestmentSummary）

- **定义**：跨账本语境下，把各本账本的投资域口径（持仓市值、持仓收益、累计收益、可投资资产）逐本取数、内存合并成的只读合计视图（ADR-0114）。
- **边界**：
  - **入口＝独立汇总路由**（ADR-0114 决策 6）：经账本切换弹层顶部的「全部账本（投资汇总）」项进入，不动活动指针、不触发原位重引导；本内页面与口径零改动；注册表损坏回退（清单不可信）时不可用。
  - **只覆盖投资域**：收支、预算、净资产、财务自由度仍是本内口径（账本的「不跨本汇总」边界，ADR-0089）；跨本相加的语义未裁决前不外扩。
  - **读路径聚合、零新增持久状态**：逐本只读建连（活动本复用进程内读连接）、逐本取数后在内存合并；不建汇总库、不改 schema、不落预聚合副本（双写即双份真相）。
  - **币种**：各账本位币一致时直接相加；不一致时按查看时当期汇率折算到**主账本＝当前活动账本**的本位币并标注口径，当期汇率取活动账本的汇率表——历史汇率只属走势曲线（PortfolioValueTrend）。
  - **只读**：不提供任何编辑入口，一切写入回到单账本语境。
  - **逐本状态显式标注**（ADR-0114 决策 5，2026-09-14 修订）：活动加密本（进程内已解锁）正常计入；非活动加密本恒不计入（进程内无逐本解锁能力，读连接口令协议禁止解锁窗外读钥匙串，ADR-0117），显式标注「未解锁、未计入」；只登记未建库、schema 版本不一致、只读打开失败三类同款逐本标注——不静默少算、不阻塞其他账本出数。
- **别名**：不使用「全局视图」（暗示覆盖全部域）、「合并账本」（暗示数据合并而非只读汇总）。

## 投资概览（InvestmentOverview）

- **定义**：投资页「概览」页签的内容口径（ADR-0131，spec #1532）——全页折本位币的**单值**视图：可投资资产一个本位币数字，加它由「投资账户现金」与「持仓市值」两腿构成；同时承载投资合计三项：总市值、持仓收益（未实现盈亏）、累计收益（spec #1532 / issue #1537）。投资页默认落点，纯只读。
- **边界**：
  - **全账本、折全局默认币种（DefaultCurrency）单值**：本页所有金额折算到同一币种后相加呈现，币种随结果透出供页面标注。与持仓视图「按账户币种分组、不跨币种合并、随搜索与账户过滤收窄」是两条并存的口径——同一标签（总市值 / 持仓收益）在概览页与持仓页签显示的**不是同一个数**，这是口径分工而非计算错误；差异由概念说明的 scope 变体句承担（先例 ADR-0129）。
  - **金额口径不自立**：合计与两腿的定义归可投资资产（InvestableAssets）与持仓、盈亏各词条；本词条只定义「这一页按什么口径把哪些数放在一起」，金额表达式不在此复制。总市值与可投资资产的持仓市值腿在全页口径下是同一聚合（字段各存其名，展示面各答一次问）；累计收益 = 持仓收益 + 已实现盈亏 + 累计分红（见累计收益词条的三腿），后两腿与既有分组口径同数据同过滤、唯逐行折本位币。
  - **缺料显式可见**：缺现价（或缺价格币→账户币折算汇率）的持仓按既有空值语义跳过、不以零计入，但页上给出未计入的持仓数（既不虚增也不静默低估）；缺折算汇率让既有码化错误上抛，页内卡内警告 + 重试，不显示半截数字；没有投资账户时照常出 0 并给一句引导——不隐藏功能。
  - **排除隐藏账户**（同 InvestableAssets 口径）；负债不计入也不抵扣。
  - **纯只读**：页内无同步、录价、设置预算等写入口或动作入口。默认落点、ESC 复位与会话内保留归界面状态与交互域（见该域「会话内保留」「ESC 键语义」）。
  - **数据新鲜度**：订阅价格失效信号（PriceChangeSignal）——同步标的信息、录入报价或后台补全实际写价后自动重拉，与持仓概览、标的页列表、组合走势、价格过期提示同批消费方。
  - **与财务自由度不冲突**：自由度仍需预算（ADR-0048 决策 4 讲的是零分母时命令照常返回、展示层负责引导）；本页承担可投资资产自身的可见性，把资产从「设了预算才看得到」里解耦出来。
- **别名**：不使用「投资首页」（暗示页面层级而非页面内容）、「资产总览」（与净资产口径混淆）、「总资产」（那是含生活资产的净资产口径，见 NetWorth）。

## 时点持仓（AsOfHolding）

- **定义**：某标的（或全组合）在**某交易日**的持有数量，由核心交易域持仓变动流水（buy / sell、convert 两腿与份额调整 split 腿）在查询时推算。「认 buy/sell、convert 两腿与 split 腿，卖出 / 转出腿取负、按日期前缀求和」三件事单点收敛在投资域的推算模块内（as-of 持仓推算接缝，spec #168）。
- **边界**：
  - **与 Holding 的分工**：Holding 答「现在持有多少」（持仓批次聚合），时点持仓答「某时点持有过多少」（流水前缀推算）；同一批买卖流水下两者在「今天」必须一致（绑定不变式测试钉住）。
  - **时间语义是交易日**：as-of 键为交易日（含当日的前缀求和）；周采样键是 PortfolioValueTrend 查询侧的时间语义，不进推算模块——双时间键契约由此显式分界。
  - **推算认 buy/sell、convert 两腿与 split 腿**（核心交易域 Transaction Kind Mapping）：convert 一笔一行两腿——转出腿取负、转入腿取正，单标的查询只取命中那腿、全组合形态两腿同时入账（转换前后组合总份额不变）；split 为单标的带符号份额增量 Δ（折算 / 结转 / 送股为 +、缩股为 −，ADR-0106 决策 8），直接计入前缀求和；现金分红（Dividend）不改变份额、不入推算；未来支持送股等改变持有量的公司行为时只改推算模块内部，走势查询不感知。
  - **消费者**：组合市值走势的数量推算经同不变量的腿流投影按标的分组增量推进（issue #1654，时点持仓接缝本身不变）；资金加权收益率的边界市值消费账户维度扩展形态（issue #1195）。单标的走势是价格直出，不消费本概念。对外 IPC 契约不变。
  - **软删除账户口径（issue #217 定案）**：流水口径排除软删除账户的持仓变动流水，与 Holding / InvestedInstrument / 净资产对齐——删除账户 = 从全部投资视角（含历史走势曲线）消失。账户删除/恢复（软删标志翻转）使流水自动进出推算，无需时点存续状态。隐藏账户不是软删除，与 v_holdings 一致不排除。
- **别名**：不使用「历史持仓」（易读成历史持仓记录）、"position"（交易术语）、与 Holding 混称「持仓数量」（无法区分现值与 as-of）。

## Investment（投资域）

- **定义**：承载核心交易域证券交易（buy / sell、基金转换 convert、份额调整 split 与现金分红 dividend）背后持仓批次、消耗匹配与已实现盈亏的概念域。
- **边界**：
  - **buy/sell 首先是交易 kind**：一笔 buy/sell 先是一笔核心交易域 `Transaction`（交易行落库经 Writer 接缝），Investment 是它背后的持仓/盈亏载体；基金转换（Conversion）同为交易 kind，两腿的持仓变化、消耗与结转同样归本域。
  - **场外基金申赎同构复用 buy/sell（ADR-0038）**：申购=buy、赎回=sell（数量=确认份额、单价=成交日净值、手续费=申购/赎回费），不新增 kind；录入按确认后结果（金额与确认份额为权威输入，单价由其反算），不做在途/确认中状态。资金流出/流入经可选出资账户归因（见核心交易域出资账户，ADR-0096）——场外直扣申购钱不经投资账户现金，出资账户与持仓份额同落一行。**录入权威按标的类型分流（issue #302）**：基金形态表单要求金额与份额必填、单价反算展示，行金额恒等于确认单整分金额（不被单价舍入污染）；其余类型维持单价权威、行金额重算。
  - **基金现金分红以 `dividend` kind 承载**（ADR-0109 / issue #1078）：手工与迁移侧记一笔现金分红流水（归属标的、现金腿入到账账户），见现金分红（Dividend）；红利再投（DRIP）由「现金分红到账投资账户 + 0 手续费买入自投资账户出资」两笔组合表达（见红利再投词条），不新增 kind。两者与「持仓变动只认 buy/sell、convert 与 split 腿」（见时点持仓）口径天然兼容——分红不改份额，故不进持仓推算。
  - 对外出口收窄为 `prepare / apply / revert` 三件套 + 删除路径第四出口 `release_for_delete`（issue #72 / #940 / #979 / ADR-0097 / ADR-0099 / ADR-0106 / ADR-0109）：prepare 校验归一化（不落库）、apply 应用副作用（buy 建仓 / sell 卖出匹配 / convert 两腿结转 / split 批次重述 / dividend 扩展行落库）、revert 回退副作用（修改路径：buy 转换链守卫+在用占用守卫+清理、sell 回补、convert 转换链守卫+在用卖出占用守卫+转出腿逐批次回补+转入批次与明细行清理、split 下游占用守卫+按重述审计精确回补、dividend 摘除扩展行）、release_for_delete 承载删除路径（sell 回补持仓并清空卖出关联 / buy 与 convert 级联回退其在用 sell 后整批清理（convert 另回补转出腿）/ split 按重述审计精确回补并清扩展行 / dividend 摘除扩展行，均返回级联 id 列表供编排入口逐笔软删）；交易行写入由核心交易域写入协议编排（经 Writer 接缝），Investment 不再反向依赖核心交易域的行更新（双向依赖已斩断，issue #70）。
  - **回退侧的两个接缝单点（issue #1018 / #1020）**：FIFO 取批次、逐批次分摊、耗尽闭合与两个精确回补原语归 `lots` 模块；两个回退出口（revert 的修改语义与 release_for_delete 的删除语义）都是同一动作 `unwind::remove` 的薄委托——守卫、级联与清理模板单点，按 kind 与修改/删除模式分派（见 Unwind）。
  - 分派用薄而穷尽的分支，不引入注册表机制（避免过度设计）。
- **别名**：不使用“投资账户”（那是投资类型的账户）、“证券模块”（偏数据层）。

## Unwind（持仓副作用撤销）

- **定义**：撤销一笔 buy / sell / convert / split / dividend 交易对持仓的全部影响（ADR-0097 语言）——回补批次消耗与卖出匹配、级联回补在用下游卖出、整批清理批次与交易扩展明细；是修改路径（撤销旧行后重建）与删除路径（撤销后软删交易行）共用的同一动作。
- **边界**：
  - **两模式一谓词**：修改与删除共用「在用」归因——只计未软删下游行的匹配/消耗记录，已删下游行的历史匹配（幽灵占用）不触发守卫、也不阻塞级联。差别只在级联：删除模式把该行批次的在用 sell 逐笔回补并返回 id 列表，供编排入口逐笔软删留痕（ADR-0097 级联契约）；修改模式恒返回空（在用占用已被守卫拒绝）。
  - **顺序即语义**：转换必须先回补转出腿再清目标行——删交易扩展行会按外键级联掉转出消耗记录，那是精确回补的唯一依据。
  - **守卫随迁单点**：部分卖出占用、转换链被后续转换消耗、转换转入份额被后续卖出、批次被在用 split 重述、split 批次被下游在用消耗五组守卫的语义与用户可见文案收口在本模块，按 kind 与修改/删除模式选择；编排入口不再注入文案（ADR-0033 决策 #4 的修订形态），同步重放与本地共用同一文案由单点天然继承。原「错误码与模板零变化」表述已过期——split 激活后本模块新增了对应的码化守卫与中英模板（ADR-0106 / ADR-0109 后续），守卫集以本模块与错误码模板为准。
  - **不属本概念**：FIFO 取批次/分摊/回补原语归 `lots`（见 Investment）；交易行软删、级联行的余额刷新与 delete op 归核心交易域删除编排。
- **别名**：不使用「回滚」（事务语义，非本概念）、「持仓重建」（只描述修改路径的重建半边）。

## 基金转换（Conversion）

- **定义**：在同一投资账户内把持有的 A 标的份额换成 B 标的份额、钱不进任何卡片也不进投资账户现金池的资本变动（ADR-0099），落账为第 9 种交易 kind `convert`：一笔转换 = 一条记录、两腿同记录（「A → B」）、无现金腿；两端称转出腿与转入腿。
- **边界**：
  - **零现金腿**：六度量系数全 0，落账前后全部账户余额（含黑洞）完全不变；不入支出报表；手续费如实记录在转换记录上、不摊入持仓成本。
  - **成本结转**：转入批次成本 = 被消耗转出批次的原始成本（FIFO 逐批次取用，耗尽批次沿用「买入锚点行权威金额 − 该批次此前已消耗成本」闭合，精确到分），不按转入日市值重置；每份成本 = 结转成本 ÷ 转入份额单次舍入（价格刻度）；转换本身对已实现盈亏贡献恒为 0。多腿转换单由提交方拆成多条 convert 记录（每腿一条），分摊口径 = 按各腿转出金额占比、尾差末腿。
  - **存储与审计**：两侧标的/份额与两侧确认金额落 `security_transactions` 扩展列；转出腿逐批次消耗（消耗哪些批次、各多少份额、按什么单位成本结转多少金额）落转出消耗记录表——它是后续修改回退与删除精确回补的**唯一依据**（转出时的 FIFO 状态在后续交易发生后不可重建），也是分批结转成本的审计载体。行金额锚点 = 结转成本（不是确认单金额）；列表金额列展示**转出金额**（确认单口径）。
  - **修改与删除（issue #979 / ADR-0099 决策 5）**：转换行的**就地修改**走全字段替换——先按旧转换清理（转换链守卫 + 在用卖出占用守卫 → 转出腿逐批次精确回补 → 转入批次与明细行清理），再按新输入重新 FIFO 消耗与结转建仓；**删除**走与 buy 同规的级联——转入批次的在用 sell 逐笔软删（各自 delete op 与余额刷新）、转出腿精确回补、转入批次与转换明细行整批清理。经修改接口**进/出 `convert` 的 kind 变更一律拒绝**（新码化错误 `trade.convert-kind-change-forbidden`）：纠错只有「软删 + 重建」一条窄路。转入份额已被后续卖出的转换修改以 `trade.convert-partially-sold-update` 拒绝（与买入的 `trade.partially-sold-update` 谓词同一、用户可见主体不同故文案各自单点）。精确回补的唯一依据是转出消耗记录（见上一条），且必须发生在清明细行之前（删行会按外键级联掉消耗记录）。
  - **守卫（收口在投资域模块，码与文案随守卫知识单点）**：两标的必须不同、同属一个投资账户（不跨账户）、转出份额不得超当前持仓（与卖出同款守卫）；不得携带出资账户（出资闭集仅 buy/sell）；携带商户/分类/保单一律拒绝，全部码化中文错误。`dividend`（现金分红）与 `split`（份额调整）均已实现，不改变 convert 的守卫集。
  - **链式结构**：一条转换单拆多腿时后腿消耗前腿建起的转入批次（ADR-0099 多腿分摊）。此已成立的链式依赖受守卫：转入批次已被**在用**后续转换消耗的前腿与买入不可修改、不可删除（否则批次连同下游转换的转出消耗记录一并消失，下游失去回退与结转的唯一依据）——链式结构须从最后一腿往前处理（修改与删除均先经该守卫）。
  - **推算与视图**：时点持仓推算转出腿取负、转入腿取正（一笔一行两个方向）；持仓视图冻结不动、批次驱动自动跟随；组合走势、净资产、可投资资产与持仓标的谓词随之自动跟随。
  - **录入形态**：只有确认单一种形态（转出/转入两侧的份额与金额为权威输入，两腿单价由金额 ÷ 份额反算、只读展示），不做基金/非基金分流；**界面无手工录入 / 编辑 / 软删入口**——「无现金腿」kind 只读呈现，列表 / 筛选 / 只读详情消费转换读投影命令 `get_transaction_convert`（两腿标的/份额/金额/手续费/结转成本全量），写入与纠错走 HTTP 契约（ADR-0106 决策 10 / #1048）；批量导入端点复用（`TransactionInput` 只增转入标的/转入份额/转出金额/转入金额四个可选字段，就地修改契约同样携带这四字段）。
  - **多端同步（issue #980 / ADR-0099 决策 6）**：转换作为语义命令重放——同步命令载荷新增可选成员 `ConvertCommandFields`（只增不改，旧载荷缺省即空）；**重放端本地重建 FIFO 快照**并落本端转出消耗记录，结转成本以源端携带值为权威比对基准（与本地重建合计不一致即显式失败挂起，不静默错账）。create / update / delete 三 op 均可重放且幂等（删除重放复用同一删除协议、不产本地 op）；依赖倒挂（买入 op 未达）以可卖出数量守卫挂起、补齐后重投递自然重试；旧版本设备产出的转换 op（只有行、无转换字段）与 schema 超前 op 均按挂起队列（ParkedOp）处理，各有码化原因（前端本地化），不静默错账。
- **别名**：不使用「基金互转」（易与转账混淆）、「换仓」（口语化、覆盖面窄）。

## 份额调整（Split）

- **定义**：同一投资账户内、**单标的**的非现金份额变动（ADR-0106），落账为核心交易域第 8 种 kind `split`：一笔一条记录，表达标的、**带符号份额增量 Δ** 与调整日；`+` = 份额折算 / 结转 / 送股，`−` = 缩股。与基金转换（Conversion）的分界：convert 是两标的互换（A → B），split 是单标的份额变多 / 变少。
- **边界**：
  - **零现金腿**：六度量系数全 0，落账前后全部账户余额（含黑洞）完全不变；`amount_cents` / `amount_native_cents` 恒为 0，不接受手续费 / 单价 / 转入标的 / 转入账户 / 出资账户 / 商户 / 分类 / 保单。注意：**持仓市值、未实现盈亏与净资产会随份额变化**（份额变了），余额不变只是「无现金腿」的弱表述。
  - **输入语义是绝对增量 Δ**（不是换算比例 f），按**落账时的在用持仓**锚定 `f = (当前持仓 + Δ) / 当前持仓`（写入序作用于落账那一刻的在用批次，FIFO 按插入序；`date` 只承担展示与时点持仓前缀求和）。
  - **成本口径 = 按比例重述在用批次**（ADR-0106 决策 2，否决「新开 0 成本批次」）：逐批 `remaining_quantity × f`、`initial_quantity × f`、`cost_per_unit_cents ÷ f`，**批次总成本精确不变**，舍入尾差归**末批次**闭合（沿用转换的「尾差末腿」纪律）。重述**不可逆**（含舍入）。
  - **存储与审计**：复用 `security_transactions` 既有列（`quantity` = Δ、`price_cents` 留 NULL），逐批次 before / after 重述落 `security_lot_adjustments`（角色对齐 `security_lot_conversions`）——它是 `revert` 精确回补与审计的**唯一依据**。既有闭合机制随之校准：历史消耗回算改读 `security_lot_sales` / `security_lot_conversions` 行里**记录时**的消耗成本（无 split 行时与既有口径恒等）。
  - **守卫（收口在投资域模块，码与文案随守卫知识单点）**：Δ ≠ 0；`Δ > 0` 须有在用持仓（零持仓无从重述）；`Δ < 0` 缩股幅度取严 `|Δ| < 当前持仓`（等号会让 f = 0、成本凭空消失；判定按份额容差口径，见份额容差（QuantityTolerance））；账户必须为投资账户，标的类型不限（基金/股票同构）。进/出 `split` 的 kind 变更一律拒绝，纠错只有「软删 + 重建」一条窄路；本行重述过的批次被**在用**下游消耗（后续 sell / convert / 后一次 split）时，本行不可改、不可删（谓词同 Unwind 的「在用占用」家族）。
  - **零盈亏与不变式**：split 对已实现盈亏贡献恒为 0；全平仓恒等式 `Σ已实现 = Σ卖出 − Σ买入 − Σ转换结转成本` 不引入新项。
  - **推算与视图**：时点持仓推算纳入 split 腿（`+Δ`）；组合走势、净资产、可投资资产与持仓标的谓词随之自动跟随；持仓视图冻结不动、批次驱动自动跟随。
  - **界面与契约**：无创建 / 编辑 / 软删操作入口，只读呈现（列表 / 筛选 / 只读详情）；筛选闭集保留 `split`；写入与纠错走 HTTP 契约（AI / 迁移侧），导入知识投资节（分域知识节，经 `GET /api/v1/import/knowledge/investment` 获取，ADR-0110）中的份额调整教学是写入面的一等交付物。
  - **多端同步（issue #1053 / ADR-0106 决策 9）**：split 作为语义命令重放——同步命令载荷新增可选成员 `SplitCommandFields`（只增不改，旧载荷缺省即空），携带 Δ 与源端**最终持仓 / 批次总成本**两个比对锚点（**不携带逐批次重述结果**：重述是「当前批次快照 + Δ」的纯函数）；重放端以本地 FIFO 快照独立重建重述，两个总量与源端携带值不一致即本地快照发散，码化挂起（`transaction.split-restatement-mismatch` / 零持仓 `trade.split-no-holding`），不静默错账。create / update / delete 三 op 均可重放且幂等（删除重放复用同一删除协议、按本地重述审计精确回补、不产本地 op）；依赖倒挂（买入 op 未达）以零持仓守卫挂起、补齐后重投递自然重试；旧版本设备产出的 split op（有行、无份额调整字段）与 schema 超前 op 均按挂起队列（ParkedOp）处理，各有码化原因。
- **别名**：不使用「拆股 / 送股」（只覆盖 `+` 方向、漏缩股）、「分红」（现金分红是独立概念，见现金分红（Dividend），与本概念无关）。

## 现金分红（Dividend）

- **定义**：**归属于某标的**的现金收入（ADR-0109 / issue #1078），落账为核心交易域 `dividend` kind 的交易行 + `security_transactions` 的 dividend 扩展行（`quantity` / `price_cents` 恒 NULL）；股息、基金分红、投顾组合分红统一同构，不按来源分家。与份额调整（Split）的分界：split 改份额、无现金；dividend 只有现金腿、不改份额。
- **边界**：
  - **现金腿记到账账户**：`amount_cents` = 分红金额（> 0），按核心交易域金额度量矩阵入账（account_flow + / income_net +，见 Transaction Kind Mapping）——分红计收入，不进支出报表。到账账户是**任意在用账户**（银行卡 / 现金 / 投资账户皆可，不限于投资账户），币种须与账户币种一致。
  - **不摊薄成本、零已实现盈亏**：不触碰 FIFO 批次、不写卖出匹配、不改变持仓数量与每份成本——分红是累计收益（CumulativePnl）的第三腿，不是第三种成本法。
  - **不要求当前有持仓**：除息 / 到账时间错位合法（已清仓标的收到尾款分红照常可记），标的只需存在。
  - **守卫（收口在投资域模块，全部码化中文错误）**：标的必填且存在；金额 > 0；到账账户在用且币种一致；不接受份额 / 单价 / 手续费 / 转入标的 / 转入账户 / 出资账户 / 商户 / 分类 / 保单。进 / 出 `dividend` 的 kind 变更一律拒绝（纠错只有「软删 + 重建」一条路），但 dividend 行本身可就地修改（全字段替换，扩展行摘除后重建）。
  - **多币种与软删口径与既有两腿对齐**：分红腿按交易行币种（= 到账账户币种）分组，不跨币种折算；软删账户与软删分红流水排除，隐藏账户照常计入。
  - **界面与契约**：无创建 / 编辑 / 软删操作入口，只读呈现（列表 / 筛选 / 只读详情）；写入与纠错走 HTTP 契约（AI 导入 / 迁移侧），契约教学见 AI 导入域。
  - **多端同步**：作为语义命令重放，复用核心交易域 TransactionCommand 既有投资字段成员（只携标的 id，现金腿随归一化行），create / update / delete 三 op 均可重放且幂等；扩展行自包含、无 FIFO 重建；标的不在时挂起（ParkedOp）、依赖补齐后重投递自然重试。
  - **红利再投（DRIP）不在本概念内**：DRIP 是「现金分红 + 再买入」两步的合成动作，由红利再投（DividendReinvestment）词条以两笔既有 kind 表达（其中的分红腿到账账户即投资账户）；本词条只承载其中的现金分红一腿——分红腿不因再投而重复计算。
  - **归属标的可以是自建标的**：迁移来源的货基 / 现金钱包按年收益同样以 dividend 落账，其归属标的可能是无真实代码、无持仓、无价格的自建标的——收益以**现金腿**体现、不以份额结转体现。这与价格恒定标的（ADR-0126）的「收益以份额结转体现」不冲突：后者说的是真实货基标的的单位净值口径，而这类按年收益行既不是货基标的、也不进价格链路（收益是已到手的现金，不是持仓市值增长）。
- **别名**：不使用「红利」（口语、易与红利再投混淆）、「派息」（偏债券票息场景）；统一用「现金分红」，简称「分红」。

## 红利再投（DividendReinvestment）

- **定义**：把现金分红按除息后净值再买入同一标的的处置方式——份额增加、成本增加、投资账户现金净额为零、外部资金分文不动（grilling 定稿，2026-09-12；2026-09-13 修订为投资账户内两笔，原黑洞两笔形态废止，动因与取舍见 ADR-0109 修订记录）。
- **边界**：
  - **由两条既有 kind 组合表达，不新增 kind**：一条现金分红（到账账户 = 投资账户）＋一条 0 手续费买入（不传出资账户；结算账户归因见核心交易域出资账户）。份额与成本与普通买入同构，唯一的差异是「钱从哪来」，那是出资账户的职责而非 kind 的职责——只改份额（份额调整）与只进现金（现金分红）各自都不成立，组合起来才完整。
  - **两腿在投资账户内自相抵**：分红腿到账 +X、买入腿出资 −X 落在同一投资账户，账户现金净额为零、外部资金分文不动；黑洞账户不是本词条的端点，投资账户流水里同日可见这对 +X / −X（净 0，账户余额不受影响）。
  - **分红腿计入收入、不摊薄成本**：再投的分红仍按 kind→度量矩阵计入收入，买入腿不进支出报表；再投买入按 0 手续费普通买入建批次，成本含再投金额，累计收益（CumulativePnl）三腿恒等式不变。
  - **与黑洞两笔形态的输出口径一致**：全部账户净额 / 收入 / 支出 / 持仓 / 成本 / 累计收益三腿均与旧形态相同，变化只在分红腿与买入腿的账户端点。
- **别名**：不使用「红利再投资」（口语变体，同义）；「现金分红」特指不买入份额的那个 kind，见现金分红（Dividend）。

## TransactionTrade（交易买卖明细）

- **定义**：一笔 buy/sell 核心交易域 Transaction 在投资域扩展表中的投影——标的、数量、单价、手续费，物理实现在 `security_transactions` 扩展表（按交易 id 关联交易行）。
- **边界**：
  - **核心交易行不含投资字段**（ADR-0003 核心表 + 扩展表）：买入/卖出编辑（issue #180）回填标的/数量/价格/费用须经只读命令读取本投影，不把投资字段塞进核心 `Transaction` 模型。
  - **投影随读带出标的代码与名称，供回填后标的选择框直接显示标的而非裸 id**；并带出标的类型，驱动表单录入形态切换（基金 = 金额 + 份额必填，其余 = 数量 + 单价，issue #302）。
  - 无明细（交易不存在/非 buy/sell）显式报「无买卖明细」。
  - **回填 ≠ 可改金额**：编辑提交走编排入口的全字段替换权威（与 HTTP 修改端点同源），明细投影只读；金额/单价的权威归属随标的类型（见 Investment）——非基金金额由 prepare 按数量×单价±手续费重算，基金金额照抄确认单、单价反算。
- **别名**：不使用“成交记录”（易与交易所对账单混淆）、“投资交易详情”。

## TransactionConvert（交易转换明细）

- **定义**：一笔 convert 核心交易域 Transaction 在投资域扩展表中的投影——转出标的/份额/转出金额与转入标的/份额/转入金额、手续费与结转成本（行金额锚点），物理实现即 `security_transactions` 的 convert 行（两腿同记录）。
- **边界**：
  - **两个读投影面，各按消费方需要**：列表/搜索读路径在核心 `Transaction` 行的 `convert` 扩展上带出转入标的 id/代码、转入份额、两侧确认金额（移动卡片「A → B」与金额列展示转出金额的数据面）；只读详情消费只读命令 `get_transaction_convert`，另带出两腿标的代码/名称与结转成本（ADR-0106 决策 10 / #1048）。
  - **行金额锚点 = 结转成本不是确认单金额**：展示金额必须读本投影的转出金额（ADR-0099），不得读 `amount_native_cents`。
  - 无明细（交易不存在/非 convert）显式报「无转换明细」。
  - **编辑提交走编排入口的全字段替换权威**（与 HTTP 修改端点同源），投影只读；kind 不得改为/改出 convert。
- **别名**：不使用「转换记录」（易与交易行本身混淆）。

## InvestedInstrument（持仓标的）

- **定义**：有**当前持仓**（持仓批次仍有剩余数量，即 `v_holdings` 视图有行、且排除软删除账户的批次）的 Instrument，即“已投资”标的（ADR-0015）。
- **边界**：
  - 判定谓词单点定义（投资域薄模块内的存在性谓词，issue #239），同一口径驱动多处：标的列表的持仓派生标记、标的页「只看持仓」过滤、持仓页签概览（issue #102/#103/#110/#902；#902 起持仓概览自盈亏页迁为投资页独立持仓页签，消费处表述随之更新），以及价格过期提示的「持仓缺现价」判定（issue #1190）。原消费处「增量同步的标的收集与统计」自 #827 起随同步覆盖面放开至全库退役，不再消费本谓词。**本清单只列消费面、不写处数**——消费处随功能增减，写死数字必漂移（先例：本清单自 #1190 起去掉「三处」计数）。
  - **与 `v_holdings` 视图的一致性由绑定测试钉住**：视图定义随发布冻结、是只读对账基准；两份 SQL 编码的一致性由投资域单测断言逐标的相等（先例：周键 ↔ week_start 生成列绑定测试，issue #239）。
  - **不含已清仓标的**：已清仓的得失由已实现盈亏（RealizedPnl）承载，不混入“已投资”。
- **别名**：不使用"已投过的标的"（含已清仓）、"自选/关注标的"（那是用户主观收藏，与持仓无关）。

## 已实现盈亏（RealizedPnl）

- **定义**：已平仓卖出匹配的「卖出所得 − 对应批次成本」实现值——盈亏页「已实现盈亏」列的得失口径，数据源为卖出匹配记录（security_lot_sales）的逐匹配盈亏列，按年/按账户两个汇总视图同源同过滤口径。
- **边界**：
  - **只算已实现**：逐匹配结算（收入分摊、成本按批次锚定），与未实现盈亏（Holding 的现价浮盈亏，见 Holding）分界——未平仓浮盈不进本口径。
  - **是「已实现收益」的一腿、不含分红**：现金分红不摊薄成本、也不进本口径（ADR-0109 决策 2），故本口径恒等于卖出匹配盈亏；盈亏页「已实现收益」列的主值 = 本口径 + 现金分红（见已实现收益（RealizedGain）），本口径在同一单元格的副行里单列——是拆解，不是替代。
  - **账户筛选限定投资账户**：盈亏页账户下拉与投资录入表单消费同一「投资账户」谓词（type = investment 的账户），非投资账户不进选项面；buy/sell 写入守卫（必须使用投资账户）已保证盈亏数据只落在投资账户上，下拉收口是选项语义而非第二道数据防线。**隐藏投资账户不排除**——隐藏 ≠ 软删，与 Holding / 时点持仓口径一致（issue #217 定案 Q2）。
  - **软删账户与软删交易不进汇总**（issue #217 定案「删除账户 = 从全部投资视角消失」的落实）：软删账户的匹配行、软删 sell 的匹配行一律被查询口径排除。删除路径的清理语义已随 ADR-0097 修订——sell 删除即回补持仓并清空其匹配行（ADR-0013 旧「sell 删除不清理」废止），正常删除不再产生已删 sell 的匹配；读口径排除仍保留，覆盖旧版本遗留的存量幽灵匹配（指向已软删 sell、未随批次清理的行，用户删除/修改对应买入时自愈，issue #940）。
  - **逐匹配明细视图已退役（ADR-0107）**：原「卖出明细」卡（逐匹配行：卖出日期/账户/标的/数量/成本单价/逐匹配盈亏）退役——它与交易页 sell 流水行高度同构，卡名曾两轮被误读为交易冗余（命名与内容物错位）；逐匹配的成本批次与盈亏不再有逐笔可见处，由汇总视图兜底（交易页 sell 行不补盈亏列，翻案须修订 ADR-0107）。查看某标的的卖出流水走持仓下钻（见界面状态与交互域）。
  - **总盈亏卡与按标的汇总已退役（ADR-0107 修订注记，2026-09-13）**：盈亏页收敛为 筛选 + 按年/按账户两表——「已实现盈亏概览」卡（总已实现盈亏）的总口径在持仓页签合计（累计收益含本腿）可得，「按标的汇总」表的按标的信息在交易页标的筛选下钻可得。**本表退役即已清仓标的的卖出流水不再有 UI 入口**（它是当时的唯一入口，翻案代价显式接受）；后端 `realized_pnl_summary` 的 `total` / `by_instrument` 读取保留，只减 UI 面。
  - **汇总按币种分组（ADR-0107）**：汇总表按匹配行币种分组展示（与持仓页签市值/未实现盈亏合计的按币种分组同款口径，issue #902 形态先例），不做跨币种折算——原「各币种裸数字直接 SUM」的混算口径废止（多币种账户下合计是错的）；盈亏的本位币折算需交易时点汇率，与 FxRateHistory 既有边界纠缠，MVP 不做。
  - **是累计收益的已实现一腿**：与 Holding 的未实现盈亏、现金分红（Dividend）的累计分红三腿相加即累计收益（见累计收益），本词条只供已实现一腿、自身不做跨币种折算。
- **别名**：不使用「平仓盈亏」「实现收益」；单说「盈亏」时以页面语境区分未实现（Holding）与已实现（本词条）。逐匹配明细行不称「交易明细」（它是卖出匹配记录的投影，不是流水行——卡名「卖出明细」的误导已随退役消亡）。

## 已实现收益（RealizedGain）

- **定义**：盈亏页「已到手多少」的口径 = 已实现盈亏（RealizedPnl）+ 现金分红（Dividend）——只含已落袋的卖出得失与标的现金收入，不含浮动盈亏（ADR-0129）。
- **边界**：
  - **是展示合成，不是第三种计算**：两腿各自定义不变——已实现盈亏仍是 FIFO 卖出匹配（ADR-0107）、现金分红仍是标的的现金收入且不摊薄成本（ADR-0109 决策 2）；本口径只做相加，不写回任何一腿、不改写持仓与批次。
  - **三层阶梯**：已实现盈亏 ⊂ 已实现收益 ⊂ 累计收益（CumulativePnl）——累计收益在本口径之上再加未实现盈亏（Holding）。三个词不可互换：盈亏页两表新增列的主值是本口径，持仓页签的合计是累计收益，两者之差恰是浮动盈亏那一腿。
  - **不含浮动盈亏是本列的口径本身，不是外部约束**：本列答「已到手多少」，浮动盈亏不在其内；按年表的完整年度收益由「年度收益」列承载（未实现变动腿随 #1534 价格历史覆盖持仓期后落地，ADR-0132），本列读数不因之改变。
  - **含红利再投的分红腿**：红利再投（DividendReinvestment）落下的分红行计入本口径（与累计收益第三腿同源）；本页不展示未实现腿，故再投年份的合计含那笔未落袋现金，可能高于当年真正到手的现金——再投买入抬高的是持仓成本，由未实现腿承接。
  - **分红腿含迁移来源的货基按年收益**：归属标的可能是自建标的（见现金分红（Dividend）），本口径不按标的来源或 kind 细分。
  - **多币种与软删口径随两腿**：按币种分组、不跨币种折算；软删账户与软删流水排除、隐藏账户照常计入。
- **别名**：不使用「到手收益」「落袋收益」「总收益」（均为叙述性、不可复用，且「总收益」与累计收益冲突）；不简称「收益」（过泛——与「持仓收益」「累计收益」并列时不可辨，ADR-0129 的命名代价即为此）。

## 年度收益（AnnualReturn）

- **定义**：盈亏页按年表「这一年赚了多少」的完整口径（ADR-0132 / issue #1535）= 年内已实现盈亏 + 年内现金分红 + 年内未实现变动（年末未实现盈亏 − 年初未实现盈亏），与第三方平台（且慢等）的年度收益可对照。实现采用等价现金流式：`年度收益 = (期末持仓市值 − 期初持仓市值) + 年内卖出净收入 + 年内现金分红 − 年内买入支出`。
- **边界**：
  - **三腿相加，不是第四种成本法**：已实现与分红两腿逐位复用已实现收益（RealizedGain）的既有口径；未实现变动由恒等式导出（年度收益 − 已实现 − 分红），估值齐全时与「年末未实现盈亏 − 年初未实现盈亏」逐位相等——FIFO 已实现与批次成本共用同一锚点，现金流式与三腿定义式可代数互导。
  - **边界时点与市值**：期初 = 上一年 12-31、期末 = 当年 12-31（当年未完即取到最新）；市值 = 时点持仓 × ≤ 该日最近周采样价 × 同期汇率（周键正反向兜底，与资金加权收益率边界市值同一历史折算纪律）。年内新开仓 / 清仓按期初或期末市值为 0 自然处理；基金转换（Conversion）无现金腿、市值连续，份额调整（Split）不产生现金——两者不入现金流、公式天然覆盖。
  - **年内买入支出含期初存量补记行**：buy 行金额合计（含费用）按字面执行——补记行不入支出会把整笔存量市值虚计为补记年的年度收益；未实现变动因此取「自补记日起算」的语义（与期初存量的既有处理同源不同形：资金加权收益率折市值、本口径计成本）。
  - **空值语义：不可算显式化**：年初或年末仍有持仓而市值缺料（缺价或缺同期汇率）→ 该年未实现变动与年度收益为空值，前端标「无法计算」，不以 0 计、不静默跳过该标的继续合计；期初或期末持仓为零则无需估值、无价也可算（年内全平仓年份不依赖任何价格）。已实现与分红两腿不受行情影响，不可算年份照常出数。
  - **按币种分组、不跨币种折算**（沿用 ADR-0107 决策 6 的分组口径；组币种 = 账户币种，与匹配行 / 分红行币种同源）：边界市值折到账户币后入组；账户 / 标的筛选对市值腿与既有两腿同源同过滤（筛到缺价标的即不可算，筛掉则不受影响）。
  - **行集不变（只加列不加行）**：仍只有「有卖出或分红」的年份成行（#1533 纪律）；只有买入 / 转换 / 份额调整的年份不出现，扩行集属后续议题；按账户表不加列（账户粒度年度收益另票裁决）。
  - **与累计收益的分界**：累计收益（CumulativePnl）是**至今**的三腿合计（当前未实现盈亏 + 全部已实现 + 全部分红，持仓口径）；年度收益是**逐年**的三腿合计，未实现腿一为存量、一为增量。
  - **命名投影（术语 ↔ 代码）**：读投影随 `realized_pnl_summary` 按年行携带（`unrealized_change_cents` / `annual_return_cents`，空值 = 不可算）；命令名与前端数据接缝不变。
- **别名**：不使用「年化收益」（年化是收益率口径，见资金加权收益率）、「本年收益」（不限定年份）、「总收益」（与累计收益冲突）；「完整年度收益」是叙述语，词条名为「年度收益」。

## 累计收益（CumulativePnl）

- **定义**：单笔持仓、单个投资账户或整个账本的投资总得失的展示口径 = 未实现盈亏（Holding）+ 已实现盈亏（RealizedPnl）+ 累计分红（现金分红（Dividend）），用于与第三方基金平台（且慢等）的「累计收益」对照（展示落地见 issue #1077；分红腿随 ADR-0109 / issue #1078 落地）。
- **边界**：
  - **是三腿相加，不是第三种计算**：未实现与已实现两腿共用同一 FIFO 批次成本（买入手续费摊薄进批次成本、卖出手续费在已实现腿扣除），相加后自动扣净全部费用；分红腿是标的的现金收入、**不摊薄成本**（见现金分红（Dividend）），只按自身现金流量计入。三腿相加恒等于「当前市值 + 累计卖出净收入 − 累计买入总支出 + 累计分红」的现金流口径；不引入第三套成本法。
  - **与「已实现收益」的分界是一整条未实现腿**：累计收益 = 已实现收益（已实现盈亏 + 现金分红，见已实现收益（RealizedGain））+ 未实现盈亏（Holding）——盈亏页两表新增列的主值是不含浮动盈亏的前者，持仓页签合计是后者；两个数不等是口径不同，不是缺陷。
  - **按币种分组、不跨币种折算**：与 ADR-0107 决策 6 及持仓页签合计同款口径；buy/sell 与 dividend 的记录币种恒为账户币，三腿同币可直接相加，多币种账户各成一组；跨币种折本位币需交易时点汇率，MVP 不做。
  - **空值语义采 Holding 侧**：缺价 / 缺汇率的持仓其未实现腿为空值，不计入且不以零计入（与持仓/净资产合计一致的「跳过空值」语义）；已实现腿来自平仓匹配、分红腿来自分红流水，均不受当前有无行情影响；某币种三腿皆空时不出现该分组（由展示层渲染为空态）。
  - **刻意不采用且慢的摊薄成本法（grill-with-docs 产品裁决 2026-09-11）**：摊薄成本（(累计买入 − 累计卖出) ÷ 当前份额）下「持仓收益」恒等于「累计收益」——用户能同时看到两个不同的数，即证明且慢未用摊薄法，故 Ledger 未实现盈亏（FIFO）与之的差异只可能来自成本法（FIFO vs 加权平均）、分红与净值时点，不来自 Ledger 少算。FIFO 批次成本是已实现盈亏、基金转换结转成本（Conversion）与份额调整重述共同的审计锚点，为贴且慢而改成本法会连带推翻一串既有裁决，故不做。
  - **展示词**：与「持仓收益」（Holding 未实现盈亏的展示词，见 Holding）同批引入，共同服务于与且慢的对照；账务口径词不变。
  - 不落库、实时派生（同 Holding 与 RealizedPnl）。
- **别名**：不使用「总收益」（易与走势/收益率口径混淆）；不简称「盈亏」（沿用词表既有口径——单说「盈亏」时以页面语境区分未实现与已实现）；不以「已实现收益」代指本词条（前者少一整条未实现腿）。

## 资金加权收益率（MoneyWeightedReturn）

- **定义**：投资粒度的**年化**内部收益率（实际天数 / 365），由实际现金流与期末市值解出——回答「我的钱实际赚了多少」，是账本唯一的年化收益率口径（ADR-0115）。**仅期初存量、无真实流水的持仓不给年化**（真实建仓时点未知，年化没有输入），同投影另出一档**未年化**收益率（累计收益 ÷ 累计投入），两者并列展示、不可互算（ADR-0115 修订 / issue #1343）；存量持仓在有了真实流水后年化恢复，起算点顺延到首笔真实流水（issue #1345）；含仅存量对的合集（账户级 / 全账级）整项降级给未年化（issue #1346，触发随 #1345 收窄）。
- **边界**：
  - **现金流**：买入为负（确认金额含手续费）、卖出为正（净额）、现金分红为正、份额调整为现金流零贡献；基金转换在单标的粒度按转出批次的结转成本拆成正负两条（转出腿为正、转入腿为负），账户级与全账级不额外引入（零现金腿天然无影响）。**期初存量行不入本集合**——它不是外部投入（见投资域期初存量）；存量 + 真实流水的持仓，其期初投入由首笔真实流水日的市值折算补入（issue #1345）。
  - **归因端点与出资账户口径一致（ADR-0096 结算账户语义）**：流水归属交易行的投资账户（buy/sell 的 `account_id` 恒为投资账户，出资账户只改结算端点不改归属行）；分红行归属到账账户。红利再投（DRIP）两腿（dividend 到账投资账户 + 0 手续费 buy 自同一投资账户出资）同日同额反号、在账户内自相抵，不构成外部投入。到账账户为非投资账户的分红按现金归因进入全账级合计（投资收益已落袋），不进任何投资账户的账户级行。
  - **期间**：默认自首笔流水起算，支持区间选择；区间开始时的存量持仓按**区间首日市值**折为一笔期初投入，区间结束的存量持仓按区间末日市值折为期末现金流——边界市值 = 时点存量数量 × ≤ 该日最新周线价格 × 同期汇率（周键正反向兜底，与组合走势同一历史折算纪律）；它是收益率的输入假设，不改账务、不构成第二套持仓口径。
  - **空值与币种**：缺价或缺汇率的持仓跳过、不计入（沿用 Holding 空值语义），其现金流也不计入所属账户与全账合计；按币种分组、不跨币种折算（与已实现盈亏、累计收益同口径）。
  - **仅存量无流水即不给年化，存量 + 真实流水年化恢复（issue #1345）**：仅含期初存量、无真实流水的持仓，年化输出「不适用」，改给未年化收益率 = 累计收益 ÷ 累计投入（分子含已实现与分红）；存量持仓之后有了真实流水（再买 / 卖 / 分红），年化以**首笔真实流水**为起算点重新成立——期前存量按该日市值折为一笔期初投入（复用决策 3 机制），该日持仓变动流水由折算承载不入集（分红是仓位外现金、恒入集），折算是年化帧的市值锚、不进未年化口径的分子分母。**两种含存量形态都不施加区间边界**（#1343 纪律延续）：存量 + 真实流水对起算点恒为首笔真实流水、期末恒取现值，选不选区间同解。**账户级与全账级合集含仅存量对时整项降级为未年化**（issue #1346；触发随 #1345 收窄）：分子分母对全合集各自汇总后相除、随行标口径，不按口径拆两行（两口径不可互算，拆行会让年化行只覆盖真实成交残余、被误读为整个合集的表现）；存量 + 真实流水对年化恢复后随普通对入年化合集、不再触发降级；合集无仅存量对时年化逐位不变；缺价 / 缺汇率的标的仍整项跳过、不入任何口径的合计。
  - **粒度**：持仓页按单标的、盈亏页按账户与全账；与金额口径（Holding 未实现盈亏 / 累计收益）并列展示、互不换算。
  - **无解不给数**：现金流多次变号时可能无解或多解，此时显式标注无法计算，不猜解。
  - **刻意不采用简单累计口径作通用口径**（累计收益 ÷ 累计投入，第三方平台常见）：它忽略资金占用时间，不能当账本的通用收益率；只在**建仓时点未知的期初存量**上作为并列的第二口径启用（单标的行限仅存量、无真实流水持仓，#1345；账户级 / 全账级限含仅存量对的合集，#1346，分子分母覆盖合集内全部标的），且分子改用含已实现与分红的累计收益，补上该口径原有的缺口。也刻意不做时间加权（TWR）——它回答选品能力，且需要逐笔现金流时点的组合市值快照（ADR-0115 替代方案）。
  - **命名投影（术语 ↔ 代码）**：读命令 `money_weighted_return_summary`（一次请求同出三消费面）、结果类型 `MoneyWeightedReturnSummary`、前端数据接缝 `useMoneyWeightedReturn`——三名一物，不是两套概念（先例：价格过期提示）。
- **别名**：不使用「收益率」（过泛）、「年化收益」（易与金额口径混称）；「累计收益率」只指期初存量持仓的那档未年化口径，不用来泛指本词条。

## 期初存量（OpeningBalance）

- **定义**：账本里**没有真实建仓时点**的存量持仓——由补记（持仓初始化）落进来，只带平台的份额与持仓成本单价（ADR-0115 修订 / issue #1343）。
- **边界**：
  - **不是当日真实入金**：它不是补记那天发生的资金流入，只是「某时刻起就存在的存量」；当成 inflow 会把「成本 → 现值」的累计涨幅摊到 1 天年化（实测把 +3.16% 年化成 8,594,733.89%）。
  - **只在建仓（buy）上成立**：卖出 / 分红 / 转换 / 份额调整都没有这层语义，携带即被拒——它们描述的是有据可查的时点事件。
  - **年化起算点顺延（issue #1345）**：仅存量、无真实流水时年化没有输入，按投资域资金加权收益率词条给未年化收益率，其所在合集（账户级 / 全账级）也整项降级给未年化（issue #1346，触发随 #1345 收窄为仅存量对）；之后有了真实流水（再买 / 卖 / 分红），年化以首笔真实流水为起算点恢复，期前存量按该日市值折为一笔期初投入（折算是年化帧的市值锚，不进未年化口径的分子分母）。
  - **与「区间首日市值」正交**：后者是区间选择引入的输入假设（ADR-0115 决策 3），期初存量是持仓自身缺时点；未年化口径不施加区间边界。
  - **只影响收益率口径**：未实现盈亏、累计收益、已实现盈亏等金额口径逐位不变。
- **别名**：不使用「初始化持仓」（口语化）、「存量成本」（那是它的成本，不是它本身）。

## 自建标的（ManualInstrument）

- **定义**：来源为用户手动创建的 Instrument（字典来源标记 = 手动），与同步填充的股票类字典相对；典型如基金投顾组合（且慢「稳稳地幸福」）与非上市虚拟股（华为虚拟股票），均记类型「其他」——fund 类型语义归场外公募（ADR-0038）。
- **边界**：
  - **创建入口类型白名单为债券/ETF/其他三类**（fund 类型唯一创建入口 = 场外基金的按代码即拉，见 Instrument；白名单守卫属 UI 入口政策，AI 创建端点不受限）：与按代码创建的股票字典正交——既防同代码自建股票与查询/创建带回的权威行冲突，也防数据源侧另插同代码 stock 行造成重复标的（ADR-0036；原「全量同步仅修 stock 类字典」的机制已随 ADR-0081 决策 3 退役，issue #698）。**入口已收编**：独立手动创建弹窗退役，「自定义标的」是「添加投资标的」对话框的一级录入通道（issue #697 收编；#826 升为一级通道——选中即零网络请求展开建档表单；查询未命中不再兜底展开表单，只报错并引导切换本通道）。
  - 创建语义：名称必填（自建标的主身份是名称），代码自由文本（幂等键），币种可选；市场缺省未知，自定义标的通道建档恒落 unknown（#826：#697 兜底建档的市场透传随一级通道化退役——自定义标的无真实市场可查，不透传）；同（代码，类型）已存在则复用该标的并更新名称。
  - **删除**：仅自建标的可删，守卫为无任何证券流水引用（buy / sell / convert / split / dividend 五种 kind 的扩展行均计入），有引用拒删；同步标的不可删（字典修正由按代码查询/创建带回权威名称承担，ADR-0081）。不引入软删。
  - **分红以本域 `dividend` kind 承载**（ADR-0109 / issue #1078）：虚拟股与投顾组合的现金分红落一条 dividend 流水——归属该标的、现金腿入到账账户（可直达银行卡），计入累计收益第三腿（见现金分红（Dividend））；改变份额的公司行为（送股 / 转增）走份额调整（Split），不走本词条。
- **别名**：不使用"自选/关注标的"（用户主观收藏，与持仓无关，见 InvestedInstrument）、"手动标的"；「自定义标的」自 #826 起是「添加投资标的」对话框录入通道的专名（UI 通道标签，ADR-0081 决策 6），指称本概念本体仍用本词条名。

## 手动报价（ManualPrice）

- **定义**：用户手动录入的价格点（日期 + 单价），无行情数据源标的（典型为自建标的）的唯一价格来源——与行情同步（自动采集）并列的第二条价格写入通道。
- **边界**：
  - 单点录入，一条通道两个落点：现价缓存 upsert + PriceHistory 周采样幂等覆盖（同周后写覆盖先写，与同步同规则）；不另立手动价格承载。
  - **现价 = 最新历史点的即时映像**（MarketPrice 既有定义的推论）：回填早于最新点的旧价只沉淀历史，不改变现价。
  - **录价入口只对手动报价通道的标的开放**（判定消费价格通道派生事实，见价格通道；自建标的与名称充代码的基金行；真实代码基金与股票的现价归同步通道，开放录价只会被下次同步冲掉）；判定口径与增量同步「净值可拉」分区同源（ADR-0036/0038）。
  - 实际写入（任一落点）即发价格失效信号（见价格失效信号，生产者第三处，ADR-0036）。
  - 且慢组合单位净值、华为每股公允价等在 Ledger 统一为标的「价格」（市值 = 数量 × 价格），不因来源不同引入「净值」语义。
- **别名**：不使用"净值"（平台语境概念，Ledger 统一为价格）、"自定义价格"、"补录价格"。

## 行情接入（QuoteAdoption）

- **定义**：按代码从行情数据源取报价并把标的接入账本的接缝——「按代码查询主干道」（见 Instrument，ADR-0081）在**新增标的路径**上的接缝化命名（ADR-0103）：基金与股票（含场内 ETF）是接缝背后的两个通道，形状进接缝、差异进通道。
- **边界**：
  - **两成员**：查询半边（按代码取行情，纯取数不落库）与落库半边（**建档 + 落现价一体**，见 Instrument 幂等建行与 MarketPrice）。两成员可分别调用，承载三类既有消费编排：添加基金一枪式（查询即落库）、添加投资标的两段式（查询回显、确认后落库，见 Instrument 录入通道）、AI 创建增强直调落库半边（见 AI 导入域 AI API）；纯查询消费（标的查询端点）只调查询半边。
  - **统一报价载荷**：基金与股票的行情投影同形——代码、权威名称、价格与价格日期为公共成员；市场、类型提示、基金分类、净值日期等通道差异以可缺省成员承载（ADR-0103；基金分类自换源起恒缺省——替代源无分类来源，契约字段保留空串并标注弃用，不用名称关键词推导，ADR-0130 决策 8）。查询未命中的错误语义各通道单点（基金查无此码、股票查无此码判定，见 ADR-0081），不并入接缝。**基金查询半边内含三段判定**（新浪批量面为主源、证监会基金电子披露为权威兜底与判定源，ADR-0130 决策 2；ADR-0039 修订的判据形状不变，2026-09-13）：批量面普通行一次给出名称与最新单位净值（在用与已终止普通基金都在面）；产不出价格点的货基错位行（万份收益占单位净值位）经披露自报形态确认落恒定价（见价格恒定标的）；批量面未收录的代码经披露区间查询改判存在性。**「查无此码」的唯一结论来源是披露区间查询的可信空报文**——批量面空值只说明「此面未收录」，披露源不可信按 fail-closed 上抛、不降级为查无此码。**股票查询半边走腾讯行情单只查询**（ADR-0130 决策 2/4；美股三市场候选遍历退役——美股走聚合路由单查询，精确交易所归属由响应自报），命中判定 = 响应回显代码与请求归一化代码全等。
  - **界外通道**：手动报价（无查询步骤、带最新点映像规则，见手动报价）与标的信息同步（批量编排 + 水位增量，见 InstrumentInfoSync）**不在接缝内**——接缝语义收窄为「按代码从数据源取行情 → 建档 → 落价」的新增标的路径；三条价格写入路径共用**价格写入单点**——现价缓存落库的全域唯一入口，现价时点口径、净值水位、最新点映像等通道语义留在各自通道（ADR-0103）。
  - **无 Rust trait 承载**：接缝由统一形状与命名承载而非接口类型——多态分派无消费者，机制税不付（ADR-0103；与 Investment 词条「不引入注册表机制」同一口味）。
  - **纯重构命名**：接缝不引入新行为——IPC/HTTP 契约、错误码、schema 零变化。
- **别名**：不使用「QuoteLookup」（只锚定查询半边，落库半边名不副实，grilling 裁决弃用）；不使用「行情接口」（接口暗示 trait 承载，与本接缝形态不符）。

## 行情批量取数（BulkQuoteFetch）

- **定义**：一次请求覆盖一批标的的取数方式（相对「每标的一次请求」的逐标的取数），用来刷新标的现价；回答的是「这次刷新用几次请求」，不回答「价格从哪条通道写入」。
- **边界**：
  - **不是价格来源**：取数方式不改变来源归属——价格通道的五值闭集与来源标记不动，标的列表的「价格来源」列不因取数面而变。
  - **只服务现价刷新**：名称随行刷新与场外基金净值刷新都走本面；价格历史的采集不经本面（见价格历史后台补全）。场内行情通道的报价本就是批量面，它的逐标的请求在解耦后只剩补历史一个理由。
  - **命中即落库**：批量面报出的最新单位净值（场内通道为最新价）即当日现价，**已有历史序列**的标的连当周采样点一并落库（ADR-0122 决策 2 的落库面；无历史序列者不落单点——单点会让「有历史序列」冒充「历史完整」，破坏首刷判据，历史归后台补全整根回填）——命中即零逐只请求；现价刷新的逐只短窗只在水位落后批量面最新净值所在自然周超过一周（缺周点补齐，水位缺失或不可解析时保守接管）与本面未覆盖（缺口）两种情形接管，只拿最新净值不采历史；首刷与深回填（覆盖不足补齐，#1534）都由价格历史后台补全逐只承担。
  - **降级闭集（ADR-0121）**：批量取数失败一律 fail-closed 回退逐标的取数；失败在本次同步内熔断（一次失败即全程走逐标的），连续失败跨同步记忆、限期停用后再半开。降级对用户可见，不静默变慢。
  - **覆盖缺口是常态**：本面按代码批量取数，不承诺覆盖全部基金（新成立未收录的不在其列；在用与已终止普通基金实测都在面）；缺失按条回退逐标的面补齐——缺口不是失败，不触发熔断，也不据此判定标的无数据。**货基在面但无价格点**（错位行：万份收益占单位净值位，ADR-0130 决策 6）——名称照常入名称字典，价格侧落逐只通道经官方披露判定门收尾；旧「排行面无货币型」的结构性缺口随换源消失（ADR-0126 修订注记），已打标的恒定标的不进任何通道（见价格恒定标的）。
  - **按链路单一源，不做多源分流**（ADR-0130 决策 2/9，取代 ADR-0121「整体单一源」的否决段）：场内报价一个源（腾讯）、场外基金净值一个源（新浪）——每条链路内不做源间分流与互备；「不做可插拔数据源抽象」保留（ADR-0103 / ADR-0121 / ADR-0130 同一口味，多源由统一形状与命名承载，不付 trait 与注册表税）。
- **命名投影（术语 ↔ 代码）**：代码侧同一概念的落点是行情同步域的批量取数面模块——取数面束 `BulkFetchSurfaces`、跨同步记忆 `BulkFetchCircuit`、批量面条目 `BulkNavPoint`（ADR-0121 决策 3/5 的参数常量同址）。术语说的是「取数面」（一次请求覆盖一批标的），代码名按该面自身的形态命名，两者一物一名不重起概念。
- **别名**：不使用「行情来源」（那是价格通道的语义，本词条恰恰不是来源归属）、不使用「批量接口」（接口形态是实现细节，本词条说的是取数面归属）。

## 价格刻度（PriceScale）

- **定义**：全投资域价格数值的统一刻度——**万分之一元**（0.0001 元）为最小单位。
- **边界**：
  - 覆盖全部价格语义列：现价缓存、价格历史、交易买卖明细的成交单价、持仓批次的每份成本；基金净值 4 位小数是其直接动因（ADR-0038）。
  - 列名沿用 `_cents` 历史名、刻度已就地重定义（BREAKING，ADR-0038）：读代码以本词条为准，勿按列名望文生义为「分」。
- **别名**：不使用"分"指代该刻度（历史语义残留，已失真）。

## InstrumentSync（标的全量同步，已退役）

- **定义**：曾经的用户手动触发、系统从东方财富 API 一次性全量拉取沪市/深市/港股股票标的信息（代码、名称、最新价）并 upsert 到标的字典与现价缓存的过程——ADR-0015 职责切分中的「全量修字典」一翼（ADR-0019 价格历史化）。
- **退役（ADR-0081 决策 3，issue #698）**：标的页入口、命令、进度/取消事件与前端组装整体删除——「按代码查询/创建带回权威名称」取代全量修字典（随用随修的个位数请求取代数百次请求的重链路，见 Instrument）。字典修正、价格刷新与历史沉淀分别由按代码查询/创建与标的信息同步（见 InstrumentInfoSync）承担，职责不再两翼并存。
- **别名**：不使用"同步价格"（偏持续同步）、"更新行情"（偏实时）。

## InstrumentInfoSync（标的信息同步）

- **定义**：用户手动触发或后台每日自动触发、单次收集**库内全部标的**（不再以「当前有持仓」为界，issue #827；前身为只收持仓标的的 HoldingPriceSync 持仓价格增量同步）后在后端按通道能力分区**刷新现价**：股票与场内 ETF 按市场与代码批量取最新价，场外基金类取最新公布单位净值（净值即价格，ADR-0038），统一 upsert 现价缓存，并有通道的行以数据源权威名称**随行刷新标的字典名称**。UI 文案为“同步标的信息”（ADR-0015 职责切分的「增量刷价格」一翼；「沉淀历史」一翼自 ADR-0122 起归价格历史后台补全；「全量修字典」一翼已随 ADR-0081 决策 3 退役，其「随用随修」口径自 #827 起扩为「随用随修 + 同步随行刷新」，ADR-0036/0081 修订）。
- **边界**：
  - **只管现价、不承担历史（ADR-0122）**：价格历史的近两年回填与持续累积归价格历史后台补全，本动作常态为秒级——原「分钟级等待」形态随现价与历史解耦退场（ADR-0019 的「采集单通道」表述由 ADR-0122 推翻）。
  - **取数面：批量为主、逐标的为降级（ADR-0121；成员随 ADR-0130 决策 2 换源）**：场外基金名称与净值同走新浪 `f_` 批量面（名称与净值一次请求同面返回，整次同步最多一次逻辑请求），场内报价走腾讯行情批量报价面（名称随响应携带、零额外请求）；批量失败 / 停用 / 未收录（缺口）fail-closed 回退逐标的通道（同步内熔断、跨同步轻度记忆、降级对用户可见，见行情批量取数）；取数方式不改变价格来源归属——价格通道五值闭集不动，来源标记按实际取数源记（ADR-0130 决策 7）。
  - **覆盖面（issue #827）**：收集口径从 InvestedInstrument 放开为库内全部标的、按通道能力分区——清仓标的同样刷新，纯建档未交易标的按同一规则刷新；**价格恒定标的不进收集**（ADR-0126：它的价格是已知常量，同步既修不了也不需要修），因此本动作的收集面、进度分母与缺口统计一并不含它；未打标的货基仍留在净值通道内、由逐只通道的官方披露判定门确认即打标（见价格恒定标的）；`INVESTED_EXISTS` 谓词不再服务收集，消费面只剩标的列表持仓派生标记、「只看持仓」过滤、持仓页签概览与价格过期提示的持仓缺现价判定（完整清单见 InvestedInstrument，不在此复述处数）。
  - 触发方式：手动触发（标的页“同步标的信息”按钮与持仓页签“当前持仓”卡右上角按钮——#902 起持仓入口随概览卡自盈亏页迁入持仓页签，两处共用同一 `useInstrumentInfoSync` 接缝、行为一致）+ **后台每日自动一次**（应用启动后延迟补跑一次、此后按自然日窗口；ADR-0122 起原「不做自动定时刷新」口径退场）。两形态同形、同取数面、共享额度让路，后台形态不占用「用户动作在途唯一」的槽位。投资页的价格过期提示只**导向**本两处手动入口，不自动触发（见价格过期提示）。
  - 按通道能力分区：**场内行情通道（stock|etf 且有市场+代码，issue #695）**——股票与场内 ETF 同走腾讯行情批量报价面，查询键按市场前缀构造（沪深港精确市场；美股聚合路由单查询，精确交易所归属由响应自报，ADR-0130 决策 2/4）（issue #695/#696 / ADR-0081）；**场外基金净值通道（ADR-0038）**——代码为 6 位数字的 fund 标的取最新公布**单位净值**并记录净值日期（现价语义 = 单位净值，净值日期兼任历史增量水位）；**无通道行自动跳过**——无行情类型（债券/其他）、名称充代码的基金行（无真实代码）与市场未知（无法构造行情查询）的行计入“跳过 M 只”统计提示，不报错；恒定价格标的同计入跳过统计（有通道但无需采集、不进收集面，见价格恒定标的）；跳过统计与标的收集出自同一次收集（后端分区，天然同源，issue #239）。
  - **名称随行刷新（issue #827；取数面随 ADR-0121 改写、随 ADR-0130 换源）**：有通道的行同步时以数据源权威名称覆盖标的行名称——场内通道随腾讯批量报价响应携带（零额外请求）；场外基金随新浪批量面与净值同面返回（一次请求同取名称与净值，不再每只有码基金一请求；货基错位行的名称照常在字典）。仅名称实际变化才落库；同码自建行名称被数据源覆盖为**已接受代价——产品裁决留痕**（ADR-0036 修订）。零名称变化不写库、不虚增 version。
  - **水位不新造**：现价缓存记录的净值日期兼任历史增量水位；增量窗口、首刷判据与「空响应 ≠ 无新净值」的语义归价格历史后台补全，本词条不复述。
- 停牌/无效价跳过、保留旧价（名称照常刷新），不中断同步；数据源返回空响应（全部代码无效）时优雅降级为空。单只的网络失败与股票通道一致——上抛中断同步；跳过统计只收「无法拉取」的行，不含网络失败。
  - 重复触发幂等：每标的现价覆盖更新（来源标记沿用数据源）；名称仅变化时写——均不产生重复/冗余数据。（当周采样点的整周覆盖幂等归 PriceHistory 与价格历史后台补全。）
  - 库内无任何标的时返回明确提示（“暂无标的可同步”）而非报错。
  - **同步全程可见（issue #897 / ADR-0095；页级明细随 ADR-0122 迁出、随逐只净值通道换源退役）**：同步编排中后端逐有通道标的发出**确定进度事件** `ledger:instrument-sync-progress`（带 payload `{ done, total }`，归 `ledger:*` 命名空间但**不是**价格失效信号——见价格失效信号）：分母为**需采集价格的通道标的数**（恒定价格标的不计，ADR-0126；跳过行不计入分母），收集完成立即发 `{ done: 0, total }`；批量取数面下一批标的由同一次请求完成，相应格数一次性推进，逐标的降级路径下则逐只推进；分母为 0（空库/全部无通道）不发任何进度事件。原基金首刷/深回填的可选**页级明细**（`fund`：基金代码 + 已完成页/总页数，issue #1061）随逐只翻页通道整体退役（issue #1571：逐只回退与历史回填同用新浪单只全历史面、一次请求整只历史，无翻页长等待）。前端 `useInstrumentInfoSync` 接缝订阅产出可观察进度（模块级共享，在途短路期间进度共享、同步全程唯一），两入口渲染同一份进度条（GlobalBusyBar 同款细条、蓝色区分 + 计数文案「同步标的信息 37/100」经 i18n），终态（成功/失败）收起清空、结果消息接棒；不做取消。
  - **同步期间读可用（issue #1276，ADR-0069 决策 4 修订）**：同步的分钟级网络等待全部发生在连接锁外，同步在途时全应用数据照常可读——持仓页签的持仓表与合计、标的页签的标的列表、走势页签的曲线，以及交易、预算等其它页面都按当前已提交数据正常出数；同步期间读到的同一张表允许新旧价格混排（与价格过期提示同一口径，不要求冻结点快照）；同步期间才首次打开投资页同样可见数据（不只剩进度条）；重复触发仍复用唯一在途同步（同步全程唯一的既有承诺不变）。本条是 ADR-0069 决策 4「网络往返不得进锁」纪律守门化后的用户可见面，由运行时持锁时长探针与同步在途读命令限时返回的集成测试守门。
  - **实际写入即发价格失效信号（ADR-0031；成败同判，issue #1277）**：实际写入价格**或**名称（`any_written`）时发出 `ledger:prices-changed`，各价格消费方由信号驱动重拉；接缝 `useInstrumentInfoSync` 的承诺是「同步全程可见、同步完成即通知失效」，调用方无需自行重拉。零写入不广播（空库/全部跳过/基金全部「已是最新」且名称无变化，以及失败且未写过）；分段形态逐段 autocommit（见「同步期间读可用」，issue #1276），中途失败的运行已落库的写入仍生效（失败 ≠ 未写过）——失败收尾同样按实际写入置脏并发信号，失败仍报错、界面照收尾裁决自动刷新一次。
  - **行情访问量（ADR-0121）**：批量取数面下请求量为常数级——名称与场外基金净值一次（新浪批量面一次请求同取，日常路径不依赖分页）、场内报价按批常数次（腾讯批量报价，批大小按实测可用量级取，见 ADR-0121 修订记录）；HTTP 层（主机池、重试、自适应限速）与价格换算由同步域网络层收口，与按代码查询通道共用。降级到逐标的通道时回到随标的数线性增长（每只一次请求），并以用户可见的降级标注解释变慢。
  - **后台每日形态的代码落点（ADR-0122 决策 3 / issue #1377）**：调度入口 `start_daily_price_refresh` 住行情同步域 `daily_refresh`（每车道一枚进程级守卫标志 + 本车道轮次编排与统计日志；接线在壳层后台服务编排单点与 `check-background-services` 守门名单）；与手动形态共用同一编排、同一进度事件与同一收尾裁决，差异仅触发方式、后台车道（共享额度让行）与静默失败面。巡检调度循环（单次拉起守卫判定、门检、自然日窗口）与单轮骨架（换装 / 会话 / 见证 / 裁决 / 发射 / 失败日志）共用行情同步域 `lane` 单点（ADR-0122 决策 3「同形调度」的代码单点，issue #1426 单轮半边 / issue #1622 调度半边，与价格历史后台补全、每日汇率同步三车道共用）。
- **别名**：不使用"增量行情"（口语）、"持仓价格增量同步"（#827 前身名，覆盖面已放开）；UI 文案固定为“同步标的信息”。

## 价格历史后台补全（PriceHistoryBackfill）

- **定义**：系统自动、**无用户入口**地把价格历史补齐到覆盖目标窗口的后台过程（ADR-0122）——按「有价格通道但历史不完整」的队列采集，与现价刷新解耦；采集语义（周采样、整周覆盖、窗口与覆盖面）全部归 PriceHistory。覆盖目标深度：基金为首笔持仓流水日所在周（无持仓流水则近两年，#1534），股票/场内标的为近两年。
- **边界**：
  - **无入口、不打断**：不给用户任何触发动作；唯一可见面是进行中的标的级完成计数，不占用全局忙碌条、不改变任何页面可用性、不可点、终态静默收起。
  - **触发与续做**：应用启动后延迟启动一次 + 每个自然日窗口各跑一次，直到队列空；队列由派生事实决定，不落任务状态——应用退出即硬停、下次启动继续。
  - **逐只采集只服务首刷、缺周点与基金深回填**：有历史序列的标的，当周采样点直接由现价刷新的批量取数落库（周采样要的正是该周最后一个有报价交易日的价格）；逐只请求只用于**首刷**（没有任何历史序列 → 取覆盖目标窗口）、**缺周点补齐**（水位落后当前自然周超过一周，例如应用数周未开）与**深回填**（最早历史周点晚于首笔持仓周——按旧深度首刷的存量基金整根补到持仓期起点，#1534）。若无此切分，每日全库逐只请求会把已降到秒级的日常重新推回分钟级。
  - **增量窗口与首刷语义**（ADR-0038 决策 6，首刷判据随 issue #1059 修订、窗口深度随 #1534 放宽到持仓期；取数面随 #1566 换源新浪单只全历史，ADR-0130 决策 2）：首刷判据 = **磁盘上没有任何历史序列**，不是「现价缓存无净值日期」——添加基金 / AI 导入已把当时最新净值日期写进现价缓存（水位有值）而 PriceHistory 为空，若仍以水位作增量起点，窗口只剩「水位次日」、近两年回填静默落空。首刷窗口起点 = 近两年与首笔持仓周的较早者（无持仓流水 = 近两年）、走新浪单只全历史面（一次请求取整只历史、含已终止基金，窗口语义由本地裁剪表达）；已有历史序列者若覆盖达标则以现价缓存的净值日期为水位、从水位次日增量（水位当日不重拉），覆盖不足（最早周点晚于首笔持仓周）则整根深回填；深回填窗口内全部周点均已入库且同值时零落库（幂等，零新点不置脏不广播）。取数失败或报文不可信一律 fail-closed——本轮不落、交下一窗口重试，不把不可信结果当「无净值」；可信空结果（查无此码 / 窗口内确实无新净值）计入跳过而非报错。
  - **单只原子（ADR-0122）**：单只标的的回填整只一次提交，中断/失败不留半根历史——由此「有历史序列」与「历史完整」等价，首刷判据依赖的正是这个等价（半截历史不可信时宁可整只留空重试，issue #1566 起由全历史面声明总数核对承接）。
  - **额度让路**：与前台请求共享同一全局限速器，前台在途时退让；不占用「用户动作在途唯一」的槽位。
  - **实际写入即发价格失效信号**（ADR-0031）：写价即广播，消费方无需自行重拉。
  - **走势空态三态**：补全中（带计数）/ 补全失败待重试 / 无数据（该标的确实没有可采的历史序列）；空态不再给「点击同步标的信息」这类指向按钮的文案。
  - **队列不含价格恒定标的**（ADR-0126）：它的价格是已知常量，落历史行不带来任何信息——队列判据、进度分母与首刷判据都跳过它。
  - **与价格过期提示分工**：过期提示只问现价水位（答「要不要刷现价」），本词条回答「走势为什么还没有曲线」；恒定标的既不进本队列也不进过期检查（见价格过期提示）。
- **别名**：不使用「后台同步」「历史同步」（与用户可见的同步动作混淆）、「增量行情」（口语）。

## 价格过期提示（PriceStalenessPrompt）

- **定义**：打开投资页时做一次的**本地水位检查**（零网络请求）——按价格通道判定库里是否有行情 / 净值通道标的的现价水位已经陈旧（或持仓标的没有现价），是则给出含过期数量的可执行提示，一键导向既有「同步标的信息」入口。**计数面 = 全库需采集价格的通道标的**（含已清仓；恒定价格标的除外，ADR-0126；已清仓且水位陈旧超过一年的行退出，见过期判定），与同步的收集面同面：提示回答的是「同步能修好多少只标的」，不是「报表被多少只影响」。历史补齐状态不归本词条（见价格历史后台补全）——导向的入口只修现价，不修历史。
- **边界**：
  - **水位不新造**：行情通道标的的水位 = 现价缓存的行情采集时点；净值通道标的的水位 = 净值日期（兼任历史增量水位，见价格历史后台补全）。判定单点在后端投资域，提示侧只渲染计数与阈值，不按类型与市场自行推断第二口径（同价格通道的判定归属）。
  - **过期判定**：水位日（行情日历以北京时间为准）距今**超过 3 个自然日**即计入——周五的水位在周六 / 周日 / 周一是 1 / 2 / 3 天，均不提示；到周二（4 天）才提示，此时周一已可拉取而本地没有。水位整个缺失时只对**持仓标的**计入（「持仓缺现价」：账本里真有一笔资产没有估值依据），纯建档未交易的行不惊动用户。已清仓行的过期计数只收到一年为止：水位陈旧超过 365 自然日的已清仓行退出计数面（issue #1663）——一年没有新点即数据源已停止披露（清盘 / 长期停牌），同步永远修不了，陈旧价又不影响报表，持续提示只是永久噪声；**持仓行不设此退出**（估值依据陈旧的提示不因陈旧太久失去意义）。阈值随结果透出，提示文案不另抄天数；退出只收窄长尾，不改正常判定，被计入的每行仍满足「超过 3 天未更新或持仓缺现价」，文案不变。
  - **提示措辞只陈述标的自身**：文案说「标的的行情 / 净值可能已过期」，**不宣称「报表会按陈旧价格计算」**——计数含已清仓标的，而报表与净资产只吃持仓，那句话对已清仓标的不成立（过度承诺）。要断言报表影响就得把计数收窄到持仓，那与票面「过期的行情 / 净值通道标的」字面不符，也不解决标的页 / 走势（自 #827 起覆盖清仓标的）里同样的陈旧价。文案与计数面须同进同退：改计数面时同步改文案。
  - **检查面 = 需要采集价格的通道成员**（行情 / 净值）：手动报价、无来源与**恒定价格**通道不在其列——「同步标的信息」修不了它们：手动报价通道的出路是录价（见手动报价），恒定价格标的没有水位可言（价格不随时间变，见价格恒定标的）。
  - **手动报价通道的持仓缺价不计入（不是漏算）**：本提示的唯一动作是「去同步」，对手动报价行无效；该行的可执行录价引导由持仓缺价行承担（issue #1193），两处分工不重叠——本提示只收「同步修得了」的行。
  - **已知边界：长假与长期停牌期间提示会持续存在（有界接受）**：两条水位的语义不同——行情通道取现价缓存的**写入时刻**，净值通道取**数据日期**；长假、长期停牌或基金停止披露净值期间数据源没有新点、同步不落库（也就没有价格失效信号），水位不会变新，提示既不会自动消失、点「去同步」也消不掉。**裁定接受**：此时本地价确实不是最新的，提示是诚实陈述；仓库没有「最近是否有交易日」的事实源（交易日历 / 节假日表不存在，已 `rg` 查证），为它造一份即新口径，且「窗口内是否真有新数据」只有网络事实能答，与零网络请求的边界冲突。缓解有二：3 个自然日阈值已吸收普通周末与 T+1 发布延迟；issue #1663 起已清仓行水位陈旧超过一年退出计数面，清盘类永久无新点的行不再永久噪声——持续提示的残余面只剩持仓行（估值依据确实陈旧）与一年内的清仓行。
  - **只读、不触发**：打开投资页不发任何网络请求、不写任何数据、不产生同步调用；提示出现后由用户点按钮进入既有同步入口，本提示自身不触发任何自动同步（ADR-0015 / ADR-0095 的显式触发口径在本词条内保留）。自 ADR-0122 起现价刷新另有后台每日自动一次——提示因此在正常使用下很少出现，出现即说明后台刷新也未成功（应用久未打开、网络不可达或取数降级）。同步实际写价后由价格失效信号驱动重查，提示随价格变新自动消失，调用方无需记得手动收提示。
  - **检查时机**：投资页挂载一次 + 价格失效信号后重查；检查失败静默降级为「不提示」（背景提示不打扰用户，也不留半态）。提示不做「已读」记忆——它与水位事实一一对应，不由会话状态决定。
  - **命名投影（术语 ↔ 代码）**：本词条是用户可见概念名；代码侧同一概念的落点是读命令 `instrument_price_staleness`、结果类型 `PriceStaleness` 与前端接缝 `usePriceStaleness`——三名一物，不是两套概念。
- **别名**：不使用"价格过期告警"（告警暗示后台监控与推送）、"陈旧价格检查"（同一概念不设第二名称）；提示动作固定为“去同步标的信息”，不新增第二套同步触发。

## 价格失效信号（PriceChangeSignal）

- **定义**：价格数据（MarketPrice / PriceHistory / FxRateHistory）发生写入后，后端发出的无 payload、粗粒度的 `ledger:prices-changed` 信号（ADR-0031；失效信号家族的成员，家族定义见核心交易域失效信号）；前端价格消费方各自订阅并重拉自身数据，替代「同步后记得手动刷新」的调用方自觉。
- **边界**：
  - **生产者五处**：InstrumentInfoSync 实际写入价格或名称时（成败同判，失败且实际写过同样广播，issue #1277；issue #827 起名称刷新同路计入）；手动报价实际写入（任一落点）时（ADR-0036）；行情接入（QuoteAdoption）落库半边落现价时——场外基金按代码即拉、场内标的按代码添加、AI/HTTP 标的创建三条创建路径同路（ADR-0103；grilling 复核 2026-09-12 补全）。零变化（空库、全部跳过、添加基金未取到净值、创建未命中现价、同步失败且未写过）不广播——失效信号的本义是「数据变了」。原「全量同步结束有落库」的生产者随全量同步退役删除（issue #698）。
  - **与平行信号的关系**：与参考失效信号 `ledger:changed`（见参考数据与设置域 Reference Data）、备份信号 `ledger:backups-changed`（见备份与数据文件域 Backup）同一 `ledger:*` 命名空间、同一形状（无 payload、粗粒度），各域语义各自锚定；不复用 `ledger:changed`——其语义锚定参考写入（ADR-0012），价格同步误发会触发参考表无谓重拉而价格消费方无人响应。
  - **消费方自选订阅**：信号可用性全局，订阅与否由消费方决定（本期为持仓概览、标的页标的列表、组合走势与价格过期提示——走势同样吃现价缓存，重拉前重置同键去重短路；价格过期提示借此在同步实际写价后重查、提示随价格变新自动消失；仪表盘等留后续）；未订阅者行为不变。
- **别名**：不使用"行情刷新事件"、"价格推送"（推送暗示带 payload 的实时行情流，本信号只是失效通知）、与 `ledger:changed` 混称"失效信号"（不区分域）。
