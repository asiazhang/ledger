# 领域词汇表：投资域

> Ledger 领域词汇表的投资域分域。全部分域与彼此关系见 `CONTEXT-MAP.md`；决策记录见 `docs/adr/`（ADR-0015 / ADR-0019 / ADR-0020 / ADR-0036 / ADR-0038 等）。
> 跨域共享术语（Transaction、Amount Model、Transaction Kind Mapping、DefaultCurrency 等）见核心交易域 `CONTEXT-core.md`，本文不复制定义。
> 若与代码行为冲突，以代码为准并同步修正本文件。

## Instrument（金融工具/标的）

- **定义**：用户可交易的金融产品，例如某只股票、某只基金、某只债券。
- **边界**：
  - 类型闭集五种：股票、基金、债券、ETF、其他。
  - 标的由显示代码与市场共同标识（沪/深/港三市场；手动创建未指定市场时视为未知）。
  - 股票类标的由"标的全量同步"从东方财富 API 批量拉取填充（代码、名称、市场、币种），用户无需手动录入；非股票标的经手动创建入口录入（类型白名单、名称必填与来源标记见自建标的，ADR-0036）。
  - **来源**：字典条目带来源标记（`source`：同步 / 手动，字面取值 `eastmoney` / `manual`，见自建标的）；它与价格数据的来源标记（现价/历史里标注价格从哪里来）同词表但语义正交——一个说「字典条目谁建的」、一个说「价格数据从哪来」，「手动字典 + 东财净值」的基金行是合法并存态；股票类字典的修正归标的全量同步，手动创建与它正交（ADR-0036）。
  - **幂等建行**：标的字典以（symbol, 类型）为自然键幂等创建，已有行复用并按需更新名称/市场，不产生同标的多条记录（防碎片）。
  - **标的搜索**：消费统一模糊搜索语义规格（唯一定义点见核心交易域 TransactionSearch，ADR-0027），判定目标为「代码 · 名称」label 等价文本，无名称时退化为裸代码。
  - **迁移建行**：AI 迁移源数据常只有名称，允许以标的名称充当代码建行（约定见 AI 导入域 AI API）；此类行与自建标的同路（非同步来源），以基金/债券等无行情来源标的为主，不参与行情同步，AI 通道亦无就地升级为真实代码的入口。
  - **场外基金标的（ADR-0038）**：类型 fund、市场恒为 unknown——场外基金没有交易所市场概念，基金代码亦无市场前缀规律，仅由 6 位代码标识；入口是手动输代码、按代码即拉东方财富详情回填（名称/类型/最新净值，见 MarketPrice），不做基金全量同步；来源标记 = 手动（自建标的的按代码增强形态，ADR-0036）。名称充代码的基金行无真实代码，不进净值通道（仍属无行情行，见 PriceHistory）。
  - 标的名称（如「贵州茅台」）由同步自动填充。
  - **投资状态**：列表返回的派生标记 = 是否为持仓标的（见 InvestedInstrument）；标的页据此展示「持仓」标记列，并可用「只看持仓」开关过滤（issue #102）。
- **别名**：不使用"证券"（偏法律概念）、"产品"（过于泛化）。不单独使用 "market_symbol" 或 "ticker"——统一使用 "symbol"。

## MarketPrice（市场价格）

- **定义**：某个 Instrument **当前**的市场报价——现价缓存，即 PriceHistory 中该标的最新一条的即时映像，供持仓市值与未实现盈亏（Holding）计算消费。
- **边界**：
  - 仅代表"现在"：每次同步覆盖更新本条记录；历史报价序列由 PriceHistory 承载，MarketPrice 不再是价格的唯一载体。
  - 现价与币种由数据源（东方财富）返回，币种按来源固定：沪/深市为人民币、港股为港币；场外基金为人民币，其现价语义 = 最新公布的**单位净值**，并记录净值日期（兼任净值同步水位，见 HoldingPriceSync）；另记录同步时间与来源标记（当前为东方财富）。
  - 价格数值刻度为**万分之一元**（全投资域价格列统一口径，见价格刻度）。
- **别名**：不使用"行情"（偏实时交易概念）、"报价"（偏询价场景）、"最新价快照"。

## PriceHistory（价格历史）

- **定义**：某个 Instrument 的市场报价按周粒度累积的历史序列，用于绘制单标的走势与投资资产走势（PortfolioValueTrend），是价格在「现价」之外的第二条承载线。
- **边界**：
  - **覆盖面 = 有价格写入通道的标的**：股票类持仓标的（口径同 InvestedInstrument）经同步通道写入；场外基金标的经净值同步通道写入（单位净值即价格，ADR-0038）；无行情来源的自建标的经手动报价通道写入（ADR-0036）。无任何价格写入的标的不参与价格记录与走势图。
  - **周采样**：每周至多记录一条，取该周最后一个有报价交易日的价格；整周无有效报价（停牌、节假日全周覆盖等）则该周无点，曲线跨越空档连续。一周内重复获取时以新数据**整周覆盖**（幂等），不产生重复。
  - **采集单通道**：初始一次性回填近两年，此后随持仓价格增量同步持续累积；数据源日线/净值序列最后一根即今日最新价，故「回填历史」同时也是「刷现价」，不存在两条刷新通道。
  - 已清仓标的的价格历史保留不删，供回看过去的组合市值；清仓只影响后续不再新增。
  - 港股以港币计价，跨币种汇总走势须经 FxRateHistory 同期折算，不用当前汇率近似历史。
- **别名**：不使用"历史行情"（口语偏全市场）、"K 线"（那是数据源的原始形态，本地不保留日线）；单只基金的净值序列可称"净值走势"，但组合走势仍不称"净值走势"（混合多类资产，见 PortfolioValueTrend）。

## FxRateHistory（汇率历史）

- **定义**：货币间兑换比率按周累积的历史序列，与 PriceHistory 同源同时段采集（东方财富汇率数据），用于把非默认币种的**历史**市值折算到核心交易域 DefaultCurrency。
- **边界**：
  - 与现有 ExchangeRate（当期汇率表）并存分工：当期折算走 ExchangeRate，历史期折算走 FxRateHistory；同期同规则（正反向兜底）。
  - 周采样与整周覆盖规则与 PriceHistory 一致。
  - 只随本域市值折算消费；MVP 阶段核心交易域流水折算（raw/native）仍只用当期汇率，不变。
- **别名**：不使用"历史汇率表"（易与当期表混淆指代）；可简称"汇率历史"。

## PortfolioValueTrend（投资资产走势）

- **定义**：把用户全部有价格历史的持仓在各时点的市值汇总成的时间序列视图，回答"我的投资总价值如何变化"；同一功能内也呈现单个标的自身价格序列的单标的走势。
- **边界**：
  - 组合市值 = 各持仓标的「当期持有数量 × 当期价格」之和：数量由核心交易域 buy/sell 交易流水在查询时推算（不物化每日/每周快照；排除软删除账户的流水，口径见时点持仓），价格取自 PriceHistory。推算**仅认 buy/sell 流水**：dividend/split 目前被写入层显式拒绝故无影响，未来支持拆股等改变持有量的公司行为时，逐期推算必须同步纳入，否则静默失真。
  - 跨币种按 FxRateHistory 折算为核心交易域 DefaultCurrency 后汇总成一条曲线；曲线为周采样点连线。
  - 展示位置 MVP 为投资页内的走势视图（预设区间切换：1 月 / 3 月 / 1 年 / 全部；组合走势与单标的走势同视图切换）；多标的叠加对比属后续迭代。
  - **不含现金账户**：总资产走势（现金余额历史重建 + 投资市值）是明确的后续迭代，不在本概念范围内。
  - 标的在区间起点之前买入无早期价格时，曲线从首个有效采样点开始。
- **别名**：不使用"净值走势"（组合混合多类资产，该词仅适用于单只基金的价格序列；且暗示收益率口径）、"收益曲线"（混入收益率口径）、"总资产走势"（明确含现金账户的后续概念）。

## Holding（持仓）

- **定义**：用户在某个投资账户中持有的某个 Instrument 的数量及成本信息。
- **边界**：
  - 数量为当前持有数量，由各持仓批次剩余数量实时聚合；持有成本为买入总成本及其币种。
  - 现价、市值、未实现盈亏由 `v_holdings` 视图实时计算（关联最新 MarketPrice 与汇率折算到账户本位币），不落库存储。
  - 市值 = 数量 × 现价（按汇率折算）；未实现盈亏 = 账户币市值 − 账户币成本。
- **别名**：不使用"仓位"（偏交易术语）、"库存"（偏实物）。

## NetWorth（净资产）

- **定义**：用户全部真实财富在某一时刻的单一合计数字（本位币）：Σ 非投资账户余额 + Σ 持仓市值，均折算为核心交易域 DefaultCurrency 后相加。
- **边界**：
  - 由后端只读聚合实时计算，不落库存储；账户侧沿用核心交易域 `account_flow` 余额口径（符号归属见核心交易域 Transaction Kind Mapping，与账户列表/余额页一致，排除隐藏/黑洞账户——见 AI 导入域 BlackHoleAccount），投资账户余额不计入——其价值经持仓市值体现，避免同一笔资产重复计算。
  - 持仓市值取持仓视图输出的账户本位币市值，再折算到 DefaultCurrency；从未录价（或缺折算汇率）的持仓按空值语义跳过，不以零计入。
  - 折算遇缺失汇率让错误上抛（中文错误信息），不静默返回不完整的合计数字。
  - 负债账户按 `account_flow` 现行符号忠实求和，不在净资产层强制取负。
  - 「总资产走势」（净资产的时间序列，现金余额历史重建 + 市值）是明确的后续迭代，不在本概念范围内。
- **别名**：不使用"总资产"（与「总资产走势」既有预留概念区分，避免同一页面两套口径混淆）、"净值"（基金净值语义不同）。

## InvestableAssets（可投资资产）

- **定义**：能产生被动收益的资产合计（本位币）：Σ 持仓市值 + Σ 投资账户余额，均折算为核心交易域 DefaultCurrency——财务自由度（FinancialFreedom）的分子（ADR-0048）。
- **边界**：
  - **与 NetWorth 的边界差异**：净资产排除投资账户余额，是防止其价值与持仓市值重复计入同一笔资产；可投资资产计入投资账户余额，是因为账户里未投入的现金（「子弹」）不被持仓市值体现，漏算会低估真正能产生被动收益的资产。两者并存不冲突，消费者按问题选口径（「能钱生钱的有多少」vs「全部家当有多少」）。
  - **生活现金/储蓄/电子钱包等非投资账户不计入**：计入会让生活费虚增自由度。
  - **排除隐藏账户**（含黑洞账户，见 AI 导入域 BlackHoleAccount）：隐藏投资账户的现金与持仓一并不进分子，归档/黑洞类账户不扭曲指标；**负债既不计入也不抵扣**——指标聚焦资产侧，口径简单可解释。
  - 从未录价的持仓按空值语义跳过（同 NetWorth），不以零计入；缺汇率让错误上抛（中文错误信息），不静默返回缺料的数字。
- **别名**：不使用"投资资产"（易与 Investment 混淆）、"总资产"（那是含生活资产与负债的净资产口径，见 NetWorth 别名边界）。

## FinancialFreedom（财务自由度）

- **定义**：可投资资产（InvestableAssets）对年度支出水平的覆盖程度（本位币百分比）：自由度 = 可投资资产 × 3% 安全提取率 ÷ 年度预算总额（见预算域 AnnualBudgetTotal）× 100%，≥100% 即财务自由；后端只读实时计算，不落库存储（ADR-0048）。
- **边界**：
  - **3% 安全提取率是常量**（保守于教科书 4%，达标线更扎实），单点收口在后端，不开放用户配置；调整先修订 ADR-0048。
  - **覆盖年数 = 可投资资产 ÷ 年度预算总额**，与自由度是同一刻度的两种表述（「每年能提多少」与「能躺几年」）；两者均保留一位小数。
  - **未设预算时照常返回零分母**，不回退实际支出——占位引导（「设置预算后解锁」）归展示层，口径层不引入第二分母。
  - **阶段标签（积累期 / 接近自由 / 财务自由）与阈值归界面层派生**：分档是展示文案而非口径，后端只输出百分比本身。
  - 买卖投资、录入报价、编辑预算后即时反映（命令实时聚合，无快照可过期）。
- **别名**：不使用"FIRE 指数"（社群口语）、"自由率"。

## 时点持仓（AsOfHolding）

- **定义**：某标的（或全组合）在**某交易日**的持有数量，由核心交易域 buy/sell 交易流水在查询时推算。「仅认 buy/sell 流水、sell 取负、按日期前缀求和」三件事单点收敛在投资域的推算模块内（as-of 持仓推算接缝，spec #168）。
- **边界**：
  - **与 Holding 的分工**：Holding 答「现在持有多少」（持仓批次聚合），时点持仓答「某时点持有过多少」（流水前缀推算）；同一批买卖流水下两者在「今天」必须一致（绑定不变式测试钉住）。
  - **时间语义是交易日**：as-of 键为交易日（含当日的前缀求和）；周采样键是 PortfolioValueTrend 查询侧的时间语义，不进推算模块——双时间键契约由此显式分界。
  - **推算仅认 buy/sell 流水**（CONTEXT 核心域 Transaction Kind Mapping）：dividend/split 目前被写入层显式拒绝故无影响；未来公司行为落地时只改推算模块内部，走势查询不感知。
  - **消费者**：仅 PortfolioValueTrend 的组合市值（逐价格行取该标的当期数量）；单标的走势是价格直出，不消费本概念。对外 IPC 契约不变。
  - **软删除账户口径（issue #217 定案）**：流水口径排除软删除账户的 buy/sell 流水，与 Holding / InvestedInstrument / 净资产对齐——删除账户 = 从全部投资视角（含历史走势曲线）消失。账户删除/恢复（软删标志翻转）使流水自动进出推算，无需时点存续状态。隐藏账户不是软删除，与 v_holdings 一致不排除。
- **别名**：不使用「历史持仓」（易读成历史持仓记录）、"position"（交易术语）、与 Holding 混称「持仓数量」（无法区分现值与 as-of）。

## Investment（投资域）

- **定义**：承载核心交易域证券交易（buy/sell）背后持仓批次、卖出匹配与已实现盈亏的概念域。
- **边界**：
  - **buy/sell 首先是交易 kind**：一笔 buy/sell 先是一笔核心交易域 `Transaction`（交易行落库经 Writer 接缝），Investment 是它背后的持仓/盈亏载体。
  - **场外基金申赎同构复用 buy/sell（ADR-0038）**：申购=buy、赎回=sell（数量=确认份额、单价=成交日净值、手续费=申购/赎回费），不新增 kind；录入按确认后结果（金额与确认份额为权威输入，单价由其反算），不做在途/确认中状态。**录入权威按标的类型分流（issue #302）**：基金形态表单要求金额与份额必填、单价反算展示，行金额恒等于确认单整分金额（不被单价舍入污染）；其余类型维持单价权威、行金额重算。
  - **基金分红不做专门承载**：现金分红手工记账、红利再投以 0 手续费的 buy 手工模拟——与「推算仅认 buy/sell」口径天然兼容；放开 dividend 留另行议题（虚拟股分红以普通 income 承载的先例同向，见自建标的）。
  - 对外出口收窄为 `prepare / apply / revert` 三件套（issue #72）：prepare 校验归一化（不落库）、apply 应用副作用（buy 建仓 / sell 卖出匹配）、revert 回退副作用（buy 守卫+清理 / sell 回补）；交易行写入由核心交易域行为层编排（经 Writer 接缝），Investment 不再反向依赖核心交易域的行更新（双向依赖已斩断，issue #70）。
  - 分派用薄而穷尽的分支，不引入注册表机制（避免过度设计）。
- **别名**：不使用“投资账户”（那是投资类型的账户）、“证券模块”（偏数据层）。

## TransactionTrade（交易买卖明细）

- **定义**：一笔 buy/sell 核心交易域 Transaction 在投资域扩展表中的投影——标的、数量、单价、手续费，物理实现在 `security_transactions` 扩展表（按交易 id 关联交易行）。
- **边界**：
  - **核心交易行不含投资字段**（ADR-0003 核心表 + 扩展表）：买入/卖出编辑（issue #180）回填标的/数量/价格/费用须经只读命令读取本投影，不把投资字段塞进核心 `Transaction` 模型。
  - **投影随读带出标的代码与名称，供回填后标的选择框直接显示标的而非裸 id**；并带出标的类型，驱动表单录入形态切换（基金 = 金额 + 份额必填，其余 = 数量 + 单价，issue #302）。
  - 无明细（交易不存在/非 buy/sell）显式报「无买卖明细」。
  - **回填 ≠ 可改金额**：编辑提交走行为层全字段替换权威（与 HTTP 修改端点同源），明细投影只读；金额/单价的权威归属随标的类型（见 Investment）——非基金金额由 prepare 按数量×单价±手续费重算，基金金额照抄确认单、单价反算。
- **别名**：不使用“成交记录”（易与交易所对账单混淆）、“投资交易详情”。

## InvestedInstrument（持仓标的）

- **定义**：有**当前持仓**（持仓批次仍有剩余数量，即 `v_holdings` 视图有行、且排除软删除账户的批次）的 Instrument，即“已投资”标的（ADR-0015）。
- **边界**：
  - 判定谓词单点定义（投资域薄模块内的存在性谓词，issue #239），同一口径驱动四处：标的列表的持仓派生标记、标的页「只看持仓」过滤、增量同步的标的收集与统计、盈亏页持仓概览（issue #102/#103/#110）。
  - **与 `v_holdings` 视图的一致性由绑定测试钉住**：视图定义随发布冻结、是只读对账基准；两份 SQL 编码的一致性由投资域单测断言逐标的相等（先例：周键 ↔ week_start 生成列绑定测试，issue #239）。
  - **不含已清仓标的**：已清仓的得失由已实现盈亏（RealizedPnl）承载，不混入“已投资”。
- **别名**：不使用"已投过的标的"（含已清仓）、"自选/关注标的"（那是用户主观收藏，与持仓无关）。

## 自建标的（ManualInstrument）

- **定义**：来源为用户手动创建的 Instrument（字典来源标记 = 手动），与同步填充的股票类字典相对；典型如基金投顾组合（且慢「稳稳地幸福」）与非上市虚拟股（华为虚拟股票），均记类型「其他」——fund 类型语义归场外公募（ADR-0038）。
- **边界**：
  - **创建入口类型白名单为债券/ETF/其他三类**（fund 类型唯一创建入口 = 场外基金的按代码即拉，见 Instrument；白名单守卫属 UI 入口政策，AI 创建端点不受限）：与 InstrumentSync（仅修 stock 类字典）正交——既防同代码自建股票被东财覆盖名称/市场，也防东财另插同代码 stock 行造成重复标的（ADR-0036）。
  - 创建语义：名称必填（自建标的主身份是名称），代码自由文本，市场未知，币种可选；同（代码，类型）已存在则复用该标的并更新名称。
  - **删除**：仅自建标的可删，守卫为无任何 buy/sell 流水引用（TransactionTrade 无行），有引用拒删；同步标的不可删（填错由全量同步修正）。不引入软删。
  - 分红等公司行为不入本域：虚拟股分红以核心交易域普通 `income` 流水入现金账户承载，dividend kind 维持写入层拒绝。
- **别名**：不使用"自定义标的"（口语，收编为本词条）、"自选/关注标的"（用户主观收藏，与持仓无关，见 InvestedInstrument）、"手动标的"。

## 手动报价（ManualPrice）

- **定义**：用户手动录入的价格点（日期 + 单价），无行情数据源标的（典型为自建标的）的唯一价格来源——与东方财富同步并列的第二条价格写入通道。
- **边界**：
  - 单点录入，一条通道两个落点：现价缓存 upsert + PriceHistory 周采样幂等覆盖（同周后写覆盖先写，与同步同规则）；不另立手动价格承载。
  - **现价 = 最新历史点的即时映像**（MarketPrice 既有定义的推论）：回填早于最新点的旧价只沉淀历史，不改变现价。
  - **录价入口只对同步覆盖不到的标的开放**（自建标的与名称充代码的基金行；真实代码基金与股票的现价归同步通道，开放录价只会被下次同步冲掉）；判定口径与增量同步「净值可拉」分区同源（ADR-0036/0038）。
  - 实际写入（任一落点）即发价格失效信号（见价格失效信号，生产者第三处，ADR-0036）。
  - 且慢组合单位净值、华为每股公允价等在 Ledger 统一为标的「价格」（市值 = 数量 × 价格），不因来源不同引入「净值」语义。
- **别名**：不使用"净值"（平台语境概念，Ledger 统一为价格）、"自定义价格"、"补录价格"。

## 价格刻度（PriceScale）

- **定义**：全投资域价格数值的统一刻度——**万分之一元**（0.0001 元）为最小单位。
- **边界**：
  - 覆盖全部价格语义列：现价缓存、价格历史、交易买卖明细的成交单价、持仓批次的每份成本；基金净值 4 位小数是其直接动因（ADR-0038）。
  - 列名沿用 `_cents` 历史名、刻度已就地重定义（BREAKING，ADR-0038）：读代码以本词条为准，勿按列名望文生义为「分」。
- **别名**：不使用"分"指代该刻度（历史语义残留，已失真）。

## InstrumentSync（标的全量同步）

- **定义**：用户手动触发、系统从东方财富 API 一次性全量拉取沪市/深市/港股股票标的信息（代码、名称、最新价），upsert 到本地标的字典 `instruments` 与现价缓存 `market_prices` 的过程。**职责 = 修标的字典**（ADR-0015 职责切分：全量修字典 / 增量刷价格 + 沉淀历史；ADR-0019 价格历史化）。
- **边界**：
  - 触发方式：手动触发（标的页"全量同步"入口，issue #101 迁移后设置页不再提供同步入口），不做自动定时刷新。
  - 同步范围：沪市、深市、港股，币种分别固定为人民币、人民币、港币；场外基金不做全量同步（基金字典按代码即建，见 Instrument，ADR-0038）。
  - 执行方式：一次性全量同步、分页拉取，无并发限制、无失败重试。
  - 去重：按标的代码匹配已有标的，名称或市场变更则更新，不存在则插入，并同步 upsert 该标的最新价到现价缓存。
  - 进度反馈：通过 `sync-instruments:progress` 事件向前端汇报当前页数/总数与累计新增、更新数量。
  - **中断机制（issue #104）**：分页循环每页检查共享取消标志，经取消命令置位后即提前返回并推送中断态事件；已落库数据保留（upsert 幂等）、下次重跑自动续上。进度事件终态区分完成与中断。
  - 无同步进行时调用取消命令无副作用，返回明确提示。
  - **结束即发价格失效信号（ADR-0031）**：结束时只要本次运行有落库（含用户中断——中断保留已落库价格，不发信号即失真）即发出 `ledger:prices-changed`，与增量同步共用同一信号。
- **与增量同步的边界**：全量修字典（增删改 `instruments` + 刷价），增量刷价格并沉淀历史（见 HoldingPriceSync、ADR-0019）；日常刷新现价与走势走增量同步，全量仅在标的字典需要修补时触发（二次确认说明范围与数百次 API 请求代价）。
- **别名**：不使用"同步价格"（偏持续同步）、"更新行情"（偏实时）。

## HoldingPriceSync（持仓价格增量同步）

- **定义**：用户手动触发、单次收集全量持仓标的（口径 = InvestedInstrument 单点谓词，不再读 `v_holdings` 视图）后在后端按类型分区刷价：股票类按市场与代码构造行情查询批量获取最新价并回填近两年周线，场外基金类逐只拉取公布净值并按净值日期水位增量回填（ADR-0038）；统一 upsert 现价缓存 + 把日线/净值序列降采样落 PriceHistory 与 FxRateHistory（ADR-0019）——不增删、不改标的的名称与市场。UI 文案为“同步持仓价格”，与“全量同步”区分（ADR-0015 职责切分：全量修字典 / 增量刷价格 + 沉淀历史）。
- **边界**：
  - 触发方式：手动触发（标的页"同步持仓价格"按钮与盈亏页"当前持仓"概览卡右上角按钮，两处共用同一 `useHoldingPriceSync` 接缝、行为一致），不做自动定时刷新。
  - 按标的类型分区：股票类走行情报价/K 线通道；**场外基金类走净值通道（ADR-0038）**——代码为 6 位数字的 fund 标的逐只拉取公布净值，以现价缓存的净值日期为水位：首次回填近两年、此后每只一页增量（周采样幂等覆盖规则不变）；债券等无行情来源标的、名称充代码的基金行（无真实代码，查不到净值）与市场未知（无法构造行情查询）的股票仍计入“跳过 M 只”统计提示，不报错；跳过统计与标的收集出自同一次收集（后端分区，天然同源，issue #239）。
  - **与 `v_holdings` 视图的口径一致性由绑定测试钉住**：标的收集改走单点谓词后不再读视图，谓词与视图两份 SQL 编码的一致性由投资域单测断言逐标的相等、口径漂移在测试期即失败（详见 InvestedInstrument 边界，issue #240）。
  - 水位增量语义（ADR-0038 决策 6）：首刷（现价缓存无净值日期）回填近两年；此后从水位次日起按页增量，水位当日不重拉，同周新净值整周覆盖采样日；「已是最新（水位后无新净值）」的基金计入同步成功但不落库、不计跳过。净值报文解析与水位语义经注入测试离线钉住，不依赖真实网络。
- 停牌/无效价跳过、保留旧价，不中断同步；数据源返回空响应（全部代码无效）时优雅降级为空。单只的网络失败与股票通道一致——上抛中断同步；跳过统计只收「无法拉取」的行，不含网络失败。
  - 重复触发幂等：每标的现价覆盖更新（来源标记沿用数据源）；PriceHistory 同周整周覆盖，均不产生重复数据。
  - 完全无持仓时返回明确提示（"无持仓标的可同步"）而非报错。
  - **成功且实际写入即发价格失效信号（ADR-0031）**：实际写入价格时发出 `ledger:prices-changed`，各价格消费方由信号驱动重拉；接缝 `useHoldingPriceSync` 的承诺是「同步完成即通知失效」，调用方无需自行重拉，零写入（无持仓/全部跳过/基金全部「已是最新」）不广播。
  - 复用全量同步的 HTTP 层（主机池、重试、限流）与价格换算，增量同步 API 访问量从全量数百次降到个位数（issue #103）。
- **别名**：不使用"增量行情"（口语），正式术语为"持仓价格增量同步"；UI 文案固定为"同步持仓价格"。

## 价格失效信号（PriceChangeSignal）

- **定义**：价格数据（MarketPrice / PriceHistory / FxRateHistory）发生写入后，后端发出的无 payload、粗粒度的 `ledger:prices-changed` 事件信号（ADR-0031）；前端价格消费方各自订阅并重拉自身数据，替代「同步后记得手动刷新」的调用方自觉。
- **边界**：
  - **生产者四处**：HoldingPriceSync 成功且实际写入价格时；InstrumentSync 结束且本次运行有落库时（含用户中断）；手动报价实际写入（任一落点）时（ADR-0036）；场外基金标的按代码即拉详情落现价缓存时（ADR-0038）。零变化（无持仓标的、全部跳过、添加基金未取到净值）不广播——失效信号的本义是「数据变了」。
  - **与平行信号的关系**：与参考失效信号 `ledger:changed`（见参考数据与设置域 Reference Data）、备份信号 `ledger:backups-changed`（见备份与数据文件域 Backup）同一 `ledger:*` 命名空间、同一形状（无 payload、粗粒度），各域语义各自锚定；不复用 `ledger:changed`——其语义锚定参考写入（ADR-0012），价格同步误发会触发参考表无谓重拉而价格消费方无人响应。
  - **消费方自选订阅**：信号可用性全局，订阅与否由消费方决定（本期为持仓概览、标的页标的列表与组合走势——走势同样吃现价缓存，重拉前重置同键去重短路；仪表盘等留后续）；未订阅者行为不变。
- **别名**：不使用"行情刷新事件"、"价格推送"（推送暗示带 payload 的实时行情流，本信号只是失效通知）、与 `ledger:changed` 混称"失效信号"（不区分域）。
