# 领域词汇表：多端同步

> Ledger 领域词汇表的多端同步分域。全部分域与彼此关系见 `CONTEXT-MAP.md`；决策记录见 `docs/adr/`（ADR-0091）。
> 跨域共享术语（Transaction、Occurrence、加密模式、主口令、IdempotencyKey 等）见各分域词汇表，本文不复制定义。
> 若与代码行为冲突，以代码为准并同步修正本文件。

## Sync（多端同步）

- **定义**：多台设备经哑通道交换各自 OpLog 并确定性重放，使账本数据最终一致的能力；各端共享同一套域引擎与不变量（ADR-0091）。
- **边界**：
  - 同步 ≠ 备份：备份是文件级整库快照的替换式还原，同步是增量命令的合并式复制（备份域 Backup 词条已声明「备份 ≠ 同步」）。
  - 同步 ≠ 行情同步：投资域 InstrumentSync / InstrumentInfoSync 是单向外拉行情数据，不是多端复制。
  - 复制模型为零丢失：并发产生的 op 全部存活，不做快照轮替、不做 CRDT 存储层（取舍见 ADR-0091）。
- **别名**：不使用「数据同步」（与行情同步混淆）、「云同步」（前提是无自建服务端，通道是哑网盘而非云服务语义）。

## Transport（同步通道）

- **定义**：搬运同步文件的哑字节通道抽象，不理解载荷语义；两端以同一抽象对接（ADR-0091）。
- **边界**：
  - 通道不做任何合并与冲突处理——它是哑的，智能全在各端；通道后端选择（WebDAV / 本地网盘目录等）是可逆工程决策，不进 ADR。
- **别名**：不使用「云服务」（无自建服务端）、「推送通道」（无推送语义）。

## OpLog（操作日志）

- **定义**：各端本地追加的语义命令序列，同步的原子单位是 op；只追加、不改写（与 migration 只增不改同一纪律）。本机落库表 `sync_ops`，op 的身份与全序字段 + 语义命令载荷随行存储。
- **边界**：
  - 每条 op 携带来源 DeviceId、端内单调逻辑时钟与产生时的 schema 版本。
  - 本地 op 在写入接缝成功后随同一事务追加（产出接缝集中各域编排入口，不散落各写路径）；写失败连同回滚，不残留 op。
  - 派生数据（余额缓存、估值聚合、预算进度）不进日志——各端经既有接缝重算（与 ADR-0067「实时计算为审计权威」同一延伸）。
- **别名**：不使用「事件流」（易与失效信号系统混淆）、「变更日志」（未表达语义命令粒度）。

## DomainCommand（语义命令）

- **定义**：op 的载荷形态——与既有写入接缝同语义的域级命令（记一笔交易、修改计划、录入估值）；重放端经同一接缝执行，不绕过不变量。
- **边界**：
  - 被否决的粒度是行级变更：绕过写入接缝会把不变量（余额缓存重算、kind 折算、删除清理副作用）在各端重复实现一遍。
  - 重放是行为编排之外的新写入入口，接缝契约与批量导入同等待遇（「新增写入路径先核对各入口」纪律适用）。
- **别名**：不使用「操作指令」「命令事件」。

## Replay（重放）

- **定义**：接收端经写入接缝执行外来 op 的过程；必须确定性——命令自包含，折算在记账端一次性完成、折算输入与结果随 op 携带（源端折算），重放不依赖本地汇率表状态与设备配置。
- **边界**：
  - 源端折算消解「重放顺序 vs 汇率同步顺序」的耦合：FxRateHistory 何时到达不影响落库结果。
  - 重放幂等：同一 op 在同一端重复到达不产生第二次效果（按 op 标识去重；位点已覆盖的 op 由位点门拦下，见位点词条）。
- **别名**：不使用「回放」（口语变体）、「应用」（与行为层「应用」步骤撞词）。

## DeviceId（设备标识）

- **定义**：端在同步拓扑中的唯一标识，参与全序 tiebreak；落 `sync_device` 单行（连同端内单调逻辑时钟）。
- **边界**：
  - 新端加入 = 配置通道凭据（密文模式下另需主口令），DeviceId 本机自生成，无独立配对协议。
  - 换机、重装生成新 DeviceId 是合法路径；旧 op 流按原 DeviceId 保持可追溯。
- **别名**：不使用「设备名」（那是展示用标签）。

## TotalOrder（全序）

- **定义**：跨端 op 的确定性排序规则——按 (逻辑时钟, DeviceId) 排序，各端对同一批 op 排出唯一一致的顺序。
- **边界**：
  - 同实体同字段的并发编辑取序末者（LWW），v1 无冲突裁决 UI；输者仍在 OpLog 中可审计。
  - LWW 只裁决「op 都活着但打架」；op 本身永不丢弃（零丢失，ADR-0091）。
  - 裁决域是实体（命令指向的实体 id）；无实体指向的命令（如期次触发）冲突域在 OccurrenceKey，不参与同实体 LWW。
- **别名**：不使用「时间线排序」（排序依据是逻辑时钟，墙钟不可靠）。

## OccurrenceKey（期次幂等键）

- **定义**：定时计划期次触发 op 的确定性幂等键（plan_id + 期次标识；期次语义见定时计划域 Occurrence）；两台设备同时自动执行同一期不双扣。
- **边界**：
  - 期次标识取期次计划日期（跨端确定性；本地期次行 id 各端独立生成、不作身份），核心交易域 Transaction.date 直接复用该日期。
  - 期次落地的幂等由键派生的确定性交易 id 承载：同键跨端派生同一落地 id，双端同时执行天然收敛同一行、只落一次；落地已被用户删除时不自动复活（重放命中即跳过）。
  - 与 AI 导入域 IdempotencyKey 同构——同一确定性去重哲学在不同写入入口的落点。
- **别名**：不使用「触发去重键」。

## ParkedOp（挂起操作）

- **定义**：不可重放 op 的统一归宿：进入挂起队列、以码化错误通知用户裁决，不阻塞其余 op 重放。
- **边界**：
  - 覆盖两类场景：外键依赖失败（如 A 端删除账户、B 端往该账户记账）与 schema 版本偏斜（旧命令重放到新 schema，或旧端收到新命令）；重放中其他执行不了的命令同样入队，不中断批次。
  - 不静默兜底：不自动复活已删数据（与「缓存缺失报码化错误引导修复、不静默回退」同一品味）。
  - 出队由重投递自然承接：挂起 op 不在日志，依赖方补齐或旧端升级后重投递会再次重放，成功即出队；仍失败则按 op 幂等覆盖挂起行（重复投递不堆积）。
  - 并发「删除 vs 修改」以 LWW 取序末者：修改胜而重放命中软删行时不自动复活，修改 op 挂起待裁决。
- **别名**：不使用「冲突队列」（LWW 冲突不进队列，只有不可重放才挂起）、「死信队列」（偏消息中间件术语）。

## Checkpoint（检查点快照）

- **定义**：全量数据快照 + 各设备 op 流的已应用位点（见位点词条）；用于新端引导与 OpLog 截断，位点之后的 op 才需重放。语义约束只有一条——任何端永远能从 Checkpoint 加其后 op 重建出一致状态（确定性重建）。
- **边界**：
  - 快照是整库一致性快照（`VACUUM INTO`，与备份同构、继承源库加密形态，文件即真相）；位点与快照须同刻成对产出。
  - 新端引导：目标必须是尚未参与同步的库；引导整库换入快照（SQL 级重建，任意加密形态组合成立），换入本机设备身份、位点表以 Checkpoint 为准就位；快照携带的日志与挂起队列随行采纳（日志提供位点之前的去重身份，挂起行经重投递幂等覆盖自愈）。
  - 截断时机与位点采纳规则属确定性工程细节，三硬约束：只有来源设备有权截断自己的流；只有位点之前（时钟 ≤ 水位）才可删；挂起 op 不在日志、位点不越过它，天然不被截断。
  - **v1 永不截断**（issue #857 钉死）：op 无时间保留期限，只有位点安全义务；Checkpoint 只用于新端引导与位点推进，不做日志瘦身（增长量级 ≈ 几十 MB/年，简单性优先）；截断机制随本票实现但默认不启用，水位来源（各端上报位点的最小值 + 已并入对端可达 Checkpoint）是通道层义务。
- **别名**：不使用「全量同步」（混淆快照引导与增量复制两种形态）。

## StreamPosition（位点）

- **定义**：本机对各来源设备 op 流的「已应用位点」——该流上已裁决 op 的连续前缀水位；位点之前的 op 已全部并入本端状态（应用/去重/位点门跳过）或作为 LWW 输者落日志可追溯。落 `sync_stream_positions` 表。
- **边界**：
  - 位点永不越过未裁决的 op：挂起中的 op 不进日志（未应用），位点停在它之前（安全钉住），增量拉取仍会拿到它，重投递自然重试——这是「截断不丢失未应用 op」的机制根据。
  - 位点在截断后依然留存（水位不因日志缩短而回退），是本机「写视角」与通道「大家写视角」之间的桥；对端全量重投时，位点门拦住位点已覆盖与已截掉的 op，不复活、不重复。
  - 本机产出的 op 同样推进自己流的位点——源端截掉旧 op 后，位点门拦住对端重投的本机旧 op。
- **别名**：不使用「游标」「偏移量」（偏流式处理术语，位点语义是已应用水位）。「Seq」不用（op 的流内地址是逻辑时钟，非独立序号）。

## SyncEnvelope（同步信封）

- **定义**：通道上传输的加密整包（Checkpoint 与 OpLog 文件），密钥由主口令经密钥派生导出（加密机制见备份域 加密模式 / 主口令）。
- **边界**：
  - 与备份同构：加密模式下通道上只有密文；未开加密模式时信封为明文，界面显著提示。
  - 主口令不随信封走，新端凭用户输入的口令开包（与密文备份恢复同形态）。
- **别名**：不使用「同步包」（口语）、「加密层」（偏实现分层）。

## SyncBoundary（同步边界）

- **定义**：什么随同步走、什么留在本机的划界，与 Backup/Restore 的迁移边界对齐：各业务域数据（核心交易、定时计划、投资、参考数据、预算、保险、物品、实物资产）同步；界面状态、ViewState、轻量设置项（设备偏好）不同步。
- **边界**：唯一特殊成员是 DefaultCurrency 的本位币基准——升格为账本级设置随同步走（见参考数据与设置域 LedgerLevelSetting），前端展示币种偏好仍留在本机。
- **别名**：不使用「同步范围」（口语）。
