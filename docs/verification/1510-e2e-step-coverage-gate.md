# e2e 步骤库覆盖守门（issue #1510 / 父 spec #1494）

> 本票是 spec #1494「严格编译期步骤校验」决策冲突的**裁决落地**：rstest-bdd 0.6.0
> 的 compile-time-validation 只挂在 `#[scenario]` 属性路径，`scenarios!` 生成路径
> 不调用校验；全量改用 `#[scenario]` 需 453 个手工绑定函数且新增场景静默漏跑
> （实测与代价见 #1494 / #1510 讨论）。故以**静态覆盖守门**替代编译期校验，保留
> `scenarios!` 的零维护绑定。本文件记录口径、实测数字、负向证据与已知边界。

## 交付物

- 守门脚本（Bun 运行时，ADR-0083）：逐 e2e 目标核对「feature 步骤行 ↔ 目标注册面」
  全等覆盖，并要求每个 feature 至少被一个 e2e 目标绑定。Rust 侧注释掩码复用结构
  守门的 TS 掩码实现（注释掩去、字面量保留），不新建第二份词法器。
- 夹具测试（vitest，10 例）：8 条守门行为用例（1 绿基线 + 7 负向）+ 2 条接线锁。
- 接线：挂 `scripts/check.sh` 与 CI frontend job；两处接线各由一条用例锁死
  （摘掉任一执行行即红，先例 `check-sh-gate-off.test.ts`）。

## 口径（逐 e2e 目标）

1. **绑定面自源码派生**：cucumber 目标的 `filter_run("<dir>")`（目录递归）与
   rstest-bdd 目标的 `scenarios!("<path>")`（文件或目录）；不维护手工目标清单。
2. **注册面取本目标的运行器族**：目标经 `#[path …] mod …;`（含嵌套 `mod x;`，
   `e2e/scheduled_steps.rs` 形态）纳入的步骤文件里，cucumber 目标只读
   `#[given/when/then(expr = "…")]`，rstest-bdd 目标只读
   `#[rstest_bdd_macros::given/when/then("…")]`——**双注册文件里两族属性共存，
   各目标只消费自己那族**，不互为歧义（该模型正是门在自检时抓出的第一版缺陷）。
3. **判定**：被绑 feature 的每条步骤行在同目标注册面内**恰好一次**匹配；占位符按
   语义转匹配式（cucumber `{string}`/`{int}`/`{float}`/`{word}`；rstest-bdd
   `{<名>:string|整数族|浮点族}`），`And`/`But` 继承前一关键字（与 Gherkin 同义）。
4. **全覆盖**：`tests/e2e/features/**` 每个 feature 至少被一个 e2e 目标绑定——
   删掉绑定（如 `scenarios!`）即红，补上 #1495 AC4「0 场景且退出码 0」的缺口。

迁移期语义：同一 feature 可同时被 cucumber 目标与新目标绑定（双轨期），只要每个
绑定它的目标都覆盖其全部步骤即可；收口删掉 cucumber 目标后口径不变、无需改门。

## 实测（本机 macOS arm64）

| 场景 | 结果 |
| --- | --- |
| 本仓现状（cucumber 单目标） | 目标 1 · 绑定 feature 40 · 步骤行 3139 · 注册 724 · 未覆盖 0 · 歧义 0 · 无绑定 0 |
| 双目标形态（对 #1509 worktree 同门核验） | 目标 2 · rstest-bdd 目标绑定 1 feature／20 注册／54 步骤；cucumber 目标 40／724／3139 · 未覆盖 0 · 歧义 0 |
| 与运行期口径对齐 | 门报出的 3139 条步骤行与旧 cucumber 运行 `3139 steps (3139 passed)` 逐数一致——匹配式与实际运行器口径同构的旁证 |

## 负向证据（每条都是夹具上的一次真实变红）

| 用例 | 制造方式 | 观测 |
| --- | --- | --- |
| 删步骤注册 | 去掉一条 `#[when(expr = …)]` | 退出 1，报 `未覆盖 …创建交易 金额 100` |
| feature 新增步骤 | 场景里加 `And 删除账户 "现金"` | 退出 1，报 `未覆盖 …删除账户 "现金"` |
| feature 无目标绑定 | 删 `filter_run(…)` 绑定行 | 退出 1，报 `无目标绑定` |
| **rstest 目标删 `scenarios!` 绑定** | 夹具只留 rstest 目标，删绑定行 | 退出 1，报 `无目标绑定`（#1495 AC4 缺口封口） |
| 同族重复注册 | 再写一条相同模式 | 退出 1，报 `同一注册重复` |
| 跨族双注册 | 同一函数同时挂两族属性，两目标同绑一个 feature | 退出 0，`目标 2 个`（防把双注册误报为重复） |
| 歧义 | 同一步骤行被 `{int}` 与 `{float}` 两条模式同时命中 | 退出 1，报 `歧义` |
| 接线锁 ×2 | 摘掉 `check.sh` / CI 的执行行 | 对应用例红 |

## 已知边界（fail loud，不静默放过）

- `Scenario Outline` / `Examples` 的 `<占位符>` 替换未纳入口径：出现即报「已知边界」
  并要求扩展守门（当前仓 40 个 feature / 453 个 Scenario 块 / 0 个 Outline）。
- `regex = "…"` 注册形态未支持：出现即报（当前仓零命中，全部为 `expr =`）。
- 未知占位符 / 未知类型提示按「任意非空」处理并留痕（不静默按字面量匹配）。

## 与相邻守门的边界

#1496 管「测试目标是否在调度面（目标不漏跑）」；本门管「feature ↔ 目标 ↔ 步骤
注册」的对应关系。两者互补：删目标文件由 #1496 的覆盖守门抓，删绑定 / 删注册 /
错配由本门抓。
