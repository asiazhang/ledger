# 手动冒烟清单：本机记住主口令（issue #574 / ADR-0075 决策 3/5）

> 验收节点：钥匙串缓存 + macOS 生物认证门属于运行期真实系统行为（系统钥匙串、
> Touch ID / Face ID 提示），**无法**在 CI/Vitest 中可靠自动化，按 issue #574
> acceptance criteria 以本清单人工冒烟记录验收。自动化覆盖（Vitest）见
> `src/__tests__/UnlockScreen.test.ts`（解锁屏缓存路径逻辑）与
> `src/__tests__/EncryptionSettings.test.ts`（偏好开关）。
>
> 前置：本机为 macOS（v1 仅 macOS 支持），已进入设置页「数据 → 加密」卡片。
> 运行形态决定缓存条目形态（issue #662）：**发布构建**条目带 Touch ID 生物认证门，
> 要求 Apple 证书背书的钥匙串 entitlement（未接入签名身份时建立/读取报
> 「当前构建受限」错误，见第 9 节）；**开发/未签名构建**（`tauri dev` / debug）
> 降级为无门缓存回退（第 10 节），不依赖签名进度即可用。
>
> 冒烟分组执行：第 1–8 节在发布构建（接入签名身份后）验收生物门形态；第 9 节在
> 未接签名身份的发布构建验收「当前构建受限」错误；第 10 节在开发/未签名构建
> 验收无门回退形态。

## 1. 开启「记住」→ 重启免手输自动解锁

- [ ] 在明文库设置页开启加密，勾选「在本机记住主口令」，输入主口令并确认。
- [ ] 转换成功并自动重启；重启后出现「正在尝试自动解锁…」加载态。
- [ ] macOS 弹出 Touch ID / Face ID 生物认证提示；认证通过后**免手输**直接进入应用
  （未出现口令输入框）。
- [ ] 关闭应用并再次启动，仍凭生物认证自动进入（每次启动都有缓存 → 自动解锁）。

## 2. macOS 生物认证：取消 → 回退手输

- [ ] 启动进入自动解锁时**取消**生物认证（按 ESC / 关闭提示）。
- [ ] 应用**不报错、不卡死**，回退到手输解锁屏，口令输入框可正常输入并解锁。
- [ ] 解锁屏出现回退提示（「生物认证已取消，请手动输入主口令」）。

## 3. 钥匙串无缓存 / 被清 → 回退手输

- [ ] 用 `security delete-generic-password -a master-passphrase -s com.zhangheng.ledger`
  （或「钥匙串访问」删除对应条目）清掉缓存。
- [ ] 重启进入自动解锁时**不弹生物认证且不报错**（无条目 → 无缓存即回退），直接显示手输
  解锁屏，口令输入可正常解锁。
- [ ] 若重新用手输解锁并勾选「记住」，缓存重建、下次重启恢复自动解锁。

## 4. 关闭「记住」→ 恢复手输

- [ ] 已加密且已打开应用的设置页：「本机记住主口令」开关置为关闭。
- [ ] 关闭后重启，不再出现自动解锁，直接显示手输解锁屏。
- [ ] 开关关闭后钥匙串条目被清除（`security find-generic-password` 应查不到）。

## 5. 修改主口令与「记住」同步

- [ ] 已加密 + 已开「记住」：设置页修改主口令（保持勾选「记住」）。
- [ ] 修改成功重启后，凭**新口令**的生物认证自动解锁（旧口令失效）。

## 6. 关闭加密 / 忘记口令重置 → 清缓存

- [ ] 关闭加密后重启：不再出现解锁屏（明文库启动）；钥匙串条目被清除。
- [ ] 忘记口令重置后：进入全新明文空库；钥匙串条目被清除（不残留可自动解锁的旧口令）。

## 7. 跨设备可移植性（缓存内容为主口令本身）

- [ ] 开启「记住」后制作的加密备份，在其他设备/恢复还原时凭该口令可正常恢复解锁
  （密钥由口令派生，不依赖本机钥匙串）。

## 8. 不支持平台：隐藏选项

- [ ] Windows / Linux：设置页加密卡片与解锁屏**不出现**「记住」选项，全程手输主口令。

## 9. 发布构建·未接入签名身份：当前构建受限（-34018 专属错误）

- [ ] 发布构建（未接签名身份，ad-hoc 签名）开启「记住」：报「系统钥匙串访问受当前
  构建签名形态限制（缺少 Apple 证书背书的钥匙串权限）」，**不**误报「生物认证未启用」。
- [ ] 启动自动解锁若遇同条件失败：回退手输，错误提示同上（不弹 Touch ID、不报裸 IO 错误）。

## 10. 开发/未签名构建：无门回退（issue #662）

> 实证边界（#662 探针，macOS 26.6.2 arm64）：数据保护钥匙串对未签名/ad-hoc
> 进程同样报 -34018（先例 block/buzz#1266），故无门条目落**传统钥匙串**。

- [ ] `tauri dev` / debug 构建设置页加密卡片显示「当前为开发构建」提示（本机缓存不带
  Touch ID 门），与发布形态可区分。
- [ ] 开启「记住」（提示开发回退形态）→ 重启后**免手输、无 Touch ID 弹窗**直接进入。
- [ ] 重编译后再启动（ad-hoc cdhash 变化；#662 实测跨 cdhash 读取会触发批准交互）：
  首次读取弹「允许访问钥匙串」批准框——点「允许」当次通过、自动解锁照常完成；
  点「始终允许」可覆盖该二进制的后续启动；点「拒绝」读取失败、回退手输。
  再重编译后重新弹（已知可接受，仅 dev）。
- [ ] 关闭「记住」后重启：回退手输；条目与偏好同步清除（`security find-generic-password
  -a master-passphrase -s com.zhangheng.ledger` 查不到）。
- [ ] 形态切换不留混合条目：同一 service/account、store 先删后建——开发构建与发布
  构建先后开关一次，传统钥匙串中始终只有一个形态的条目（无残留旧口令）。
