# NSH 立桩验收执行手册——硬伤清单对表（issue #2024 AC1 备料）

- 性质：**执行手册与记录槽，不是验收记录**。对表结论（各体感项的红/绿判断）归人类执行后回填 #2015；本文件只提供每项的具体操作步骤、需记录的数值与判读口径。自动化可断言的部分已由 headless 测试承担（§5），本手册管 headless 断言不了的面（渲染/迟滞/输入延迟/常驻内存/IME，research doc §2.5 的归属表）。
- 判据来源：ADR-0145 硬伤清单（决策 8 立桩靶标）＋ spec #2015 Further Notes 对表清单（无需禁用环境变量即正常渲染；100 行翻页无可感知迟滞；输入无可感知延迟；常驻内存与旧壳对照；无闪烁/字体/分数缩放缺陷；中文 IME 正常）。
- 分页口径：立桩为 **100 行/页**（#2015 修订记录，#2018 起；旧壳 50 行/页是 #2010 迟滞触发点，立桩翻倍验证原生余量）。

## 1. 环境准备

```sh
# 构建立桩应用（bin = nsh-app，Linux 平台后端 GTK4）
( cd src-tauri && cargo build -p nsh-app )

# 性能数据集（ADR-0062 唯一确定性生成器；默认 50 万笔，几十秒；
# 同参数必出同库；默认输出在 target 下，--out 指到专用目录更顺手）
( cd src-tauri && cargo run --bin ledger-perf -- generate --out /tmp/nsh-acceptance/ledger.db )

# 启动立桩应用（启动参数 = 账本目录，目录内含 ledger.db；无解锁向导/设置页）
./src-tauri/target/debug/nsh-app /tmp/nsh-acceptance

# 旧壳对照（日常开发形态；打开库的方式以旧壳当时启动参数为准）
pnpm tauri dev
```

- 生成器输出的摘要行（accounts/transactions/软删数/购买项行数等）是数据规模记录槽，对表时原样誊入 #2015 记录。
- 常驻内存对照优先两壳开**同一本库**（规模相同才有对照意义）；若旧壳无法指向生成库，则两壳各开同量级库并在记录中注明规模差异。
- 自动化侧已在 2000 笔缩量数据集（同一生成器，约 20 页）上核过计数一致性（§5）；体感面必须用全量级库实测。

## 2. 逐项对表操作

每项格式：操作步骤 → 需记录的数值 → 判读口径。判读只给口径，结论由执行人填。

### ① 无需禁用环境变量即正常渲染（DMA-BUF）

- 步骤：桌面会话（Hyprland/Wayland）直接跑 §1 启动命令，**不设任何 `WEBKIT_*` 环境变量**（旧壳必需 `WEBKIT_DISABLE_DMABUF_RENDERER=1`，#2010；NSH 走 GTK4，预期无此类需求）。观察首屏表格、分页条、期间步进器、搜索框是否正常呈现并可交互。
- 记录：启动命令、桌面环境与合成器版本（`hyprctl version`）、stderr 有无渲染告警、首屏截图（可选）。
- 判读：窗口正常渲染且可交互、无花屏/空白 = 通过；任何需要环境变量才能正常渲染的形态 = 不通过（硬伤未消失）。

### ② 100 行翻页无可感知迟滞（数据集量级）

- 步骤：打开 50 万笔生成库，就绪后：裸键 `]` / `[` 连续翻页 ≥ 20 次（覆盖首页→末页往返与边界幂等），再点分页条页码按钮与「上一页/下一页」各数次；观察每次行集换血是否即时。
- 记录：体感分级（即时 / 轻微 / 明显）逐路径记录；连翻 20 次的主观累计；可选秒表计 10 次翻页总耗时（记录用，非阈值）。对照基线 = 旧壳同库翻页（#2010 实测数百 ms/页）。
- 判据：「无可感知迟滞」为体感结论，执行人记录后回填；自动化侧不设时间断言（「Counts are deterministic; timings are not」，research doc §1.5）。

### ③ 输入无可感知延迟

- 步骤：搜索框逐键输入英文与中文（IME 开启）、退格、回车提交；期间观察字符回显与候选框跟随。
- 记录：键入回显即时性（体感分级）；composing 期间有无卡顿；与 ⑥ 合并记录 IME 侧观察。
- 判据：「无可感知延迟」为体感结论，执行人记录。

### ④ 常驻内存与旧壳对照

- 步骤：两壳各开同一本 50 万笔库，静置 1 分钟后与连续翻页 20 次后各记一次常驻内存：

  ```sh
  grep VmRSS /proc/$(pgrep -xf '目标进程名')/status
  ```

  NSH 侧进程 = `nsh-app`；旧壳在 `tauri dev` 下是多进程，取承载主窗口的进程（`ps aux` 辅以系统监视器判别）。
- 记录：四个数值（NSH/旧壳 × 静置/翻页后，KB）+ 库规模 + 桌面环境。若旧壳只能开日常库，记录其库规模并在结论中注明不可完全同口径。
- 判读：给出两壳数值与倍率即可，阈值由执行人结合 #2010 语境判读。

### ⑤ 无闪烁 / 字体 / 分数缩放缺陷

- 步骤（三个子形态各自观察 ≥ 1 分钟）：
  - 深浅色：切换系统外观，观察表格文字/金额语义色随动（双态色值已由 headless `app_window_colors_amount_cells_by_kind_semantic` 断言，真实窗口复核呈现）。
  - 字体：中文、数字分组（`1,234.56` 形态）、`¥` 符号的渲染清晰度。
  - 分数缩放：Hyprland monitor `scale` 依次 1 / 1.25 / 1.5 各启动一次，观察模糊与错位。
- 记录：每形态有无闪烁、模糊、错位、破图。
- 判读：任一形态出现可复现渲染缺陷即按 ADR-0145 硬伤清单语义记录（不通过项）。

### ⑥ 中文 IME 正常（清单已在 #2023 留档，直接引用）

- 验收清单 = #2023 AC2：候选框跟随定位、焦点不漂移、composing 期间 `[`/`]`/`,`/`.` 与搜索触发不误动作；人工验收记录留档 #2023，本手册不重复。
- 补充实测点（与 headless 观察钉同表复核，见 §4）：搜索框中文输入后回车提交（单行输入回车 = 失焦提交），再按 `,`/`.` 应步进期间、且不再向查询追加字符。

## 4. 搜索 × 期间组合语义实测观察（备料交付②）

集成分支合并时报告的两处未定义组合，headless 观察钉 `search_and_period_combo_keys_pins_actual_behavior`（`src-tauri/crates/nsh/tests/app_headless.rs`）已记录引擎侧现状（可执行证据，非规格裁决；后续票定义语义时应有意更新该钉）：

1. **组合②（搜索期间期间标签显示）**：期间标签照常显示且不重置——「全部」态呈「选择期间」召唤文案，有游标呈当期标签；搜索只换行集与计数词，不动期间快照。
2. **期间过滤对搜索命中面不生效**：当月期间下搜索，上月备注照样命中（搜索读路径 `boot::transaction_search` 无区间参数，`load` 按非空查询走搜索路径）。
3. **组合①（搜索期间按 `,`/`.`）焦点在框**（输入后默认态）：键被输入框吃掉（When::Auto 可编辑焦点闸不派发）——查询追加字符触发重搜（「支出,」→ 命中 0 条），期间步进不发生。
4. **组合①焦点在框外**（回车提交 BlurAndSubmit 失焦后）：键照常派发——期间快照步进、标签随之变化，行集与命中数原样（搜索重读不携期间，唯一可观察变化是标签）。
5. 附带记录：headless 逻辑点击不转移键盘焦点（press 是逻辑派发非物理命中）；点击步进器在搜索态同样只换标签不动行集。

真实窗口复核点（人工，并入 §2 ⑥/③ 执行）：上列 1/2/4 在 GTK4 真实窗口是否同表（尤其 IME composing 中的按键路径与焦点转移时机——真实输入法栈与 headless 引擎路径不同）。
