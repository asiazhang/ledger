## 0. 结论摘要

1. **四个病灶是同一结构性根因（视觉常量无单一来源）的四个切面**【实测】：字号裸调 643 处 13 种取值、`app_class` 431 处指向出厂 palette、控件与间距规格各视图自定——逐处手改无法收敛，必须先立来源再改值。
2. **「颜色无主权」的根因是壳内没有 `nsh.json`**【实测】：主题整体落在 NSH 出厂默认 shadcn `neutral`（黑白灰 + 10pt 圆角）——不是选得差，是从未选过。NSH 主题文件机制（shadcn `cssVars` 格式、亮暗双态、覆盖式只写差异、自定义令牌经 `theme().color()` / `bg-*` 类消费）在 Rust 模式原生可用【一手】。
3. **spotish 的可移植三件套**＝主题令牌表（`theme.json`）＋视觉规约（`DESIGN.md`：字阶表、圆角同心规则、间距语法、控件规格、表面层级）＋组件封装单点（每件 `nsh/base` 只包一次）【一手】。三件全部模式无关（TSX 实现细节不在移植面内），映射到本仓＝ADR-0147 决策 1–3。
4. **NSH 官方设计指南本身就强制同一纪律**【一手】：app 必须自建 ui 层、视图禁裸样式、禁裸 hex 与 palette 类、字阶 ≈12/14/16/18/20pt、间距 2/4/8/12/16/24/32pt、桌面控件高 24–32pt（默认 32）、同心圆角「内 ≈ max(0, 外 − 缝)」。本仓现状正是指南点名的「无自有组件层的漂移」形态【推断】。
5. **落地节奏裁决为双轨**（ADR-0147 决策 3）：常量模块 + 规约先止血，视图随触碰渐进收口进壳内 ui 层——一次性建全 ui 层等于第二场重写；官方指南对既有应用的原话即「先检查并扩展既有地基」【一手】。
6. **Omarchy 系统主题派生跟随否决**（ADR-0147 决策 5）：spotish 的 palette 派生（信 4 个系统色 + 对比度校验派生全表）工程量成套，主题主权先行；列为可选后续另票【推断】。

## 1. 本仓病灶量化【实测】

统计口径：`src-app/src/` 顶层模块（壳根包，68 个 `.rs`），2026-11-11。

| 病灶 | 证据 |
|---|---|
| 字号无层级 | `text_size(px(…))` 共 **643 处**：12px×288、13px×236、11px×67、16×16、14×11、15×7、20×4、18×4、28×3、24×2、22×2、10×2、9×1——**13 种字号并存**，12/13/11 三个近邻值承担了 92% 的正文排版，层级靠手感 |
| 颜色无主权 | 壳内**无 `nsh.json`**（全仓 find 无命中、未被 gitignore）→ 主题 = NSH 出厂默认 shadcn `neutral`；`app_class(` 共 **431 处**，token 类（`bg-background`/`text-muted-foreground`/`bg-accent`…）全部指向出厂 palette；裸 hex 已基本绝迹（仅 2 处注释引用旧壳色值：走势线主色 `#2080f0`、警告色沿旧壳 naive-ui 值）——但业务/UI 语义色以常量散落模块内（`plot_line`、`danger`） |
| 控件尺寸不齐 | 按钮/输入框/菜单内边距与高度各视图直写（`px-2 py-1` 等类散见），无控件规格文档、无尺寸常量 |
| 间距/圆角随意 | 无间距尺度、无圆角阶，圆角值散写；无同心圆角约束 |

配套事实：壳内无任何视觉规约文档（`CONTEXT-ui-interaction.md` 管交互语义不管视觉）；外观设置（#2053）只管设备级亮暗强指，不持出厂观感。

## 2. spotish UI 系统解剖【一手】

### 2.1 主题令牌表（`theme.json`）

- shadcn `cssVars` 格式，三段：`theme`（双态共用的圆角阶 `radius` 8 / `radius-card` 12 / `radius-panel` 16 / `radius-inset` 8 与 `font-mono`）、`light`、`dark`。
- UI 语义名全表（background/foreground/card/popover/primary/secondary/muted/accent/destructive/border/input/ring/sidebar 族/shell/player/control/control-foreground/row-hover/chart-1…5）+ 自有语义（`liked`/`liked-foreground`）。`var(--…)` 引用同表令牌，亮暗各持一套值。
- `nsh.json` 挂 `"theme": "theme.json"` + `"appearance": "system"`；亮暗切换原生生效。

### 2.2 视觉规约（`docs/DESIGN.md`）

叠于 NSH 官方设计指南之上（「规则相左时，spotish 的赢」）。骨架与本仓可直接对齐的要点：

- **原则**：自有观感（信息架构借 Spotify、观感自立）、暗色安静平坦、光只属于音乐光、紧凑、快与轻（无变化不重绘、可增长必虚拟化）。
- **色彩规则**：一切颜色走令牌；控件永不上色（`tint()` = foreground，白控件压任何封面）；primary 按钮用 `foreground` 不用强调色（强调色只留给小面）；弹层实色不透灰。
- **字阶表**（用途 → 类）：页面大标题 `text-4xl`、集合名 `text-3xl`、节标题/弹窗题 `text-xl`、正文/行题/菜单/按钮 `text-sm`、次级 `text-xs`、overline `text-[11px]` 大写加字距；时刻与计数等宽字体 tabular figures 防抖动。
- **圆角**：四档令牌 + 同心规则「内 = 外 − 缝」（面板 16 内嵌行 8 于 8pt 缝）；按钮全圆（pill/disc）。
- **间距**：页面沟 12pt、面板嵌入四边同值 8pt、列表行距 4pt、壳周 8pt。
- **表面与层级**：页面平坦、面板 1px 边框无阴影、弹层/对话框/吐司各自规格、浮层元素带柔和阴影；「不做玻璃」（每滚动帧省一整页截图）。
- **组件规格**：侧栏行 44 高/图标 22pt、卡片 144 宽（黄金比例播放键）、曲目行 48 高、集合头 96pt 封面、按钮三型（IconButton/PlayButton/ActionButton 各带尺寸档）、滑条无拇指点、播放条 72 高 pill 三档宽度布局、Now Playing 全屏表面规则。
- **系统跟随（本仓否决项，见 §6）**：Omarchy 上读主题文件实时跟随，只信系统 4 色（background/foreground/accent/red），对比度校验派生全表（foreground 7:1、primary 3:1、表面 6–15% 阶梯、muted-foreground 4.5:1）。

### 2.3 动效令牌（`tokens.ts`）——范围外，记录存在

一套时长（120–520ms 五档）/缓动/距离/缩放常量，全 app 动效唯一来源。本次裁决不动效（病灶四项不含），移植清单不收；后续若立动效票，此件是蓝本。

### 2.4 组件封装单点

每件 `nsh/base` 组件只包一次（`src/components/ui/`），带变体与尺寸；页面只组合不自行造型。与 NSH 官方指南「app ui 层」章节互为印证（见 §3）。

## 3. NSH 官方机制与强制项【一手】

### 3.1 主题加载（Rust 模式同等适用）

- `nsh.json` `"theme"` 键指向主题文件（或内联），shadcn `cssVars` 格式；tweakcn / shadcn themes 导出直接可用；**覆盖式**——只写要改的令牌，未写的沿用默认。
- 自定义令牌：`"up": "#16a34a"` → Rust `theme().color("up")`、类 `bg-up` / `text-up/70`；数字令牌 `"radius-card": "14px"` → `theme().number("radius-card")` / `rounded-(--radius-card)`。
- 每令牌亮暗各一值，系统外观切换原生换色、无重渲染；bundler 构建期校验主题文件（缺文件/坏 JSON/非 cssVars 即构建失败）。
- 默认主题 = shadcn `neutral`（黑白灰、10pt 圆角）——本仓现状的出处。

### 3.2 设计指南强制项（与病灶一一对应）

- **必须先立设计系统**：「Establish the app's design system first……For an existing app, inspect and extend those foundations first」；标准文件进仓库，「人和编码 agent 用同一套决策」。
- **app 自有 ui 层**：`src/ui/` 一文件一件、有限 API（variant/size/状态/内容槽），look 内聚件内；「Features compose ui, they do not style」——视图禁直连 `nsh/base` 控件、禁写颜色/圆角/字号、禁手搓控件。无此层的 app「每个屏幕各造各的按钮，功能一多设计与行为就不再互相同意」。
- **禁裸值**：应用 UI 不得出现裸 hex / `rgb()` / `hsl()` / palette 类（`bg-zinc-100`）；缺角色先加令牌再使用。
- **数值规范**：字阶 ≈12/14/16/18/20pt；间距语义阶 2/4/8/12/16/24/32pt（关系优先：件内 4、近亲 8、同组 12、组间 16/24、区界 32）；桌面控件高 24–32pt（默认 32）、图标 14–16pt、行 28–36pt；同心圆角「内 ≈ max(0, 外 − 缝)」、圆角须小于短边之半；对齐脊线与「差一渲染像素即缺陷」的不变量。
- **状态与双验**：hover/pressed/focus/selected/disabled/loading/validation 各态须有一致处理；每个自定义表面亮暗双态 + 自定义主题值下验看。

### 3.3 Rust 模式样式双路

typed 方法（`text_sm()`、`.p_4()`、`.rounded(move || theme().radius)`）与 `app_class` 类字符串两路皆通；官方建议组件自身样式用 typed、跨件注入用 `app_class`。本仓现有 431 处 `app_class` 与 643 处 `text_size` 裸调即两条路的无纪律用法【推断：收口时不强制二选一，收口对象是「值的来源」不是「书写方式」】。

## 4. 三件套移植映射

| spotish 件 | 本仓落点（ADR-0147） | 形态 |
|---|---|---|
| `theme.json` + `nsh.json` | 决策 1：主题令牌表 | shadcn cssVars、亮暗双态、shadcn 标准名 + 自有令牌（盈亏涨跌/警告/图表系列色收编散落常量） |
| `docs/DESIGN.md` | 决策 2：`docs/DESIGN.md` 视觉唯一真源 | 原则→色彩→字阶→形状间距→表面→组件规格；视图零裸值，例外挂账 |
| ui 层封装单点 | 决策 3：壳内 ui 层双轨 | 蓝图＝正典封装层；落地＝设计常量模块（字阶/间距/圆角）止血 + 既有封装族（ADR-0118 NSH 后继）渐进收口 |
| 官方规范数值 | 决策 4：直接采用 | 字阶 12/14/16/18/20、间距 2/4/8/12/16/24/32、radius 8/12/16 + inset、控件 32 默认高；表格行高落地微调 |
| Omarchy palette 派生 | 决策 5：否决，可选后续 | 信 4 系统色 + 对比度派生全表；工程量成套，另票再议 |

模式无关性：三件套全部不依赖 TSX/QuickJS——主题文件由框架加载、规约是文档、常量模块与封装层在 Rust 侧同构成立【一手：rust.md 主题节为 Rust 模式原生 API】。

## 5. 落地票建议清单（拆步顺序）

1. **票 1（止血 + 主权，单票可交付）**：
   - 引入 `nsh.json`（含 `"theme"`、`"appearance"` 与壳元信息）+ 主题令牌表初版：shadcn 标准名亮暗双态 + 自有令牌（走势主色、危险/警告、涨跌色自 `plot_line`/`danger` 等散落常量收编）；
   - 立 `docs/DESIGN.md` 骨架（原则/色彩/字阶/形状间距/表面/组件规格，数值按决策 4）；
   - 立设计常量模块（字阶/间距/圆角唯一来源，壳根包内）；
   - 散落语义色常量改走令牌。
   - 验收口径建议：出厂观感脱离 neutral（对照截图）；`plot_line`/`danger` 无本地色常量。
2. **票 2…N（逐视图收口）**：按视图批次把裸 `text_size(px(…))` 换字阶常量、控件内边距对齐规格、圆角对齐尺度；每票一批视图、独立可回滚。守门建议：源码扫描新增裸 `text_size(px(` 直调即红（接线型负向判据的扫描形态，先例 #959/#961），挂入既有检查脚本时点由实施票定。
3. **可选票（另立）**：Omarchy 系统主题派生跟随（§2.2 算法要点已在，工程量成套）；动效令牌（§2.3 蓝本）；组件画廊页（官方「Show it」建议——每组件每变体每状态亮暗双验的调试页）。

## 6. 范围外与显式不做

- 动效系统（病灶不含，蓝本已记录）；
- TSX 专属实现细节（模式张力分支已闭，ADR-0145 决策 1 不动摇）；
- spotish 其余七维度（引擎接缝/测试/打包/更新器/依赖纪律/多形态 shells/工程文档纪律）——本次裁决不参考，本文不为它们留移植判断；
- 与旧壳的视觉对齐：原生壳观感自立（ADR-0145「观感从平台控件、不复刻 naive-ui」口径的延伸——本次是把「自立」从口号落成令牌表）。
