多端同步：原理与流程

Ledger · 依据 ADR-0091 与多端同步域词汇表（CONTEXT-sync.md）编写 · 2026-09-08

一句话原理：每台设备把记账动作记成语义命令操作日志（OpLog），经网盘上的哑通道（Transport）交换密文信封，各端经既有写入接缝确定性重放（Replay），最终一致且零丢失——没有自建服务端，智能全在各端，通道只搬字节。

1. 核心概念

术语是什么关键性质
OpLog 操作日志各端本地追加的语义命令序列，同步的原子单位是 op只增不改；op 携带 DeviceId、逻辑时钟、schema 版本
DomainCommand 语义命令op 的载荷：与既有写入接缝同语义的域级命令重放走同一接缝，不绕过不变量
Replay 重放接收端经写入接缝执行外来 op确定性：源端折算、折算结果随 op 走；幂等去重
TotalOrder / LWW 全序(逻辑时钟, DeviceId) 排出唯一一致顺序同字段并发编辑取序末者，输者可审计
OccurrenceKey 期次幂等键plan_id + 期次的确定性去重键两台设备同时自动执行同一期不双扣
ParkedOp 挂起操作不可重放 op 的统一归宿码化错误通知、不阻塞、不静默兜底
Checkpoint 检查点快照全量快照 + 各流已应用位点新端引导与日志截断；快照+增量=一致状态
SyncEnvelope 同步信封通道上传输的加密整包密钥由主口令派生；主口令不随信封走
Transport 同步通道网盘上的哑字节通道（v1 内置 WebDAV）不理解内容、不做合并
DeviceId 设备标识端在同步拓扑中的唯一标识本机自生成，参与全序 tiebreak

2. 架构总览

两个端运行同一套 Rust 域引擎（ADR-0056：域不依赖壳）。引擎向上经既有写入接缝读写账本，向下把 op 打包成加密信封丢进哑通道。通道两侧完全对称，没有服务端角色。

"重放 op" .-> A2 A1 --- A5 end subgraph T["哑通道（网盘 WebDAV 目录）"] E[("SyncEnvelope 加密整包：Checkpoint + OpLog 文件")] end subgraph DB["设备 B（Android）"] B5["同步引擎：合并 · 重放 · 挂起 · Checkpoint"] --> B6["op 重放"] B6 --> B2["行为编排入口（既有写接缝）"] B2 --> B1[("SQLite 账本")] B4[("OpLog（只增不改）")] --> B5 B1 -. "本端写入产 op" .-> B4 end A5 <--> |"上传 / 拉取密文"| E E <--> |"拉取 / 上传密文"| B5
注意两条铁律：① 通道不理解载荷，被拷走的只是密文（加密模式）；② 派生数据（余额缓存、估值聚合、预算进度）永不进日志——各端重算，「实时计算为审计权威」原则自然延伸到同步。

3. 一次同步的完整时序

以「设备 A 记一笔交易，设备 B 稍后打开应用」为例。写入即时入队上传，把双端并发编辑的窗口压到最小。

sequenceDiagram autonumber actor U1 as 用户（设备 A） participant E1 as 同步引擎 A participant T as WebDAV 哑通道 participant E2 as 同步引擎 B actor U2 as 用户（设备 B） U1->>E1: 记一笔交易（100 USD） E1->>E1: 行为编排入口执行，源端折算（结果随 op 走） E1->>E1: 追加 op（DeviceId · 逻辑时钟 · schema 版本） E1->>T: 即时入队：上传 SyncEnvelope（密文） U2->>E2: 打开应用（或轮询命中） E2->>T: 拉取新信封 T-->>E2: 密文 E2->>E2: 解密（密钥由主口令派生，口令不落盘不传输） E2->>E2: 跨端 op 排全序（逻辑时钟, DeviceId） loop 每条到达的 op E2->>E2: op 标识已见过？——是则丢弃（幂等） alt 可重放（引用完好、schema 兼容） E2->>E2: 经写入接缝重放 → 余额缓存等派生数据同事务重算 else 不可重放 E2->>E2: ParkedOp 挂起 + 码化错误通知（不阻塞其余 op） end end E2-->>U2: 账本与设备 A 最终一致

4. 单条 op 的到达决策

引擎对每条外来 op 只做三个判断：见过吗、排得进全序吗、重放得过吗。任何一步失败都有明确归宿，没有静默路径。

flowchart TD ARRIVE["op 到达（来自对端信封）"] --> SEEN{"op 标识已应用过？"} SEEN -->|是| DROP["丢弃（幂等去重，不产生第二次效果）"] SEEN -->|否| ORDER["按（逻辑时钟, DeviceId）插入全序"] ORDER --> SAME{"与本地并发编辑同字段冲突？"} SAME -->|"是（罕见并发）"| LWW["LWW：序末者生效，输者 op 留存可审计"] SAME -->|否| REPLAY LWW --> REPLAY["经既有写入接缝重放"] REPLAY --> OK{"外键 / 引用完好且 schema 兼容？"} OK -->|是| APPLY["落库 + 派生数据同事务重算"] OK -->|否| PARK["ParkedOp 挂起队列"] PARK --> NOTIFY["码化错误通知用户，同步主流程不阻塞"] NOTIFY --> RESOLVE{"用户裁决"} RESOLVE -->|"依赖方处理（如补删） / 旧端升级"| REPLAY2["重新重放 → 出队"] RESOLVE -->|"暂不处理"| WAIT["留在挂起队列，随时可查"] APPLY --> DONE["账本状态更新，等待下次 Checkpoint"]

6. 零丢失：一个并发示例

「零丢失」指并发产生的 op 全部存活——输赢只发生在同字段的裁决上，op 本身永不丢弃。下例：两端在离线状态各改了同一笔交易的备注。

sequenceDiagram autonumber participant A as 设备 A participant B as 设备 B Note over A,B: 离线：两端各自记 op（逻辑时钟各自单调递增） A->>A: 修改备注为「出差用餐」 B->>B: 修改备注为「请客户吃饭」 Note over A,B: 恢复连接，交换信封，得到同一批 op B->>B: 排全序：A 的逻辑时钟早于 B → B 后写 A->>A: 重放 B 的 op → 备注变为「请客户吃饭」（LWW，序末者胜） B->>B: 重放 A 的 op（先）→ 再保留自己的（后） Note over A,B: 两端一致为「请客户吃饭」；A 的旧值仍在 OpLog 中可审计，未丢

8. 安全模型

  • 静态数据保护：加密模式下，网盘上只有 SyncEnvelope 密文（Checkpoint + 日志整包），密钥由主口令经密钥派生导出，口令永不落盘、不传输；网盘账号泄露不等于账本泄露。
  • 与备份同构：复用备份域的加密模式 / 主口令机制；新端开包凭用户输入的口令，与密文备份恢复同形态。
  • 明文兜底知情：未开加密模式时允许明文同步，但界面显著提示。

9. 同步边界：什么不走同步

与 Backup/Restore 的迁移边界对齐（SyncBoundary）：

随同步走留在本机
核心交易、定时计划、投资（含手动报价、FxRateHistory）、参考数据字典、预算、保险、物品、实物资产；账本级设置（DefaultCurrency 本位币基准） 界面状态、ViewState、窗口状态、界面语言、主题、金额隐私模式、备份目录等轻量设备偏好
